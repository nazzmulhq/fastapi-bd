Standard Library Types¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা পাবেন

  • Python-এর নিজস্ব আর standard library-র প্রতিটি সমর্থিত টাইপ (bool, str, int, datetime, list, dict, UUID, Path ...) Pydantic কীভাবে যাচাই করে।
  • প্রতিটির জন্য: কোন ইনপুট গ্রহণযোগ্য (যাচাই), কোন শর্ত দেওয়া যায় (constraint), strict mode-এ কী বদলায়, আর কীভাবে dump হয়।
  • প্রতিটি অংশ একই ছাঁচে সাজানো, তাই দরকারি টাইপের অংশে সরাসরি চলে যান।

এই অংশে সমর্থিত built-in আর standard library টাইপগুলোর তালিকা দেওয়া হলো: অনুমোদিত মান, সম্ভাব্য শর্ত, আর কঠোরতা (strictness) কনফিগার করা যায় কিনা।

প্রতিটি টাইপের অনুমোদিত মানের সারসংক্ষেপের জন্য রূপান্তর সারণি-ও দেখুন।

কীভাবে পড়বেন

প্রতিটি টাইপের অংশে চারটি ভাগ: যাচাই (কোন ইনপুট চলে আর কীভাবে রূপান্তর হয়), শর্ত (Field()-এ কী দেওয়া যায়), কঠোরতা (strict mode-এ কী চলে), আর সিরিয়ালাইজেশন (dump-এ কী রূপে বের হয়, যদি আলাদা হয়)।

মনে রাখুন

আলাদা করে বলা না থাকলে, Python আর JSON দুই মোডেই মানগুলো যেমন আছে তেমন সিরিয়ালাইজ হয়।

Boolean¶

Built-in টাইপ: bool

যাচাই

  • একটি বৈধ bool instance, অর্থাৎ True বা False।
  • পূর্ণসংখ্যা 0 বা 1।
  • একটি স্ট্রিং, যা ছোট হাতের অক্ষরে বদলালে '0', 'off', 'f', 'false', 'n', 'no', '1', 'on' 't', 'true', 'y', 'yes'-এর একটি হয়।
  • bytes অবজেক্ট, যা স্ট্রিংয়ে decode করলে আগের নিয়ম অনুযায়ী বৈধ।

কঠোরতা

strict mode-এ শুধু boolean মানই বৈধ। Strict() metadata ক্লাস ব্যবহারের সুবিধাজনক বিকল্প হিসেবে Pydantic StrictBool টাইপ দেয়।

উদাহরণ

from pydantic import BaseModel, ValidationError


class BooleanModel(BaseModel):
    bool_value: bool


print(BooleanModel(bool_value=False))
#> bool_value=False
print(BooleanModel(bool_value='False'))
#> bool_value=False
print(BooleanModel(bool_value=1))
#> bool_value=True
try:
    BooleanModel(bool_value=[])
except ValidationError as e:
    print(str(e))
    """
    1 validation error for BooleanModel
    bool_value
      Input should be a valid boolean [type=bool_type, input_value=[], input_type=list]
    """

স্ট্রিং¶

Built-in টাইপ: str

যাচাই

  • স্ট্রিং যেমন আছে তেমন গ্রহণ হয়।
  • bytes আর bytearray UTF-8 স্ট্রিংয়ে decode হয়।
  • Enum রূপান্তর হয় এর value অ্যাট্রিবিউটে str() ডেকে।
  • [coerce_numbers_to_str][pydantic.ConfigDict.coerce_numbers_to_str] সেট থাকলে, যেকোনো সংখ্যার টাইপ (int, float আর Decimal) একটি স্ট্রিংয়ে রূপান্তর হয়ে যেমন আছে তেমন গ্রহণ হবে।

শর্ত

স্ট্রিং নিচের শর্তগুলো সমর্থন করে:

শর্ত বর্ণনা JSON Schema
pattern স্ট্রিংকে যে regex প্যাটার্নের সাথে মিলতে হবে pattern keyword (নিচের নোট দেখুন)।
min_length স্ট্রিংয়ের ন্যূনতম দৈর্ঘ্য minLength keyword
max_length স্ট্রিংয়ের সর্বোচ্চ দৈর্ঘ্য maxLength keyword
strip_whitespace শুরু আর শেষের ফাঁকা জায়গা বাদ দেবে কিনা প্রযোজ্য নয়
to_upper স্ট্রিং বড় হাতের অক্ষরে বদলাবে কিনা প্রযোজ্য নয়
to_lower স্ট্রিং ছোট হাতের অক্ষরে বদলাবে কিনা প্রযোজ্য নয়
ascii_only শুধু ASCII অক্ষর অনুমোদন করবে কিনা প্রযোজ্য নয়

এই শর্তগুলো StringConstraints metadata টাইপ দিয়ে, অথবা Field() ফাংশন দিয়ে দেওয়া যায় (strip_whitespace, to_upper, to_lower আর ascii_only ছাড়া)।

annotated-types লাইব্রেরিও MinLen, MaxLen আর Len metadata টাইপ দেয়, সাথে LowerCase, UpperCase, IsDigit আর IsAscii predicate (অবশ্যই str দিয়ে প্যারামিটার দিতে হবে, যেমন LowerCase[str])।

বাংলা লেখা আর দৈর্ঘ্য

min_length/max_length Unicode অক্ষর (code point) গোনে, bytes নয়। তবে বাংলায় যুক্তাক্ষর আর কার-চিহ্ন আলাদা code point, তাই 'ক্ষ'-এর দৈর্ঘ্য ৩ (ক + ্ + ষ)। আর ascii_only=True দিলে বাংলা লেখা গ্রহণ হবে না।

pattern শর্ত

ডিফল্টভাবে, pattern শর্ত প্রয়োগে Pydantic Rust-এর regex crate ব্যবহার করবে। regex engine নিয়ন্ত্রণ করা যায় [regex_engine][pydantic.ConfigDict.regex_engine] কনফিগারেশন মান দিয়ে। pattern-এ একটি compile করা regular expression অবজেক্ট দিলে, স্বয়ংক্রিয়ভাবে Python engine ব্যবহার হবে।

JSON Schema specification যদিও ECMA-262-এ বর্ণিত dialect অনুযায়ী বৈধ প্যাটার্ন ব্যবহারের পরামর্শ দেয়, Pydantic তা জোর করে না।

কঠোরতা

strict mode-এ শুধু স্ট্রিং মানই বৈধ। Strict() metadata ক্লাস ব্যবহারের সুবিধাজনক বিকল্প হিসেবে Pydantic StrictStr টাইপ দেয়।

উদাহরণ

from typing import Annotated

from pydantic import BaseModel, StringConstraints


class StringModel(BaseModel):
    str_value: str = ""
    constrained_str_value: Annotated[str, StringConstraints(to_lower=True)] = ""


print(StringModel(str_value="test").str_value)
#> test
print(StringModel(constrained_str_value='TEST').constrained_str_value)
#> test

Bytes¶

Built-in টাইপ: bytes।

আরও দেখুন: ByteSize।

যাচাই

  • bytes instance যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং আর bytearray instance bytes-এ রূপান্তর হয়, [val_json_bytes][pydantic.ConfigDict.val_json_bytes] কনফিগারেশন মান অনুযায়ী (নাম যা-ই হোক, এটি Python আর JSON দুই মোডেই প্রযোজ্য)।

শর্ত

স্ট্রিং নিচের শর্তগুলো সমর্থন করে:

শর্ত বর্ণনা JSON Schema
min_length bytes-এর ন্যূনতম দৈর্ঘ্য minLength keyword
max_length bytes-এর সর্বোচ্চ দৈর্ঘ্য maxLength keyword

annotated-types লাইব্রেরির MinLen আর MaxLen metadata টাইপও ব্যবহার করা যায়।

কঠোরতা

strict mode-এ শুধু bytes instance বৈধ। Strict() metadata ক্লাস ব্যবহারের সুবিধাজনক বিকল্প হিসেবে Pydantic StrictBytes টাইপ দেয়।

JSON মোডে strict mode-এর কোনো প্রভাব নেই।

সংখ্যা¶

Pydantic Python standard library-র নিচের সংখ্যার টাইপগুলো সমর্থন করে:

পূর্ণসংখ্যা (Integers)¶

Built-in টাইপ: int।

যাচাই

  • পূর্ণসংখ্যা যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং আর bytes পূর্ণসংখ্যায় রূপান্তরের চেষ্টা করা হয় আর যেমন আছে তেমন যাচাই হয় (বিস্তারিত জানতে দেখুন jiter বাস্তবায়ন)।
  • float পূর্ণসংখ্যা হিসেবে যাচাই হয়, যদি float ইনপুটটি অসীম বা NaN (not-a-number) না হয় আর দশমিক অংশ 0 হয়।
  • Decimal instance, যদি সেগুলো সসীম হয় আর হর 1 হয়।
  • Fraction instance, যদি সেগুলো পূর্ণসংখ্যা হয়।
  • Enum রূপান্তর হয় এর value অ্যাট্রিবিউট দিয়ে।

শর্ত

পূর্ণসংখ্যা নিচের শর্তগুলো সমর্থন করে (সংখ্যাগুলো পূর্ণসংখ্যায় রূপান্তরযোগ্য হতে হবে):

শর্ত বর্ণনা JSON Schema
le মান এই সংখ্যার চেয়ে ছোট বা সমান হতে হবে maximum keyword
ge মান এই সংখ্যার চেয়ে বড় বা সমান হতে হবে minimum keyword
lt মান এই সংখ্যার চেয়ে কঠোরভাবে ছোট হতে হবে exclusiveMaximum keyword
gt মান এই সংখ্যার চেয়ে কঠোরভাবে বড় হতে হবে exclusiveMinimum keyword
multiple_of মান এই সংখ্যার গুণিতক হতে হবে multipleOf keyword

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির Le, Ge, Lt, Gt আর MultipleOf metadata টাইপও ব্যবহার করা যায়।

অনুমোদিত পূর্ণসংখ্যার মান আরও সীমিত করতে Pydantic নিচের টাইপগুলোও দেয়:

  • PositiveInt: ইনপুট শূন্যের চেয়ে বড় হতে হবে।
  • NegativeInt: ইনপুট শূন্যের চেয়ে ছোট হতে হবে।
  • NonPositiveInt: ইনপুট শূন্যের চেয়ে ছোট বা সমান হতে হবে।
  • NonNegativeInt: ইনপুট শূন্যের চেয়ে বড় বা সমান হতে হবে।

কঠোরতা

strict mode-এ শুধু পূর্ণসংখ্যার মান বৈধ। Strict() metadata ক্লাস ব্যবহারের সুবিধাজনক বিকল্প হিসেবে Pydantic StrictInt টাইপ দেয়।

দশমিক সংখ্যা (Floats)¶

Built-in টাইপ: float।

যাচাই

  • float যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং আর bytes float-এ রূপান্তরের চেষ্টা করা হয় আর যেমন আছে তেমন যাচাই হয়। (বিস্তারিত জানতে দেখুন Rust বাস্তবায়ন)।
  • ইনপুটে একটি __float__() মেথড থাকলে, ইনপুটকে float-এ রূপান্তর করতে সেটি ডাকা হবে। __float__() সংজ্ঞায়িত না থাকলে, __index__()-এ ফিরে যায়। এর মধ্যে আছে (তবে এগুলোতেই সীমিত নয়) Decimal আর Fraction টাইপ।

শর্ত

float নিচের শর্তগুলো সমর্থন করে:

শর্ত বর্ণনা JSON Schema

lt মান এই সংখ্যার চেয়ে কঠোরভাবে ছোট হতে হবে exclusiveMaximum keyword
gt মান এই সংখ্যার চেয়ে কঠোরভাবে বড় হতে হবে exclusiveMinimum keyword

annotated-types লাইব্রেরিও Le, Ge, Lt, Gt আর MultipleOf metadata টাইপ দেয়, সাথে IsFinite, IsNotFinite, IsNan, IsNotNan, IsAscii, IsInfinite আর IsNotInfinite predicate (অবশ্যই float দিয়ে প্যারামিটার দিতে হবে, যেমন IsFinite[float])। AllowInfNan টাইপও ব্যবহার করা যায়।

Pydantic সুবিধাজনক alias হিসেবে নিচের টাইপগুলোও দেয়:

  • PositiveFloat: ইনপুট শূন্যের চেয়ে বড় হতে হবে।
  • NegativeFloat: ইনপুট শূন্যের চেয়ে ছোট হতে হবে।
  • NonPositiveFloat: ইনপুট শূন্যের চেয়ে ছোট বা সমান হতে হবে।
  • NonNegativeFloat: ইনপুট শূন্যের চেয়ে বড় বা সমান হতে হবে।
  • FiniteFloat: NaN (not-a-number) আর অসীম মান আটকায়।

কঠোরতা

strict mode-এ শুধু float মান আর যে ইনপুটের একটি __float__() বা __index__() মেথড আছে সেগুলো বৈধ। Strict() metadata ক্লাস ব্যবহারের সুবিধাজনক বিকল্প হিসেবে Pydantic StrictFloat টাইপ দেয়।

v2.12-এ বদলেছে

JSON Schema-তে max_digits আর decimal_places শর্তের সাথে মেলে এমন একটি pattern থাকে।

v2.14-এ বদলেছে

তৈরি হওয়া প্যাটার্ন জটিল হওয়ায় পরবর্তী ব্যবহারকারীদের সমস্যা করতে পারে বলে, JSON Schema-তে ডিফল্টভাবে আর pattern থাকে না।

GenerateJsonSchema-এর subclass বানিয়ে get_decimal_pattern() মেথড override করে প্যাটার্নটি যোগ করা যায়:

from decimal import Decimal
from typing import Annotated

from pydantic import Field, TypeAdapter
from pydantic.json_schema import GenerateJsonSchema


class MyGenerateJsonSchema(GenerateJsonSchema):
    def get_decimal_pattern(self, schema):
        return self.build_decimal_pattern(schema)


ta = TypeAdapter(Annotated[Decimal, Field(max_digits=5, decimal_places=2)])
print(
    ta.json_schema(schema_generator=MyGenerateJsonSchema, mode='serialization')
)
"""
{
    'pattern': '^-?(?:(?:0|[1-9][0-9]{0,2})(?:\\.[0-9]{1,2}0*)?|0E[+-][1-9][0-9]*|[1-9](?:\\.[0-9]+)?E\\+[1-2])$',
    'type': 'string',
}
"""

তৈরি হওয়া প্যাটার্ন এখন আর lookahead assertion ব্যবহার করে না, আর exponent ও allow_inf_nan বিবেচনা করে।

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির Le, Ge, Lt, Gt আর MultipleOf metadata টাইপ আর AllowInfNan টাইপও ব্যবহার করা যায়।

টাকা-পয়সার হিসাবে

দাম বা টাকার অঙ্কে float নয়, Decimal ব্যবহার করুন: 0.1 + 0.2 float-এ 0.30000000000000004, কিন্তু Decimal-এ ঠিক 0.3। যেমন price: Decimal = Field(max_digits=10, decimal_places=2)।

কঠোরতা

strict mode-এ শুধু decimal.Decimal instance গ্রহণ হয়। JSON মোডে strict mode-এর কোনো প্রভাব নেই।

সিরিয়ালাইজেশন

Python মোডে, Decimal instance যেমন আছে তেমন সিরিয়ালাইজ হয়।

JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয়। এই আচরণ বদলাতে একটি serializer ব্যবহার করা যায়:

from decimal import Decimal
from typing import Annotated

from pydantic import BaseModel, PlainSerializer


class Model(BaseModel):
    f: Annotated[Decimal, PlainSerializer(float, when_used='json')]


my_model = Model(f=Decimal('2.1'))

print(my_model.model_dump())  # (1)!
#> {'f': Decimal('2.1')}
print(my_model.model_dump_json())  # (2)!
#> {"f":2.1}
  1. Python মোডে, f একটি Decimal instance-ই থাকে।
  2. JSON মোডে, f একটি float হিসেবে সিরিয়ালাইজ হয়।

Datetime¶

Standard library টাইপ: datetime.datetime।

যাচাই

  • datetime instance যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং আর bytes দুইভাবে যাচাই হয়:
    • RFC 3339 ফরম্যাট মানা স্ট্রিং (datetime আর date দুটোই)। আরও বিস্তারিত জানতে দেখুন speedate ডকুমেন্টেশন।
    • Unix timestamp, epoch থেকে সেকেন্ড বা মিলিসেকেন্ড হিসেবে। আরও বিস্তারিত জানতে দেখুন [val_temporal_unit][pydantic.ConfigDict.val_temporal_unit] কনফিগারেশন মান।
  • পূর্ণসংখ্যা আর float (বা পূর্ণসংখ্যা বা float-এ রূপান্তরযোগ্য টাইপ) unix timestamp হিসেবে যাচাই হয়, স্ট্রিংয়ের মতো একই নিয়মে।
  • datetime.date instance গ্রহণ হয়, আর একটি datetime instance-এ রূপান্তরিত হয় hour, minute, second আর microsecond অ্যাট্রিবিউট 0, আর tzinfo অ্যাট্রিবিউট None করে।

মনে রাখুন

নামযুক্ত timezone-এর সমর্থন (RFC 9557-এ যেমন বলা আছে, যেমন [Asia/Dhaka]) এই issue-এ অনুসরণ করা যায়।

সিরিয়ালাইজেশন

Python মোডে, datetime instance যেমন আছে তেমন সিরিয়ালাইজ হয়।

JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয়।

শর্ত

Datetime নিচের শর্তগুলো সমর্থন করে (শর্তের মান একটি datetime instance-এ রূপান্তরযোগ্য হতে হবে):

শর্ত বর্ণনা JSON Schema
le মান এই datetime-এর চেয়ে ছোট বা সমান হতে হবে প্রযোজ্য নয়
ge মান এই datetime-এর চেয়ে বড় বা সমান হতে হবে প্রযোজ্য নয়
lt মান এই datetime-এর চেয়ে কঠোরভাবে ছোট হতে হবে প্রযোজ্য নয়
gt মান এই datetime-এর চেয়ে কঠোরভাবে বড় হতে হবে প্রযোজ্য নয়

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির Le, Ge, Lt আর Gt metadata টাইপও ব্যবহার করা যায়।

অনুমোদিত datetime মান আরও সীমিত করতে Pydantic নিচের টাইপগুলোও দেয়:

  • AwareDatetime: ইনপুটে timezone থাকতে হবে।
  • NaiveDatetime: ইনপুটে timezone থাকা চলবে না।
  • PastDatetime: যাচাইয়ের সময় ইনপুট অতীতের হতে হবে।
  • FutureDatetime: যাচাইয়ের সময় ইনপুট ভবিষ্যতের হতে হবে।

কঠোরতা

strict mode-এ শুধু datetime instance গ্রহণ হয়। JSON মোডে শুধু RFC 3339 ফরম্যাট মানা স্ট্রিং (শুধু datetime) বা unix timestamp গ্রহণ হয়।

উদাহরণ

from datetime import datetime
from typing import Annotated

from pydantic import AwareDatetime, BaseModel, Field


class Event(BaseModel):
    dt: Annotated[AwareDatetime, Field(gt=datetime(2000, 1, 1))]


event = Event(dt='2032-04-23T10:20:30.400+02:30')

print(event.model_dump())
"""
{'dt': datetime.datetime(2032, 4, 23, 10, 20, 30, 400000, tzinfo=TzInfo(9000))}
"""
print(event.model_dump_json())
#> {"dt":"2032-04-23T10:20:30.400000+02:30"}

বাংলাদেশের সময়

'2024-03-26T10:00:00+06:00' লিখলে timezone-সহ (aware) datetime পাবেন। প্রোডাকশনে সবসময় timezone-সহ সময় রাখা ভালো; দরকারে AwareDatetime টাইপ দিয়ে timezone বাধ্যতামূলক করুন।

তারিখ (Dates)¶

Standard library টাইপ: datetime.date।

যাচাই

  • date instance যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং আর bytes দুইভাবে যাচাই হয়:
    • RFC 3339 তারিখ ফরম্যাট মানা স্ট্রিং (YYYY-MM-DD)। আরও বিস্তারিত জানতে দেখুন speedate ডকুমেন্টেশন।
    • Unix timestamp, epoch থেকে সেকেন্ড বা মিলিসেকেন্ড হিসেবে। আরও বিস্তারিত জানতে দেখুন [val_temporal_unit][pydantic.ConfigDict.val_temporal_unit] কনফিগারেশন মান।
  • যাচাই ব্যর্থ হলে, ইনপুটটি datetime হিসেবে যাচাই করা যায় (সংখ্যা হিসেবেও), যদি সময়ের অংশ 0 হয় আর timezone না থাকে।

সিরিয়ালাইজেশন

Python মোডে, date instance যেমন আছে তেমন সিরিয়ালাইজ হয়।

JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয়।

শর্ত

Date নিচের শর্তগুলো সমর্থন করে (শর্তের মান একটি date instance-এ রূপান্তরযোগ্য হতে হবে):

শর্ত বর্ণনা JSON Schema
le মান এই তারিখের চেয়ে ছোট বা সমান হতে হবে প্রযোজ্য নয়
ge মান এই তারিখের চেয়ে বড় বা সমান হতে হবে প্রযোজ্য নয়
lt মান এই তারিখের চেয়ে কঠোরভাবে ছোট হতে হবে প্রযোজ্য নয়
gt মান এই তারিখের চেয়ে কঠোরভাবে বড় হতে হবে প্রযোজ্য নয়

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির Le, Ge, Lt আর Gt metadata টাইপও ব্যবহার করা যায়।

অনুমোদিত তারিখের মান আরও সীমিত করতে Pydantic নিচের টাইপগুলোও দেয়:

  • PastDate: যাচাইয়ের সময় ইনপুট অতীতের হতে হবে (যেমন জন্মতারিখ)।
  • FutureDate: যাচাইয়ের সময় ইনপুট ভবিষ্যতের হতে হবে (যেমন অ্যাপয়েন্টমেন্ট)।

কঠোরতা

strict mode-এ শুধু date instance গ্রহণ হয়। JSON মোডে শুধু RFC 3339 ফরম্যাট মানা স্ট্রিং (শুধু date) বা unix timestamp গ্রহণ হয়।

উদাহরণ

from pydantic import BaseModel

    d: date

print(my_birthday.model_dump())
#> {'d': datetime.date(2023, 3, 24)}
print(my_birthday.model_dump_json())
#> {"d":"2023-03-24"}

Enum¶

Standard library টাইপ: enum.Enum।

যাচাই

  • সরাসরি enum.Enum টাইপ ব্যবহার করলে, যেকোনো enum.Enum instance যেমন আছে তেমন যাচাই হয়।
  • একটি enum.Enum subclass টাইপ হিসেবে ব্যবহার করলে, যেকোনো enum সদস্য বা enum সদস্যদের মানের সাথে মেলে এমন মান যেমন আছে তেমন যাচাই হয়।

সিরিয়ালাইজেশন

Python মোডে, enum instance যেমন আছে তেমন সিরিয়ালাইজ হয়। যাচাইয়ের সময় enum-এর মান ব্যবহার করতে (যাতে সিরিয়ালাইজেশনেও তা-ই ব্যবহার হয়) [use_enum_values][pydantic.ConfigDict.use_enum_values] কনফিগারেশন মান সেট করা যায়।

JSON মোডে, enum instance তাদের মান দিয়ে সিরিয়ালাইজ হয়।

উদাহরণ

from enum import Enum, IntEnum

from pydantic import BaseModel, ValidationError


class FruitEnum(str, Enum):
    PEAR = 'pear'
    BANANA = 'banana'


class ToolEnum(IntEnum):
    SPANNER = 1
    WRENCH = 2


class CookingModel(BaseModel):
    fruit: FruitEnum = FruitEnum.PEAR
    tool: ToolEnum = ToolEnum.SPANNER


print(CookingModel())
#> fruit=<FruitEnum.PEAR: 'pear'> tool=<ToolEnum.SPANNER: 1>
print(CookingModel(tool=2, fruit='banana'))
#> fruit=<FruitEnum.BANANA: 'banana'> tool=<ToolEnum.WRENCH: 2>
try:
    CookingModel(fruit='other')
except ValidationError as e:
    print(e)
    """
    1 validation error for CookingModel
    fruit
      Input should be 'pear' or 'banana' [type=enum, input_value='other', input_type=str]
    """

None টাইপ¶

সমর্থিত টাইপ: None, NoneType বা Literal[None] (এগুলো সমতুল্য)।

মান হিসেবে শুধু None অনুমোদন করে।

Generic collection টাইপ¶

Pydantic অনেক ধরনের generic collection টাইপ সমর্থন করে, built-in (যেমন list) আর collections.abc মডিউলের abstract base class (যেমন Sequence) দুটোই।

বেশিরভাগ ক্ষেত্রে abstract টাইপের চেয়ে built-in টাইপ ব্যবহারের পরামর্শ দেওয়া হয়। ডেটা রূপান্তরের কারণে, list বা tuple ব্যবহার করলেও অন্য বেশিরভাগ iterable ইনপুট হিসেবে চলবে, আরও ভালো পারফরম্যান্সসহ।

collection টাইপে কঠোরতা

collection টাইপে strict mode প্রয়োগ করলে, কঠোরতা ভেতরের টাইপে প্রযোজ্য হয় না। ভবিষ্যতে এটি বদলাতে পারে, দেখুন এই issue।

তালিকা (Lists)¶

Built-in টাইপ: list (পুরনো alias: typing.List)।

যাচাই

  • list, tuple, set আর frozenset instance, অথবা এমন যেকোনো iterable যা string, bytes, bytearray, dict বা [mapping][] নয়, অনুমোদন করে। একটি list instance তৈরি করে।
  • একটি generic প্যারামিটার দিলে, তালিকার সব আইটেমে উপযুক্ত যাচাই প্রয়োগ হয়।

শর্ত

তালিকা নিচের শর্তগুলো সমর্থন করে:

শর্ত বর্ণনা JSON Schema
min_length তালিকায় অন্তত এতগুলো আইটেম থাকতে হবে minItems keyword
max_length তালিকায় সর্বোচ্চ এতগুলো আইটেম থাকতে পারবে maxItems keyword

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির MinLen আর MaxLen metadata টাইপও ব্যবহার করা যায়।

কঠোরতা

strict mode-এ শুধু list instance বৈধ। strict mode তালিকার আইটেমে প্রযোজ্য হয় না। এটি কাজ করাতে strict শর্তটি প্যারামিটার টাইপে প্রয়োগ করতে হবে (যেমন list[StrictInt])।

উদাহরণ

from pydantic import BaseModel, Field


class Model(BaseModel):
    simple_list: list[object] | None = None
    list_of_ints: list[int] | None = Field(default=None, strict=True)


print(Model(simple_list=('1', '2', '3')).simple_list)
#> ['1', '2', '3']
print(Model(list_of_ints=['1', 2, 3]).list_of_ints)
#> [1, 2, 3]

Tuple¶

Built-in টাইপ: tuple (পুরনো alias: typing.Tuple)।

মনে রাখুন

খুলে দেওয়া tuple টাইপ (PEP 646 অনুযায়ী) এখনো সমর্থিত নয়, আর এই issue-এ অনুসরণ করা যায়।

যাচাই

  • tuple, list, set আর frozenset instance, অথবা এমন যেকোনো iterable যা string, bytes, bytearray, dict বা [mapping][] নয়, অনুমোদন করে। একটি tuple instance তৈরি করে।
  • উপাদানের টাইপ দেওয়া থাকলে tuple-এর আইটেমে উপযুক্ত যাচাই প্রয়োগ হয় (যেমন tuple[int, str] মানে প্রথমটি সংখ্যা, দ্বিতীয়টি লেখা; tuple[int, ...] মানে যত খুশি সংখ্যা)।

শর্ত

তালিকা নিচের শর্তগুলো সমর্থন করে:

শর্ত বর্ণনা JSON Schema
min_length tuple-এ অন্তত এতগুলো আইটেম থাকতে হবে minItems keyword
max_length tuple-এ সর্বোচ্চ এতগুলো আইটেম থাকতে পারবে maxItems keyword

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির MinLen আর MaxLen metadata টাইপও ব্যবহার করা যায়।

এছাড়া, tuple-এর গঠন অনুযায়ী prefixItems JSON Schema keyword ব্যবহার হতে পারে।

কঠোরতা

strict mode-এ শুধু tuple instance বৈধ। strict mode tuple-এর আইটেমে প্রযোজ্য হয় না। এটি কাজ করাতে strict শর্তটি প্যারামিটার টাইপগুলোতে প্রয়োগ করতে হবে।

উদাহরণ

from pydantic import BaseModel


class Model(BaseModel):
    simple_tuple: tuple | None = None
    tuple_of_different_types: tuple[int, float, bool] | None = None


print(Model(simple_tuple=[1, 2, 3, 4]).simple_tuple)
#> (1, 2, 3, 4)
print(Model(tuple_of_different_types=[3, 2, 1]).tuple_of_different_types)
#> (3, 2.0, True)

Named tuple¶

Standard library টাইপ: typing.NamedTuple (আর collections.namedtuple() factory ফাংশন দিয়ে তৈরি টাইপ – প্রতিটি ফিল্ডের টাইপ অন্তর্নিহিতভাবে Any)।

যাচাই

  • tuple আর list instance অনুমোদন করে। প্রতিটি আইটেম ফিল্ডের সংজ্ঞা অনুযায়ী যাচাই করে।
  • dict instance অনুমোদন করে। key-গুলো named tuple-এর ফিল্ডের নামের সাথে মিলতে হবে, আর মানগুলো ফিল্ডের সংজ্ঞা অনুযায়ী যাচাই হয়।
  • named tuple ক্লাসের instance অনুমোদন করে (ফিল্ডগুলো আবার যাচাই হয়)।

সিরিয়ালাইজেশন

Python মোডে, named tuple tuple হিসেবে সিরিয়ালাইজ হয়। JSON মোডে, এগুলো array হিসেবে সিরিয়ালাইজ হয়।

উদাহরণ

from typing import NamedTuple

from pydantic import BaseModel


class Point(NamedTuple):
    x: int
    y: int


class Model(BaseModel):
    p: Point


model = Model(p=('1', 2))

print(model.model_dump())
#> {'p': (1, 2)}

সেট (Sets)¶

টাইপ: set (বা collections.abc.MutableSet) আর frozenset (বা collections.abc.Set) (পুরনো alias: typing.Set আর typing.FrozenSet)।

যাচাই

  • set, frozenset, tuple আর list instance, অথবা এমন যেকোনো iterable যা string, bytes, bytearray, dict বা [mapping][] নয়, অনুমোদন করে। একটি set বা frozenset instance তৈরি করে (ফলে পুনরাবৃত্ত মান বাদ পড়ে)।
  • একটি generic প্যারামিটার দিলে, set/frozenset-এর সব আইটেমে উপযুক্ত যাচাই প্রয়োগ হয়।

শর্ত

সেট নিচের শর্তগুলো সমর্থন করে:

শর্ত বর্ণনা JSON Schema
min_length সেটে অন্তত এতগুলো আইটেম থাকতে হবে minItems keyword
max_length সেটে সর্বোচ্চ এতগুলো আইটেম থাকতে পারবে maxItems keyword

এই শর্তগুলো Field() ফাংশন দিয়ে দেওয়া যায়। annotated-types লাইব্রেরির MinLen আর MaxLen metadata টাইপও ব্যবহার করা যায়।

কঠোরতা

strict mode-এ শুধু set/frozenset instance বৈধ। strict mode সেটের আইটেমে প্রযোজ্য হয় না। এটি কাজ করাতে strict শর্তটি প্যারামিটার টাইপে প্রয়োগ করতে হবে।

Python মোডে, সেট যেমন আছে তেমন সিরিয়ালাইজ হয়। JSON মোডে, এগুলো array হিসেবে সিরিয়ালাইজ হয়।

Sequence¶

Standard library টাইপ: collections.abc.Sequence (পুরনো alias: typing.Sequence)।

বেশিরভাগ ক্ষেত্রে আপনি built-in টাইপ (যেমন list বা tuple) ব্যবহার করতে চাইবেন, কারণ টাইপ রূপান্তর প্রযোজ্য হবে। সিরিয়ালাইজেশনের সময় ইনপুটের টাইপ অক্ষুণ্ণ রাখতে চাইলে Sequence টাইপ ব্যবহার করা যায়।

যাচাই

যেকোনো collections.abc.Sequence instance (স্ট্রিং আর bytes ছাড়া) গ্রহণ হয়। এটি list() constructor দিয়ে একটি তালিকায় রূপান্তরিত হয়, তারপর আবার মূল ইনপুটের টাইপে ফেরত রূপান্তরিত হয়।

স্ট্রিংকে sequence ধরা হয় না

কারিগরিভাবে স্ট্রিং বৈধ sequence instance হলেও, প্রায়ই সেটি উদ্দেশ্য থাকে না, আর এটি বাগের একটি প্রচলিত উৎস।

ফলে, Pydantic Sequence টাইপের জন্য স্ট্রিং আর bytes গ্রহণ করবে না (নিচের উদাহরণ দেখুন)।

Python মোডে, sequence যেমন আছে তেমন সিরিয়ালাইজ হয়। JSON মোডে, এগুলো array হিসেবে সিরিয়ালাইজ হয়।

চলার সময়ের সীমাবদ্ধতার কারণে, Python 3.12 বা তার নিচে Pydantic typing_extensions-এর TypedDict টাইপ ব্যবহার দাবি করবে।

TypedDict এমন একটি ডিকশনারি টাইপ ঘোষণা করে যার প্রতিটি instance-এ নির্দিষ্ট key-এর একটি সেট থাকবে বলে আশা করা হয়, আর প্রতিটি key একটি নির্দিষ্ট টাইপের মানের সাথে যুক্ত।

এই টাইপ কনফিগারেশন সমর্থন করে।

কঠোরতা

strict mode-এ শুধু dict instance বৈধ (lax মোডে mapping-ও চলে, এখানে নয়)। strict mode typed ডিকশনারির value-তে প্রযোজ্য হয় না। এটি কাজ করাতে strict শর্তটি value-র টাইপগুলোতে প্রয়োগ করতে হবে।

উদাহরণ

from typing_extensions import TypedDict

from pydantic import TypeAdapter, ValidationError


class User(TypedDict):
    name: str
    id: int


ta = TypeAdapter(User)

print(ta.validate_python({'name': 'foo', 'id': 1}))
#> {'name': 'foo', 'id': 1}

try:
    ta.validate_python({'name': 'foo'})
except ValidationError as e:
    print(e)
    """
    1 validation error for User
    id
      Field required [type=missing, input_value={'name': 'foo'}, input_type=dict]
    """

Iterable¶

Standard library টাইপ: collections.abc.Iterable (পুরনো alias: typing.Iterable)।

যাচাই

Iterable অলসভাবে (lazily) যাচাই হয়, আর একটি ভেতরের ডেটা কাঠামোয় মোড়ানো থাকে যার ওপর লুপ চালানো যায় (আর লুপ চলার সময় আইটেমের টাইপ যাচাই হয়)। অর্থাৎ তালিকার মতো একটি নির্দিষ্ট container দিলেও, যাচাই করা টাইপ list টাইপের হবে না। তবে Pydantic নিশ্চিত করবে যে ইনপুট মানটি iterable, এর থেকে একটি [iterator][] নিয়ে (মানটিতে iter() ডেকে)।

বদলে নির্দিষ্ট collection টাইপ (যেমন তালিকা) ব্যবহারের পরামর্শ দেওয়া হয়, যদি না আপনি একটি অসীম iterator ব্যবহার করছেন (সেক্ষেত্রে ইনপুট সাথে সাথে যাচাই করলে অসীম লুপ হতো)।

উদাহরণ

from collections.abc import Iterable

from pydantic import BaseModel, ValidationError


class Model(BaseModel):
    f: Iterable[str]


m = Model(f=[1, 2])  # Validates fine

try:
    next(m.f)
except ValidationError as e:
    print(e)
    """
    1 validation error for ValidatorIterator
    0
      Input should be a valid string [type=string_type, input_value=1, input_type=int]
    """

Callable¶

Standard library টাইপ: collections.abc.Callable (পুরনো alias: typing.Callable)।

যাচাই

Pydantic শুধু যাচাই করে যে ইনপুটটি একটি callable (callable() ফাংশন দিয়ে)। এটি প্যারামিটারের সংখ্যা বা তাদের টাইপ, বা ফেরত মানের টাইপ যাচাই করে না।

from collections.abc import Callable

from pydantic import BaseModel


class Foo(BaseModel):
    callback: Callable[[int], int]


m = Foo(callback=lambda x: x)
print(m)
#> callback=<function <lambda> at 0x0123456789ab>

সিরিয়ালাইজেশন

callable যেমন আছে তেমন সিরিয়ালাইজ হয়। callable JSON মোডে সিরিয়ালাইজ করা যায় না (একটি PydanticSerializationError ওঠে)।

IP ঠিকানা¶

Standard library টাইপ:

  • ipaddress.IPv4Address
  • ipaddress.IPv4Interface
  • ipaddress.IPv4Network
  • ipaddress.IPv6Address
  • ipaddress.IPv6Interface
  • ipaddress.IPv6Network

আরও দেখুন: IPvAnyAddress, IPvAnyInterface আর IPvAnyNetwork Pydantic টাইপ।

যাচাই

  • instance যেমন আছে তেমন যাচাই হয়।
  • অন্য ইনপুট মান সংশ্লিষ্ট ঠিকানা টাইপের constructor-এ পাঠানো হয়।

কঠোরতা

strict mode-এ শুধু ঠিকানা টাইপগুলো গ্রহণ হয়। JSON মোডে, strict mode-এ শুধু স্ট্রিং গ্রহণ হয়, আর lax মোডে পূর্ণসংখ্যাও গ্রহণ হয় (যেমন 3232235521 যাচাই হয় IPv4Address('192.168.0.1') হিসেবে)।

সিরিয়ালাইজেশন

Python মোডে, IP ঠিকানা যেমন আছে তেমন সিরিয়ালাইজ হয়। JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয়।

UUID¶

Standard library টাইপ: uuid.UUID।

যাচাই

  • UUID instance যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং আর bytes UUID হিসেবে যাচাই হয়, আর একটি UUID instance-এ রূপান্তরিত হয়।

শর্ত

UUID টাইপ একটি version শর্ত সমর্থন করে। UuidVersion metadata টাইপ ব্যবহার করা যায়।

Pydantic সুবিধাজনক alias হিসেবে নিচের টাইপগুলোও দেয়: UUID1, UUID3, UUID4, UUID5, UUID6, UUID7, UUID8।

কঠোরতা

strict mode-এ শুধু UUID instance গ্রহণ হয়। JSON মোডে strict mode-এর কোনো প্রভাব নেই।

সিরিয়ালাইজেশন

Python মোডে, UUID যেমন আছে তেমন সিরিয়ালাইজ হয়। JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয়।

উদাহরণ

from typing import Annotated
from uuid import UUID

from pydantic import BaseModel
from pydantic.types import UUID7, UuidVersion


class Model(BaseModel):
    u1: UUID7
    u2: Annotated[UUID, UuidVersion(4)]


print(
    Model(
        u1='01999b2c-8353-749b-8dac-859307fae22b',
        u2=UUID('125725f3-e1b4-44e3-90c3-1a20eab12da5'),
    )
)
"""
u1=UUID('01999b2c-8353-749b-8dac-859307fae22b') u2=UUID('125725f3-e1b4-44e3-90c3-1a20eab12da5')
"""

Type¶

Built-in টাইপ: type (পুরনো alias: typing.Type)।

যাচাই

টাইপ আর্গুমেন্টের subclass এমন যেকোনো টাইপ (ক্লাস) অনুমোদন করে। যেমন, type[str] দিলে str ক্লাস বা যেকোনো str subclass ইনপুট হিসেবে চলে। কোনো টাইপ আর্গুমেন্ট না দিলে (অর্থাৎ annotation হিসেবে শুধু type), যেকোনো ক্লাস অনুমোদিত।

সিরিয়ালাইজেশন

টাইপ যেমন আছে তেমন সিরিয়ালাইজ হয়। টাইপ JSON মোডে সিরিয়ালাইজ করা যায় না (একটি PydanticSerializationError ওঠে)।

from pydantic import BaseModel, ValidationError


class Foo:
    pass


class Bar(Foo):
    pass


class Other:
    pass


class SimpleModel(BaseModel):
    just_subclasses: type[Foo]


SimpleModel(just_subclasses=Foo)
SimpleModel(just_subclasses=Bar)
try:
    SimpleModel(just_subclasses=Other)
except ValidationError as e:
    print(e)
    """
    1 validation error for SimpleModel
    just_subclasses
      Input should be a subclass of Foo [type=is_subclass_of, input_value=<class '__main__.Other'>, input_type=type]
    """

Literal¶

Typing কাঠামো: typing.Literal (আরও দেখুন: typing specification)।

শুধু নির্দিষ্ট কিছু মান অনুমোদন করতে Literal ব্যবহার করা যায় (যেমন Literal['pending', 'paid', 'cancelled'])।

মনে রাখুন, literal মান যাচাইয়ের সময় Pydantic strict mode-এর আচরণ প্রয়োগ করে (দেখুন এই issue); অর্থাৎ Literal[1]-এ '1' স্ট্রিং চলবে না।

উদাহরণ

from typing import Literal

from pydantic import BaseModel, ValidationError


class Pie(BaseModel):
    flavor: Literal['apple', 'pumpkin']
    quantity: Literal[1, 2] = 1


Pie(flavor='apple')
Pie(flavor='pumpkin')
try:
    Pie(flavor='cherry')
except ValidationError as e:
    print(str(e))
    """
    1 validation error for Pie
    flavor
      Input should be 'apple' or 'pumpkin' [type=literal_error, input_value='cherry', input_type=str]
    """

try:
    Pie(flavor='apple', quantity='1')
except ValidationError as e:
    print(str(e))
    """
    1 validation error for Pie
    quantity
      Input should be 1 or 2 [type=literal_error, input_value='1', input_type=str]
    """

Any¶

টাইপ: typing.Any বা object।

None-সহ যেকোনো মান অনুমোদন করে, কোনো যাচাই বা রূপান্তর ছাড়া।

Hashable¶

Standard library টাইপ: collections.abc.Hashable (পুরনো alias: typing.Hashable)।

যাচাই

hash করা যায় এমন যেকোনো মান (isinstance(value, Hashable) দিয়ে)।

Regex প্যাটার্ন¶

Standard library টাইপ: re.Pattern (পুরনো alias: typing.Pattern)।

যাচাই

  • Pattern instance-এর জন্য, পরীক্ষা করে যে pattern অ্যাট্রিবিউটটি সঠিক টাইপের (Pattern টাইপ প্যারামিটার অনুযায়ী str বা bytes)।
  • টাইপ প্যারামিটার str বা bytes হলে, str (বা যথাক্রমে bytes) টাইপের ইনপুট মান re.compile() দিয়ে compile করার চেষ্টা করা হয়।

সিরিয়ালাইজেশন

Python মোডে, Pattern instance যেমন আছে তেমন সিরিয়ালাইজ হয়।

JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয় (মনে রাখুন, flag এখন অক্ষুণ্ণ থাকে না)।

Path¶

Standard library টাইপ:

  • pathlib.Path।
  • pathlib.PurePath।
  • pathlib.PosixPath।
  • pathlib.WindowsPath।
  • pathlib.PurePosixPath।
  • pathlib.PureWindowsPath।
  • os.PathLike (অবশ্যই str, bytes বা Any দিয়ে প্যারামিটার দিতে হবে)।

যাচাই

  • Path instance যেমন আছে তেমন যাচাই হয়।
  • স্ট্রিং গ্রহণ হয় আর টাইপের constructor-এ পাঠানো হয়। os.PathLike ব্যবহার করলে, bytes টাইপ দিয়ে প্যারামিটার দেওয়া থাকলে bytes গ্রহণ হয়।

কঠোরতা

strict mode-এ শুধু Path instance গ্রহণ হয়। JSON মোডে strict mode-এর কোনো প্রভাব নেই।

সিরিয়ালাইজেশন

Python মোডে, Path instance যেমন আছে তেমন সিরিয়ালাইজ হয়।

JSON মোডে, এগুলো স্ট্রিং হিসেবে সিরিয়ালাইজ হয়।

পথ আসলেই আছে কিনা

Path শুধু লেখাটিকে পথ বানায়, ফাইলটি আছে কিনা দেখে না। থাকা বাধ্যতামূলক করতে FilePath বা DirectoryPath ব্যবহার করুন (দেখুন Pydantic Types)।

সংক্ষেপে মনে রাখুন

  • lax মোডে Pydantic যৌক্তিক রূপান্তর করে ('1' → 1, '2024-01-01' → date, tuple → list); strict মোডে শুধু ঠিক টাইপ।
  • collection-এ strict শুধু বাইরের টাইপে; ভেতরের আইটেমে চাইলে list[StrictInt] এর মতো লিখুন।
  • JSON মোডে Decimal, UUID, datetime, timedelta, Path, IP সব স্ট্রিং হয়ে যায়; set, tuple, deque হয় array।
  • Sequence স্ট্রিং গ্রহণ করে না; টাকার হিসাবে Decimal।
