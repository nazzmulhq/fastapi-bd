JSON Schema¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

API ডকুমেন্টেশন

pydantic.json_schema

এই পেজে যা শিখবেন

  • JSON Schema কী, আর Pydantic মডেল থেকে কীভাবে তা তৈরি হয়।
  • model_json_schema() আর TypeAdapter.json_schema() ব্যবহার।
  • ফিল্ড আর মডেল স্তরে schema নিজের মতো করা: title, description, examples, json_schema_extra।
  • কাস্টম টাইপের schema, schema তৈরির পুরো প্রক্রিয়া বদলানো, আর $ref নিজের মতো করা।

উদাহরণ দিয়ে বুঝি

JSON Schema হলো ডেটার একটি "নিয়মের বই", যা নিজেও JSON-এ লেখা: "এই অবজেক্টে name থাকবে, সেটি স্ট্রিং; age থাকবে, সেটি integer আর বাধ্যতামূলক"। যেকোনো ভাষার যেকোনো টুল এই নিয়মের বই পড়ে বুঝতে পারে আপনার ডেটা কেমন। FastAPI-র /docs পেজ, SDK জেনারেটর, এমনকি AI মডেলের "structured output", সবই এই JSON Schema পড়ে কাজ করে। Pydantic আপনার Python মডেল থেকে এই নিয়মের বই স্বয়ংক্রিয়ভাবে লিখে দেয়।

Pydantic মডেল থেকে স্বয়ংক্রিয়ভাবে JSON schema তৈরি আর নিজের মতো করার সুযোগ দেয়। তৈরি হওয়া JSON schema নিচের স্পেসিফিকেশনগুলো মেনে চলে:

  • JSON Schema Draft 2020-12
  • OpenAPI Specification v3.1.0।

JSON Schema তৈরি করা¶

JSON schema তৈরি করতে নিচের ফাংশনগুলো ব্যবহার করুন:

  • BaseModel.model_json_schema একটি মডেলের schema-র একটি JSON-যোগ্য dict ফেরত দেয়।
  • TypeAdapter.json_schema একটি adapt করা টাইপের schema-র একটি JSON-যোগ্য dict ফেরত দেয়।

নোট

এই মেথডগুলোকে BaseModel.model_dump_json আর TypeAdapter.dump_json-এর সাথে গুলিয়ে ফেলবেন না, যেগুলো যথাক্রমে মডেল বা adapt করা টাইপের ইনস্ট্যান্স (আসল ডেটা) সিরিয়ালাইজ করে। ওই মেথডগুলো JSON স্ট্রিং ফেরত দেয়। তুলনায়, BaseModel.model_json_schema আর TypeAdapter.json_schema যথাক্রমে মডেল বা adapt করা টাইপের JSON schema (ডেটার নিয়ম) বোঝায় এমন একটি JSON-যোগ্য dict ফেরত দেয়।

JSON schema-র "JSON-যোগ্য" প্রকৃতি নিয়ে

model_json_schema-এর ফলাফলের "JSON-যোগ্য" প্রকৃতি সম্পর্কে বলতে গেলে, কোনো BaseModel m-এর ওপর json.dumps(m.model_json_schema()) কল করলে একটি বৈধ JSON স্ট্রিং পাওয়া যায়। একইভাবে, TypeAdapter.json_schema-এর ক্ষেত্রে, json.dumps(TypeAdapter(<some_type>).json_schema()) কল করলে একটি বৈধ JSON স্ট্রিং পাওয়া যায়।

পরামর্শ

Pydantic নিচের দুটোই সমর্থন করে:

  1. JSON Schema নিজের মতো করা
  2. JSON Schema তৈরির প্রক্রিয়া নিজের মতো করা

প্রথম পদ্ধতির পরিধি সাধারণত সংকীর্ণ, এটি আরও নির্দিষ্ট ক্ষেত্র আর টাইপের জন্য JSON schema নিজের মতো করতে দেয়। দ্বিতীয় পদ্ধতির পরিধি সাধারণত বড়, এটি সামগ্রিকভাবে JSON schema তৈরির প্রক্রিয়া নিজের মতো করতে দেয়। দুটো পদ্ধতিতেই একই ফল পাওয়া যায়, কিন্তু আপনার প্রয়োজন অনুযায়ী একটি অন্যটির চেয়ে সহজ সমাধান দিতে পারে।

একটি BaseModel থেকে JSON schema তৈরির একটি উদাহরণ:

import json
from enum import Enum
from typing import Annotated

from pydantic import BaseModel, Field
from pydantic.config import ConfigDict


class FooBar(BaseModel):
    count: int
    size: float | None = None


class Gender(str, Enum):
    male = 'male'
    female = 'female'
    other = 'other'
    not_given = 'not_given'


class MainModel(BaseModel):
    """
    This is the description of the main model
    """

    model_config = ConfigDict(title='Main')

    foo_bar: FooBar
    gender: Annotated[Gender | None, Field(alias='Gender')] = None
    snap: int = Field(
        default=42,
        title='The Snap',
        description='this is the value of snap',
        gt=30,
        lt=50,
    )


main_model_schema = MainModel.model_json_schema()  # (1)!
print(json.dumps(main_model_schema, indent=2))  # (2)!

JSON আউটপুট:

    "FooBar": {
      "properties": {

            {
              "type": "number"

  2. schema dict-এর ওপর json.dumps কল করলে একটি JSON স্ট্রিং পাওয়া যায়।

আউটপুটটি সহজ ভাষায়

  • properties: প্রতিটি ফিল্ড আর তার টাইপ। snap-এর জন্য title, description, default আর gt/lt থেকে আসা exclusiveMinimum/exclusiveMaximum সব দেখা যাচ্ছে।
  • required: বাধ্যতামূলক ফিল্ড, এখানে শুধু foo_bar।
  • $defs: নেস্টেড মডেল (FooBar) আর enum (Gender)-এর সংজ্ঞা আলাদা রাখা, আর $ref দিয়ে উল্লেখ করা।
  • description: মডেলের docstring থেকে, আর title: ConfigDict(title='Main') থেকে।
  • Gender ফিল্ডটি alias দিয়ে লেখা, কারণ schema ডিফল্টভাবে alias ব্যবহার করে।

TypeAdapter ক্লাস দিয়ে যেকোনো টাইপের জন্য যাচাই, সিরিয়ালাইজ আর JSON schema তৈরির মেথডসহ একটি অবজেক্ট তৈরি করা যায়। এটি Pydantic V1-এর schema_of-এর (যা এখন deprecated) সম্পূর্ণ বিকল্প।

একটি TypeAdapter থেকে JSON schema তৈরির একটি উদাহরণ:

from pydantic import TypeAdapter

adapter = TypeAdapter(list[int])
print(adapter.json_schema())
#> {'items': {'type': 'integer'}, 'type': 'array'}

BaseModel আর TypeAdapter-এর সমন্বয়ের জন্যও JSON schema তৈরি করতে পারেন, যেমন এই উদাহরণে দেখানো হয়েছে:

import json

from pydantic import BaseModel, TypeAdapter


class Cat(BaseModel):
    name: str
    color: str


class Dog(BaseModel):
    name: str
    breed: str


ta = TypeAdapter(Cat | Dog)
ta_schema = ta.json_schema()
print(json.dumps(ta_schema, indent=2))

JsonSchemaMode কনফিগার করা¶

model_json_schema আর TypeAdapter.json_schema মেথডের mode প্যারামিটার দিয়ে JSON schema তৈরির মোড নির্দিষ্ট করুন। ডিফল্টভাবে মোড 'validation', যা মডেলের যাচাইয়ের schema-র সাথে মেলে এমন JSON schema তৈরি করে।

JsonSchemaMode হলো একটি টাইপ alias, যা mode প্যারামিটারের উপলব্ধ অপশনগুলো বোঝায়:

  • 'validation' (ইনপুট হিসেবে কী গ্রহণ করা হয়)
  • 'serialization' (আউটপুট হিসেবে কী বের হয়)

mode প্যারামিটার কীভাবে নির্দিষ্ট করতে হয়, আর তা তৈরি হওয়া JSON schema-কে কীভাবে প্রভাবিত করে, তার একটি উদাহরণ:

from decimal import Decimal

from pydantic import BaseModel


class Model(BaseModel):
    a: Decimal = Decimal('12.34')


print(Model.model_json_schema(mode='validation'))
"""
{
    'properties': {
        'a': {
            'anyOf': [{'type': 'number'}, {'type': 'string'}],
            'default': '12.34',
            'title': 'A',
        }
    },
    'title': 'Model',
    'type': 'object',
}
"""

print(Model.model_json_schema(mode='serialization'))
"""
{
    'properties': {'a': {'default': '12.34', 'title': 'A', 'type': 'string'}},
    'title': 'Model',
    'type': 'object',
}
"""

(Decimal ইনপুটে সংখ্যা বা স্ট্রিং দুটোই গ্রহণ করে, তাই validation schema-তে anyOf; কিন্তু আউটপুটে সবসময় স্ট্রিং হিসেবে বের হয়, তাই serialization schema-তে শুধু string।)

JSON Schema নিজের মতো করা¶

তৈরি হওয়া JSON schema ফিল্ড স্তরে আর মডেল স্তরে দুই জায়গাতেই নিজের মতো করা যায়।

ফিল্ড আর মডেল দুই স্তরেই JSON schema-তে বাড়তি তথ্য যোগ করতে json_schema_extra অপশন ব্যবহার করতে পারেন।

কাস্টম টাইপের জন্য, JSON schema তৈরি নিজের মতো করতে Pydantic অন্যান্য টুল দেয়:

  1. WithJsonSchema অ্যানোটেশন
  2. SkipJsonSchema অ্যানোটেশন
  3. __get_pydantic_core_schema__ বাস্তবায়ন
  4. __get_pydantic_json_schema__ বাস্তবায়ন

ফিল্ড-স্তরের কাস্টমাইজেশন¶

ফিল্ডের JSON Schema নিজের মতো করা যায়। এটি সাধারণত Field() ফাংশন দিয়ে করা হয়।

কিছু ফিল্ড প্যারামিটার শুধু তৈরি হওয়া JSON Schema নিজের মতো করতে ব্যবহার হয়:

  • title: ফিল্ডের শিরোনাম।
  • description: ফিল্ডের বর্ণনা।
  • examples: ফিল্ডের উদাহরণ।
  • json_schema_extra: ফিল্ডে যোগ করার বাড়তি JSON Schema প্রপার্টি (নির্দিষ্ট ডকুমেন্টেশন দেখুন)।
  • field_title_generator: একটি ফাংশন, যা ফিল্ডের নাম আর তথ্যের ভিত্তিতে প্রোগ্রাম দিয়ে ফিল্ডের শিরোনাম সেট করে।

একটি উদাহরণ:

import json
from typing import Annotated

from pydantic import BaseModel, EmailStr, Field, SecretStr


class User(BaseModel):
    age: int = Field(description='Age of the user')
    email: Annotated[EmailStr, Field(examples=['marcelo@mail.com'])]  # (1)!
    name: str = Field(title='Username')
    password: SecretStr = Field(
        json_schema_extra={
            'title': 'Password',
            'description': 'Password of the user',
            'examples': ['123456'],
        }
    )


print(json.dumps(User.model_json_schema(), indent=2))

JSON আউটপুট:

  1. Annotated প্যাটার্নও ব্যবহার করা যায়।

(লক্ষ্য করুন, SecretStr পাসওয়ার্ড ফিল্ড schema-তে "writeOnly": true আর "format": "password" পেয়েছে, অর্থাৎ এটি শুধু পাঠানো যায়, ফেরত দেখানো হয় না।)

প্রোগ্রাম দিয়ে ফিল্ডের শিরোনাম তৈরি¶

ফিল্ডের নাম আর তথ্যের ভিত্তিতে প্রোগ্রাম দিয়ে শিরোনাম তৈরি করতে field_title_generator প্যারামিটার ব্যবহার করা যায়।

নিচের উদাহরণ দেখুন:

import json

from pydantic import BaseModel, Field
from pydantic.fields import FieldInfo


def make_title(field_name: str, field_info: FieldInfo) -> str:
    return field_name.upper()


class Person(BaseModel):
    name: str = Field(field_title_generator=make_title)
    age: int = Field(field_title_generator=make_title)


print(json.dumps(Person.model_json_schema(), indent=2))
"""
{
  "properties": {
    "name": {
      "title": "NAME",
      "type": "string"
    },
    "age": {
      "title": "AGE",
      "type": "integer"
    }
  },
  "required": [
    "name",
    "age"
  ],
  "title": "Person",
  "type": "object"
}
"""

মডেল-স্তরের কাস্টমাইজেশন¶

একটি মডেলে JSON schema তৈরি নিজের মতো করতে model config-ও ব্যবহার করতে পারেন। বিশেষ করে, নিচের config অপশনগুলো প্রাসঙ্গিক:

  • title
  • json_schema_extra
  • json_schema_mode_override
  • field_title_generator
  • model_title_generator

json_schema_extra ব্যবহার করা¶

JSON schema-তে বাড়তি তথ্য যোগ করতে json_schema_extra অপশন ব্যবহার করা যায়, হয় ফিল্ড স্তরে, নয়তো মডেল স্তরে। json_schema_extra-তে একটি dict বা একটি Callable দিতে পারেন।

dict দিয়ে json_schema_extra ব্যবহার¶

JSON schema-তে বাড়তি তথ্য যোগ করতে json_schema_extra-তে একটি dict দিতে পারেন:

import json

from pydantic import BaseModel, ConfigDict


class Model(BaseModel):
    a: str

    model_config = ConfigDict(json_schema_extra={'examples': [{'a': 'Foo'}]})


print(json.dumps(Model.model_json_schema(), indent=2))

JSON আউটপুট:

{
  "examples": [
    {
      "a": "Foo"
    }
  ],
  "properties": {
    "a": {
      "title": "A",
      "type": "string"
    }
  },
  "required": [
    "a"
  ],
  "title": "Model",
  "type": "object"
}

(FastAPI-তে রিকোয়েস্ট বডির উদাহরণ /docs-এ দেখাতে ঠিক এভাবেই examples যোগ করা হয়।)

Callable দিয়ে json_schema_extra ব্যবহার¶

একটি ফাংশন দিয়ে JSON schema বদলাতে json_schema_extra-তে একটি Callable দিতে পারেন:

import json

from pydantic import BaseModel, Field


def pop_default(s):
    s.pop('default')


class Model(BaseModel):
    a: int = Field(default=1, json_schema_extra=pop_default)


print(json.dumps(Model.model_json_schema(), indent=2))

JSON আউটপুট:

{
  "properties": {
    "a": {
      "title": "A",
      "type": "integer"
    }
  },
  "title": "Model",
  "type": "object"
}

(ফাংশনটি schema থেকে default মুছে দিয়েছে, তাই আউটপুটে a-এর ডিফল্ট দেখা যাচ্ছে না।)

json_schema_extra মিলিয়ে দেওয়া¶

v2.9 থেকে, Pydantic অ্যানোটেট করা টাইপগুলোর json_schema_extra ডিকশনারিগুলো মিলিয়ে (merge করে) দেয়। এই পদ্ধতি আগের ওভাররাইড আচরণের বদলে মেলানোর আরও যোগমূলক একটি পদ্ধতি দেয়। একাধিক টাইপে json schema-র বাড়তি তথ্য পুনরায় ব্যবহারের ক্ষেত্রে এটি বেশ কাজের হতে পারে।

আমরা এই পরিবর্তনকে মূলত একটি বাগ ফিক্স হিসেবে দেখেছি, কারণ এটি BaseModel আর TypeAdapter ইনস্ট্যান্সের মধ্যে json_schema_extra মেলানোর আচরণে অনিচ্ছাকৃত পার্থক্য দূর করে - আরও বিস্তারিত জানতে এই issue দেখুন।

import json
from typing import Annotated, TypeAlias

from pydantic import Field, TypeAdapter

ExternalType: TypeAlias = Annotated[
    int, Field(json_schema_extra={'key1': 'value1'})
]

ta = TypeAdapter(
    Annotated[ExternalType, Field(json_schema_extra={'key2': 'value2'})]
)
print(json.dumps(ta.json_schema(), indent=2))
"""
{
  "key1": "value1",
  "key2": "value2",
  "type": "integer"
}
"""

নোট

আমরা আর dict আর callable টাইপের json_schema_extra স্পেসিফিকেশনের মিশ্রণ সমর্থন করি না (আর কখনো পুরোপুরি করিনি)। যদি আপনার ক্ষেত্রে এটি একটি প্রয়োজন হয়, তাহলে অনুগ্রহ করে একটি pydantic issue খুলুন আর আপনার পরিস্থিতি ব্যাখ্যা করুন - জোরালো যুক্তি পেলে আমরা এই সিদ্ধান্ত আবার বিবেচনা করতে খুশি হব।

WithJsonSchema অ্যানোটেশন¶

পরামর্শ

কাস্টম টাইপের জন্য __get_pydantic_json_schema__() বাস্তবায়নের চেয়ে WithJsonSchema ব্যবহার করাই ভালো, কারণ এটি আরও সহজ আর ভুলের সম্ভাবনা কম।

একটি টাইপের JSON Schema ওভাররাইড করার জন্য ব্যবহৃত একটি অ্যানোটেশন।

এটি কাজের যখন এমন একটি টাইপের জন্য JSON Schema সেট করতে চান যা ডিফল্টভাবে কোনো JSON Schema তৈরি করে না (যেমন Callable)। লক্ষ্য করুন, এটি টাইপটির পুরো তৈরি হওয়া JSON Schema ওভাররাইড করে (নিচের উদাহরণে 'type'-ও দিতে হয়েছে)।

import json
from typing import Annotated

from pydantic import BaseModel, WithJsonSchema

MyInt = Annotated[
    int,
    WithJsonSchema({'type': 'integer', 'examples': [1, 0, -1]}),
]


class Model(BaseModel):
    a: MyInt


print(json.dumps(Model.model_json_schema(), indent=2))

JSON আউটপুট:

{
  "properties": {
    "a": {
      "examples": [
        1,
        0,
        -1
      ],
      "title": "A",
      "type": "integer"
    }
  },
  "required": [
    "a"
  ],
  "title": "Model",
  "type": "object"
}

আরও বিস্তারিত জানতে API ডকুমেন্টেশন দেখুন।

নোট

validator যুক্ত ফিল্ডের JSON Schema সূক্ষ্মভাবে ঠিক করতে আপনি WithJsonSchema অ্যানোটেশন ব্যবহারে প্রলুব্ধ হতে পারেন। এর বদলে json_schema_input_type আর্গুমেন্ট ব্যবহারের পরামর্শ দেওয়া হয়।

SkipJsonSchema অ্যানোটেশন¶

API ডকুমেন্টেশন

pydantic.json_schema.SkipJsonSchema

তৈরি হওয়া JSON schema থেকে একটি অন্তর্ভুক্ত ফিল্ড (বা একটি ফিল্ডের স্পেসিফিকেশনের অংশ) বাদ দিতে SkipJsonSchema অ্যানোটেশন ব্যবহার করা যায়। আরও বিস্তারিত জানতে API ডকস দেখুন।

__get_pydantic_core_schema__ বাস্তবায়ন ¶

কাস্টম টাইপ (field_name: TheType বা field_name: Annotated[TheType, ...] হিসেবে ব্যবহৃত) আর Annotated মেটাডেটা (field_name: Annotated[int, SomeMetadata] হিসেবে ব্যবহৃত) __get_pydantic_core_schema__ বাস্তবায়ন করে তৈরি হওয়া schema বদলাতে বা ওভাররাইড করতে পারে। এই মেথড দুটি positional আর্গুমেন্ট পায়:

  1. এই টাইপের সাথে সংশ্লিষ্ট টাইপ অ্যানোটেশন (তাই TheType[T][int]-এর ক্ষেত্রে এটি হবে TheType[int])।
  2. __get_pydantic_core_schema__-এর পরবর্তী বাস্তবায়নকারীকে কল করার জন্য একটি handler/callback।

handler ব্যবস্থাটি ঠিক wrap ফিল্ড validator-এর মতো কাজ করে। এই ক্ষেত্রে ইনপুট হলো টাইপ আর আউটপুট একটি core_schema।

(core schema হলো Pydantic-এর ভেতরের "নির্দেশনার তালিকা", যা Rust ইঞ্জিন pydantic-core পড়ে যাচাই আর সিরিয়ালাইজ করে। JSON schema এই core schema থেকেই তৈরি হয়।)

একটি কাস্টম টাইপের উদাহরণ যা তৈরি হওয়া core_schema ওভাররাইড করে:

from dataclasses import dataclass
from typing import Any

from pydantic_core import core_schema

from pydantic import BaseModel, GetCoreSchemaHandler


@dataclass
class CompressedString:
    dictionary: dict[int, str]
    text: list[int]

    def build(self) -> str:
        return ' '.join([self.dictionary[key] for key in self.text])

    @classmethod
    def __get_pydantic_core_schema__(
        cls, source: type[Any], handler: GetCoreSchemaHandler
    ) -> core_schema.CoreSchema:
        assert source is CompressedString
        return core_schema.no_info_after_validator_function(
            cls._validate,
            core_schema.str_schema(),
            serialization=core_schema.plain_serializer_function_ser_schema(
                cls._serialize,
                info_arg=False,
                return_schema=core_schema.str_schema(),
            ),
        )

    @staticmethod
    def _validate(value: str) -> 'CompressedString':
        inverse_dictionary: dict[str, int] = {}
        text: list[int] = []
        for word in value.split(' '):
            if word not in inverse_dictionary:
                inverse_dictionary[word] = len(inverse_dictionary)
            text.append(inverse_dictionary[word])
        return CompressedString(
            {v: k for k, v in inverse_dictionary.items()}, text
        )

    @staticmethod
    def _serialize(value: 'CompressedString') -> str:
        return value.build()


class MyModel(BaseModel):
    value: CompressedString


print(MyModel.model_json_schema())
"""
{
    'properties': {'value': {'title': 'Value', 'type': 'string'}},
    'required': ['value'],
    'title': 'MyModel',
    'type': 'object',
}
"""
print(MyModel(value='fox fox fox dog fox'))
"""
value = CompressedString(dictionary={0: 'fox', 1: 'dog'}, text=[0, 0, 0, 1, 0])
"""

print(MyModel(value='fox fox fox dog fox').model_dump(mode='json'))
#> {'value': 'fox fox fox dog fox'}

কোডটি সহজ ভাষায়

CompressedString একটি নিজস্ব ক্লাস, যা একটি বাক্যকে শব্দের অভিধান আর সংখ্যার তালিকা হিসেবে সংকুচিত করে রাখে। __get_pydantic_core_schema__ Pydantic-কে বলে দেয়: "ইনপুট হবে একটি স্ট্রিং (str_schema()), যাচাইয়ের পরে _validate দিয়ে সংকুচিত রূপে বানাও, আর সিরিয়ালাইজ করার সময় _serialize দিয়ে আবার স্ট্রিং বানাও"। ফলে JSON schema-তে ফিল্ডটি সাধারণ string হিসেবেই দেখায়।

যেহেতু Pydantic CompressedString-এর জন্য schema তৈরি করতে জানে না, তাই এর __get_pydantic_core_schema__ মেথডে handler(source) কল করলে একটি pydantic.errors.PydanticSchemaGenerationError এরর পেতেন। বেশিরভাগ কাস্টম টাইপের ক্ষেত্রে এমনই হবে, তাই কাস্টম টাইপের জন্য প্রায় কখনোই handler কল করতে চাইবেন না।

Annotated মেটাডেটার প্রক্রিয়া প্রায় একই, শুধু সাধারণত handler কল করে Pydantic-কে schema তৈরি সামলাতে দিতে পারেন।

from collections.abc import Sequence
from dataclasses import dataclass
from typing import Annotated, Any

from pydantic_core import core_schema

from pydantic import BaseModel, GetCoreSchemaHandler, ValidationError


@dataclass
class RestrictCharacters:
    alphabet: Sequence[str]

    def __get_pydantic_core_schema__(
        self, source: type[Any], handler: GetCoreSchemaHandler
    ) -> core_schema.CoreSchema:
        if not self.alphabet:
            raise ValueError('Alphabet may not be empty')
        schema = handler(
            source
        )  # get the CoreSchema from the type / inner constraints
        if schema['type'] != 'str':
            raise TypeError('RestrictCharacters can only be applied to strings')
        return core_schema.no_info_after_validator_function(
            self.validate,
            schema,
        )

    def validate(self, value: str) -> str:
        if any(c not in self.alphabet for c in value):
            raise ValueError(
                f'{value!r} is not restricted to {self.alphabet!r}'
            )
        return value


class MyModel(BaseModel):
    value: Annotated[str, RestrictCharacters('ABC')]


print(MyModel.model_json_schema())
"""
{
    'properties': {'value': {'title': 'Value', 'type': 'string'}},
    'required': ['value'],
    'title': 'MyModel',
    'type': 'object',
}
"""
print(MyModel(value='CBA'))
#> value='CBA'

try:
    MyModel(value='XYZ')
except ValidationError as e:
    print(e)
    """
    1 validation error for MyModel
    value
      Value error, 'XYZ' is not restricted to 'ABC' [type=value_error, input_value='XYZ', input_type=str]
    """

(RestrictCharacters('ABC') আগে handler(source) দিয়ে স্বাভাবিক str schema নেয়, তারপর তার পরে নিজের যাচাই জুড়ে দেয়: স্ট্রিংয়ে শুধু A, B, C অক্ষর থাকতে পারবে।)

এ পর্যন্ত আমরা schema মুড়ে দিচ্ছিলাম, কিন্তু যদি শুধু এটিকে বদলাতে বা উপেক্ষা করতে চান, তাও করতে পারেন।

schema বদলাতে, প্রথমে handler কল করুন, তারপর ফলাফলটি পরিবর্তন করুন:

from typing import Annotated, Any

from pydantic_core import ValidationError, core_schema

from pydantic import BaseModel, GetCoreSchemaHandler


class SmallString:
    def __get_pydantic_core_schema__(
        self,
        source: type[Any],
        handler: GetCoreSchemaHandler,
    ) -> core_schema.CoreSchema:
        schema = handler(source)
        assert schema['type'] == 'str'
        schema['max_length'] = 10  # modify in place
        return schema


class MyModel(BaseModel):
    value: Annotated[str, SmallString()]


try:
    MyModel(value='too long!!!!!')
except ValidationError as e:
    print(e)
    """
    1 validation error for MyModel
    value
      String should have at most 10 characters [type=string_too_long, input_value='too long!!!!!', input_type=str]
    """

পরামর্শ

লক্ষ্য করুন, একটি schema আপনাকে অবশ্যই ফেরত দিতে হবে, এমনকি যদি শুধু সেটিকে জায়গায় বদলান।

schema পুরোপুরি ওভাররাইড করতে, handler কল না করে নিজের CoreSchema ফেরত দিন:

from typing import Annotated, Any

from pydantic_core import ValidationError, core_schema

from pydantic import BaseModel, GetCoreSchemaHandler


class AllowAnySubclass:
    def __get_pydantic_core_schema__(
        self, source: type[Any], handler: GetCoreSchemaHandler
    ) -> core_schema.CoreSchema:
        # we can't call handler since it will fail for arbitrary types
        def validate(value: Any) -> Any:
            if not isinstance(value, source):
                raise ValueError(
                    f'Expected an instance of {source}, got an instance of {type(value)}'
                )
            return value

        return core_schema.no_info_plain_validator_function(validate)


class Foo:
    pass


class Model(BaseModel):
    f: Annotated[Foo, AllowAnySubclass()]


print(Model(f=Foo()))
#> f=<__main__.Foo object at 0x0123456789ab>


class NotFoo:
    pass


try:
    Model(f=NotFoo())
except ValidationError as e:
    print(e)
    """
    1 validation error for Model
    f
      Value error, Expected an instance of <class '__main__.Foo'>, got an instance of <class '__main__.NotFoo'> [type=value_error, input_value=<__main__.NotFoo object at 0x0123456789ab>, input_type=NotFoo]
    """

__get_pydantic_json_schema__ বাস্তবায়ন ¶

তৈরি হওয়া json schema বদলাতে বা ওভাররাইড করতে __get_pydantic_json_schema__-ও বাস্তবায়ন করতে পারেন। এই মেথড বদলালে শুধু JSON schema প্রভাবিত হয় - core schema নয়, যা যাচাই আর সিরিয়ালাইজেশনে ব্যবহার হয়।

তৈরি হওয়া JSON schema বদলানোর একটি উদাহরণ:

import json
from typing import Any

from pydantic_core import core_schema as cs

from pydantic import GetCoreSchemaHandler, GetJsonSchemaHandler, TypeAdapter
from pydantic.json_schema import JsonSchemaValue


class Person:
    name: str
    age: int

    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age

    @classmethod
    def __get_pydantic_core_schema__(
        cls, source_type: Any, handler: GetCoreSchemaHandler
    ) -> cs.CoreSchema:
        return cs.typed_dict_schema(
            {
                'name': cs.typed_dict_field(cs.str_schema()),
                'age': cs.typed_dict_field(cs.int_schema()),
            },
        )

    @classmethod
    def __get_pydantic_json_schema__(
        cls, core_schema: cs.CoreSchema, handler: GetJsonSchemaHandler
    ) -> JsonSchemaValue:
        json_schema = handler(core_schema)
        json_schema = handler.resolve_ref_schema(json_schema)
        json_schema['examples'] = [
            {
                'name': 'John Doe',
                'age': 25,
            }
        ]
        json_schema['title'] = 'Person'
        return json_schema


print(json.dumps(TypeAdapter(Person).json_schema(), indent=2))

JSON schema-র টাইপ¶

টাইপ, কাস্টম ফিল্ড টাইপ আর শর্ত (যেমন max_length) সংশ্লিষ্ট স্পেসিফিকেশনের ফরম্যাটে ম্যাপ করা হয় নিচের অগ্রাধিকারের ক্রমে (যখন সমতুল্য কিছু পাওয়া যায়):

  1. JSON Schema Core
  2. JSON Schema Validation
  3. OpenAPI Data Types
  4. আরও জটিল string সাব-টাইপের জন্য Pydantic-এর সম্প্রসারণ সংজ্ঞায়িত করতে স্ট্যান্ডার্ড format JSON ফিল্ড ব্যবহার হয়।

Python বা Pydantic থেকে JSON schema-তে ফিল্ডের schema ম্যাপিং নিচের মতো করা হয়:

সারণির কলামগুলোর অর্থ

  • Python type: আপনার মডেলে লেখা টাইপ।
  • JSON Schema Type: JSON schema-তে কোন মৌলিক টাইপ হিসেবে দেখাবে (string, integer, array ইত্যাদি)।
  • Additional JSON Schema: সাথে কোন বাড়তি তথ্য যোগ হবে (যেমন "format": "email")।
  • Defined in: নিয়মটি কোন স্ট্যান্ডার্ড থেকে এসেছে।
  • Notes: বাড়তি মন্তব্য।

JSON Schema তৈরির প্রক্রিয়া নিজের মতো করা¶

API ডকুমেন্টেশন

pydantic.json_schema

যদি কাস্টম schema তৈরির দরকার হয়, তাহলে আপনার অ্যাপ্লিকেশনের প্রয়োজনমতো GenerateJsonSchema ক্লাস বদলে একটি schema_generator ব্যবহার করতে পারেন।

JSON schema তৈরির বিভিন্ন মেথড একটি keyword argument schema_generator: type[GenerateJsonSchema] = GenerateJsonSchema গ্রহণ করে, আর JSON schema তৈরিতে নিজের পদ্ধতি ব্যবহার করতে এই মেথডগুলোতে আপনার কাস্টম সাব-ক্লাস দিতে পারেন।

GenerateJsonSchema একটি টাইপের pydantic-core schema-কে একটি JSON schema-তে রূপান্তর বাস্তবায়ন করে। নকশা অনুযায়ী, এই ক্লাস JSON schema তৈরির প্রক্রিয়াকে ছোট ছোট মেথডে ভাগ করে, যেগুলো সাব-ক্লাসে সহজে ওভাররাইড করে JSON schema তৈরির "সার্বিক" পদ্ধতি বদলানো যায়।

from pydantic import BaseModel
from pydantic.json_schema import GenerateJsonSchema


class MyGenerateJsonSchema(GenerateJsonSchema):
    def generate(self, schema, mode='validation'):
        json_schema = super().generate(schema, mode=mode)
        json_schema['title'] = 'Customize title'
        json_schema['$schema'] = self.schema_dialect
        return json_schema


class MyModel(BaseModel):
    x: int


print(MyModel.model_json_schema(schema_generator=MyGenerateJsonSchema))
"""
{
    'properties': {'x': {'title': 'X', 'type': 'integer'}},
    'required': ['x'],
    'title': 'Customize title',
    'type': 'object',
    '$schema': 'https://json-schema.org/draft/2020-12/schema',
}
"""

(এখানে generate মেথড ওভাররাইড করে প্রতিটি schema-র শিরোনাম বদলানো আর $schema কী যোগ করা হয়েছে।)

যেসব ফিল্ডের বৈধ json schema নেই সেগুলো schema থেকে বাদ দিতে নিচের পদ্ধতি ব্যবহার করতে পারেন:

from collections.abc import Callable

from pydantic_core import PydanticOmit, core_schema

from pydantic import BaseModel
from pydantic.json_schema import GenerateJsonSchema, JsonSchemaValue


class MyGenerateJsonSchema(GenerateJsonSchema):
    def handle_invalid_for_json_schema(
        self, schema: core_schema.CoreSchema, error_info: str
    ) -> JsonSchemaValue:
        raise PydanticOmit


def example_callable():
    return 1


class Example(BaseModel):
    name: str = 'example'
    function: Callable = example_callable


instance_example = Example()

validation_schema = instance_example.model_json_schema(
    schema_generator=MyGenerateJsonSchema, mode='validation'
)
print(validation_schema)
"""
{
    'properties': {
        'name': {'default': 'example', 'title': 'Name', 'type': 'string'}
    },
    'title': 'Example',
    'type': 'object',
}
"""

JSON schema সাজানো (sorting)¶

ডিফল্টভাবে, Pydantic key-গুলো বর্ণানুক্রমে সাজিয়ে JSON schema পুনরাবৃত্তভাবে সাজায়। উল্লেখযোগ্যভাবে, মডেলে ফিল্ডগুলো যে ক্রমে সংজ্ঞায়িত তা বজায় রাখতে Pydantic properties key-এর মানগুলো সাজানো এড়িয়ে যায়।

এই আচরণ নিজের মতো করতে চাইলে, আপনার কাস্টম GenerateJsonSchema সাব-ক্লাসে sort মেথড ওভাররাইড করতে পারেন। নিচের উদাহরণে সাজানো পুরোপুরি বন্ধ করতে একটি কিছু-না-করা sort মেথড ব্যবহার করা হয়েছে, যা মডেলের ফিল্ড আর json_schema_extra key-এর বজায় থাকা ক্রমে দেখা যায়:

import json

from pydantic import BaseModel, Field
from pydantic.json_schema import GenerateJsonSchema, JsonSchemaValue


class MyGenerateJsonSchema(GenerateJsonSchema):
    def sort(
        self, value: JsonSchemaValue, parent_key: str | None = None
    ) -> JsonSchemaValue:
        """No-op, we don't want to sort schema values at all."""
        return value


class Bar(BaseModel):
    c: str
    b: str
    a: str = Field(json_schema_extra={'c': 'hi', 'b': 'hello', 'a': 'world'})


json_schema = Bar.model_json_schema(schema_generator=MyGenerateJsonSchema)
print(json.dumps(json_schema, indent=2))
"""
{
  "type": "object",
  "properties": {
    "c": {
      "type": "string",
      "title": "C"
    },
    "b": {
      "type": "string",
      "title": "B"
    },
    "a": {
      "type": "string",
      "c": "hi",
      "b": "hello",
      "a": "world",
      "title": "A"
    }
  },
  "required": [
    "c",
    "b",
    "a"
  ],
  "title": "Bar"
}
"""

JSON Schema-তে $ref নিজের মতো করা¶

model_json_schema() বা model_dump_json()-কে ref_template keyword argument দিয়ে কল করে $ref-এর ফরম্যাট বদলানো যায়। সংজ্ঞাগুলো সবসময় $defs key-এর নিচে রাখা হয়, কিন্তু রেফারেন্সের জন্য একটি নির্দিষ্ট উপসর্গ ব্যবহার করা যায়।

JSON schema-র ডিফল্ট সংজ্ঞার অবস্থান বাড়ানো বা বদলানোর প্রয়োজন হলে এটি কাজের। যেমন, OpenAPI-র ক্ষেত্রে:

import json

from pydantic import BaseModel
from pydantic.type_adapter import TypeAdapter


class Foo(BaseModel):
    a: int


class Model(BaseModel):
    a: Foo


adapter = TypeAdapter(Model)

print(
    json.dumps(
        adapter.json_schema(ref_template='#/components/schemas/{model}'),
        indent=2,
    )
)

JSON আউটপুট:

{
  "$defs": {
    "Foo": {
      "properties": {
        "a": {
          "title": "A",
          "type": "integer"
        }
      },
      "required": [
        "a"
      ],
      "title": "Foo",
      "type": "object"
    }
  },
  "properties": {
    "a": {
      "$ref": "#/components/schemas/Foo"
    }
  },
  "required": [
    "a"
  ],
  "title": "Model",
  "type": "object"
}

(OpenAPI-তে মডেলগুলো থাকে #/components/schemas/...-এ, তাই ref_template দিয়ে $ref-গুলো সেই ঠিকানায় নির্দেশ করানো হয়েছে।)

JSON Schema তৈরি নিয়ে বিবিধ নোট¶

  • Optional ফিল্ডের JSON schema দেখায় যে null মান অনুমোদিত।
  • Decimal টাইপ JSON schema-তে স্ট্রিং হিসেবে দেখানো (আর সিরিয়ালাইজ করা) হয়।
  • যেহেতু JSON-এ namedtuple টাইপ নেই, তাই একটি মডেলের JSON schema namedtuple-কে namedtuple হিসেবে রাখে না।
  • ব্যবহৃত সাব-মডেলগুলো স্পেসিফিকেশন অনুযায়ী $defs JSON অ্যাট্রিবিউটে যোগ হয় আর রেফারেন্স করা হয়।
  • পরিবর্তনসহ (Field ক্লাস দিয়ে, যেমন কাস্টম শিরোনাম, বর্ণনা বা ডিফল্ট মান) সাব-মডেলগুলো রেফারেন্সের বদলে পুনরাবৃত্তভাবে অন্তর্ভুক্ত হয়।
  • মডেলের description নেওয়া হয় ক্লাসের docstring থেকে, অথবা Field ক্লাসের description আর্গুমেন্ট থেকে।
  • schema ডিফল্টভাবে key হিসেবে alias ব্যবহার করে তৈরি হয়, কিন্তু model_json_schema() বা model_dump_json()-কে by_alias=False keyword argument দিয়ে কল করে মডেলের প্রপার্টির নাম ব্যবহার করেও তৈরি করা যায়।

সংক্ষেপে মনে রাখুন

  • Model.model_json_schema() বা TypeAdapter(T).json_schema() দিয়ে JSON schema পাওয়া যায়।
  • mode='validation' (ইনপুটের নিয়ম) আর mode='serialization' (আউটপুটের নিয়ম) ভিন্ন হতে পারে।
  • Field(title=..., description=..., examples=...) আর json_schema_extra দিয়ে schema-তে তথ্য যোগ করুন।
  • কাস্টম টাইপের জন্য সবচেয়ে সহজ WithJsonSchema; বড় পরিবর্তনের জন্য GenerateJsonSchema সাব-ক্লাস।
