কেন Pydantic Validation ব্যবহার করবেন?¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা জানবেন

  • Pydantic-এর ৭টি বড় সুবিধা: টাইপ হিন্ট, গতি, সিরিয়ালাইজেশন, JSON Schema, strict মোড, বিভিন্ন ধরনের স্কিমা আর কাস্টমাইজেশন।
  • প্রতিটি সুবিধার ছোট উদাহরণ, সহজ ব্যাখ্যাসহ।
  • কোন কোন বিখ্যাত লাইব্রেরি আর প্রতিষ্ঠান Pydantic ব্যবহার করে।

আজ Pydantic মাসে অনেকবার ডাউনলোড হয়, আর বিশ্বের সবচেয়ে বড় আর পরিচিত কিছু প্রতিষ্ঠান এটি ব্যবহার করে।

ছয় বছর আগে শুরু হওয়ার পর থেকে কেন এত মানুষ Pydantic গ্রহণ করেছে তা নিশ্চিত করে বলা কঠিন, তবে এখানে কয়েকটি অনুমান দেওয়া হলো।

টাইপ হিন্ট দিয়ে চালিত স্কিমা যাচাই¶

Pydantic যে স্কিমা (ডেটার কাঠামোর নিয়ম) অনুযায়ী যাচাই করে, তা সাধারণত Python-এর টাইপ হিন্ট দিয়ে সংজ্ঞায়িত হয়।

এর জন্য টাইপ হিন্ট দারুণ, কারণ আপনি যদি আধুনিক Python লেখেন, তাহলে এগুলো কীভাবে ব্যবহার করতে হয় তা আগে থেকেই জানেন। টাইপ হিন্ট ব্যবহারের মানে আরও হলো, Pydantic স্ট্যাটিক টাইপিং টুলের (mypy আর Pyright-এর মতো) আর IDE-এর (PyCharm আর VSCode-এর মতো) সাথে ভালোভাবে মানিয়ে চলে।

(টাইপ হিন্ট মানে name: str, age: int এর মতো লেখা, যা বলে দেয় কোন ভেরিয়েবলে কোন ধরনের মান থাকবে। বিস্তারিত দেখুন Python টাইপের পরিচিতি পেজে।)

উদাহরণ - শুধু টাইপ হিন্ট 
from typing import Annotated, Literal

from annotated_types import Gt

from pydantic import BaseModel


class Fruit(BaseModel):
    name: str  # (1)!
    color: Literal['red', 'green']  # (2)!
    weight: Annotated[float, Gt(0)]  # (3)!
    bazam: dict[str, list[tuple[int, bool, float]]]  # (4)!


print(
    Fruit(
        name='Apple',
        color='red',
        weight=4.2,
        bazam={'foobar': [(1, True, 0.1)]},
    )
)
#> name='Apple' color='red' weight=4.2 bazam={'foobar': [(1, True, 0.1)]}
  1. name ফিল্ডে শুধু str লেখা — যেকোনো স্ট্রিং চলবে।
  2. Literal টাইপ দিয়ে বাধ্য করা হয়েছে যে color হবে হয় 'red', নয়তো 'green'।
  3. এমনকি যখন এমন শর্ত দিতে চাই যা Python টাইপে প্রকাশ করা যায় না, তখনও Annotated আর annotated-types দিয়ে টাইপিং সাপোর্ট বজায় রেখেই শর্ত চাপানো যায় (এখানে: ওজন ০-এর চেয়ে বেশি)।
  4. আমি দাবি করছি না যে "bazam" সত্যিই ফলের কোনো বৈশিষ্ট্য; এটি শুধু দেখাতে যে যত জটিল টাইপই হোক, সহজে যাচাই করা যায়।

আরও জানুন

দেখুন সমর্থিত টাইপ নিয়ে ডকুমেন্টেশন।

গতি (Performance)¶

Pydantic-এর মূল যাচাইয়ের যুক্তি একটি আলাদা প্যাকেজে (pydantic-core) বাস্তবায়িত, যেখানে বেশিরভাগ টাইপের যাচাই লেখা হয়েছে Rust-এ।

ফলে Pydantic Python-এর দ্রুততম ডেটা যাচাই লাইব্রেরিগুলোর একটি।

উদাহরণ দিয়ে বুঝি

Rust হলো একটি দ্রুতগতির প্রোগ্রামিং ভাষা, যা সরাসরি মেশিন কোডে চলে। Pydantic-এর ভারী কাজটা (হাজার হাজার ডেটা পরীক্ষা) Rust-এ লেখা "ইঞ্জিন" করে, আর আপনি শুধু সহজ Python লেখেন। অনেকটা গাড়ির মতো: আপনি স্টিয়ারিং ঘোরান (Python), আর ভেতরের শক্তিশালী ইঞ্জিন (Rust) গাড়ি চালায়।

গতির উদাহরণ - Pydantic বনাম বিশেষভাবে লেখা কোড

সাধারণত, কোনো নির্দিষ্ট কাজের জন্য বিশেষভাবে লেখা কোড একটি সাধারণ-উদ্দেশ্যের validator-এর চেয়ে অনেক দ্রুত হওয়ার কথা, কিন্তু এই উদাহরণে JSON পার্স করা আর URL যাচাইয়ের সময় Pydantic বিশেষভাবে লেখা কোডের চেয়ে ৩০০%-এর বেশি দ্রুত।

Performance Example
import json
import timeit
from urllib.parse import urlparse

import requests

from pydantic import HttpUrl, TypeAdapter

reps = 7
number = 100
r = requests.get('https://api.github.com/emojis')
r.raise_for_status()
emojis_json = r.content


def emojis_pure_python(raw_data):
    data = json.loads(raw_data)
    output = {}
    for key, value in data.items():
        assert isinstance(key, str)
        url = urlparse(value)
        assert url.scheme in ('https', 'http')
        output[key] = url


emojis_pure_python_times = timeit.repeat(
    'emojis_pure_python(emojis_json)',
    globals={
        'emojis_pure_python': emojis_pure_python,
        'emojis_json': emojis_json,
    },
    repeat=reps,
    number=number,
)
print(f'pure python: {min(emojis_pure_python_times) / number * 1000:0.2f}ms')
#> pure python: 5.32ms

type_adapter = TypeAdapter(dict[str, HttpUrl])
emojis_pydantic_times = timeit.repeat(
    'type_adapter.validate_json(emojis_json)',
    globals={
        'type_adapter': type_adapter,
        'HttpUrl': HttpUrl,
        'emojis_json': emojis_json,
    },
    repeat=reps,
    number=number,
)
print(f'pydantic: {min(emojis_pydantic_times) / number * 1000:0.2f}ms')
#> pydantic: 1.54ms

print(
    f'Pydantic {min(emojis_pure_python_times) / min(emojis_pydantic_times):0.2f}x faster'
)
#> Pydantic 3.45x faster

উদাহরণটি সহজ ভাষায়

GitHub-এর ইমোজি তালিকা (নাম আর ছবির URL) ডাউনলোড করে দুইভাবে যাচাই করা হয়েছে: একবার হাতে লেখা Python লুপ দিয়ে (emojis_pure_python), আরেকবার TypeAdapter(dict[str, HttpUrl]).validate_json(...) দিয়ে। timeit দিয়ে সময় মেপে দেখা গেল Pydantic প্রায় ৩.৪৫ গুণ দ্রুত, কারণ JSON পার্স আর URL যাচাই দুটোই Rust-এ একসাথে হয়।

অন্যান্য কম্পাইল করা ভাষায় লেখা গতি-কেন্দ্রিক লাইব্রেরির মতো নয়, Pydantic-এ functional validator দিয়ে যাচাই নিজের মতো করার চমৎকার সুবিধাও আছে।

আরও জানুন

Samuel Colvin-এর PyCon 2023-এর বক্তৃতা ব্যাখ্যা করে pydantic-core কীভাবে কাজ করে আর এটি Pydantic-এর সাথে কীভাবে যুক্ত।

সিরিয়ালাইজেশন¶

Pydantic মডেলকে তিনভাবে সিরিয়ালাইজ (অন্য রূপে রূপান্তর) করার সুবিধা দেয়:

  1. সংশ্লিষ্ট Python অবজেক্ট দিয়ে তৈরি একটি Python dict-এ।
  2. শুধু "JSON-যোগ্য" টাইপ দিয়ে তৈরি একটি Python dict-এ।
  3. একটি JSON স্ট্রিংয়ে।

তিনটি মোডেই আউটপুট নিজের মতো করা যায়: নির্দিষ্ট ফিল্ড বাদ দিয়ে, যে ফিল্ড সেট করা হয়নি তা বাদ দিয়ে, ডিফল্ট মান বাদ দিয়ে, আর None মান বাদ দিয়ে।

উদাহরণ - তিনভাবে সিরিয়ালাইজেশন 
from datetime import datetime

from pydantic import BaseModel


class Meeting(BaseModel):
    when: datetime
    where: bytes
    why: str = 'No idea'


m = Meeting(when='2020-01-01T12:00', where='home')
print(m.model_dump(exclude_unset=True))
#> {'when': datetime.datetime(2020, 1, 1, 12, 0), 'where': b'home'}
print(m.model_dump(exclude={'where'}, mode='json'))
#> {'when': '2020-01-01T12:00:00', 'why': 'No idea'}
print(m.model_dump_json(exclude_defaults=True))
#> {"when":"2020-01-01T12:00:00","where":"home"}

উদাহরণটি সহজ ভাষায়

  • model_dump(exclude_unset=True): শুধু যে ফিল্ডগুলো আসলে দেওয়া হয়েছিল সেগুলো, Python অবজেক্ট হিসেবে (তারিখ থাকে datetime, where থাকে bytes)। why দেওয়া হয়নি, তাই বাদ।
  • model_dump(exclude={'where'}, mode='json'): where বাদ দিয়ে, আর সব মান JSON-যোগ্য রূপে (তারিখ হয়ে যায় স্ট্রিং)।
  • model_dump_json(exclude_defaults=True): সরাসরি JSON স্ট্রিং, যে ফিল্ডের মান ডিফল্টের সমান (why) তা বাদ দিয়ে।

আরও জানুন

দেখুন সিরিয়ালাইজেশন নিয়ে ডকুমেন্টেশন।

JSON Schema¶

যেকোনো Pydantic স্কিমা থেকে একটি JSON Schema তৈরি করা যায় — ফলে নিজেই নিজের ডকুমেন্টেশন দেয় এমন API তৈরি করা যায়, আর JSON Schema ফরম্যাট সমর্থন করে এমন অনেক টুলের সাথে যুক্ত হওয়া যায়।

উদাহরণ - JSON Schema 
from datetime import datetime

from pydantic import BaseModel


class Address(BaseModel):
    street: str
    city: str
    zipcode: str


class Meeting(BaseModel):
    when: datetime
    where: Address
    why: str = 'No idea'


print(Meeting.model_json_schema())
"""
{
    '$defs': {
        'Address': {
            'properties': {
                'street': {'title': 'Street', 'type': 'string'},
                'city': {'title': 'City', 'type': 'string'},
                'zipcode': {'title': 'Zipcode', 'type': 'string'},
            },
            'required': ['street', 'city', 'zipcode'],
            'title': 'Address',
            'type': 'object',
        }
    },
    'properties': {
        'when': {'format': 'date-time', 'title': 'When', 'type': 'string'},
        'where': {'$ref': '#/$defs/Address'},
        'why': {'default': 'No idea', 'title': 'Why', 'type': 'string'},
    },
    'required': ['when', 'where'],
    'title': 'Meeting',
    'type': 'object',
}
"""

উদাহরণটি সহজ ভাষায়

Meeting.model_json_schema() মডেলটির একটি "মানচিত্র" দেয়: কোন ফিল্ড কোন টাইপের (when তারিখ-সময় স্ট্রিং, why স্ট্রিং যার ডিফল্ট আছে), কোনগুলো বাধ্যতামূলক (required), আর নেস্টেড মডেল Address আলাদা করে $defs-এ রাখা হয়েছে আর $ref দিয়ে উল্লেখ করা হয়েছে। FastAPI ঠিক এই JSON Schema দিয়েই /docs পেজ তৈরি করে।

Pydantic JSON Schema স্পেসিফিকেশনের সর্বশেষ সংস্করণ (2020-12) মেনে চলে, যা OpenAPI 3.1-এর সাথে সামঞ্জস্যপূর্ণ।

আরও জানুন

দেখুন JSON Schema নিয়ে ডকুমেন্টেশন।

Strict মোড আর ডেটা রূপান্তর¶

ডিফল্টভাবে, Pydantic প্রচলিত ভুল টাইপের প্রতি সহনশীল আর ডেটাকে সঠিক টাইপে রূপান্তর করে — যেমন একটি int ফিল্ডে সংখ্যাসূচক স্ট্রিং দিলে সেটি int হিসেবে পার্স হবে।

Pydantic-এ একটি strict মোড-ও আছে, যেখানে টাইপ রূপান্তর করা হয় না, আর ইনপুট ডেটা প্রত্যাশিত স্কিমার সাথে হুবহু না মিললে একটি যাচাই এরর হয়।

কিন্তু JSON ডেটা যাচাইয়ের সময় strict মোড প্রায় অকেজো হতো, কারণ JSON-এ অনেক প্রচলিত Python টাইপের সমতুল্য টাইপ নেই, যেমন datetime, UUID বা bytes।

এর সমাধানে, Pydantic এক ধাপেই JSON পার্স আর যাচাই করতে পারে। এতে যুক্তিসঙ্গত ডেটা রূপান্তর সম্ভব হয় (যেমন স্ট্রিংকে datetime অবজেক্টে পার্স করা)। যেহেতু JSON পার্সিং Rust-এ বাস্তবায়িত, তাই এটি খুবই দ্রুতও।

উদাহরণ - এমন strict মোড যা সত্যিই কাজের 
from datetime import datetime

from pydantic import BaseModel, ValidationError


class Meeting(BaseModel):
    when: datetime
    where: bytes


m = Meeting.model_validate({'when': '2020-01-01T12:00', 'where': 'home'})
print(m)
#> when=datetime.datetime(2020, 1, 1, 12, 0) where=b'home'
try:
    m = Meeting.model_validate(
        {'when': '2020-01-01T12:00', 'where': 'home'}, strict=True
    )
except ValidationError as e:
    print(e)
    """
    2 validation errors for Meeting
    when
      Input should be a valid datetime [type=datetime_type, input_value='2020-01-01T12:00', input_type=str]
    where
      Input should be a valid bytes [type=bytes_type, input_value='home', input_type=str]
    """

m_json = Meeting.model_validate_json(
    '{"when": "2020-01-01T12:00", "where": "home"}'
)
print(m_json)
#> when=datetime.datetime(2020, 1, 1, 12, 0) where=b'home'

উদাহরণটি সহজ ভাষায়

  • সাধারণ model_validate (lax): স্ট্রিং তারিখ আর স্ট্রিং 'home' দুটোই রূপান্তর হয়ে গেল।
  • strict=True দিলে: Python ডিকশনারিতে তারিখ স্ট্রিং হিসেবে এলে গ্রহণ করে না, দুটি এরর দেয়।
  • কিন্তু model_validate_json দিয়ে JSON থেকে পড়লে: JSON-এ তো তারিখ লেখার একমাত্র উপায় স্ট্রিং, তাই সেখানে স্ট্রিং থেকে তারিখ গ্রহণযোগ্য। এভাবে strict মোড JSON-এর সাথেও বাস্তবসম্মতভাবে কাজ করে।

আরও জানুন

দেখুন strict মোড নিয়ে ডকুমেন্টেশন।

Dataclass, TypedDict, এবং আরও¶

স্কিমা তৈরি করে যাচাই আর সিরিয়ালাইজেশনের জন্য Pydantic চারটি উপায় দেয়:

  1. BaseModel — Pydantic-এর নিজস্ব প্যারেন্ট ক্লাস, যাতে ইনস্ট্যান্স মেথডের মাধ্যমে অনেক প্রচলিত সুবিধা পাওয়া যায়।
  2. Pydantic dataclass — স্ট্যান্ডার্ড dataclass-এর ওপর একটি মোড়ক, যাতে বাড়তি যাচাই হয়।
  3. TypeAdapter — যেকোনো টাইপকে যাচাই আর সিরিয়ালাইজেশনের উপযোগী করার একটি সাধারণ উপায়। এতে TypedDict আর NamedTuple-এর মতো টাইপ যাচাই করা যায়, সাথে সাধারণ টাইপও (যেমন int বা timedelta) — সমর্থিত সব টাইপ TypeAdapter-এর সাথে ব্যবহার করা যায়।
  4. validate_call — একটি ডেকোরেটর, যা একটি ফাংশন কল করার সময় যাচাই করে।
উদাহরণ - একটি TypedDict-এর ওপর ভিত্তি করে স্কিমা 
from datetime import datetime

from typing_extensions import NotRequired, TypedDict

from pydantic import TypeAdapter


class Meeting(TypedDict):
    when: datetime
    where: bytes
    why: NotRequired[str]


meeting_adapter = TypeAdapter(Meeting)
m = meeting_adapter.validate_python(  # (1)!
    {'when': '2020-01-01T12:00', 'where': 'home'}
)
print(m)
#> {'when': datetime.datetime(2020, 1, 1, 12, 0), 'where': b'home'}
meeting_adapter.dump_python(m, exclude={'where'})  # (2)!

print(meeting_adapter.json_schema())  # (3)!
"""
{
    'properties': {
        'when': {'format': 'date-time', 'title': 'When', 'type': 'string'},
        'where': {'format': 'binary', 'title': 'Where', 'type': 'string'},
        'why': {'title': 'Why', 'type': 'string'},
    },
    'required': ['when', 'where'],
    'title': 'Meeting',
    'type': 'object',
}
"""
  1. একটি TypedDict-এর জন্য TypeAdapter যাচাই করছে, এটি validate_json দিয়ে সরাসরি JSON ডেটাও যাচাই করতে পারে।
  2. dump_python দিয়ে একটি TypedDict-কে Python অবজেক্টে সিরিয়ালাইজ করা, এটি dump_json দিয়ে JSON-এও সিরিয়ালাইজ করতে পারে।
  3. TypeAdapter একটি JSON Schema-ও তৈরি করতে পারে।

উদাহরণ দিয়ে বুঝি

চারটি উপায়কে চার রকম পাত্রের মতো ভাবুন, ভেতরের "পরীক্ষক" কিন্তু একই। BaseModel হলো সব সুবিধাসহ পূর্ণ বাক্স, dataclass হলো পরিচিত Python বাক্সে পরীক্ষা যোগ করা, TypeAdapter হলো যেকোনো জিনিসে (এমনকি শুধু int বা একটি TypedDict) পরীক্ষক লাগানোর অ্যাডাপ্টার, আর validate_call হলো ফাংশনের দরজায় পরীক্ষক বসানো।

কাস্টমাইজেশন¶

Functional validator আর serializer, সাথে কাস্টম টাইপের জন্য একটি শক্তিশালী প্রোটোকল থাকায়, Pydantic কীভাবে কাজ করবে তা প্রতিটি ফিল্ড বা প্রতিটি টাইপ ধরে নিজের মতো করা যায়।

কাস্টমাইজেশনের উদাহরণ - wrap validator

"wrap validator" Pydantic V2-তে নতুন, আর যাচাই নিজের মতো করার সবচেয়ে শক্তিশালী উপায়গুলোর একটি।

from datetime import datetime, timezone
from typing import Any

from pydantic_core.core_schema import ValidatorFunctionWrapHandler

from pydantic import BaseModel, field_validator


class Meeting(BaseModel):
    when: datetime

    @field_validator('when', mode='wrap')
    def when_now(
        cls, input_value: Any, handler: ValidatorFunctionWrapHandler
    ) -> datetime:
        if input_value == 'now':
            return datetime.now()
        when = handler(input_value)
        # in this specific application we know tz naive datetimes are in UTC
        if when.tzinfo is None:
            when = when.replace(tzinfo=timezone.utc)
        return when


print(Meeting(when='2020-01-01T12:00+01:00'))
#> when=datetime.datetime(2020, 1, 1, 12, 0, tzinfo=TzInfo(3600))
print(Meeting(when='now'))
#> when=datetime.datetime(2032, 1, 2, 3, 4, 5, 6)
print(Meeting(when='2020-01-01T12:00'))
#> when=datetime.datetime(2020, 1, 1, 12, 0, tzinfo=datetime.timezone.utc)

উদাহরণটি সহজ ভাষায়

mode='wrap' validator Pydantic-এর নিজের যাচাইকে "মুড়ে" রাখে: আগে-পরে নিজের কাজ করা যায়।

  • ইনপুট যদি 'now' হয়, Pydantic-এর যাচাই না চালিয়েই বর্তমান সময় ফেরত দেয়।
  • নইলে handler(input_value) দিয়ে Pydantic-এর স্বাভাবিক যাচাই চালায়।
  • তারপর ফলাফলে টাইমজোন না থাকলে UTC বসিয়ে দেয়।

আরও জানুন

দেখুন validator, কাস্টম serializer আর কাস্টম টাইপ নিয়ে ডকুমেন্টেশন।
