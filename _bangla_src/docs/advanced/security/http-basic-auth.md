# HTTP Basic Auth { #http-basic-auth }

/// note | এই পেজে যা শিখবেন

* সবচেয়ে সহজ লগইন ব্যবস্থা HTTP Basic Auth, যেখানে ব্রাউজার নিজেই ইউজারনেম-পাসওয়ার্ড চায়।
* `secrets.compare_digest()` দিয়ে নিরাপদে ইউজারনেম-পাসওয়ার্ড মেলানো।
* "টাইমিং অ্যাটাক" কী, আর কেন সাধারণ `==` দিয়ে তুলনা বিপজ্জনক।

///

সবচেয়ে সহজ ক্ষেত্রগুলোর জন্য HTTP Basic Auth ব্যবহার করতে পারেন।

HTTP Basic Auth-এ অ্যাপ্লিকেশনটি একটি হেডার আশা করে, যাতে একটি ইউজারনেম আর একটি পাসওয়ার্ড থাকে।

এটি না পেলে একটি HTTP ৪০১ "Unauthorized" এরর ফেরত দেয়।

আর `Basic` মান আর একটি ঐচ্ছিক `realm` প্যারামিটারসহ একটি `WWW-Authenticate` হেডার ফেরত দেয়।

এটি ব্রাউজারকে ইউজারনেম আর পাসওয়ার্ডের জন্য তার নিজস্ব একটি ছোট লগইন বক্স দেখাতে বলে।

তারপর আপনি ওই ইউজারনেম আর পাসওয়ার্ড লিখলে ব্রাউজার স্বয়ংক্রিয়ভাবে সেগুলো হেডারে পাঠায়।

/// tip | কখন ব্যবহার করবেন

অভ্যন্তরীণ টুল, অ্যাডমিন পেজ বা পরীক্ষামূলক API-এর মতো ছোট ক্ষেত্রের জন্য এটি দ্রুত ও সহজ। তবে পাসওয়ার্ড প্রতিটি রিকোয়েস্টে যায় (Base64-এ, যা এনক্রিপশন নয়), তাই অবশ্যই HTTPS-এর সাথে ব্যবহার করবেন। বড় অ্যাপের জন্য টোকেন-ভিত্তিক (JWT) লগইন ভালো।

///

## সহজ HTTP Basic Auth { #simple-http-basic-auth }

* `HTTPBasic` আর `HTTPBasicCredentials` ইমপোর্ট করুন।
* `HTTPBasic` ব্যবহার করে একটি "`security` স্কিম" তৈরি করুন।
* আপনার *পাথ অপারেশনে* একটি ডিপেন্ডেন্সিসহ ওই `security` ব্যবহার করুন।
* এটি `HTTPBasicCredentials` টাইপের একটি অবজেক্ট ফেরত দেয়:
    * এতে পাঠানো `username` আর `password` থাকে।

## ইউজারনেম যাচাই করুন { #check-the-username }

এখানে আরও পূর্ণাঙ্গ একটি উদাহরণ।

ইউজারনেম আর পাসওয়ার্ড সঠিক কিনা যাচাই করতে একটি ডিপেন্ডেন্সি ব্যবহার করুন।

এর জন্য ইউজারনেম আর পাসওয়ার্ড যাচাই করতে Python-এর স্ট্যান্ডার্ড মডিউল [`secrets`](https://docs.python.org/3/library/secrets.html) ব্যবহার করুন।

`secrets.compare_digest()`-কে `bytes` বা এমন একটি `str` নিতে হয় যাতে শুধু ASCII অক্ষর (ইংরেজির অক্ষর) আছে, এর মানে এটি `Sebastián`-এর `á`-এর মতো অক্ষরে (বা বাংলা অক্ষরে) কাজ করবে না।

এটি সামলাতে আমরা প্রথমে `username` আর `password`-কে UTF-8 দিয়ে এনকোড করে `bytes`-এ রূপান্তর করি।

তারপর `secrets.compare_digest()` ব্যবহার করে নিশ্চিত হতে পারি যে `credentials.username` হলো `"stanleyjobson"`, আর `credentials.password` হলো `"swordfish"`।

{* ../../docs_src/security/tutorial007_an_py310.py hl[1,12:24] *}

এটি এর মতো হতো:

```Python
if not (credentials.username == "stanleyjobson") or not (credentials.password == "swordfish"):
    # কোনো একটি এরর ফেরত দিন
    ...
```

কিন্তু `secrets.compare_digest()` ব্যবহার করলে এটি "টাইমিং অ্যাটাক" নামের এক ধরনের আক্রমণের বিরুদ্ধে নিরাপদ থাকবে।

### টাইমিং অ্যাটাক { #timing-attacks }

কিন্তু "টাইমিং অ্যাটাক" কী?

কল্পনা করুন কিছু আক্রমণকারী ইউজারনেম আর পাসওয়ার্ড অনুমান করার চেষ্টা করছে।

আর তারা ইউজারনেম `johndoe` আর পাসওয়ার্ড `love123` দিয়ে একটি রিকোয়েস্ট পাঠায়।

তখন আপনার অ্যাপ্লিকেশনের Python কোড এরকম কিছুর সমতুল্য হবে:

```Python
if "johndoe" == "stanleyjobson" and "love123" == "swordfish":
    ...
```

কিন্তু Python যে মুহূর্তে `johndoe`-এর প্রথম `j`-কে `stanleyjobson`-এর প্রথম `s`-এর সাথে তুলনা করবে, তখনই এটি `False` ফেরত দেবে, কারণ এটি ইতিমধ্যে জেনে গেছে যে দুটি স্ট্রিং এক নয়, ভাবছে "বাকি অক্ষরগুলো তুলনা করে আর হিসাব নষ্ট করার দরকার নেই"। আর আপনার অ্যাপ্লিকেশন বলবে "Incorrect username or password"।

কিন্তু তারপর আক্রমণকারীরা ইউজারনেম `stanleyjobsox` আর পাসওয়ার্ড `love123` দিয়ে চেষ্টা করে।

আর আপনার অ্যাপ্লিকেশনের কোড এরকম কিছু করে:

```Python
if "stanleyjobsox" == "stanleyjobson" and "love123" == "swordfish":
    ...
```

দুটি স্ট্রিং যে এক নয় তা বোঝার আগে Python-কে `stanleyjobsox` আর `stanleyjobson` দুটোতেই পুরো `stanleyjobso` তুলনা করতে হবে। তাই "Incorrect username or password" উত্তর দিতে এটি কয়েক মাইক্রোসেকেন্ড বেশি সময় নেবে।

#### উত্তরের সময় আক্রমণকারীদের সাহায্য করে { #the-time-to-answer-helps-the-attackers }

এই পর্যায়ে, সার্ভার "Incorrect username or password" রেসপন্স পাঠাতে কয়েক মাইক্রোসেকেন্ড বেশি সময় নিয়েছে খেয়াল করে আক্রমণকারীরা জেনে যাবে যে তারা _কিছু একটা_ ঠিক পেয়েছে, শুরুর কিছু অক্ষর ঠিক ছিল।

আর তারপর তারা আবার চেষ্টা করতে পারে, এটা জেনে যে এটি সম্ভবত `johndoe`-এর চেয়ে `stanleyjobsox`-এর বেশি কাছাকাছি কিছু।

#### একটি "পেশাদার" আক্রমণ { #a-professional-attack }

অবশ্যই, আক্রমণকারীরা এসব হাতে হাতে চেষ্টা করবে না, তারা এটি করতে একটি প্রোগ্রাম লিখবে, সম্ভবত প্রতি সেকেন্ডে হাজার হাজার বা লক্ষ লক্ষ পরীক্ষাসহ। আর তারা একবারে একটি করে বাড়তি সঠিক অক্ষর পাবে।

কিন্তু এভাবে, কয়েক মিনিট বা কয়েক ঘণ্টায় আক্রমণকারীরা আমাদের অ্যাপ্লিকেশনের "সাহায্যে", শুধু উত্তর দিতে নেওয়া সময় ব্যবহার করে, সঠিক ইউজারনেম আর পাসওয়ার্ড অনুমান করে ফেলত।

/// tip | উদাহরণ দিয়ে বুঝি

একটি তালার কথা ভাবুন, যেখানে সংখ্যা মেলানোর সময় প্রথম ভুল সংখ্যাতেই "খট" করে শব্দ হয়। শব্দ কত দেরিতে হলো তা শুনে চোর বুঝে যায় কতগুলো সংখ্যা ঠিক হয়েছে, আর এক এক করে পুরো কোড বের করে ফেলে। `secrets.compare_digest()` এমন তালা, যা সবসময় সব সংখ্যা মিলিয়ে তারপর শব্দ করে, তাই কোনো সূত্র পাওয়া যায় না।

///

#### `secrets.compare_digest()` দিয়ে ঠিক করুন { #fix-it-with-secrets-compare-digest }

কিন্তু আমাদের কোডে আসলে আমরা `secrets.compare_digest()` ব্যবহার করছি।

সংক্ষেপে, `stanleyjobsox`-কে `stanleyjobson`-এর সাথে তুলনা করতে যে সময় লাগবে, `johndoe`-কে `stanleyjobson`-এর সাথে তুলনা করতেও সেই একই সময় লাগবে। পাসওয়ার্ডের ক্ষেত্রেও একই।

এভাবে আপনার অ্যাপ্লিকেশনের কোডে `secrets.compare_digest()` ব্যবহার করলে এটি এই পুরো ধরনের নিরাপত্তা আক্রমণের বিরুদ্ধে নিরাপদ থাকবে।

### এরর ফেরত দিন { #return-the-error }

ক্রেডেনশিয়াল ভুল তা শনাক্ত করার পরে, ৪০১ স্ট্যাটাস কোডসহ (কোনো ক্রেডেনশিয়াল না দিলে যেটি ফেরত যায়, সেটিই) একটি `HTTPException` ফেরত দিন, আর ব্রাউজার যাতে আবার লগইন বক্স দেখায় সেজন্য `WWW-Authenticate` হেডার যোগ করুন:

/// check | সংক্ষেপে মনে রাখুন

* `security = HTTPBasic()` আর `credentials: Annotated[HTTPBasicCredentials, Depends(security)]`।
* ইউজারনেম-পাসওয়ার্ড মেলাতে কখনো `==` নয়, `secrets.compare_digest(a_bytes, b_bytes)`।
* ভুল হলে ৪০১ আর `headers={"WWW-Authenticate": "Basic"}`, যাতে ব্রাউজার আবার লগইন বক্স দেখায়।
* সবসময় HTTPS-এর সাথে ব্যবহার করুন।
