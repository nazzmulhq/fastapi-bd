# কঠোর Content-Type যাচাই { #strict-content-type-checking }

/// note | এই পেজে যা শিখবেন

* `Content-Type` হেডার কী, আর FastAPI কেন JSON বডির জন্য এটি বাধ্যতামূলক রাখে।
* CSRF আক্রমণ কী, আর কোন বিশেষ পরিস্থিতিতে এটি বিপজ্জনক।
* দরকার হলে `strict_content_type=False` দিয়ে এই যাচাই বন্ধ করা।

///

ডিফল্টভাবে **FastAPI** JSON রিকোয়েস্ট বডির জন্য কঠোরভাবে `Content-Type` হেডার যাচাই করে। এর মানে, বডিকে JSON হিসেবে পার্স করার জন্য JSON রিকোয়েস্টে একটি বৈধ `Content-Type` হেডার (যেমন `application/json`) **অবশ্যই** থাকতে হবে।

(`Content-Type` হেডার হলো রিকোয়েস্টের গায়ে লাগানো লেবেল, যা বলে দেয় ভেতরের ডেটা কোন ধরনের: JSON, ফর্ম, ছবি ইত্যাদি।)

## CSRF ঝুঁকি { #csrf-risk }

এই ডিফল্ট আচরণটি একটি খুবই নির্দিষ্ট পরিস্থিতিতে এক ধরনের **Cross-Site Request Forgery (CSRF)** আক্রমণ থেকে সুরক্ষা দেয়।

/// tip | উদাহরণ দিয়ে বুঝি

**CSRF** মানে একটি ক্ষতিকর ওয়েবসাইট আপনার ব্রাউজারকে দিয়ে গোপনে অন্য একটি সাইটে (যেখানে আপনার প্রবেশাধিকার আছে) রিকোয়েস্ট পাঠায়, যেন আপনিই পাঠিয়েছেন। অনেকটা কেউ আপনার হাতের লেখা নকল করে আপনার নামে ব্যাংকে চিঠি পাঠানোর মতো।

**CORS preflight** হলো ব্রাউজারের একটি নিরাপত্তা প্রহরী: অন্য সাইটে "অস্বাভাবিক" রিকোয়েস্ট পাঠানোর আগে ব্রাউজার সেই সাইটকে জিজ্ঞেস করে, "এই সাইট থেকে রিকোয়েস্ট নেবেন?" (বিস্তারিত দেখুন [CORS](../tutorial/cors.md) পেজে।)

///

এই আক্রমণগুলো একটি সুযোগ কাজে লাগায়: ব্রাউজার স্ক্রিপ্টকে কোনো CORS preflight যাচাই ছাড়াই রিকোয়েস্ট পাঠাতে দেয়, যখন রিকোয়েস্টগুলো:

* কোনো `Content-Type` হেডার রাখে না (যেমন `Blob` বডিসহ `fetch()` ব্যবহার করে)
* আর কোনো অথেনটিকেশন তথ্য পাঠায় না।

এই ধরনের আক্রমণ মূলত প্রাসঙ্গিক যখন:

* অ্যাপ্লিকেশনটি লোকালি (যেমন `localhost`-এ) বা একটি অভ্যন্তরীণ নেটওয়ার্কে চলছে
* আর অ্যাপ্লিকেশনে কোনো অথেনটিকেশন নেই, এটি ধরে নেয় যে একই নেটওয়ার্ক থেকে আসা যেকোনো রিকোয়েস্ট বিশ্বাসযোগ্য।

## আক্রমণের উদাহরণ { #example-attack }

ধরুন আপনি একটি লোকাল AI এজেন্ট চালানোর ব্যবস্থা তৈরি করলেন।

এটি একটি API দেয় এখানে:

```
http://localhost:8000/v1/agents/multivac
```

আর একটি ফ্রন্টএন্ডও আছে এখানে:

```
http://localhost:8000
```

/// tip | পরামর্শ

লক্ষ্য করুন, দুটোরই host একই।

///

তারপর ফ্রন্টএন্ড ব্যবহার করে আপনি AI এজেন্টকে দিয়ে আপনার হয়ে কাজ করাতে পারেন।

যেহেতু এটি খোলা ইন্টারনেটে নয়, **লোকালি** চলছে, তাই আপনি সিদ্ধান্ত নিলেন যে **কোনো অথেনটিকেশন রাখবেন না**, শুধু লোকাল নেটওয়ার্কে প্রবেশাধিকারের ওপর ভরসা করবেন।

তারপর আপনার একজন ব্যবহারকারী এটি ইনস্টল করে লোকালি চালাতে পারেন।

তারপর তিনি একটি ক্ষতিকর ওয়েবসাইট খুলতে পারেন, যেমন এমন কিছু:

```
https://evilhackers.example.com
```

আর সেই ক্ষতিকর ওয়েবসাইট `Blob` বডিসহ `fetch()` ব্যবহার করে লোকাল API-তে রিকোয়েস্ট পাঠায় এখানে:

```
http://localhost:8000/v1/agents/multivac
```

ক্ষতিকর ওয়েবসাইট আর লোকাল অ্যাপের host আলাদা হলেও, ব্রাউজার একটি CORS preflight রিকোয়েস্ট চালু করবে না, কারণ:

* এটি কোনো অথেনটিকেশন ছাড়া চলছে, তাই কোনো লগইন তথ্য পাঠাতে হয় না।
* ব্রাউজার মনে করে এটি JSON পাঠাচ্ছে না (কারণ `Content-Type` হেডার নেই)।

তারপর ক্ষতিকর ওয়েবসাইটটি লোকাল AI এজেন্টকে দিয়ে ব্যবহারকারীর সাবেক বসকে রাগী বার্তা পাঠাতে পারে... বা এর চেয়েও খারাপ কিছু। 😅

/// info | FastAPI কীভাবে এটি আটকায়

যেহেতু FastAPI `Content-Type` ছাড়া আসা বডিকে JSON হিসেবে গ্রহণ করে না, তাই ক্ষতিকর সাইটের পাঠানো এমন রিকোয়েস্ট যাচাইয়ে ব্যর্থ হয়। আর যদি আক্রমণকারী `Content-Type: application/json` যোগ করে, তাহলে ব্রাউজার আগে CORS preflight পাঠায়, যা আপনার অ্যাপ অনুমতি না দিলে আটকে যায়। দুই দিক থেকেই আক্রমণ বন্ধ।

///

## খোলা ইন্টারনেট { #open-internet }

যদি আপনার অ্যাপ খোলা ইন্টারনেটে থাকে, তাহলে আপনি "নেটওয়ার্ককে বিশ্বাস" করে যে কাউকে অথেনটিকেশন ছাড়া বিশেষ ক্ষমতাসম্পন্ন রিকোয়েস্ট পাঠাতে দেবেন না।

আক্রমণকারীরা ব্রাউজার ছাড়াই সরাসরি একটি স্ক্রিপ্ট চালিয়ে আপনার API-তে রিকোয়েস্ট পাঠাতে পারে, তাই আপনি সম্ভবত ইতিমধ্যে সব বিশেষ ক্ষমতাসম্পন্ন এন্ডপয়েন্ট সুরক্ষিত করছেন।

সেই ক্ষেত্রে **এই আক্রমণ / ঝুঁকি আপনার জন্য প্রযোজ্য নয়**।

এই ঝুঁকি আর আক্রমণ মূলত প্রাসঙ্গিক যখন অ্যাপটি **লোকাল নেটওয়ার্কে** চলে আর সেটিই **একমাত্র ধরে নেওয়া সুরক্ষা**।

## Content-Type ছাড়া রিকোয়েস্ট অনুমোদন করা { #allowing-requests-without-content-type }

যদি এমন ক্লায়েন্ট সাপোর্ট করতে হয় যারা `Content-Type` হেডার পাঠায় না, তাহলে `strict_content_type=False` সেট করে কঠোর যাচাই বন্ধ করতে পারেন:

{* ../../docs_src/strict_content_type/tutorial001_py310.py hl[4] *}

এই সেটিংয়ে, `Content-Type` হেডার ছাড়া আসা রিকোয়েস্টের বডিও JSON হিসেবে পার্স হবে, যা FastAPI-এর পুরনো সংস্করণগুলোর আচরণের মতোই।

/// warning | সতর্কতা

শুধু তখনই `strict_content_type=False` ব্যবহার করুন যখন সত্যিই দরকার, আর নিশ্চিত হন যে আপনার অ্যাপে সঠিক অথেনটিকেশন আছে বা এটি ওপরে বর্ণিত লোকাল-নেটওয়ার্ক পরিস্থিতিতে চলছে না।

* এটি লোকাল, অথেনটিকেশনহীন অ্যাপকে ক্ষতিকর ওয়েবসাইটের CSRF আক্রমণ থেকে বাঁচায়।
* পুরনো ক্লায়েন্টের জন্য `FastAPI(strict_content_type=False)` দিয়ে বন্ধ করা যায়, তবে সাবধানে।
