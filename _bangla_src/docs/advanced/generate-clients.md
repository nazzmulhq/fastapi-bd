# SDK তৈরি করা { #generating-sdks }

/// note | এই পেজে যা শিখবেন

* SDK বা "ক্লায়েন্ট লাইব্রেরি" কী, আর কেন হাতে লেখার বদলে স্বয়ংক্রিয়ভাবে তৈরি করা ভালো।
* Hey API দিয়ে আপনার FastAPI ব্যাকএন্ডের জন্য একটি TypeScript SDK তৈরি করা।
* tag আর কাস্টম operation ID দিয়ে সুন্দর মেথডের নাম পাওয়া।

///

যেহেতু **FastAPI** **OpenAPI** স্পেসিফিকেশনের ওপর ভিত্তি করে তৈরি, তাই এর API-গুলো একটি স্ট্যান্ডার্ড ফরম্যাটে বর্ণনা করা যায় যা অনেক টুল বোঝে।

এতে হালনাগাদ **ডকুমেন্টেশন**, একাধিক ভাষায় ক্লায়েন্ট লাইব্রেরি (<abbr title="Software Development Kits">**SDKs**</abbr>), আর আপনার কোডের সাথে মিল রেখে চলা **টেস্টিং** বা **অটোমেশন ওয়ার্কফ্লো** তৈরি করা সহজ হয়।

এই গাইডে আপনি শিখবেন কীভাবে আপনার FastAPI ব্যাকএন্ডের জন্য একটি **TypeScript SDK** তৈরি করতে হয়।

/// tip | উদাহরণ দিয়ে বুঝি

ধরুন আপনার ব্যাকএন্ড FastAPI-তে আর ফ্রন্টএন্ড React/TypeScript-এ। ফ্রন্টএন্ড ডেভেলপারকে প্রতিটি এন্ডপয়েন্টের জন্য হাতে `fetch("/items/", ...)` লিখতে হয়, আর কোন ফিল্ডের নাম কী তা মুখস্থ রাখতে হয়। SDK হলো একটি তৈরি "রিমোট কন্ট্রোল": `ItemsService.createItem(...)` এর মতো ফাংশন, যেখানে এডিটর নিজেই বলে দেয় কোন ফিল্ড লাগবে। আর এই রিমোট কন্ট্রোল আপনার OpenAPI স্কিমা থেকে এক কমান্ডে তৈরি হয়।

///

## ওপেন সোর্স SDK জেনারেটর { #open-source-sdk-generators }

একটি বহুমুখী অপশন হলো [OpenAPI Generator](https://openapi-generator.tech/), যা **অনেক প্রোগ্রামিং ভাষা** সাপোর্ট করে আর আপনার OpenAPI স্পেসিফিকেশন থেকে SDK তৈরি করতে পারে।

**TypeScript ক্লায়েন্টের** জন্য [Hey API](https://heyapi.dev/) একটি বিশেষভাবে তৈরি সমাধান, যা TypeScript জগতের জন্য উপযোগী অভিজ্ঞতা দেয়।

আরও SDK জেনারেটর খুঁজে পাবেন [OpenAPI.Tools](https://openapi.tools/categories/sdk-generators)-এ।

/// tip | পরামর্শ

FastAPI স্বয়ংক্রিয়ভাবে **OpenAPI 3.1** স্পেসিফিকেশন তৈরি করে, তাই আপনি যে টুলই ব্যবহার করুন, তাকে এই সংস্করণ সাপোর্ট করতে হবে।

একটি সহজ FastAPI অ্যাপ্লিকেশন দিয়ে শুরু করি:

{* ../../docs_src/generate_clients/tutorial001_py310.py hl[7:9,12:13,16:17,21] *}

লক্ষ্য করুন, *পাথ অপারেশনগুলো* রিকোয়েস্ট আর রেসপন্সের ডেটার জন্য যে মডেল ব্যবহার করে তা নির্ধারণ করে দিয়েছে, `Item` আর `ResponseMessage` মডেল ব্যবহার করে।

/// info | কোডটি সহজ ভাষায়

* লাইন ৭–৯: `Item` মডেল (`name`, `price`), যা ক্লায়েন্ট পাঠাবে।
* লাইন ১২–১৩: `ResponseMessage` মডেল, যা সার্ভার উত্তরে দেবে।
* লাইন ১৬–১৭: `response_model=ResponseMessage` আর `item: Item` থেকে OpenAPI জানে কী ঢুকবে আর কী বের হবে।
* লাইন ২১: `response_model=list[Item]` মানে উত্তর হবে `Item`-এর একটি তালিকা।

এই মডেলগুলো যত স্পষ্ট, তৈরি হওয়া SDK তত ভালো হবে।

সেই তথ্য অ্যাপের **OpenAPI স্কিমায়** থাকে, তারপর API ডকসে দেখানো হয়।

### Hey API { #hey-api }

মডেলসহ একটি FastAPI অ্যাপ হয়ে গেলে আমরা Hey API দিয়ে একটি TypeScript ক্লায়েন্ট তৈরি করতে পারি। এটি করার দ্রুততম উপায় হলো npx।

```sh
npx @hey-api/openapi-ts -i http://localhost:8000/openapi.json -o src/client
```

এটি `./src/client`-এ একটি TypeScript SDK তৈরি করবে।

(এখানে `-i` মানে ইনপুট, অর্থাৎ আপনার চলমান অ্যাপের OpenAPI JSON, আর `-o` মানে আউটপুট ফোল্ডার।)

কীভাবে [`@hey-api/openapi-ts` ইনস্টল করবেন](https://heyapi.dev/openapi-ts/get-started) আর [তৈরি হওয়া আউটপুট](https://heyapi.dev/openapi-ts/output) সম্পর্কে তাদের ওয়েবসাইটে পড়তে পারেন।

### ক্লায়েন্ট মেথডের নাম { #client-method-names }

এই মুহূর্তে তৈরি হওয়া মেথডের নামগুলো, যেমন `createItemItemsPost`, খুব পরিষ্কার দেখায় না:

```TypeScript
ItemsService.createItemItemsPost({name: "Plumbus", price: 5})
```

...কারণ ক্লায়েন্ট জেনারেটর প্রতিটি *পাথ অপারেশনের* জন্য OpenAPI-এর অভ্যন্তরীণ **operation ID** ব্যবহার করে।

OpenAPI-তে প্রতিটি operation ID সব *পাথ অপারেশনের* মধ্যে অনন্য (unique) হতে হয়, তাই FastAPI সেই operation ID তৈরি করতে **ফাংশনের নাম**, **পাথ** আর **HTTP মেথড/অপারেশন** ব্যবহার করে, কারণ এভাবে এটি নিশ্চিত করতে পারে যে operation ID-গুলো অনন্য।

(তাই `create_item` + `/items/` + `POST` মিলে হয়েছে `createItemItemsPost`।)

তবে এরপর দেখাব কীভাবে এটি উন্নত করা যায়। 🤓

## কাস্টম operation ID আর ভালো মেথডের নাম { #custom-operation-ids-and-better-method-names }

এই operation ID-গুলো যেভাবে **তৈরি** হয় তা **পরিবর্তন** করে এগুলোকে সহজ করা যায়, আর ক্লায়েন্টে **সহজ মেথডের নাম** পাওয়া যায়।

এই ক্ষেত্রে আপনাকে অন্য কোনোভাবে নিশ্চিত করতে হবে যে প্রতিটি operation ID **অনন্য**।

যেমন, নিশ্চিত করতে পারেন যে প্রতিটি *পাথ অপারেশনের* একটি tag আছে, তারপর **tag** আর *পাথ অপারেশনের* **নাম** (ফাংশনের নাম) দিয়ে operation ID তৈরি করতে পারেন।

### কাস্টম Unique ID তৈরির ফাংশন { #custom-generate-unique-id-function }

FastAPI প্রতিটি *পাথ অপারেশনের* জন্য একটি **unique ID** ব্যবহার করে, যা **operation ID**-র জন্য আর রিকোয়েস্ট বা রেসপন্সের জন্য দরকারি কাস্টম মডেলের নামের জন্যও ব্যবহার হয়।

আপনি সেই ফাংশনটি নিজের মতো করে নিতে পারেন। এটি একটি `APIRoute` নেয় আর একটি স্ট্রিং ফেরত দেয়।

যেমন, এখানে এটি প্রথম tag (সম্ভবত আপনার একটিই tag থাকবে) আর *পাথ অপারেশনের* নাম (ফাংশনের নাম) ব্যবহার করছে।

তারপর সেই কাস্টম ফাংশনটি **FastAPI**-তে `generate_unique_id_function` প্যারামিটার হিসেবে দিতে পারেন:

{* ../../docs_src/generate_clients/tutorial003_py310.py hl[6:7,10] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ৬–৭: `custom_generate_unique_id` প্রতিটি রাউটের প্রথম tag আর ফাংশনের নাম জুড়ে ID বানায়, যেমন `items-create_item`।
* লাইন ১০: `FastAPI(generate_unique_id_function=...)` দিয়ে FastAPI-কে এই নতুন নিয়ম ব্যবহার করতে বলা হয়।

খেয়াল রাখুন: এই নিয়মে প্রতিটি পাথ অপারেশনে অন্তত একটি tag থাকতেই হবে, নইলে `route.tags[0]` এরর দেবে।

### ক্লায়েন্ট জেনারেটরের জন্য OpenAPI স্পেসিফিকেশন আগে থেকে প্রসেস করা { #preprocess-the-openapi-specification-for-the-client-generator }

তৈরি হওয়া কোডে এখনো কিছু **একই তথ্য দুবার** আছে।

আমরা ইতিমধ্যে জানি যে এই মেথডটি **items**-এর সাথে সম্পর্কিত, কারণ শব্দটি `ItemsService`-এ আছে (tag থেকে নেওয়া), কিন্তু মেথডের নামের শুরুতেও tag-এর নাম আছে। 😕

সাধারণভাবে OpenAPI-র জন্য আমরা সম্ভবত এটি রাখতেই চাইব, কারণ এতে operation ID-গুলো **অনন্য** থাকা নিশ্চিত হয়।

কিন্তু তৈরি হওয়া ক্লায়েন্টের জন্য, ক্লায়েন্ট তৈরির ঠিক আগে OpenAPI operation ID-গুলো **পরিবর্তন** করতে পারি, শুধু মেথডের নামগুলো আরও সুন্দর আর **পরিচ্ছন্ন** করতে।

আমরা OpenAPI JSON একটি `openapi.json` ফাইলে ডাউনলোড করে, তারপর এমন একটি স্ক্রিপ্ট দিয়ে **শুরুর tag-টি সরিয়ে** দিতে পারি:

* লাইন ৭–১৩: প্রতিটি পাথ আর প্রতিটি অপারেশন ঘুরে, `operationId`-এর শুরু থেকে `"items-"` এর মতো tag অংশটি কেটে ফেলা হয়।
* লাইন ১৫: পরিবর্তিত JSON আবার ফাইলে লেখা।

Node.js সংস্করণটিও একই কাজ করে, শুধু JavaScript-এ।

///

এতে operation ID-গুলো `items-get_items` এর মতো থেকে শুধু `get_items`-এ বদলে যাবে, ফলে ক্লায়েন্ট জেনারেটর সহজ মেথডের নাম তৈরি করতে পারবে।

### আগে থেকে প্রসেস করা OpenAPI দিয়ে একটি TypeScript ক্লায়েন্ট তৈরি করুন { #generate-a-typescript-client-with-the-preprocessed-openapi }

যেহেতু শেষ ফলাফল এখন একটি `openapi.json` ফাইলে আছে, তাই আপনার ইনপুটের ঠিকানা আপডেট করতে হবে:

```sh
npx @hey-api/openapi-ts -i ./openapi.json -o src/client
```

নতুন ক্লায়েন্ট তৈরির পরে এখন আপনার থাকবে **পরিচ্ছন্ন মেথডের নাম**, সাথে সব **অটোকমপ্লিশন**, **এডিটরে এরর** ইত্যাদি:

<img src="/img/tutorial/generate-clients/image08.png">

## সুবিধা { #benefits }

স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট ব্যবহার করলে আপনি **অটোকমপ্লিশন** পাবেন:

* মেথডের জন্য।
* বডিতে রিকোয়েস্টের ডেটা, কোয়েরি প্যারামিটার ইত্যাদির জন্য।
* রেসপন্সের ডেটার জন্য।

সবকিছুর জন্য **এডিটরে এরর**-ও দেখতে পাবেন।

আর যখনই ব্যাকএন্ড কোড আপডেট করে ফ্রন্টএন্ড **আবার তৈরি** করবেন, তখন যেকোনো নতুন *পাথ অপারেশন* মেথড হিসেবে পাওয়া যাবে, পুরনোগুলো সরে যাবে, আর অন্য যেকোনো পরিবর্তন তৈরি হওয়া কোডে প্রতিফলিত হবে। 🤓

এর মানে আরও, কিছু বদলালে তা স্বয়ংক্রিয়ভাবে ক্লায়েন্ট কোডে **প্রতিফলিত** হবে। আর ক্লায়েন্ট **build** করলে, ব্যবহৃত ডেটায় কোনো **অমিল** থাকলে এরর দেবে।

তাই প্রোডাকশনে আপনার চূড়ান্ত ব্যবহারকারীদের সামনে এরর দেখা দেওয়ার জন্য অপেক্ষা করে তারপর সমস্যা কোথায় খোঁজার বদলে, আপনি ডেভেলপমেন্টের একেবারে শুরুতেই **অনেক এরর ধরে ফেলবেন**। ✨
