# ডেটা স্ট্রিম করা { #stream-data }

/// note | এই পেজে যা শিখবেন

* JSON নয় এমন ডেটা (টেক্সট, বাইনারি, ছবি, ভিডিও) `StreamingResponse` দিয়ে টুকরো টুকরো পাঠানো।
* সঠিক `Content-Type` দিতে নিজের রেসপন্স ক্লাস বানানো।
* ফাইল পড়া কেন "ব্লকিং" হতে পারে আর কীভাবে সামলাবেন।

///

আপনি যদি এমন ডেটা স্ট্রিম করতে চান যা JSON আকারে সাজানো যায়, তাহলে [JSON Lines স্ট্রিম করা](../tutorial/stream-json-lines.md) ব্যবহার করা উচিত।

কিন্তু আপনি যদি **খাঁটি বাইনারি ডেটা** বা স্ট্রিং **স্ট্রিম** করতে চান, তাহলে এভাবে করতে পারেন।

/// note | নোট

FastAPI 0.134.0-এ যোগ হয়েছে।

///

## ব্যবহারের ক্ষেত্র { #use-cases }

খাঁটি স্ট্রিং স্ট্রিম করতে চাইলে এটি ব্যবহার করতে পারেন, যেমন সরাসরি একটি **AI LLM** সার্ভিসের আউটপুট থেকে।

**বড় বাইনারি ফাইল** স্ট্রিম করতেও এটি ব্যবহার করতে পারেন, যেখানে পুরোটা একবারে মেমরিতে না পড়ে, পড়ার সাথে সাথে প্রতিটি টুকরো (chunk) স্ট্রিম করেন। যেমন ১ GB-এর একটি ফাইল পাঠাতে ১ GB RAM লাগবে না।

এভাবে **ভিডিও** বা **অডিও**-ও স্ট্রিম করতে পারেন, এমনকি প্রসেস করে পাঠানোর সাথে সাথেই এটি তৈরিও হতে পারে।

## `yield`-সহ একটি `StreamingResponse` { #a-streamingresponse-with-yield }

আপনার *পাথ অপারেশন ফাংশনে* `response_class=StreamingResponse` ঘোষণা করলে, একে একে প্রতিটি ডেটার টুকরো পাঠাতে `yield` ব্যবহার করতে পারেন।

{* ../../docs_src/stream_data/tutorial001_py310.py ln[1:23] hl[20,23] *}

FastAPI প্রতিটি ডেটার টুকরো যেমন আছে তেমনই `StreamingResponse`-কে দেবে, এটিকে JSON বা এরকম কিছুতে রূপান্তরের চেষ্টা করবে না।

/// info | কোডটি সহজ ভাষায়

* লাইন ৯-১৭: একটি লম্বা গল্পের টেক্সট।
* লাইন ২০: `response_class=StreamingResponse` বলে দেয় যে রেসপন্স স্ট্রিম হবে।
* লাইন ২২-২৩: গল্পের প্রতিটি লাইন একে একে `yield` করা হচ্ছে, আর প্রতিটি সাথে সাথে ক্লায়েন্টের কাছে চলে যাচ্ছে।

### অ্যানোটেশন ছাড়া { #no-annotation }

বাইনারি ডেটা স্ট্রিম করার জন্য আসলে রিটার্ন টাইপ অ্যানোটেশন ঘোষণার দরকার নেই।

যেহেতু FastAPI Pydantic দিয়ে ডেটা JSON-এ রূপান্তর বা কোনোভাবে সিরিয়ালাইজ করার চেষ্টা করবে না, তাই এই ক্ষেত্রে টাইপ অ্যানোটেশন শুধু আপনার এডিটর আর টুলগুলোর ব্যবহারের জন্য, FastAPI এটি ব্যবহার করবে না।

{* ../../docs_src/stream_data/tutorial001_py310.py ln[32:35] hl[33] *}

এর আরও মানে, `StreamingResponse`-এর সাথে ডেটা বাইটগুলো ঠিক যেভাবে পাঠাতে চান সেভাবে তৈরি ও এনকোড করার **স্বাধীনতা** আর **দায়িত্ব** দুটোই আপনার, টাইপ অ্যানোটেশন যাই হোক। 🤓

## একটি কাস্টম `PNGStreamingResponse` { #a-custom-pngstreamingresponse }

ওপরের উদাহরণগুলোতে ডেটা বাইটগুলো স্ট্রিম হচ্ছিল, কিন্তু রেসপন্সে কোনো `Content-Type` হেডার ছিল না, তাই ক্লায়েন্ট জানত না সে কী ধরনের ডেটা পাচ্ছে।

আপনি `StreamingResponse`-এর একটি কাস্টম সাব-ক্লাস তৈরি করতে পারেন, যা `Content-Type` হেডারে আপনার স্ট্রিম করা ডেটার ধরন সেট করে।

যেমন, `media_type` অ্যাট্রিবিউট ব্যবহার করে `Content-Type` হেডার `image/png` সেট করে এমন একটি `PNGStreamingResponse` তৈরি করতে পারেন:

### একটি ফাইলের অভিনয় { #simulate-a-file }

এই উদাহরণে আমরা `io.BytesIO` দিয়ে একটি ফাইলের অভিনয় করছি। এটি একটি ফাইলের মতো অবজেক্ট, যা শুধু মেমরিতে থাকে, কিন্তু আমাদের একই ইন্টারফেস ব্যবহার করতে দেয়।

যেমন, ফাইলের মতোই এর ওপর লুপ চালিয়ে বিষয়বস্তু পড়তে পারি।

{* ../../docs_src/stream_data/tutorial002_py310.py ln[1:27] hl[3,12:13,25] *}

/// note | কারিগরি বিবরণ

অন্য দুটি ভেরিয়েবল, `image_base64` আর `binary_image`, হলো Base64-এ এনকোড করা একটি ছবি, যা পরে বাইটে রূপান্তর করে `io.BytesIO`-তে দেওয়া হয়।

শুধু এই উদাহরণে এটি যাতে একই ফাইলে থাকতে পারে আর আপনি কপি করে হুবহু চালাতে পারেন, সেজন্য। 🥚

///

একটি `with` ব্লক ব্যবহার করে আমরা নিশ্চিত করি যে জেনারেটর ফাংশন (`yield`-ওয়ালা ফাংশন) শেষ হওয়ার পরে ফাইলের মতো অবজেক্টটি বন্ধ হবে। মানে রেসপন্স পাঠানো শেষ হওয়ার পরে।

এই নির্দিষ্ট উদাহরণে এটা তেমন জরুরি হতো না, কারণ এটি একটি নকল মেমরি-ফাইল (`io.BytesIO`), কিন্তু একটি আসল ফাইলের ক্ষেত্রে কাজ শেষে ফাইলটি বন্ধ করা নিশ্চিত করা জরুরি।

### ফাইল আর Async { #files-and-async }

বেশিরভাগ ক্ষেত্রে ফাইলের মতো অবজেক্টগুলো ডিফল্টভাবে async আর await-এর সাথে সামঞ্জস্যপূর্ণ নয়।

যেমন, এদের `await file.read()` বা `async for chunk in file` নেই।

আর অনেক ক্ষেত্রে এগুলো পড়া একটি ব্লকিং কাজ হবে (যা ইভেন্ট লুপ আটকে দিতে পারে), কারণ এগুলো ডিস্ক বা নেটওয়ার্ক থেকে পড়া হয়।

/// note | নোট

ওপরের উদাহরণটি আসলে একটি ব্যতিক্রম, কারণ `io.BytesIO` অবজেক্টটি আগে থেকেই মেমরিতে আছে, তাই এটি পড়লে কিছু আটকাবে না।

কিন্তু অনেক ক্ষেত্রে একটি ফাইল বা ফাইলের মতো অবজেক্ট পড়া ব্লক করবে।

///

ইভেন্ট লুপ আটকানো এড়াতে আপনি শুধু `async def`-এর বদলে সাধারণ `def` দিয়ে *পাথ অপারেশন ফাংশন* ঘোষণা করতে পারেন। এতে FastAPI এটিকে একটি থ্রেডপুল কর্মীতে চালাবে, যাতে মূল লুপ আটকে না যায়।

/// tip | পরামর্শ

আপনার যদি একটি async ফাংশনের ভেতর থেকে ব্লকিং কোড, বা একটি ব্লকিং ফাংশনের ভেতর থেকে একটি async ফাংশন ডাকতে হয়, তাহলে FastAPI-এর "ভাই" লাইব্রেরি [Asyncer](https://asyncer.tiangolo.com) ব্যবহার করতে পারেন।

### `yield from` { #yield-from }

যখন আপনি কোনো কিছুর ওপর লুপ চালাচ্ছেন, যেমন একটি ফাইলের মতো অবজেক্ট, আর প্রতিটি জিনিসের জন্য `yield` করছেন, তখন `for` লুপ বাদ দিয়ে সরাসরি প্রতিটি জিনিস yield করতে `yield from`-ও ব্যবহার করতে পারেন।

এটি FastAPI-এর নিজস্ব কিছু নয়, এটি শুধুই Python, তবে জেনে রাখার মতো একটি সুন্দর কৌশল। 😎

{* ../../docs_src/stream_data/tutorial002_py310.py ln[37:40] hl[40] *}

`yield from image_file` আর `for chunk in image_file: yield chunk` একই কাজ করে, প্রথমটি শুধু ছোট।

/// check | সংক্ষেপে মনে রাখুন

* JSON নয় এমন ডেটা স্ট্রিম করতে `response_class=StreamingResponse` আর ফাংশনে `yield`।
* ডেটা যেমন দেবেন তেমনই যাবে, এনকোডিং (`.encode("utf-8")`) আপনার দায়িত্ব।
* সঠিক ধরন জানাতে `media_type`-সহ নিজের সাব-ক্লাস: `class PNGStreamingResponse(StreamingResponse): media_type = "image/png"`।
* ডিস্কের ফাইল পড়লে সাধারণ `def` ব্যবহার করুন, যাতে সার্ভার আটকে না যায়।
