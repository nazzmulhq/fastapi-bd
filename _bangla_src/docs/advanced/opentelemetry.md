# OpenTelemetry { #opentelemetry }

/// note | এই পেজে যা শিখবেন

* টেলিমেট্রি (মেট্রিক, ট্রেস, লগ) কী, আর কেন API চালানোর সময় এগুলো দরকার।
* FastAPI নিজে থেকেই কীভাবে OpenTelemetry ডেটা সংগ্রহ করে।
* এনভায়রনমেন্ট ভেরিয়েবল দিয়ে ডেটা একটি মনিটরিং সার্ভিসে পাঠানো।
* কী রেকর্ড হবে আর কী হবে না, তা নিয়ন্ত্রণ করা।

///

আপনার API চলার সময় হয়তো জানতে চাইবেন এটি কত ট্রাফিক (রিকোয়েস্ট) পাচ্ছে, কোন রিকোয়েস্টগুলো ধীর, আর কখন এরর হচ্ছে।

**টেলিমেট্রি** হলো আপনার অ্যাপ্লিকেশনের আচরণ সম্পর্কে ডেটা, যা এই প্রশ্নগুলোর উত্তর দিতে সাহায্য করে। প্রচলিত ধরনগুলো হলো:

- **মেট্রিক (Metrics)**: সময়ের সাথে সারসংক্ষেপ করা যায় এমন পরিমাপ, যেমন রেসপন্সের সময় আর কতগুলো রিকোয়েস্ট সামলানো হচ্ছে।
- **ট্রেস (Traces)**: প্রতিটি আলাদা রিকোয়েস্ট আর সেটি সামলাতে করা কাজগুলোর রেকর্ড। সময় মাপা প্রতিটি কাজকে বলা হয় একটি **span**।
- **লগ (Logs)**: সময় লেখা ঘটনার রেকর্ড, যেমন একটি অ্যাপ্লিকেশন চালু হওয়া বা একটি কাজ ব্যর্থ হওয়া।

/// tip | উদাহরণ দিয়ে বুঝি

গাড়ির ড্যাশবোর্ডের কথা ভাবুন। স্পিডোমিটার আর জ্বালানির কাঁটা হলো **মেট্রিক** (সংখ্যায় পরিমাপ)। একটি নির্দিষ্ট যাত্রার পুরো রুট আর কোথায় কতক্ষণ থেমেছিল, তা হলো **ট্রেস**। আর "ইঞ্জিন চেক করুন" এর মতো সতর্কবার্তার তালিকা হলো **লগ**। এগুলো দেখে সমস্যা হওয়ার আগেই বা হওয়ার সাথে সাথে বোঝা যায় কী ঘটছে।

///

[**OpenTelemetry**](https://opentelemetry.io/) হলো টেলিমেট্রি সংগ্রহ করে একটি মনিটরিং সার্ভিসে পাঠানোর জন্য একগুচ্ছ স্ট্যান্ডার্ড আর টুল, যেখানে আপনি ড্যাশবোর্ডে এগুলো দেখতে পারেন।

**FastAPI ডিফল্টভাবেই OpenTelemetry সাপোর্ট দেয়** HTTP রিকোয়েস্টের ট্রেস, মেট্রিক আর লগের জন্য। WebSocket সংযোগও ট্রেস আর লগ দেয়। ওই ডেটা দেখতে, এটি গ্রহণ করতে একটি মনিটরিং সার্ভিস কনফিগার করুন।

## অন্যান্য মনিটরিং সার্ভিস { #other-monitoring-services }

অন্য কোনো মনিটরিং সার্ভিসে টেলিমেট্রি পাঠাতে, **OTLP** গ্রহণ করে এমন একটি এন্ডপয়েন্ট কনফিগার করুন। OTLP হলো টেলিমেট্রি পাঠানোর OpenTelemetry প্রোটোকল। সার্ভিসটির HTTP/protobuf বেস এন্ডপয়েন্ট ব্যবহার করুন।

এই এনভায়রনমেন্ট ভেরিয়েবলগুলো সেট করুন, উদাহরণের URL-এর জায়গায় আপনার এন্ডপয়েন্ট দিয়ে:

```bash
export FASTAPI_OTEL_AUTO_CONFIGURE=true
export OTEL_SERVICE_NAME=my-api
export OTEL_EXPORTER_OTLP_ENDPOINT=https://collector.example.com
```

`FASTAPI_OTEL_AUTO_CONFIGURE=true` FastAPI-এর স্বয়ংক্রিয় exporter সেটআপ চালু করে। `OTEL_SERVICE_NAME` মনিটরিং সার্ভিসে আপনার অ্যাপকে শনাক্ত করে। এন্ডপয়েন্ট হলো ডেটা গ্রহণের বেস URL। ওই URL-এর নিচে ট্রেস যায় `/v1/traces`-এ, মেট্রিক `/v1/metrics`-এ আর লগ `/v1/logs`-এ।

আপনার সার্ভিসে অথেনটিকেশন লাগলে, এটি যে হেডার নির্দিষ্ট করে সেগুলো `OTEL_EXPORTER_OTLP_HEADERS`-এ সেট করুন, যেমন `api-key=YOUR_API_KEY`।

(Grafana, Jaeger, Honeycomb, Datadog, SigNoz এর মতো অনেক মনিটরিং সার্ভিস OTLP গ্রহণ করে। এনভায়রনমেন্ট ভেরিয়েবল নিয়ে আরও জানতে দেখুন [এনভায়রনমেন্ট ভেরিয়েবল](../environment-variables.md)।)

<div class="termy">

```console

```

</div>

আরেকটি টার্মিনালে একটি রিকোয়েস্ট পাঠান:

$ curl http://127.0.0.1:8000/items/1

## টেলিমেট্রি নিজের মতো সাজান { #customize-telemetry }

### Provider আর exporter কনফিগার করুন { #configure-providers-and-exporters }

একটি **provider** সেই অবজেক্টগুলো দেয় যা ট্রেস, মেট্রিক বা লগ রেকর্ড করে। এর কনফিগারেশন নিয়ন্ত্রণ করে ওই ডেটা কীভাবে প্রসেস আর এক্সপোর্ট হবে।

টেলিমেট্রি লাইব্রেরিগুলো OpenTelemetry-এর গ্লোবাল provider কনফিগার করতে পারে। অ্যাপ চালু হওয়ার আগে লাইব্রেরিটি কনফিগার করুন, আর FastAPI স্বয়ংক্রিয়ভাবে ওই provider-গুলো ব্যবহার করবে।

ডিফল্টভাবে FastAPI কনফিগার করা provider-গুলো কোনো exporter যোগ না করেই ব্যবহার করে। স্বয়ংক্রিয় সেটআপ চালু থাকলে আর এনভায়রনমেন্টে একটি OTLP এন্ডপয়েন্ট সেট করা থাকলে, FastAPI প্রতিটি চালু provider-এ ওই গন্তব্যের জন্য একটি exporter যোগ করে। বিদ্যমান exporter-গুলো তাদের গন্তব্যে ডেটা পাঠাতে থাকে।

অন্য কোনো লাইব্রেরি যদি ইতিমধ্যে একই গন্তব্যে এক্সপোর্ট কনফিগার করে থাকে, তাহলে টেলিমেট্রি দুবার যাওয়া এড়াতে `FASTAPI_OTEL_AUTO_CONFIGURE` সেট না করে রাখুন বা `false` সেট করুন।

`telemetry` ডিকশনারিতে সরাসরি একটি provider-ও দিতে পারেন। যেমন, এই provider আপনার টার্মিনালে রিকোয়েস্টের span প্রিন্ট করতে OpenTelemetry-এর কনসোল exporter ব্যবহার করে:

{* ../../docs_src/opentelemetry/tutorial002_py310.py hl[2:8] *}

**exporter** span-গুলো তাদের গন্তব্যে পাঠায়। `BatchSpanProcessor` span-গুলো দলবদ্ধ করে ব্যাকগ্রাউন্ডে পাঠায়। আপনার মনিটরিং লাইব্রেরির গন্তব্য ব্যবহার করতে কনসোল exporter-এর বদলে ওই লাইব্রেরির দেওয়া একটি exporter বসান। আরও কনফিগারেশন অপশনের জন্য [OpenTelemetry-এর Python instrumentation গাইড](https://opentelemetry.io/docs/languages/python/instrumentation/) দেখুন।

একটি মেট্রিক বা লগ provider দিতে একই ডিকশনারিতে `meter_provider` বা `logger_provider` ব্যবহার করুন। যে অ্যাপ্লিকেশন বা লাইব্রেরি একটি provider তৈরি করে, সেটিই তার বন্ধ হওয়া সামলায়। FastAPI শুধু নিজের যোগ করা এক্সপোর্ট কম্পোনেন্টগুলো সামলায়।

OpenTelemetry ডিফল্টভাবে গ্লোবাল provider ব্যবহার করে। [mount করা সাব-অ্যাপ্লিকেশনগুলোর](sub-applications.md) জন্য স্বাধীন টেলিমেট্রি কনফিগারেশনের নিশ্চয়তা নেই।

### রিকোয়েস্টের কাজগুলো ট্রেস করা { #trace-request-operations }

ডিফল্টভাবে রিকোয়েস্টের ট্রেসে span থাকে ডিপেন্ডেন্সি সমাধান, আপনার পাথ অপারেশন ফাংশন চালানো, রেসপন্স সিরিয়ালাইজ করা আর FastAPI-এর `BackgroundTasks`-এর প্রতিটি টাস্ক চালানোর জন্য। এই span-গুলো একই provider আর exporter ব্যবহার করে।

ব্যাকগ্রাউন্ড টাস্কের span রিকোয়েস্টের ট্রেসের অংশই থাকে। এগুলো HTTP রেসপন্সের span শেষ হওয়ার পরে চলে, তাই মাপা রেসপন্সের সময় বাড়ায় না।

শুধু HTTP রিকোয়েস্টের span রেকর্ড করতে `operation_spans`-কে `False` সেট করুন:

### WebSocket সংযোগ ট্রেস করা { #trace-websocket-connections }

প্রতিটি WebSocket সংযোগের একটি span থাকে, যেমন `WS /ws/{room}`, যা হ্যান্ডলার আর ডিপেন্ডেন্সির পরিষ্কার পর্যন্ত কভার করে। এটি একই provider আর সেটিংস ব্যবহার করে, ডিপেন্ডেন্সি সমাধান আর এন্ডপয়েন্ট চালানোর জন্য `operation_spans`-সহ।

HTTP রিকোয়েস্টের মেট্রিক শুধু HTTP রিকোয়েস্ট কভার করে। `1000` বা `1001` কোডসহ স্বাভাবিক WebSocket বিচ্ছিন্নতা এরর লগ তৈরি করে না।

### এরর পরীক্ষা করা { #inspect-errors }

FastAPI অসামলানো এক্সেপশনগুলো OpenTelemetry লগ হিসেবে রেকর্ড করে, রিকোয়েস্ট বা সংযোগের ট্রেসের সাথে যুক্ত করে। ট্রেস স্যাম্পল না হলেও এরর লগ রেকর্ড হয়।

এক্সেপশন লগে এক্সেপশনের টাইপ, বার্তা আর stack trace থাকে। বার্তা আর stack trace-এ সংবেদনশীল তথ্য থাকতে পারে। এগুলো ফিল্টার বা মুছে দিতে আপনার provider-এর লগ প্রসেসর ব্যবহার করুন, অথবা এই লগগুলো বন্ধ করতে `logs`-কে `False` সেট করুন।

FastAPI রিকোয়েস্ট যাচাইয়ের ব্যর্থতাগুলোও রাউট আর এররের সংখ্যাসহ সতর্কবার্তা লগ হিসেবে রেকর্ড করে। এই লগে অবৈধ ইনপুট থাকে না।

## কী রেকর্ড হবে বেছে নিন { #choose-what-to-record }

`telemetry` ডিকশনারি এই সেটিংসগুলোও গ্রহণ করে:

| সেটিং | কাজ | ডিফল্ট |
| --- | --- | --- |
| `tracing` | HTTP রিকোয়েস্ট আর WebSocket সংযোগের span রেকর্ড করা | `True` |
| `metrics` | HTTP রিকোয়েস্টের মেট্রিক রেকর্ড করা | `True` |
| `logs` | যাচাই ব্যর্থতা আর অসামলানো এক্সেপশন রেকর্ড করা | `True` |
| `operation_spans` | রিকোয়েস্টের কাজগুলোর জন্য span যোগ করা | `True` |
| `exclude` | ASGI scope পাওয়া একটি ফাংশন `True` ফেরত দিলে সেই রিকোয়েস্ট বাদ দেওয়া | `None` |
| `auto_configure` | এনভায়রনমেন্ট ভেরিয়েবলে সেট করা এন্ডপয়েন্টের জন্য exporter যোগ করা | `FASTAPI_OTEL_AUTO_CONFIGURE=true` হলে `True`, নইলে `False` |

যেমন, health check (সার্ভার বেঁচে আছে কিনা দেখার রিকোয়েস্ট) বাদ দিয়ে মেট্রিক সংগ্রহ করতে:

```python
from fastapi import FastAPI

app = FastAPI(
    telemetry={
        "tracing": False,
        "exclude": lambda scope: scope["path"] == "/health",
    }
)
```

`telemetry` ডিকশনারিতে একটি স্পষ্ট `auto_configure` মান `FASTAPI_OTEL_AUTO_CONFIGURE`-কে ওভাররাইড করে। কোডে স্বয়ংক্রিয় সেটআপ চালু করতে `telemetry={"auto_configure": True}`, অথবা এনভায়রনমেন্ট ভেরিয়েবল চালু করলেও একটি অ্যাপের জন্য এটি বন্ধ করতে `telemetry={"auto_configure": False}` ব্যবহার করুন।

/// check | সংক্ষেপে মনে রাখুন

* মেট্রিক = সংখ্যার পরিমাপ, ট্রেস = একেকটি রিকোয়েস্টের পথ (span-সহ), লগ = ঘটনার রেকর্ড।
* `fastapi[standard]` থাকলে FastAPI নিজেই এগুলো সংগ্রহ করে, কোনো কোড লাগে না।
* মনিটরিং সার্ভিসে পাঠাতে `FASTAPI_OTEL_AUTO_CONFIGURE=true`, `OTEL_SERVICE_NAME` আর OTLP এন্ডপয়েন্টের এনভায়রনমেন্ট ভেরিয়েবল দিন।
* `FastAPI(telemetry={...})` দিয়ে কী রেকর্ড হবে নিয়ন্ত্রণ করুন, সংবেদনশীল তথ্য লগে যাচ্ছে কিনা খেয়াল রাখুন।
