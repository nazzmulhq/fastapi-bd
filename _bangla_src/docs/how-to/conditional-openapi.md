# শর্তসাপেক্ষ OpenAPI { #conditional-openapi }

/// note | এই পেজে যা শিখবেন

* এনভায়রনমেন্ট ভেরিয়েবল দিয়ে `/docs`, `/redoc` আর `/openapi.json` চালু বা বন্ধ করা।
* কেন ডকস লুকিয়ে রাখা আসল নিরাপত্তা নয়, আর আসল নিরাপত্তার জন্য কী করা উচিত।

///

প্রয়োজন হলে, পরিবেশ অনুযায়ী (যেমন নিজের কম্পিউটার বনাম আসল সার্ভার) শর্তসাপেক্ষে OpenAPI কনফিগার করতে, এমনকি পুরোপুরি বন্ধ করতে সেটিংস আর এনভায়রনমেন্ট ভেরিয়েবল ব্যবহার করতে পারেন।

## নিরাপত্তা, API এবং ডকস সম্পর্কে { #about-security-apis-and-docs }

প্রোডাকশনে আপনার ডকুমেন্টেশনের ইউজার ইন্টারফেস লুকিয়ে রাখা আপনার API সুরক্ষার উপায় হওয়া *উচিত নয়*।

এতে আপনার API-তে কোনো বাড়তি নিরাপত্তা যোগ হয় না, *পাথ অপারেশনগুলো* তখনো যেখানে আছে সেখানেই পাওয়া যাবে।

যদি আপনার কোডে কোনো নিরাপত্তা ত্রুটি থাকে, তা তখনো থাকবে।

ডকুমেন্টেশন লুকালে শুধু আপনার API-র সাথে কীভাবে কাজ করতে হয় তা বোঝা কঠিন হয়, আর প্রোডাকশনে ডিবাগ করা আপনার জন্যও কঠিন হতে পারে। এটিকে সাধারণভাবে [Security through obscurity](https://en.wikipedia.org/wiki/Security_through_obscurity)-এর (লুকিয়ে রেখে নিরাপত্তা) একটি রূপ হিসেবে দেখা যেতে পারে।

/// tip | উদাহরণ দিয়ে বুঝি

বাড়ির দরজার নম্বরপ্লেট খুলে ফেললে চোর কি আর ঢুকতে পারবে না? পারবে, শুধু একটু খুঁজতে হবে। আসল নিরাপত্তা হলো মজবুত তালা। ডকস লুকানো হলো নম্বরপ্লেট খোলার মতো, আর অথেনটিকেশন, পারমিশন, পাসওয়ার্ড হ্যাশ হলো আসল তালা।

///

যদি আপনার API সুরক্ষিত করতে চান, তাহলে আরও ভালো কয়েকটি কাজ করতে পারেন, যেমন:

* নিশ্চিত করুন যে আপনার রিকোয়েস্ট বডি আর রেসপন্সের জন্য সুনির্দিষ্ট Pydantic মডেল আছে।
* ডিপেন্ডেন্সি ব্যবহার করে দরকারি পারমিশন আর রোল কনফিগার করুন।
* কখনো সাধারণ লেখায় (plaintext) পাসওয়ার্ড সংরক্ষণ করবেন না, শুধু পাসওয়ার্ড হ্যাশ রাখুন।
* pwdlib আর JWT টোকেনের মতো সুপরিচিত ক্রিপ্টোগ্রাফিক টুল প্রয়োগ আর ব্যবহার করুন।
* যেখানে দরকার সেখানে OAuth2 scope দিয়ে আরও সূক্ষ্ম পারমিশন নিয়ন্ত্রণ যোগ করুন।
* ...ইত্যাদি।

তবুও, আপনার হয়তো খুবই নির্দিষ্ট একটি ক্ষেত্র থাকতে পারে যেখানে কোনো পরিবেশের জন্য (যেমন প্রোডাকশনে) বা এনভায়রনমেন্ট ভেরিয়েবলের কনফিগারেশন অনুযায়ী সত্যিই API ডকস বন্ধ করা দরকার।

## সেটিংস আর env var থেকে শর্তসাপেক্ষ OpenAPI { #conditional-openapi-from-settings-and-env-vars }

আপনার তৈরি হওয়া OpenAPI আর ডকস UI কনফিগার করতে সহজেই একই Pydantic সেটিংস ব্যবহার করতে পারেন।

যেমন:

{* ../../docs_src/conditional_openapi/tutorial001_py310.py hl[6,11] *}

এখানে আমরা `openapi_url` সেটিং ঘোষণা করি, একই ডিফল্ট `"/openapi.json"` দিয়ে।

আর তারপর `FastAPI` অ্যাপ তৈরির সময় এটি ব্যবহার করি।

/// info | কোডটি সহজ ভাষায়

* লাইন ৫–৬: `Settings` ক্লাসে `openapi_url`, ডিফল্ট `"/openapi.json"`। এনভায়রনমেন্টে `OPENAPI_URL` থাকলে সেটি এই মানকে বদলে দেবে।
* লাইন ১১: `FastAPI(openapi_url=settings.openapi_url)`। যদি মানটি খালি স্ট্রিং হয়, FastAPI OpenAPI স্কিমা তৈরি করে না, আর `/docs` ও `/redoc`-ও বন্ধ হয়ে যায় (কারণ এরা স্কিমার ওপর নির্ভর করে)।

(সেটিংস কীভাবে কাজ করে তা বিস্তারিত দেখুন [সেটিংস এবং এনভায়রনমেন্ট ভেরিয়েবল](../advanced/settings.md) পেজে।)

///

তারপর এনভায়রনমেন্ট ভেরিয়েবল `OPENAPI_URL`-কে খালি স্ট্রিং সেট করে OpenAPI (UI ডকসসহ) বন্ধ করতে পারেন, এভাবে:

<div class="termy">

```console
$ OPENAPI_URL= uvicorn main:app

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

</div>

তারপর যদি `/openapi.json`, `/docs` বা `/redoc` URL-এ যান, শুধু এমন একটি `404 Not Found` এরর পাবেন:

```JSON
{
    "detail": "Not Found"
}
```

/// check | সংক্ষেপে মনে রাখুন

* `FastAPI(openapi_url="")` দিলে OpenAPI আর সব ডকস UI বন্ধ হয়ে যায়।
* Pydantic সেটিংস দিয়ে এটি এনভায়রনমেন্ট ভেরিয়েবলের ওপর নির্ভরশীল করা যায়।
* ডকস লুকানো নিরাপত্তা নয়, আসল নিরাপত্তার জন্য অথেনটিকেশন, পারমিশন আর সঠিক মডেল ব্যবহার করুন।
