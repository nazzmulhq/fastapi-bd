# এন্টারপ্রাইজ সাপোর্ট { #enterprise-support }

/// note | এই পেজটি কী

বড় কোম্পানিগুলো, যাদের আসল প্রোডাকশন সিস্টেম Pydantic-এর ওপর চলে, তারা টাকা দিয়ে Pydantic-এর ইঞ্জিনিয়ারদের কাছ থেকে সরাসরি, দ্রুত সাহায্য নিতে পারে। এই পেজ সেই বাণিজ্যিক সাপোর্ট নিয়ে। ব্যক্তিগত শেখা বা সাধারণ প্রশ্নের জন্য এটি দরকার নেই, তার জন্য [সাহায্য](help_with_pydantic.md) পেজ দেখুন।

///

Pydantic প্রায়ই অবিশ্বস্ত ডেটা আর প্রোডাকশন সিস্টেমের বাকি অংশের মাঝখানে বসে থাকে। যখন সেই সীমানাটি গুরুত্বপূর্ণ, তখন কোনো দুর্ঘটনা (incident) বা বড় আপগ্রেডের সময় একটি পাবলিক ইস্যু ট্র্যাকার এমন পথ নয় যার ওপর আপনি ভরসা করতে চাইবেন।

এন্টারপ্রাইজ প্ল্যানে আছে Pydantic ইঞ্জিনিয়ারদের সাথে সরাসরি যোগাযোগ, ২৪/৭ অগ্রাধিকার সাপোর্ট, সেটআপে সাহায্য, আর আপনার কাজের ধরন অনুযায়ী একটি SLA (Service Level Agreement: কত দ্রুত সাড়া দেওয়া হবে তার লিখিত চুক্তি)। আপনার চুক্তিতে এটিও নির্ধারণ করা যায় যে কোনো নিরাপত্তা দুর্বলতা আপনার আওতাভুক্ত কোনো রিলিজকে প্রভাবিত করলে আমরা কীভাবে সমন্বয় করব।

[Discuss enterprise support](https://pydantic.dev/contact){ .md-button .md-button--primary }

## Pydantic ইঞ্জিনিয়াররা কোথায় সাহায্য করতে পারেন { #where-pydantic-engineers-can-help }

সাধারণ প্রশ্নের জন্য পাবলিক ডকুমেন্টেশন, ইস্যু ট্র্যাকার আর কমিউনিটি চ্যানেল ব্যবহার করুন। এন্টারপ্রাইজ সাপোর্ট কভার করে প্রোডাকশনের দুর্ঘটনা, বড় আপগ্রেড, আর্কিটেকচার বা পারফরম্যান্স রিভিউ, আর সমন্বিতভাবে নিরাপত্তা দুর্বলতার প্রতিক্রিয়া।

## সাপোর্ট কীভাবে কাজ করে { #how-support-works }

1. **সাপোর্টের পরিধি ঠিক করুন**

   আপনার চুক্তির আওতায় কোন প্যাকেজ, রিলিজ লাইন, পরিবেশ (environment), অপারেশনাল ও নিরাপত্তা বিষয়ক যোগাযোগের ব্যক্তি, আর প্রাথমিক সাড়া দেওয়ার লক্ষ্যমাত্রা থাকবে তা নির্ধারণ করুন।

2. **দরকারি তথ্য প্রস্তুত রাখুন**

   গুরুত্বপূর্ণ পথে Pydantic কোথায় কোথায় আছে তা চিহ্নিত করুন, আর ঠিক করুন কীভাবে একটি পুনরাবৃত্তিযোগ্য উদাহরণ, প্রাসঙ্গিক কনফিগারেশন আর সাম্প্রতিক পরিবর্তনগুলো সংগ্রহ করবেন।

3. **সরাসরি জানান**

   প্রোডাকশনকে প্রভাবিত করা সমস্যা বা সন্দেহজনক নিরাপত্তা দুর্বলতা সম্মত হওয়া ব্যক্তিগত চ্যানেলে সরাসরি Pydantic ইঞ্জিনিয়ারদের জানান। আমরা আপনার দলের সাথে মিলে সমস্যাটি আলাদা করে বের করি আর পরবর্তী পদক্ষেপ ঠিক করি।

## ওপেন সোর্সই ভিত্তি থাকছে { #open-source-remains-the-foundation }

Pydantic-এর লাইসেন্স, ডকুমেন্টেশন, রিলিজ, ইস্যু ট্র্যাকার আর কমিউনিটি সাপোর্ট সবার জন্য খোলাই থাকছে। এন্টারপ্রাইজ সাপোর্ট শুধু সেই দলগুলোর জন্য একটি সরাসরি পথ আর চুক্তিবদ্ধ প্রতিশ্রুতি যোগ করে, যারা প্রোডাকশনে Pydantic-এর ওপর নির্ভর করে।

## দলগুলো যা জিজ্ঞেস করে { #questions-teams-ask }

/// details | এটি কি Logfire সাপোর্টের মতোই?
    type: note

না। এই পেজটি Pydantic validation লাইব্রেরির সাপোর্ট নিয়ে। Logfire একটি আলাদা প্রোডাক্ট, যার নিজস্ব বাণিজ্যিক প্ল্যান আর সাপোর্ট আছে।

///

/// details | Pydantic ইঞ্জিনিয়াররা কী খুঁজে বের করতে সাহায্য করতে পারেন?
    type: note

আমরা আপনার ইঞ্জিনিয়ারদের সাথে মিলে সমস্যাটি পুনরায় তৈরি করি, Pydantic-এর আচরণ আলাদা করে দেখি, প্রাসঙ্গিক বাস্তবায়নের বিবরণ ব্যাখ্যা করি, আর পরবর্তী পদক্ষেপ ঠিক করি। চারপাশের অ্যাপ্লিকেশন আর অবকাঠামোর মালিকানা আপনার দলেরই থাকে।

///

/// details | আমরা কি নির্দিষ্ট সংস্করণ আর প্রাথমিক সাড়ার লক্ষ্যমাত্রা ঠিক করে নিতে পারি?
    type: note

হ্যাঁ। সমর্থিত সংস্করণ, গুরুত্বের স্তর (severity), প্রাথমিক সাড়ার লক্ষ্যমাত্রা আর অন্যান্য প্রতিশ্রুতি আপনার বাণিজ্যিক চুক্তিতে নির্ধারিত হয়। আপনার প্রয়োজন নিয়ে আলোচনা করতে [যোগাযোগ করুন](https://pydantic.dev/contact)।

///

/// details | নিরাপত্তা দুর্বলতা কীভাবে সামলানো হয়?
    type: note

যে কেউ Pydantic-এর [নিরাপত্তা রিপোর্টিং প্রক্রিয়া](https://github.com/pydantic/pydantic/security/policy)-র মাধ্যমে গোপনে একটি সন্দেহজনক দুর্বলতা জানাতে পারেন। আওতাভুক্ত রিলিজ লাইনকে প্রভাবিত করা নিশ্চিত সমস্যার ক্ষেত্রে, এন্টারপ্রাইজ সাপোর্ট যোগ করে নির্দিষ্ট নিরাপত্তা যোগাযোগকারী আর প্রভাব মূল্যায়ন, প্রতিকার, প্যাচ করা রিলিজ ও প্রকাশের (disclosure) সমন্বিত কাজ। যেখানে উপযুক্ত সেখানে Advisory আর CVE প্রকাশ করা হয়; জানানো আর সাড়া দেওয়ার প্রতিশ্রুতি আপনার চুক্তিতে নির্ধারিত থাকে।
