# বিকল্প, অনুপ্রেরণা এবং তুলনা { #alternatives-inspiration-and-comparisons }

/// note | এই পেজে যা জানবেন

* FastAPI তৈরির আগে কোন কোন টুল ছিল (Django, Flask, Marshmallow, APIStar ইত্যাদি)।
* প্রতিটি টুলের ভালো দিক কী ছিল, সীমাবদ্ধতা কী ছিল।
* প্রতিটি থেকে FastAPI কোন ধারণা নিয়েছে (প্রতিটি অংশের শেষে সবুজ বাক্সে)।
* FastAPI নিজে কোন তিনটি টুলের ওপর দাঁড়িয়ে আছে: Pydantic, Starlette, Uvicorn।

FastAPI ব্যবহার শিখতে এই পেজ জরুরি নয়, তবে অন্য ফ্রেমওয়ার্ক থেকে এলে বা "কেন এভাবে" জানতে চাইলে খুব কাজের।

///

**FastAPI**-কে কী অনুপ্রেরণা দিয়েছে, বিকল্পগুলোর সাথে এর তুলনা কেমন, আর তাদের কাছ থেকে এটি কী শিখেছে।

## ভূমিকা { #intro }

অন্যদের আগের কাজ না থাকলে **FastAPI**-এর অস্তিত্বই থাকত না।

আগে অনেক টুল তৈরি হয়েছে, যা এটি তৈরিতে অনুপ্রেরণা দিয়েছে।

আমি কয়েক বছর ধরে একটি নতুন ফ্রেমওয়ার্ক তৈরি এড়িয়ে চলছিলাম। প্রথমে আমি **FastAPI**-এর সব ফিচার অনেকগুলো ভিন্ন ফ্রেমওয়ার্ক, প্লাগ-ইন আর টুল দিয়ে সমাধান করার চেষ্টা করেছিলাম।

কিন্তু এক পর্যায়ে, আগের টুলগুলোর সেরা ধারণাগুলো নিয়ে, আগে উপলব্ধই ছিল না এমন ভাষার ফিচার (Python 3.6+ টাইপ হিন্ট) ব্যবহার করে, সেগুলো সম্ভাব্য সেরা উপায়ে মিলিয়ে, এই সব ফিচার দেয় এমন কিছু তৈরি করা ছাড়া আর কোনো উপায় ছিল না।

## আগের টুলগুলো { #previous-tools }

### [Django](https://www.djangoproject.com/) { #django }

এটি সবচেয়ে জনপ্রিয় Python ফ্রেমওয়ার্ক আর ব্যাপকভাবে বিশ্বস্ত। Instagram-এর মতো সিস্টেম তৈরিতে এটি ব্যবহার হয়।

এটি রিলেশনাল ডেটাবেসের (যেমন MySQL বা PostgreSQL) সাথে তুলনামূলকভাবে শক্তভাবে জড়িত, তাই একটি NoSQL ডেটাবেসকে (যেমন Couchbase, MongoDB, Cassandra ইত্যাদি) প্রধান সংরক্ষণ ইঞ্জিন হিসেবে রাখা খুব একটা সহজ নয়।

এটি তৈরি করা হয়েছিল ব্যাকএন্ডে HTML তৈরি করার জন্য, আধুনিক ফ্রন্টএন্ড (যেমন React, Vue.js আর Angular) বা এর সাথে যোগাযোগ করা অন্য সিস্টেমের (যেমন <abbr title="Internet of Things: ইন্টারনেটে যুক্ত যন্ত্র, যেমন স্মার্ট বাল্ব">IoT</abbr> ডিভাইস) ব্যবহারের জন্য API তৈরি করতে নয়।

### [Django REST Framework](https://www.django-rest-framework.org/) { #django-rest-framework }

Django REST Framework তৈরি করা হয়েছিল ভেতরে Django ব্যবহার করে Web API তৈরির একটি নমনীয় টুলকিট হিসেবে, এর API সক্ষমতা বাড়াতে।

Mozilla, Red Hat আর Eventbrite-সহ অনেক কোম্পানি এটি ব্যবহার করে।

এটি **স্বয়ংক্রিয় API ডকুমেন্টেশনের** প্রথম উদাহরণগুলোর একটি ছিল, আর নির্দিষ্টভাবে এটিই ছিল প্রথম ধারণাগুলোর একটি যা **FastAPI**-এর "খোঁজ" শুরু করতে অনুপ্রেরণা দিয়েছিল।

/// note | নোট

Django REST Framework তৈরি করেছেন Tom Christie। তিনিই Starlette আর Uvicorn-এর নির্মাতা, যার ওপর **FastAPI** ভিত্তি করে তৈরি।

///

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

একটি স্বয়ংক্রিয় API ডকুমেন্টেশনের ওয়েব ইউজার ইন্টারফেস রাখা।

///

### [Flask](https://flask.palletsprojects.com) { #flask }

Flask একটি "মাইক্রোফ্রেমওয়ার্ক", এতে ডেটাবেস সংযোগ বা Django-তে ডিফল্টভাবে আসা অনেক কিছুই নেই।

এই সরলতা আর নমনীয়তার কারণে NoSQL ডেটাবেসকে প্রধান ডেটা সংরক্ষণ ব্যবস্থা হিসেবে ব্যবহারের মতো কাজ করা যায়।

যেহেতু এটি খুব সহজ, তাই শেখা তুলনামূলকভাবে স্বাভাবিক, যদিও ডকুমেন্টেশন কিছু জায়গায় বেশ কারিগরি হয়ে যায়।

এটি এমন অ্যাপ্লিকেশনেও সাধারণত ব্যবহার হয় যেগুলোর ডেটাবেস, ইউজার ব্যবস্থাপনা, বা Django-তে আগে থেকে তৈরি অনেক ফিচারের কোনোটিই দরকার নেই। যদিও এর অনেক ফিচার প্লাগ-ইন দিয়ে যোগ করা যায়।

অংশগুলোর এই আলাদা থাকা, আর ঠিক যা দরকার তা কভার করতে বাড়ানো যায় এমন একটি "মাইক্রোফ্রেমওয়ার্ক" হওয়া, এটি একটি মূল বৈশিষ্ট্য ছিল যা আমি রাখতে চেয়েছিলাম।

Flask-এর সরলতা দেখে, API তৈরির জন্য এটি একটি ভালো মিল মনে হয়েছিল। এরপর খুঁজতে হতো Flask-এর জন্য একটি "Django REST Framework"।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

একটি মাইক্রো-ফ্রেমওয়ার্ক হওয়া। দরকারি টুল আর অংশগুলো সহজে মিলিয়ে নেওয়ার সুযোগ রাখা।

একটি সহজ আর ব্যবহারে সহজ রাউটিং ব্যবস্থা রাখা।

### [Requests](https://requests.readthedocs.io) { #requests }

**FastAPI** আসলে **Requests**-এর বিকল্প নয়। এদের পরিধি একেবারে আলাদা।

আসলে একটি FastAPI অ্যাপ্লিকেশনের *ভেতরে* Requests ব্যবহার করা খুবই সাধারণ ব্যাপার।

তবুও, FastAPI Requests থেকে বেশ অনুপ্রেরণা পেয়েছে।

**Requests** হলো API-র সাথে (ক্লায়েন্ট হিসেবে) *যোগাযোগ* করার লাইব্রেরি, আর **FastAPI** হলো API (সার্ভার হিসেবে) *তৈরি* করার লাইব্রেরি।

এরা কমবেশি বিপরীত প্রান্তে, একে অপরের পরিপূরক।

Requests-এর ডিজাইন খুবই সহজ আর স্বাভাবিক, এটি ব্যবহারে খুব সহজ, যুক্তিসঙ্গত ডিফল্টসহ। কিন্তু একই সাথে এটি খুবই শক্তিশালী আর নিজের মতো বদলানো যায়।

এজন্যই, অফিসিয়াল ওয়েবসাইটে যেমন বলা আছে:

> Requests is one of the most downloaded Python packages of all time

(অর্থাৎ: Requests সর্বকালের সবচেয়ে বেশি ডাউনলোড হওয়া Python প্যাকেজগুলোর একটি।)

এটি ব্যবহারের পদ্ধতি খুবই সহজ। যেমন, একটি `GET` রিকোয়েস্ট করতে লিখবেন:

```Python
response = requests.get("http://example.com/some/url")
```

FastAPI-তে এর বিপরীত API *পাথ অপারেশন* দেখতে এমন হতে পারে:

```Python hl_lines="1"
@app.get("/some/url")
def read_url():
    return {"message": "Hello World"}
```

`requests.get(...)` আর `@app.get(...)`-এর মিল লক্ষ্য করুন।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

* একটি সহজ আর স্বাভাবিক API রাখা।
* HTTP মেথডের নাম (অপারেশন) সরাসরি, সোজাসুজি আর স্বাভাবিকভাবে ব্যবহার করা।
* যুক্তিসঙ্গত ডিফল্ট রাখা, কিন্তু শক্তিশালী কাস্টমাইজেশনের সুযোগসহ।

### [Swagger](https://swagger.io/) / [OpenAPI](https://github.com/OAI/OpenAPI-Specification/) { #swagger-openapi }

Django REST Framework থেকে আমি যে প্রধান ফিচারটি চেয়েছিলাম তা হলো স্বয়ংক্রিয় API ডকুমেন্টেশন।

তারপর আমি দেখলাম JSON (বা JSON-এর একটি সম্প্রসারণ YAML) ব্যবহার করে API ডকুমেন্ট করার একটি স্ট্যান্ডার্ড আছে, যার নাম Swagger।

আর Swagger API-র জন্য একটি ওয়েব ইউজার ইন্টারফেস আগে থেকেই তৈরি ছিল। তাই একটি API-র জন্য Swagger ডকুমেন্টেশন তৈরি করতে পারলে এই ওয়েব ইউজার ইন্টারফেস স্বয়ংক্রিয়ভাবে ব্যবহার করা যেত।

এক পর্যায়ে Swagger Linux Foundation-কে দিয়ে দেওয়া হয়, আর এর নাম বদলে হয় OpenAPI।

এজন্যই সংস্করণ 2.0-এর কথা বলার সময় "Swagger" বলা সাধারণ, আর সংস্করণ 3+-এর জন্য "OpenAPI"।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

কাস্টম স্কিমার বদলে API স্পেসিফিকেশনের জন্য একটি খোলা স্ট্যান্ডার্ড গ্রহণ আর ব্যবহার করা।

আর স্ট্যান্ডার্ড-ভিত্তিক ইউজার ইন্টারফেস টুলগুলো যুক্ত করা:

* [Swagger UI](https://github.com/swagger-api/swagger-ui)
* [ReDoc](https://github.com/Redocly/redoc)

এই দুটি বেছে নেওয়া হয়েছে বেশ জনপ্রিয় আর স্থিতিশীল হওয়ার জন্য, তবে একটু খুঁজলেই OpenAPI-র জন্য ডজনখানেক বিকল্প ইউজার ইন্টারফেস পাবেন (যেগুলো **FastAPI**-এর সাথে ব্যবহার করতে পারেন)।

### Flask REST ফ্রেমওয়ার্ক { #flask-rest-frameworks }

কয়েকটি Flask REST ফ্রেমওয়ার্ক আছে, কিন্তু এগুলো খুঁজে দেখতে সময় আর পরিশ্রম দেওয়ার পরে দেখলাম অনেকগুলোই বন্ধ বা পরিত্যক্ত, অনেক অমীমাংসিত সমস্যাসহ যা এগুলোকে অনুপযুক্ত করে তোলে।

### [Marshmallow](https://marshmallow.readthedocs.io/en/stable/) { #marshmallow }

API সিস্টেমের দরকারি প্রধান ফিচারগুলোর একটি হলো ডেটা "<dfn title="অন্য নাম: marshalling, রূপান্তর">সিরিয়ালাইজেশন</dfn>", অর্থাৎ কোড (Python) থেকে ডেটা নিয়ে নেটওয়ার্কের মাধ্যমে পাঠানো যায় এমন কিছুতে রূপান্তর করা। যেমন, ডেটাবেসের ডেটা থাকা একটি অবজেক্টকে একটি JSON অবজেক্টে রূপান্তর করা। `datetime` অবজেক্টকে স্ট্রিংয়ে রূপান্তর করা, ইত্যাদি।

API-র দরকারি আরেকটি বড় ফিচার হলো ডেটা যাচাই, নির্দিষ্ট কিছু প্যারামিটার অনুযায়ী ডেটা বৈধ কিনা নিশ্চিত করা। যেমন, কোনো ফিল্ড একটি `int`, এলোমেলো কোনো স্ট্রিং নয়। এটি বিশেষ করে আগত ডেটার জন্য উপকারী।

ডেটা যাচাইয়ের ব্যবস্থা না থাকলে, সব যাচাই আপনাকে কোডে হাতে করতে হতো।

এই ফিচারগুলো দেওয়ার জন্যই Marshmallow তৈরি হয়েছিল। এটি একটি দারুণ লাইব্রেরি, আর আমি আগে এটি অনেক ব্যবহার করেছি।

কিন্তু এটি তৈরি হয়েছিল Python টাইপ হিন্ট আসার আগে। তাই প্রতিটি <dfn title="ডেটা কেমন আকারের হওয়া উচিত তার সংজ্ঞা">স্কিমা</dfn> সংজ্ঞায়িত করতে আপনাকে Marshmallow-এর দেওয়া নির্দিষ্ট ইউটিলিটি আর ক্লাস ব্যবহার করতে হয়।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

কোড দিয়ে এমন "স্কিমা" সংজ্ঞায়িত করা, যা স্বয়ংক্রিয়ভাবে ডেটা টাইপ আর যাচাই দেয়।

///

### [Webargs](https://webargs.readthedocs.io/en/latest/) { #webargs }

API-র দরকারি আরেকটি বড় ফিচার হলো আগত রিকোয়েস্ট থেকে ডেটা <dfn title="পড়া আর Python ডেটায় রূপান্তর করা">পার্স করা</dfn>।

Webargs হলো Flask-সহ কয়েকটি ফ্রেমওয়ার্কের ওপরে সেই সুবিধা দেওয়ার জন্য তৈরি একটি টুল।

ডেটা যাচাই করতে এটি ভেতরে Marshmallow ব্যবহার করে। আর এটি একই ডেভেলপারদের তৈরি।

এটি একটি দারুণ টুল, আর **FastAPI** আসার আগে আমি এটিও অনেক ব্যবহার করেছি।

/// note | নোট

Webargs তৈরি করেছেন Marshmallow-এর একই ডেভেলপাররা।

///

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

আগত রিকোয়েস্ট ডেটার স্বয়ংক্রিয় যাচাই রাখা।

///

### [APISpec](https://apispec.readthedocs.io/en/stable/) { #apispec }

Marshmallow আর Webargs প্লাগ-ইন হিসেবে যাচাই, পার্সিং আর সিরিয়ালাইজেশন দেয়।

কিন্তু ডকুমেন্টেশন তখনো বাকি। তখন APISpec তৈরি হলো।

এটি অনেক ফ্রেমওয়ার্কের জন্য একটি প্লাগ-ইন (আর Starlette-এর জন্যও একটি প্লাগ-ইন আছে)।

এটি যেভাবে কাজ করে: একটি রাউট সামলানো প্রতিটি ফাংশনের docstring-এর ভেতরে YAML ফরম্যাটে স্কিমার সংজ্ঞা লেখেন।

আর এটি OpenAPI স্কিমা তৈরি করে।

Flask, Starlette, Responder ইত্যাদিতে এটি এভাবেই কাজ করে।

কিন্তু তখন আবার সেই সমস্যা: একটি Python স্ট্রিংয়ের ভেতরে একটি ছোট-সিনট্যাক্স (একটি বড় YAML)।

এডিটর এতে খুব একটা সাহায্য করতে পারে না। আর যদি আমরা প্যারামিটার বা Marshmallow স্কিমা বদলাই আর সেই YAML docstring-ও বদলাতে ভুলে যাই, তাহলে তৈরি হওয়া স্কিমা পুরনো হয়ে যাবে।

/// note | নোট

APISpec তৈরি করেছেন Marshmallow-এর একই ডেভেলপাররা।

///

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

API-র খোলা স্ট্যান্ডার্ড, OpenAPI, সাপোর্ট করা।

///

### [Flask-apispec](https://flask-apispec.readthedocs.io/en/latest/) { #flask-apispec }

এটি একটি Flask প্লাগ-ইন, যা Webargs, Marshmallow আর APISpec-কে একসাথে জোড়ে।

এটি APISpec ব্যবহার করে, Webargs আর Marshmallow-এর তথ্য দিয়ে স্বয়ংক্রিয়ভাবে OpenAPI স্কিমা তৈরি করে।

এটি একটি দারুণ টুল, খুবই অবমূল্যায়িত। বাজারের অনেক Flask প্লাগ-ইনের চেয়ে এটি অনেক বেশি জনপ্রিয় হওয়া উচিত ছিল। হয়তো এর ডকুমেন্টেশন খুব সংক্ষিপ্ত আর বিমূর্ত হওয়ার কারণে।

এটি Python docstring-এর ভেতরে YAML (আরেকটি সিনট্যাক্স) লেখার সমস্যার সমাধান করেছিল।

Flask, Marshmallow আর Webargs-সহ Flask-apispec-এর এই সমন্বয় **FastAPI** তৈরির আগ পর্যন্ত আমার প্রিয় ব্যাকএন্ড স্ট্যাক ছিল।

এটি ব্যবহার করতে গিয়ে কয়েকটি Flask full-stack জেনারেটর তৈরি হয়। এগুলোই প্রধান স্ট্যাক যা আমি (আর কয়েকটি বাইরের দল) এখন পর্যন্ত ব্যবহার করে আসছি:

* [https://github.com/tiangolo/full-stack](https://github.com/tiangolo/full-stack)
* [https://github.com/tiangolo/full-stack-flask-couchbase](https://github.com/tiangolo/full-stack-flask-couchbase)
* [https://github.com/tiangolo/full-stack-flask-couchdb](https://github.com/tiangolo/full-stack-flask-couchdb)

আর এই একই full-stack জেনারেটরগুলোই ছিল [**FastAPI** প্রজেক্ট জেনারেটরের](project-generation.md) ভিত্তি।

/// note | নোট

Flask-apispec তৈরি করেছেন Marshmallow-এর একই ডেভেলপাররা।

///

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

সিরিয়ালাইজেশন আর যাচাই সংজ্ঞায়িত করা একই কোড থেকে স্বয়ংক্রিয়ভাবে OpenAPI স্কিমা তৈরি করা।

### [NestJS](https://nestjs.com/) (এবং [Angular](https://angular.dev/)) { #nestjs-and-angular }

এটি Python-ও নয়, NestJS হলো Angular-এর অনুপ্রেরণায় তৈরি একটি JavaScript (TypeScript) NodeJS ফ্রেমওয়ার্ক।

Flask-apispec দিয়ে যা করা যায় তার কিছুটা কাছাকাছি কিছু এটি অর্জন করে।

এতে Angular 2-এর অনুপ্রেরণায় একটি সমন্বিত ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা আছে। এতে "injectable"-গুলো আগে থেকে নিবন্ধন করতে হয় (আমার জানা অন্য সব ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থার মতো), তাই কোড লম্বা হয় আর পুনরাবৃত্তি বাড়ে।

যেহেতু প্যারামিটারগুলো TypeScript টাইপ দিয়ে বর্ণনা করা হয় (Python টাইপ হিন্টের মতো), তাই এডিটর সাপোর্ট বেশ ভালো।

কিন্তু যেহেতু JavaScript-এ কম্পাইল হওয়ার পরে TypeScript-এর টাইপ তথ্য থাকে না, তাই এটি একই সাথে যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশন সংজ্ঞায়িত করতে টাইপের ওপর নির্ভর করতে পারে না। এর কারণে আর কিছু ডিজাইন সিদ্ধান্তের কারণে, যাচাই, সিরিয়ালাইজেশন আর স্বয়ংক্রিয় স্কিমা তৈরির জন্য অনেক জায়গায় ডেকোরেটর যোগ করতে হয়। তাই কোড বেশ লম্বা হয়ে যায়।

এটি নেস্টেড মডেল খুব ভালোভাবে সামলাতে পারে না। তাই যদি রিকোয়েস্টের JSON বডি এমন একটি JSON অবজেক্ট হয় যার ভেতরের ফিল্ডগুলো আবার নেস্টেড JSON অবজেক্ট, তাহলে তা সঠিকভাবে ডকুমেন্ট আর যাচাই করা যায় না।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

দারুণ এডিটর সাপোর্ট পেতে Python টাইপ ব্যবহার করা।

একটি শক্তিশালী ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা রাখা। কোডের পুনরাবৃত্তি কমানোর একটি উপায় খুঁজে বের করা।

### [Sanic](https://sanic.readthedocs.io/en/latest/) { #sanic }

এটি ছিল `asyncio`-ভিত্তিক প্রথম অত্যন্ত দ্রুত Python ফ্রেমওয়ার্কগুলোর একটি। এটি Flask-এর খুব কাছাকাছি করে তৈরি করা হয়েছিল।

/// note | কারিগরি বিবরণ

এটি Python-এর ডিফল্ট `asyncio` লুপের বদলে [`uvloop`](https://github.com/MagicStack/uvloop) ব্যবহার করত। এটাই একে এত দ্রুত করেছিল।

এটি স্পষ্টভাবে Uvicorn আর Starlette-কে অনুপ্রাণিত করেছে, যা বর্তমানে খোলা বেঞ্চমার্কে Sanic-এর চেয়ে দ্রুত।

///

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

চোখ ধাঁধানো পারফরম্যান্স পাওয়ার একটি উপায় খুঁজে বের করা।

এজন্যই **FastAPI** Starlette-এর ওপর ভিত্তি করে তৈরি, কারণ এটি উপলব্ধ দ্রুততম ফ্রেমওয়ার্ক (তৃতীয় পক্ষের বেঞ্চমার্কে পরীক্ষিত)।

### [Falcon](https://falconframework.org/) { #falcon }

Falcon আরেকটি উচ্চ-পারফরম্যান্স Python ফ্রেমওয়ার্ক, এটি ন্যূনতম হওয়ার জন্য আর Hug-এর মতো অন্য ফ্রেমওয়ার্কের ভিত্তি হিসেবে কাজ করার জন্য ডিজাইন করা।

এটি এমনভাবে ডিজাইন করা যে ফাংশনগুলো দুটি প্যারামিটার নেয়, একটি "request" আর একটি "response"। তারপর আপনি request থেকে অংশগুলো "পড়েন", আর response-এ অংশগুলো "লেখেন"। এই ডিজাইনের কারণে, ফাংশনের প্যারামিটার হিসেবে স্ট্যান্ডার্ড Python টাইপ হিন্ট দিয়ে রিকোয়েস্ট প্যারামিটার আর বডি ঘোষণা করা সম্ভব নয়।

তাই ডেটা যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশন কোডে করতে হয়, স্বয়ংক্রিয়ভাবে নয়। অথবা এগুলো Falcon-এর ওপরে একটি ফ্রেমওয়ার্ক হিসেবে বাস্তবায়ন করতে হয়, যেমন Hug। একটি request অবজেক্ট আর একটি response অবজেক্ট প্যারামিটার হিসেবে রাখার Falcon-এর ডিজাইনে অনুপ্রাণিত অন্য ফ্রেমওয়ার্কগুলোতেও একই পার্থক্য দেখা যায়।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

দারুণ পারফরম্যান্স পাওয়ার উপায় খুঁজে বের করা।

Hug-এর সাথে মিলে (যেহেতু Hug Falcon-এর ওপর ভিত্তি করে তৈরি) **FastAPI**-কে ফাংশনে একটি `response` প্যারামিটার ঘোষণা করতে অনুপ্রাণিত করেছে।

যদিও FastAPI-তে এটি ঐচ্ছিক, আর মূলত হেডার, কুকি আর বিকল্প স্ট্যাটাস কোড সেট করতে ব্যবহার হয়।

### [Molten](https://moltenframework.com/) { #molten }

**FastAPI** তৈরির প্রথম পর্যায়ে আমি Molten খুঁজে পাই। আর এতে বেশ কাছাকাছি ধারণা আছে:

* Python টাইপ হিন্টের ওপর ভিত্তি করে।
* এই টাইপগুলো থেকে যাচাই আর ডকুমেন্টেশন।
* ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা।

এটি Pydantic-এর মতো তৃতীয় পক্ষের কোনো ডেটা যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশন লাইব্রেরি ব্যবহার করে না, এর নিজস্ব আছে। তাই এই ডেটা টাইপের সংজ্ঞাগুলো এত সহজে পুনরায় ব্যবহার করা যেত না।

এতে একটু বেশি লম্বা কনফিগারেশন লাগে। আর যেহেতু এটি WSGI-ভিত্তিক (ASGI-এর বদলে), তাই এটি Uvicorn, Starlette আর Sanic-এর মতো টুলের দেওয়া উচ্চ পারফরম্যান্সের সুবিধা নেওয়ার জন্য ডিজাইন করা নয়।

ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থায় ডিপেন্ডেন্সিগুলো আগে থেকে নিবন্ধন করতে হয়, আর ডিপেন্ডেন্সিগুলো ঘোষিত টাইপের ভিত্তিতে সমাধান হয়। তাই একটি নির্দিষ্ট টাইপ দেয় এমন একাধিক "component" ঘোষণা করা সম্ভব নয়।

রাউটগুলো এক জায়গায় ঘোষণা করা হয়, অন্য জায়গায় ঘোষিত ফাংশন ব্যবহার করে (এন্ডপয়েন্ট সামলানো ফাংশনের ঠিক ওপরে বসানো যায় এমন ডেকোরেটর ব্যবহারের বদলে)। এটি Flask (আর Starlette) যেভাবে করে তার চেয়ে Django যেভাবে করে তার কাছাকাছি। এটি কোডে এমন জিনিসগুলো আলাদা করে দেয় যা তুলনামূলকভাবে ঘনিষ্ঠভাবে যুক্ত।

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

মডেল অ্যাট্রিবিউটের "ডিফল্ট" মান ব্যবহার করে ডেটা টাইপের বাড়তি যাচাই সংজ্ঞায়িত করা। এতে এডিটর সাপোর্ট উন্নত হয়, আর আগে Pydantic-এ এটি ছিল না।

এটি আসলে Pydantic-এর কিছু অংশ আপডেট করতে অনুপ্রাণিত করেছে, একই যাচাই-ঘোষণার ধরন সাপোর্ট করতে (এই সব কার্যকারিতা এখন Pydantic-এ আগে থেকেই আছে)।

///

### [Hug](https://github.com/hugapi/hug) { #hug }

Python টাইপ হিন্ট দিয়ে API প্যারামিটারের টাইপ ঘোষণা বাস্তবায়ন করা প্রথম ফ্রেমওয়ার্কগুলোর একটি ছিল Hug। এটি একটি দারুণ ধারণা ছিল যা অন্য টুলগুলোকেও একই কাজ করতে অনুপ্রাণিত করেছে।

এটি ঘোষণায় স্ট্যান্ডার্ড Python টাইপের বদলে কাস্টম টাইপ ব্যবহার করত, তবুও এটি ছিল এক বিশাল পদক্ষেপ।

এটি পুরো API-কে JSON-এ ঘোষণা করে একটি কাস্টম স্কিমা তৈরি করা প্রথম ফ্রেমওয়ার্কগুলোরও একটি ছিল।

এটি OpenAPI আর JSON Schema-র মতো কোনো স্ট্যান্ডার্ডের ওপর ভিত্তি করে ছিল না। তাই Swagger UI-এর মতো অন্য টুলের সাথে এটি যুক্ত করা সোজা হতো না। কিন্তু আবারও, এটি একটি খুবই উদ্ভাবনী ধারণা ছিল।

এর একটি মজার, অস্বাভাবিক ফিচার আছে: একই ফ্রেমওয়ার্ক দিয়ে API আর CLI দুটোই তৈরি করা যায়।

যেহেতু এটি সিঙ্ক্রোনাস Python ওয়েব ফ্রেমওয়ার্কের আগের স্ট্যান্ডার্ড (WSGI)-এর ওপর ভিত্তি করে তৈরি, তাই এটি WebSocket আর অন্যান্য জিনিস সামলাতে পারে না, যদিও এর পারফরম্যান্সও উচ্চ।

/// note | নোট

Hug তৈরি করেছেন Timothy Crosley, যিনি [`isort`](https://github.com/PyCQA/isort)-এরও নির্মাতা, Python ফাইলে ইমপোর্টগুলো স্বয়ংক্রিয়ভাবে সাজানোর একটি দারুণ টুল।

///

/// tip | **FastAPI**-কে অনুপ্রাণিত করা ধারণা

Hug APIStar-এর কিছু অংশকে অনুপ্রাণিত করেছে, আর APIStar-এর পাশাপাশি এটি ছিল আমার কাছে সবচেয়ে সম্ভাবনাময় টুলগুলোর একটি।

Hug **FastAPI**-কে প্যারামিটার ঘোষণায় Python টাইপ হিন্ট ব্যবহার করতে, আর স্বয়ংক্রিয়ভাবে API সংজ্ঞায়িত করা একটি স্কিমা তৈরি করতে অনুপ্রাণিত করতে সাহায্য করেছে।

Hug **FastAPI**-কে হেডার আর কুকি সেট করতে ফাংশনে একটি `response` প্যারামিটার ঘোষণা করতে অনুপ্রাণিত করেছে।

///

### [APIStar](https://github.com/encode/apistar) (<= 0.5) { #apistar-0-5 }

**FastAPI** তৈরির সিদ্ধান্ত নেওয়ার ঠিক আগে আমি **APIStar** সার্ভার খুঁজে পাই। আমি যা খুঁজছিলাম তার প্রায় সবই এতে ছিল আর এর ডিজাইন ছিল দারুণ।

প্যারামিটার আর রিকোয়েস্ট ঘোষণায় Python টাইপ হিন্ট ব্যবহার করা ফ্রেমওয়ার্কের যে বাস্তবায়নগুলো আমি দেখেছি, এটি ছিল তার প্রথমগুলোর একটি (NestJS আর Molten-এর আগে)। আমি এটি কমবেশি Hug-এর সময়েই খুঁজে পাই। কিন্তু APIStar OpenAPI স্ট্যান্ডার্ড ব্যবহার করত।

এতে কয়েক জায়গায় একই টাইপ হিন্টের ভিত্তিতে স্বয়ংক্রিয় ডেটা যাচাই, ডেটা সিরিয়ালাইজেশন আর OpenAPI স্কিমা তৈরি ছিল।

বডি স্কিমার সংজ্ঞা Pydantic-এর মতো একই Python টাইপ হিন্ট ব্যবহার করত না, এটি কিছুটা Marshmallow-এর কাছাকাছি ছিল, তাই এডিটর সাপোর্ট ততটা ভালো হতো না, তবুও APIStar ছিল উপলব্ধ সেরা অপশন।

সেই সময়ে এর বেঞ্চমার্ক পারফরম্যান্স ছিল সেরা (শুধু Starlette একে ছাড়িয়ে গিয়েছিল)।

প্রথমে এতে স্বয়ংক্রিয় API ডকুমেন্টেশনের ওয়েব UI ছিল না, কিন্তু আমি জানতাম যে আমি এতে Swagger UI যোগ করতে পারব।

এতে একটি ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা ছিল। ওপরে আলোচিত অন্য টুলগুলোর মতো এতেও component-গুলো আগে থেকে নিবন্ধন করতে হতো। তবুও, এটি একটি দারুণ ফিচার ছিল।

আমি কখনো এটি একটি পূর্ণ প্রজেক্টে ব্যবহার করতে পারিনি, কারণ এতে নিরাপত্তা সংযোগ ছিল না, তাই Flask-apispec-ভিত্তিক full-stack জেনারেটরে আমার যে সব ফিচার ছিল সেগুলো বদলাতে পারিনি। সেই কার্যকারিতা যোগ করে একটি pull request তৈরি করা আমার করণীয় তালিকায় ছিল।

কিন্তু তারপর, প্রজেক্টের মনোযোগ বদলে গেল।

এটি আর API ওয়েব ফ্রেমওয়ার্ক রইল না, কারণ নির্মাতাকে Starlette-এ মনোযোগ দিতে হয়েছিল।

এখন APIStar হলো OpenAPI স্পেসিফিকেশন যাচাই করার একগুচ্ছ টুল, ওয়েব ফ্রেমওয়ার্ক নয়।

APIStar তৈরি করেছেন Tom Christie। সেই একই ব্যক্তি যিনি তৈরি করেছেন:

* Django REST Framework
* Starlette (যার ওপর **FastAPI** ভিত্তি করে তৈরি)
* Uvicorn (যা Starlette আর **FastAPI** ব্যবহার করে)

/// tip | **FastAPI**-কে যে অনুপ্রেরণা দিয়েছে

অস্তিত্বে আসতে।

একই Python টাইপ দিয়ে একাধিক জিনিস (ডেটা যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশন) ঘোষণা করা, যা একই সাথে দারুণ এডিটর সাপোর্টও দেয়, এই ধারণাটিকে আমি একটি অসাধারণ ধারণা মনে করতাম।

আর দীর্ঘ সময় ধরে একই রকম ফ্রেমওয়ার্ক খুঁজে আর অনেক ভিন্ন বিকল্প পরীক্ষা করার পরে, APIStar ছিল উপলব্ধ সেরা অপশন।

তারপর APIStar সার্ভার হিসেবে থেমে গেল আর Starlette তৈরি হলো, যা এমন একটি ব্যবস্থার জন্য নতুন আর আরও ভালো ভিত্তি ছিল। এটাই ছিল **FastAPI** তৈরির চূড়ান্ত অনুপ্রেরণা।

আমি **FastAPI**-কে APIStar-এর একটি "আত্মিক উত্তরসূরি" মনে করি, যা আগের এই সব টুল থেকে শেখা অভিজ্ঞতার ভিত্তিতে ফিচার, টাইপিং ব্যবস্থা আর অন্যান্য অংশ উন্নত আর সম্প্রসারিত করেছে।

## **FastAPI** যা ব্যবহার করে { #used-by-fastapi }

### [Pydantic](https://pydantic.dev/docs/) { #pydantic }

Pydantic হলো Python টাইপ হিন্টের ভিত্তিতে ডেটা যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশন (JSON Schema ব্যবহার করে) সংজ্ঞায়িত করার একটি লাইব্রেরি।

এটাই একে অত্যন্ত স্বাভাবিক করে তোলে।

এটি Marshmallow-এর সাথে তুলনীয়। যদিও বেঞ্চমার্কে এটি Marshmallow-এর চেয়ে দ্রুত। আর যেহেতু এটি একই Python টাইপ হিন্টের ওপর ভিত্তি করে, তাই এডিটর সাপোর্ট দারুণ।

/// tip | **FastAPI** এটি যে কাজে ব্যবহার করে

সব ডেটা যাচাই, ডেটা সিরিয়ালাইজেশন আর স্বয়ংক্রিয় মডেল ডকুমেন্টেশন (JSON Schema-র ভিত্তিতে) সামলাতে।

তারপর **FastAPI** সেই JSON Schema ডেটা নিয়ে OpenAPI-তে রাখে, এর অন্য সব কাজের পাশাপাশি।

///

### [Starlette](https://starlette.dev/) { #starlette }

Starlette হলো একটি হালকা <dfn title="অ্যাসিঙ্ক্রোনাস Python ওয়েব অ্যাপ্লিকেশন তৈরির নতুন স্ট্যান্ডার্ড">ASGI</dfn> ফ্রেমওয়ার্ক/টুলকিট, যা উচ্চ-পারফরম্যান্স asyncio সার্ভিস তৈরির জন্য আদর্শ।

এটি খুবই সহজ আর স্বাভাবিক। এটি সহজে বাড়ানোর মতো আর মডুলার কম্পোনেন্টসহ ডিজাইন করা।

এতে আছে:

* সত্যিই চমকপ্রদ পারফরম্যান্স।
* WebSocket সাপোর্ট।
* একই প্রসেসে ব্যাকগ্রাউন্ড টাস্ক।
* চালু আর বন্ধ হওয়ার ইভেন্ট।
* HTTPX-এর ওপর তৈরি টেস্ট ক্লায়েন্ট।
* CORS, GZip, স্ট্যাটিক ফাইল, স্ট্রিমিং রেসপন্স।
* সেশন আর কুকি সাপোর্ট।
* ১০০% টেস্ট কভারেজ।
* ১০০% টাইপ অ্যানোটেটেড কোডবেস।
* খুব কম বাধ্যতামূলক ডিপেন্ডেন্সি।

Starlette বর্তমানে পরীক্ষিত দ্রুততম Python ফ্রেমওয়ার্ক। শুধু Uvicorn একে ছাড়িয়ে যায়, যা কোনো ফ্রেমওয়ার্ক নয়, একটি সার্ভার।

Starlette মৌলিক ওয়েব মাইক্রোফ্রেমওয়ার্কের সব কার্যকারিতা দেয়।

কিন্তু এটি স্বয়ংক্রিয় ডেটা যাচাই, সিরিয়ালাইজেশন বা ডকুমেন্টেশন দেয় না।

এটাই **FastAPI** ওপরে যোগ করা প্রধান জিনিসগুলোর একটি, সবই Python টাইপ হিন্টের ভিত্তিতে (Pydantic ব্যবহার করে)। সাথে আছে ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা, নিরাপত্তা ইউটিলিটি, OpenAPI স্কিমা তৈরি ইত্যাদি।

/// note | কারিগরি বিবরণ

ASGI হলো Django-র মূল দলের সদস্যদের তৈরি করা একটি নতুন "স্ট্যান্ডার্ড"। এটি এখনো একটি "Python স্ট্যান্ডার্ড" (একটি PEP) নয়, যদিও তারা তা করার প্রক্রিয়ায় আছেন।

তবুও, এটি ইতিমধ্যে কয়েকটি টুল একটি "স্ট্যান্ডার্ড" হিসেবে ব্যবহার করছে। এতে একসাথে কাজ করার ক্ষমতা অনেক বাড়ে, কারণ আপনি Uvicorn-এর বদলে অন্য যেকোনো ASGI সার্ভার (যেমন Daphne বা Hypercorn) ব্যবহার করতে পারেন, বা `python-socketio`-এর মতো ASGI-সামঞ্জস্যপূর্ণ টুল যোগ করতে পারেন।

///

/// tip | **FastAPI** এটি যে কাজে ব্যবহার করে

ওয়েবের সব মূল অংশ সামলাতে। আর ওপরে ফিচার যোগ করতে।

`FastAPI` ক্লাসটি নিজেই সরাসরি `Starlette` ক্লাস থেকে উত্তরাধিকার (inherit) পায়।

তাই Starlette দিয়ে যা যা করতে পারেন, তার সবই সরাসরি **FastAPI** দিয়ে করতে পারেন, কারণ এটি মূলত আরও শক্তিশালী করা Starlette।

///

### [Uvicorn](https://uvicorn.dev) { #uvicorn }

Uvicorn হলো uvloop আর httptools-এর ওপর তৈরি একটি বিদ্যুৎগতির ASGI সার্ভার।

এটি ওয়েব ফ্রেমওয়ার্ক নয়, একটি সার্ভার। যেমন, এটি পাথ অনুযায়ী রাউটিংয়ের টুল দেয় না। সেটি Starlette (বা **FastAPI**)-এর মতো একটি ফ্রেমওয়ার্ক ওপরে দেয়।

Starlette আর **FastAPI**-এর জন্য এটিই সুপারিশকৃত সার্ভার।

/// tip | **FastAPI** এটিকে যেভাবে সুপারিশ করে

**FastAPI** অ্যাপ্লিকেশন চালানোর প্রধান ওয়েব সার্ভার হিসেবে।

একটি অ্যাসিঙ্ক্রোনাস মাল্টি-প্রসেস সার্ভার পেতে `--workers` কমান্ড লাইন অপশনও ব্যবহার করতে পারেন।

আরও বিস্তারিত দেখুন [ডিপ্লয়মেন্ট](deployment/index.md) অংশে।

## বেঞ্চমার্ক এবং গতি { #benchmarks-and-speed }

Uvicorn, Starlette আর FastAPI-এর মধ্যে পার্থক্য বুঝতে, তুলনা করতে আর দেখতে, [বেঞ্চমার্ক](benchmarks.md) অংশটি দেখুন।

/// check | সংক্ষেপে মনে রাখুন

| টুল | FastAPI যা নিয়েছে |
| --- | --- |
| Django REST Framework | স্বয়ংক্রিয় API ডকস |
| Flask | মাইক্রো-ফ্রেমওয়ার্ক, সহজ রাউটিং |
| Requests | সহজ API, `get`/`post` এর মতো মেথডের নাম |
| Swagger/OpenAPI | খোলা স্ট্যান্ডার্ড, Swagger UI আর ReDoc |
| Marshmallow, Webargs | কোড দিয়ে স্কিমা, আগত ডেটার যাচাই |
| APISpec, Flask-apispec | কোড থেকেই OpenAPI তৈরি |
| NestJS | টাইপ দিয়ে এডিটর সাপোর্ট, ডিপেন্ডেন্সি ইনজেকশন |
| Sanic, Falcon | উচ্চ পারফরম্যান্স, `response` প্যারামিটার |
| Molten, Hug | টাইপ হিন্ট দিয়ে প্যারামিটার আর যাচাই |
| APIStar | পুরো ধারণাটিই, FastAPI এর "আত্মিক উত্তরসূরি" |

আর FastAPI দাঁড়িয়ে আছে তিনটি টুলের ওপর: **Pydantic** (ডেটা), **Starlette** (ওয়েব), **Uvicorn** (সার্ভার)।
