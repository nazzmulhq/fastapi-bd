# মিডলওয়্যার { #middleware }

/// note | এই পেজে যা শিখবেন

* মিডলওয়্যার কী, আর কোথায় কাজে লাগে।
* `@app.middleware("http")` দিয়ে নিজের মিডলওয়্যার বানানো।
* প্রতিটি রিকোয়েস্টে কত সময় লাগল তা মেপে হেডারে যোগ করা।
* একাধিক মিডলওয়্যার কোন ক্রমে চলে।

///

**FastAPI** অ্যাপ্লিকেশনে মিডলওয়্যার যোগ করতে পারেন।

একটি "মিডলওয়্যার" হলো এমন একটি ফাংশন, যা প্রতিটি **রিকোয়েস্ট** কোনো নির্দিষ্ট *পাথ অপারেশনে* প্রসেস হওয়ার আগে সেটি নিয়ে কাজ করে। আর প্রতিটি **রেসপন্স** ফেরত পাঠানোর আগেও সেটি নিয়ে কাজ করে।

* এটি আপনার অ্যাপ্লিকেশনে আসা প্রতিটি **রিকোয়েস্ট** নেয়।
* তারপর ওই **রিকোয়েস্ট** নিয়ে কিছু করতে পারে বা দরকারি যেকোনো কোড চালাতে পারে।
* তারপর **রিকোয়েস্টটি** অ্যাপ্লিকেশনের বাকি অংশে (কোনো *পাথ অপারেশনে*) প্রসেস হতে পাঠিয়ে দেয়।
* তারপর অ্যাপ্লিকেশনের (কোনো *পাথ অপারেশনের*) তৈরি করা **রেসপন্স** নেয়।
* ওই **রেসপন্স** নিয়ে কিছু করতে পারে বা দরকারি যেকোনো কোড চালাতে পারে।
* তারপর **রেসপন্সটি** ফেরত দেয়।

/// tip | উদাহরণ দিয়ে বুঝি

একটি অফিস ভবনের প্রধান ফটকের নিরাপত্তারক্ষীর কথা ভাবুন। যে-ই ঢুকুক, যে তলাতেই যাক, সবাইকে তার সামনে দিয়ে ঢুকতে আর বেরোতে হয়। সে ঢোকার সময়টা খাতায় লেখে, বেরোনোর সময় হাতে একটা পাস ধরিয়ে দেয়। মিডলওয়্যারও তাই: সব রিকোয়েস্ট আর রেসপন্স তার ভেতর দিয়ে যায়। লগ লেখা, সময় মাপা, হেডার যোগ করা, এমন "সবার জন্য একই" কাজের জন্য এটি আদর্শ।

///

/// note | কারিগরি বিবরণ

আপনার যদি `yield`-সহ ডিপেন্ডেন্সি থাকে, তাহলে বের হওয়ার কোডটি মিডলওয়্যারের *পরে* চলবে।

যদি কোনো ব্যাকগ্রাউন্ড টাস্ক থাকে ([ব্যাকগ্রাউন্ড টাস্ক](background-tasks.md) অংশে আছে, পরে দেখবেন), সেগুলো সব মিডলওয়্যারের *পরে* চলবে।

///

## একটি মিডলওয়্যার তৈরি করুন { #create-a-middleware }

একটি মিডলওয়্যার তৈরি করতে একটি ফাংশনের ওপরে `@app.middleware("http")` ডেকোরেটর ব্যবহার করুন।

মিডলওয়্যার ফাংশন পায়:

* `request`।
* একটি ফাংশন `call_next`, যা প্যারামিটার হিসেবে `request` নেবে।
    * এই ফাংশন `request`-টি সংশ্লিষ্ট *পাথ অপারেশনে* পাঠাবে।
    * তারপর সংশ্লিষ্ট *পাথ অপারেশনের* তৈরি করা `response` ফেরত দেবে।
* তারপর ফেরত দেওয়ার আগে `response`-টি আরও পরিবর্তন করতে পারেন।

{* ../../docs_src/middleware/tutorial001_py310.py hl[8:9,11,14] *}

/// tip | পরামর্শ

মনে রাখবেন, নিজস্ব কাস্টম হেডার [`X-` প্রিফিক্স ব্যবহার করে](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers) যোগ করা যায়।

কিন্তু আপনার যদি এমন কাস্টম হেডার থাকে যা ব্রাউজারের একটি ক্লায়েন্টকে দেখাতে চান, তাহলে [Starlette-এর CORS ডকুমেন্টেশনে](https://starlette.dev/middleware/#corsmiddleware) বর্ণিত `expose_headers` প্যারামিটার ব্যবহার করে সেগুলো আপনার CORS কনফিগারেশনে ([CORS (Cross-Origin Resource Sharing)](cors.md)) যোগ করতে হবে।

///

/// note | কারিগরি বিবরণ

`from starlette.requests import Request`-ও ব্যবহার করতে পারতেন।

**FastAPI** ডেভেলপার হিসেবে আপনার সুবিধার জন্য এটি দেয়। কিন্তু এটি সরাসরি Starlette থেকে আসে।

///

### `response`-এর আগে ও পরে { #before-and-after-the-response }

কোনো *পাথ অপারেশন* `request` পাওয়ার আগে, `request`-এর সাথে চালানোর জন্য কোড যোগ করতে পারেন।

আর `response` তৈরি হওয়ার পরে, ফেরত দেওয়ার আগেও।

যেমন, আপনি `X-Process-Time` নামে একটি কাস্টম হেডার যোগ করতে পারেন, যাতে রিকোয়েস্ট প্রসেস করে রেসপন্স তৈরি করতে কত সেকেন্ড লেগেছে তা থাকবে:

/// info | কোডটি সহজ ভাষায়

* লাইন ৮: `@app.middleware("http")`: নিচের ফাংশনটি সব HTTP রিকোয়েস্টের মিডলওয়্যার।
* লাইন ১০: শুরুর সময় নোট করা (`time.perf_counter()` হলো খুব নিখুঁত একটি স্টপওয়াচ)।
* লাইন ১১: `await call_next(request)`: রিকোয়েস্টটি আসল পাথ অপারেশনে পাঠিয়ে তার রেসপন্সের জন্য অপেক্ষা।
* লাইন ১২: কত সময় লাগল তা বের করা।
* লাইন ১৩: রেসপন্সে `X-Process-Time` হেডার যোগ করা।
* লাইন ১৪: রেসপন্স ফেরত দেওয়া।

`call_next`-এর আগের লাইনগুলো রিকোয়েস্টের আগে চলে, পরের লাইনগুলো রেসপন্সের পরে চলে।

///

/// tip | পরামর্শ

এখানে আমরা `time.time()`-এর বদলে [`time.perf_counter()`](https://docs.python.org/3/library/time.html#time.perf_counter) ব্যবহার করছি, কারণ এই ধরনের কাজের জন্য এটি বেশি নিখুঁত হতে পারে। 🤓

## একাধিক মিডলওয়্যার চলার ক্রম { #multiple-middleware-execution-order }

আপনি যখন `@app.middleware()` ডেকোরেটর বা `app.add_middleware()` মেথড দিয়ে একাধিক মিডলওয়্যার যোগ করেন, প্রতিটি নতুন মিডলওয়্যার অ্যাপ্লিকেশনটিকে মুড়ে দেয়, ফলে একটি স্তূপ (stack) তৈরি হয়। সবশেষে যোগ করা মিডলওয়্যারটি থাকে *সবচেয়ে বাইরে*, আর প্রথমটি থাকে *সবচেয়ে ভেতরে*।

রিকোয়েস্টের পথে *সবচেয়ে বাইরের* মিডলওয়্যার প্রথমে চলে।

রেসপন্সের পথে এটি সবশেষে চলে।

যেমন:

```Python
app.add_middleware(MiddlewareA)
app.add_middleware(MiddlewareB)
```

এতে চলার ক্রম হবে এমন:

* **রিকোয়েস্ট**: MiddlewareB → MiddlewareA → route

* **রেসপন্স**: route → MiddlewareA → MiddlewareB

এই স্তূপের মতো আচরণ নিশ্চিত করে যে মিডলওয়্যারগুলো একটি অনুমানযোগ্য আর নিয়ন্ত্রণযোগ্য ক্রমে চলবে।

/// tip | উদাহরণ দিয়ে বুঝি

পেঁয়াজের খোসার মতো ভাবুন। পরে যোগ করা মিডলওয়্যার বাইরের খোসা। রিকোয়েস্ট বাইরে থেকে ভেতরে ঢোকে (B, তারপর A), কেন্দ্রে পাথ অপারেশন, তারপর রেসপন্স ভেতর থেকে বাইরে বেরোয় (A, তারপর B)।

## অন্যান্য মিডলওয়্যার { #other-middlewares }

অন্যান্য মিডলওয়্যার সম্পর্কে পরে আরও পড়তে পারেন [অ্যাডভান্সড ইউজার গাইড: উন্নত মিডলওয়্যার](../advanced/middleware.md)-এ।

পরের অংশে পড়বেন কীভাবে একটি মিডলওয়্যার দিয়ে <abbr title="Cross-Origin Resource Sharing">CORS</abbr> সামলাবেন।

/// check | সংক্ষেপে মনে রাখুন

* মিডলওয়্যার প্রতিটি রিকোয়েস্টের আগে আর প্রতিটি রেসপন্সের পরে চলে।
* বানান: `@app.middleware("http")` আর `async def f(request, call_next)`।
* `response = await call_next(request)`-এর আগে রিকোয়েস্টের কাজ, পরে রেসপন্সের কাজ।
* পরে যোগ করা মিডলওয়্যার সবচেয়ে বাইরে থাকে।
