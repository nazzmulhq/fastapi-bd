# Password (আর হ্যাশিং)-সহ OAuth2, JWT টোকেনসহ Bearer { #oauth2-with-password-and-hashing-bearer-with-jwt-tokens }

/// note | এই পেজে যা শিখবেন

* JWT টোকেন কী, আর কেন এটি নিরাপদ (সই করা, কিন্তু এনক্রিপ্টেড নয়)।
* `pwdlib` দিয়ে আসল, নিরাপদ পাসওয়ার্ড হ্যাশিং।
* `PyJWT` দিয়ে মেয়াদসহ টোকেন তৈরি ও যাচাই।
* "টাইমিং অ্যাটাক" কী, আর কোড কীভাবে তা ঠেকায়।
* পুরো কোডটি ধাপে ধাপে, যা আপনি আসল প্রজেক্টে ব্যবহার করতে পারবেন।

///

এখন যেহেতু পুরো সিকিউরিটি প্রবাহ আমাদের আছে, চলুন <abbr title="JSON Web Tokens">JWT</abbr> টোকেন আর নিরাপদ পাসওয়ার্ড হ্যাশিং ব্যবহার করে অ্যাপ্লিকেশনটিকে সত্যিই নিরাপদ করি।

এই কোড আপনি আসলেই আপনার অ্যাপ্লিকেশনে ব্যবহার করতে পারবেন, আপনার ডেটাবেসে পাসওয়ার্ড হ্যাশ সংরক্ষণ করতে পারবেন, ইত্যাদি।

আগের অধ্যায়ে যেখানে থেমেছিলাম সেখান থেকে শুরু করে ধাপে ধাপে বাড়াব।

## JWT সম্পর্কে { #about-jwt }

JWT মানে "JSON Web Tokens"।

এটি একটি JSON অবজেক্টকে স্পেস ছাড়া একটি লম্বা ঘন স্ট্রিংয়ে রূপান্তর করার স্ট্যান্ডার্ড। এটি দেখতে এমন:

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

ডট (`.`) দিয়ে আলাদা তিনটি অংশ: প্রথমটি হেডার (কোন অ্যালগরিদম), দ্বিতীয়টি আসল তথ্য (যেমন ইউজারের নাম, মেয়াদ), তৃতীয়টি সই।

এটি এনক্রিপ্টেড নয়, তাই যে কেউ এর বিষয়বস্তু থেকে তথ্য বের করতে পারে। (তাই JWT-তে কখনো পাসওয়ার্ডের মতো গোপন তথ্য রাখবেন না।)

কিন্তু এটি সই (signed) করা। তাই আপনার দেওয়া একটি টোকেন ফেরত পেলে যাচাই করতে পারবেন যে এটি আপনিই দিয়েছিলেন।

এভাবে আপনি এমন একটি টোকেন তৈরি করতে পারেন যার মেয়াদ, ধরা যাক, ১ সপ্তাহ। তারপর ইউজার পরের দিন টোকেন নিয়ে ফিরে এলে আপনি জানবেন যে ইউজার এখনো আপনার সিস্টেমে লগইন করা আছে।

এক সপ্তাহ পরে টোকেনের মেয়াদ শেষ হবে, ইউজার আর অনুমোদিত থাকবে না, আর নতুন টোকেন পেতে আবার সাইন ইন করতে হবে। আর ইউজার (বা তৃতীয় কোনো পক্ষ) যদি মেয়াদ বদলাতে টোকেনটি পরিবর্তনের চেষ্টা করে, আপনি তা ধরে ফেলতে পারবেন, কারণ সই মিলবে না।

/// tip | উদাহরণ দিয়ে বুঝি

JWT হলো সিলমোহর দেওয়া একটি খোলা চিঠির মতো। যে কেউ চিঠিটি পড়তে পারে ("এই ব্যক্তি johndoe, মেয়াদ রবিবার পর্যন্ত")। কিন্তু সিলমোহরটি শুধু আপনার কাছে থাকা গোপন চাবি (`SECRET_KEY`) দিয়েই বানানো যায়। কেউ লেখা বদলালে সিলমোহর আর মিলবে না, আর আপনি সাথে সাথে বুঝে যাবেন চিঠিটি জাল।

///

JWT টোকেন নিয়ে খেলে দেখতে আর এগুলো কীভাবে কাজ করে দেখতে চাইলে [https://jwt.io](https://jwt.io/) দেখুন।

## `PyJWT` ইনস্টল করুন { #install-pyjwt }

Python-এ JWT টোকেন তৈরি ও যাচাই করতে `PyJWT` ইনস্টল করতে হবে।

আপনার প্রজেক্টে `pyjwt` যোগ করুন:

<div class="termy">

```console
$ uv add pyjwt

---> 100%
```

</div>

/// note | নোট

আপনি যদি RSA বা ECDSA এর মতো ডিজিটাল সিগনেচার অ্যালগরিদম ব্যবহারের পরিকল্পনা করেন, তাহলে ক্রিপ্টোগ্রাফি লাইব্রেরির ডিপেন্ডেন্সি `pyjwt[crypto]` ইনস্টল করা উচিত।

এ নিয়ে আরও পড়তে পারেন [PyJWT ইনস্টলেশন ডকুমেন্টেশনে](https://pyjwt.readthedocs.io/en/latest/installation.html)।

## পাসওয়ার্ড হ্যাশিং { #password-hashing }

"হ্যাশিং" মানে কোনো বিষয়বস্তুকে (এই ক্ষেত্রে একটি পাসওয়ার্ড) বাইটের একটি ক্রমে (শুধু একটি স্ট্রিং) রূপান্তর করা, যা দেখতে অর্থহীন হিজিবিজির মতো।

হুবহু একই বিষয়বস্তু (হুবহু একই পাসওয়ার্ড) দিলে প্রতিবার হুবহু একই হিজিবিজি পাবেন।

কিন্তু হিজিবিজি থেকে উল্টো পথে পাসওয়ার্ডে ফিরে যাওয়া যায় না।

### কেন পাসওয়ার্ড হ্যাশিং ব্যবহার করবেন { #why-use-password-hashing }

আপনার ডেটাবেস চুরি হলে চোরের কাছে আপনার ইউজারদের সাধারণ টেক্সট পাসওয়ার্ড থাকবে না, শুধু হ্যাশ থাকবে।

তাই চোর ওই পাসওয়ার্ড অন্য কোনো সিস্টেমে ব্যবহারের চেষ্টা করতে পারবে না (অনেক ইউজার সব জায়গায় একই পাসওয়ার্ড ব্যবহার করে, তাই এটি বিপজ্জনক হতো)।

## `pwdlib` ইনস্টল করুন { #install-pwdlib }

pwdlib পাসওয়ার্ড হ্যাশ সামলানোর জন্য একটি দারুণ Python প্যাকেজ।

এটি অনেক নিরাপদ হ্যাশিং অ্যালগরিদম আর সেগুলোর সাথে কাজ করার টুল সাপোর্ট করে।

সুপারিশকৃত অ্যালগরিদম হলো "Argon2"।

Argon2-সহ `pwdlib` আপনার প্রজেক্টে যোগ করুন:

<div class="termy">

```console
$ uv add "pwdlib[argon2]"

---> 100%
```

</div>

/// tip | পরামর্শ

`pwdlib` দিয়ে আপনি এমনকি এটিকে কনফিগার করতে পারেন, যাতে এটি **Django**, একটি **Flask** সিকিউরিটি প্লাগ-ইন বা আরও অনেকগুলোর তৈরি পাসওয়ার্ড পড়তে পারে।

তাই যেমন, একটি Django অ্যাপ্লিকেশনের একই ডেটা একটি ডেটাবেসে একটি FastAPI অ্যাপ্লিকেশনের সাথে ভাগাভাগি করতে পারবেন। অথবা একই ডেটাবেস ব্যবহার করে ধীরে ধীরে একটি Django অ্যাপ্লিকেশন স্থানান্তর করতে পারবেন।

আর আপনার ইউজাররা একই সময়ে আপনার Django অ্যাপ থেকে বা আপনার **FastAPI** অ্যাপ থেকে লগইন করতে পারবে।

## পাসওয়ার্ড হ্যাশ ও যাচাই করুন { #hash-and-verify-the-passwords }

`pwdlib` থেকে দরকারি টুলগুলো ইমপোর্ট করুন।

সুপারিশকৃত সেটিংসসহ একটি PasswordHash ইনস্ট্যান্স তৈরি করুন - এটি পাসওয়ার্ড হ্যাশ আর যাচাই করতে ব্যবহার হবে।

/// tip | পরামর্শ

pwdlib bcrypt হ্যাশিং অ্যালগরিদমও সাপোর্ট করে, তবে পুরোনো (legacy) অ্যালগরিদম রাখে না - পুরোনো হ্যাশ নিয়ে কাজের জন্য passlib লাইব্রেরি ব্যবহারের সুপারিশ করা হয়।

যেমন, অন্য কোনো সিস্টেমের (যেমন Django) তৈরি পাসওয়ার্ড পড়তে ও যাচাই করতে এটি ব্যবহার করতে পারেন, কিন্তু যেকোনো নতুন পাসওয়ার্ড Argon2 বা Bcrypt এর মতো ভিন্ন অ্যালগরিদম দিয়ে হ্যাশ করতে পারেন।

আর একই সময়ে সবগুলোর সাথে সামঞ্জস্যপূর্ণ থাকতে পারেন।

///

ইউজারের কাছ থেকে আসা একটি পাসওয়ার্ড হ্যাশ করার জন্য একটি সহায়ক ফাংশন তৈরি করুন।

আর পাওয়া একটি পাসওয়ার্ড সংরক্ষিত হ্যাশের সাথে মেলে কিনা যাচাইয়ের জন্য আরেকটি।

আর অথেনটিকেট করে একজন ইউজার ফেরত দেওয়ার জন্য আরও একটি।

/// info | কোডটি সহজ ভাষায়

* লাইন ৪৯: `password_hash = PasswordHash.recommended()`: সুপারিশকৃত সেটিংস (Argon2) দিয়ে হ্যাশার তৈরি।
* লাইন ৫১: `DUMMY_HASH`: একটি নকল পাসওয়ার্ডের হ্যাশ, নিচে ব্যাখ্যা করা হয়েছে কেন।
* লাইন ৫৮-৫৯: `verify_password`: সাধারণ পাসওয়ার্ড আর হ্যাশ মেলে কিনা যাচাই, `True`/`False` দেয়।
* লাইন ৬২-৬৩: `get_password_hash`: নতুন পাসওয়ার্ড হ্যাশ করে (যেমন রেজিস্ট্রেশনের সময়)।
* লাইন ৭২-৭৯: `authenticate_user`: ইউজার না পেলে বা পাসওয়ার্ড না মিললে `False`, সব ঠিক থাকলে ইউজার ফেরত দেয়।

///

`authenticate_user`-কে যখন এমন একটি ইউজারনেম দিয়ে ডাকা হয় যা ডেটাবেসে নেই, তখনও আমরা একটি নকল হ্যাশের বিপরীতে `verify_password` চালাই।

এতে নিশ্চিত হয় যে ইউজারনেম বৈধ হোক বা না হোক, এন্ডপয়েন্টটি উত্তর দিতে মোটামুটি একই সময় নেয়। এতে **টাইমিং অ্যাটাক** ঠেকানো যায়, যা দিয়ে কোন কোন ইউজারনেম আছে তার তালিকা বের করা যেত।

/// tip | টাইমিং অ্যাটাক সহজ ভাষায়

পাসওয়ার্ড হ্যাশ যাচাই করতে কিছুটা সময় লাগে (ইচ্ছা করেই ধীর রাখা হয়)। যদি ইউজার না থাকলে কোড সাথে সাথে "না" বলে দিত, আর থাকলে হ্যাশ যাচাইয়ে সময় নিত, তাহলে একজন হ্যাকার শুধু উত্তর আসার সময় মেপেই বুঝে যেত কোন ইউজারনেমগুলো আসল। নকল হ্যাশ যাচাই করে দুই ক্ষেত্রেই সমান সময় নেওয়া হয়, তাই এই সূত্র আর থাকে না।

## JWT টোকেন সামলান { #handle-jwt-tokens }

ইনস্টল করা মডিউলগুলো ইমপোর্ট করুন।

JWT টোকেন সই করতে ব্যবহারের জন্য একটি এলোমেলো গোপন চাবি (secret key) তৈরি করুন।

একটি নিরাপদ এলোমেলো গোপন চাবি তৈরি করতে এই কমান্ডটি ব্যবহার করুন:

<div class="termy">

```console
$ openssl rand -hex 32

09d25e094faa6ca2556c818166b7a9563b93f7099f6f0f4caa6cf63b88e8d3e7
```

</div>

আর আউটপুটটি `SECRET_KEY` ভেরিয়েবলে কপি করুন (উদাহরণেরটি ব্যবহার করবেন না)।

`SECRET_KEY` কখনো কোডে লিখে GitHub-এ তুলবেন না। আসল প্রজেক্টে এটি [এনভায়রনমেন্ট ভেরিয়েবলে](../../environment-variables.md) রাখুন। যার কাছে এই চাবি থাকবে, সে যেকোনো ইউজারের নামে বৈধ টোকেন বানাতে পারবে।

JWT টোকেন সই করতে ব্যবহৃত অ্যালগরিদমসহ একটি `ALGORITHM` ভেরিয়েবল তৈরি করে এটিকে `"HS256"` সেট করুন।

টোকেনের মেয়াদের জন্য একটি ভেরিয়েবল তৈরি করুন।

টোকেন এন্ডপয়েন্টে রেসপন্সের জন্য ব্যবহৃত হবে এমন একটি Pydantic মডেল সংজ্ঞায়িত করুন।

একটি নতুন অ্যাক্সেস টোকেন তৈরির জন্য একটি সহায়ক ফাংশন তৈরি করুন।

### JWT "subject" `sub` নিয়ে কারিগরি বিবরণ { #technical-details-about-the-jwt-subject-sub }

JWT স্পেসিফিকেশন বলে যে `sub` নামে একটি কী আছে, যাতে টোকেনের subject (বিষয়, মানে টোকেনটি কার বা কীসের জন্য) থাকে।

এটি ব্যবহার ঐচ্ছিক, তবে ইউজারের পরিচয় এখানেই রাখার কথা, তাই আমরা এখানে এটি ব্যবহার করছি।

একজন ইউজারকে শনাক্ত করা আর তাকে সরাসরি আপনার API-তে কাজ করতে দেওয়া ছাড়াও JWT অন্য কাজে ব্যবহার হতে পারে।

যেমন, আপনি একটি "গাড়ি" বা একটি "ব্লগ পোস্ট" শনাক্ত করতে পারেন।

তারপর ওই জিনিসটির ওপর অনুমতি যোগ করতে পারেন, যেমন "চালানো" (গাড়ির জন্য) বা "সম্পাদনা" (ব্লগের জন্য)।

আর তারপর সেই JWT টোকেন একজন ইউজারকে (বা বটকে) দিতে পারেন, আর সে এটি ব্যবহার করে ওই কাজগুলো (গাড়ি চালানো, বা ব্লগ পোস্ট সম্পাদনা) করতে পারবে, এমনকি কোনো অ্যাকাউন্ট ছাড়াই, শুধু আপনার API-এর তৈরি করা JWT টোকেন দিয়ে।

এই ধারণাগুলো ব্যবহার করে JWT অনেক বেশি জটিল পরিস্থিতিতে ব্যবহার করা যায়।

সেসব ক্ষেত্রে এদের কয়েকটির একই ID থাকতে পারে, ধরা যাক `foo` (একজন ইউজার `foo`, একটি গাড়ি `foo`, আর একটি ব্লগ পোস্ট `foo`)।

তাই ID-এর সংঘর্ষ এড়াতে, ইউজারের জন্য JWT টোকেন তৈরির সময় `sub` কী-এর মানের আগে কিছু জুড়ে দিতে পারেন, যেমন `username:`। তাহলে এই উদাহরণে `sub`-এর মান হতে পারত: `username:johndoe`।

মনে রাখার জরুরি বিষয় হলো, `sub` কী-তে পুরো অ্যাপ্লিকেশনজুড়ে একটি অনন্য শনাক্তকারী থাকা উচিত, আর এটি একটি স্ট্রিং হওয়া উচিত।

## `scopes`-সহ উন্নত ব্যবহার { #advanced-usage-with-scopes }

OAuth2-তে "scopes"-এর ধারণা আছে।

এগুলো দিয়ে একটি JWT টোকেনে নির্দিষ্ট একগুচ্ছ অনুমতি যোগ করতে পারেন।

তারপর এই টোকেন সরাসরি একজন ইউজার বা তৃতীয় পক্ষকে দিতে পারেন, যাতে তারা কিছু সীমাবদ্ধতাসহ আপনার API-এর সাথে কাজ করতে পারে।

এগুলো কীভাবে ব্যবহার করবেন আর **FastAPI**-তে কীভাবে একীভূত তা পরে **অ্যাডভান্সড ইউজার গাইডে** শিখতে পারবেন।

## সংক্ষেপে { #recap }

এ পর্যন্ত যা দেখেছেন তা দিয়ে OAuth2 আর JWT এর মতো স্ট্যান্ডার্ড ব্যবহার করে একটি নিরাপদ **FastAPI** অ্যাপ্লিকেশন সেটআপ করতে পারবেন।

প্রায় যেকোনো ফ্রেমওয়ার্কে সিকিউরিটি সামলানো খুব দ্রুতই বেশ জটিল একটি বিষয় হয়ে ওঠে।

যেসব প্যাকেজ এটি অনেক সহজ করে দেয়, সেগুলোর অনেককেই ডেটা মডেল, ডেটাবেস আর উপলব্ধ ফিচারের সাথে অনেক আপস করতে হয়। আর এর মধ্যে কিছু প্যাকেজ যেগুলো সবকিছু অতিরিক্ত সহজ করে ফেলে, সেগুলোর ভেতরে আসলে নিরাপত্তার ত্রুটি থাকে।

---

**FastAPI** কোনো ডেটাবেস, ডেটা মডেল বা টুলের সাথে কোনো আপস করে না।

আপনার প্রজেক্টের জন্য যেগুলো সবচেয়ে উপযুক্ত, সেগুলো বেছে নেওয়ার পুরো স্বাধীনতা এটি আপনাকে দেয়।

আর আপনি সরাসরি `pwdlib` আর `PyJWT` এর মতো অনেক ভালোভাবে রক্ষণাবেক্ষণ করা আর বহুল ব্যবহৃত প্যাকেজ ব্যবহার করতে পারেন, কারণ বাইরের প্যাকেজ যুক্ত করতে **FastAPI**-এর কোনো জটিল ব্যবস্থার দরকার হয় না।

তবে নমনীয়তা, মজবুতি বা নিরাপত্তার সাথে আপস না করে প্রক্রিয়াটি যতটা সম্ভব সহজ করার টুল এটি আপনাকে দেয়।

আর আপনি তুলনামূলকভাবে সহজ উপায়ে OAuth2 এর মতো নিরাপদ, স্ট্যান্ডার্ড প্রোটোকল ব্যবহার ও ইমপ্লিমেন্ট করতে পারেন।

এই একই স্ট্যান্ডার্ড অনুসরণ করে আরও সূক্ষ্ম অনুমতি ব্যবস্থার জন্য OAuth2 "scopes" কীভাবে ব্যবহার করবেন, সে সম্পর্কে **অ্যাডভান্সড ইউজার গাইডে** আরও শিখতে পারবেন। Facebook, Google, GitHub, Microsoft, X (Twitter) ইত্যাদির মতো অনেক বড় অথেনটিকেশন প্রোভাইডার তাদের ইউজারদের পক্ষে তৃতীয় পক্ষের অ্যাপ্লিকেশনকে তাদের API-এর সাথে কাজ করার অনুমতি দিতে scopes-সহ OAuth2 ব্যবহার করে।

/// check | সংক্ষেপে মনে রাখুন

* JWT = সই করা টোকেন, যে কেউ পড়তে পারে কিন্তু বদলাতে পারে না। গোপন তথ্য রাখবেন না।
* পাসওয়ার্ড হ্যাশ করুন `pwdlib` (Argon2) দিয়ে: `password_hash.hash(...)`, যাচাই `password_hash.verify(...)`।

* `SECRET_KEY` গোপন রাখুন, এনভায়রনমেন্ট ভেরিয়েবলে রাখুন।
