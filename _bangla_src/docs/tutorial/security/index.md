# সিকিউরিটি { #security }

/// note | এই পেজে যা শিখবেন

* অথেনটিকেশন (আপনি কে) আর অথরাইজেশন (আপনার কী অনুমতি আছে) এর পার্থক্য।
* OAuth2, OpenID Connect, OpenAPI এই নামগুলো আসলে কী।
* OpenAPI কোন কোন সিকিউরিটি পদ্ধতি সংজ্ঞায়িত করে।
* পরের অধ্যায়গুলোতে কী শিখবেন তার একটি মানচিত্র।

///

সিকিউরিটি, অথেনটিকেশন আর অথরাইজেশন সামলানোর অনেক উপায় আছে।

আর সাধারণত এটি একটি জটিল ও "কঠিন" বিষয়।

অনেক ফ্রেমওয়ার্ক আর সিস্টেমে শুধু সিকিউরিটি আর অথেনটিকেশন সামলাতেই প্রচুর পরিশ্রম আর কোড লাগে (অনেক ক্ষেত্রে এটি লেখা মোট কোডের ৫০% বা তারও বেশি হতে পারে)।

**FastAPI** অনেকগুলো টুল দেয়, যাতে আপনি সব সিকিউরিটি স্পেসিফিকেশন পড়ে না শিখেই সহজে, দ্রুত আর একটি স্ট্যান্ডার্ড উপায়ে **সিকিউরিটি** সামলাতে পারেন।

/// tip | দুটি জরুরি শব্দ

* **অথেনটিকেশন (Authentication)**: "আপনি কে?" যাচাই করা। যেমন অফিসে ঢোকার সময় আইডি কার্ড দেখানো, বা ইউজারনেম-পাসওয়ার্ড দিয়ে লগইন।
* **অথরাইজেশন (Authorization)**: "আপনার কী করার অনুমতি আছে?" যাচাই করা। যেমন আইডি কার্ড থাকলেও সবাই সার্ভার রুমে ঢুকতে পারে না, শুধু নির্দিষ্ট কর্মীরা পারে।

আগে অথেনটিকেশন, তারপর অথরাইজেশন।

///

তবে প্রথমে কয়েকটি ছোট ধারণা দেখে নেওয়া যাক।

## তাড়া আছে? { #in-a-hurry }

এসব শব্দ নিয়ে আপনার মাথাব্যথা না থাকলে, আর *এখনই* শুধু ইউজারনেম আর পাসওয়ার্ড-ভিত্তিক অথেনটিকেশনসহ সিকিউরিটি যোগ করতে হলে, পরের অধ্যায়গুলোতে চলে যান।

## OAuth2 { #oauth2 }

OAuth2 হলো একটি স্পেসিফিকেশন, যা অথেনটিকেশন আর অথরাইজেশন সামলানোর বেশ কয়েকটি উপায় সংজ্ঞায়িত করে।

এটি বেশ বিস্তৃত একটি স্পেসিফিকেশন, আর বেশ কয়েকটি জটিল ব্যবহারের ক্ষেত্র কভার করে।

এতে একটি "তৃতীয় পক্ষ" ব্যবহার করে অথেনটিকেট করার উপায়ও আছে।

"Facebook, Google, X (Twitter), GitHub দিয়ে লগইন করুন" ধরনের সব সিস্টেম ভেতরে এটিই ব্যবহার করে।

### OAuth 1 { #oauth-1 }

একটি OAuth 1-ও ছিল, যা OAuth2 থেকে অনেক আলাদা আর আরও জটিল, কারণ এতে যোগাযোগ কীভাবে এনক্রিপ্ট (তালাবদ্ধ) করতে হবে তার সরাসরি স্পেসিফিকেশন ছিল।

এটি আজকাল খুব একটা জনপ্রিয় বা ব্যবহৃত নয়।

OAuth2 যোগাযোগ কীভাবে এনক্রিপ্ট করতে হবে তা নির্দিষ্ট করে না, এটি ধরে নেয় যে আপনার অ্যাপ্লিকেশন HTTPS দিয়ে সার্ভ করা হচ্ছে।

/// tip | পরামর্শ

**ডিপ্লয়মেন্ট** নিয়ে অংশে দেখবেন কীভাবে Traefik আর Let's Encrypt ব্যবহার করে বিনামূল্যে HTTPS সেটআপ করবেন।

///

## OpenID Connect { #openid-connect }

OpenID Connect হলো আরেকটি স্পেসিফিকেশন, যা **OAuth2**-এর ওপর ভিত্তি করে তৈরি।

এটি শুধু OAuth2-কে প্রসারিত করে, OAuth2-তে তুলনামূলকভাবে অস্পষ্ট কিছু বিষয় নির্দিষ্ট করে দিয়ে, যাতে বিভিন্ন সিস্টেম একে অপরের সাথে আরও সহজে কাজ করতে পারে।

যেমন, Google লগইন OpenID Connect ব্যবহার করে (যা ভেতরে OAuth2 ব্যবহার করে)।

কিন্তু Facebook লগইন OpenID Connect সাপোর্ট করে না। এর নিজস্ব ধরনের OAuth2 আছে।

### OpenID ("OpenID Connect" নয়) { #openid-not-openid-connect }

একটি "OpenID" স্পেসিফিকেশনও ছিল। এটি **OpenID Connect**-এর মতো একই সমস্যা সমাধানের চেষ্টা করত, কিন্তু OAuth2-এর ওপর ভিত্তি করে তৈরি ছিল না।

তাই এটি সম্পূর্ণ আলাদা একটি বাড়তি সিস্টেম ছিল।

এটি আজকাল খুব একটা জনপ্রিয় বা ব্যবহৃত নয়।

## OpenAPI { #openapi }

OpenAPI (আগে Swagger নামে পরিচিত) হলো API তৈরির উন্মুক্ত স্পেসিফিকেশন (এখন Linux Foundation-এর অংশ)।

**FastAPI** তৈরি **OpenAPI**-এর ওপর।

এর কারণেই একাধিক স্বয়ংক্রিয় ইন্টারঅ্যাকটিভ ডকুমেন্টেশন ইন্টারফেস, কোড তৈরি ইত্যাদি সম্ভব হয়।

OpenAPI-তে একাধিক সিকিউরিটি "স্কিম" সংজ্ঞায়িত করার উপায় আছে।

সেগুলো ব্যবহার করে আপনি এই সব স্ট্যান্ডার্ড-ভিত্তিক টুলের সুবিধা নিতে পারেন, এই ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমসহ। (যেমন `/docs`-এ একটি "Authorize" বাটন আসে, সেখানে লগইন করে সুরক্ষিত API পরীক্ষা করা যায়।)

OpenAPI এই সিকিউরিটি স্কিমগুলো সংজ্ঞায়িত করে:

* `apiKey`: একটি অ্যাপ্লিকেশন-নির্দিষ্ট কী (গোপন চাবি), যা আসতে পারে:
    * একটি কুয়েরি প্যারামিটার থেকে।
    * একটি হেডার থেকে।
    * একটি কুকি থেকে।
* `http`: স্ট্যান্ডার্ড HTTP অথেনটিকেশন সিস্টেম, যার মধ্যে আছে:
    * `bearer`: `Authorization` নামে একটি হেডার, যার মান `Bearer ` আর তার পরে একটি টোকেন। এটি OAuth2 থেকে এসেছে।
    * HTTP Basic অথেনটিকেশন।
    * HTTP Digest ইত্যাদি।
* `oauth2`: সিকিউরিটি সামলানোর সব OAuth2 উপায় (যাদের বলা হয় "flow" বা প্রবাহ)।
    * এই flow-গুলোর কয়েকটি একটি OAuth 2.0 অথেনটিকেশন প্রোভাইডার (যেমন Google, Facebook, X (Twitter), GitHub ইত্যাদি) বানানোর জন্য উপযুক্ত:
        * `implicit`
        * `clientCredentials`
        * `authorizationCode`
    * কিন্তু একটি নির্দিষ্ট "flow" আছে, যা একই অ্যাপ্লিকেশনে সরাসরি অথেনটিকেশন সামলাতে নিখুঁতভাবে ব্যবহার করা যায়:
        * `password`: পরের কয়েকটি অধ্যায়ে এর উদাহরণ দেখানো হবে।
* `openIdConnect`: স্বয়ংক্রিয়ভাবে OAuth2 অথেনটিকেশন ডেটা খুঁজে বের করার উপায় সংজ্ঞায়িত করে।
    * এই স্বয়ংক্রিয় খুঁজে বের করার ব্যাপারটিই OpenID Connect স্পেসিফিকেশনে সংজ্ঞায়িত।

/// tip | পরামর্শ

Google, Facebook, X (Twitter), GitHub ইত্যাদির মতো অন্য অথেনটিকেশন/অথরাইজেশন প্রোভাইডার যুক্ত করাও সম্ভব আর তুলনামূলকভাবে সহজ।

সবচেয়ে জটিল সমস্যা হলো ওগুলোর মতো একটি অথেনটিকেশন/অথরাইজেশন প্রোভাইডার বানানো, কিন্তু **FastAPI** আপনাকে সহজে এটি করার টুল দেয়, ভারী কাজগুলো আপনার হয়ে করে।

///

## **FastAPI** টুল { #fastapi-utilities }

FastAPI `fastapi.security` মডিউলে এই প্রতিটি সিকিউরিটি স্কিমের জন্য বেশ কয়েকটি টুল দেয়, যা এই সিকিউরিটি ব্যবস্থাগুলো ব্যবহার সহজ করে।

পরের অধ্যায়গুলোতে দেখবেন **FastAPI**-এর দেওয়া ওই টুলগুলো ব্যবহার করে কীভাবে আপনার API-তে সিকিউরিটি যোগ করবেন।

আর এটি কীভাবে স্বয়ংক্রিয়ভাবে ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমে একীভূত হয় তাও দেখবেন।

/// check | সংক্ষেপে মনে রাখুন

* অথেনটিকেশন = আপনি কে, অথরাইজেশন = আপনি কী করতে পারবেন।
* OAuth2 হলো লগইন ও অনুমতির প্রচলিত স্ট্যান্ডার্ড, OpenID Connect এর ওপর তৈরি।
* OpenAPI-এর সিকিউরিটি স্কিম: `apiKey`, `http` (যেমন Bearer টোকেন), `oauth2`, `openIdConnect`।
* পরের অধ্যায়গুলো ধাপে ধাপে ইউজারনেম-পাসওয়ার্ড দিয়ে লগইন আর JWT টোকেন বানানো শেখাবে।
