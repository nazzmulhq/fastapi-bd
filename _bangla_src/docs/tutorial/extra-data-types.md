# বাড়তি ডেটা টাইপ { #extra-data-types }

/// note | এই পেজে যা শিখবেন

* `int`, `str` ছাড়াও তারিখ, সময়, UUID, দশমিক ইত্যাদি জটিল টাইপ ব্যবহার করা।
* এই টাইপগুলো JSON-এ কীভাবে লেখা হয় আর পড়া হয়।

///

এ পর্যন্ত আপনি প্রচলিত ডেটা টাইপগুলো ব্যবহার করেছেন, যেমন:

* `int`
* `float`
* `str`
* `bool`

কিন্তু আরও জটিল ডেটা টাইপও ব্যবহার করতে পারেন।

আর এ পর্যন্ত দেখা সব সুবিধা তখনও পাবেন:

* দারুণ এডিটর সাহায্য।
* আসা রিকোয়েস্ট থেকে ডেটা রূপান্তর।
* রেসপন্স ডেটার জন্য ডেটা রূপান্তর।
* ডেটা যাচাই।
* স্বয়ংক্রিয় অ্যানোটেশন ও ডকুমেন্টেশন।

## অন্যান্য ডেটা টাইপ { #other-data-types }

এখানে কিছু বাড়তি ডেটা টাইপ দেওয়া হলো যা ব্যবহার করতে পারেন:

* `UUID`:
    * একটি স্ট্যান্ডার্ড "Universally Unique Identifier" (সর্বজনীনভাবে অনন্য শনাক্তকারী), অনেক ডেটাবেস ও সিস্টেমে ID হিসেবে প্রচলিত। দেখতে এমন: `3fa85f64-5717-4562-b3fc-2c963f66afa6`। এত লম্বা ও এলোমেলো যে দুটি UUID মিলে যাওয়ার সম্ভাবনা প্রায় শূন্য।
    * রিকোয়েস্ট ও রেসপন্সে এটি একটি `str` হিসেবে উপস্থাপিত হবে।
* `datetime.datetime`:
    * একটি Python `datetime.datetime` (তারিখ ও সময় একসাথে)।
    * রিকোয়েস্ট ও রেসপন্সে এটি ISO 8601 ফরম্যাটে একটি `str` হিসেবে উপস্থাপিত হবে, যেমন: `2008-09-15T15:53:00+05:00`। এখানে `T` তারিখ আর সময়কে আলাদা করে, আর `+05:00` হলো টাইমজোন (বাংলাদেশের জন্য `+06:00`)।
* `datetime.date`:
    * Python `datetime.date` (শুধু তারিখ)।
    * রিকোয়েস্ট ও রেসপন্সে এটি ISO 8601 ফরম্যাটে একটি `str` হিসেবে উপস্থাপিত হবে, যেমন: `2008-09-15`।
* `datetime.time`:
    * একটি Python `datetime.time` (শুধু সময়)।
    * রিকোয়েস্ট ও রেসপন্সে এটি ISO 8601 ফরম্যাটে একটি `str` হিসেবে উপস্থাপিত হবে, যেমন: `14:23:55.003`।
* `datetime.timedelta`:
    * একটি Python `datetime.timedelta` (সময়ের ব্যবধান, যেমন "২ ঘণ্টা ৩০ মিনিট")।
    * রিকোয়েস্ট ও রেসপন্সে এটি মোট সেকেন্ডের একটি `float` হিসেবে উপস্থাপিত হবে।
    * Pydantic এটিকে "ISO 8601 time diff encoding" হিসেবেও উপস্থাপন করতে দেয়, [আরও তথ্যের জন্য ডকুমেন্টেশন দেখুন](https://pydantic.dev/docs/validation/latest/concepts/serialization/#custom-serializers)।
* `frozenset`:
    * রিকোয়েস্ট ও রেসপন্সে এটি একটি `set`-এর মতোই ধরা হয়:
        * রিকোয়েস্টে একটি লিস্ট পড়া হবে, পুনরাবৃত্তি বাদ দিয়ে একটি `set`-এ রূপান্তর করা হবে।
        * রেসপন্সে `set`-টি একটি `list`-এ রূপান্তরিত হবে।
        * তৈরি হওয়া স্কিমা উল্লেখ করবে যে `set`-এর মানগুলো অনন্য (JSON Schema-র `uniqueItems` ব্যবহার করে)।
* `bytes`:
    * স্ট্যান্ডার্ড Python `bytes`।
    * রিকোয়েস্ট ও রেসপন্সে `str` হিসেবে ধরা হবে।
    * তৈরি হওয়া স্কিমা উল্লেখ করবে যে এটি `binary` "format"-সহ একটি `str`।
* `Decimal`:
    * স্ট্যান্ডার্ড Python `Decimal`। টাকা-পয়সার হিসাবে খুব কাজের, কারণ `float`-এ `0.1 + 0.2` হয় `0.30000000000000004`, কিন্তু `Decimal`-এ হুবহু `0.3`।
    * রিকোয়েস্ট ও রেসপন্সে একটি `float`-এর মতোই সামলানো হয়।
* বৈধ সব Pydantic ডেটা টাইপ এখানে দেখতে পারেন: [Pydantic ডেটা টাইপ](https://pydantic.dev/docs/validation/latest/concepts/types/)।

/// info | কোডটি সহজ ভাষায়

* লাইন ১২: `item_id: UUID`: পাথ থেকে আসবে, একটি বৈধ UUID হতে হবে।
* লাইন ১৩-১৪: শুরু ও শেষের তারিখ-সময়, বডি থেকে।
* লাইন ১৫: `process_after: timedelta`: কতক্ষণ পরে কাজ শুরু হবে, যেমন `3600` পাঠালে ১ ঘণ্টা।
* লাইন ১৬: `repeat_at`: কোন সময়ে পুনরাবৃত্তি হবে, ঐচ্ছিক।
* লাইন ১৮: `start_datetime + process_after`: তারিখের সাথে সময়ের ব্যবধান যোগ, ফলাফল নতুন একটি তারিখ-সময়।
* লাইন ১৯: `end_datetime - start_process`: দুই তারিখ-সময়ের পার্থক্য, ফলাফল একটি `timedelta`।

ক্লায়েন্ট টেক্সট পাঠায় (যেমন `"2024-01-15T10:00:00"`), কিন্তু ফাংশনে আপনি আসল `datetime` অবজেক্ট পান, তাই সরাসরি যোগ-বিয়োগ করা যায়। রেসপন্সে আবার সব টেক্সটে রূপান্তরিত হয়ে যায়।

* `UUID`, `datetime`, `date`, `time`, `timedelta`, `Decimal`, `bytes`, `frozenset` সবই টাইপ হিসেবে ব্যবহার করা যায়।
* JSON-এ এগুলো টেক্সট বা সংখ্যা হিসেবে যায়, কিন্তু ফাংশনে আসল Python অবজেক্ট হিসেবে পান।
* তারিখ-সময়ের জন্য ISO 8601 ফরম্যাট: `2024-01-15T10:00:00+06:00`।
