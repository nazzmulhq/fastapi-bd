# টেস্টিং { #testing }

/// note | এই পেজে যা শিখবেন

* টেস্ট কেন লিখবেন, আর `TestClient` দিয়ে সার্ভার না চালিয়েই API পরীক্ষা করা।
* `pytest` দিয়ে টেস্ট লেখা ও চালানো (`test_` দিয়ে শুরু ফাংশন, `assert`)।
* টেস্ট আলাদা ফাইলে রাখা।
* হেডার, JSON বডি, ফর্ম, কুকি পাঠিয়ে টেস্ট করা।

///

[Starlette](https://starlette.dev/testclient/)-এর কল্যাণে **FastAPI** অ্যাপ্লিকেশন টেস্ট করা সহজ ও আনন্দদায়ক।

এটি [HTTPX](https://www.python-httpx.org)-এর ওপর তৈরি, যা আবার Requests-এর আদলে ডিজাইন করা, তাই এটি খুবই পরিচিত আর সহজবোধ্য।

এটি দিয়ে **FastAPI**-এর সাথে সরাসরি [pytest](https://docs.pytest.org/) ব্যবহার করতে পারেন।

/// tip | কেন টেস্ট লিখবেন?

প্রতিবার কোড বদলানোর পরে `/docs`-এ গিয়ে হাতে হাতে সব পাথ পরীক্ষা করা ক্লান্তিকর আর ভুলের সম্ভাবনা থাকে। টেস্ট হলো এমন কোড, যা এক কমান্ডেই সব পরীক্ষা করে জানিয়ে দেয় কিছু ভেঙেছে কিনা। একবার লিখলে প্রতিবার বিনামূল্যে নিশ্চিন্ত থাকা যায়।

///

## `TestClient` ব্যবহার { #using-testclient }

/// note | নোট

`TestClient` ব্যবহার করতে প্রথমে [`httpx`](https://www.python-httpx.org) ইনস্টল করুন।

আপনার প্রজেক্টে এটি যোগ করুন:

```console
$ uv add httpx
```

///

`TestClient` ইমপোর্ট করুন।

আপনার **FastAPI** অ্যাপ্লিকেশনটি দিয়ে একটি `TestClient` তৈরি করুন।

`test_` দিয়ে শুরু হওয়া নামের ফাংশন তৈরি করুন (এটি `pytest`-এর একটি স্ট্যান্ডার্ড নিয়ম)।

`httpx`-এর মতোই `TestClient` অবজেক্টটি ব্যবহার করুন।

যা যাচাই করতে চান তার জন্য সাধারণ Python এক্সপ্রেশন দিয়ে সহজ `assert` স্টেটমেন্ট লিখুন (আবারও, স্ট্যান্ডার্ড `pytest`)।

{* ../../docs_src/app_testing/tutorial001_py310.py hl[2,12,15:18] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ২: `TestClient` ইমপোর্ট।
* লাইন ১২: `client = TestClient(app)`: আপনার অ্যাপের জন্য একটি "নকল ব্রাউজার" তৈরি। এটি আসল নেটওয়ার্ক ছাড়াই সরাসরি অ্যাপকে রিকোয়েস্ট পাঠায়।
* লাইন ১৫: `test_` দিয়ে শুরু, তাই `pytest` এটিকে টেস্ট হিসেবে চিনবে।
* লাইন ১৬: `/` পাথে `GET` রিকোয়েস্ট পাঠানো।
* লাইন ১৭-১৮: `assert` মানে "এটা সত্য হতেই হবে"। স্ট্যাটাস কোড ২০০ আর JSON ঠিক না হলে টেস্ট ব্যর্থ হবে আর কোথায় পার্থক্য তা দেখাবে।

///

/// tip | পরামর্শ

খেয়াল করুন, টেস্টিং ফাংশনগুলো সাধারণ `def`, `async def` নয়।

আর ক্লায়েন্টকে ডাকাগুলোও সাধারণ ডাক, `await` ব্যবহার না করে।

এতে কোনো জটিলতা ছাড়াই সরাসরি `pytest` ব্যবহার করতে পারেন।

///

/// note | কারিগরি বিবরণ

`from starlette.testclient import TestClient`-ও ব্যবহার করতে পারতেন।

**FastAPI** ডেভেলপার হিসেবে আপনার সুবিধার জন্যই একই `starlette.testclient`-কে `fastapi.testclient` হিসেবে দেয়। কিন্তু এটি সরাসরি Starlette থেকে আসে।

///

/// tip | পরামর্শ

আপনার FastAPI অ্যাপ্লিকেশনে রিকোয়েস্ট পাঠানো ছাড়াও যদি টেস্টে `async` ফাংশন ডাকতে চান (যেমন অ্যাসিঙ্ক্রোনাস ডেটাবেস ফাংশন), তাহলে অ্যাডভান্সড টিউটোরিয়ালের [Async টেস্ট](../advanced/async-tests.md) দেখুন।

## টেস্ট আলাদা করা { #separating-tests }

একটি আসল অ্যাপ্লিকেশনে সম্ভবত আপনার টেস্টগুলো একটি আলাদা ফাইলে থাকবে।

আর আপনার **FastAPI** অ্যাপ্লিকেশনও হয়তো কয়েকটি ফাইল/মডিউল ইত্যাদি দিয়ে তৈরি হবে।

### **FastAPI** অ্যাপ ফাইল { #fastapi-app-file }

ধরা যাক আপনার ফাইল কাঠামো [বড় অ্যাপ্লিকেশন](bigger-applications.md)-এ বর্ণিত কাঠামোর মতো:

```
.
├── app
│   ├── __init__.py
│   └── main.py
```

`main.py` ফাইলে আপনার **FastAPI** অ্যাপ আছে:

{* ../../docs_src/app_testing/app_a_py310/main.py *}

### টেস্টিং ফাইল { #testing-file }

তারপর আপনার টেস্টগুলোসহ একটি `test_main.py` ফাইল থাকতে পারে। এটি একই Python প্যাকেজে থাকতে পারে (একটি `__init__.py` ফাইলসহ একই ফোল্ডারে):

``` hl_lines="5"
.
├── app
│   ├── __init__.py
│   ├── main.py
│   └── test_main.py
```

যেহেতু এই ফাইলটি একই প্যাকেজে, তাই `main` মডিউল (`main.py`) থেকে `app` অবজেক্ট ইমপোর্ট করতে রিলেটিভ ইমপোর্ট ব্যবহার করতে পারেন:

{* ../../docs_src/app_testing/app_a_py310/test_main.py hl[3] *}

...আর টেস্টের কোড আগের মতোই রাখতে পারেন।

## টেস্টিং: বিস্তৃত উদাহরণ { #testing-extended-example }

এবার এই উদাহরণটি বাড়িয়ে আরও খুঁটিনাটি যোগ করি, যাতে বিভিন্ন অংশ কীভাবে টেস্ট করতে হয় তা দেখা যায়।

### বিস্তৃত **FastAPI** অ্যাপ ফাইল { #extended-fastapi-app-file }

আগের মতোই একই ফাইল কাঠামো চালিয়ে যাই:

```
.
├── app
│   ├── __init__.py
│   ├── main.py
│   └── test_main.py
```

ধরা যাক এখন আপনার **FastAPI** অ্যাপসহ `main.py` ফাইলে আরও কিছু **পাথ অপারেশন** আছে।

এতে একটি `GET` অপারেশন আছে, যা একটি এরর ফেরত দিতে পারে।

এতে একটি `POST` অপারেশন আছে, যা কয়েকটি এরর ফেরত দিতে পারে।

দুটো *পাথ অপারেশনেই* একটি `X-Token` হেডার লাগে।

### বিস্তৃত টেস্টিং ফাইল { #extended-testing-file }

তারপর বিস্তৃত টেস্টগুলো দিয়ে `test_main.py` হালনাগাদ করতে পারেন:

{* ../../docs_src/app_testing/app_b_an_py310/test_main.py *}

/// info | টেস্টগুলো সহজ ভাষায়

প্রতিটি টেস্ট একটি নির্দিষ্ট পরিস্থিতি যাচাই করে:

* `test_read_item`: সঠিক টোকেন, আছে এমন আইটেম → ২০০ আর আইটেমের তথ্য।
* `test_read_item_bad_token`: ভুল টোকেন → ৪০০।
* `test_read_nonexistent_item`: নেই এমন আইটেম → ৪০৪।
* `test_create_item`: সঠিক টোকেন, নতুন আইটেম → ২০০।
* `test_create_item_bad_token`: ভুল টোকেনে তৈরি → ৪০০।
* `test_create_existing_item`: আগে থেকে আছে এমন আইটেম আবার তৈরি → ৪০৯ (conflict)।

ভালো টেস্টে শুধু "সব ঠিক থাকলে কী হয়" নয়, "কিছু ভুল হলে কী হয়" সেটাও যাচাই করা হয়।

///

যখনই ক্লায়েন্টকে রিকোয়েস্টে কোনো তথ্য পাঠাতে হবে আর আপনি জানেন না কীভাবে, তখন `httpx`-এ কীভাবে করতে হয় তা খুঁজতে পারেন (Google-এ), এমনকি `requests` দিয়ে কীভাবে করতে হয় তাও, কারণ HTTPX-এর ডিজাইন Requests-এর ডিজাইনের ওপর ভিত্তি করে তৈরি।

তারপর টেস্টেও ঠিক একই কাজ করুন।

যেমন:

* একটি *পাথ* বা *কুয়েরি* প্যারামিটার পাঠাতে URL-এর সাথেই যোগ করে দিন।
* একটি JSON বডি পাঠাতে `json` প্যারামিটারে একটি Python অবজেক্ট (যেমন একটি `dict`) দিন।
* JSON-এর বদলে *ফর্ম ডেটা* পাঠাতে হলে এর বদলে `data` প্যারামিটার ব্যবহার করুন।
* *হেডার* পাঠাতে `headers` প্যারামিটারে একটি `dict` ব্যবহার করুন।
* *কুকির* জন্য `cookies` প্যারামিটারে একটি `dict`।

ব্যাকএন্ডে ডেটা কীভাবে পাঠাতে হয় (`httpx` বা `TestClient` ব্যবহার করে) সে সম্পর্কে আরও তথ্যের জন্য [HTTPX ডকুমেন্টেশন](https://www.python-httpx.org) দেখুন।

/// note | নোট

খেয়াল করুন, `TestClient` JSON-এ রূপান্তরযোগ্য ডেটা গ্রহণ করে, Pydantic মডেল নয়।

আপনার টেস্টে যদি একটি Pydantic মডেল থাকে আর টেস্টিংয়ের সময় এর ডেটা অ্যাপ্লিকেশনে পাঠাতে চান, তাহলে [JSON-সামঞ্জস্যপূর্ণ এনকোডার](encoder.md)-এ বর্ণিত `jsonable_encoder` ব্যবহার করতে পারেন।

## চালান { #run-it }

এরপর শুধু `pytest` ইনস্টল করতে হবে।

আপনার প্রজেক্টে এটি যোগ করুন:

<div class="termy">

```console
$ uv add pytest

---> 100%
```

</div>

এটি স্বয়ংক্রিয়ভাবে ফাইল আর টেস্টগুলো খুঁজে বের করে চালাবে, আর ফলাফল আপনাকে জানাবে।

টেস্টগুলো চালান এভাবে:

<div class="termy">

```console
$ uv run pytest

test_main.py <span style="color: green; white-space: pre;">......                            [100%]</span>

<span style="color: green;">================= 1 passed in 0.03s =================</span>
```

</div>

আউটপুটে প্রতিটি সফল টেস্টের জন্য একটি `.` বা সবুজ লেখা, আর ব্যর্থ টেস্টের জন্য `F` আর বিস্তারিত কারণ দেখাবে।

/// check | সংক্ষেপে মনে রাখুন

* `client = TestClient(app)` দিয়ে সার্ভার না চালিয়েই অ্যাপে রিকোয়েস্ট পাঠান।
* টেস্ট ফাংশনের নাম `test_` দিয়ে শুরু, সাধারণ `def`, ভেতরে `assert`।
* `client.get(url, headers=..., cookies=...)`, `client.post(url, json=...)` বা `data=...`।
* চালান `uv run pytest` দিয়ে।
* সফল আর ব্যর্থ দুই পরিস্থিতিই টেস্ট করুন।
