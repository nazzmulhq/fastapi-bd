# বডি - নেস্টেড মডেল { #body-nested-models }

/// note | এই পেজে যা শিখবেন

* মডেলের ভেতরে লিস্ট আর সেট রাখা।
* একটি মডেলের ভেতরে আরেকটি মডেল (নেস্টেড বা স্তরে স্তরে সাজানো মডেল)।
* `HttpUrl`-এর মতো বিশেষ টাইপ দিয়ে যাচাই।
* বডি হিসেবে সরাসরি একটি লিস্ট বা ডিকশনারি গ্রহণ করা।

///

**FastAPI** দিয়ে যত গভীর স্তরেই সাজানো (নেস্টেড) মডেল হোক, সেগুলো সংজ্ঞায়িত, যাচাই, ডকুমেন্ট আর ব্যবহার করতে পারেন (Pydantic-এর কল্যাণে)।

"নেস্টেড" মানে একটির ভেতরে আরেকটি, যেমন রাশিয়ান পুতুলের ভেতরে পুতুল। একটি অর্ডারের ভেতরে অনেকগুলো পণ্য, প্রতিটি পণ্যের ভেতরে অনেকগুলো ছবি, এভাবে।

### টাইপ প্যারামিটারসহ একটি `list` ঘোষণা করুন { #declare-a-list-with-a-type-parameter }

যেসব টাইপের টাইপ প্যারামিটার (ভেতরের টাইপ) থাকে, যেমন `list`, `dict`, `tuple`, সেগুলো ঘোষণা করতে
তৃতীয় বন্ধনী `[` আর `]` দিয়ে ভেতরের টাইপ(গুলো) "টাইপ প্যারামিটার" হিসেবে দিন

```Python
my_list: list[str]
```

এটা পুরোপুরি টাইপ ঘোষণার স্ট্যান্ডার্ড Python সিনট্যাক্স।

ভেতরের টাইপসহ মডেলের অ্যাট্রিবিউটের জন্যও এই একই স্ট্যান্ডার্ড সিনট্যাক্স ব্যবহার করুন।

## সেট টাইপ { #set-types }

কিন্তু একটু ভাবলে বোঝা যায়, ট্যাগগুলো পুনরাবৃত্তি হওয়া উচিত নয়, সম্ভবত সেগুলো অনন্য (ইউনিক) স্ট্রিং হবে।

আর অনন্য জিনিসের সেটের জন্য Python-এর একটি বিশেষ ডেটা টাইপ আছে, `set`।

তাহলে `tags`-কে স্ট্রিংয়ের একটি সেট হিসেবে ঘোষণা করা যায়:

{* ../../docs_src/body_nested_models/tutorial003_py310.py hl[12] *}

এতে, পুনরাবৃত্ত ডেটাসহ রিকোয়েস্ট এলেও সেটি অনন্য জিনিসের একটি সেটে রূপান্তরিত হবে।

যেমন ক্লায়েন্ট `"tags": ["বই", "নতুন", "বই"]` পাঠালে আপনি পাবেন `{"বই", "নতুন"}`, দ্বিতীয় "বই" বাদ পড়ে যাবে।

আর যখনই ওই ডেটা আউটপুট দেবেন, উৎসে পুনরাবৃত্তি থাকলেও, এটি অনন্য জিনিসের সেট হিসেবেই আউটপুট হবে।

আর সেই অনুযায়ী এটি অ্যানোটেট / ডকুমেন্টও করা হবে।

## নেস্টেড মডেল { #nested-models }

একটি Pydantic মডেলের প্রতিটি অ্যাট্রিবিউটের একটি টাইপ আছে।

কিন্তু সেই টাইপ নিজেই আরেকটি Pydantic মডেল হতে পারে।

তাই নির্দিষ্ট অ্যাট্রিবিউটের নাম, টাইপ আর যাচাইসহ অনেক গভীর স্তরে সাজানো JSON "অবজেক্ট" ঘোষণা করতে পারেন।

এসবই, যত খুশি স্তরে।

তারপর এটিকে একটি অ্যাট্রিবিউটের টাইপ হিসেবে ব্যবহার করতে পারি:

{* ../../docs_src/body_nested_models/tutorial004_py310.py hl[18] *}

এর মানে **FastAPI** এরকম একটি বডি আশা করবে:

```JSON
{
    "name": "Foo",
    "description": "The pretender",
    "price": 42.0,
    "tax": 3.2,
    "tags": ["rock", "metal", "bar"],
    "image": {
        "url": "http://example.com/baz.jpg",
        "name": "The Foo live"
    }
}
```

/// info | কোডটি সহজ ভাষায়

* লাইন ৭-৯: `Image` মডেল, যাতে আছে একটি `url` আর একটি `name`।
* লাইন ১৮: `image: Image | None = None`: `Item`-এর ভেতরে একটি ঐচ্ছিক `image`, যার আকার `Image` মডেলের মতো।
* তাই JSON-এ `"image"` কী-এর ভেতরে আরেকটি অবজেক্ট (`{"url": ..., "name": ...}`) থাকে, আর FastAPI সেটিরও যাচাই করে। `image`-এর ভেতরে `name` না থাকলে এরর আসবে, আর এররের `loc`-এ লেখা থাকবে `["body", "image", "name"]`, মানে ঠিক কোন স্তরে সমস্যা।

///

আবারও, শুধু ওই ঘোষণাটুকু দিয়েই **FastAPI**-তে পাবেন:

* এডিটরের সাহায্য (কমপ্লিশন ইত্যাদি), নেস্টেড মডেলের ক্ষেত্রেও
* ডেটা রূপান্তর
* ডেটা যাচাই
* স্বয়ংক্রিয় ডকুমেন্টেশন

## বিশেষ টাইপ ও যাচাই { #special-types-and-validation }

`str`, `int`, `float` ইত্যাদির মতো সাধারণ একক টাইপ ছাড়াও আরও জটিল একক টাইপ ব্যবহার করতে পারেন, যেগুলো `str` থেকে ইনহেরিট করে।

আপনার কাছে কী কী অপশন আছে তা দেখতে [Pydantic-এর টাইপের সারসংক্ষেপ](https://pydantic.dev/docs/validation/latest/concepts/types/) দেখুন। পরের অধ্যায়ে কিছু উদাহরণ দেখবেন।

যেমন, `Image` মডেলে যেহেতু একটি `url` ফিল্ড আছে, তাই এটিকে `str`-এর বদলে Pydantic-এর `HttpUrl`-এর একটি ইনস্ট্যান্স হিসেবে ঘোষণা করতে পারি:

{* ../../docs_src/body_nested_models/tutorial005_py310.py hl[2,8] *}

স্ট্রিংটি একটি বৈধ URL কিনা তা যাচাই করা হবে, এবং JSON Schema / OpenAPI-তেও সেভাবেই ডকুমেন্ট করা হবে।

যেমন `"url": "hello"` পাঠালে এরর আসবে, কিন্তু `"url": "https://example.com/photo.jpg"` ঠিক আছে।

## শুধু লিস্টের বডি { #bodies-of-pure-lists }

আপনি যে JSON বডি আশা করছেন তার সবচেয়ে ওপরের মানটি যদি একটি JSON `array` (একটি Python `list`) হয়, তাহলে Pydantic মডেলের মতোই ফাংশনের প্যারামিটারে টাইপটি ঘোষণা করতে পারেন:

```Python
images: list[Image]
```

যেমন:

{* ../../docs_src/body_nested_models/tutorial008_py310.py hl[13] *}

এখানে বডিটি নিজেই একটি তালিকা, যেমন `[{"url": "...", "name": "a"}, {"url": "...", "name": "b"}]`। একসাথে অনেকগুলো ছবি আপলোডের তথ্য পাঠানোর মতো ক্ষেত্রে এটা কাজে লাগে।

## যেকোনো `dict`-এর বডি { #bodies-of-arbitrary-dicts }

একটি বডিকে এমন একটি `dict` হিসেবেও ঘোষণা করতে পারেন, যার কী-গুলো এক টাইপের আর মানগুলো অন্য টাইপের।

এভাবে আপনাকে আগে থেকে জানতে হবে না বৈধ ফিল্ড/অ্যাট্রিবিউটের নামগুলো কী (যেমনটা Pydantic মডেলের ক্ষেত্রে হয়)।

যেসব কী আপনি আগে থেকে জানেন না, সেগুলো গ্রহণ করতে চাইলে এটি কাজে লাগবে।

সেটিই আমরা এখানে দেখব।

এই ক্ষেত্রে, যেকোনো `dict` গ্রহণ করবেন, যতক্ষণ এর কী-গুলো `int` আর মানগুলো `float`:

কিন্তু Pydantic-এর স্বয়ংক্রিয় ডেটা রূপান্তর আছে।

এর মানে, আপনার API-এর ক্লায়েন্টরা কী হিসেবে কেবল স্ট্রিং পাঠাতে পারলেও, যতক্ষণ সেই স্ট্রিংগুলোতে শুধু পূর্ণসংখ্যা থাকে, Pydantic সেগুলো রূপান্তর আর যাচাই করবে।

**FastAPI**-তে আপনি Pydantic মডেলের দেওয়া সর্বোচ্চ নমনীয়তা পান, অথচ কোড থাকে সহজ, ছোট আর সুন্দর।

আর সাথে সব সুবিধা:

* এডিটরের সাহায্য (সব জায়গায় কমপ্লিশন!)
* ডেটা রূপান্তর (পার্সিং / সিরিয়ালাইজেশন নামেও পরিচিত)
* ডেটা যাচাই
* স্কিমা ডকুমেন্টেশন
* স্বয়ংক্রিয় ডকুমেন্টেশন

/// check | সংক্ষেপে মনে রাখুন

* লিস্ট: `list[str]`, অনন্য মানের সংগ্রহ: `set[str]`।
* একটি মডেলকে আরেকটি মডেলের অ্যাট্রিবিউটের টাইপ হিসেবে দিলেই নেস্টেড মডেল হয়ে যায়।
* মডেলের লিস্ট: `list[Image]`।
* URL যাচাই করতে `HttpUrl` এর মতো বিশেষ টাইপ ব্যবহার করুন।
* অজানা কী-ওয়ালা ডেটার জন্য `dict[int, float]` এর মতো টাইপ।
