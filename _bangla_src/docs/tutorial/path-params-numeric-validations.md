# পাথ প্যারামিটার ও সংখ্যার যাচাই { #path-parameters-and-numeric-validations }

/// note | এই পেজে যা শিখবেন

* `Path` দিয়ে পাথ প্যারামিটারে শিরোনাম ও যাচাইয়ের নিয়ম যোগ করা।
* Python-এ প্যারামিটারের ক্রমের একটি ঝামেলা আর তার সমাধান (`Annotated` বা `*`)।
* সংখ্যার সীমা ঠিক করা: `gt`, `ge`, `lt`, `le`।

///

`Query` দিয়ে যেমন কুয়েরি প্যারামিটারে আরও যাচাই ও মেটাডেটা ঘোষণা করা যায়, ঠিক তেমনই `Path` দিয়ে পাথ প্যারামিটারেও একই ধরনের যাচাই ও মেটাডেটা ঘোষণা করা যায়।

প্রথমে `fastapi` থেকে `Path` ইমপোর্ট করুন, আর `Annotated`-ও ইমপোর্ট করুন:

আপনার কাছে পুরোনো সংস্করণ থাকলে `Annotated` ব্যবহার করতে গেলে এরর পাবেন।

## মেটাডেটা ঘোষণা করুন { #declare-metadata }

`Query`-র সব প্যারামিটার এখানেও ঘোষণা করতে পারেন।

যেমন, পাথ প্যারামিটার `item_id`-এর জন্য একটি `title` মেটাডেটা ঘোষণা করতে লিখতে পারেন:

{* ../../docs_src/path_params_numeric_validations/tutorial001_an_py310.py hl[10] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ১০: `item_id: Annotated[int, Path(title="The ID of the item to get")]` মানে `item_id` একটি পূর্ণসংখ্যা, পাথ থেকে আসবে, আর ডকুমেন্টেশনে এর শিরোনাম দেখাবে "The ID of the item to get"।
* লাইন ১১: `q` একটি ঐচ্ছিক কুয়েরি প্যারামিটার, যার URL-এ নাম `item-query` (alias)।

///

/// note | নোট

একটি পাথ প্যারামিটার সবসময়ই আবশ্যক, কারণ এটিকে পাথের অংশ হতেই হবে। আপনি `None` দিয়ে ঘোষণা করলেও বা ডিফল্ট মান দিলেও কোনো প্রভাব পড়বে না, এটি সবসময় আবশ্যকই থাকবে।

যুক্তিটা সহজ: `/items/{item_id}` পাথে `item_id` না থাকলে পাথটাই হয়ে যায় `/items/`, যা আলাদা একটি ঠিকানা।

## প্যারামিটারগুলো প্রয়োজনমতো সাজান { #order-the-parameters-as-you-need }

/// tip | পরামর্শ

আপনি `Annotated` ব্যবহার করলে এটি সম্ভবত তেমন জরুরি বা প্রয়োজনীয় নয়।

///

ধরা যাক আপনি কুয়েরি প্যারামিটার `q`-কে একটি আবশ্যক `str` হিসেবে ঘোষণা করতে চান।

আর ওই প্যারামিটারের জন্য আর কিছু ঘোষণা করার দরকার নেই, তাই আসলে `Query` ব্যবহারেরও দরকার নেই।

কিন্তু `item_id` পাথ প্যারামিটারের জন্য আপনাকে তবুও `Path` ব্যবহার করতে হবে। আর কোনো কারণে আপনি `Annotated` ব্যবহার করতে চান না।

"ডিফল্ট" ছাড়া একটি মানের আগে "ডিফল্ট"সহ একটি মান রাখলে Python আপত্তি করবে। (`Path(...)` এখানে ডিফল্ট মানের জায়গায় বসে, তাই Python এটিকে ডিফল্টসহ প্যারামিটার ভাবে।)

কিন্তু আপনি ক্রম বদলে নিতে পারেন, আর ডিফল্ট ছাড়া মানটি (কুয়েরি প্যারামিটার `q`) প্রথমে রাখতে পারেন।

**FastAPI**-এর কাছে এটা কোনো ব্যাপার না। এটি প্যারামিটারগুলো চেনে তাদের নাম, টাইপ আর ডিফল্ট ঘোষণা (`Query`, `Path` ইত্যাদি) দেখে, ক্রম নিয়ে মাথা ঘামায় না।

তাই আপনার ফাংশন এভাবে ঘোষণা করতে পারেন:

{* ../../docs_src/path_params_numeric_validations/tutorial002_py310.py hl[7] *}

তবে মনে রাখবেন, `Annotated` ব্যবহার করলে এই সমস্যা হবে না। কারণ তখন `Query()` বা `Path()`-এর জন্য ফাংশন প্যারামিটারের ডিফল্ট মান ব্যবহার করছেন না, তাই ক্রম নিয়ে চিন্তা নেই।

## প্যারামিটারগুলো প্রয়োজনমতো সাজানো, কিছু কৌশল { #order-the-parameters-as-you-need-tricks }

/// tip | পরামর্শ

আপনি `Annotated` ব্যবহার করলে এটি সম্ভবত তেমন জরুরি বা প্রয়োজনীয় নয়।

///

এখানে একটি **ছোট কৌশল** দেওয়া হলো যা কাজে লাগতে পারে, তবে প্রায়ই দরকার হবে না।

যদি আপনি চান:

* `q` কুয়েরি প্যারামিটারটি `Query` বা কোনো ডিফল্ট মান ছাড়াই ঘোষণা করতে
* `Path` ব্যবহার করে পাথ প্যারামিটার `item_id` ঘোষণা করতে
* এগুলোকে ভিন্ন ক্রমে রাখতে
* `Annotated` ব্যবহার না করতে

...তাহলে এর জন্য Python-এর একটি ছোট্ট বিশেষ সিনট্যাক্স আছে।

ফাংশনের প্রথম প্যারামিটার হিসেবে `*` দিন।

Python ওই `*` দিয়ে কিছুই করবে না, কিন্তু বুঝবে যে পরের সব প্যারামিটার কিওয়ার্ড আর্গুমেন্ট (নাম=মান জোড়া) হিসেবে ডাকতে হবে, যাদের <abbr title="এসেছে: K-ey W-ord Arg-uments থেকে"><code>kwargs</code></abbr>-ও বলা হয়। ডিফল্ট মান না থাকলেও। কিওয়ার্ড আর্গুমেন্টের ক্ষেত্রে Python ক্রম নিয়ে আপত্তি করে না।

{* ../../docs_src/path_params_numeric_validations/tutorial003_py310.py hl[7] *}

### `Annotated` দিয়ে আরও ভালো { #better-with-annotated }

মনে রাখবেন, `Annotated` ব্যবহার করলে যেহেতু ফাংশন প্যারামিটারের ডিফল্ট মান ব্যবহার করছেন না, তাই এই সমস্যা হবে না, এবং সম্ভবত `*` ব্যবহারেরও দরকার হবে না।

## সংখ্যার যাচাই: এর চেয়ে বড় বা সমান { #number-validations-greater-than-or-equal }

`Query` আর `Path` (এবং পরে দেখবেন এমন আরও কিছু) দিয়ে সংখ্যার শর্ত ঘোষণা করা যায়।

এখানে `ge=1` দিলে `item_id`-কে `1`-এর "চেয়ে বড় বা সমান" (`g`reater than or `e`qual) একটি পূর্ণসংখ্যা হতে হবে।

{* ../../docs_src/path_params_numeric_validations/tutorial004_an_py310.py hl[10] *}

এখন `/items/0` বা `/items/-5` পাঠালে এরর আসবে, `/items/1` বা তার বেশি হলে ঠিক আছে। আইডি সাধারণত ১ থেকে শুরু হয়, তাই এমন নিয়ম খুব কাজের।

## সংখ্যার যাচাই: এর চেয়ে বড়, আর এর চেয়ে ছোট বা সমান { #number-validations-greater-than-and-less-than-or-equal }

একই কথা প্রযোজ্য:

* `gt`: এর চেয়ে বড় (`g`reater `t`han)
* `le`: এর চেয়ে ছোট বা সমান (`l`ess than or `e`qual)

{* ../../docs_src/path_params_numeric_validations/tutorial005_an_py310.py hl[10] *}

এখানে `gt=0, le=1000` মানে `item_id` শূন্যের চেয়ে বড় এবং ১০০০ বা তার কম হতে হবে, অর্থাৎ ১ থেকে ১০০০।

## সংখ্যার যাচাই: দশমিক সংখ্যা, এর চেয়ে বড় আর এর চেয়ে ছোট { #number-validations-floats-greater-than-and-less-than }

সংখ্যার যাচাই `float` (দশমিক) মানের ক্ষেত্রেও কাজ করে।

এখানেই শুধু <abbr title="greater than - এর চেয়ে বড়"><code>ge</code></abbr> নয়, <abbr title="greater than - এর চেয়ে বড়"><code>gt</code></abbr> ঘোষণা করতে পারাটা জরুরি হয়ে ওঠে। কারণ এটি দিয়ে আপনি দাবি করতে পারেন যে, যেমন, একটি মান অবশ্যই `0`-এর চেয়ে বড় হবে, যদিও তা `1`-এর চেয়ে ছোট।

তাই `0.5` বৈধ মান হবে। কিন্তু `0.0` বা `0` হবে না।

আর <abbr title="less than - এর চেয়ে ছোট"><code>lt</code></abbr>-এর ক্ষেত্রেও একই কথা।

{* ../../docs_src/path_params_numeric_validations/tutorial006_an_py310.py hl[13] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ১০: `*` দিয়ে শুরু, তাই পরের সব প্যারামিটার যেকোনো ক্রমে রাখা যায়।
* লাইন ১১: `item_id` পাথ থেকে আসবে, ০ থেকে ১০০০ এর মধ্যে (`ge=0, le=1000`)।
* লাইন ১২: `q` একটি আবশ্যক কুয়েরি প্যারামিটার।
* লাইন ১৩: `size` একটি দশমিক সংখ্যা, কুয়েরি থেকে আসবে, `0`-এর চেয়ে বড় আর `10.5`-এর চেয়ে ছোট হতে হবে। যেমন `?size=2.5` ঠিক, `?size=0` বা `?size=11` ভুল।

## সংক্ষেপে { #recap }

`Query`, `Path` (এবং এখনো দেখেননি এমন আরও কিছু) দিয়ে মেটাডেটা আর স্ট্রিং যাচাই ঘোষণা করতে পারেন, ঠিক [কুয়েরি প্যারামিটার ও স্ট্রিং ভ্যালিডেশনের](query-params-str-validations.md) মতোই।

আর সংখ্যার যাচাইও ঘোষণা করতে পারেন:

* `gt`: এর চেয়ে বড় (`g`reater `t`han)
* `ge`: এর চেয়ে বড় বা সমান (`g`reater than or `e`qual)
* `lt`: এর চেয়ে ছোট (`l`ess `t`han)
* `le`: এর চেয়ে ছোট বা সমান (`l`ess than or `e`qual)

/// tip | মনে রাখার সহজ উপায়

| লিখবেন | গণিতের চিহ্ন | উদাহরণ (`5` দিলে) |
|---|---|---|
| `gt=5` | `>` ৫ | ৬ ঠিক, ৫ ভুল |
| `ge=5` | `≥` ৫ | ৫ ঠিক, ৪ ভুল |
| `lt=5` | `<` ৫ | ৪ ঠিক, ৫ ভুল |
| `le=5` | `≤` ৫ | ৫ ঠিক, ৬ ভুল |

`e` থাকলে "সমান"-ও চলবে (`e`qual)।

///

/// note | নোট

`Query`, `Path` এবং পরে যেসব ক্লাস দেখবেন সেগুলো একটি সাধারণ `Param` ক্লাসের সাব-ক্লাস।

এরা সবাই বাড়তি যাচাই ও মেটাডেটার জন্য আপনার দেখা একই প্যারামিটারগুলো ভাগাভাগি করে।

///

/// note | কারিগরি বিবরণ

আপনি যখন `fastapi` থেকে `Query`, `Path` ইত্যাদি ইমপোর্ট করেন, সেগুলো আসলে ফাংশন।

যেগুলো ডাকলে একই নামের ক্লাসের ইনস্ট্যান্স রিটার্ন করে।

অর্থাৎ আপনি `Query` ইমপোর্ট করেন, যা একটি ফাংশন। আর এটি ডাকলে `Query` নামেরই একটি ক্লাসের ইনস্ট্যান্স রিটার্ন করে।

এই ফাংশনগুলো রাখা হয়েছে (সরাসরি ক্লাস ব্যবহার না করে) যাতে আপনার এডিটর এদের টাইপ নিয়ে ভুল এরর না দেখায়।

এভাবে আপনি সাধারণ এডিটর আর কোডিং টুল ব্যবহার করতে পারেন, ওই এররগুলো উপেক্ষা করার জন্য আলাদা কনফিগারেশন যোগ না করেই।

///

/// check | সংক্ষেপে মনে রাখুন

* পাথ প্যারামিটারে নিয়ম যোগ করতে `Annotated[int, Path(...)]`।
* পাথ প্যারামিটার সবসময় আবশ্যক।
* `Annotated` ব্যবহার করলে প্যারামিটারের ক্রম নিয়ে ঝামেলা নেই। না করলে প্রথমে `*` দিয়ে সমাধান করা যায়।
* সংখ্যার সীমা: `gt`, `ge`, `lt`, `le`, পূর্ণসংখ্যা ও দশমিক দুই ক্ষেত্রেই কাজ করে।
