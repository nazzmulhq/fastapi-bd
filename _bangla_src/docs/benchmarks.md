# বেঞ্চমার্ক { #benchmarks }

/// note | এই পেজে যা জানবেন

* বেঞ্চমার্ক (গতির তুলনা পরীক্ষা) কী, আর FastAPI এতে কোথায় দাঁড়িয়ে।
* Uvicorn, Starlette আর FastAPI-এর সম্পর্ক, আর কেন এদের সরাসরি তুলনা করা ঠিক নয়।
* বেঞ্চমার্কের ফলাফল সঠিকভাবে পড়ার নিয়ম।

///

স্বাধীন TechEmpower বেঞ্চমার্ক দেখায় যে Uvicorn-এর অধীনে চলা **FastAPI** অ্যাপ্লিকেশনগুলো [উপলব্ধ দ্রুততম Python ফ্রেমওয়ার্কগুলোর একটি](https://www.techempower.com/benchmarks/#section=test&runid=7464e520-0dc2-473d-bd34-dbdfd7e85911&hw=ph&test=query&l=zijzen-7), শুধু Starlette আর Uvicorn-এর নিচে (যা FastAPI নিজেই ভেতরে ব্যবহার করে)।

কিন্তু বেঞ্চমার্ক আর তুলনা দেখার সময় নিচের বিষয়গুলো মাথায় রাখা উচিত।

## বেঞ্চমার্ক এবং গতি { #benchmarks-and-speed }

বেঞ্চমার্ক দেখলে, প্রায়ই ভিন্ন ভিন্ন ধরনের কয়েকটি টুলকে সমতুল্য হিসেবে তুলনা করতে দেখা যায়।

বিশেষ করে, Uvicorn, Starlette আর FastAPI-কে একসাথে তুলনা করতে দেখা যায় (আরও অনেক টুলের মধ্যে)।

টুলটি যত সহজ সমস্যার সমাধান করে, তত ভালো পারফরম্যান্স পায়। আর বেশিরভাগ বেঞ্চমার্ক টুলটির দেওয়া বাড়তি ফিচারগুলো পরীক্ষা করে না।

স্তরবিন্যাসটি এরকম:

* **Uvicorn**: একটি ASGI সার্ভার
    * **Starlette**: (Uvicorn ব্যবহার করে) একটি ওয়েব মাইক্রোফ্রেমওয়ার্ক
        * **FastAPI**: (Starlette ব্যবহার করে) API তৈরির জন্য ডেটা যাচাই ইত্যাদি কয়েকটি বাড়তি ফিচারসহ একটি API মাইক্রোফ্রেমওয়ার্ক।

/// tip | উদাহরণ দিয়ে বুঝি

একটি খালি গাড়ির চেসিস (Uvicorn), তার ওপর বডি আর সিট বসানো গাড়ি (Starlette), আর তার ওপর AC, GPS, এয়ারব্যাগসহ পূর্ণ গাড়ি (FastAPI)। খালি চেসিস অবশ্যই সবচেয়ে হালকা আর দ্রুত, কিন্তু তাতে চড়ে অফিস যাবেন না। আর যদি নিজে চেসিসে সিট, AC, এয়ারব্যাগ লাগান, শেষে ওজন পূর্ণ গাড়ির মতোই হবে। তাই তুলনা করতে হয় একই শ্রেণির গাড়ির মধ্যে।

///

* **Uvicorn**:
    * এর পারফরম্যান্স সবচেয়ে ভালো হবে, কারণ সার্ভারটি ছাড়া এতে খুব বেশি বাড়তি কোড নেই।
    * আপনি সরাসরি Uvicorn-এ একটি অ্যাপ্লিকেশন লিখবেন না। সেটা করলে আপনার কোডে কমবেশি অন্তত Starlette (বা **FastAPI**)-এর দেওয়া সব কোড রাখতে হতো। আর তা করলে, আপনার চূড়ান্ত অ্যাপ্লিকেশনের বাড়তি ভার (overhead) একটি ফ্রেমওয়ার্ক ব্যবহার করার মতোই হতো, অথচ ফ্রেমওয়ার্ক ব্যবহার করলে আপনার অ্যাপের কোড আর বাগ কম থাকত।
    * যদি Uvicorn তুলনা করেন, তাহলে এটিকে Daphne, Hypercorn, uWSGI ইত্যাদির সাথে তুলনা করুন। অ্যাপ্লিকেশন সার্ভারগুলোর সাথে।
* **Starlette**:
    * Uvicorn-এর পরে এর পারফরম্যান্স সবচেয়ে ভালো হবে। আসলে, Starlette চলতে Uvicorn ব্যবহার করে। তাই বেশি কোড চালাতে হওয়ায় এটি সম্ভবত Uvicorn-এর চেয়ে শুধু "ধীর" হতে পারে।
    * কিন্তু এটি আপনাকে পাথ-ভিত্তিক রাউটিং ইত্যাদিসহ সহজ ওয়েব অ্যাপ্লিকেশন তৈরির টুল দেয়।
    * যদি Starlette তুলনা করেন, তাহলে এটিকে Sanic, Flask, Django ইত্যাদির সাথে তুলনা করুন। ওয়েব ফ্রেমওয়ার্ক (বা মাইক্রোফ্রেমওয়ার্ক)-এর সাথে।
* **FastAPI**:
    * যেভাবে Starlette Uvicorn ব্যবহার করে আর এর চেয়ে দ্রুত হতে পারে না, সেভাবে **FastAPI** Starlette ব্যবহার করে, তাই এটি এর চেয়ে দ্রুত হতে পারে না।
    * FastAPI Starlette-এর ওপরে আরও ফিচার দেয়। এমন ফিচার যা API তৈরির সময় প্রায় সবসময় দরকার হয়, যেমন ডেটা যাচাই আর সিরিয়ালাইজেশন। আর এটি ব্যবহার করে আপনি বিনামূল্যে স্বয়ংক্রিয় ডকুমেন্টেশন পান (স্বয়ংক্রিয় ডকুমেন্টেশন চলমান অ্যাপ্লিকেশনে বাড়তি ভারও যোগ করে না, এটি চালু হওয়ার সময় তৈরি হয়)।
    * যদি FastAPI ব্যবহার না করে সরাসরি Starlette (বা Sanic, Flask, Responder এর মতো অন্য টুল) ব্যবহার করতেন, তাহলে সব ডেটা যাচাই আর সিরিয়ালাইজেশন আপনাকে নিজে বাস্তবায়ন করতে হতো। তাই আপনার চূড়ান্ত অ্যাপ্লিকেশনের বাড়তি ভার তবুও FastAPI দিয়ে তৈরি করার মতোই হতো। আর অনেক ক্ষেত্রে, এই ডেটা যাচাই আর সিরিয়ালাইজেশনই অ্যাপ্লিকেশনে লেখা কোডের সবচেয়ে বড় অংশ।
    * তাই FastAPI ব্যবহার করে আপনি ডেভেলপমেন্টের সময়, বাগ, কোডের লাইন বাঁচাচ্ছেন, আর সম্ভবত এটি ব্যবহার না করলে যে পারফরম্যান্স পেতেন তা-ই (বা তার চেয়ে ভালো) পাবেন (কারণ তখন সবকিছু আপনাকে নিজের কোডে বাস্তবায়ন করতে হতো)।
    * যদি FastAPI তুলনা করেন, তাহলে এটিকে এমন একটি ওয়েব অ্যাপ্লিকেশন ফ্রেমওয়ার্ক (বা টুলের সমষ্টি)-এর সাথে তুলনা করুন যা ডেটা যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশন দেয়, যেমন Flask-apispec, NestJS, Molten ইত্যাদি। সমন্বিত স্বয়ংক্রিয় ডেটা যাচাই, সিরিয়ালাইজেশন আর ডকুমেন্টেশনসহ ফ্রেমওয়ার্কগুলোর সাথে।
