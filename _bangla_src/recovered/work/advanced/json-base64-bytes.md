# Base64 হিসেবে বাইটসহ JSON { #json-with-bytes-as-base64 }

আপনার অ্যাপের যদি JSON ডেটা গ্রহণ ও পাঠাতে হয়, কিন্তু তাতে বাইনারি ডেটা অন্তর্ভুক্ত করতে হয়, তাহলে আপনি সেটি base64 হিসেবে এনকোড করতে পারেন।

## Base64 বনাম ফাইল { #base64-vs-files }

প্রথমে বিবেচনা করুন JSON-এ এনকোড করার বদলে বাইনারি ডেটা আপলোডের জন্য [রিকোয়েস্ট ফাইল](../tutorial/request-files.md) এবং বাইনারি ডেটা পাঠানোর জন্য [কাস্টম রেসপন্স - FileResponse](./custom-response.md#fileresponse) ব্যবহার করতে পারেন কিনা।

JSON-এ কেবল UTF-8 এনকোড করা স্ট্রিং থাকতে পারে, তাই এতে কাঁচা বাইট থাকতে পারে না।

Base64 বাইনারি ডেটাকে স্ট্রিংয়ে এনকোড করতে পারে, তবে এটি করতে মূল বাইনারি ডেটার চেয়ে বেশি অক্ষর ব্যবহার করতে হয়, তাই এটি সাধারণত সাধারণ ফাইলের চেয়ে কম দক্ষ।

কেবল তখনই base64 ব্যবহার করুন যদি আপনাকে অবশ্যই JSON-এ বাইনারি ডেটা অন্তর্ভুক্ত করতে হয়, এবং এর জন্য ফাইল ব্যবহার করতে না পারেন।

## Pydantic `bytes` { #pydantic-bytes }

আপনি `bytes` ফিল্ডসহ একটি Pydantic মডেল ঘোষণা করে, তারপর মডেল কনফিগে `val_json_bytes` ব্যবহার করে এটিকে ইনপুট JSON ডেটা *ভ্যালিডেট* করতে base64 ব্যবহার করতে বলতে পারেন, সেই ভ্যালিডেশনের অংশ হিসেবে এটি base64 স্ট্রিংকে বাইটে ডিকোড করবে।

## আউটপুট ডেটার জন্য Pydantic `bytes` { #pydantic-bytes-for-output-data }

আউটপুট ডেটার জন্য আপনি মডেল কনফিগে `ser_json_bytes`-সহ `bytes` ফিল্ডও ব্যবহার করতে পারেন, আর JSON রেসপন্স তৈরির সময় Pydantic বাইটগুলোকে base64 হিসেবে *সিরিয়ালাইজ* করবে।

## ইনপুট ও আউটপুট ডেটার জন্য Pydantic `bytes` { #pydantic-bytes-for-input-and-output-data }

আর অবশ্যই, JSON ডেটা গ্রহণ ও পাঠানোর সময় `val_json_bytes` দিয়ে ইনপুট (*ভ্যালিডেট*) এবং `ser_json_bytes` দিয়ে আউটপুট (*সিরিয়ালাইজ*) দুটোই সামলাতে আপনি base64 ব্যবহারের জন্য কনফিগার করা একই মডেল ব্যবহার করতে পারেন।
