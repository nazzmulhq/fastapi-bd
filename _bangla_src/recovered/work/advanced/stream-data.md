# ডেটা স্ট্রিম { #stream-data }

আপনি যদি JSON হিসেবে সাজানো যায় এমন ডেটা স্ট্রিম করতে চান, তাহলে আপনার উচিত [JSON Lines স্ট্রিম করা](../tutorial/stream-json-lines.md)।

কিন্তু আপনি যদি **খাঁটি বাইনারি ডেটা** বা স্ট্রিং **স্ট্রিম করতে** চান, তাহলে এখানে দেখানো হলো কীভাবে করবেন।

/// note | নোট

FastAPI 0.134.0-এ যোগ করা হয়েছে।

///

## ব্যবহারের ক্ষেত্র { #use-cases }

আপনি যদি খাঁটি স্ট্রিং স্ট্রিম করতে চান, যেমন সরাসরি কোনো **AI LLM** সার্ভিসের আউটপুট থেকে, তাহলে এটি ব্যবহার করতে পারেন।

আপনি এটি **বড় বাইনারি ফাইল** স্ট্রিম করতেও ব্যবহার করতে পারেন, যেখানে পুরোটা একবারে মেমরিতে না পড়ে, পড়তে পড়তে ডেটার প্রতিটি অংশ স্ট্রিম করেন।

এভাবে আপনি **ভিডিও** বা **অডিও**-ও স্ট্রিম করতে পারেন, এমনকি প্রসেস করে পাঠানোর সময়ই এটি তৈরি হতে পারে।

## `yield`-সহ একটি `StreamingResponse` { #a-streamingresponse-with-yield }

আপনি যদি আপনার *পাথ অপারেশন ফাংশনে* একটি `response_class=StreamingResponse` ঘোষণা করেন, তাহলে একে একে ডেটার প্রতিটি অংশ পাঠাতে `yield` ব্যবহার করতে পারেন।

### অ্যানোটেশন ছাড়া { #no-annotation }

বাইনারি ডেটা স্ট্রিম করার জন্য রিটার্ন টাইপ অ্যানোটেশন ঘোষণা করার আসলে দরকার নেই।

যেহেতু FastAPI Pydantic দিয়ে ডেটাকে JSON-এ রূপান্তর বা কোনোভাবে সিরিয়ালাইজ করার চেষ্টা করবে না, তাই এক্ষেত্রে টাইপ অ্যানোটেশন কেবল আপনার এডিটর ও টুলের ব্যবহারের জন্য, FastAPI এটি ব্যবহার করবে না।

{* ../../docs_src/stream_data/tutorial001_py310.py ln[32:35] hl[33] *}

এর মানে এটাও যে `StreamingResponse`-এ টাইপ অ্যানোটেশন থেকে স্বাধীনভাবে ডেটার বাইটগুলো ঠিক যেভাবে পাঠানো দরকার সেভাবে তৈরি ও এনকোড করার **স্বাধীনতা** ও **দায়িত্ব** দুটোই আপনার। 🤓

## একটি কাস্টম `PNGStreamingResponse` { #a-custom-pngstreamingresponse }

ওপরের উদাহরণগুলোতে ডেটার বাইটগুলো স্ট্রিম করা হয়েছে, কিন্তু রেসপন্সে কোনো `Content-Type` হেডার ছিল না, তাই ক্লায়েন্ট জানত না কোন ধরনের ডেটা পাচ্ছে।

আপনি `StreamingResponse`-এর একটি কাস্টম সাব-ক্লাস তৈরি করতে পারেন যা `Content-Type` হেডারকে আপনার স্ট্রিম করা ডেটার টাইপে সেট করে।

### একটি ফাইলের অনুকরণ { #simulate-a-file }

এই উদাহরণে আমরা `io.BytesIO` দিয়ে একটি ফাইলের অনুকরণ করছি, যা একটি file-like অবজেক্ট যা কেবল মেমরিতে থাকে, তবে আমাদের একই ইন্টারফেস ব্যবহার করতে দেয়।

যেমন, ফাইলের মতোই এর বিষয়বস্তু নিতে আমরা এর ওপর ইটারেট করতে পারি।

শুধু এজন্য যাতে এই উদাহরণের জন্য এটি একই ফাইলে থাকতে পারে এবং আপনি এটি কপি করে যেমন আছে তেমন চালাতে পারেন। 🥚

একটি `with` ব্লক ব্যবহার করে আমরা নিশ্চিত করি যে জেনারেটর ফাংশন (`yield`-সহ ফাংশন) শেষ হওয়ার পরে, অর্থাৎ রেসপন্স পাঠানো শেষ হওয়ার পরে file-like অবজেক্টটি বন্ধ হয়।

এই নির্দিষ্ট উদাহরণে এটি ততটা গুরুত্বপূর্ণ নয়, কারণ এটি একটি নকল ইন-মেমরি ফাইল (`io.BytesIO`-সহ), কিন্তু একটি আসল ফাইলের ক্ষেত্রে এটি নিয়ে কাজ শেষ হওয়ার পরে ফাইলটি বন্ধ হচ্ছে তা নিশ্চিত করা গুরুত্বপূর্ণ।

### ফাইল ও Async { #files-and-async }

বেশিরভাগ ক্ষেত্রে file-like অবজেক্টগুলো ডিফল্টভাবে async ও await-এর সাথে সামঞ্জস্যপূর্ণ নয়।

যেমন, এগুলোতে কোনো `await file.read()` বা `async for chunk in file` নেই।

আর অনেক ক্ষেত্রে এগুলো পড়া একটি ব্লকিং অপারেশন হবে (যা ইভেন্ট লুপ ব্লক করতে পারে), কারণ এগুলো ডিস্ক বা নেটওয়ার্ক থেকে পড়া হয়।

/// note | নোট

ওপরের উদাহরণটি আসলে একটি ব্যতিক্রম, কারণ `io.BytesIO` অবজেক্টটি আগে থেকেই মেমরিতে আছে, তাই এটি পড়লে কিছুই ব্লক হবে না।

তবে অনেক ক্ষেত্রে একটি ফাইল বা file-like অবজেক্ট পড়া ব্লক করবে।

///

ইভেন্ট লুপ ব্লক হওয়া এড়াতে আপনি শুধু *পাথ অপারেশন ফাংশনটি* `async def`-এর বদলে সাধারণ `def` দিয়ে ঘোষণা করতে পারেন, এতে FastAPI মূল লুপ ব্লক হওয়া এড়াতে এটি একটি থ্রেডপুল ওয়ার্কারে চালাবে।

### `yield from` { #yield-from }

আপনি যখন কোনো কিছুর ওপর ইটারেট করছেন, যেমন একটি file-like অবজেক্ট, এবং তারপর প্রতিটি আইটেমের জন্য `yield` করছেন, তখন `for` লুপ বাদ দিয়ে সরাসরি প্রতিটি আইটেম yield করতে `yield from`-ও ব্যবহার করতে পারেন।

এটি FastAPI-এর নিজস্ব কিছু নয়, এটি শুধুই Python, তবে জেনে রাখার মতো একটি সুন্দর কৌশল। 😎
