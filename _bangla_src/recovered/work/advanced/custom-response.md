# কাস্টম রেসপন্স - HTML, স্ট্রিম, ফাইল ও অন্যান্য { #custom-response-html-stream-file-others }

ডিফল্টভাবে **FastAPI** JSON রেসপন্স রিটার্ন করবে।

[সরাসরি একটি Response রিটার্ন করুন](response-directly.md)-এ যেমন দেখেছেন, সরাসরি একটি `Response` রিটার্ন করে আপনি এটি ওভাররাইড করতে পারেন।

কিন্তু আপনি যদি সরাসরি একটি `Response` (বা এর কোনো সাবক্লাস, যেমন `JSONResponse`) রিটার্ন করেন, তাহলে ডেটা স্বয়ংক্রিয়ভাবে রূপান্তরিত হবে না (এমনকি আপনি একটি `response_model` ঘোষণা করলেও), এবং ডকুমেন্টেশন স্বয়ংক্রিয়ভাবে তৈরি হবে না (যেমন, তৈরি হওয়া OpenAPI-এর অংশ হিসেবে HTTP হেডার `Content-Type`-এ নির্দিষ্ট "মিডিয়া টাইপ" অন্তর্ভুক্ত করা)।

তবে আপনি *পাথ অপারেশন ডেকোরেটরে* `response_class` প্যারামিটার ব্যবহার করে কোন `Response` (যেমন যেকোনো `Response` সাবক্লাস) ব্যবহার হবে তাও ঘোষণা করতে পারেন।

আপনার *পাথ অপারেশন ফাংশন* থেকে আপনি যে বিষয়বস্তু রিটার্ন করবেন তা ওই `Response`-এর ভেতরে রাখা হবে।

/// note | নোট

আপনি যদি মিডিয়া টাইপ ছাড়া একটি রেসপন্স ক্লাস ব্যবহার করেন, তাহলে FastAPI আশা করবে যে আপনার রেসপন্সে কোনো কনটেন্ট নেই, তাই এটি তার তৈরি করা OpenAPI ডকুমেন্টেশনে রেসপন্সের ফরম্যাট ডকুমেন্ট করবে না।

///

## JSON রেসপন্স { #json-responses }

ডিফল্টভাবে FastAPI JSON রেসপন্স রিটার্ন করে।

আপনি যদি একটি [রেসপন্স মডেল](../tutorial/response-model.md) ঘোষণা করেন, তাহলে FastAPI এটি ব্যবহার করে Pydantic দিয়ে ডেটা JSON-এ সিরিয়ালাইজ করবে।

আপনি যদি কোনো রেসপন্স মডেল ঘোষণা না করেন, তাহলে FastAPI [JSON সামঞ্জস্যপূর্ণ এনকোডার](../tutorial/encoder.md)-এ ব্যাখ্যা করা `jsonable_encoder` ব্যবহার করবে এবং এটিকে একটি `JSONResponse`-এ রাখবে।

আপনি যদি JSON মিডিয়া টাইপসহ (`application/json`) একটি `response_class` ঘোষণা করেন, যেমনটা `JSONResponse`-এর ক্ষেত্রে, তাহলে আপনার রিটার্ন করা ডেটা *পাথ অপারেশন ডেকোরেটরে* আপনার ঘোষিত যেকোনো Pydantic `response_model` দিয়ে স্বয়ংক্রিয়ভাবে রূপান্তরিত (এবং ফিল্টার) হবে। তবে ডেটা Pydantic দিয়ে JSON বাইটে সিরিয়ালাইজ হবে না, বরং এটি `jsonable_encoder` দিয়ে রূপান্তরিত হয়ে `JSONResponse` ক্লাসে পাঠানো হবে, যা Python-এর স্ট্যান্ডার্ড JSON লাইব্রেরি ব্যবহার করে এটি বাইটে সিরিয়ালাইজ করবে।

## HTML রেসপন্স { #html-response }

**FastAPI** থেকে সরাসরি HTML-সহ একটি রেসপন্স রিটার্ন করতে `HTMLResponse` ব্যবহার করুন।

* আপনার *পাথ অপারেশন ডেকোরেটরের* `response_class` প্যারামিটার হিসেবে `HTMLResponse` দিন।

### OpenAPI-তে ডকুমেন্ট করুন এবং `Response` ওভাররাইড করুন { #document-in-openapi-and-override-response }

আপনি যদি ফাংশনের ভেতর থেকে রেসপন্স ওভাররাইড করতে চান কিন্তু একই সাথে OpenAPI-তে "মিডিয়া টাইপ" ডকুমেন্ট করতে চান, তাহলে `response_class` প্যারামিটার ব্যবহার করতে পারেন এবং একটি `Response` অবজেক্টও রিটার্ন করতে পারেন।

তখন `response_class` কেবল OpenAPI *পাথ অপারেশন* ডকুমেন্ট করতে ব্যবহার হবে, কিন্তু আপনার `Response` যেমন আছে তেমনই ব্যবহার হবে।

## উপলব্ধ রেসপন্স { #available-responses }

উপলব্ধ কিছু রেসপন্স এখানে দেওয়া হলো।

মনে রাখবেন, অন্য যেকোনো কিছু রিটার্ন করতে আপনি `Response` ব্যবহার করতে পারেন, এমনকি একটি কাস্টম সাব-ক্লাসও তৈরি করতে পারেন।

/// note | কারিগরি বিবরণ

আপনি `from starlette.responses import HTMLResponse`-ও ব্যবহার করতে পারতেন।

**FastAPI** শুধু আপনার, অর্থাৎ ডেভেলপারের সুবিধার জন্য একই `starlette.responses`-কে `fastapi.responses` হিসেবে দেয়। তবে উপলব্ধ বেশিরভাগ রেসপন্স সরাসরি Starlette থেকে আসে।

### `Response` { #response }

মূল `Response` ক্লাস, অন্য সব রেসপন্স এটি থেকে ইনহেরিট করে।

আপনি এটি সরাসরি রিটার্ন করতে পারেন।

এটি নিচের প্যারামিটারগুলো গ্রহণ করে:

* `content` - একটি `str` বা `bytes`।
* `status_code` - একটি `int` HTTP স্ট্যাটাস কোড।
* `headers` - স্ট্রিংয়ের একটি `dict`।
* `media_type` - মিডিয়া টাইপ নির্দেশকারী একটি `str`। যেমন `"text/html"`।

FastAPI (আসলে Starlette) স্বয়ংক্রিয়ভাবে একটি Content-Length হেডার অন্তর্ভুক্ত করবে। এটি `media_type`-এর ভিত্তিতে এবং টেক্সট টাইপের জন্য একটি charset যোগ করে একটি Content-Type হেডারও অন্তর্ভুক্ত করবে।

### `JSONResponse` { #jsonresponse }

কিছু ডেটা নিয়ে একটি `application/json` এনকোড করা রেসপন্স রিটার্ন করে।

ওপরে যেমন পড়েছেন, **FastAPI**-তে এটিই ডিফল্ট রেসপন্স।

/// note | কারিগরি বিবরণ

তবে আপনি যদি একটি রেসপন্স মডেল বা রিটার্ন টাইপ ঘোষণা করেন, তাহলে ডেটা JSON-এ সিরিয়ালাইজ করতে সেটিই সরাসরি ব্যবহার হবে, এবং `JSONResponse` ক্লাস ব্যবহার না করেই JSON-এর জন্য সঠিক মিডিয়া টাইপসহ একটি রেসপন্স সরাসরি রিটার্ন হবে।

সেরা পারফরম্যান্স পাওয়ার এটিই আদর্শ উপায়।

### `StreamingResponse` { #streamingresponse }

একটি async জেনারেটর বা একটি সাধারণ জেনারেটর/ইটারেটর (`yield`-সহ একটি ফাংশন) নিয়ে রেসপন্স বডি স্ট্রিম করে।

{* ../../docs_src/custom_response/tutorial007_py310.py hl[3,16] *}

/// note | কারিগরি বিবরণ

একটি `async` টাস্ক কেবল একটি `await`-এ পৌঁছালেই বাতিল করা যায়। যদি কোনো `await` না থাকে, তাহলে জেনারেটরটি (`yield`-সহ ফাংশন) সঠিকভাবে বাতিল করা যায় না এবং বাতিলের অনুরোধের পরেও চলতে থাকতে পারে।

যেহেতু এই ছোট উদাহরণে কোনো `await` স্টেটমেন্টের দরকার নেই, তাই ইভেন্ট লুপকে বাতিল সামলানোর সুযোগ দিতে আমরা একটি `await anyio.sleep(0)` যোগ করি।

বড় বা অসীম স্ট্রিমের ক্ষেত্রে এটি আরও বেশি গুরুত্বপূর্ণ হবে।

///

/// tip | পরামর্শ

সরাসরি একটি `StreamingResponse` রিটার্ন করার বদলে সম্ভবত আপনার [ডেটা স্ট্রিম](./stream-data.md)-এর স্টাইল অনুসরণ করা উচিত, এটি অনেক বেশি সুবিধাজনক এবং পর্দার আড়ালে আপনার হয়ে বাতিল সামলায়।

আপনি যদি JSON Lines স্ট্রিম করেন, তাহলে [JSON Lines স্ট্রিম করুন](../tutorial/stream-json-lines.md) টিউটোরিয়াল অনুসরণ করুন।

অন্যান্য রেসপন্স টাইপের তুলনায় ইনস্ট্যান্স তৈরিতে এটি ভিন্ন সেট আর্গুমেন্ট নেয়:

* `path` - স্ট্রিম করার ফাইলের পাথ।
* `headers` - অন্তর্ভুক্ত করার জন্য যেকোনো কাস্টম হেডার, একটি ডিকশনারি হিসেবে।
* `media_type` - মিডিয়া টাইপ নির্দেশকারী একটি স্ট্রিং। সেট করা না থাকলে ফাইলের নাম বা পাথ থেকে মিডিয়া টাইপ অনুমান করা হবে।
* `filename` - সেট করা থাকলে এটি রেসপন্সের `Content-Disposition`-এ অন্তর্ভুক্ত হবে।

ফাইল রেসপন্সে উপযুক্ত `Content-Length`, `Last-Modified` ও `ETag` হেডার থাকবে।

## কাস্টম রেসপন্স ক্লাস { #custom-response-class }

`Response` থেকে ইনহেরিট করে আপনি নিজের কাস্টম রেসপন্স ক্লাস তৈরি করে ব্যবহার করতে পারেন।

যেমন, ধরা যাক আপনি কিছু সেটিংসসহ [`orjson`](https://github.com/ijl/orjson) ব্যবহার করতে চান।

ধরা যাক আপনি চান এটি ইনডেন্ট ও ফরম্যাট করা JSON রিটার্ন করুক, তাই আপনি orjson অপশন `orjson.OPT_INDENT_2` ব্যবহার করতে চান।

আপনি একটি `CustomORJSONResponse` তৈরি করতে পারেন। আপনাকে মূলত যা করতে হবে তা হলো একটি `Response.render(content)` মেথড তৈরি করা যা কনটেন্টকে `bytes` হিসেবে রিটার্ন করে:

### `orjson` নাকি রেসপন্স মডেল { #orjson-or-response-model }

আপনি যদি পারফরম্যান্স খোঁজেন, তাহলে সম্ভবত একটি `orjson` রেসপন্সের চেয়ে একটি [রেসপন্স মডেল](../tutorial/response-model.md) ব্যবহার করাই আপনার জন্য ভালো।

রেসপন্স মডেলের ক্ষেত্রে FastAPI মাঝের কোনো ধাপ ছাড়াই, যেমন `jsonable_encoder` দিয়ে রূপান্তর, যা অন্য যেকোনো ক্ষেত্রে ঘটত, Pydantic ব্যবহার করে ডেটা JSON-এ সিরিয়ালাইজ করবে।

আর ভেতরে ভেতরে JSON-এ সিরিয়ালাইজ করতে Pydantic `orjson`-এর মতোই একই অন্তর্নিহিত Rust ব্যবস্থা ব্যবহার করে, তাই রেসপন্স মডেল দিয়েই আপনি ইতিমধ্যে সেরা পারফরম্যান্স পাবেন।

## ডিফল্ট রেসপন্স ক্লাস { #default-response-class }

একটি **FastAPI** ক্লাস ইনস্ট্যান্স বা একটি `APIRouter` তৈরির সময় আপনি নির্দিষ্ট করতে পারেন ডিফল্টভাবে কোন রেসপন্স ক্লাস ব্যবহার হবে।

যে প্যারামিটারটি এটি সংজ্ঞায়িত করে তা হলো `default_response_class`।

নিচের উদাহরণে **FastAPI** সব *পাথ অপারেশনে* ডিফল্টভাবে JSON-এর বদলে `HTMLResponse` ব্যবহার করবে।
