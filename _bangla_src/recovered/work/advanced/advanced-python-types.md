# অ্যাডভান্সড Python টাইপ { #advanced-python-types }

Python টাইপ নিয়ে কাজ করার সময় কাজে আসতে পারে এমন কিছু অতিরিক্ত ধারণা এখানে দেওয়া হলো।

## `Union` বা `Optional` ব্যবহার { #using-union-or-optional }

আপনার কোড যদি কোনো কারণে `|` ব্যবহার করতে না পারে, যেমন যদি এটি একটি টাইপ অ্যানোটেশনে না থেকে `response_model=`-এর মতো কিছুতে থাকে, তাহলে খাড়া দাগ (`|`) ব্যবহারের বদলে আপনি `typing` থেকে `Union` ব্যবহার করতে পারেন।

যেমন, আপনি ঘোষণা করতে পারেন যে কোনো কিছু একটি `str` বা `None` হতে পারে:

`typing`-এ কোনো কিছু `None` হতে পারে তা ঘোষণা করার একটি শর্টকাটও আছে, `Optional` দিয়ে।

আমার খুবই **ব্যক্তিগত** দৃষ্টিকোণ থেকে একটি পরামর্শ:

* 🚨 `Optional[SomeType]` ব্যবহার এড়িয়ে চলুন
* এর বদলে ✨ **`Union[SomeType, None]` ব্যবহার করুন** ✨।

দুটোই সমতুল্য এবং ভেতরে ভেতরে একই, তবে আমি `Optional`-এর বদলে `Union`-এর পরামর্শ দেব, কারণ "**optional**" (ঐচ্ছিক) শব্দটি মনে করিয়ে দিতে পারে যে ভ্যালুটি ঐচ্ছিক, অথচ এর আসল মানে হলো "এটি `None` হতে পারে", এমনকি যদি এটি ঐচ্ছিক না হয়ে তখনও আবশ্যক থাকে।

আমার মনে হয় `Union[SomeType, None]` এর অর্থ আরও স্পষ্টভাবে প্রকাশ করে।

এটি শুধু শব্দ আর নামের ব্যাপার। কিন্তু ওই শব্দগুলো আপনি ও আপনার টিমমেটরা কোড নিয়ে কীভাবে ভাবেন তাকে প্রভাবিত করতে পারে।

উদাহরণ হিসেবে এই ফাংশনটি নেওয়া যাক:

⟦CODE2⟧

`name` প্যারামিটারটি `Optional[str]` হিসেবে সংজ্ঞায়িত, কিন্তু এটি **ঐচ্ছিক নয়**, আপনি প্যারামিটারটি ছাড়া ফাংশনটি কল করতে পারবেন না:

```Python
say_hi()  # ওহ না, এটি একটি এরর দেয়! 😱
```

`name` প্যারামিটারটি **তখনও আবশ্যক** (*ঐচ্ছিক* নয়), কারণ এর কোনো ডিফল্ট ভ্যালু নেই। তবুও `name` ভ্যালু হিসেবে `None` গ্রহণ করে:

```Python
say_hi(name=None)  # এটি কাজ করে, None বৈধ 🎉
```
