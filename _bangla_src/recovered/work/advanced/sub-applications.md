# সাব-অ্যাপ্লিকেশন - মাউন্ট { #sub-applications-mounts }

আপনার যদি নিজস্ব স্বাধীন OpenAPI ও নিজস্ব ডকুমেন্টেশন UI-সহ দুটি স্বাধীন FastAPI অ্যাপ্লিকেশন দরকার হয়, তাহলে আপনি একটি মূল অ্যাপ রেখে এক (বা একাধিক) সাব-অ্যাপ্লিকেশন "মাউন্ট" করতে পারেন।

## একটি **FastAPI** অ্যাপ্লিকেশন মাউন্ট করা { #mounting-a-fastapi-application }

"মাউন্টিং" মানে একটি নির্দিষ্ট পাথে একটি সম্পূর্ণ "স্বাধীন" অ্যাপ্লিকেশন যোগ করা, যা তারপর ওই সাব-অ্যাপ্লিকেশনে ঘোষিত _পাথ অপারেশন_ দিয়ে ওই পাথের অধীনে সবকিছু সামলানোর দায়িত্ব নেয়।

আপনি যদি দুটি ইউজার ইন্টারফেসের যেকোনোটির সাথে কাজ করার চেষ্টা করেন, সেগুলো সঠিকভাবে কাজ করবে, কারণ ব্রাউজার প্রতিটি নির্দিষ্ট অ্যাপ বা সাব-অ্যাপের সাথে কথা বলতে পারবে।

### কারিগরি বিবরণ: `root_path` { #technical-details-root-path }

আপনি যখন ওপরে বর্ণিত উপায়ে একটি সাব-অ্যাপ্লিকেশন মাউন্ট করেন, তখন FastAPI ASGI স্পেসিফিকেশনের `root_path` নামের একটি ব্যবস্থা ব্যবহার করে সাব-অ্যাপ্লিকেশনকে মাউন্ট পাথ জানানোর দায়িত্ব নেবে।

এভাবে সাব-অ্যাপ্লিকেশন জানবে যে ডকুমেন্টেশন UI-এর জন্য ওই পাথ prefix ব্যবহার করতে হবে।

আর সাব-অ্যাপ্লিকেশনেরও নিজস্ব মাউন্ট করা সাব-অ্যাপ্লিকেশন থাকতে পারে এবং সবকিছু সঠিকভাবে কাজ করবে, কারণ FastAPI এই সব `root_path` স্বয়ংক্রিয়ভাবে সামলায়।

`root_path` এবং এটি কীভাবে স্পষ্টভাবে ব্যবহার করতে হয় সে সম্পর্কে আরও জানবেন [প্রক্সির পেছনে](behind-a-proxy.md) সম্পর্কিত অংশে।
