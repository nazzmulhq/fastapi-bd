# সরাসরি একটি Response রিটার্ন করুন { #return-a-response-directly }

আপনি যখন একটি **FastAPI** *পাথ অপারেশন* তৈরি করেন, তখন সাধারণত এটি থেকে যেকোনো ডেটা রিটার্ন করতে পারেন: একটি `dict`, একটি `list`, একটি Pydantic মডেল, একটি ডেটাবেস মডেল ইত্যাদি।

আপনি যদি একটি [রেসপন্স মডেল](../tutorial/response-model.md) ঘোষণা করেন, তাহলে FastAPI এটি ব্যবহার করে Pydantic দিয়ে ডেটা JSON-এ সিরিয়ালাইজ করবে।

আপনি যদি কোনো রেসপন্স মডেল ঘোষণা না করেন, তাহলে FastAPI [JSON সামঞ্জস্যপূর্ণ এনকোডার](../tutorial/encoder.md)-এ ব্যাখ্যা করা `jsonable_encoder` ব্যবহার করবে এবং এটিকে একটি `JSONResponse`-এ রাখবে।

আপনি সরাসরি একটি `JSONResponse` তৈরি করে সেটিও রিটার্ন করতে পারেন।

/// tip | পরামর্শ

সরাসরি একটি `JSONResponse` রিটার্ন করার চেয়ে একটি [রেসপন্স মডেল](../tutorial/response-model.md) ব্যবহার করলে সাধারণত আপনি অনেক ভালো পারফরম্যান্স পাবেন, কারণ এভাবে এটি Pydantic ব্যবহার করে, Rust-এ, ডেটা সিরিয়ালাইজ করে।

///

## একটি `Response` রিটার্ন করুন { #return-a-response }

আপনি একটি `Response` বা এর যেকোনো সাব-ক্লাস রিটার্ন করতে পারেন।

/// note | নোট

`JSONResponse` নিজেই `Response`-এর একটি সাব-ক্লাস।

///

আর আপনি যখন একটি `Response` রিটার্ন করেন, **FastAPI** সেটি সরাসরি পাস করে দেবে।

এটি Pydantic মডেল দিয়ে কোনো ডেটা রূপান্তর করবে না, বিষয়বস্তুকে কোনো টাইপে রূপান্তর করবে না, ইত্যাদি।

এটি আপনাকে অনেক **নমনীয়তা** দেয়। আপনি যেকোনো ডেটা টাইপ রিটার্ন করতে পারেন, যেকোনো ডেটা ঘোষণা বা ভ্যালিডেশন ওভাররাইড করতে পারেন, ইত্যাদি।

এটি আপনাকে অনেক **দায়িত্বও** দেয়। আপনাকে নিশ্চিত করতে হবে যে আপনার রিটার্ন করা ডেটা সঠিক, সঠিক ফরম্যাটে আছে, সিরিয়ালাইজ করা যায়, ইত্যাদি।

## একটি `Response`-এ `jsonable_encoder` ব্যবহার { #using-the-jsonable-encoder-in-a-response }

যেহেতু আপনার রিটার্ন করা `Response`-এ **FastAPI** কোনো পরিবর্তন করে না, তাই আপনাকে নিশ্চিত করতে হবে যে এর বিষয়বস্তু এর জন্য প্রস্তুত।

যেমন, একটি Pydantic মডেলকে প্রথমে সব ডেটা টাইপ (যেমন `datetime`, `UUID` ইত্যাদি) JSON-সামঞ্জস্যপূর্ণ টাইপে রূপান্তর করে একটি `dict`-এ রূপান্তর না করে আপনি সেটি একটি `JSONResponse`-এ রাখতে পারবেন না।

এসব ক্ষেত্রে, একটি রেসপন্সে পাঠানোর আগে আপনার ডেটা রূপান্তর করতে আপনি `jsonable_encoder` ব্যবহার করতে পারেন:

## একটি কাস্টম `Response` রিটার্ন করা { #returning-a-custom-response }

ওপরের উদাহরণে আপনার প্রয়োজনীয় সব অংশ দেখানো হয়েছে, তবে এটি এখনো খুব একটা কাজের নয়, কারণ আপনি শুধু সরাসরি `item` রিটার্ন করতে পারতেন, আর **FastAPI** আপনার হয়ে সেটিকে একটি `dict`-এ রূপান্তর করে একটি `JSONResponse`-এ রাখত, ইত্যাদি। এর সবই ডিফল্টভাবে।

এবার দেখা যাক কীভাবে এটি ব্যবহার করে একটি কাস্টম রেসপন্স রিটার্ন করা যায়।

ধরা যাক আপনি একটি [XML](https://en.wikipedia.org/wiki/XML) রেসপন্স রিটার্ন করতে চান।

## একটি রেসপন্স মডেল কীভাবে কাজ করে { #how-a-response-model-works }

আপনি যখন একটি পাথ অপারেশনে একটি [রেসপন্স মডেল - রিটার্ন টাইপ](../tutorial/response-model.md) ঘোষণা করেন, তখন **FastAPI** এটি ব্যবহার করে Pydantic দিয়ে ডেটা JSON-এ সিরিয়ালাইজ করবে।

{* ../../docs_src/response_model/tutorial001_01_py310.py hl[16,21] *}

যেহেতু এটি Rust-এর দিকে ঘটবে, তাই সাধারণ Python ও `JSONResponse` ক্লাস দিয়ে করার চেয়ে পারফরম্যান্স অনেক ভালো হবে।

একটি `response_model` বা রিটার্ন টাইপ ব্যবহার করলে FastAPI ডেটা রূপান্তর করতে `jsonable_encoder` (যা ধীরতর হতো) বা `JSONResponse` ক্লাস কোনোটিই ব্যবহার করবে না।

তার বদলে এটি রেসপন্স মডেল (বা রিটার্ন টাইপ) ব্যবহার করে Pydantic দিয়ে তৈরি হওয়া JSON বাইটগুলো নেয় এবং সরাসরি JSON-এর জন্য সঠিক মিডিয়া টাইপসহ (`application/json`) একটি `Response` রিটার্ন করে।

## নোট { #notes }

আপনি যখন সরাসরি একটি `Response` রিটার্ন করেন, তখন এর ডেটা স্বয়ংক্রিয়ভাবে ভ্যালিডেট, রূপান্তর (সিরিয়ালাইজ) বা ডকুমেন্ট হয় না।

তবে আপনি তবুও [OpenAPI-তে অতিরিক্ত রেসপন্স](additional-responses.md)-এ বর্ণিত উপায়ে এটি ডকুমেন্ট করতে পারেন।

পরের অংশগুলোতে দেখবেন স্বয়ংক্রিয় ডেটা রূপান্তর, ডকুমেন্টেশন ইত্যাদি বজায় রেখেই কীভাবে এই কাস্টম `Response`-গুলো ব্যবহার/ঘোষণা করতে হয়।
