# বডি - আপডেট { #body-updates }

## `PUT` দিয়ে প্রতিস্থাপন করে আপডেট { #update-replacing-with-put }

একটি আইটেম আপডেট করতে আপনি [HTTP `PUT`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/PUT) অপারেশন ব্যবহার করতে পারেন।

ইনপুট ডেটাকে JSON হিসেবে সংরক্ষণযোগ্য ডেটায় (যেমন একটি NoSQL ডেটাবেসে) রূপান্তর করতে আপনি `jsonable_encoder` ব্যবহার করতে পারেন। যেমন, `datetime`-কে `str`-এ রূপান্তর করা।

## `PATCH` দিয়ে আংশিক আপডেট { #partial-updates-with-patch }

ডেটা *আংশিকভাবে* আপডেট করতে আপনি [HTTP `PATCH`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/PATCH) অপারেশনও ব্যবহার করতে পারেন।

এর মানে আপনি কেবল যে ডেটা আপডেট করতে চান সেটুকুই পাঠাতে পারেন, বাকিগুলো অক্ষত রেখে।

/// note | নোট

`PATCH` `PUT`-এর চেয়ে কম ব্যবহৃত ও কম পরিচিত।

আর অনেক টিম আংশিক আপডেটের জন্যও কেবল `PUT` ব্যবহার করে।

এগুলো আপনি যেভাবে খুশি ব্যবহার করতে **স্বাধীন**, **FastAPI** কোনো বিধিনিষেধ চাপিয়ে দেয় না।

তবে এই গাইড আপনাকে মোটামুটি দেখায় যে এগুলো কীভাবে ব্যবহার করার কথা।

### Pydantic-এর `exclude_unset` প্যারামিটার ব্যবহার { #using-pydantics-exclude-unset-parameter }

আপনি যদি আংশিক আপডেট গ্রহণ করতে চান, তাহলে Pydantic মডেলের `.model_dump()`-এ `exclude_unset` প্যারামিটার ব্যবহার করা খুবই কাজের।

যেমন `item.model_dump(exclude_unset=True)`।

এটি এমন একটি `dict` তৈরি করবে যাতে কেবল `item` মডেল তৈরির সময় সেট করা ডেটা থাকবে, ডিফল্ট ভ্যালুগুলো বাদ দিয়ে।

### আংশিক আপডেট সংক্ষেপে { #partial-updates-recap }

সংক্ষেপে, আংশিক আপডেট প্রয়োগ করতে আপনি:

* (ঐচ্ছিকভাবে) `PUT`-এর বদলে `PATCH` ব্যবহার করবেন।
* সংরক্ষিত ডেটা বের করে আনবেন।
* সেই ডেটা একটি Pydantic মডেলে রাখবেন।
* ইনপুট মডেল থেকে ডিফল্ট ভ্যালু ছাড়া একটি `dict` তৈরি করবেন (`exclude_unset` ব্যবহার করে)।
    * এভাবে আপনি কেবল ইউজারের আসলে সেট করা ভ্যালুগুলোই আপডেট করতে পারবেন, আপনার মডেলের ডিফল্ট ভ্যালু দিয়ে আগে থেকে সংরক্ষিত ভ্যালুগুলো ওভাররাইড না করে।
* সংরক্ষিত মডেলের একটি কপি তৈরি করবেন, প্রাপ্ত আংশিক আপডেট দিয়ে এর অ্যাট্রিবিউটগুলো আপডেট করে (`update` প্যারামিটার ব্যবহার করে)।
* কপি করা মডেলটিকে আপনার DB-তে সংরক্ষণযোগ্য কিছুতে রূপান্তর করবেন (যেমন `jsonable_encoder` ব্যবহার করে)।
    * এটি আবার মডেলের `.model_dump()` মেথড ব্যবহারের মতোই, তবে এটি নিশ্চিত করে (এবং রূপান্তর করে) যে ভ্যালুগুলো JSON-এ রূপান্তরযোগ্য ডেটা টাইপে আছে, যেমন `datetime`-কে `str`-এ।
* ডেটা আপনার DB-তে সংরক্ষণ করবেন।
* আপডেট করা মডেলটি রিটার্ন করবেন।

/// tip | পরামর্শ

আপনি আসলে একটি HTTP `PUT` অপারেশনের সাথেও এই একই কৌশল ব্যবহার করতে পারেন।

তবে এখানের উদাহরণে `PATCH` ব্যবহার করা হয়েছে কারণ এটি এ ধরনের ক্ষেত্রের জন্যই তৈরি।

/// note | নোট

লক্ষ করুন, ইনপুট মডেলটি তবুও ভ্যালিডেট করা হয়।

তাই আপনি যদি এমন আংশিক আপডেট গ্রহণ করতে চান যাতে সব অ্যাট্রিবিউট বাদ দেওয়া যায়, তাহলে আপনার এমন একটি মডেল দরকার যার সব অ্যাট্রিবিউট ঐচ্ছিক হিসেবে চিহ্নিত (ডিফল্ট ভ্যালু বা `None`-সহ)।

**আপডেটের** জন্য সব ঐচ্ছিক ভ্যালুসহ মডেল এবং **তৈরির** জন্য আবশ্যক ভ্যালুসহ মডেলের মধ্যে পার্থক্য করতে আপনি [অতিরিক্ত মডেল](extra-models.md)-এ বর্ণিত ধারণাগুলো ব্যবহার করতে পারেন।
