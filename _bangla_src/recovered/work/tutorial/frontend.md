# ফ্রন্টএন্ড { #frontend }

`app.frontend()` (বা `router.frontend()`) দিয়ে আপনি স্ট্যাটিক ফ্রন্টএন্ড অ্যাপ সার্ভ করতে পারেন।

এটি স্ট্যাটিক ফাইল তৈরি করে এমন ফ্রন্টএন্ড টুলের জন্য কাজের, যেমন Vite-সহ React, TanStack Router, Astro, Vue, Svelte, Angular, Solid ও অন্যান্য।

এই টুলগুলোতে সাধারণত একটি ধাপ থাকে যা ফ্রন্টএন্ড বিল্ড করে, এরকম একটি কমান্ড দিয়ে:

⟦CODE1⟧

এটি আপনার ফ্রন্টএন্ড ফাইলসহ `./dist/`-এর মতো একটি ডিরেক্টরি তৈরি করবে।

এই ফ্রন্টএন্ড ফ্রেমওয়ার্কগুলোর প্রয়োজনীয় রীতি মেনে ওই ডিরেক্টরি সার্ভ করতে আপনি `app.frontend()` ব্যবহার করতে পারেন।

**FastAPI** প্রথমে *পাথ অপারেশনগুলো* যাচাই করে। কোনো সাধারণ রাউট না মিললেই কেবল ফ্রন্টএন্ড ফাইলগুলো যাচাই করা হয়, তাই আপনার API-তে কোনো প্রভাব পড়বে না।

## ক্লায়েন্ট-সাইড রাউটিং { #client-side-routing }

**সিঙ্গেল-পেজ অ্যাপ** (SPA)-সহ অনেক ফ্রন্টএন্ড অ্যাপ ক্লায়েন্ট-সাইড রাউটিং ব্যবহার করে। `/dashboard/settings`-এর মতো একটি পাথ হয়তো আসল কোনো ফাইল নয়, কিন্তু ফ্রেমওয়ার্কটি এটি সামলানোর দায়িত্ব নেবে।

তাই ওই URL সরাসরি অ্যাক্সেস করলে (অ্যাপের ভেতর দিয়ে নেভিগেট না করে), ব্যাকএন্ডের উচিত `index.html` থেকে ফ্রন্টএন্ড অ্যাপটি সার্ভ করা, যাতে ফ্রন্টএন্ড ফ্রেমওয়ার্ক তারপর ক্লায়েন্ট-সাইড রাউটিং সামলাতে পারে।

এর জন্য `fallback="index.html"` ব্যবহার করুন:

{* ../../docs_src/frontend/tutorial002_py310.py hl[5] *}

**FastAPI** এই fallback কেবল সেই `GET` ও `HEAD` রিকোয়েস্টের জন্য ব্যবহার করে যেগুলো `Accept: text/html` বা `Accept: application/xhtml+xml` দিয়ে স্পষ্টভাবে HTML গ্রহণ করে, যেমনটা ব্রাউজারের নেভিগেশন রিকোয়েস্ট সাধারণত করে। JavaScript, CSS ও ছবির মতো অনুপস্থিত ফাইল তখনও `404` রিটার্ন করে।

`POST` বা `PUT`-এর মতো অন্যান্য মেথডসহ এমন পাথে রিকোয়েস্ট, যা কেবল ফ্রন্টএন্ড fallback-এর সাথে মেলে, সেগুলোও `404` রিটার্ন করে। সাধারণ **FastAPI** *পাথ অপারেশনগুলো* তখনও ফ্রন্টএন্ড রাউটের চেয়ে বেশি অগ্রাধিকার পায়।

/// tip | পরামর্শ

ডিফল্টভাবে `fallback`-এর ভ্যালু হলো `fallback="auto"`। বেশিরভাগ ক্ষেত্রে আপনাকে `fallback` উল্লেখ করতে হবে না। বিস্তারিত জানতে নিচে পড়ুন।

///

ক্লায়েন্ট-সাইড রাউটিং ব্যবহার করে এমন অনেক ফ্রন্টএন্ড অ্যাপের ক্ষেত্রে আপনি এটিই চাইবেন, যেমন TanStack Router-সহ React, Vue, Angular, SvelteKit বা Solid।

/// tip | পরামর্শ

ডিফল্টভাবে `fallback`-এর ভ্যালু হলো `fallback="auto"`। এতে, যদি একটি `404.html` ফাইল পাওয়া যায়, তাহলে সেটি স্বয়ংক্রিয়ভাবে fallback হিসেবে ব্যবহার হবে।

তাই সাধারণত আপনি `fallback` আর্গুমেন্ট বাদ দিতে পারেন।

এটি Astro-র মতো ফ্রন্টএন্ড টুলের ক্ষেত্রে কাজের, যেগুলো প্রতিটি পেজের জন্য স্ট্যাটিক HTML ফাইল তৈরি করে।

## Fallback Auto { #fallback-auto }

ডিফল্টভাবে `app.frontend()` `fallback="auto"` ব্যবহার করে।

ফ্রন্টএন্ড ডিরেক্টরিতে যদি একটি `404.html` ফাইল থাকে, তাহলে অনুপস্থিত ফ্রন্টএন্ড পাথগুলো `404` স্ট্যাটাস কোডসহ ওই ফাইলটি সার্ভ করে।

অন্যথায়, যদি একটি `index.html` ফাইল থাকে, তাহলে অনুপস্থিত ব্রাউজার নেভিগেশন পাথগুলো `index.html` সার্ভ করে, যা ক্লায়েন্ট-সাইড রাউটিংসহ অনেক ফ্রন্টএন্ড অ্যাপ আশা করে।

তাই বেশিরভাগ ক্ষেত্রে আপনি `fallback` আর্গুমেন্ট উল্লেখ না করেই `app.frontend("/", directory="dist")` ব্যবহার করতে পারেন।

## ডিরেক্টরি যাচাই { #check-directory }

ডিফল্টভাবে `app.frontend()` `check_dir="auto"` ব্যবহার করে।

যখন `FASTAPI_ENV` এনভায়রনমেন্ট ভেরিয়েবল `development`-এ সেট করা থাকে, তখন ফ্রন্টএন্ড বিল্ড আউটপুট ডিরেক্টরি অনুপস্থিত থাকলে **FastAPI** কেবল একটি সতর্কবার্তা দেখায়। [`fastapi dev` কমান্ড](https://github.com/fastapi/fastapi-cli#fastapi-dev) এই এনভায়রনমেন্ট ভেরিয়েবলটি আগে থেকে সেট করা না থাকলে আপনার হয়ে সেট করে দেয়। এতে ডেভেলপমেন্টের সময় ফ্রন্টএন্ড বিল্ড বা চালু করার আগেই আপনি ব্যাকএন্ড চালু করতে পারেন।

অন্য যেকোনো এনভায়রনমেন্টে, অ্যাপ তৈরি হওয়ার সময় **FastAPI** একটি এরর রেইজ করে। এতে ফ্রন্টএন্ড ফাইল ছাড়া একটি অ্যাপ ডিপ্লয় করার আগেই কনফিগারেশনের ভুল ধরা পড়ে।

অ্যাপ তৈরি হওয়ার সময় সবসময় ডিরেক্টরি যাচাই করতে আপনি `check_dir=True`-ও সেট করতে পারেন।

আপনার ফ্রন্টএন্ড ফাইলগুলো যদি পরে তৈরি হয়, যেমন অ্যাপ অবজেক্ট তৈরির পরে একটি আলাদা বিল্ড ধাপে, তাহলে `check_dir=False` সেট করুন:

{* ../../docs_src/frontend/tutorial006_py310.py hl[5] *}

`check_dir=False` দিলে অ্যাপ তৈরি হওয়ার সময় **FastAPI** ডিরেক্টরি যাচাই করবে না। কোনো রিকোয়েস্ট সামলানোর সময়ও যদি কনফিগার করা ডিরেক্টরি অনুপস্থিত থাকে, তাহলে **FastAPI** তখন একটি এরর রেইজ করবে।

## ডিপেন্ডেন্সি ও মিডলওয়্যার { #dependencies-and-middleware }

ফ্রন্টএন্ড রেসপন্সগুলো সাধারণ **FastAPI** অ্যাপ্লিকেশনের ভেতরেই চলে, তাই HTTP মিডলওয়্যার এগুলোর ক্ষেত্রেও প্রযোজ্য।

অ্যাপ থেকে, একটি `APIRouter` থেকে এবং `include_router()` থেকে আসা ডিপেন্ডেন্সিগুলোও ফ্রন্টএন্ড রেসপন্সে প্রযোজ্য। কুকি অথেনটিকেশন বা এরকম কিছু দিয়ে একটি ফ্রন্টএন্ড সুরক্ষিত করতে এটি কাজে আসতে পারে।

সাধারণ *পাথ অপারেশনের* মতোই ডিপেন্ডেন্সিগুলো রেসপন্স হেডার পরিবর্তন করতে এবং ব্যাকগ্রাউন্ড টাস্ক যোগ করতে পারে।

## কেবল স্ট্যাটিক বিল্ড আউটপুট { #static-build-output-only }

`app.frontend()` আপনার ফ্রন্টএন্ড বিল্ডের আগে থেকে তৈরি করা ফাইলগুলো সার্ভ করে।

এটি সার্ভার-সাইড রেন্ডারিং চালায় না। এটি স্ট্যাটিক ফাইল তৈরি করে এমন ফ্রন্টএন্ড ফ্রেমওয়ার্কের জন্য, প্রতিটি রিকোয়েস্টের জন্য সার্ভারে ডায়নামিক রেন্ডারিং দরকার এমন ফ্রেমওয়ার্কের জন্য নয়।
