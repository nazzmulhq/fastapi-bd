# এরর হ্যান্ডলিং { #handling-errors }

এমন অনেক পরিস্থিতি আছে যেখানে আপনার API ব্যবহারকারী কোনো ক্লায়েন্টকে একটি এরর জানাতে হয়।

এই ক্লায়েন্ট হতে পারে ফ্রন্টএন্ডসহ একটি ব্রাউজার, অন্য কারো কোড, একটি IoT ডিভাইস ইত্যাদি।

আপনাকে হয়তো ক্লায়েন্টকে জানাতে হবে যে:

* ওই অপারেশনের জন্য ক্লায়েন্টের যথেষ্ট অনুমতি নেই।
* ওই রিসোর্সে ক্লায়েন্টের অ্যাক্সেস নেই।
* ক্লায়েন্ট যে আইটেমটি অ্যাক্সেস করার চেষ্টা করছিল তা নেই।
* ইত্যাদি।

এসব ক্ষেত্রে আপনি সাধারণত **400**-এর ঘরের (৪০০ থেকে ৪৯৯) একটি **HTTP স্ট্যাটাস কোড** রিটার্ন করবেন।

এটি 200 HTTP স্ট্যাটাস কোডের (২০০ থেকে ২৯৯) মতো। ওই "200" স্ট্যাটাস কোডগুলোর মানে রিকোয়েস্টে কোনো না কোনোভাবে "সফলতা" ছিল।

400-এর ঘরের স্ট্যাটাস কোডগুলোর মানে ক্লায়েন্টের দিক থেকে একটি এরর হয়েছে।

মনে আছে সেই সব **"404 Not Found"** এরর (এবং কৌতুক)?

### আপনার কোডে একটি `HTTPException` রেইজ করুন { #raise-an-httpexception-in-your-code }

`HTTPException` হলো API-এর জন্য প্রাসঙ্গিক অতিরিক্ত ডেটাসহ একটি সাধারণ Python এক্সেপশন।

যেহেতু এটি একটি Python এক্সেপশন, তাই আপনি এটি `return` করেন না, `raise` করেন।

এর মানে এটাও যে আপনি যদি এমন একটি ইউটিলিটি ফাংশনের ভেতরে থাকেন যা আপনার *পাথ অপারেশন ফাংশনের* ভেতর থেকে কল করছেন, এবং ওই ইউটিলিটি ফাংশনের ভেতর থেকে `HTTPException` রেইজ করেন, তাহলে এটি *পাথ অপারেশন ফাংশনের* বাকি কোড চালাবে না, সাথে সাথে ওই রিকোয়েস্টটি শেষ করে `HTTPException` থেকে HTTP এররটি ক্লায়েন্টকে পাঠিয়ে দেবে।

একটি ভ্যালু রিটার্ন করার চেয়ে একটি এক্সেপশন রেইজ করার সুবিধা ডিপেন্ডেন্সি ও সিকিউরিটি সম্পর্কিত অংশে আরও স্পষ্ট হবে।

এই উদাহরণে, ক্লায়েন্ট যখন এমন একটি ID দিয়ে আইটেম রিকোয়েস্ট করে যা নেই, তখন `404` স্ট্যাটাস কোডসহ একটি এক্সেপশন রেইজ করুন:

#### FastAPI-এর `HTTPException` বনাম Starlette-এর `HTTPException` { #fastapis-httpexception-vs-starlettes-httpexception }

**FastAPI**-এর নিজস্ব `HTTPException` আছে।

আর **FastAPI**-এর `HTTPException` এরর ক্লাস Starlette-এর `HTTPException` এরর ক্লাস থেকে ইনহেরিট করে।

একমাত্র পার্থক্য হলো **FastAPI**-এর `HTTPException` `detail` ফিল্ডের জন্য JSON-যোগ্য যেকোনো ডেটা গ্রহণ করে, আর Starlette-এর `HTTPException` এর জন্য কেবল স্ট্রিং গ্রহণ করে।

তাই আপনার কোডে আপনি স্বাভাবিকভাবেই **FastAPI**-এর `HTTPException` রেইজ করে যেতে পারেন।

কিন্তু যখন আপনি একটি এক্সেপশন হ্যান্ডলার রেজিস্টার করেন, তখন সেটি Starlette-এর `HTTPException`-এর জন্য রেজিস্টার করা উচিত।

এভাবে Starlette-এর অভ্যন্তরীণ কোডের কোনো অংশ, বা কোনো Starlette এক্সটেনশন বা প্লাগ-ইন যদি একটি Starlette `HTTPException` রেইজ করে, তাহলে আপনার হ্যান্ডলার সেটি ধরে সামলাতে পারবে।

এই উদাহরণে, একই কোডে দুটি `HTTPException`-ই রাখতে পারার জন্য Starlette-এর এক্সেপশনটির নাম বদলে `StarletteHTTPException` রাখা হয়েছে:
