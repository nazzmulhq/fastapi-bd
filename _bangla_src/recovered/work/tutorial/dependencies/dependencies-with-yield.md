# yield-সহ ডিপেন্ডেন্সি { #dependencies-with-yield }

FastAPI এমন ডিপেন্ডেন্সি সাপোর্ট করে যেগুলো <dfn title='কখনো কখনো "exit code", "cleanup code", "teardown code", "closing code", "context manager exit code" ইত্যাদি নামেও ডাকা হয়।'>শেষ হওয়ার পরে কিছু অতিরিক্ত ধাপ</dfn> সম্পন্ন করে।

এটি করতে `return`-এর বদলে `yield` ব্যবহার করুন, আর অতিরিক্ত ধাপগুলো (কোড) এর পরে লিখুন।

/// tip | পরামর্শ

প্রতিটি ডিপেন্ডেন্সিতে `yield` কেবল একবারই ব্যবহার করবেন।

///

/// note | কারিগরি বিবরণ

যেকোনো ফাংশন যা এগুলোর সাথে ব্যবহার করা বৈধ:

* [`@contextlib.contextmanager`](https://docs.python.org/3/library/contextlib.html#contextlib.contextmanager) বা
* [`@contextlib.asynccontextmanager`](https://docs.python.org/3/library/contextlib.html#contextlib.asynccontextmanager)

তা একটি **FastAPI** ডিপেন্ডেন্সি হিসেবে ব্যবহার করাও বৈধ।

আসলে FastAPI ভেতরে ভেতরে ওই দুটি ডেকোরেটরই ব্যবহার করে।

## `yield` ও `try`-সহ একটি ডিপেন্ডেন্সি { #a-dependency-with-yield-and-try }

আপনি যদি `yield`-সহ একটি ডিপেন্ডেন্সিতে একটি `try` ব্লক ব্যবহার করেন, তাহলে ডিপেন্ডেন্সিটি ব্যবহারের সময় যে এক্সেপশনই ছোড়া হোক তা আপনি পাবেন।

যেমন, মাঝের কোনো এক সময়ে কোনো কোড, অন্য কোনো ডিপেন্ডেন্সিতে বা একটি *পাথ অপারেশনে*, যদি একটি ডেটাবেস ট্রানজ্যাকশন "রোলব্যাক" করে বা অন্য কোনো এক্সেপশন তৈরি করে, তাহলে আপনি আপনার ডিপেন্ডেন্সিতে এক্সেপশনটি পাবেন।

তাই `except SomeException` দিয়ে আপনি ডিপেন্ডেন্সির ভেতরে ওই নির্দিষ্ট এক্সেপশনটি খুঁজতে পারেন।

একইভাবে, এক্সেপশন হোক বা না হোক, এক্সিট ধাপগুলো যাতে এক্সিকিউট হয় তা নিশ্চিত করতে আপনি `finally` ব্যবহার করতে পারেন।

## `yield`-সহ সাব-ডিপেন্ডেন্সি { #sub-dependencies-with-yield }

আপনার যেকোনো আকার ও আকৃতির সাব-ডিপেন্ডেন্সি ও সাব-ডিপেন্ডেন্সির "ট্রি" থাকতে পারে, এবং এগুলোর যেকোনোটি বা সবগুলোই `yield` ব্যবহার করতে পারে।

**FastAPI** নিশ্চিত করবে যে `yield`-সহ প্রতিটি ডিপেন্ডেন্সির "exit code" সঠিক ক্রমে চলে।

যেমন, `dependency_c`-এর `dependency_b`-এর ওপর ডিপেন্ডেন্সি থাকতে পারে, আর `dependency_b`-এর `dependency_a`-এর ওপর:

{* ../../docs_src/dependencies/tutorial008_an_py310.py hl[6,14,22] *}

আর এগুলোর সবই `yield` ব্যবহার করতে পারে।

এক্ষেত্রে `dependency_c`-এর exit code এক্সিকিউট করার জন্য `dependency_b`-এর ভ্যালু (এখানে নাম `dep_b`) তখনও উপলব্ধ থাকা দরকার।

আর এর পালায়, `dependency_b`-এর exit code-এর জন্য `dependency_a`-এর ভ্যালু (এখানে নাম `dep_a`) উপলব্ধ থাকা দরকার।

{* ../../docs_src/dependencies/tutorial008_an_py310.py hl[18:19,26:27] *}

একইভাবে, আপনার কিছু ডিপেন্ডেন্সি `yield`-সহ এবং কিছু অন্য ডিপেন্ডেন্সি `return`-সহ থাকতে পারে, এবং সেগুলোর কয়েকটি অন্য কয়েকটির ওপর নির্ভর করতে পারে।

আর আপনার একটিমাত্র ডিপেন্ডেন্সি থাকতে পারে যার `yield`-সহ আরও কয়েকটি ডিপেন্ডেন্সি প্রয়োজন, ইত্যাদি।

আপনি ডিপেন্ডেন্সির যেকোনো সমন্বয় রাখতে পারেন।

**FastAPI** নিশ্চিত করবে যে সবকিছু সঠিক ক্রমে চলে।

**FastAPI** এটি অর্জন করতে ভেতরে ভেতরে এগুলো ব্যবহার করে।

## `yield` ও `HTTPException`-সহ ডিপেন্ডেন্সি { #dependencies-with-yield-and-httpexception }

আপনি দেখেছেন যে `yield`-সহ ডিপেন্ডেন্সি ব্যবহার করে `try` ব্লক রাখতে পারেন, যা কিছু কোড এক্সিকিউট করার চেষ্টা করে এবং তারপর `finally`-এর পরে কিছু exit code চালায়।

যে এক্সেপশন রেইজ হয়েছে তা ধরে তা দিয়ে কিছু করতে আপনি `except`-ও ব্যবহার করতে পারেন।

যেমন, আপনি একটি ভিন্ন এক্সেপশন রেইজ করতে পারেন, যেমন `HTTPException`।

/// tip | পরামর্শ

এটি কিছুটা অ্যাডভান্সড কৌশল, আর বেশিরভাগ ক্ষেত্রে আপনার এটি আসলে দরকার হবে না, কারণ আপনি আপনার অ্যাপ্লিকেশনের বাকি কোডের ভেতর থেকে, যেমন *পাথ অপারেশন ফাংশনে*, এক্সেপশন (`HTTPException`-সহ) রেইজ করতে পারেন।

তবে আপনার দরকার হলে এটি আছে। 🤓

## আগাম প্রস্থান ও `scope` { #early-exit-and-scope }

সাধারণত `yield`-সহ ডিপেন্ডেন্সির exit code ক্লায়েন্টকে **রেসপন্স পাঠানোর পরে** এক্সিকিউট হয়।

কিন্তু আপনি যদি জানেন যে *পাথ অপারেশন ফাংশন* থেকে রিটার্ন করার পরে ডিপেন্ডেন্সিটি আর ব্যবহার করতে হবে না, তাহলে `Depends(scope="function")` ব্যবহার করে FastAPI-কে জানাতে পারেন যে *পাথ অপারেশন ফাংশন* রিটার্ন করার পরে, কিন্তু **রেসপন্স পাঠানোর** **আগেই** ডিপেন্ডেন্সিটি বন্ধ করতে হবে।

{* ../../docs_src/dependencies/tutorial008e_an_py310.py hl[12,16] *}

`Depends()` একটি `scope` প্যারামিটার গ্রহণ করে, যা হতে পারে:

* `"function"`: রিকোয়েস্ট সামলানো *পাথ অপারেশন ফাংশনের* আগে ডিপেন্ডেন্সি শুরু হবে, *পাথ অপারেশন ফাংশন* শেষ হওয়ার পরে কিন্তু ক্লায়েন্টকে রেসপন্স ফেরত পাঠানোর **আগে** ডিপেন্ডেন্সি শেষ হবে। তাই ডিপেন্ডেন্সি ফাংশনটি *পাথ অপারেশন **ফাংশনকে*** **ঘিরে** এক্সিকিউট হবে।
* `"request"`: রিকোয়েস্ট সামলানো *পাথ অপারেশন ফাংশনের* আগে ডিপেন্ডেন্সি শুরু হবে (`"function"` ব্যবহারের মতোই), কিন্তু ক্লায়েন্টকে রেসপন্স ফেরত পাঠানোর **পরে** শেষ হবে। তাই ডিপেন্ডেন্সি ফাংশনটি **রিকোয়েস্ট** ও রেসপন্স চক্রকে **ঘিরে** এক্সিকিউট হবে।

নির্দিষ্ট করা না থাকলে এবং ডিপেন্ডেন্সিতে `yield` থাকলে, ডিফল্টভাবে এর `scope` হবে `"request"`।

### সাব-ডিপেন্ডেন্সির জন্য `scope` { #scope-for-sub-dependencies }

আপনি যখন `scope="request"` (ডিফল্ট)-সহ একটি ডিপেন্ডেন্সি ঘোষণা করেন, তখন যেকোনো সাব-ডিপেন্ডেন্সিরও `scope` `"request"` হতে হবে।

কিন্তু `"function"` `scope`-সহ একটি ডিপেন্ডেন্সির `"function"` `scope` এবং `"request"` `scope`-সহ ডিপেন্ডেন্সি থাকতে পারে।

কারণ যেকোনো ডিপেন্ডেন্সিকে তার সাব-ডিপেন্ডেন্সিগুলোর আগে নিজের exit code চালাতে পারতে হবে, কেননা exit code চলার সময়ও হয়তো সেগুলো ব্যবহার করার দরকার হতে পারে।

## `yield`, `HTTPException`, `except` ও ব্যাকগ্রাউন্ড টাস্কসহ ডিপেন্ডেন্সি { #dependencies-with-yield-httpexception-except-and-background-tasks }

বিভিন্ন ব্যবহারের ক্ষেত্র কাভার করতে এবং কিছু সমস্যা ঠিক করতে `yield`-সহ ডিপেন্ডেন্সি সময়ের সাথে বিবর্তিত হয়েছে।

## Context Manager { #context-managers }

### "Context Manager" কী { #what-are-context-managers }

"Context Manager" হলো সেই সব Python অবজেক্ট যেগুলো আপনি একটি `with` স্টেটমেন্টে ব্যবহার করতে পারেন।

যেমন, [একটি ফাইল পড়তে আপনি `with` ব্যবহার করতে পারেন](https://docs.python.org/3/tutorial/inputoutput.html#reading-and-writing-files):

⟦CODE3⟧

ভেতরে ভেতরে `open("./somefile.txt")` একটি অবজেক্ট তৈরি করে, যাকে "Context Manager" বলা হয়।

`with` ব্লক শেষ হলে এটি ফাইলটি বন্ধ করা নিশ্চিত করে, এমনকি এক্সেপশন হলেও।

আপনি যখন `yield`-সহ একটি ডিপেন্ডেন্সি তৈরি করেন, তখন **FastAPI** ভেতরে ভেতরে এর জন্য একটি context manager তৈরি করবে, এবং এটিকে আরও কিছু সম্পর্কিত টুলের সাথে মেলাবে।
