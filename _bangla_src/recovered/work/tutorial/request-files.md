তবে বেশ কয়েকটি ক্ষেত্রে `UploadFile` ব্যবহার করে আপনি উপকৃত হতে পারেন।

`bytes`-এর তুলনায় `UploadFile` ব্যবহারের বেশ কিছু সুবিধা আছে:

* প্যারামিটারের ডিফল্ট ভ্যালুতে আপনাকে `File()` ব্যবহার করতে হয় না।
* এটি একটি "spooled" ফাইল ব্যবহার করে:
    * একটি সর্বোচ্চ আকারের সীমা পর্যন্ত ফাইলটি মেমরিতে সংরক্ষিত থাকে, আর এই সীমা পেরোলে এটি ডিস্কে সংরক্ষিত হবে।
* এর মানে এটি সব মেমরি খরচ না করেই ছবি, ভিডিও, বড় বাইনারি ইত্যাদির মতো বড় ফাইলের জন্য ভালোভাবে কাজ করবে।
* আপলোড করা ফাইল থেকে আপনি মেটাডেটা পেতে পারেন।
* এর একটি [file-like](https://docs.python.org/3/glossary.html#term-file-like-object) `async` ইন্টারফেস আছে।
* এটি একটি আসল Python [`SpooledTemporaryFile`](https://docs.python.org/3/library/tempfile.html#tempfile.SpooledTemporaryFile) অবজেক্ট প্রকাশ করে, যা আপনি সরাসরি এমন অন্য লাইব্রেরিতে পাঠাতে পারেন যেগুলো একটি file-like অবজেক্ট আশা করে।

### `UploadFile` { #uploadfile }

`UploadFile`-এর নিচের অ্যাট্রিবিউটগুলো আছে:

* `filename`: আপলোড করা মূল ফাইলের নামসহ একটি `str` (যেমন `myimage.jpg`)।
* `content_type`: কনটেন্ট টাইপসহ (MIME টাইপ / মিডিয়া টাইপ) একটি `str` (যেমন `image/jpeg`)।
* `file`: একটি [`SpooledTemporaryFile`](https://docs.python.org/3/library/tempfile.html#tempfile.SpooledTemporaryFile) (একটি [file-like](https://docs.python.org/3/glossary.html#term-file-like-object) অবজেক্ট)। এটি আসল Python ফাইল অবজেক্ট, যা আপনি সরাসরি এমন অন্য ফাংশন বা লাইব্রেরিতে পাঠাতে পারেন যেগুলো একটি "file-like" অবজেক্ট আশা করে।

`UploadFile`-এর নিচের `async` মেথডগুলো আছে। এগুলো সবই ভেতরে ভেতরে সংশ্লিষ্ট ফাইল মেথডগুলো কল করে (অভ্যন্তরীণ `SpooledTemporaryFile` ব্যবহার করে)।

* `write(data)`: ফাইলে `data` (`str` বা `bytes`) লেখে।
* `read(size)`: ফাইলের `size` (`int`) পরিমাণ বাইট/অক্ষর পড়ে।
* `seek(offset)`: ফাইলের `offset` (`int`) বাইট অবস্থানে যায়।
    * যেমন, `await myfile.seek(0)` ফাইলের শুরুতে চলে যাবে।
    * আপনি যদি একবার `await myfile.read()` চালান এবং তারপর আবার বিষয়বস্তু পড়তে হয়, তাহলে এটি বিশেষভাবে কাজে আসে।
* `close()`: ফাইলটি বন্ধ করে।

যেহেতু এই সব মেথড `async` মেথড, তাই আপনাকে এগুলো "await" করতে হবে।

## "ফর্ম ডেটা" কী { #what-is-form-data }

HTML ফর্ম (`<form></form>`) যেভাবে সার্ভারে ডেটা পাঠায়, তাতে সাধারণত ওই ডেটার জন্য একটি "বিশেষ" এনকোডিং ব্যবহার হয়, যা JSON থেকে আলাদা।

**FastAPI** নিশ্চিত করবে যে ওই ডেটা JSON-এর বদলে সঠিক জায়গা থেকে পড়া হচ্ছে।

/// note | কারিগরি বিবরণ

ফর্মের ডেটায় ফাইল না থাকলে সাধারণত এটি `application/x-www-form-urlencoded` "মিডিয়া টাইপ" ব্যবহার করে এনকোড করা হয়।

কিন্তু ফর্মে ফাইল থাকলে এটি `multipart/form-data` হিসেবে এনকোড করা হয়। আপনি `File` ব্যবহার করলে **FastAPI** জানবে যে বডির সঠিক অংশ থেকে ফাইলগুলো নিতে হবে।

এই এনকোডিং ও ফর্ম ফিল্ড সম্পর্কে আরও পড়তে চাইলে [`POST`-এর জন্য <abbr title="Mozilla Developer Network - মোজিলা ডেভেলপার নেটওয়ার্ক">MDN</abbr> ওয়েব ডকুমেন্টেশনে](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/POST) যান।

///

/// warning | সতর্কতা

একটি *পাথ অপারেশনে* আপনি একাধিক `File` ও `Form` প্যারামিটার ঘোষণা করতে পারেন, কিন্তু একই সাথে JSON হিসেবে গ্রহণ করার আশায় `Body` ফিল্ড ঘোষণা করতে পারবেন না, কারণ রিকোয়েস্টের বডি `application/json`-এর বদলে `multipart/form-data` দিয়ে এনকোড করা থাকবে।

এটি **FastAPI**-এর কোনো সীমাবদ্ধতা নয়, এটি HTTP প্রোটোকলের অংশ।
