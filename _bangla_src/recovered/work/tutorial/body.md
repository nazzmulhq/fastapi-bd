# রিকোয়েস্ট বডি { #request-body }

আপনাকে যখন কোনো ক্লায়েন্ট (ধরা যাক, একটি ব্রাউজার) থেকে আপনার API-তে ডেটা পাঠাতে হয়, তখন আপনি সেটি একটি **রিকোয়েস্ট বডি** হিসেবে পাঠান।

একটি **রিকোয়েস্ট** বডি হলো ক্লায়েন্ট আপনার API-তে যে ডেটা পাঠায়। একটি **রেসপন্স** বডি হলো আপনার API ক্লায়েন্টকে যে ডেটা পাঠায়।

আপনার API-কে প্রায় সবসময়ই একটি **রেসপন্স** বডি পাঠাতে হয়। কিন্তু ক্লায়েন্টদের সবসময় **রিকোয়েস্ট বডি** পাঠানোর প্রয়োজন হয় না, কখনো কখনো তারা শুধু একটি পাথ রিকোয়েস্ট করে, হয়তো কিছু কুয়েরি প্যারামিটারসহ, কিন্তু কোনো বডি পাঠায় না।

একটি **রিকোয়েস্ট** বডি ঘোষণা করতে আপনি [Pydantic](https://pydantic.dev/docs/) মডেল ব্যবহার করেন, এর সব শক্তি ও সুবিধাসহ।

/// note | নোট

ডেটা পাঠাতে আপনার এগুলোর একটি ব্যবহার করা উচিত: `POST` (সবচেয়ে প্রচলিত), `PUT`, `DELETE` বা `PATCH`।

স্পেসিফিকেশনে একটি `GET` রিকোয়েস্টের সাথে বডি পাঠানোর আচরণ অনির্ধারিত, তবুও FastAPI এটি সাপোর্ট করে, কেবল খুবই জটিল/চরম ক্ষেত্রের জন্য।

যেহেতু এটি নিরুৎসাহিত করা হয়, তাই `GET` ব্যবহার করলে Swagger UI-সহ ইন্টারঅ্যাকটিভ ডকুমেন্টেশন বডির ডকুমেন্টেশন দেখাবে না, আর মাঝখানের প্রক্সিগুলো হয়তো এটি সাপোর্ট করবে না।

## ফলাফল { #results }

শুধু ওই Python টাইপ ঘোষণা দিয়েই **FastAPI**:

* রিকোয়েস্টের বডি JSON হিসেবে পড়বে।
* সংশ্লিষ্ট টাইপগুলো রূপান্তর করবে (প্রয়োজন হলে)।
* ডেটা ভ্যালিডেট করবে।
    * ডেটা অবৈধ হলে, এটি একটি সুন্দর ও স্পষ্ট এরর রিটার্ন করবে, যা ঠিক কোথায় এবং কোন ডেটা ভুল ছিল তা দেখাবে।
* প্রাপ্ত ডেটা আপনাকে `item` প্যারামিটারে দেবে।
    * যেহেতু আপনি ফাংশনে এটিকে `Item` টাইপের হিসেবে ঘোষণা করেছেন, তাই সব অ্যাট্রিবিউট ও তাদের টাইপের জন্য আপনি সব এডিটর সাপোর্টও (কমপ্লিশন ইত্যাদি) পাবেন।
* আপনার মডেলের জন্য [JSON Schema](https://json-schema.org) সংজ্ঞা তৈরি করবে, আপনার প্রজেক্টের জন্য যুক্তিসঙ্গত হলে এগুলো আপনি অন্য যেকোনো জায়গায়ও ব্যবহার করতে পারেন।
* ওই স্কিমাগুলো তৈরি হওয়া OpenAPI স্কিমার অংশ হবে, এবং স্বয়ংক্রিয় ডকুমেন্টেশনের <abbr title="User Interfaces - ইউজার ইন্টারফেস">UI</abbr>-গুলো সেগুলো ব্যবহার করবে।

## রিকোয়েস্ট বডি + পাথ প্যারামিটার { #request-body-path-parameters }

আপনি একই সাথে পাথ প্যারামিটার ও রিকোয়েস্ট বডি ঘোষণা করতে পারেন।

**FastAPI** বুঝতে পারবে যে যেসব ফাংশন প্যারামিটার পাথ প্যারামিটারের সাথে মেলে সেগুলো **পাথ থেকে নিতে হবে**, আর যেসব ফাংশন প্যারামিটার Pydantic মডেল হিসেবে ঘোষণা করা হয়েছে সেগুলো **রিকোয়েস্ট বডি থেকে নিতে হবে**।

## রিকোয়েস্ট বডি + পাথ + কুয়েরি প্যারামিটার { #request-body-path-query-parameters }

আপনি **বডি**, **পাথ** ও **কুয়েরি** প্যারামিটার, সবগুলো একই সাথে ঘোষণা করতে পারেন।

**FastAPI** এগুলোর প্রতিটিকে চিনে নেবে এবং সঠিক জায়গা থেকে ডেটা নেবে।

{* ../../docs_src/body/tutorial004_py310.py hl[16] *}

ফাংশন প্যারামিটারগুলো এভাবে চেনা হবে:

* প্যারামিটারটি যদি **পাথেও** ঘোষণা করা থাকে, তাহলে এটি পাথ প্যারামিটার হিসেবে ব্যবহার হবে।
* প্যারামিটারটি যদি **একক টাইপের** হয় (যেমন `int`, `float`, `str`, `bool` ইত্যাদি), তাহলে এটি **কুয়েরি** প্যারামিটার হিসেবে ধরা হবে।
* প্যারামিটারটি যদি একটি **Pydantic মডেলের** টাইপ হিসেবে ঘোষণা করা হয়, তাহলে এটি রিকোয়েস্ট **বডি** হিসেবে ধরা হবে।

/// note | নোট

ডিফল্ট ভ্যালু `= None` থাকার কারণে FastAPI জানবে যে `q`-এর ভ্যালু আবশ্যক নয়।

ভ্যালুটি যে আবশ্যক নয় তা নির্ধারণ করতে FastAPI `str | None` ব্যবহার করে না, এটি জানবে যে এটি আবশ্যক নয় কারণ এর ডিফল্ট ভ্যালু `= None`।

তবে টাইপ অ্যানোটেশন যোগ করলে আপনার এডিটর আপনাকে আরও ভালো সাপোর্ট দিতে এবং এরর ধরতে পারবে।
