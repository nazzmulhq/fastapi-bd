# শর্তসাপেক্ষ OpenAPI { #conditional-openapi }

দরকার হলে আপনি এনভায়রনমেন্টের ওপর নির্ভর করে শর্তসাপেক্ষে OpenAPI কনফিগার করতে, এমনকি পুরোপুরি বন্ধ করতে সেটিংস ও এনভায়রনমেন্ট ভেরিয়েবল ব্যবহার করতে পারেন।

## সিকিউরিটি, API ও ডকুমেন্টেশন প্রসঙ্গে { #about-security-apis-and-docs }

প্রোডাকশনে আপনার ডকুমেন্টেশন ইউজার ইন্টারফেস লুকিয়ে রাখা আপনার API সুরক্ষার উপায় *হওয়া উচিত নয়*।

এটি আপনার API-তে কোনো বাড়তি নিরাপত্তা যোগ করে না, *পাথ অপারেশনগুলো* যেখানে আছে সেখানে তখনও উপলব্ধ থাকবে।

আপনার কোডে যদি কোনো সিকিউরিটি ত্রুটি থাকে, তাহলে সেটি তখনও থাকবে।

ডকুমেন্টেশন লুকালে শুধু আপনার API-এর সাথে কীভাবে কাজ করতে হয় তা বোঝা আরও কঠিন হয়, এবং প্রোডাকশনে এটি ডিবাগ করা আপনার জন্য আরও কঠিন হতে পারে। একে শুধু [Security through obscurity](https://en.wikipedia.org/wiki/Security_through_obscurity)-এর একটি রূপ হিসেবে গণ্য করা যায়।

আপনি যদি আপনার API সুরক্ষিত করতে চান, তাহলে এর চেয়ে ভালো বেশ কিছু কাজ করতে পারেন, যেমন:

* নিশ্চিত করুন যে আপনার রিকোয়েস্ট বডি ও রেসপন্সের জন্য সুসংজ্ঞায়িত Pydantic মডেল আছে।
* ডিপেন্ডেন্সি ব্যবহার করে যেকোনো প্রয়োজনীয় অনুমতি ও রোল কনফিগার করুন।
* কখনো প্লেইনটেক্সট পাসওয়ার্ড সংরক্ষণ করবেন না, কেবল পাসওয়ার্ড হ্যাশ সংরক্ষণ করুন।
* pwdlib ও JWT টোকেনের মতো সুপরিচিত ক্রিপ্টোগ্রাফিক টুল বাস্তবায়ন ও ব্যবহার করুন, ইত্যাদি।
* প্রয়োজনমতো OAuth2 scopes দিয়ে আরও সূক্ষ্ম অনুমতি নিয়ন্ত্রণ যোগ করুন।
* ...ইত্যাদি।

তবুও আপনার হয়তো খুবই নির্দিষ্ট একটি ব্যবহারের ক্ষেত্র থাকতে পারে যেখানে কোনো এনভায়রনমেন্টের জন্য (যেমন প্রোডাকশনের জন্য) বা এনভায়রনমেন্ট ভেরিয়েবলের কনফিগারেশনের ওপর নির্ভর করে আপনাকে সত্যিই API ডকুমেন্টেশন বন্ধ করতে হয়।
