# কাস্টম Request ও APIRoute ক্লাস { #custom-request-and-apiroute-class }

কিছু ক্ষেত্রে আপনি হয়তো `Request` ও `APIRoute` ক্লাসের ব্যবহৃত লজিক ওভাররাইড করতে চাইবেন।

বিশেষ করে, এটি একটি মিডলওয়্যারের লজিকের ভালো বিকল্প হতে পারে।

যেমন, আপনার অ্যাপ্লিকেশন প্রসেস করার আগে আপনি যদি রিকোয়েস্ট বডি পড়তে বা পরিবর্তন করতে চান।

/// danger | বিপদ

এটি একটি "অ্যাডভান্সড" ফিচার।

আপনি যদি সবে **FastAPI** শুরু করে থাকেন, তাহলে এই অংশটি এড়িয়ে যেতে পারেন।

///

## ব্যবহারের ক্ষেত্র { #use-cases }

কিছু ব্যবহারের ক্ষেত্রের মধ্যে আছে:

* non-JSON রিকোয়েস্ট বডিকে JSON-এ রূপান্তর করা (যেমন [`msgpack`](https://msgpack.org/index.html))।
* gzip দিয়ে কম্প্রেস করা রিকোয়েস্ট বডি ডিকম্প্রেস করা।
* সব রিকোয়েস্ট বডি স্বয়ংক্রিয়ভাবে লগ করা।

## কাস্টম রিকোয়েস্ট বডি এনকোডিং সামলানো { #handling-custom-request-body-encodings }

চলুন দেখি gzip রিকোয়েস্ট ডিকম্প্রেস করতে কীভাবে একটি কাস্টম `Request` সাবক্লাস ব্যবহার করা যায়।

আর ওই কাস্টম রিকোয়েস্ট ক্লাস ব্যবহার করতে একটি `APIRoute` সাবক্লাস।

### একটি কাস্টম `GzipRequest` ক্লাস তৈরি করুন { #create-a-custom-gziprequest-class }

/// tip | পরামর্শ

এটি কীভাবে কাজ করে তা দেখানোর জন্য একটি খেলনা উদাহরণ, আপনার যদি Gzip সাপোর্ট দরকার হয়, তাহলে দেওয়া [`GzipMiddleware`](../advanced/middleware.md#gzipmiddleware) ব্যবহার করতে পারেন।

///

প্রথমে আমরা একটি `GzipRequest` ক্লাস তৈরি করি, যা উপযুক্ত হেডার থাকলে বডি ডিকম্প্রেস করতে `Request.body()` মেথড ওভাররাইট করবে।

হেডারে `gzip` না থাকলে এটি বডি ডিকম্প্রেস করার চেষ্টা করবে না।

এভাবে একই রাউট ক্লাস gzip দিয়ে কম্প্রেস করা বা কম্প্রেস না করা রিকোয়েস্ট সামলাতে পারে।

### একটি কাস্টম `GzipRoute` ক্লাস তৈরি করুন { #create-a-custom-gziproute-class }

এরপর আমরা `fastapi.routing.APIRoute`-এর একটি কাস্টম সাবক্লাস তৈরি করি যা `GzipRequest` ব্যবহার করবে।

এবার এটি `APIRoute.get_route_handler()` মেথড ওভাররাইট করবে।

এই মেথডটি একটি ফাংশন রিটার্ন করে। আর সেই ফাংশনটিই একটি রিকোয়েস্ট গ্রহণ করে একটি রেসপন্স রিটার্ন করবে।

এখানে আমরা মূল রিকোয়েস্ট থেকে একটি `GzipRequest` তৈরি করতে এটি ব্যবহার করি।

{* ../../docs_src/custom_request_and_route/tutorial001_an_py310.py hl[19:27] *}

/// note | কারিগরি বিবরণ

একটি `Request`-এর একটি `request.scope` অ্যাট্রিবিউট আছে, যা শুধু রিকোয়েস্ট সম্পর্কিত মেটাডেটা ধারণকারী একটি Python `dict`।

একটি `Request`-এর একটি `request.receive`-ও আছে, যা রিকোয়েস্টের বডি "গ্রহণ" করার একটি ফাংশন।

`scope` `dict` ও `receive` ফাংশন দুটোই ASGI স্পেসিফিকেশনের অংশ।

আর ওই দুটি জিনিস, `scope` ও `receive`, একটি নতুন `Request` ইনস্ট্যান্স তৈরি করতে যা যা দরকার।

`Request` সম্পর্কে আরও জানতে [রিকোয়েস্ট নিয়ে Starlette-এর ডকুমেন্টেশন](https://starlette.dev/requests/) দেখুন।

///

`GzipRequest.get_route_handler`-এর রিটার্ন করা ফাংশন কেবল একটি কাজই ভিন্নভাবে করে, তা হলো `Request`-কে একটি `GzipRequest`-এ রূপান্তর করা।

এটি করে, আমাদের `GzipRequest` আমাদের *পাথ অপারেশনে* ডেটা পাঠানোর আগে (প্রয়োজন হলে) সেটি ডিকম্প্রেস করার দায়িত্ব নেবে।

এরপর সব প্রসেসিং লজিক একই থাকে।

কিন্তু `GzipRequest.body`-তে আমাদের পরিবর্তনগুলোর কারণে, প্রয়োজনের সময় **FastAPI** যখন রিকোয়েস্ট বডি লোড করবে তখন সেটি স্বয়ংক্রিয়ভাবে ডিকম্প্রেস হবে।

/// tip | পরামর্শ

এই একই সমস্যার সমাধান করতে `RequestValidationError`-এর একটি কাস্টম হ্যান্ডলারে `body` ব্যবহার করা সম্ভবত অনেক বেশি সহজ ([এরর হ্যান্ডলিং](../tutorial/handling-errors.md#use-the-requestvalidationerror-body))।

তবে এই উদাহরণটি এখনো বৈধ এবং এটি দেখায় কীভাবে অভ্যন্তরীণ কম্পোনেন্টগুলোর সাথে কাজ করতে হয়।
