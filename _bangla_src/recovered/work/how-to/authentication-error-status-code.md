# পুরোনো 403 অথেনটিকেশন এরর স্ট্যাটাস কোড ব্যবহার { #use-old-403-authentication-error-status-codes }

FastAPI ভার্সন `0.122.0`-এর আগে, অথেনটিকেশন ব্যর্থ হওয়ার পরে অন্তর্ভুক্ত সিকিউরিটি ইউটিলিটিগুলো যখন ক্লায়েন্টকে একটি এরর রিটার্ন করত, তখন সেগুলো HTTP স্ট্যাটাস কোড `403 Forbidden` ব্যবহার করত।

FastAPI ভার্সন `0.122.0` থেকে সেগুলো আরও উপযুক্ত HTTP স্ট্যাটাস কোড `401 Unauthorized` ব্যবহার করে, এবং HTTP স্পেসিফিকেশন [RFC 7235](https://datatracker.ietf.org/doc/html/rfc7235#section-3.1), [RFC 9110](https://datatracker.ietf.org/doc/html/rfc9110#name-401-unauthorized) অনুসরণ করে রেসপন্সে একটি যুক্তিসঙ্গত `WWW-Authenticate` হেডার রিটার্ন করে।

কিন্তু কোনো কারণে আপনার ক্লায়েন্টরা যদি পুরোনো আচরণের ওপর নির্ভর করে, তাহলে আপনার সিকিউরিটি ক্লাসে `make_not_authenticated_error` মেথড ওভাররাইড করে আপনি সেটিতে ফিরে যেতে পারেন।

যেমন, আপনি `HTTPBearer`-এর একটি সাবক্লাস তৈরি করতে পারেন যা ডিফল্ট `401 Unauthorized` এররের বদলে একটি `403 Forbidden` এরর রিটার্ন করে:
