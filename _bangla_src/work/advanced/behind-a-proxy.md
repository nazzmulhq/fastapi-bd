# প্রক্সির পেছনে { #behind-a-proxy }

অনেক পরিস্থিতিতে আপনি আপনার FastAPI অ্যাপের সামনে Traefik বা Nginx-এর মতো একটি **প্রক্সি** ব্যবহার করবেন।

এই প্রক্সিগুলো HTTPS সার্টিফিকেট ও অন্যান্য বিষয় সামলাতে পারে।

## প্রক্সি Forwarded হেডার { #proxy-forwarded-headers }

আপনার অ্যাপ্লিকেশনের সামনের একটি **প্রক্সি** সাধারণত আপনার **সার্ভারে** রিকোয়েস্ট পাঠানোর আগে তাৎক্ষণিকভাবে কিছু হেডার সেট করে, যাতে সার্ভার জানতে পারে যে রিকোয়েস্টটি প্রক্সি **ফরোয়ার্ড** করেছে, এবং মূল (পাবলিক) URL, ডোমেইনসহ, এটি HTTPS ব্যবহার করছে কিনা ইত্যাদি জানতে পারে।

**সার্ভার** প্রোগ্রাম (যেমন **FastAPI CLI**-এর মাধ্যমে **Uvicorn**) এই হেডারগুলো বুঝতে পারে, এবং তারপর সেই তথ্য আপনার অ্যাপ্লিকেশনে পাঠায়।

কিন্তু সিকিউরিটির জন্য, যেহেতু সার্ভার জানে না যে এটি একটি বিশ্বস্ত প্রক্সির পেছনে আছে, তাই এটি ওই হেডারগুলো বিবেচনায় নেবে না।

/// note | কারিগরি বিবরণ

প্রক্সি হেডারগুলো হলো:

* [X-Forwarded-For](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For)
* [X-Forwarded-Proto](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-Proto)
* [X-Forwarded-Host](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-Host)

///

### প্রক্সি Forwarded হেডার চালু করুন { #enable-proxy-forwarded-headers }

আপনি *CLI অপশন* `--forwarded-allow-ips` দিয়ে FastAPI CLI চালু করতে পারেন এবং ওই forwarded হেডারগুলো পড়ার জন্য বিশ্বস্ত IP ঠিকানাগুলো দিতে পারেন।

আপনি যদি এটি `--forwarded-allow-ips="*"` সেট করেন, তাহলে এটি সব আগত IP-কে বিশ্বাস করবে।

আপনার **সার্ভার** যদি একটি বিশ্বস্ত **প্রক্সির** পেছনে থাকে এবং কেবল প্রক্সিই এর সাথে কথা বলে, তাহলে এতে ওই **প্রক্সির** IP যাই হোক তা গ্রহণ করবে।

### প্রক্সি Forwarded হেডার কীভাবে কাজ করে { #how-proxy-forwarded-headers-work }

ক্লায়েন্ট ও **অ্যাপ্লিকেশন সার্ভারের** মাঝে **প্রক্সি** কীভাবে forwarded হেডার যোগ করে তার একটি দৃশ্যমান উপস্থাপনা এখানে দেওয়া হলো:

⟦CODE3⟧

**প্রক্সি** মূল ক্লায়েন্ট রিকোয়েস্টটি আটকায় এবং **অ্যাপ্লিকেশন সার্ভারে** রিকোয়েস্ট পাঠানোর আগে বিশেষ *forwarded* হেডারগুলো (`X-Forwarded-*`) যোগ করে।

এই হেডারগুলো মূল রিকোয়েস্ট সম্পর্কে এমন তথ্য সংরক্ষণ করে যা নইলে হারিয়ে যেত:

* **X-Forwarded-For**: মূল ক্লায়েন্টের IP ঠিকানা
* **X-Forwarded-Proto**: মূল প্রোটোকল (`https`)
* **X-Forwarded-Host**: মূল হোস্ট (`mysuperapp.com`)

যখন **FastAPI CLI** `--forwarded-allow-ips` দিয়ে কনফিগার করা থাকে, তখন এটি এই হেডারগুলো বিশ্বাস করে এবং ব্যবহার করে, যেমন রিডাইরেক্টে সঠিক URL তৈরি করতে।

## বাদ দেওয়া পাথ prefix-সহ প্রক্সি { #proxy-with-a-stripped-path-prefix }

আপনার এমন একটি প্রক্সি থাকতে পারে যা আপনার অ্যাপ্লিকেশনে একটি পাথ prefix যোগ করে।

এসব ক্ষেত্রে আপনার অ্যাপ্লিকেশন কনফিগার করতে আপনি `root_path` ব্যবহার করতে পারেন।

`root_path` হলো ASGI স্পেসিফিকেশনের দেওয়া একটি ব্যবস্থা (যার ওপর, Starlette-এর মাধ্যমে, FastAPI তৈরি)।

এই নির্দিষ্ট ক্ষেত্রগুলো সামলাতে `root_path` ব্যবহার হয়।

আর সাব-অ্যাপ্লিকেশন মাউন্ট করার সময়ও এটি ভেতরে ভেতরে ব্যবহার হয়।

বাদ দেওয়া পাথ prefix-সহ একটি প্রক্সি থাকার মানে, এক্ষেত্রে, আপনি আপনার কোডে `/app`-এ একটি পাথ ঘোষণা করতে পারেন, কিন্তু তারপর ওপরে একটি স্তর (প্রক্সি) যোগ করেন যা আপনার **FastAPI** অ্যাপ্লিকেশনকে `/api/v1`-এর মতো একটি পাথের অধীনে রাখবে।

এক্ষেত্রে মূল পাথ `/app` আসলে `/api/v1/app`-এ সার্ভ হবে।

যদিও আপনার সব কোড এই ধরে নিয়ে লেখা যে শুধু `/app` আছে।

{* ../../docs_src/behind_a_proxy/tutorial001_py310.py hl[6] *}

আর অ্যাপ সার্ভারে (সম্ভবত FastAPI CLI-এর মাধ্যমে Uvicorn) রিকোয়েস্ট পাঠানোর আগে প্রক্সি তাৎক্ষণিকভাবে **পাথ prefix** **"বাদ দেবে"**, আপনার অ্যাপ্লিকেশনকে এই বিশ্বাসে রেখে যে এটি `/app`-এ সার্ভ হচ্ছে, যাতে prefix `/api/v1` অন্তর্ভুক্ত করতে আপনাকে আপনার সব কোড আপডেট করতে না হয়।

এ পর্যন্ত সবকিছু স্বাভাবিকভাবে কাজ করবে।

কিন্তু তারপর আপনি যখন অন্তর্ভুক্ত ডকুমেন্টেশন UI (ফ্রন্টএন্ড) খুলবেন, তখন এটি `/api/v1/openapi.json`-এর বদলে `/openapi.json`-এ OpenAPI স্কিমা পাওয়ার আশা করবে।

তাই ফ্রন্টএন্ড (যা ব্রাউজারে চলে) `/openapi.json`-এ পৌঁছানোর চেষ্টা করবে এবং OpenAPI স্কিমা পেতে পারবে না।

যেহেতু আমাদের অ্যাপের জন্য `/api/v1` পাথ prefix-সহ একটি প্রক্সি আছে, তাই ফ্রন্টএন্ডকে `/api/v1/openapi.json`-এ OpenAPI স্কিমা আনতে হবে।

## বাদ দেওয়া পাথ prefix-সহ প্রক্সি সম্পর্কে { #about-proxies-with-a-stripped-path-prefix }

মনে রাখবেন, বাদ দেওয়া পাথ prefix-সহ একটি প্রক্সি এটি কনফিগার করার উপায়গুলোর কেবল একটি।

সম্ভবত অনেক ক্ষেত্রে ডিফল্ট হবে যে প্রক্সির কোনো বাদ দেওয়া পাথ prefix নেই।

এরকম ক্ষেত্রে (বাদ দেওয়া পাথ prefix ছাড়া), প্রক্সি `https://myawesomeapp.com`-এর মতো কিছুতে শুনবে, আর তারপর ব্রাউজার যদি `https://myawesomeapp.com/api/v1/app`-এ যায় এবং আপনার সার্ভার (যেমন Uvicorn) `http://127.0.0.1:8000`-এ শোনে, তাহলে প্রক্সি (বাদ দেওয়া পাথ prefix ছাড়া) একই পাথে Uvicorn অ্যাক্সেস করবে: `http://127.0.0.1:8000/api/v1/app`।

## অতিরিক্ত সার্ভার { #additional-servers }

/// warning | সতর্কতা

এটি আরও অ্যাডভান্সড একটি ব্যবহারের ক্ষেত্র। নির্দ্বিধায় এড়িয়ে যান।

///

ডিফল্টভাবে **FastAPI** OpenAPI স্কিমায় `root_path`-এর URL দিয়ে একটি `server` তৈরি করবে।

তবে আপনি অন্যান্য বিকল্প `servers`-ও দিতে পারেন, যেমন আপনি যদি চান *একই* ডকুমেন্টেশন UI একটি স্টেজিং ও একটি প্রোডাকশন এনভায়রনমেন্ট দুটোর সাথেই কাজ করুক।

আপনি যদি `servers`-এর একটি কাস্টম লিস্ট দেন এবং একটি `root_path` থাকে (কারণ আপনার API একটি প্রক্সির পেছনে থাকে), তাহলে **FastAPI** লিস্টের শুরুতে এই `root_path`-সহ একটি "server" যোগ করবে।

## একটি সাব-অ্যাপ্লিকেশন মাউন্ট করা { #mounting-a-sub-application }

`root_path`-সহ একটি প্রক্সি ব্যবহারের পাশাপাশি যদি আপনাকে একটি সাব-অ্যাপ্লিকেশন মাউন্ট করতে হয় ([সাব-অ্যাপ্লিকেশন - মাউন্ট](sub-applications.md)-এ যেমন বর্ণনা করা হয়েছে), তাহলে আপনি প্রত্যাশামতোই স্বাভাবিকভাবে এটি করতে পারেন।

FastAPI ভেতরে ভেতরে বুদ্ধিমত্তার সাথে `root_path` ব্যবহার করবে, তাই এটি এমনিতেই কাজ করবে। ✨
