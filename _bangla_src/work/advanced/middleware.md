# অ্যাডভান্সড মিডলওয়্যার { #advanced-middleware }

মূল টিউটোরিয়ালে আপনি পড়েছেন কীভাবে আপনার অ্যাপ্লিকেশনে [কাস্টম মিডলওয়্যার](../tutorial/middleware.md) যোগ করতে হয়।

আর তারপর এটাও পড়েছেন কীভাবে [`CORSMiddleware` দিয়ে CORS](../tutorial/cors.md) সামলাতে হয়।

এই অংশে আমরা দেখব কীভাবে অন্যান্য মিডলওয়্যার ব্যবহার করতে হয়।

## ASGI মিডলওয়্যার যোগ করা { #adding-asgi-middlewares }

যেহেতু **FastAPI** Starlette-এর ওপর ভিত্তি করে তৈরি এবং <abbr title="Asynchronous Server Gateway Interface - অ্যাসিঙ্ক্রোনাস সার্ভার গেটওয়ে ইন্টারফেস">ASGI</abbr> স্পেসিফিকেশন বাস্তবায়ন করে, তাই আপনি যেকোনো ASGI মিডলওয়্যার ব্যবহার করতে পারেন।

একটি মিডলওয়্যার কাজ করার জন্য FastAPI বা Starlette-এর জন্য তৈরি হতে হবে এমন নয়, যতক্ষণ এটি ASGI স্পেক মেনে চলে।

সাধারণভাবে ASGI মিডলওয়্যার হলো এমন ক্লাস যা প্রথম আর্গুমেন্ট হিসেবে একটি ASGI অ্যাপ পাওয়ার আশা করে।

তাই থার্ড-পার্টি ASGI মিডলওয়্যারের ডকুমেন্টেশনে সম্ভবত আপনাকে এরকম কিছু করতে বলা হবে:

⟦CODE1⟧

কিন্তু FastAPI (আসলে Starlette) এটি করার আরও সহজ একটি উপায় দেয়, যা নিশ্চিত করে যে অভ্যন্তরীণ মিডলওয়্যারগুলো সার্ভার এরর সামলায় এবং কাস্টম এক্সেপশন হ্যান্ডলারগুলো সঠিকভাবে কাজ করে।

এর জন্য আপনি `app.add_middleware()` ব্যবহার করেন (CORS-এর উদাহরণের মতো)।

⟦CODE2⟧

`app.add_middleware()` প্রথম আর্গুমেন্ট হিসেবে একটি মিডলওয়্যার ক্লাস এবং মিডলওয়্যারে পাঠানোর জন্য যেকোনো অতিরিক্ত আর্গুমেন্ট গ্রহণ করে।

## অন্তর্ভুক্ত মিডলওয়্যার { #integrated-middlewares }

**FastAPI**-তে প্রচলিত ব্যবহারের ক্ষেত্রগুলোর জন্য বেশ কয়েকটি মিডলওয়্যার অন্তর্ভুক্ত আছে, এরপর আমরা দেখব কীভাবে এগুলো ব্যবহার করতে হয়।

/// note | কারিগরি বিবরণ

পরের উদাহরণগুলোর জন্য আপনি `from starlette.middleware.something import SomethingMiddleware`-ও ব্যবহার করতে পারতেন।

**FastAPI** শুধু আপনার, অর্থাৎ ডেভেলপারের সুবিধার জন্য `fastapi.middleware`-এ বেশ কয়েকটি মিডলওয়্যার দেয়। তবে উপলব্ধ বেশিরভাগ মিডলওয়্যার সরাসরি Starlette থেকে আসে।

## `HTTPSRedirectMiddleware` { #httpsredirectmiddleware }

নিশ্চিত করে যে সব আগত রিকোয়েস্ট অবশ্যই `https` বা `wss` হবে।

`http` বা `ws`-এ আসা যেকোনো রিকোয়েস্ট এর বদলে নিরাপদ স্কিমে রিডাইরেক্ট হবে।

## `TrustedHostMiddleware` { #trustedhostmiddleware }

HTTP Host Header আক্রমণ থেকে সুরক্ষার জন্য নিশ্চিত করে যে সব আগত রিকোয়েস্টে সঠিকভাবে সেট করা `Host` হেডার আছে।

{* ../../docs_src/advanced_middleware/tutorial002_py310.py hl[2,6:8] *}

নিচের আর্গুমেন্টগুলো সাপোর্টেড:

* `allowed_hosts` - হোস্টনেম হিসেবে অনুমোদিত হওয়া উচিত এমন ডোমেইন নামের একটি লিস্ট। সাবডোমেইন মেলাতে `*.example.com`-এর মতো ওয়াইল্ডকার্ড ডোমেইন সাপোর্টেড। যেকোনো হোস্টনেম অনুমোদন করতে হয় `allowed_hosts=["*"]` ব্যবহার করুন অথবা মিডলওয়্যারটি বাদ দিন।
* `www_redirect` - True সেট করা থাকলে অনুমোদিত হোস্টগুলোর non-www ভার্সনে আসা রিকোয়েস্টগুলো তাদের www সমতুল্যে রিডাইরেক্ট হবে। ডিফল্ট `True`।

কোনো আগত রিকোয়েস্ট সঠিকভাবে ভ্যালিডেট না হলে একটি `400` রেসপন্স পাঠানো হবে।

## `GZipMiddleware` { #gzipmiddleware }

`Accept-Encoding` হেডারে `"gzip"` আছে এমন যেকোনো রিকোয়েস্টের জন্য GZip রেসপন্স সামলায়।

মিডলওয়্যারটি স্ট্যান্ডার্ড ও স্ট্রিমিং দুই ধরনের রেসপন্সই সামলাবে।

{* ../../docs_src/advanced_middleware/tutorial003_py310.py hl[2,6] *}

নিচের আর্গুমেন্টগুলো সাপোর্টেড:

* `minimum_size` - বাইটে এই ন্যূনতম আকারের চেয়ে ছোট রেসপন্স GZip করবে না। ডিফল্ট `500`।
* `compresslevel` - GZip কম্প্রেশনের সময় ব্যবহৃত হয়। এটি ১ থেকে ৯ পর্যন্ত একটি পূর্ণসংখ্যা। ডিফল্ট `9`। কম ভ্যালুতে কম্প্রেশন দ্রুত হয় কিন্তু ফাইলের আকার বড় হয়, আর বেশি ভ্যালুতে কম্প্রেশন ধীর হয় কিন্তু ফাইলের আকার ছোট হয়।
