# বড় অ্যাপ্লিকেশন - একাধিক ফাইল { #bigger-applications-multiple-files }

আপনি যদি একটি অ্যাপ্লিকেশন বা ওয়েব API তৈরি করেন, তাহলে সবকিছু একটিমাত্র ফাইলে রাখতে পারার ঘটনা খুব কমই ঘটে।

///

* `app` ডিরেক্টরিতে সবকিছু আছে। আর এতে একটি খালি ফাইল `app/__init__.py` আছে, তাই এটি একটি "Python প্যাকেজ" ("Python মডিউলের" একটি সংগ্রহ): `app`।
* এতে একটি `app/main.py` ফাইল আছে। যেহেতু এটি একটি Python প্যাকেজের (`__init__.py` ফাইলসহ একটি ডিরেক্টরি) ভেতরে আছে, তাই এটি ওই প্যাকেজের একটি "মডিউল": `app.main`।
* একটি `app/dependencies.py` ফাইলও আছে, `app/main.py`-এর মতোই এটিও একটি "মডিউল": `app.dependencies`।
* আরেকটি `__init__.py` ফাইলসহ একটি সাবডিরেক্টরি `app/routers/` আছে, তাই এটি একটি "Python সাবপ্যাকেজ": `app.routers`।
* `app/routers/items.py` ফাইলটি একটি প্যাকেজ `app/routers/`-এর ভেতরে আছে, তাই এটি একটি সাবমডিউল: `app.routers.items`।
* `app/routers/users.py`-এর ক্ষেত্রেও তাই, এটি আরেকটি সাবমডিউল: `app.routers.users`।
* আরেকটি `__init__.py` ফাইলসহ একটি সাবডিরেক্টরি `app/internal/`-ও আছে, তাই এটি আরেকটি "Python সাবপ্যাকেজ": `app.internal`।
* আর `app/internal/admin.py` ফাইলটি আরেকটি সাবমডিউল: `app.internal.admin`।

মন্তব্যসহ একই ফাইল কাঠামো:

```bash
.
├── app                  # "app" একটি Python প্যাকেজ
│   ├── __init__.py      # এই ফাইলটি "app"-কে একটি "Python প্যাকেজ" বানায়
│   ├── main.py          # "main" মডিউল, যেমন import app.main
│   ├── dependencies.py  # "dependencies" মডিউল, যেমন import app.dependencies
│   └── routers          # "routers" একটি "Python সাবপ্যাকেজ"
│   │   ├── __init__.py  # "routers"-কে একটি "Python সাবপ্যাকেজ" বানায়
│   │   ├── items.py     # "items" সাবমডিউল, যেমন import app.routers.items
│   │   └── users.py     # "users" সাবমডিউল, যেমন import app.routers.users
│   └── internal         # "internal" একটি "Python সাবপ্যাকেজ"
│       ├── __init__.py  # "internal"-কে একটি "Python সাবপ্যাকেজ" বানায়
│       └── admin.py     # "admin" সাবমডিউল, যেমন import app.internal.admin
```

## `APIRouter` { #apirouter }

ধরা যাক শুধু ইউজার সামলানোর জন্য নির্দিষ্ট ফাইলটি হলো `/app/routers/users.py`-এর সাবমডিউলটি।

আপনি চান আপনার ইউজার সম্পর্কিত *পাথ অপারেশনগুলো* বাকি কোড থেকে আলাদা থাকুক, যাতে সবকিছু গোছানো থাকে।

কিন্তু এটি এখনো একই **FastAPI** অ্যাপ্লিকেশন/ওয়েব API-এর অংশ (এটি একই "Python প্যাকেজের" অংশ)।

`APIRouter` ব্যবহার করে আপনি ওই মডিউলের জন্য *পাথ অপারেশন* তৈরি করতে পারেন।

`FastAPI` ক্লাস যেভাবে ব্যবহার করতেন, সেভাবেই এটি ব্যবহার করুন:

## `APIRouter`-সহ আরেকটি মডিউল { #another-module-with-apirouter }

ধরা যাক আপনার অ্যাপ্লিকেশনের "items" সামলানোর জন্য নির্দিষ্ট এন্ডপয়েন্টগুলোও আছে `app/routers/items.py` মডিউলে।

আপনার *পাথ অপারেশন* আছে এগুলোর জন্য:

* `/items/`
* `/items/{item_id}`

এর পুরো গঠন `app/routers/users.py`-এর মতোই।

তবে আমরা আরেকটু বুদ্ধিমান হয়ে কোড কিছুটা সহজ করতে চাই।

আমরা জানি এই মডিউলের সব *পাথ অপারেশনে* একই জিনিস আছে:

* পাথ `prefix`: `/items`।
* `tags`: (শুধু একটি ট্যাগ: `items`)।
* অতিরিক্ত `responses`।
* `dependencies`: এগুলো সবারই আমাদের তৈরি করা সেই `X-Token` ডিপেন্ডেন্সি দরকার।

তাই এর সবকিছু প্রতিটি *পাথ অপারেশনে* যোগ করার বদলে আমরা এটি `APIRouter`-এ যোগ করতে পারি।

লক্ষ করুন, [*পাথ অপারেশন ডেকোরেটরে* ডিপেন্ডেন্সির](dependencies/dependencies-in-path-operation-decorators.md) মতোই, আপনার *পাথ অপারেশন ফাংশনে* কোনো ভ্যালু পাঠানো হবে না।

///

শেষ ফলাফল হলো item-এর পাথগুলো এখন:

* `/items/`
* `/items/{item_id}`

...ঠিক যেমনটা আমরা চেয়েছিলাম।

* এগুলো একটিমাত্র স্ট্রিং `"items"` ধারণকারী ট্যাগের একটি লিস্ট দিয়ে চিহ্নিত হবে।
    * এই "ট্যাগগুলো" স্বয়ংক্রিয় ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমের (OpenAPI ব্যবহার করে) জন্য বিশেষভাবে কাজের।
* এগুলোর সবগুলোতে পূর্বনির্ধারিত `responses` অন্তর্ভুক্ত থাকবে।
* এই সব *পাথ অপারেশনের* আগে `dependencies`-এর লিস্টটি মূল্যায়ন/এক্সিকিউট হবে।
    * আপনি যদি কোনো নির্দিষ্ট *পাথ অপারেশনেও* ডিপেন্ডেন্সি ঘোষণা করেন, **সেগুলোও এক্সিকিউট হবে**।
    * রাউটারের ডিপেন্ডেন্সিগুলো প্রথমে এক্সিকিউট হয়, তারপর [ডেকোরেটরের `dependencies`](dependencies/dependencies-in-path-operation-decorators.md), এবং তারপর সাধারণ প্যারামিটার ডিপেন্ডেন্সিগুলো।
    * আপনি [`scopes`-সহ `Security` ডিপেন্ডেন্সিও](../advanced/security/oauth2-scopes.md) যোগ করতে পারেন।

/// tip | পরামর্শ

`APIRouter`-এ `dependencies` থাকলে তা, যেমন, পুরো একদল *পাথ অপারেশনের* জন্য অথেনটিকেশন আবশ্যক করতে ব্যবহার করা যায়। এমনকি যদি ডিপেন্ডেন্সিগুলো প্রতিটিতে আলাদাভাবে যোগ করা না হয়।

///

/// tip | পরামর্শ

`prefix`, `tags`, `responses` ও `dependencies` প্যারামিটারগুলো (আরও অনেক ক্ষেত্রের মতোই) শুধু **FastAPI**-এর একটি ফিচার, যা আপনাকে কোডের পুনরাবৃত্তি এড়াতে সাহায্য করে।

### কাস্টম `prefix`, `tags`, `responses` ও `dependencies`-সহ একটি `APIRouter` অন্তর্ভুক্ত করুন { #include-an-apirouter-with-a-custom-prefix-tags-responses-and-dependencies }

## একই রাউটার ভিন্ন `prefix` দিয়ে একাধিকবার অন্তর্ভুক্ত করুন { #include-the-same-router-multiple-times-with-different-prefix }

ভিন্ন ভিন্ন prefix দিয়ে *একই* রাউটারের সাথে আপনি একাধিকবার `.include_router()` ব্যবহার করতে পারেন।

এটি কাজে আসতে পারে, যেমন, একই API ভিন্ন ভিন্ন prefix-এর অধীনে প্রকাশ করতে, যেমন `/api/v1` ও `/api/latest`।

এটি একটি অ্যাডভান্সড ব্যবহার যা হয়তো আপনার আসলে দরকার হবে না, তবে দরকার হলে এটি আছে।

যেভাবে আপনি একটি `FastAPI` অ্যাপ্লিকেশনে একটি `APIRouter` অন্তর্ভুক্ত করতে পারেন, সেভাবেই একটি `APIRouter`-কে আরেকটি `APIRouter`-এ অন্তর্ভুক্ত করতে পারেন, এভাবে:

⟦CODE16⟧

`FastAPI` অ্যাপে `router` অন্তর্ভুক্ত করার আগে বা পরে আপনি এটি করতে পারেন। FastAPI তবুও রাউটিং ও OpenAPI-তে `other_router`-এর *পাথ অপারেশনগুলো* অন্তর্ভুক্ত করবে।

রাউটারগুলোতে পরে যোগ করা *পাথ অপারেশনের* ক্ষেত্রেও একই কথা প্রযোজ্য। আগের অন্তর্ভুক্তির মাধ্যমেও সেগুলো দেখা যাবে।

/// warning | কারিগরি বিবরণ

একটি রাউটার অন্তর্ভুক্ত করার পরে সরাসরি `router.routes` পরিবর্তন করা এড়িয়ে চলুন। FastAPI রাউটার অন্তর্ভুক্তিকে সক্রিয় (live) হিসেবে গণ্য করে, তাই মূল রাউটার ও এর রাউটগুলো রাউটিং ও OpenAPI তৈরির অংশ থেকে যায়।

রাউট ও রাউটার যোগ করতে পাথ অপারেশন ডেকোরেটর ও `.include_router()`-এর মতো ডকুমেন্টেড API ব্যবহার করুন।

`router.routes`-কে একটি নিম্ন-স্তরের রাউট ট্রি হিসেবে গণ্য করুন যাতে রাউট সংজ্ঞা ও অন্তর্ভুক্ত রাউটার থাকতে পারে, এবং চূড়ান্ত পাথ অপারেশনগুলোর একটি সমতল লিস্ট হিসেবে এর ওপর নির্ভর করা এড়িয়ে চলুন।
