যেমন, OAuth2 স্পেসিফিকেশন যে উপায়গুলোতে ব্যবহার করা যায় তার একটিতে ("password flow" নামে পরিচিত) ফর্ম ফিল্ড হিসেবে একটি `username` ও `password` পাঠানো আবশ্যক।

<dfn title="স্পেসিফিকেশন">স্পেক</dfn> অনুযায়ী ফিল্ডগুলোর নাম হুবহু `username` ও `password` হতে হবে, এবং JSON নয়, ফর্ম ফিল্ড হিসেবে পাঠাতে হবে।

`Form` দিয়ে আপনি `Body` (এবং `Query`, `Path`, `Cookie`)-এর মতো একই কনফিগারেশন ঘোষণা করতে পারেন, যার মধ্যে আছে ভ্যালিডেশন, উদাহরণ, একটি alias (যেমন `username`-এর বদলে `user-name`) ইত্যাদি।

/// note | নোট

`Form` হলো এমন একটি ক্লাস যা সরাসরি `Body` থেকে ইনহেরিট করে।

///

/// tip | পরামর্শ

ফর্ম বডি ঘোষণা করতে আপনাকে স্পষ্টভাবে `Form` ব্যবহার করতে হবে, কারণ এটি ছাড়া প্যারামিটারগুলো কুয়েরি প্যারামিটার বা বডি (JSON) প্যারামিটার হিসেবে ধরা হবে।

## "ফর্ম ফিল্ড" সম্পর্কে { #about-form-fields }

HTML ফর্ম (`<form></form>`) যেভাবে সার্ভারে ডেটা পাঠায়, তাতে সাধারণত ওই ডেটার জন্য একটি "বিশেষ" এনকোডিং ব্যবহার হয়, যা JSON থেকে আলাদা।

**FastAPI** নিশ্চিত করবে যে ওই ডেটা JSON-এর বদলে সঠিক জায়গা থেকে পড়া হচ্ছে।

/// note | কারিগরি বিবরণ

ফর্মের ডেটা সাধারণত `application/x-www-form-urlencoded` "মিডিয়া টাইপ" ব্যবহার করে এনকোড করা হয়।

কিন্তু ফর্মে ফাইল থাকলে এটি `multipart/form-data` হিসেবে এনকোড করা হয়। ফাইল সামলানোর বিষয়ে পরের অধ্যায়ে পড়বেন।

এই এনকোডিং ও ফর্ম ফিল্ড সম্পর্কে আরও পড়তে চাইলে [`POST`-এর জন্য <abbr title="Mozilla Developer Network - মোজিলা ডেভেলপার নেটওয়ার্ক">MDN</abbr> ওয়েব ডকুমেন্টেশনে](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/POST) যান।

///

/// warning | সতর্কতা

একটি *পাথ অপারেশনে* আপনি একাধিক `Form` প্যারামিটার ঘোষণা করতে পারেন, কিন্তু একই সাথে JSON হিসেবে গ্রহণ করার আশায় `Body` ফিল্ড ঘোষণা করতে পারবেন না, কারণ রিকোয়েস্টের বডি `application/json`-এর বদলে `application/x-www-form-urlencoded` দিয়ে এনকোড করা থাকবে।

এটি **FastAPI**-এর কোনো সীমাবদ্ধতা নয়, এটি HTTP প্রোটোকলের অংশ।
