# মিডলওয়্যার { #middleware }

আপনি **FastAPI** অ্যাপ্লিকেশনে মিডলওয়্যার যোগ করতে পারেন।

একটি "মিডলওয়্যার" হলো এমন একটি ফাংশন যা প্রতিটি **রিকোয়েস্ট** কোনো নির্দিষ্ট *পাথ অপারেশন* প্রসেস করার আগে সেটির সাথে কাজ করে। আর প্রতিটি **রেসপন্স** রিটার্ন করার আগেও সেটির সাথে কাজ করে।

* এটি আপনার অ্যাপ্লিকেশনে আসা প্রতিটি **রিকোয়েস্ট** নেয়।
* তারপর এটি ওই **রিকোয়েস্টের** সাথে কিছু করতে পারে বা প্রয়োজনীয় যেকোনো কোড চালাতে পারে।
* তারপর এটি **রিকোয়েস্টটি** অ্যাপ্লিকেশনের বাকি অংশে (কোনো *পাথ অপারেশনে*) প্রসেস করার জন্য পাঠায়।
* তারপর এটি অ্যাপ্লিকেশনের (কোনো *পাথ অপারেশনের*) তৈরি করা **রেসপন্সটি** নেয়।
* এটি ওই **রেসপন্সের** সাথে কিছু করতে পারে বা প্রয়োজনীয় যেকোনো কোড চালাতে পারে।
* তারপর এটি **রেসপন্সটি** রিটার্ন করে।

/// note | কারিগরি বিবরণ

আপনার যদি `yield`-সহ ডিপেন্ডেন্সি থাকে, তাহলে exit code মিডলওয়্যারের *পরে* চলবে।

যদি কোনো ব্যাকগ্রাউন্ড টাস্ক থাকে ([ব্যাকগ্রাউন্ড টাস্ক](background-tasks.md) অংশে আলোচিত, যা আপনি পরে দেখবেন), সেগুলো সব মিডলওয়্যারের *পরে* চলবে।

///

## একটি মিডলওয়্যার তৈরি করুন { #create-a-middleware }

একটি মিডলওয়্যার তৈরি করতে একটি ফাংশনের ওপরে `@app.middleware("http")` ডেকোরেটর ব্যবহার করুন।

মিডলওয়্যার ফাংশনটি পায়:

* `request`।
* একটি ফাংশন `call_next`, যা প্যারামিটার হিসেবে `request` পাবে।
    * এই ফাংশনটি `request`-কে সংশ্লিষ্ট *পাথ অপারেশনে* পাঠাবে।
    * তারপর এটি সংশ্লিষ্ট *পাথ অপারেশনের* তৈরি করা `response` রিটার্ন করে।
* তারপর রিটার্ন করার আগে আপনি `response`-কে আরও পরিবর্তন করতে পারেন।

{* ../../docs_src/middleware/tutorial001_py310.py hl[8:9,11,14] *}

/// tip | পরামর্শ

মনে রাখবেন, কাস্টম মালিকানাধীন হেডার [`X-` উপসর্গ ব্যবহার করে](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers) যোগ করা যায়।

তবে আপনার যদি এমন কাস্টম হেডার থাকে যা আপনি চান একটি ব্রাউজারের ক্লায়েন্ট দেখতে পাক, তাহলে [Starlette-এর CORS ডকুমেন্টেশনে](https://starlette.dev/middleware/#corsmiddleware) ডকুমেন্ট করা `expose_headers` প্যারামিটার ব্যবহার করে সেগুলো আপনার CORS কনফিগারেশনে ([CORS (Cross-Origin Resource Sharing)](cors.md)) যোগ করতে হবে।

///

/// note | কারিগরি বিবরণ

আপনি `from starlette.requests import Request`-ও ব্যবহার করতে পারতেন।

**FastAPI** এটি আপনার, অর্থাৎ ডেভেলপারের সুবিধার জন্য দেয়। তবে এটি সরাসরি Starlette থেকে আসে।

### `response`-এর আগে ও পরে { #before-and-after-the-response }

কোনো *পাথ অপারেশন* `request` পাওয়ার আগে আপনি সেটির সাথে চালানোর জন্য কোড যোগ করতে পারেন।

আর `response` তৈরি হওয়ার পরে, রিটার্ন করার আগেও।

যেমন, রিকোয়েস্ট প্রসেস করে রেসপন্স তৈরি করতে কত সেকেন্ড লেগেছে তা ধারণকারী একটি কাস্টম হেডার `X-Process-Time` যোগ করতে পারেন:

## একাধিক মিডলওয়্যারের এক্সিকিউশন ক্রম { #multiple-middleware-execution-order }

আপনি যখন `@app.middleware()` ডেকোরেটর বা `app.add_middleware()` মেথড ব্যবহার করে একাধিক মিডলওয়্যার যোগ করেন, তখন প্রতিটি নতুন মিডলওয়্যার অ্যাপ্লিকেশনটিকে মুড়িয়ে নেয়, ফলে একটি স্ট্যাক তৈরি হয়। সবশেষে যোগ করা মিডলওয়্যারটি হয় *সবচেয়ে বাইরের*, আর প্রথমটি হয় *সবচেয়ে ভেতরের*।

রিকোয়েস্টের পথে *সবচেয়ে বাইরের* মিডলওয়্যারটি প্রথমে চলে।

রেসপন্সের পথে এটি সবশেষে চলে।

যেমন:

⟦CODE1⟧

এর ফলে এক্সিকিউশনের ক্রম হয় এরকম:

* **রিকোয়েস্ট**: MiddlewareB → MiddlewareA → route

* **রেসপন্স**: route → MiddlewareA → MiddlewareB

স্ট্যাক করার এই আচরণ নিশ্চিত করে যে মিডলওয়্যারগুলো একটি অনুমানযোগ্য ও নিয়ন্ত্রণযোগ্য ক্রমে এক্সিকিউট হয়।
