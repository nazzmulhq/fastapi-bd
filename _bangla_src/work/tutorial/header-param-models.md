# হেডার প্যারামিটার মডেল { #header-parameter-models }

আপনার যদি পরস্পর সম্পর্কিত একদল **হেডার প্যারামিটার** থাকে, তাহলে সেগুলো ঘোষণা করতে আপনি একটি **Pydantic মডেল** তৈরি করতে পারেন।

এতে আপনি **মডেলটি** **একাধিক জায়গায়** **পুনরায় ব্যবহার** করতে পারবেন, আর সব প্যারামিটারের জন্য একবারে ভ্যালিডেশন ও মেটাডেটাও ঘোষণা করতে পারবেন। 😎

এটি FastAPI ভার্সন `0.115.0` থেকে সাপোর্টেড। 🤓

## অতিরিক্ত হেডার নিষিদ্ধ করুন { #forbid-extra-headers }

কিছু বিশেষ ক্ষেত্রে (সম্ভবত খুব একটা প্রচলিত নয়) আপনি যে হেডারগুলো গ্রহণ করতে চান সেগুলো **সীমিত** করতে চাইতে পারেন।

যেকোনো `extra` ফিল্ড `forbid` করতে আপনি Pydantic-এর মডেল কনফিগারেশন ব্যবহার করতে পারেন:

{* ../../docs_src/header_param_models/tutorial002_an_py310.py hl[10] *}

যেমন, ক্লায়েন্ট যদি `plumbus` ভ্যালুসহ একটি `tool` হেডার পাঠানোর চেষ্টা করে, তাহলে সে একটি **এরর** রেসপন্স পাবে, যা জানাবে যে `tool` হেডার প্যারামিটারটি অনুমোদিত নয়:

## আন্ডারস্কোর রূপান্তর বন্ধ করুন { #disable-convert-underscores }

সাধারণ হেডার প্যারামিটারের মতোই, প্যারামিটারের নামে আন্ডারস্কোর অক্ষর থাকলে সেগুলো **স্বয়ংক্রিয়ভাবে হাইফেনে রূপান্তরিত হয়**।

যেমন, কোডে আপনার যদি `save_data` নামে একটি হেডার প্যারামিটার থাকে, তাহলে প্রত্যাশিত HTTP হেডার হবে `save-data`, এবং ডকুমেন্টেশনে সেভাবেই দেখা যাবে।

কোনো কারণে এই স্বয়ংক্রিয় রূপান্তর বন্ধ করতে চাইলে, হেডার প্যারামিটারের Pydantic মডেলের ক্ষেত্রেও আপনি সেটি করতে পারেন।
