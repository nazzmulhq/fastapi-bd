# বডি - ফিল্ড { #body-fields }

যেভাবে আপনি `Query`, `Path` ও `Body` দিয়ে *পাথ অপারেশন ফাংশনের* প্যারামিটারে অতিরিক্ত ভ্যালিডেশন ও মেটাডেটা ঘোষণা করতে পারেন, একইভাবে Pydantic-এর `Field` ব্যবহার করে Pydantic মডেলের ভেতরেও ভ্যালিডেশন ও মেটাডেটা ঘোষণা করতে পারেন।

তারপর আপনি মডেল অ্যাট্রিবিউটের সাথে `Field` ব্যবহার করতে পারেন:

{* ../../docs_src/body_fields/tutorial001_an_py310.py hl[11:14] *}

`Field` ঠিক `Query`, `Path` ও `Body`-এর মতোই কাজ করে, এতে একই সব প্যারামিটার ইত্যাদি আছে।

/// note | কারিগরি বিবরণ

আসলে `Query`, `Path` এবং এরপর যেগুলো দেখবেন সেগুলো একটি সাধারণ `Param` ক্লাসের সাবক্লাসের অবজেক্ট তৈরি করে, যা নিজেই Pydantic-এর `FieldInfo` ক্লাসের একটি সাবক্লাস।

আর Pydantic-এর `Field`-ও `FieldInfo`-এর একটি ইনস্ট্যান্স রিটার্ন করে।

`Body`-ও সরাসরি `FieldInfo`-এর একটি সাবক্লাসের অবজেক্ট রিটার্ন করে। আর পরে আরও কিছু দেখবেন যেগুলো `Body` ক্লাসের সাবক্লাস।

মনে রাখবেন, আপনি যখন `fastapi` থেকে `Query`, `Path` ও অন্যগুলো ইম্পোর্ট করেন, সেগুলো আসলে এমন ফাংশন যা বিশেষ ক্লাস রিটার্ন করে।

///

/// tip | পরামর্শ

লক্ষ করুন, টাইপ, ডিফল্ট ভ্যালু ও `Field`-সহ প্রতিটি মডেল অ্যাট্রিবিউটের গঠন একটি *পাথ অপারেশন ফাংশনের* প্যারামিটারের মতোই, শুধু `Path`, `Query` ও `Body`-এর বদলে `Field`।

///

## অতিরিক্ত তথ্য যোগ করুন { #add-extra-information }

আপনি `Field`, `Query`, `Body` ইত্যাদিতে অতিরিক্ত তথ্য ঘোষণা করতে পারেন। আর তা তৈরি হওয়া JSON Schema-তে অন্তর্ভুক্ত হবে।

ডকুমেন্টেশনের পরের দিকে উদাহরণ ঘোষণা করা শেখার সময় অতিরিক্ত তথ্য যোগ করার বিষয়ে আরও জানবেন।

/// warning | সতর্কতা

`Field`-এ দেওয়া অতিরিক্ত কী-গুলো আপনার অ্যাপ্লিকেশনের ফলাফলস্বরূপ OpenAPI স্কিমাতেও থাকবে।
যেহেতু এই কী-গুলো অবশ্যই OpenAPI স্পেসিফিকেশনের অংশ নাও হতে পারে, তাই কিছু OpenAPI টুল, যেমন [OpenAPI ভ্যালিডেটর](https://validator.swagger.io/), আপনার তৈরি হওয়া স্কিমার সাথে কাজ নাও করতে পারে।

///

## সংক্ষেপে { #recap }

মডেল অ্যাট্রিবিউটের জন্য অতিরিক্ত ভ্যালিডেশন ও মেটাডেটা ঘোষণা করতে আপনি Pydantic-এর `Field` ব্যবহার করতে পারেন।

অতিরিক্ত JSON Schema মেটাডেটা দিতে আপনি অতিরিক্ত কিওয়ার্ড আর্গুমেন্টও ব্যবহার করতে পারেন।
