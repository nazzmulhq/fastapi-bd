# সিকিউরিটি { #security }

সিকিউরিটি, অথেনটিকেশন ও অথরাইজেশন সামলানোর অনেক উপায় আছে।

আর এটি সাধারণত একটি জটিল ও "কঠিন" বিষয়।

অনেক ফ্রেমওয়ার্ক ও সিস্টেমে শুধু সিকিউরিটি ও অথেনটিকেশন সামলাতেই প্রচুর পরিশ্রম ও কোড লাগে (অনেক ক্ষেত্রে এটি লেখা মোট কোডের ৫০% বা তারও বেশি হতে পারে)।

**FastAPI** আপনাকে সব সিকিউরিটি স্পেসিফিকেশন পড়ে শেখা ছাড়াই সহজে, দ্রুত ও স্ট্যান্ডার্ড উপায়ে **সিকিউরিটি** সামলাতে সাহায্য করার জন্য বেশ কিছু টুল দেয়।

তবে প্রথমে কিছু ছোট ধারণা দেখে নেওয়া যাক।

## তাড়াহুড়োয় আছেন? { #in-a-hurry }

আপনার যদি এই পরিভাষাগুলো নিয়ে কোনো মাথাব্যথা না থাকে এবং *এখনই* শুধু ইউজারনেম ও পাসওয়ার্ডভিত্তিক অথেনটিকেশনসহ সিকিউরিটি যোগ করতে হয়, তাহলে পরের অধ্যায়গুলোতে চলে যান।

## OAuth2 { #oauth2 }

OAuth2 হলো একটি স্পেসিফিকেশন যা অথেনটিকেশন ও অথরাইজেশন সামলানোর বেশ কয়েকটি উপায় সংজ্ঞায়িত করে।

এটি বেশ বিস্তৃত একটি স্পেসিফিকেশন এবং বেশ কয়েকটি জটিল ব্যবহারের ক্ষেত্র কাভার করে।

এতে একটি "থার্ড পার্টি" ব্যবহার করে অথেনটিকেট করার উপায়ও আছে।

"Facebook, Google, X (Twitter), GitHub দিয়ে লগইন" সুবিধাসহ সব সিস্টেম ভেতরে ভেতরে এটিই ব্যবহার করে।

### OAuth 1 { #oauth-1 }

একটি OAuth 1 ছিল, যা OAuth2 থেকে খুবই আলাদা এবং আরও জটিল, কারণ এতে যোগাযোগ কীভাবে এনক্রিপ্ট করতে হবে তার সরাসরি স্পেসিফিকেশন অন্তর্ভুক্ত ছিল।

আজকাল এটি খুব একটা জনপ্রিয় বা ব্যবহৃত নয়।

OAuth2 যোগাযোগ কীভাবে এনক্রিপ্ট করতে হবে তা নির্দিষ্ট করে না, এটি আশা করে যে আপনার অ্যাপ্লিকেশন HTTPS দিয়ে সার্ভ করা হবে।

/// tip | পরামর্শ

**ডিপ্লয়মেন্ট** সম্পর্কিত অংশে আপনি দেখবেন কীভাবে Traefik ও Let's Encrypt ব্যবহার করে বিনামূল্যে HTTPS সেট আপ করতে হয়।

## OpenID Connect { #openid-connect }

OpenID Connect হলো **OAuth2**-এর ওপর ভিত্তি করে তৈরি আরেকটি স্পেসিফিকেশন।

এটি শুধু OAuth2-কে বাড়িয়ে OAuth2-তে তুলনামূলকভাবে অস্পষ্ট কিছু বিষয় নির্দিষ্ট করে, যাতে এটিকে আরও আন্তঃকার্যক্ষম করা যায়।

যেমন, Google লগইন OpenID Connect ব্যবহার করে (যা ভেতরে ভেতরে OAuth2 ব্যবহার করে)।

কিন্তু Facebook লগইন OpenID Connect সাপোর্ট করে না। এর নিজস্ব ধরনের OAuth2 আছে।

### OpenID ("OpenID Connect" নয়) { #openid-not-openid-connect }

একটি "OpenID" স্পেসিফিকেশনও ছিল। সেটি **OpenID Connect**-এর মতো একই সমস্যা সমাধানের চেষ্টা করেছিল, কিন্তু OAuth2-এর ওপর ভিত্তি করে তৈরি ছিল না।

তাই এটি ছিল সম্পূর্ণ একটি অতিরিক্ত সিস্টেম।

আজকাল এটি খুব একটা জনপ্রিয় বা ব্যবহৃত নয়।

## OpenAPI { #openapi }

OpenAPI (আগে Swagger নামে পরিচিত) হলো API তৈরির ওপেন স্পেসিফিকেশন (এখন Linux Foundation-এর অংশ)।

**FastAPI** **OpenAPI**-এর ওপর ভিত্তি করে তৈরি।

এ কারণেই একাধিক স্বয়ংক্রিয় ইন্টারঅ্যাকটিভ ডকুমেন্টেশন ইন্টারফেস, কোড জেনারেশন ইত্যাদি সম্ভব হয়।

OpenAPI-তে একাধিক সিকিউরিটি "স্কিম" সংজ্ঞায়িত করার একটি উপায় আছে।

এগুলো ব্যবহার করে আপনি এই সব স্ট্যান্ডার্ড-ভিত্তিক টুলের সুবিধা নিতে পারেন, এই ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমগুলোসহ।

OpenAPI নিচের সিকিউরিটি স্কিমগুলো সংজ্ঞায়িত করে:

* `apiKey`: একটি অ্যাপ্লিকেশন-নির্দিষ্ট কী, যা আসতে পারে:
    * একটি কুয়েরি প্যারামিটার থেকে।
    * একটি হেডার থেকে।
    * একটি কুকি থেকে।
* `http`: স্ট্যান্ডার্ড HTTP অথেনটিকেশন সিস্টেম, যার মধ্যে আছে:
    * `bearer`: `Bearer ` ও তারপর একটি টোকেন ভ্যালুসহ একটি `Authorization` হেডার। এটি OAuth2 থেকে উত্তরাধিকারসূত্রে এসেছে।
    * HTTP Basic অথেনটিকেশন।
    * HTTP Digest ইত্যাদি।
* `oauth2`: সিকিউরিটি সামলানোর সব OAuth2 উপায় (যেগুলোকে "flow" বলা হয়)।
    * এই flow-গুলোর কয়েকটি একটি OAuth 2.0 অথেনটিকেশন প্রোভাইডার (যেমন Google, Facebook, X (Twitter), GitHub ইত্যাদি) তৈরির জন্য উপযুক্ত:
        * `implicit`
        * `clientCredentials`
        * `authorizationCode`
    * তবে একটি নির্দিষ্ট "flow" আছে যা সরাসরি একই অ্যাপ্লিকেশনে অথেনটিকেশন সামলানোর জন্য একদম উপযুক্তভাবে ব্যবহার করা যায়:
        * `password`: পরের কয়েকটি অধ্যায়ে এর উদাহরণ থাকবে।
* `openIdConnect`: OAuth2 অথেনটিকেশন ডেটা স্বয়ংক্রিয়ভাবে খুঁজে বের করার উপায় সংজ্ঞায়িত করার একটি পদ্ধতি এতে আছে।
    * এই স্বয়ংক্রিয় খুঁজে বের করার বিষয়টিই OpenID Connect স্পেসিফিকেশনে সংজ্ঞায়িত।


/// tip | পরামর্শ

Google, Facebook, X (Twitter), GitHub ইত্যাদির মতো অন্যান্য অথেনটিকেশন/অথরাইজেশন প্রোভাইডার যুক্ত করাও সম্ভব এবং তুলনামূলকভাবে সহজ।

সবচেয়ে জটিল সমস্যা হলো ওগুলোর মতো একটি অথেনটিকেশন/অথরাইজেশন প্রোভাইডার তৈরি করা, তবে **FastAPI** আপনাকে সহজে এটি করার টুল দেয়, আর ভারী কাজগুলো আপনার হয়ে করে দেয়।

## **FastAPI** ইউটিলিটি { #fastapi-utilities }

FastAPI `fastapi.security` মডিউলে এই প্রতিটি সিকিউরিটি স্কিমের জন্য বেশ কিছু টুল দেয়, যা এই সিকিউরিটি ব্যবস্থাগুলো ব্যবহার সহজ করে।

পরের অধ্যায়গুলোতে আপনি দেখবেন **FastAPI**-এর দেওয়া ওই টুলগুলো ব্যবহার করে কীভাবে আপনার API-তে সিকিউরিটি যোগ করতে হয়।

আর এটি কীভাবে স্বয়ংক্রিয়ভাবে ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমে যুক্ত হয়ে যায় তাও দেখবেন।
