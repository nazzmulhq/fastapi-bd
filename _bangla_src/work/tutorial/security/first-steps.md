# সিকিউরিটি - প্রথম ধাপ { #security-first-steps }

কল্পনা করা যাক কোনো একটি ডোমেইনে আপনার **ব্যাকএন্ড** API আছে।

আর আপনার একটি **ফ্রন্টএন্ড** আছে আরেকটি ডোমেইনে, বা একই ডোমেইনের ভিন্ন একটি পাথে (বা একটি মোবাইল অ্যাপ্লিকেশনে)।

আর আপনি চান ফ্রন্টএন্ড যাতে একটি **ইউজারনেম** ও **পাসওয়ার্ড** ব্যবহার করে ব্যাকএন্ডের সাথে অথেনটিকেট করতে পারে।

**FastAPI** দিয়ে এটি তৈরি করতে আমরা **OAuth2** ব্যবহার করতে পারি।

তবে আপনার প্রয়োজনীয় ছোট ছোট তথ্যগুলো খুঁজে পেতে পুরো লম্বা স্পেসিফিকেশন পড়ার সময়টুকু আপনাকে বাঁচিয়ে দেওয়া যাক।

সিকিউরিটি সামলাতে **FastAPI**-এর দেওয়া টুলগুলো ব্যবহার করা যাক।

আর একই অ্যাপ্লিকেশন ডিবাগ, যাচাই ও টেস্ট করতে আপনি নিজেও এটি ব্যবহার করতে পারেন।

## `password` flow { #the-password-flow }

এবার একটু পিছিয়ে গিয়ে বোঝা যাক এসব কী।

`password` "flow" হলো সিকিউরিটি ও অথেনটিকেশন সামলানোর জন্য OAuth2-তে সংজ্ঞায়িত উপায়গুলোর ("flow") একটি।

OAuth2 এমনভাবে ডিজাইন করা হয়েছিল যাতে ব্যাকএন্ড বা API, ইউজারকে অথেনটিকেট করা সার্ভার থেকে স্বাধীন থাকতে পারে।

কিন্তু এক্ষেত্রে একই **FastAPI** অ্যাপ্লিকেশন API ও অথেনটিকেশন দুটোই সামলাবে।

তাই সেই সরলীকৃত দৃষ্টিকোণ থেকে এটি পর্যালোচনা করা যাক:

* ইউজার ফ্রন্টএন্ডে `username` ও `password` লেখেন এবং `Enter` চাপেন।
* ফ্রন্টএন্ড (ইউজারের ব্রাউজারে চলমান) ওই `username` ও `password` আমাদের API-এর একটি নির্দিষ্ট URL-এ পাঠায় (`tokenUrl="token"` দিয়ে ঘোষিত)।
* API ওই `username` ও `password` যাচাই করে এবং একটি "টোকেন" দিয়ে রেসপন্স করে (আমরা এখনো এর কিছুই বাস্তবায়ন করিনি)।
    * একটি "টোকেন" হলো শুধু কিছু বিষয়বস্তুসহ একটি স্ট্রিং, যা আমরা পরে এই ইউজারকে যাচাই করতে ব্যবহার করতে পারি।
    * সাধারণত একটি টোকেন কিছু সময় পরে মেয়াদোত্তীর্ণ হওয়ার জন্য সেট করা থাকে।
        * তাই পরে কোনো এক সময়ে ইউজারকে আবার লগ ইন করতে হবে।
        * আর টোকেন চুরি হলে ঝুঁকিও কম থাকে। এটি এমন কোনো স্থায়ী চাবি নয় যা চিরকাল কাজ করবে (বেশিরভাগ ক্ষেত্রে)।
* ফ্রন্টএন্ড ওই টোকেনটি অস্থায়ীভাবে কোথাও সংরক্ষণ করে।
* ইউজার ফ্রন্টএন্ড ওয়েব অ্যাপের অন্য একটি অংশে যেতে ফ্রন্টএন্ডে ক্লিক করেন।
* ফ্রন্টএন্ডকে API থেকে আরও কিছু ডেটা আনতে হবে।
    * কিন্তু ওই নির্দিষ্ট এন্ডপয়েন্টের জন্য অথেনটিকেশন প্রয়োজন।
    * তাই আমাদের API-এর সাথে অথেনটিকেট করতে এটি `Bearer ` ও তারপর টোকেন ভ্যালুসহ একটি `Authorization` হেডার পাঠায়।
    * টোকেনে যদি `foobar` থাকে, তাহলে `Authorization` হেডারের বিষয়বস্তু হবে: `Bearer foobar`।

## **FastAPI**-এর `OAuth2PasswordBearer` { #fastapis-oauth2passwordbearer }

এই সিকিউরিটি ফিচারগুলো বাস্তবায়নের জন্য **FastAPI** বিমূর্ততার বিভিন্ন স্তরে বেশ কিছু টুল দেয়।

এই উদাহরণে আমরা একটি **Bearer** টোকেন ব্যবহার করে **Password** flow-সহ **OAuth2** ব্যবহার করব। আমরা এটি করি `OAuth2PasswordBearer` ক্লাস ব্যবহার করে।

/// note | নোট

একটি "bearer" টোকেনই একমাত্র অপশন নয়।

তবে আমাদের ব্যবহারের ক্ষেত্রের জন্য এটিই সেরা।

আর বেশিরভাগ ব্যবহারের ক্ষেত্রেও এটি সেরা হতে পারে, যদি না আপনি OAuth2 বিশেষজ্ঞ হন এবং ঠিক জানেন কেন অন্য কোনো অপশন আপনার প্রয়োজনের সাথে আরও ভালোভাবে মানানসই।

সেক্ষেত্রেও **FastAPI** আপনাকে এটি তৈরির টুল দেয়।

///

`OAuth2PasswordBearer` ক্লাসের একটি ইনস্ট্যান্স তৈরির সময় আমরা `tokenUrl` প্যারামিটার দিই। এই প্যারামিটারে সেই URL থাকে যা ক্লায়েন্ট (ইউজারের ব্রাউজারে চলমান ফ্রন্টএন্ড) একটি টোকেন পাওয়ার জন্য `username` ও `password` পাঠাতে ব্যবহার করবে।

{* ../../docs_src/security/tutorial001_an_py310.py hl[8] *}

/// tip | পরামর্শ

এখানে `tokenUrl="token"` একটি আপেক্ষিক URL `token`-কে বোঝায় যা আমরা এখনো তৈরি করিনি। যেহেতু এটি একটি আপেক্ষিক URL, তাই এটি `./token`-এর সমতুল্য।

যেহেতু আমরা একটি আপেক্ষিক URL ব্যবহার করছি, তাই আপনার API যদি `https://example.com/`-এ থাকত, তাহলে এটি `https://example.com/token`-কে বোঝাত। কিন্তু আপনার API যদি `https://example.com/api/v1/`-এ থাকত, তাহলে এটি `https://example.com/api/v1/token`-কে বোঝাত।

[প্রক্সির পেছনে](../../advanced/behind-a-proxy.md)-এর মতো অ্যাডভান্সড ব্যবহারের ক্ষেত্রেও আপনার অ্যাপ্লিকেশন যাতে কাজ করে যায় তা নিশ্চিত করতে আপেক্ষিক URL ব্যবহার করা গুরুত্বপূর্ণ।

///

এই প্যারামিটারটি ওই এন্ডপয়েন্ট / *পাথ অপারেশন* তৈরি করে না, বরং ঘোষণা করে যে টোকেন পেতে ক্লায়েন্টকে `/token` URL-টিই ব্যবহার করতে হবে। সেই তথ্য OpenAPI-তে, এবং তারপর ইন্টারঅ্যাকটিভ API ডকুমেন্টেশন সিস্টেমগুলোতে ব্যবহার হয়।

শিগগিরই আমরা আসল পাথ অপারেশনটিও তৈরি করব।

/// note | নোট

আপনি যদি খুব কঠোর "Pythonista" হন, তাহলে হয়তো `token_url`-এর বদলে `tokenUrl` প্যারামিটার নামের স্টাইলটি আপনার অপছন্দ হতে পারে।

এর কারণ এটি OpenAPI স্পেকের মতো একই নাম ব্যবহার করছে। যাতে এই সিকিউরিটি স্কিমগুলোর কোনোটি সম্পর্কে আরও খোঁজ নিতে হলে আপনি শুধু কপি-পেস্ট করে আরও তথ্য খুঁজে পেতে পারেন।

### এটি ব্যবহার করুন { #use-it }

এখন আপনি ওই `oauth2_scheme`-কে `Depends` দিয়ে একটি ডিপেন্ডেন্সিতে দিতে পারেন।

{* ../../docs_src/security/tutorial001_an_py310.py hl[12] *}

এই ডিপেন্ডেন্সি একটি `str` দেবে, যা *পাথ অপারেশন ফাংশনের* `token` প্যারামিটারে অ্যাসাইন করা হবে।

**FastAPI** জানবে যে OpenAPI স্কিমায় (এবং স্বয়ংক্রিয় API ডকুমেন্টেশনে) একটি "সিকিউরিটি স্কিম" সংজ্ঞায়িত করতে এই ডিপেন্ডেন্সিটি ব্যবহার করা যায়।

/// note | কারিগরি বিবরণ

**FastAPI** জানবে যে OpenAPI-তে সিকিউরিটি স্কিম সংজ্ঞায়িত করতে এটি (একটি ডিপেন্ডেন্সিতে ঘোষিত) `OAuth2PasswordBearer` ক্লাস ব্যবহার করতে পারে, কারণ এটি `fastapi.security.oauth2.OAuth2` থেকে ইনহেরিট করে, যা আবার `fastapi.security.base.SecurityBase` থেকে ইনহেরিট করে।

OpenAPI-এর (এবং স্বয়ংক্রিয় API ডকুমেন্টেশনের) সাথে যুক্ত সব সিকিউরিটি ইউটিলিটি `SecurityBase` থেকে ইনহেরিট করে, এভাবেই **FastAPI** জানতে পারে কীভাবে সেগুলো OpenAPI-তে যুক্ত করতে হবে।

## এটি কী করে { #what-it-does }

এটি রিকোয়েস্টে গিয়ে ওই `Authorization` হেডারটি খুঁজবে, ভ্যালুটি `Bearer ` ও তারপর কোনো টোকেন কিনা যাচাই করবে, এবং টোকেনটি একটি `str` হিসেবে রিটার্ন করবে।

এটি যদি কোনো `Authorization` হেডার না দেখে, বা ভ্যালুতে কোনো `Bearer ` টোকেন না থাকে, তাহলে এটি সরাসরি 401 স্ট্যাটাস কোড এরর (`UNAUTHORIZED`) দিয়ে রেসপন্স করবে।

এরর রিটার্ন করার জন্য টোকেনটি আছে কিনা তাও আপনাকে যাচাই করতে হবে না। আপনি নিশ্চিত থাকতে পারেন যে আপনার ফাংশন এক্সিকিউট হলে ওই টোকেনে একটি `str` থাকবে।

ইন্টারঅ্যাকটিভ ডকুমেন্টেশনে আপনি ইতিমধ্যে এটি চেষ্টা করে দেখতে পারেন:
