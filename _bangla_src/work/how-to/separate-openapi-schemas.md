# ইনপুট ও আউটপুটের জন্য আলাদা OpenAPI স্কিমা, নাকি নয় { #separate-openapi-schemas-for-input-and-output-or-not }

**Pydantic v2** প্রকাশিত হওয়ার পর থেকে তৈরি হওয়া OpenAPI আগের চেয়ে একটু বেশি নির্ভুল ও **সঠিক**। 😎

আসলে কিছু ক্ষেত্রে এমনকি একই Pydantic মডেলের জন্য OpenAPI-তে ইনপুট ও আউটপুটের জন্য **দুটি JSON Schema** থাকবে, সেগুলোর **ডিফল্ট ভ্যালু** আছে কিনা তার ওপর নির্ভর করে।

চলুন দেখি এটি কীভাবে কাজ করে এবং দরকার হলে কীভাবে এটি বদলাতে হয়।

### আউটপুটের জন্য মডেল { #model-for-output }

কিন্তু আপনি যদি একই মডেলকে আউটপুট হিসেবে ব্যবহার করেন, এখানের মতো:

{* ../../docs_src/separate_openapi_schemas/tutorial001_py310.py hl[19] *}

...তাহলে যেহেতু `description`-এর একটি ডিফল্ট ভ্যালু আছে, তাই আপনি ওই ফিল্ডের জন্য **কিছুই রিটার্ন না করলেও** এতে তখনও ওই **ডিফল্ট ভ্যালু** থাকবে।

### আউটপুট রেসপন্স ডেটার জন্য মডেল { #model-for-output-response-data }

আপনি যদি ডকুমেন্টেশন ব্যবহার করে রেসপন্সটি দেখেন, তাহলে কোডটি একটি `description` ফিল্ডে কিছু যোগ না করলেও JSON রেসপন্সে ডিফল্ট ভ্যালু (`null`) থাকে:

<div class="screenshot">
<img src="/img/tutorial/separate-openapi-schemas/image02.png">
</div>

এর মানে এতে **সবসময় একটি ভ্যালু থাকবে**, শুধু কখনো কখনো ভ্যালুটি `None` (বা JSON-এ `null`) হতে পারে।

এর মানে আপনার API ব্যবহারকারী ক্লায়েন্টদের যাচাই করতে হবে না ভ্যালুটি আছে কিনা, তারা **ধরে নিতে পারে যে ফিল্ডটি সবসময় থাকবে**, শুধু কিছু ক্ষেত্রে এর ডিফল্ট ভ্যালু `None` হবে।

OpenAPI-তে এটি বর্ণনা করার উপায় হলো ওই ফিল্ডটিকে **আবশ্যক** হিসেবে চিহ্নিত করা, কারণ এটি সবসময় থাকবে।

এ কারণে একটি মডেলের JSON Schema ভিন্ন হতে পারে, এটি **ইনপুট নাকি আউটপুটের** জন্য ব্যবহার হচ্ছে তার ওপর নির্ভর করে:

* **ইনপুটের** জন্য `description` **আবশ্যক হবে না**
* **আউটপুটের** জন্য এটি **আবশ্যক** হবে (এবং সম্ভবত `None`, বা JSON-এর ভাষায় `null`)

### ডকুমেন্টেশনে ইনপুট ও আউটপুটের জন্য মডেল { #model-for-input-and-output-in-docs }

আর আপনি যদি OpenAPI-তে সব উপলব্ধ স্কিমা (JSON Schema) দেখেন, তাহলে দেখবেন দুটি আছে, একটি `Item-Input` এবং একটি `Item-Output`।

`Item-Input`-এর জন্য `description` **আবশ্যক নয়**, এতে কোনো লাল তারকাচিহ্ন নেই।

কিন্তু `Item-Output`-এর জন্য `description` **আবশ্যক**, এতে একটি লাল তারকাচিহ্ন আছে।

<div class="screenshot">
<img src="/img/tutorial/separate-openapi-schemas/image04.png">
</div>

**Pydantic v2**-এর এই ফিচারের সাথে আপনার API ডকুমেন্টেশন আরও **নির্ভুল**, আর আপনার যদি স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট ও SDK থাকে, সেগুলোও আরও নির্ভুল হবে, আরও ভালো **ডেভেলপার অভিজ্ঞতা** ও সামঞ্জস্যসহ। 🎉

## স্কিমা আলাদা করবেন না { #do-not-separate-schemas }

এবার, কিছু ক্ষেত্রে আপনি হয়তো **ইনপুট ও আউটপুটের জন্য একই স্কিমা** রাখতে চাইবেন।

সম্ভবত এর প্রধান ব্যবহারের ক্ষেত্র হলো আপনার যদি ইতিমধ্যে কিছু স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট কোড/SDK থাকে এবং আপনি এখনই সব স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট কোড/SDK আপডেট করতে না চান, আপনি সম্ভবত কোনো এক সময়ে এটি করতে চাইবেন, তবে হয়তো এখনই নয়।

সেক্ষেত্রে আপনি **FastAPI**-তে `separate_input_output_schemas=False` প্যারামিটার দিয়ে এই ফিচারটি বন্ধ করতে পারেন।
