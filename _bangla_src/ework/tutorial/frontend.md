# ফ্রন্টএন্ড { #frontend }

/// note | এই পেজে যা শিখবেন

* React, Vue, Svelte ইত্যাদি দিয়ে বানানো ফ্রন্টএন্ড একই FastAPI অ্যাপ থেকে সার্ভ করা।
* ক্লায়েন্ট-সাইড রাউটিং কী, আর `fallback` কেন লাগে।
* কাস্টম 404 পেজ, ফোল্ডার যাচাই, আর রাউটারের সাথে ব্যবহার।

///

`app.frontend()` (বা `router.frontend()`) দিয়ে স্ট্যাটিক ফ্রন্টএন্ড অ্যাপ সার্ভ করতে পারেন।

যেসব ফ্রন্টএন্ড টুল স্ট্যাটিক ফাইল তৈরি করে, যেমন Vite-সহ React, TanStack Router, Astro, Vue, Svelte, Angular, Solid ইত্যাদি, সেগুলোর জন্য এটি কাজের।

এই টুলগুলোতে সাধারণত একটি ধাপ থাকে যা ফ্রন্টএন্ড "বিল্ড" করে (চূড়ান্ত ফাইল তৈরি করে), এমন একটি কমান্ড দিয়ে:

```bash
npm run build
```

এতে আপনার ফ্রন্টএন্ড ফাইলসহ `./dist/`-এর মতো একটি ফোল্ডার তৈরি হবে।

এই ফ্রন্টএন্ড ফ্রেমওয়ার্কগুলোর প্রয়োজনীয় নিয়ম মেনে ওই ফোল্ডারটি সার্ভ করতে `app.frontend()` ব্যবহার করতে পারেন।

**FastAPI** আগে *পাথ অপারেশনগুলো* যাচাই করে। কোনো সাধারণ রাউট না মিললেই কেবল ফ্রন্টএন্ড ফাইলগুলো যাচাই করা হয়, তাই আপনার API প্রভাবিত হবে না।

/// tip | উদাহরণ দিয়ে বুঝি

আপনার একটি অনলাইন দোকান আছে। দোকানের সুন্দর ওয়েবসাইট (ফ্রন্টএন্ড) React দিয়ে বানানো, আর ডেটা দেয় FastAPI (ব্যাকএন্ড)। আলাদা দুটি সার্ভার না চালিয়ে একটি FastAPI অ্যাপ থেকেই দুটো সার্ভ করা যায়: `/api/...` ঠিকানায় API, বাকি সব ঠিকানায় ওয়েবসাইট।

## ক্লায়েন্ট-সাইড রাউটিং { #client-side-routing }

**single-page app** (SPA)-সহ অনেক ফ্রন্টএন্ড অ্যাপ ক্লায়েন্ট-সাইড রাউটিং ব্যবহার করে। `/dashboard/settings`-এর মতো একটি পাথ হয়তো আসল কোনো ফাইল নয়, বরং ফ্রেমওয়ার্ক নিজেই সেটি সামলায়।

/// tip | SPA সহজ ভাষায়

Single-page app মানে পুরো ওয়েবসাইটটা আসলে একটিমাত্র `index.html` পেজ। ব্যবহারকারী বিভিন্ন পাতায় গেলে JavaScript পেজের বিষয়বস্তু বদলে দেয় আর ঠিকানা বারে নতুন URL দেখায়, কিন্তু সার্ভারে আসলে `/dashboard/settings` নামে কোনো ফাইল নেই।

///

তাই কেউ যদি ওই URL সরাসরি খোলে (অ্যাপের ভেতর দিয়ে না গিয়ে), তাহলে ব্যাকএন্ডের উচিত `index.html` থেকে ফ্রন্টএন্ড অ্যাপটি সার্ভ করা, যাতে তারপর ফ্রন্টএন্ড ফ্রেমওয়ার্ক ক্লায়েন্ট-সাইড রাউটিং সামলাতে পারে।

এর জন্য `fallback="index.html"` ব্যবহার করুন:

{* ../../docs_src/frontend/tutorial002_py310.py hl[5] *}

**FastAPI** এই fallback শুধু সেই `GET` আর `HEAD` রিকোয়েস্টের জন্য ব্যবহার করে, যেগুলো স্পষ্টভাবে `Accept: text/html` বা `Accept: application/xhtml+xml` দিয়ে HTML গ্রহণ করে, যেমনটা ব্রাউজারের পাতা খোলার রিকোয়েস্ট সাধারণত করে। অনুপস্থিত JavaScript, CSS আর ছবির মতো ফাইলগুলো তখনও `404` ফেরত দেয়।

অন্য মেথডের রিকোয়েস্ট, যেমন `POST` বা `PUT`, যেসব পাথ শুধু ফ্রন্টএন্ড fallback-এর সাথে মেলে সেগুলোতে গেলেও `404` ফেরত দেয়। সাধারণ **FastAPI** *পাথ অপারেশনগুলো* তখনও ফ্রন্টএন্ড রাউটের চেয়ে বেশি অগ্রাধিকার পায়।

/// tip | পরামর্শ

ডিফল্টভাবে `fallback`-এর মান `fallback="auto"`। বেশিরভাগ ক্ষেত্রে `fallback` নির্দিষ্ট করার দরকার হবে না। বিস্তারিত নিচে পড়ুন।

///

ক্লায়েন্ট-সাইড রাউটিং ব্যবহার করা অনেক ফ্রন্টএন্ড অ্যাপের জন্য এটাই আপনি চাইবেন, যেমন TanStack Router-সহ React, Vue, Angular, SvelteKit বা Solid।

/// tip | পরামর্শ

তাই সাধারণত `fallback` আর্গুমেন্ট বাদ দিতে পারেন।

## Fallback Auto { #fallback-auto }

ডিফল্টভাবে `app.frontend()` `fallback="auto"` ব্যবহার করে।

ফ্রন্টএন্ড ফোল্ডারে যদি একটি `404.html` ফাইল থাকে, তাহলে অনুপস্থিত ফ্রন্টএন্ড পাথে ওই ফাইলটি `404` স্ট্যাটাস কোডসহ সার্ভ হয়।

নইলে, যদি একটি `index.html` ফাইল থাকে, তাহলে ব্রাউজারের অনুপস্থিত পাতার পাথে `index.html` সার্ভ হয়, যা ক্লায়েন্ট-সাইড রাউটিংওয়ালা অনেক ফ্রন্টএন্ড অ্যাপ আশা করে।

তাই বেশিরভাগ ক্ষেত্রে `fallback` আর্গুমেন্ট নির্দিষ্ট না করেই `app.frontend("/", directory="dist")` ব্যবহার করতে পারেন।

## ফোল্ডার যাচাই { #check-directory }

ডিফল্টভাবে `app.frontend()` `check_dir="auto"` ব্যবহার করে।

`FASTAPI_ENV` এনভায়রনমেন্ট ভেরিয়েবল `development` সেট করা থাকলে, ফ্রন্টএন্ড বিল্ডের আউটপুট ফোল্ডার না থাকলে **FastAPI** শুধু একটি সতর্কবার্তা দেখায়। [`fastapi dev` কমান্ড](https://github.com/fastapi/fastapi-cli#fastapi-dev) এই এনভায়রনমেন্ট ভেরিয়েবল আগে থেকে সেট না থাকলে আপনার হয়ে সেট করে দেয়। এতে ডেভেলপমেন্টের সময় ফ্রন্টএন্ড বিল্ড বা চালু করার আগেই ব্যাকএন্ড চালু করা যায়।

অন্য যেকোনো এনভায়রনমেন্টে, অ্যাপ তৈরির সময় **FastAPI** একটি এরর দেয়। এতে ফ্রন্টএন্ড ফাইল ছাড়া একটি অ্যাপ ডিপ্লয় করার আগেই কনফিগারেশনের ভুল ধরা পড়ে।

অ্যাপ তৈরির সময় সবসময় ফোল্ডার যাচাই করতে `check_dir=True`-ও সেট করতে পারেন।

আপনার ফ্রন্টএন্ড ফাইলগুলো যদি পরে তৈরি হয়, যেমন অ্যাপ অবজেক্ট তৈরির পরে আলাদা একটি বিল্ড ধাপে, তাহলে `check_dir=False` সেট করুন:

{* ../../docs_src/frontend/tutorial006_py310.py hl[5] *}

`check_dir=False` দিলে অ্যাপ তৈরির সময় **FastAPI** ফোল্ডার যাচাই করবে না। রিকোয়েস্ট সামলানোর সময়ও যদি কনফিগার করা ফোল্ডারটি না থাকে, তাহলে **FastAPI** তখন একটি এরর দেবে।

## ডিপেন্ডেন্সি ও মিডলওয়্যার { #dependencies-and-middleware }

ফ্রন্টএন্ড রেসপন্সগুলো সাধারণ **FastAPI** অ্যাপ্লিকেশনের ভেতরেই চলে, তাই HTTP মিডলওয়্যার এগুলোতে প্রযোজ্য।

অ্যাপ, একটি `APIRouter`, আর `include_router()`-এর ডিপেন্ডেন্সিগুলোও ফ্রন্টএন্ড রেসপন্সে প্রযোজ্য। কুকি অথেনটিকেশন বা এরকম কিছু দিয়ে একটি ফ্রন্টএন্ড সুরক্ষিত করতে এটি কাজে লাগতে পারে। (যেমন অ্যাডমিন প্যানেল শুধু লগইন করা ব্যবহারকারীরা দেখতে পারবে।)

ডিপেন্ডেন্সিগুলো রেসপন্স হেডারও বদলাতে আর ব্যাকগ্রাউন্ড টাস্কও যোগ করতে পারে, সাধারণ *পাথ অপারেশনের* মতোই।

## শুধু স্ট্যাটিক বিল্ড আউটপুট { #static-build-output-only }

`app.frontend()` আপনার ফ্রন্টএন্ড বিল্ডের আগে থেকে তৈরি ফাইলগুলো সার্ভ করে।

এটি server-side rendering চালায় না। এটি সেই ফ্রন্টএন্ড ফ্রেমওয়ার্কগুলোর জন্য, যেগুলো স্ট্যাটিক ফাইল তৈরি করে, সেগুলোর জন্য নয় যেগুলোর প্রতিটি রিকোয়েস্টে সার্ভারে ডায়নামিক রেন্ডারিং দরকার (যেমন Next.js-এর সার্ভার মোড)।

* ফ্রন্টএন্ড পরে বিল্ড হলে `check_dir=False`।
