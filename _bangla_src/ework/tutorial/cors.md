# CORS (Cross-Origin Resource Sharing) { #cors-cross-origin-resource-sharing }

/// note | এই পেজে যা শিখবেন

* CORS কী, আর ব্রাউজার কেন অন্য "origin"-এর API ডাকতে বাধা দেয়।
* "origin" বলতে কী বোঝায়।
* `CORSMiddleware` দিয়ে কোন কোন ওয়েবসাইটকে অনুমতি দেবেন।
* প্রতিটি সেটিং কী করে, আর সাধারণ ভুলগুলো।

///

[CORS বা "Cross-Origin Resource Sharing"](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS) বলতে সেই পরিস্থিতিগুলো বোঝায়, যখন একটি ব্রাউজারে চলা ফ্রন্টএন্ডে এমন JavaScript কোড থাকে যা একটি ব্যাকএন্ডের সাথে যোগাযোগ করে, আর ব্যাকএন্ডটি ফ্রন্টএন্ডের থেকে ভিন্ন একটি "origin"-এ থাকে।

/// tip | কেন এই নিয়ম?

ধরুন আপনি একটি ক্ষতিকর ওয়েবসাইটে ঢুকলেন। ব্রাউজারে আপনি আপনার ব্যাংকের সাইটে লগইন করা আছেন। ক্ষতিকর সাইটের JavaScript যদি আপনার অজান্তে ব্যাংকের API-তে রিকোয়েস্ট পাঠাতে পারত, তাহলে বিপদ হতো। তাই ব্রাউজার নিয়ম করেছে: অন্য origin-এর API কেবল তখনই ডাকা যাবে যখন সেই API নিজে বলে "হ্যাঁ, এই সাইটকে আমি অনুমতি দিচ্ছি"। এই অনুমতি দেওয়ার ব্যবস্থাটাই CORS।

///

## Origin { #origin }

একটি origin হলো প্রোটোকল (`http`, `https`), ডোমেইন (`myapp.com`, `localhost`, `localhost.tiangolo.com`) আর পোর্টের (`80`, `443`, `8080`) সমন্বয়।

তাই এগুলো সবই আলাদা origin:

* `http://localhost`
* `https://localhost`
* `http://localhost:8080`

সবগুলোই `localhost`-এ হলেও এরা ভিন্ন প্রোটোকল বা পোর্ট ব্যবহার করে, তাই এরা আলাদা "origin"।

## ধাপগুলো { #steps }

তাহলে ধরা যাক আপনার ব্রাউজারে `http://localhost:8080`-এ একটি ফ্রন্টএন্ড চলছে, আর এর JavaScript `http://localhost`-এ চলা একটি ব্যাকএন্ডের সাথে যোগাযোগের চেষ্টা করছে (যেহেতু আমরা কোনো পোর্ট নির্দিষ্ট করিনি, ব্রাউজার ডিফল্ট পোর্ট `80` ধরে নেবে)।

তখন ব্রাউজার `:80`-ব্যাকএন্ডে একটি HTTP `OPTIONS` রিকোয়েস্ট পাঠাবে, আর ব্যাকএন্ড যদি এই ভিন্ন origin (`http://localhost:8080`) থেকে যোগাযোগের অনুমতি দেওয়া যথাযথ হেডার পাঠায়, তাহলে `:8080`-ব্রাউজার ফ্রন্টএন্ডের JavaScript-কে `:80`-ব্যাকএন্ডে তার রিকোয়েস্ট পাঠাতে দেবে।

এটি করতে `:80`-ব্যাকএন্ডের কাছে "অনুমোদিত origin"-এর একটি তালিকা থাকতে হবে।

এই ক্ষেত্রে `:8080`-ফ্রন্টএন্ড সঠিকভাবে কাজ করতে তালিকায় `http://localhost:8080` থাকতে হবে।

## ওয়াইল্ডকার্ড { #wildcards }

সবাইকে অনুমতি দিতে তালিকাটিকে `"*"` (একটি "ওয়াইল্ডকার্ড") হিসেবেও ঘোষণা করা সম্ভব।

তবে তাতে শুধু নির্দিষ্ট কিছু ধরনের যোগাযোগের অনুমতি মিলবে, ক্রেডেনশিয়াল জড়িত সবকিছু বাদ দিয়ে: কুকি, Bearer টোকেনের মতো Authorization হেডার ইত্যাদি।

তাই সবকিছু ঠিকভাবে কাজ করাতে অনুমোদিত origin-গুলো স্পষ্টভাবে উল্লেখ করাই ভালো।

## `CORSMiddleware` ব্যবহার করুন { #use-corsmiddleware }

`CORSMiddleware` ব্যবহার করে আপনার **FastAPI** অ্যাপ্লিকেশনে এটি কনফিগার করতে পারেন।

* `CORSMiddleware` ইমপোর্ট করুন।
* অনুমোদিত origin-গুলোর একটি তালিকা তৈরি করুন (স্ট্রিং হিসেবে)।
* এটিকে আপনার **FastAPI** অ্যাপ্লিকেশনে একটি "মিডলওয়্যার" হিসেবে যোগ করুন।

আপনার ব্যাকএন্ড কী কী অনুমতি দেবে তাও নির্দিষ্ট করতে পারেন:

* ক্রেডেনশিয়াল (Authorization হেডার, কুকি ইত্যাদি)।
* নির্দিষ্ট HTTP মেথড (`POST`, `PUT`) অথবা ওয়াইল্ডকার্ড `"*"` দিয়ে সবগুলো।
* নির্দিষ্ট HTTP হেডার অথবা ওয়াইল্ডকার্ড `"*"` দিয়ে সবগুলো।

///

`CORSMiddleware`-এর ইমপ্লিমেন্টেশনের ডিফল্ট প্যারামিটারগুলো ডিফল্টভাবে কড়া (সীমাবদ্ধ), তাই ক্রস-ডোমেইন পরিস্থিতিতে ব্রাউজারকে নির্দিষ্ট origin, মেথড বা হেডার ব্যবহারের অনুমতি দিতে সেগুলো আপনাকে স্পষ্টভাবে চালু করতে হবে।

এই আর্গুমেন্টগুলো সাপোর্টেড:

* `allow_origins` - যেসব origin-কে ক্রস-অরিজিন রিকোয়েস্ট করার অনুমতি দেওয়া উচিত তাদের একটি তালিকা। যেমন `['https://example.org', 'https://www.example.org']`। যেকোনো origin-কে অনুমতি দিতে `['*']` ব্যবহার করতে পারেন।
* `allow_origin_regex` - একটি রেগুলার এক্সপ্রেশন স্ট্রিং, যার সাথে মিলে যাওয়া origin-গুলোকে ক্রস-অরিজিন রিকোয়েস্ট করার অনুমতি দেওয়া হবে। যেমন `'https://.*\.example\.org'` (`example.org`-এর সব সাবডোমেইন)।
* `allow_methods` - ক্রস-অরিজিন রিকোয়েস্টে অনুমোদিত HTTP মেথডের একটি তালিকা। ডিফল্ট `['GET']`। সব স্ট্যান্ডার্ড মেথড অনুমোদন করতে `['*']` ব্যবহার করতে পারেন।
* `allow_headers` - ক্রস-অরিজিন রিকোয়েস্টে সাপোর্ট করা উচিত এমন HTTP রিকোয়েস্ট হেডারের একটি তালিকা। ডিফল্ট `[]`। সব হেডার অনুমোদন করতে `['*']` ব্যবহার করতে পারেন। [সাধারণ CORS রিকোয়েস্টের](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#simple_requests) জন্য `Accept`, `Accept-Language`, `Content-Language` আর `Content-Type` হেডার সবসময় অনুমোদিত।
* `allow_credentials` - ক্রস-অরিজিন রিকোয়েস্টে কুকি সাপোর্ট করা উচিত কিনা তা নির্দেশ করে। ডিফল্ট `False`।

    `allow_credentials` `True` সেট করা থাকলে `allow_origins`, `allow_methods` আর `allow_headers`-এর কোনোটিই `['*']` সেট করা যাবে না। এগুলোর সবই [স্পষ্টভাবে উল্লেখ করতে](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#credentialed_requests_and_wildcards) হবে।

* `expose_headers` - কোন কোন রেসপন্স হেডার ব্রাউজারের কাছে অ্যাক্সেসযোগ্য করা উচিত তা নির্দেশ করে। ডিফল্ট `[]`।
* `max_age` - ব্রাউজার CORS রেসপন্স সর্বোচ্চ কত সেকেন্ড ক্যাশ করে রাখবে তা সেট করে। ডিফল্ট `600`।

/// warning | সাধারণ ভুল

* লগইন কুকি বা টোকেন দরকার, তাই `allow_credentials=True` দিলেন, আবার `allow_origins=["*"]`-ও দিলেন। এই সংমিশ্রণ কাজ করবে না। নির্দিষ্ট origin লিখুন।
* origin-এর শেষে `/` দিয়ে ফেলা, যেমন `"http://localhost:8080/"`। origin-এ পাথ থাকে না, শেষের স্ল্যাশ ছাড়া লিখুন।
* `http` আর `https` গুলিয়ে ফেলা। দুটো আলাদা origin।

মিডলওয়্যার দুটি নির্দিষ্ট ধরনের HTTP রিকোয়েস্টে সাড়া দেয়...

### CORS preflight রিকোয়েস্ট { #cors-preflight-requests }

এগুলো হলো `Origin` আর `Access-Control-Request-Method` হেডারসহ যেকোনো `OPTIONS` রিকোয়েস্ট। ("Preflight" মানে "উড্ডয়নের আগের যাচাই": আসল রিকোয়েস্ট পাঠানোর আগে ব্রাউজার জিজ্ঞেস করে নেয় অনুমতি আছে কিনা।)

এই ক্ষেত্রে মিডলওয়্যার আসা রিকোয়েস্টটি মাঝপথে ধরে যথাযথ CORS হেডারসহ উত্তর দেবে, তথ্যগত উদ্দেশ্যে একটি `200` বা `400` রেসপন্স দিয়ে।

### সাধারণ রিকোয়েস্ট { #simple-requests }

`Origin` হেডারসহ যেকোনো রিকোয়েস্ট। এই ক্ষেত্রে মিডলওয়্যার রিকোয়েস্টটি স্বাভাবিকভাবেই সামনে পাঠিয়ে দেবে, তবে রেসপন্সে যথাযথ CORS হেডার যোগ করে দেবে।

## আরও তথ্য { #more-info }
