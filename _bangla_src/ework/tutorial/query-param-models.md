# কুয়েরি প্যারামিটার মডেল { #query-parameter-models }

/// note | এই পেজে যা শিখবেন

* সম্পর্কিত কয়েকটি কুয়েরি প্যারামিটারকে একটি Pydantic মডেলে একসাথে রাখা।
* একই মডেল একাধিক জায়গায় পুনরায় ব্যবহার করা।
* অপরিচিত বাড়তি কুয়েরি প্যারামিটার এলে কীভাবে নিষেধ করবেন।

///

আপনার যদি পরস্পর সম্পর্কিত একগুচ্ছ **কুয়েরি প্যারামিটার** থাকে, তাহলে সেগুলো ঘোষণা করতে একটি **Pydantic মডেল** তৈরি করতে পারেন।

এতে **মডেলটি** **একাধিক জায়গায়** **পুনরায় ব্যবহার** করতে পারবেন, আর সব প্যারামিটারের যাচাই ও মেটাডেটা একবারে ঘোষণা করতে পারবেন। 😎

যেমন, একটি অনলাইন দোকানের পণ্যের তালিকায় প্রায় সব পেজেই "কতগুলো দেখাব", "কোথা থেকে শুরু", "কীভাবে সাজাব" এমন একই ফিল্টার লাগে। প্রতিবার আলাদা করে না লিখে একটি মডেলে রেখে দিলেই হয়।

এটি FastAPI সংস্করণ `0.115.0` থেকে সাপোর্টেড। 🤓

## Pydantic মডেলসহ কুয়েরি প্যারামিটার { #query-parameters-with-a-pydantic-model }

আপনার প্রয়োজনীয় **কুয়েরি প্যারামিটারগুলো** একটি **Pydantic মডেলে** ঘোষণা করুন, তারপর প্যারামিটারটিকে `Query` হিসেবে ঘোষণা করুন:

{* ../../docs_src/query_param_models/tutorial001_an_py310.py hl[9:13,17] *}

**FastAPI** রিকোয়েস্টের **কুয়েরি প্যারামিটারগুলো** থেকে **প্রতিটি ফিল্ডের** ডেটা **বের করে** আপনার সংজ্ঞায়িত Pydantic মডেলটি দেবে।

/// info | কোডটি সহজ ভাষায়

* লাইন ৯: `FilterParams` নামে একটি মডেল, যাতে সব ফিল্টার একসাথে।
* লাইন ১০: `limit: int = Field(100, gt=0, le=100)`: কতগুলো আইটেম দেখাবে। ডিফল্ট ১০০, আর ১ থেকে ১০০-এর মধ্যে হতে হবে। `Field` দিয়ে মডেলের ভেতরে যাচাইয়ের নিয়ম দেওয়া হয়, ঠিক `Query`-র মতো।
* লাইন ১১: `offset`: কতগুলো বাদ দিয়ে শুরু করবে, ডিফল্ট ০, ঋণাত্মক হতে পারবে না।
* লাইন ১২: `order_by: Literal["created_at", "updated_at"]`: শুধু এই দুটি মানের একটি হতে পারবে। `Literal` মানে "হুবহু এই মানগুলোর একটি"।
* লাইন ১৩: `tags: list[str] = []`: একাধিক ট্যাগ, যেমন `?tags=a&tags=b`।
* লাইন ১৭: `Annotated[FilterParams, Query()]`: `Query()` না দিলে FastAPI মডেলটিকে বডি ভাবত। `Query()` বলে দেয় যে এগুলো কুয়েরি থেকে আসবে।

যেমন `/items/?limit=10&offset=20&order_by=updated_at&tags=book` পাঠালে `filter_query.limit` হবে `10`, `filter_query.tags` হবে `["book"]` ইত্যাদি।

## বাড়তি কুয়েরি প্যারামিটার নিষেধ করুন { #forbid-extra-query-parameters }

কিছু বিশেষ ক্ষেত্রে (সম্ভবত খুব প্রচলিত নয়), আপনি হয়তো যে কুয়েরি প্যারামিটারগুলো গ্রহণ করবেন সেগুলো **সীমিত** করতে চাইবেন।

যেকোনো `extra` (বাড়তি) ফিল্ড `forbid` (নিষেধ) করতে Pydantic-এর মডেল কনফিগারেশন ব্যবহার করতে পারেন:

{* ../../docs_src/query_param_models/tutorial002_an_py310.py hl[10] *}

লাইন ১০-এর `model_config = {"extra": "forbid"}` মানে "মডেলে যেসব ফিল্ড নেই, সেগুলো এলে গ্রহণ করবে না"।

কোনো ক্লায়েন্ট যদি **কুয়েরি প্যারামিটারে** কোনো **বাড়তি** ডেটা পাঠানোর চেষ্টা করে, তাহলে সে একটি **এরর** রেসপন্স পাবে।

যেমন, ক্লায়েন্ট যদি `plumbus` মানসহ একটি `tool` কুয়েরি প্যারামিটার পাঠানোর চেষ্টা করে, এভাবে:

```http
https://example.com/items/?limit=10&tool=plumbus
```

তাহলে সে একটি **এরর** রেসপন্স পাবে, যেখানে বলা থাকবে যে কুয়েরি প্যারামিটার `tool` অনুমোদিত নয়:

⟦CODE1⟧

এটি কাজে লাগে যখন ক্লায়েন্ট ভুল বানানে প্যারামিটার পাঠায় (যেমন `limt=10`)। নিষেধ না করলে সেটি চুপচাপ উপেক্ষা হতো, আর ক্লায়েন্ট বুঝতেই পারত না কেন ফিল্টার কাজ করছে না।

## সারাংশ { #summary }

**FastAPI**-তে **কুয়েরি প্যারামিটার** ঘোষণা করতে **Pydantic মডেল** ব্যবহার করতে পারেন। 😎

/// tip | পরামর্শ

আগাম জানিয়ে রাখি: কুকি আর হেডার ঘোষণা করতেও Pydantic মডেল ব্যবহার করা যায়, তবে সে বিষয়ে টিউটোরিয়ালে পরে পড়বেন। 🤫

/// check | সংক্ষেপে মনে রাখুন

* সম্পর্কিত কুয়েরি প্যারামিটারগুলো একটি `BaseModel` ক্লাসে রাখুন।
* ফাংশনে `Annotated[ModelName, Query()]` লিখুন, `Query()` অবশ্যই দিতে হবে।
* মডেলের ভেতরে যাচাইয়ের নিয়ম দিতে `Field(...)` ব্যবহার করুন।
* অজানা প্যারামিটার আটকাতে `model_config = {"extra": "forbid"}`।
