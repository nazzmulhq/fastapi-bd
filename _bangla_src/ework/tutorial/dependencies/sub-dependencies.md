# সাব-ডিপেন্ডেন্সি { #sub-dependencies }

/// note | এই পেজে যা শিখবেন

* ডিপেন্ডেন্সির ভেতরে আরেকটি ডিপেন্ডেন্সি (সাব-ডিপেন্ডেন্সি) ব্যবহার করা।
* একই ডিপেন্ডেন্সি একাধিক জায়গায় দরকার হলে FastAPI কেন এটি একবারই চালায় (ক্যাশ)।

///

এমন ডিপেন্ডেন্সি তৈরি করতে পারেন যাদের **সাব-ডিপেন্ডেন্সি** আছে।

এগুলো আপনার যত **গভীর** স্তরের দরকার তত গভীর হতে পারে।

**FastAPI** এগুলো সমাধানের দায়িত্ব নেবে।

এভাবে একটি প্রথম ডিপেন্ডেন্সি ("dependable") তৈরি করতে পারেন:

{* ../../docs_src/dependencies/tutorial005_an_py310.py hl[8:9] *}

এটি একটি ঐচ্ছিক কুয়েরি প্যারামিটার `q` একটি `str` হিসেবে ঘোষণা করে, তারপর শুধু সেটি ফেরত দেয়।

এটি বেশ সহজ (খুব একটা কাজের নয়), তবে সাব-ডিপেন্ডেন্সি কীভাবে কাজ করে তাতে মনোযোগ দিতে আমাদের সাহায্য করবে।

## দ্বিতীয় ডিপেন্ডেন্সি, "dependable" আর "dependant" দুটোই { #second-dependency-dependable-and-dependant }

তারপর আরেকটি ডিপেন্ডেন্সি ফাংশন (একটি "dependable") তৈরি করতে পারেন, যা একই সাথে নিজেরও একটি ডিপেন্ডেন্সি ঘোষণা করে (তাই এটি একটি "dependant"-ও):

{* ../../docs_src/dependencies/tutorial005_an_py310.py hl[13] *}

ঘোষিত প্যারামিটারগুলোতে মনোযোগ দেওয়া যাক:

* এই ফাংশনটি নিজে একটি ডিপেন্ডেন্সি ("dependable") হলেও এটি আরেকটি ডিপেন্ডেন্সি ঘোষণা করে (এটি অন্য কিছুর ওপর "নির্ভর" করে)।
    * এটি `query_extractor`-এর ওপর নির্ভর করে, আর এর ফেরত দেওয়া মান `q` প্যারামিটারে বসায়।
* এটি একটি ঐচ্ছিক `last_query` কুকিও `str` হিসেবে ঘোষণা করে।
    * ব্যবহারকারী কোনো কুয়েরি `q` না দিলে আমরা শেষবার ব্যবহৃত কুয়েরিটি ব্যবহার করি, যা আগে একটি কুকিতে সংরক্ষণ করে রেখেছিলাম।

## একই ডিপেন্ডেন্সি একাধিকবার ব্যবহার { #using-the-same-dependency-multiple-times }

আপনার কোনো ডিপেন্ডেন্সি যদি একই *পাথ অপারেশনের* জন্য একাধিকবার ঘোষণা করা থাকে, যেমন একাধিক ডিপেন্ডেন্সির একটি সাধারণ সাব-ডিপেন্ডেন্সি আছে, তাহলে **FastAPI** জানবে যে ওই সাব-ডিপেন্ডেন্সিটি প্রতি রিকোয়েস্টে কেবল একবারই ডাকতে হবে।

আর এটি ফেরত দেওয়া মানটি একটি <dfn title="গণনা করা/তৈরি করা মান সংরক্ষণের একটি ব্যবস্থা, যাতে আবার গণনা না করে পুনরায় ব্যবহার করা যায়।">"ক্যাশে"</dfn> সংরক্ষণ করবে, আর ওই নির্দিষ্ট রিকোয়েস্টে যেসব "dependant"-এর এটি দরকার সবাইকে সেটিই দেবে, একই রিকোয়েস্টের জন্য ডিপেন্ডেন্সিটি একাধিকবার না ডেকে।

যেমন "বর্তমান ইউজার খুঁজে বের করা" ডিপেন্ডেন্সিটি যদি তিন জায়গায় লাগে, ডেটাবেসে তিনবার খোঁজার দরকার নেই, একবার খুঁজেই তিন জায়গায় দেওয়া হয়।

একটি উন্নত পরিস্থিতিতে, যেখানে আপনি জানেন যে একই রিকোয়েস্টে "ক্যাশ" করা মান ব্যবহার না করে প্রতিটি ধাপে (হয়তো একাধিকবার) ডিপেন্ডেন্সিটি ডাকা দরকার, সেখানে `Depends` ব্যবহারের সময় `use_cache=False` প্যারামিটার সেট করতে পারেন:

//// tab | Python 3.10+

```Python hl_lines="1"
async def needy_dependency(fresh_value: Annotated[str, Depends(get_value, use_cache=False)]):
    return {"fresh_value": fresh_value}
```

////

//// tab | Python 3.10+ Annotated ছাড়া

/// tip | পরামর্শ

সম্ভব হলে `Annotated` সংস্করণটি ব্যবহার করুন।

///

```Python hl_lines="1"
async def needy_dependency(fresh_value: str = Depends(get_value, use_cache=False)):
    return {"fresh_value": fresh_value}
```

## সংক্ষেপে { #recap }

এখানে ব্যবহৃত সব জমকালো শব্দ বাদ দিলে, **ডিপেন্ডেন্সি ইনজেকশন** ব্যবস্থাটি বেশ সহজ।

শুধু কিছু ফাংশন, যেগুলো দেখতে *পাথ অপারেশন ফাংশনের* মতোই।

তবুও এটি খুবই শক্তিশালী, আর যত খুশি গভীর স্তরের নেস্টেড ডিপেন্ডেন্সি "গ্রাফ" (গাছ) ঘোষণা করতে দেয়।

/// tip | পরামর্শ

এই সহজ উদাহরণগুলো দেখে হয়তো এটা খুব কাজের মনে হচ্ছে না।

কিন্তু **সিকিউরিটি** নিয়ে অধ্যায়গুলোতে দেখবেন এটি কতটা কাজের।

আর এটি আপনার কতটা কোড বাঁচাবে তাও দেখবেন।

///

/// check | সংক্ষেপে মনে রাখুন

* একটি ডিপেন্ডেন্সি নিজের প্যারামিটারে `Depends(...)` দিয়ে আরেকটি ডিপেন্ডেন্সি চাইতে পারে।
* পাথ অপারেশনে শুধু শেষেরটি লিখলেই হয়, পুরো শিকল FastAPI নিজে চালায়।
* একই রিকোয়েস্টে একই ডিপেন্ডেন্সি একবারই চলে (ক্যাশ), প্রতিবার নতুন করে চালাতে `use_cache=False`।
