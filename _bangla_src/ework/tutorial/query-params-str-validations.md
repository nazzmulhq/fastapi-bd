# কুয়েরি প্যারামিটার ও স্ট্রিং ভ্যালিডেশন { #query-parameters-and-string-validations }

/// note | এই পেজে যা শিখবেন

* `Query` আর `Annotated` দিয়ে কুয়েরি প্যারামিটারে বাড়তি নিয়ম (যেমন সর্বোচ্চ দৈর্ঘ্য) যোগ করা।
* সর্বনিম্ন/সর্বোচ্চ দৈর্ঘ্য, রেগুলার এক্সপ্রেশন দিয়ে প্যাটার্ন মেলানো।
* আবশ্যক, ঐচ্ছিক আর একাধিক মানের (লিস্ট) কুয়েরি প্যারামিটার।
* শিরোনাম, বিবরণ, বিকল্প নাম (alias), deprecated চিহ্নিত করা আর ডকুমেন্টেশন থেকে লুকানো।
* নিজের বানানো যাচাই ফাংশন (`AfterValidator`)।

///

**FastAPI** আপনাকে প্যারামিটারগুলোর জন্য বাড়তি তথ্য আর যাচাইয়ের নিয়ম ঘোষণা করতে দেয়।

উদাহরণ হিসেবে এই অ্যাপ্লিকেশনটি নেওয়া যাক:

{* ../../docs_src/query_params_str_validations/tutorial001_py310.py hl[7] *}

কুয়েরি প্যারামিটার `q`-এর টাইপ `str | None`, মানে এটি `str` টাইপের কিন্তু `None`-ও হতে পারে। আর আসলেই এর ডিফল্ট মান `None`, তাই FastAPI জানবে এটি আবশ্যক নয়।

/// note | নোট

`= None` ডিফল্ট মানের কারণে FastAPI জানবে যে `q`-এর মান আবশ্যক নয়।

`str | None` থাকলে আপনার এডিটর আরও ভালো সাহায্য করতে আর ভুল ধরতে পারবে।

///

## বাড়তি যাচাই { #additional-validation }

আমরা একটি নিয়ম চাপাতে যাচ্ছি: `q` ঐচ্ছিক হলেও, যখনই দেওয়া হবে, **এর দৈর্ঘ্য ৫০ অক্ষরের বেশি হবে না**।

বাস্তবে এমন নিয়ম খুব কাজে লাগে। যেমন সার্চ বক্সে কেউ ১০ হাজার অক্ষর পাঠিয়ে আপনার ডেটাবেসকে চাপে ফেলতে না পারে।

এটি করতে প্রথমে ইমপোর্ট করুন:

* `fastapi` থেকে `Query`
* `typing` থেকে `Annotated`

আপনার কাছে পুরোনো সংস্করণ থাকলে `Annotated` ব্যবহার করতে গেলে এরর পাবেন।

`Annotated` ব্যবহারের আগে [FastAPI সংস্করণ আপগ্রেড করে](../deployment/versions.md#upgrading-the-fastapi-versions) অন্তত 0.95.1 করে নিন।

## `q` প্যারামিটারের টাইপে `Annotated` ব্যবহার করুন { #use-annotated-in-the-type-for-the-q-parameter }

মনে আছে, আগে [Python টাইপের পরিচিতি](../python-types.md#type-hints-with-metadata-annotations)-তে বলেছিলাম যে `Annotated` দিয়ে প্যারামিটারে মেটাডেটা (বাড়তি তথ্য) যোগ করা যায়?

এবার FastAPI-এর সাথে এটি ব্যবহারের সময়। 🚀

আমাদের এই টাইপ অ্যানোটেশনটি ছিল:

```Python
q: str | None = None
```

আমরা এটিকে `Annotated` দিয়ে মুড়ে দেব, ফলে হবে:

```Python
q: Annotated[str | None] = None
```

দুটো সংস্করণের মানে একই: `q` এমন একটি প্যারামিটার যা `str` বা `None` হতে পারে, আর ডিফল্টভাবে এটি `None`।

এবার মজার অংশে যাওয়া যাক। 🎉

## `q` প্যারামিটারের `Annotated`-এ `Query` যোগ করুন { #add-query-to-annotated-in-the-q-parameter }

এখন আমাদের এই `Annotated` আছে, যেখানে আরও তথ্য রাখা যায় (এই ক্ষেত্রে কিছু বাড়তি যাচাই)। তাই `Annotated`-এর ভেতরে `Query` যোগ করুন, আর `max_length` প্যারামিটারটি `50` সেট করুন:

{* ../../docs_src/query_params_str_validations/tutorial002_an_py310.py hl[9] *}

খেয়াল করুন, ডিফল্ট মান এখনো `None`, তাই প্যারামিটারটি এখনো ঐচ্ছিক।

কিন্তু এখন `Annotated`-এর ভেতরে `Query(max_length=50)` রেখে আমরা FastAPI-কে বলছি যে এই মানের জন্য **বাড়তি যাচাই** চাই, এটি সর্বোচ্চ ৫০ অক্ষরের হতে হবে। 😎

/// info | লাইনটি সহজ ভাষায়

`q: Annotated[str | None, Query(max_length=50)] = None`

এটিকে তিন ভাগে পড়ুন:

* `str | None`: আসল টাইপ, টেক্সট বা কিছুই না।
* `Query(max_length=50)`: FastAPI-এর জন্য বাড়তি তথ্য, "এটি একটি কুয়েরি প্যারামিটার, আর দৈর্ঘ্য সর্বোচ্চ ৫০"।
* `= None`: ডিফল্ট মান, তাই ঐচ্ছিক।

এখন কেউ `?q=` এর পরে ৫১ বা তার বেশি অক্ষর পাঠালে FastAPI নিজেই `422` এরর দেবে।

///

/// tip | পরামর্শ

এখানে আমরা `Query()` ব্যবহার করছি কারণ এটি একটি **কুয়েরি প্যারামিটার**। পরে আমরা `Path()`, `Body()`, `Header()` আর `Cookie()`-এর মতো আরও কিছু দেখব, যেগুলোও `Query()`-এর মতো একই আর্গুমেন্ট গ্রহণ করে।

///

FastAPI এখন:

* ডেটা **যাচাই** করবে, সর্বোচ্চ দৈর্ঘ্য যে ৫০ অক্ষর তা নিশ্চিত করবে
* ডেটা বৈধ না হলে ক্লায়েন্টকে একটি **পরিষ্কার এরর** দেখাবে
* OpenAPI স্কিমার *পাথ অপারেশনে* প্যারামিটারটির **ডকুমেন্টেশন** রাখবে (তাই এটি **স্বয়ংক্রিয় ডকুমেন্টেশন UI**-তে দেখা যাবে)

## বিকল্প (পুরোনো) উপায়: ডিফল্ট মান হিসেবে `Query` { #alternative-old-query-as-the-default-value }

FastAPI-এর আগের সংস্করণগুলোতে (<dfn title="২০২৩-০৩-এর আগে">0.95.0</dfn>-এর আগে) `Query`-কে `Annotated`-এর ভেতরে না রেখে প্যারামিটারের ডিফল্ট মান হিসেবে ব্যবহার করতে হতো। খুব সম্ভবত আশেপাশে এমন কোড দেখবেন, তাই এটা বুঝিয়ে দিচ্ছি।

/// tip | পরামর্শ

নতুন কোডে, যখনই সম্ভব, ওপরে বোঝানো `Annotated` ব্যবহার করুন। এর অনেকগুলো সুবিধা আছে (নিচে বলা হয়েছে), কোনো অসুবিধা নেই। 🍰

///

ফাংশন প্যারামিটারের ডিফল্ট মান হিসেবে `Query()` ব্যবহার করে `max_length` প্যারামিটার ৫০ সেট করা হয় এভাবে:

{* ../../docs_src/query_params_str_validations/tutorial002_py310.py hl[7] *}

যেহেতু এই ক্ষেত্রে (`Annotated` ছাড়া) ফাংশনের ডিফল্ট মান `None`-এর জায়গায় `Query()` বসাতে হয়, তাই ডিফল্ট মান এখন `Query(default=None)` প্যারামিটার দিয়ে সেট করতে হয়। এটি (অন্তত FastAPI-এর জন্য) ডিফল্ট মান নির্ধারণের একই কাজ করে।

তাই:

```Python
q: str | None = Query(default=None)
```

...প্যারামিটারটিকে ঐচ্ছিক করে, ডিফল্ট মান `None`, ঠিক যেমন:


```Python
q: str | None = None
```

তবে `Query` সংস্করণটি স্পষ্টভাবে এটিকে একটি কুয়েরি প্যারামিটার হিসেবে ঘোষণা করে।

তারপর আমরা `Query`-তে আরও প্যারামিটার দিতে পারি। এই ক্ষেত্রে `max_length` প্যারামিটার, যা স্ট্রিংয়ের ক্ষেত্রে প্রযোজ্য:

```Python
q: str | None = Query(default=None, max_length=50)
```

এটি ডেটা যাচাই করবে, ডেটা বৈধ না হলে পরিষ্কার এরর দেখাবে, আর OpenAPI স্কিমার *পাথ অপারেশনে* প্যারামিটারটির ডকুমেন্টেশন রাখবে।

### ডিফল্ট মান হিসেবে নাকি `Annotated`-এ `Query` { #query-as-the-default-value-or-in-annotated }

মনে রাখবেন, `Annotated`-এর ভেতরে `Query` ব্যবহার করলে `Query`-র `default` প্যারামিটার ব্যবহার করা যায় না।

এর বদলে ফাংশন প্যারামিটারের আসল ডিফল্ট মান ব্যবহার করুন। নইলে দুটো পরস্পরবিরোধী হবে।

যেমন এটা অনুমোদিত নয়:

```Python
q: Annotated[str, Query(default="rick")] = "morty"
```

...কারণ বোঝা যায় না ডিফল্ট মান `"rick"` হবে নাকি `"morty"`।

তাই আপনি (অগ্রাধিকার দিয়ে) লিখবেন:

```Python
q: Annotated[str, Query()] = "rick"
```

...অথবা পুরোনো কোডে দেখবেন:

```Python
q: str = Query(default="rick")
```

### `Annotated`-এর সুবিধা { #advantages-of-annotated }

ফাংশন প্যারামিটারে ডিফল্ট মানের বদলে **`Annotated` ব্যবহারের সুপারিশ করা হয়**, এটি অনেকগুলো কারণে **ভালো**। 🤓

**ফাংশন প্যারামিটারের** **ডিফল্ট** মানটিই **আসল ডিফল্ট** মান থাকে, যা সাধারণভাবে Python-এর সাথে বেশি স্বাভাবিক। 😌

ওই একই ফাংশন FastAPI ছাড়া **অন্য জায়গায়** **ডাকতে** পারবেন, আর সেটা **প্রত্যাশামতোই কাজ করবে**। কোনো **আবশ্যক** প্যারামিটার (ডিফল্ট ছাড়া) থাকলে আপনার **এডিটর** এরর দেখিয়ে জানাবে, আর আবশ্যক প্যারামিটার না দিয়ে চালালে **Python**-ও আপত্তি করবে।

`Annotated` ব্যবহার না করে **(পুরোনো) ডিফল্ট মানের ধরন** ব্যবহার করলে, ফাংশনটি FastAPI ছাড়া **অন্য জায়গায়** ডাকতে গেলে ঠিকমতো কাজ করাতে আর্গুমেন্টগুলো দিতে **মনে রাখতে** হবে। নইলে মানগুলো আপনার প্রত্যাশার চেয়ে আলাদা হবে (যেমন `str`-এর বদলে `QueryInfo` বা এরকম কিছু)। আর আপনার এডিটর আপত্তি করবে না, ফাংশন চালাতে Python-ও আপত্তি করবে না, শুধু ভেতরের কাজগুলোতে গিয়ে এরর হবে।

যেহেতু `Annotated`-এ একাধিক মেটাডেটা রাখা যায়, তাই এখন একই ফাংশন অন্য টুলের সাথেও ব্যবহার করতে পারবেন, যেমন [Typer](https://typer.tiangolo.com/)। 🚀

* `fixedquery`: হুবহু `fixedquery` মান।
* `$`: সেখানেই শেষ, `fixedquery`-এর পরে আর কোনো অক্ষর নেই।

**"রেগুলার এক্সপ্রেশন"**-এর এসব ধারণায় হারিয়ে গেছেন মনে হলে চিন্তা করবেন না। অনেকের কাছেই এটি কঠিন বিষয়। রেগুলার এক্সপ্রেশন ছাড়াও আপনি এখনো অনেক কাজ করতে পারবেন।

এখন শুধু জেনে রাখুন, যখনই দরকার হবে, **FastAPI**-তে এগুলো ব্যবহার করতে পারবেন।

/// tip | কয়েকটি কাজের রেগুলার এক্সপ্রেশন

* `^\d+$`: শুধু অঙ্ক, যেমন `12345`।
* `^[a-z0-9_]+$`: শুধু ছোট হাতের ইংরেজি অক্ষর, অঙ্ক আর আন্ডারস্কোর, যেমন ইউজারনেম।
* `^01[3-9]\d{8}$`: বাংলাদেশি মোবাইল নম্বর, যেমন `01712345678`।

## আবশ্যক প্যারামিটার { #required-parameters }

যখন আরও যাচাই বা মেটাডেটা ঘোষণার দরকার নেই, তখন শুধু ডিফল্ট মান না দিয়েই `q` কুয়েরি প্যারামিটারকে আবশ্যক করা যায়, এভাবে:

```Python
q: str
```

এটির বদলে:

```Python
q: str | None = None
```

কিন্তু এখন আমরা এটি `Query` দিয়ে ঘোষণা করছি, যেমন এভাবে:

```Python
q: Annotated[str | None, Query(min_length=3)] = None
```

তাই `Query` ব্যবহার করার সময় কোনো মান আবশ্যক ঘোষণা করতে চাইলে শুধু ডিফল্ট মান দেবেন না:

{* ../../docs_src/query_params_str_validations/tutorial006_an_py310.py hl[9] *}

### আবশ্যক, কিন্তু `None` হতে পারে { #required-can-be-none }

## কাস্টম যাচাই { #custom-validation }

এমন ক্ষেত্র থাকতে পারে যেখানে আপনার কিছু **কাস্টম যাচাই** দরকার, যা ওপরে দেখানো প্যারামিটারগুলো দিয়ে করা যায় না।

সেসব ক্ষেত্রে একটি **কাস্টম যাচাই ফাংশন** ব্যবহার করতে পারেন, যা সাধারণ যাচাইয়ের পরে (যেমন মানটি যে একটি `str` তা যাচাইয়ের পরে) প্রয়োগ হয়।

`Annotated`-এর ভেতরে [Pydantic-এর `AfterValidator`](https://pydantic.dev/docs/validation/latest/concepts/validators/#field-after-validator) ব্যবহার করে এটি করা যায়।

/// tip | পরামর্শ

Pydantic-এ [`BeforeValidator`](https://pydantic.dev/docs/validation/latest/concepts/validators/#field-before-validator) এবং আরও কিছু আছে। 🤓

///

যেমন, এই কাস্টম যাচাইকারী দেখে যে আইটেম ID একটি <abbr title="International Standard Book Number - আন্তর্জাতিক মান বই নম্বর">ISBN</abbr> বই নম্বরের জন্য `isbn-` দিয়ে, অথবা একটি <abbr title="Internet Movie Database: সিনেমার তথ্যসহ একটি ওয়েবসাইট">IMDB</abbr> সিনেমার URL ID-এর জন্য `imdb-` দিয়ে শুরু হয়েছে কিনা:

{* ../../docs_src/query_params_str_validations/tutorial015_an_py310.py hl[5,16:19,24] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ৫: Pydantic থেকে `AfterValidator` আনা হলো।
* লাইন ৯-১৩: `data` হলো কয়েকটি বই/সিনেমার একটি নকল ডেটাবেস (ID: নাম)।
* লাইন ১৬-১৯: `check_valid_id` হলো আমাদের নিজের যাচাই ফাংশন। ID যদি `isbn-` বা `imdb-` দিয়ে শুরু না হয়, তাহলে `ValueError` ছোড়ে। ঠিক থাকলে ID-টাই ফেরত দেয়।
* লাইন ২৪: `Annotated[str | None, AfterValidator(check_valid_id)]` মানে আগে সাধারণ যাচাই (টেক্সট কিনা), তারপর আমাদের ফাংশন দিয়ে যাচাই।
* লাইন ২৬-২৭: ID দেওয়া থাকলে ডেটাবেস থেকে নাম খোঁজা।
* লাইন ২৯: ID না দিলে এলোমেলোভাবে একটি বেছে নেওয়া।

`ValueError` ছোড়া হলে FastAPI সেটিকে ক্লায়েন্টের জন্য সুন্দর একটি `422` এররে রূপান্তর করে, আপনার বার্তাসহ।

### কোডটি বুঝে নিন { #understand-that-code }

#### `value.startswith()` দিয়ে স্ট্রিং { #string-with-value-startswith }

#### একটি এলোমেলো আইটেম { #a-random-item }

`data.items()` দিয়ে আমরা একটি <dfn title="এমন কিছু যার ওপর for লুপ চালানো যায়, যেমন একটি list, set ইত্যাদি।">ইটারেবল অবজেক্ট</dfn> পাই, যার প্রতিটি উপাদান হলো ডিকশনারির প্রতিটি আইটেমের কী আর মান নিয়ে একটি টাপল।

`list(data.items())` দিয়ে এই ইটারেবল অবজেক্টকে একটি সত্যিকারের `list`-এ রূপান্তর করি।

তারপর `random.choice()` দিয়ে লিস্ট থেকে একটি **এলোমেলো মান** পাই, অর্থাৎ `(id, name)` সহ একটি টাপল। এটি হবে এরকম কিছু: `("imdb-tt0371724", "The Hitchhiker's Guide to the Galaxy")`।

তারপর টাপলের **ওই দুটি মান** যথাক্রমে `id` আর `name` ভেরিয়েবলে **বসিয়ে দিই**।

তাই ব্যবহারকারী কোনো আইটেম ID না দিলেও একটি এলোমেলো সাজেশন পাবেন।

## সংক্ষেপে { #recap }

আপনার প্যারামিটারগুলোর জন্য বাড়তি যাচাই আর মেটাডেটা ঘোষণা করতে পারেন।

সাধারণ যাচাই ও মেটাডেটা:

* `alias`: URL-এ ব্যবহৃত বিকল্প নাম
* `title`: শিরোনাম
* `description`: বিবরণ
* `deprecated`: পুরোনো, ব্যবহার না করার পরামর্শ

স্ট্রিংয়ের জন্য নির্দিষ্ট যাচাই:

* `min_length`: সর্বনিম্ন দৈর্ঘ্য
* `max_length`: সর্বোচ্চ দৈর্ঘ্য
* `pattern`: রেগুলার এক্সপ্রেশন প্যাটার্ন

`AfterValidator` দিয়ে কাস্টম যাচাই।

এই উদাহরণগুলোতে আপনি দেখলেন কীভাবে `str` মানের জন্য যাচাই ঘোষণা করতে হয়।

সংখ্যার মতো অন্য টাইপের জন্য যাচাই কীভাবে ঘোষণা করবেন তা পরের অধ্যায়গুলোতে দেখুন।

/// check | সংক্ষেপে মনে রাখুন

* ধরনটি মনে রাখুন: `q: Annotated[টাইপ, Query(নিয়ম...)] = ডিফল্ট`।
* `= ডিফল্ট` থাকলে ঐচ্ছিক, না থাকলে আবশ্যক।
* দৈর্ঘ্য: `min_length`, `max_length`। প্যাটার্ন: `pattern`।
* একাধিক মান: `list[str]` টাইপ, আর অবশ্যই `Query()` ব্যবহার করতে হবে।
* নিজের নিয়ম: `AfterValidator(ফাংশন)`, ভুল হলে ফাংশনে `ValueError` ছুড়ুন।
* পুরোনো কোডে `q: str = Query(default=...)` দেখতে পারেন, নতুন কোডে `Annotated` ব্যবহার করুন।
