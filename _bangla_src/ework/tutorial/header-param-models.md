# হেডার প্যারামিটার মডেল { #header-parameter-models }

/// note | এই পেজে যা শিখবেন

* সম্পর্কিত কয়েকটি হেডার একটি Pydantic মডেলে একসাথে পড়া।
* অপরিচিত বাড়তি হেডার নিষেধ করা, আর আন্ডারস্কোর রূপান্তর বন্ধ করা।

///

আপনার যদি পরস্পর সম্পর্কিত একগুচ্ছ **হেডার প্যারামিটার** থাকে, তাহলে সেগুলো ঘোষণা করতে একটি **Pydantic মডেল** তৈরি করতে পারেন।

এতে **মডেলটি** **একাধিক জায়গায়** **পুনরায় ব্যবহার** করতে পারবেন, আর সব প্যারামিটারের যাচাই ও মেটাডেটা একবারে ঘোষণা করতে পারবেন। 😎

/// note | নোট

এটি FastAPI সংস্করণ `0.115.0` থেকে সাপোর্টেড। 🤓

## Pydantic মডেলসহ হেডার প্যারামিটার { #header-parameters-with-a-pydantic-model }

আপনার প্রয়োজনীয় **হেডার প্যারামিটারগুলো** একটি **Pydantic মডেলে** ঘোষণা করুন, তারপর প্যারামিটারটিকে `Header` হিসেবে ঘোষণা করুন:

{* ../../docs_src/header_param_models/tutorial001_an_py310.py hl[9:14,18] *}

**FastAPI** রিকোয়েস্টের **হেডারগুলো** থেকে **প্রতিটি ফিল্ডের** ডেটা **বের করে** আপনার সংজ্ঞায়িত Pydantic মডেলটি দেবে।

/// info | কোডটি সহজ ভাষায়

* `host`: কোন ডোমেইনে রিকোয়েস্ট এসেছে, আবশ্যক।
* `save_data`: ব্রাউজার ডেটা সাশ্রয় মোডে আছে কিনা (`Save-Data` হেডার), আবশ্যক, `bool`।
* `if_modified_since`, `traceparent`: ঐচ্ছিক। (`traceparent` সাধারণত রিকোয়েস্ট ট্র্যাক করার টুলগুলো পাঠায়।)
* `x_tag: list[str]`: `X-Tag` হেডার একাধিকবার আসতে পারে।
* মডেলের ফিল্ডেও `_` স্বয়ংক্রিয়ভাবে `-` হয়ে যায়, যেমন `save_data` হয়ে যায় `save-data`।

## বাড়তি হেডার নিষেধ করুন { #forbid-extra-headers }

কিছু বিশেষ ক্ষেত্রে (সম্ভবত খুব প্রচলিত নয়), আপনি হয়তো যে হেডারগুলো গ্রহণ করবেন সেগুলো **সীমিত** করতে চাইবেন।

যেকোনো `extra` (বাড়তি) ফিল্ড `forbid` (নিষেধ) করতে Pydantic-এর মডেল কনফিগারেশন ব্যবহার করতে পারেন:

{* ../../docs_src/header_param_models/tutorial002_an_py310.py hl[10] *}

কোনো ক্লায়েন্ট যদি কিছু **বাড়তি হেডার** পাঠানোর চেষ্টা করে, তাহলে সে একটি **এরর** রেসপন্স পাবে।

যেমন, ক্লায়েন্ট যদি `plumbus` মানসহ একটি `tool` হেডার পাঠানোর চেষ্টা করে, তাহলে সে একটি **এরর** রেসপন্স পাবে, যেখানে বলা থাকবে যে হেডার প্যারামিটার `tool` অনুমোদিত নয়:

## আন্ডারস্কোর রূপান্তর বন্ধ করুন { #disable-convert-underscores }

সাধারণ হেডার প্যারামিটারের মতোই, প্যারামিটারের নামে আন্ডারস্কোর অক্ষর থাকলে সেগুলো **স্বয়ংক্রিয়ভাবে হাইফেনে রূপান্তরিত** হয়।

যেমন, কোডে যদি `save_data` নামে একটি হেডার প্যারামিটার থাকে, তাহলে প্রত্যাশিত HTTP হেডার হবে `save-data`, আর ডকুমেন্টেশনেও এভাবেই দেখাবে।

কোনো কারণে এই স্বয়ংক্রিয় রূপান্তর বন্ধ করতে চাইলে, হেডার প্যারামিটারের Pydantic মডেলের ক্ষেত্রেও সেটি করতে পারেন।

{* ../../docs_src/header_param_models/tutorial003_an_py310.py hl[19] *}

/// warning | সতর্কতা

`convert_underscores`-কে `False` সেট করার আগে মনে রাখুন, কিছু HTTP প্রক্সি ও সার্ভার আন্ডারস্কোরসহ হেডার ব্যবহারের অনুমতি দেয় না।

## সারাংশ { #summary }

**FastAPI**-তে **হেডার** ঘোষণা করতে **Pydantic মডেল** ব্যবহার করতে পারেন। 😎

/// check | সংক্ষেপে মনে রাখুন

* কয়েকটি হেডার একসাথে: একটি মডেল বানিয়ে `Annotated[ModelName, Header()]`।
* মডেলের ফিল্ডের `_` হেডারে `-` হয়ে যায়, বন্ধ করতে `Header(convert_underscores=False)`।
* অজানা হেডার আটকাতে `model_config = {"extra": "forbid"}`, তবে সাবধানে।
