# বডি - হালনাগাদ (আপডেট) { #body-updates }

/// note | এই পেজে যা শিখবেন

* `PUT` দিয়ে পুরো ডেটা প্রতিস্থাপন, আর এর একটি লুকানো ফাঁদ।
* `PATCH` দিয়ে শুধু পরিবর্তিত অংশটুকু হালনাগাদ (আংশিক আপডেট)।
* `exclude_unset` আর `model_copy(update=...)` এর ব্যবহার।

///

## `PUT` দিয়ে প্রতিস্থাপন করে আপডেট { #update-replacing-with-put }

একটি আইটেম আপডেট করতে [HTTP `PUT`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/PUT) অপারেশন ব্যবহার করতে পারেন।

ইনপুট ডেটাকে JSON হিসেবে সংরক্ষণযোগ্য ডেটায় (যেমন একটি NoSQL ডেটাবেসে) রূপান্তর করতে `jsonable_encoder` ব্যবহার করতে পারেন। যেমন `datetime`-কে `str`-এ রূপান্তর।

`PUT` এমন ডেটা গ্রহণ করতে ব্যবহার হয়, যা বিদ্যমান ডেটাকে প্রতিস্থাপন করবে।

আর ডেটা সেই "নতুন" `tax` `10.5` দিয়েই সংরক্ষিত হবে।

/// warning | ফাঁদটি সহজ ভাষায়

আপনি শুধু নাম আর দাম বদলাতে চেয়েছিলেন, করের কথা কিছু বলেননি। কিন্তু `PUT` মানে "পুরোটা বদলে দাও", তাই যা পাঠাননি তা ডিফল্ট মানে ফিরে গেল। আগের কর ২০.২ হারিয়ে ১০.৫ হয়ে গেল, কেউ টেরও পেল না। এটা এড়াতেই `PATCH` ব্যবহার করা হয়।

///

## `PATCH` দিয়ে আংশিক আপডেট { #partial-updates-with-patch }

ডেটা *আংশিকভাবে* আপডেট করতে [HTTP `PATCH`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/PATCH) অপারেশনও ব্যবহার করতে পারেন।

এর মানে, আপনি শুধু যে ডেটা আপডেট করতে চান সেটুকু পাঠাতে পারেন, বাকিটা অক্ষত থাকবে।

/// note | নোট

`PATCH` তুলনামূলকভাবে `PUT`-এর চেয়ে কম ব্যবহৃত ও কম পরিচিত।

আর অনেক টিম আংশিক আপডেটের জন্যও শুধু `PUT` ব্যবহার করে।

আপনি এগুলো যেভাবে খুশি ব্যবহার করতে **স্বাধীন**, **FastAPI** কোনো বাধা দেয় না।

তবে এই গাইড মোটামুটি দেখায় এগুলো কীভাবে ব্যবহারের উদ্দেশ্যে তৈরি।

///

### Pydantic-এর `exclude_unset` প্যারামিটার ব্যবহার { #using-pydantics-exclude-unset-parameter }

আংশিক আপডেট গ্রহণ করতে চাইলে Pydantic মডেলের `.model_dump()`-এ `exclude_unset` প্যারামিটার ব্যবহার করা খুব কাজের।

যেমন `item.model_dump(exclude_unset=True)`।

এটি এমন একটি `dict` তৈরি করবে, যাতে শুধু `item` মডেল তৈরির সময় সেট করা ডেটা থাকবে, ডিফল্ট মানগুলো বাদ দিয়ে।

তারপর এটি দিয়ে এমন একটি `dict` তৈরি করতে পারেন, যাতে শুধু সেট করা (রিকোয়েস্টে পাঠানো) ডেটা থাকে, ডিফল্ট মান বাদ দিয়ে:

### আংশিক আপডেট সংক্ষেপে { #partial-updates-recap }

সংক্ষেপে, আংশিক আপডেট প্রয়োগ করতে আপনি:

* (ঐচ্ছিকভাবে) `PUT`-এর বদলে `PATCH` ব্যবহার করবেন।
* সংরক্ষিত ডেটা বের করবেন।
* সেই ডেটা একটি Pydantic মডেলে রাখবেন।
* ইনপুট মডেল থেকে ডিফল্ট মান ছাড়া একটি `dict` তৈরি করবেন (`exclude_unset` ব্যবহার করে)।
    * এতে আপনার মডেলের ডিফল্ট মান দিয়ে আগে থেকে সংরক্ষিত মানগুলো মুছে না দিয়ে, শুধু ব্যবহারকারীর আসলে সেট করা মানগুলোই আপডেট করতে পারবেন।
* সংরক্ষিত মডেলের একটি কপি তৈরি করবেন, পাওয়া আংশিক আপডেট দিয়ে এর অ্যাট্রিবিউটগুলো হালনাগাদ করে (`update` প্যারামিটার ব্যবহার করে)।
* কপি করা মডেলটিকে আপনার ডেটাবেসে রাখার উপযোগী কিছুতে রূপান্তর করবেন (যেমন `jsonable_encoder` ব্যবহার করে)।
    * এটি আবার মডেলের `.model_dump()` মেথড ব্যবহার করার মতোই, তবে এটি নিশ্চিত করে (আর রূপান্তর করে) যে মানগুলো JSON-এ রূপান্তরযোগ্য ডেটা টাইপে আছে, যেমন `datetime` থেকে `str`।
* ডেটা আপনার ডেটাবেসে সংরক্ষণ করবেন।
* আপডেট করা মডেলটি ফেরত দেবেন।

/// info | কোডটি সহজ ভাষায় (লাইন ২৮-৩৫)

* লাইন ২৮: `@app.patch(...)`: আংশিক আপডেট।
* লাইন ৩০: ডেটাবেস থেকে আগের ডেটা আনা।
* লাইন ৩১: সেটি দিয়ে একটি `Item` মডেল বানানো।
* লাইন ৩২: ক্লায়েন্ট যা পাঠিয়েছে শুধু সেটুকু নেওয়া (`exclude_unset=True`)।
* লাইন ৩৩: পুরোনো মডেলের কপি, শুধু পাঠানো ফিল্ডগুলো বদলে।
* লাইন ৩৪: JSON-উপযোগী করে ডেটাবেসে রাখা।
* লাইন ৩৫: নতুন আইটেম ফেরত দেওয়া।

এখন `bar`-এ শুধু `{"price": 99}` পাঠালে দাম বদলাবে, কর `20.2`-ই থাকবে।

/// tip | পরামর্শ

আসলে একটি HTTP `PUT` অপারেশনেও এই একই কৌশল ব্যবহার করতে পারেন।

তবে এখানকার উদাহরণে `PATCH` ব্যবহার করা হয়েছে, কারণ এটি এমন ক্ষেত্রের জন্যই তৈরি।

/// note | নোট

খেয়াল করুন, ইনপুট মডেলটি তবুও যাচাই করা হয়।

তাই আপনি যদি এমন আংশিক আপডেট গ্রহণ করতে চান যেখানে সব অ্যাট্রিবিউটই বাদ দেওয়া যায়, তাহলে এমন একটি মডেল লাগবে যার সব অ্যাট্রিবিউট ঐচ্ছিক হিসেবে চিহ্নিত (ডিফল্ট মান বা `None`-সহ)। এই উদাহরণের `Item` মডেলে তাই সবকিছুর ডিফল্ট আছে।

**আপডেটের** জন্য সব ঐচ্ছিক মানসহ মডেল আর **তৈরির** জন্য আবশ্যক মানসহ মডেল আলাদা করতে [বাড়তি মডেল](extra-models.md)-এ বর্ণিত ধারণাগুলো ব্যবহার করতে পারেন।

/// check | সংক্ষেপে মনে রাখুন

* `PUT` = পুরোটা প্রতিস্থাপন, না পাঠানো ফিল্ড ডিফল্টে ফিরে যায়।
* `PATCH` = শুধু পাঠানো ফিল্ড বদলায়।
* আংশিক আপডেটের ধাপ: পুরোনো ডেটা আনুন → `item.model_dump(exclude_unset=True)` → `old.model_copy(update=...)` → সংরক্ষণ।
* আপডেট মডেলের সব ফিল্ড ঐচ্ছিক রাখুন।
