# বর্তমান ইউজার পাওয়া { #get-current-user }

/// note | এই পেজে যা শিখবেন

* টোকেন থেকে বর্তমান (লগইন করা) ইউজার বের করার একটি ডিপেন্ডেন্সি বানানো।
* পাথ অপারেশনে সরাসরি `current_user` পাওয়া।
* কেন সিকিউরিটির কোড একবার লিখে হাজারটা পাথ অপারেশনে ব্যবহার করা যায়।

///

কিন্তু এটা এখনো তেমন কাজের নয়। টোকেন একটি দুর্বোধ্য স্ট্রিং মাত্র, আমাদের জানা দরকার এটি কোন ইউজারের।

চলুন এটিকে দিয়ে আমাদের বর্তমান ইউজারটি পাই।

## একটি `get_current_user` ডিপেন্ডেন্সি তৈরি করুন { #create-a-get-current-user-dependency }

`get_current_user` নামে একটি ডিপেন্ডেন্সি তৈরি করা যাক।

মনে আছে, ডিপেন্ডেন্সির সাব-ডিপেন্ডেন্সি থাকতে পারে?

`get_current_user`-এর একটি ডিপেন্ডেন্সি থাকবে, আগে তৈরি করা সেই একই `oauth2_scheme`।

আগে যেমন সরাসরি *পাথ অপারেশনে* করছিলাম, ঠিক তেমনই আমাদের নতুন ডিপেন্ডেন্সি `get_current_user` সাব-ডিপেন্ডেন্সি `oauth2_scheme` থেকে একটি `str` হিসেবে একটি `token` পাবে:

{* ../../docs_src/security/tutorial002_an_py310.py hl[31] *}

খেয়াল করুন, আমরা `current_user`-এর টাইপ Pydantic মডেল `User` হিসেবে ঘোষণা করছি।

এতে ফাংশনের ভেতরে সব কমপ্লিশন আর টাইপ যাচাইয়ে সাহায্য পাব।

/// info | শিকলটি সহজ ভাষায়

`read_users_me` → চায় `get_current_user` → যা চায় `oauth2_scheme` → যা রিকোয়েস্টের `Authorization` হেডার থেকে টোকেন বের করে।

পাথ অপারেশনে শুধু `current_user` চাইলেন, আর পুরো শিকলটা FastAPI নিজে চালিয়ে আপনাকে একটি `User` অবজেক্ট দিল।

///

/// tip | পরামর্শ

আপনার হয়তো মনে আছে যে রিকোয়েস্ট বডিও Pydantic মডেল দিয়ে ঘোষণা করা হয়।

এখানে **FastAPI** বিভ্রান্ত হবে না, কারণ আপনি `Depends` ব্যবহার করছেন।

///

/// tip | পরামর্শ

এই ডিপেন্ডেন্সি ব্যবস্থা যেভাবে ডিজাইন করা, তাতে আমরা এমন বিভিন্ন ডিপেন্ডেন্সি (বিভিন্ন "dependable") রাখতে পারি, যারা সবাই একটি `User` মডেল ফেরত দেয়।

ওই ধরনের ডেটা ফেরত দিতে পারে এমন কেবল একটি ডিপেন্ডেন্সি রাখতে আমরা বাধ্য নই।

///

## অন্যান্য মডেল { #other-models }

এখন আপনি সরাসরি *পাথ অপারেশন ফাংশনে* বর্তমান ইউজার পেতে পারেন, আর `Depends` ব্যবহার করে **ডিপেন্ডেন্সি ইনজেকশন** স্তরে সিকিউরিটি ব্যবস্থা সামলাতে পারেন।

আর সিকিউরিটির প্রয়োজনের জন্য যেকোনো মডেল বা ডেটা ব্যবহার করতে পারেন (এই ক্ষেত্রে একটি Pydantic মডেল `User`)।

কিন্তু কোনো নির্দিষ্ট ডেটা মডেল, ক্লাস বা টাইপ ব্যবহার করতে আপনি বাধ্য নন।

আপনার মডেলে `username` না রেখে একটি `id` আর `email` রাখতে চান? অবশ্যই। এই একই টুলগুলো ব্যবহার করতে পারেন।

শুধু একটি `str` রাখতে চান? বা শুধু একটি `dict`? বা সরাসরি একটি ডেটাবেস ক্লাস মডেলের ইনস্ট্যান্স? সবই একইভাবে কাজ করে।

আপনার অ্যাপ্লিকেশনে আসলে মানুষ লগইন করে না, বরং রোবট, বট বা অন্য সিস্টেম, যাদের শুধু একটি অ্যাক্সেস টোকেন আছে? আবারও, সব একইভাবে কাজ করে।

আপনার অ্যাপ্লিকেশনের জন্য যে ধরনের মডেল, যে ধরনের ক্লাস, যে ধরনের ডেটাবেস দরকার, সেটিই ব্যবহার করুন। ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা দিয়ে **FastAPI** আপনাকে সাহায্য করবে।

## কোডের আকার { #code-size }

এই উদাহরণটি হয়তো লম্বা মনে হতে পারে। মনে রাখবেন, আমরা একই ফাইলে সিকিউরিটি, ডেটা মডেল, সহায়ক ফাংশন আর *পাথ অপারেশন* মেশাচ্ছি।

কিন্তু মূল কথাটি এখানে।

সিকিউরিটি আর ডিপেন্ডেন্সি ইনজেকশনের অংশটুকু একবারই লেখা হয়।

আর আপনি এটিকে যত খুশি জটিল করতে পারেন। তবুও এটি থাকবে একবারই লেখা, এক জায়গায়। সব নমনীয়তাসহ।

কিন্তু হাজার হাজার এন্ডপয়েন্ট (*পাথ অপারেশন*) একই সিকিউরিটি ব্যবস্থা ব্যবহার করতে পারে।

আর এদের সবাই (বা আপনি যতগুলো চান) এই ডিপেন্ডেন্সিগুলো বা আপনার তৈরি অন্য যেকোনো ডিপেন্ডেন্সি পুনরায় ব্যবহারের সুবিধা নিতে পারে।

আর এই হাজার হাজার *পাথ অপারেশনের* প্রতিটি মাত্র ৩ লাইনের হতে পারে:

## সংক্ষেপে { #recap }

এখন আপনি সরাসরি আপনার *পাথ অপারেশন ফাংশনে* বর্তমান ইউজার পেতে পারেন।

আমরা ইতিমধ্যে অর্ধেক পথ চলে এসেছি।

শুধু একটি *পাথ অপারেশন* যোগ করতে হবে, যেখানে ইউজার/ক্লায়েন্ট আসলে `username` আর `password` পাঠাবে।

সেটি পরের অধ্যায়ে।

/// check | সংক্ষেপে মনে রাখুন

* `get_current_user` ডিপেন্ডেন্সি টোকেন নিয়ে ইউজার ফেরত দেয়।
* যেকোনো পাথ অপারেশনে `current_user: Annotated[User, Depends(get_current_user)]` লিখলেই লগইন করা ইউজার পাওয়া যায়।
* সিকিউরিটির কোড এক জায়গায় লেখা, ব্যবহার সবখানে।
