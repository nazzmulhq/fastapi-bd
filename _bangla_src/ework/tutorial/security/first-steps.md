# সিকিউরিটি - প্রথম ধাপ { #security-first-steps }

/// note | এই পেজে যা শিখবেন

* মাত্র কয়েক লাইনে API-তে প্রাথমিক সিকিউরিটি যোগ করা।
* `/docs`-এর "Authorize" বাটন কোথা থেকে আসে।
* OAuth2 "password flow" ধাপে ধাপে কীভাবে কাজ করে।
* টোকেন আর `Authorization: Bearer ...` হেডার কী।
* `OAuth2PasswordBearer` কী করে।

///

ধরা যাক আপনার **ব্যাকএন্ড** API কোনো একটি ডোমেইনে আছে। (ব্যাকএন্ড মানে সার্ভারের দিকের অংশ, যেখানে ডেটা আর লজিক থাকে।)

আর আপনার একটি **ফ্রন্টএন্ড** আছে অন্য একটি ডোমেইনে, বা একই ডোমেইনের ভিন্ন পাথে (বা একটি মোবাইল অ্যাপ্লিকেশনে)। (ফ্রন্টএন্ড মানে ব্যবহারকারী যা দেখে আর ব্যবহার করে, যেমন ওয়েবসাইট বা অ্যাপ।)

আর আপনি চান ফ্রন্টএন্ড যেন একটি **ইউজারনেম** আর **পাসওয়ার্ড** ব্যবহার করে ব্যাকএন্ডের কাছে নিজের পরিচয় প্রমাণ (অথেনটিকেট) করতে পারে।

**FastAPI**-তে এটি বানাতে **OAuth2** ব্যবহার করতে পারি।

তবে আপনার দরকারি ছোট ছোট তথ্যগুলো খুঁজতে পুরো লম্বা স্পেসিফিকেশন পড়ার সময়টা আপনাকে বাঁচিয়ে দেওয়া যাক।

সিকিউরিটি সামলাতে **FastAPI**-এর দেওয়া টুলগুলো ব্যবহার করা যাক।

আর আপনি নিজেও একই অ্যাপ্লিকেশন ডিবাগ, যাচাই আর পরীক্ষা করতে এটি ব্যবহার করতে পারেন।

## `password` flow { #the-password-flow }

এবার একটু পিছিয়ে গিয়ে বুঝে নেওয়া যাক এসব কী।

`password` "flow" হলো সিকিউরিটি আর অথেনটিকেশন সামলাতে OAuth2-এ সংজ্ঞায়িত উপায়গুলোর ("flow") একটি।

OAuth2 এমনভাবে ডিজাইন করা হয়েছিল যাতে ব্যাকএন্ড বা API, ব্যবহারকারীকে অথেনটিকেট করা সার্ভার থেকে স্বাধীন থাকতে পারে।

কিন্তু এই ক্ষেত্রে একই **FastAPI** অ্যাপ্লিকেশন API আর অথেনটিকেশন দুটোই সামলাবে।

তাই সেই সরলীকৃত দৃষ্টিকোণ থেকে দেখা যাক:

* ব্যবহারকারী ফ্রন্টএন্ডে `username` আর `password` লিখে `Enter` চাপে।
* ফ্রন্টএন্ড (ব্যবহারকারীর ব্রাউজারে চলছে) সেই `username` আর `password` আমাদের API-এর একটি নির্দিষ্ট URL-এ পাঠায় (`tokenUrl="token"` দিয়ে ঘোষিত)।
* API সেই `username` আর `password` যাচাই করে, আর একটি "টোকেন" দিয়ে উত্তর দেয় (এর কিছুই আমরা এখনো ইমপ্লিমেন্ট করিনি)।
    * একটি "টোকেন" শুধু কিছু বিষয়বস্তুসহ একটি স্ট্রিং, যা পরে এই ব্যবহারকারীকে যাচাই করতে ব্যবহার করতে পারি।
    * সাধারণত একটি টোকেন কিছু সময় পরে মেয়াদোত্তীর্ণ হওয়ার জন্য সেট করা থাকে।
        * তাই ব্যবহারকারীকে পরে কোনো এক সময় আবার লগইন করতে হবে।
        * আর টোকেন চুরি হলেও ঝুঁকি কম। এটি একটি স্থায়ী চাবির মতো নয় যা চিরকাল কাজ করবে (বেশিরভাগ ক্ষেত্রে)।
* ফ্রন্টএন্ড সেই টোকেনটি কোথাও অস্থায়ীভাবে সংরক্ষণ করে।
* ব্যবহারকারী ফ্রন্টএন্ড ওয়েব অ্যাপের আরেকটি অংশে যেতে ক্লিক করে।
* ফ্রন্টএন্ডকে API থেকে আরও কিছু ডেটা আনতে হয়।
    * কিন্তু সেই নির্দিষ্ট এন্ডপয়েন্টের জন্য অথেনটিকেশন দরকার।
    * তাই আমাদের API-এর সাথে অথেনটিকেট করতে এটি `Authorization` নামে একটি হেডার পাঠায়, যার মান `Bearer ` আর তার পরে টোকেন।
    * টোকেনে যদি `foobar` থাকে, তাহলে `Authorization` হেডারের বিষয়বস্তু হবে: `Bearer foobar`।

/// tip | উদাহরণ দিয়ে বুঝি

একটি অনুষ্ঠানে ঢোকার কথা ভাবুন:

1. গেটে আইডি কার্ড দেখালেন (ইউজারনেম-পাসওয়ার্ড)।
2. তারা যাচাই করে হাতে একটি রিস্টব্যান্ড পরিয়ে দিল (টোকেন)।
3. এরপর প্রতিটি স্টলে আর আইডি কার্ড দেখাতে হয় না, শুধু রিস্টব্যান্ড দেখালেই হয় (`Authorization: Bearer <টোকেন>`)।
4. দিন শেষে রিস্টব্যান্ড অকেজো হয়ে যায় (টোকেনের মেয়াদ শেষ)।

"Bearer" মানে "বহনকারী", অর্থাৎ যার কাছে টোকেন আছে সে-ই ঢুকতে পারবে। তাই টোকেন গোপন রাখতে হয়।

///

## **FastAPI**-এর `OAuth2PasswordBearer` { #fastapis-oauth2passwordbearer }

এই সিকিউরিটি ফিচারগুলো ইমপ্লিমেন্ট করতে **FastAPI** বিভিন্ন স্তরের বেশ কয়েকটি টুল দেয়।

এই উদাহরণে আমরা **OAuth2** ব্যবহার করব, **Password** flow-সহ, একটি **Bearer** টোকেন ব্যবহার করে। এটি করি `OAuth2PasswordBearer` ক্লাস দিয়ে।

/// note | নোট

একটি "bearer" টোকেনই একমাত্র উপায় নয়।

তবে আমাদের ব্যবহারের ক্ষেত্রের জন্য এটিই সবচেয়ে ভালো।

আর বেশিরভাগ ক্ষেত্রেই হয়তো এটি সবচেয়ে ভালো, যদি না আপনি একজন OAuth2 বিশেষজ্ঞ হন এবং ঠিক জানেন কেন আপনার প্রয়োজনের জন্য আরেকটি উপায় বেশি উপযুক্ত।

সেক্ষেত্রেও **FastAPI** আপনাকে সেটি বানানোর টুল দেয়।

///

`OAuth2PasswordBearer` ক্লাসের একটি ইনস্ট্যান্স তৈরি করার সময় আমরা `tokenUrl` প্যারামিটারটি দিই। এই প্যারামিটারে সেই URL থাকে, যা ক্লায়েন্ট (ব্যবহারকারীর ব্রাউজারে চলা ফ্রন্টএন্ড) একটি টোকেন পেতে `username` আর `password` পাঠাতে ব্যবহার করবে।

{* ../../docs_src/security/tutorial001_an_py310.py hl[8] *}

/// tip | পরামর্শ

এখানে `tokenUrl="token"` একটি আপেক্ষিক (relative) URL `token`-কে বোঝায়, যা আমরা এখনো তৈরি করিনি। যেহেতু এটি একটি আপেক্ষিক URL, তাই এটি `./token`-এর সমতুল্য।

যেহেতু আমরা একটি আপেক্ষিক URL ব্যবহার করছি, তাই আপনার API যদি `https://example.com/`-এ থাকত, তাহলে এটি বোঝাত `https://example.com/token`। কিন্তু আপনার API যদি `https://example.com/api/v1/`-এ থাকত, তাহলে এটি বোঝাত `https://example.com/api/v1/token`।

একটি আপেক্ষিক URL ব্যবহার করা জরুরি, যাতে [প্রক্সির পেছনে](../../advanced/behind-a-proxy.md) এর মতো উন্নত ক্ষেত্রেও আপনার অ্যাপ্লিকেশন কাজ করতে থাকে।

///

এই প্যারামিটার ওই এন্ডপয়েন্ট / *পাথ অপারেশন* তৈরি করে না, শুধু ঘোষণা করে যে টোকেন পেতে ক্লায়েন্টকে `/token` URL-টিই ব্যবহার করতে হবে। সেই তথ্য OpenAPI-তে, আর তারপর ইন্টারঅ্যাকটিভ API ডকুমেন্টেশন সিস্টেমে ব্যবহার হয়।

আসল পাথ অপারেশনটিও আমরা শিগগিরই তৈরি করব।

/// note | নোট

আপনি যদি খুব কঠোর "Pythonista" (Python-এর নিয়ম কঠোরভাবে মানা মানুষ) হন, তাহলে হয়তো `token_url`-এর বদলে প্যারামিটারের নাম `tokenUrl`-এর ধরন আপনার অপছন্দ হতে পারে।

এর কারণ এটি OpenAPI স্পেসিফিকেশনের একই নাম ব্যবহার করছে। যাতে এই সিকিউরিটি স্কিমগুলোর কোনোটি নিয়ে আরও খুঁজতে হলে আপনি শুধু কপি-পেস্ট করে আরও তথ্য খুঁজে পান।

`oauth2_scheme` ভেরিয়েবলটি `OAuth2PasswordBearer`-এর একটি ইনস্ট্যান্স, কিন্তু এটি একটি "callable"-ও।

এটিকে এভাবে ডাকা যেতে পারে:

```Python
oauth2_scheme(some, parameters)
```

তাই এটি `Depends`-এর সাথে ব্যবহার করা যায়।

### এটি ব্যবহার করুন { #use-it }

এবার `Depends` দিয়ে একটি ডিপেন্ডেন্সিতে সেই `oauth2_scheme` দিতে পারেন।

{* ../../docs_src/security/tutorial001_an_py310.py hl[12] *}

এই ডিপেন্ডেন্সি একটি `str` দেবে, যা *পাথ অপারেশন ফাংশনের* `token` প্যারামিটারে বসানো হয়।

**FastAPI** জানবে যে OpenAPI স্কিমাতে (আর স্বয়ংক্রিয় API ডকুমেন্টেশনে) একটি "সিকিউরিটি স্কিম" সংজ্ঞায়িত করতে এটি এই ডিপেন্ডেন্সি ব্যবহার করতে পারে।

/// note | কারিগরি বিবরণ

**FastAPI** জানবে যে OpenAPI-তে সিকিউরিটি স্কিম সংজ্ঞায়িত করতে এটি `OAuth2PasswordBearer` ক্লাস (একটি ডিপেন্ডেন্সিতে ঘোষিত) ব্যবহার করতে পারে, কারণ এটি `fastapi.security.oauth2.OAuth2` থেকে ইনহেরিট করে, যা আবার `fastapi.security.base.SecurityBase` থেকে ইনহেরিট করে।

OpenAPI-এর (আর স্বয়ংক্রিয় API ডকুমেন্টেশনের) সাথে একীভূত হওয়া সব সিকিউরিটি টুল `SecurityBase` থেকে ইনহেরিট করে, এভাবেই **FastAPI** জানতে পারে কীভাবে এগুলো OpenAPI-তে একীভূত করতে হবে।

## এটি কী করে { #what-it-does }

এটি রিকোয়েস্টে গিয়ে ওই `Authorization` হেডার খুঁজবে, দেখবে মানটি `Bearer ` আর তার পরে কোনো টোকেন কিনা, আর টোকেনটি একটি `str` হিসেবে ফেরত দেবে।

যদি এটি কোনো `Authorization` হেডার না দেখে, বা মানটিতে `Bearer ` টোকেন না থাকে, তাহলে এটি সরাসরি ৪০১ স্ট্যাটাস কোডের এরর (`UNAUTHORIZED`, মানে "অনুমোদিত নয়") দিয়ে উত্তর দেবে।

এরর ফেরত দিতে টোকেন আছে কিনা তাও আপনাকে যাচাই করতে হবে না। আপনি নিশ্চিত থাকতে পারেন যে আপনার ফাংশন চললে সেই টোকেনে একটি `str` থাকবেই।

ইন্টারঅ্যাকটিভ ডকুমেন্টেশনে আপনি ইতিমধ্যে এটি চেষ্টা করে দেখতে পারেন:

<img src="/img/tutorial/security/image03.png">

আমরা এখনো টোকেনের বৈধতা যাচাই করছি না, তবে এটি একটি ভালো শুরু।

## সংক্ষেপে { #recap }

তাহলে, মাত্র ৩ বা ৪ লাইন বাড়তি কোডেই আপনার ইতিমধ্যে কিছুটা প্রাথমিক সিকিউরিটি আছে।

/// check | সংক্ষেপে মনে রাখুন

* `oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")` দিয়ে সিকিউরিটি ব্যবস্থা তৈরি করুন।
* `token: Annotated[str, Depends(oauth2_scheme)]` দিলে ওই পাথে ঢুকতে `Authorization: Bearer <টোকেন>` হেডার লাগবে, না থাকলে স্বয়ংক্রিয়ভাবে ৪০১।
* `/docs`-এ "Authorize" বাটন আর তালা চিহ্ন নিজে থেকেই আসে।
* এখনো টোকেন যাচাই হচ্ছে না, আর `/token` পাথও বানানো হয়নি, সেগুলো পরের অধ্যায়ে।
