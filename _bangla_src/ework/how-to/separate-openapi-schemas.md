# ইনপুট আর আউটপুটের জন্য আলাদা OpenAPI স্কিমা, নাকি নয় { #separate-openapi-schemas-for-input-and-output-or-not }

/// note | এই পেজে যা শিখবেন

* কেন একই Pydantic মডেলের জন্য OpenAPI-তে দুটি স্কিমা (`Item-Input` আর `Item-Output`) দেখা যায়।
* ডিফল্ট মানওয়ালা ফিল্ড ইনপুটে "ঐচ্ছিক" কিন্তু আউটপুটে "বাধ্যতামূলক" কেন।
* `separate_input_output_schemas=False` দিয়ে এই আচরণ বন্ধ করা।

///

**Pydantic v2** প্রকাশের পর থেকে, তৈরি হওয়া OpenAPI আগের চেয়ে একটু বেশি নির্ভুল আর **সঠিক**। 😎

আসলে, কিছু ক্ষেত্রে, একই Pydantic মডেলের জন্য OpenAPI-তে **দুটি JSON স্কিমা**-ও থাকবে, ইনপুট আর আউটপুটের জন্য, তাদের **ডিফল্ট মান** আছে কিনা তার ওপর নির্ভর করে।

চলুন দেখি এটি কীভাবে কাজ করে আর দরকার হলে কীভাবে বদলাতে হয়।

### আউটপুটের জন্য মডেল { #model-for-output }

কিন্তু যদি একই মডেল এখানের মতো আউটপুট হিসেবে ব্যবহার করেন:

...তাহলে যেহেতু `description`-এর একটি ডিফল্ট মান আছে, তাই যদি সেই ফিল্ডের জন্য **কিছু ফেরত না দেন**, তবুও এতে সেই **ডিফল্ট মানটি** থাকবে।

### আউটপুট রেসপন্স ডেটার জন্য মডেল { #model-for-output-response-data }

যদি ডকসে চেষ্টা করে রেসপন্সটি দেখেন, তাহলে কোড একটি `description` ফিল্ডে কিছু যোগ না করলেও, JSON রেসপন্সে ডিফল্ট মান (`null`) থাকে:

<div class="screenshot">
<img src="/img/tutorial/separate-openapi-schemas/image02.png">
</div>

এর মানে এতে **সবসময় একটি মান থাকবে**, শুধু কখনো কখনো মানটি `None` (বা JSON-এ `null`) হতে পারে।

এর মানে আপনার API ব্যবহারকারী ক্লায়েন্টদের মানটি আছে কিনা তা যাচাই করতে হবে না, তারা **ধরে নিতে পারে যে ফিল্ডটি সবসময় থাকবে**, শুধু কিছু ক্ষেত্রে এর ডিফল্ট মান `None` হবে।

OpenAPI-তে এটি বর্ণনা করার উপায় হলো ফিল্ডটিকে **বাধ্যতামূলক** হিসেবে চিহ্নিত করা, কারণ এটি সবসময় থাকবে।

সেই কারণে, একটি মডেলের JSON স্কিমা ভিন্ন হতে পারে, এটি **ইনপুট নাকি আউটপুট** হিসেবে ব্যবহার হচ্ছে তার ওপর নির্ভর করে:

* **ইনপুটের** জন্য `description` **বাধ্যতামূলক হবে না**
* **আউটপুটের** জন্য এটি **বাধ্যতামূলক** হবে (আর সম্ভবত `None`, বা JSON-এর ভাষায় `null`)

/// tip | উদাহরণ দিয়ে বুঝি

একটি ভর্তি ফর্মে "মধ্য নাম" ঘরটি পূরণ করা ঐচ্ছিক (ইনপুট)। কিন্তু অফিস থেকে যে পরিচয়পত্র ছাপা হয় (আউটপুট), তাতে "মধ্য নাম" ঘরটি সবসময় থাকে, কারো ক্ষেত্রে শুধু ফাঁকা ("নেই")। তাই ফর্মের নিয়ম আর পরিচয়পত্রের নিয়ম একটু আলাদা, যদিও তথ্য একই।

### ডকসে ইনপুট আর আউটপুটের মডেল { #model-for-input-and-output-in-docs }

আর যদি OpenAPI-তে উপলব্ধ সব স্কিমা (JSON স্কিমা) দেখেন, দেখবেন দুটি আছে, একটি `Item-Input` আর একটি `Item-Output`।

`Item-Input`-এর জন্য `description` **বাধ্যতামূলক নয়**, এতে লাল তারকাচিহ্ন নেই।

কিন্তু `Item-Output`-এর জন্য `description` **বাধ্যতামূলক**, এতে লাল তারকাচিহ্ন আছে।

<div class="screenshot">
<img src="/img/tutorial/separate-openapi-schemas/image04.png">
</div>

**Pydantic v2**-এর এই ফিচারের মাধ্যমে আপনার API ডকুমেন্টেশন আরও **নির্ভুল** হয়, আর যদি আপনার স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট আর SDK থাকে, সেগুলোও আরও নির্ভুল হবে, আরও ভালো **ডেভেলপার অভিজ্ঞতা** আর সামঞ্জস্যসহ। 🎉

## স্কিমা আলাদা না করা { #do-not-separate-schemas }

এখন, কিছু ক্ষেত্রে আপনি **ইনপুট আর আউটপুটের জন্য একই স্কিমা** রাখতে চাইতে পারেন।

সম্ভবত এর প্রধান কারণ হলো, যদি আপনার ইতিমধ্যে কিছু স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট কোড/SDK থাকে আর আপনি এখনই সব স্বয়ংক্রিয়ভাবে তৈরি ক্লায়েন্ট কোড/SDK আপডেট করতে না চান। সম্ভবত কোনো এক সময় তা করতে চাইবেন, কিন্তু হয়তো এখনই নয়।

সেই ক্ষেত্রে, **FastAPI**-তে `separate_input_output_schemas=False` প্যারামিটার দিয়ে এই ফিচারটি বন্ধ করতে পারেন।

/// note | নোট

`separate_input_output_schemas`-এর সাপোর্ট FastAPI `0.102.0`-এ যোগ করা হয়েছে। 🤓
