# কাস্টম Request এবং APIRoute ক্লাস { #custom-request-and-apiroute-class }

/// note | এই পেজে যা শিখবেন

* `Request` আর `APIRoute` ক্লাসের সাব-ক্লাস বানিয়ে রিকোয়েস্ট প্রসেসিং বদলানো।
* gzip দিয়ে সংকুচিত রিকোয়েস্ট বডি স্বয়ংক্রিয়ভাবে খোলা।
* এরর হ্যান্ডলারে রিকোয়েস্ট বডি পড়া।
* একটি রাউটারের সব রেসপন্সে কত সময় লাগল তা হেডারে যোগ করা।

///

কিছু ক্ষেত্রে আপনি `Request` আর `APIRoute` ক্লাসের ব্যবহৃত যুক্তি (logic) ওভাররাইড করতে চাইতে পারেন।

বিশেষ করে, এটি একটি middleware-এ যুক্তি রাখার একটি ভালো বিকল্প হতে পারে।

যেমন, যদি আপনার অ্যাপ্লিকেশন প্রসেস করার আগে রিকোয়েস্ট বডি পড়তে বা পরিবর্তন করতে চান।

/// danger | বিপদ

এটি একটি "অ্যাডভান্সড" ফিচার।

যদি আপনি সবে **FastAPI** দিয়ে শুরু করে থাকেন, তাহলে এই অংশটি এড়িয়ে যেতে পারেন।

///

## ব্যবহারের ক্ষেত্র { #use-cases }

কিছু ব্যবহারের ক্ষেত্র:

* JSON নয় এমন রিকোয়েস্ট বডিকে JSON-এ রূপান্তর করা (যেমন [`msgpack`](https://msgpack.org/index.html))।
* gzip দিয়ে সংকুচিত রিকোয়েস্ট বডি খোলা (decompress)।
* সব রিকোয়েস্ট বডি স্বয়ংক্রিয়ভাবে লগ করা।

/// tip | উদাহরণ দিয়ে বুঝি

`APIRoute` হলো একটি অফিসের দরজার প্রহরী, যে প্রতিটি চিঠি (রিকোয়েস্ট) ভেতরের কর্মকর্তার (পাথ অপারেশন) কাছে পৌঁছে দেয়। কাস্টম রাউট ক্লাস মানে প্রহরীকে নতুন দায়িত্ব দেওয়া: "সিল করা প্যাকেট এলে আগে খুলে দিও" (gzip), "প্রতিটি চিঠি কখন এল আর কতক্ষণে উত্তর গেল লিখে রাখো" (সময় মাপা)। কর্মকর্তাদের নিজেদের কাজে কোনো পরিবর্তন লাগে না।

///

## কাস্টম রিকোয়েস্ট বডি এনকোডিং সামলানো { #handling-custom-request-body-encodings }

চলুন দেখি কীভাবে gzip রিকোয়েস্ট খুলতে একটি কাস্টম `Request` সাব-ক্লাস ব্যবহার করা যায়।

আর সেই কাস্টম রিকোয়েস্ট ক্লাস ব্যবহার করতে একটি `APIRoute` সাব-ক্লাস।

### একটি কাস্টম `GzipRequest` ক্লাস তৈরি করুন { #create-a-custom-gziprequest-class }

/// tip | পরামর্শ

এটি কীভাবে কাজ করে তা দেখানোর জন্য একটি খেলনা উদাহরণ। যদি Gzip সাপোর্ট দরকার হয়, তাহলে দেওয়া [`GzipMiddleware`](../advanced/middleware.md#gzipmiddleware) ব্যবহার করতে পারেন।

///

প্রথমে আমরা একটি `GzipRequest` ক্লাস তৈরি করি, যা উপযুক্ত হেডার থাকলে বডি খোলার জন্য `Request.body()` মেথডটি ওভাররাইট করবে।

যদি হেডারে `gzip` না থাকে, তাহলে এটি বডি খোলার চেষ্টা করবে না।

এভাবে একই রাউট ক্লাস gzip দিয়ে সংকুচিত বা অসংকুচিত দুই ধরনের রিকোয়েস্টই সামলাতে পারবে।

{* ../../docs_src/custom_request_and_route/tutorial001_an_py310.py hl[9:16] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ৯: `GzipRequest` হলো সাধারণ `Request`-এর একটি সাব-ক্লাস।
* লাইন ১১: `_body` আগে থেকে না থাকলেই শুধু পড়া হবে, যাতে একই বডি বারবার পড়তে না হয়।
* লাইন ১২: `super().body()` দিয়ে মূল (কাঁচা) বডি পড়া।
* লাইন ১৩–১৪: `Content-Encoding` হেডারে `gzip` থাকলে `gzip.decompress` দিয়ে খোলা।
* লাইন ১৫–১৬: ফলাফল `_body`-তে রেখে ফেরত দেওয়া।

///

### একটি কাস্টম `GzipRoute` ক্লাস তৈরি করুন { #create-a-custom-gziproute-class }

এরপর, আমরা `fastapi.routing.APIRoute`-এর একটি কাস্টম সাব-ক্লাস তৈরি করি যা `GzipRequest` ব্যবহার করবে।

এবার এটি `APIRoute.get_route_handler()` মেথডটি ওভাররাইট করবে।

এই মেথডটি একটি ফাংশন ফেরত দেয়। আর সেই ফাংশনটিই একটি রিকোয়েস্ট গ্রহণ করে একটি রেসপন্স ফেরত দেবে।

এখানে আমরা এটি ব্যবহার করে মূল রিকোয়েস্ট থেকে একটি `GzipRequest` তৈরি করি।

{* ../../docs_src/custom_request_and_route/tutorial001_an_py310.py hl[19:27] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ২১: `super().get_route_handler()` দিয়ে FastAPI-এর স্বাভাবিক হ্যান্ডলারটি নেওয়া হয়।
* লাইন ২৩–২৫: নতুন একটি হ্যান্ডলার, যা আগে সাধারণ `request`-কে `GzipRequest`-এ মুড়ে নেয়, তারপর স্বাভাবিক হ্যান্ডলারকে দেয়।
* লাইন ২৭: এই নতুন হ্যান্ডলারটিই ফেরত দেওয়া হয়।
* লাইন ৩১ (পুরো উদাহরণে): `app.router.route_class = GzipRoute` দিয়ে অ্যাপের সব রাউটে এটি চালু করা হয়।

///

/// note | কারিগরি বিবরণ

একটি `Request`-এর একটি `request.scope` অ্যাট্রিবিউট আছে, যা শুধু একটি Python `dict`, যাতে রিকোয়েস্ট সম্পর্কিত মেটাডেটা থাকে।

একটি `Request`-এর একটি `request.receive`-ও আছে, যা রিকোয়েস্টের বডি "গ্রহণ" করার একটি ফাংশন।

`scope` `dict` আর `receive` ফাংশন দুটোই ASGI স্পেসিফিকেশনের অংশ।

আর এই দুটি জিনিস, `scope` আর `receive`, দিয়েই একটি নতুন `Request` ইনস্ট্যান্স তৈরি করা যায়।

`Request` সম্পর্কে আরও জানতে [Starlette-এর Requests ডকস](https://starlette.dev/requests/) দেখুন।

///

`GzipRoute.get_route_handler`-এর ফেরত দেওয়া ফাংশনটি একমাত্র যে কাজটি ভিন্নভাবে করে তা হলো `Request`-কে একটি `GzipRequest`-এ রূপান্তর করা।

এটি করার ফলে, আমাদের `GzipRequest` ডেটা আমাদের *পাথ অপারেশনে* পাঠানোর আগে (প্রয়োজন হলে) খোলার দায়িত্ব নেবে।

এরপর, প্রসেসিংয়ের সব যুক্তি একই।

কিন্তু `GzipRequest.body`-তে আমাদের পরিবর্তনের কারণে, দরকার হলে **FastAPI** যখন রিকোয়েস্ট বডি লোড করবে তখন এটি স্বয়ংক্রিয়ভাবে খোলা হবে।

## একটি এক্সেপশন হ্যান্ডলারে রিকোয়েস্ট বডি পড়া { #accessing-the-request-body-in-an-exception-handler }

/// tip | পরামর্শ

এই একই সমস্যার সমাধানে, সম্ভবত `RequestValidationError`-এর জন্য একটি কাস্টম হ্যান্ডলারে `body` ব্যবহার করা অনেক সহজ ([এরর সামলানো](../tutorial/handling-errors.md#use-the-requestvalidationerror-body))।

তবে এই উদাহরণটি এখনো বৈধ, আর এটি দেখায় কীভাবে অভ্যন্তরীণ কম্পোনেন্টগুলোর সাথে কাজ করতে হয়।

///

একটি এক্সেপশন হ্যান্ডলারে রিকোয়েস্ট বডি পড়তেও আমরা একই পদ্ধতি ব্যবহার করতে পারি।

আমাদের শুধু একটি `try`/`except` ব্লকের ভেতরে রিকোয়েস্টটি সামলাতে হবে:

* `Request`-এর সাব-ক্লাস বানিয়ে `body()` বদলালে বডি পড়ার ধরন বদলানো যায় (যেমন gzip খোলা)।
* `APIRoute`-এর সাব-ক্লাসে `get_route_handler()` ওভাররাইড করে প্রতিটি রিকোয়েস্টের আগে-পরে কাজ যোগ করা যায়।
* পুরো অ্যাপে চালু করতে `app.router.route_class = ...`, শুধু একটি রাউটারে চাইলে `APIRouter(route_class=...)`।
