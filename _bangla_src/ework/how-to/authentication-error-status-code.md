# পুরনো 403 অথেনটিকেশন এরর স্ট্যাটাস কোড ব্যবহার করা { #use-old-403-authentication-error-status-codes }

/// note | এই পেজে যা শিখবেন

* `401 Unauthorized` আর `403 Forbidden`-এর পার্থক্য।
* কেন FastAPI 0.122.0 থেকে 401 ফেরত দেয়।
* দরকার হলে পুরনো 403 আচরণে ফিরে যাওয়া।

///

FastAPI সংস্করণ `0.122.0`-এর আগে, ব্যর্থ অথেনটিকেশনের পরে যখন সমন্বিত নিরাপত্তা টুলগুলো ক্লায়েন্টকে একটি এরর ফেরত দিত, তখন সেগুলো HTTP স্ট্যাটাস কোড `403 Forbidden` ব্যবহার করত।

FastAPI সংস্করণ `0.122.0` থেকে, সেগুলো আরও উপযুক্ত HTTP স্ট্যাটাস কোড `401 Unauthorized` ব্যবহার করে, আর HTTP স্পেসিফিকেশন, [RFC 7235](https://datatracker.ietf.org/doc/html/rfc7235#section-3.1), [RFC 9110](https://datatracker.ietf.org/doc/html/rfc9110#name-401-unauthorized) অনুসরণ করে রেসপন্সে একটি যুক্তিসঙ্গত `WWW-Authenticate` হেডার ফেরত দেয়।

/// tip | উদাহরণ দিয়ে বুঝি

একটি অফিস ভবনের কথা ভাবুন। **401** মানে "আপনি কে তা জানি না, আগে পরিচয়পত্র দেখান" (লগইন করা হয়নি বা টোকেন নেই)। **403** মানে "আপনি কে তা জানি, কিন্তু এই ঘরে ঢোকার অনুমতি আপনার নেই" (লগইন আছে কিন্তু পারমিশন নেই)। টোকেন না দিলে 401-ই সঠিক উত্তর, তাই FastAPI এখন সেটাই দেয়।

///

কিন্তু যদি কোনো কারণে আপনার ক্লায়েন্টরা পুরনো আচরণের ওপর নির্ভর করে, তাহলে আপনার সিকিউরিটি ক্লাসে `make_not_authenticated_error` মেথডটি ওভাররাইড করে আগের আচরণে ফিরে যেতে পারেন।

যেমন, `HTTPBearer`-এর একটি সাব-ক্লাস তৈরি করতে পারেন যা ডিফল্ট `401 Unauthorized` এররের বদলে একটি `403 Forbidden` এরর ফেরত দেয়:

/// info | কোডটি সহজ ভাষায়

* লাইন ৯: `HTTPBearer403` হলো সাধারণ `HTTPBearer`-এর একটি সাব-ক্লাস।
* লাইন ১০–১৩: `make_not_authenticated_error` মেথডটি এখন 403 স্ট্যাটাসসহ একটি `HTTPException` ফেরত দেয়।
* লাইন ১৬: ডিপেন্ডেন্সিতে সাধারণ `HTTPBearer()`-এর বদলে `HTTPBearer403()` ব্যবহার করা হয়েছে।

/// check | সংক্ষেপে মনে রাখুন

* নতুন FastAPI লগইন না থাকলে 401 দেয় (সঠিক নিয়ম), পুরনোটা দিত 403।
* পুরনো ক্লায়েন্টের জন্য 403 দরকার হলে সিকিউরিটি ক্লাসের সাব-ক্লাস বানিয়ে `make_not_authenticated_error` ওভাররাইড করুন।
* এক্সেপশন `return` করুন, `raise` নয়।
