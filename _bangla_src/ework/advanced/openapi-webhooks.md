# OpenAPI Webhook { #openapi-webhooks }

/// note | এই পেজে যা শিখবেন

* webhook কী, আর এটি সাধারণ API রিকোয়েস্ট থেকে কীভাবে উল্টো।
* `@app.webhooks.post()` দিয়ে webhook ডকুমেন্ট করা।
* কলব্যাক আর webhook-এর পার্থক্য।

///

এমন কিছু ক্ষেত্র আছে যেখানে আপনি আপনার API-র **ব্যবহারকারীদের** জানাতে চান যে আপনার অ্যাপ কিছু ডেটা নিয়ে *তাদের* অ্যাপকে কল করতে (রিকোয়েস্ট পাঠাতে) পারে, সাধারণত কোনো ধরনের **ঘটনা (event)** সম্পর্কে **জানাতে**।

এর মানে, ব্যবহারকারীরা আপনার API-তে রিকোয়েস্ট পাঠানোর স্বাভাবিক প্রক্রিয়ার বদলে, **আপনার API** (বা আপনার অ্যাপ) **তাদের সিস্টেমে** (তাদের API, তাদের অ্যাপে) **রিকোয়েস্ট পাঠাতে** পারে।

একে সাধারণত বলা হয় **webhook**।

/// tip | উদাহরণ দিয়ে বুঝি

বারবার দোকানে গিয়ে "আমার পার্সেল এসেছে?" জিজ্ঞেস করার বদলে আপনি দোকানে নিজের ফোন নম্বর রেখে এলেন। পার্সেল এলেই দোকান আপনাকে SMS পাঠায়। এই SMS হলো webhook: ঘটনা ঘটলে সার্ভার নিজে থেকেই আপনাকে জানায়। পেমেন্ট গেটওয়ে (যেমন bKash, Stripe) "পেমেন্ট সফল" জানাতে এভাবেই webhook ব্যবহার করে।

///

## Webhook-এর ধাপগুলো { #webhooks-steps }

সাধারণত প্রক্রিয়াটি হলো, **আপনি** কোডে **নির্ধারণ করেন** কোন বার্তা পাঠাবেন, অর্থাৎ **রিকোয়েস্টের বডি**।

আপনি কোনোভাবে এটিও নির্ধারণ করেন যে কোন **মুহূর্তে** আপনার অ্যাপ ওই রিকোয়েস্ট বা ইভেন্টগুলো পাঠাবে।

আর **আপনার ব্যবহারকারীরা** কোনোভাবে (যেমন কোথাও একটি ওয়েব ড্যাশবোর্ডে) সেই **URL** নির্ধারণ করেন যেখানে আপনার অ্যাপ ওই রিকোয়েস্টগুলো পাঠাবে।

webhook-এর URL কীভাবে নিবন্ধন হবে আর আসলে রিকোয়েস্টগুলো পাঠানোর কোড, এই সব **যুক্তি (logic)** আপনার ওপর। আপনি **নিজের কোডে** যেভাবে চান সেভাবে লিখবেন।

## **FastAPI** আর OpenAPI দিয়ে webhook ডকুমেন্ট করা { #documenting-webhooks-with-fastapi-and-openapi }

**FastAPI**-তে OpenAPI ব্যবহার করে আপনি এই webhook-গুলোর নাম, আপনার অ্যাপ কোন ধরনের HTTP অপারেশন পাঠাতে পারে (যেমন `POST`, `PUT` ইত্যাদি), আর আপনার অ্যাপ কোন রিকোয়েস্ট **বডি** পাঠাবে তা নির্ধারণ করতে পারেন।

এতে আপনার **webhook** রিকোয়েস্ট গ্রহণ করার জন্য ব্যবহারকারীদের **তাদের API বাস্তবায়ন** করা অনেক সহজ হয়, তারা হয়তো নিজেদের API কোডের কিছু অংশ স্বয়ংক্রিয়ভাবে তৈরিও করতে পারবেন।

/// note | নোট

Webhook পাওয়া যায় OpenAPI 3.1.0 ও তার পরের সংস্করণে, FastAPI `0.99.0` ও তার পরের সংস্করণ এটি সাপোর্ট করে।

///

## webhook-সহ একটি অ্যাপ { #an-app-with-webhooks }

যখন একটি **FastAPI** অ্যাপ্লিকেশন তৈরি করেন, তখন একটি `webhooks` অ্যাট্রিবিউট থাকে যা দিয়ে *webhook* সংজ্ঞায়িত করতে পারেন, ঠিক যেভাবে *পাথ অপারেশন* সংজ্ঞায়িত করেন, যেমন `@app.webhooks.post()` দিয়ে।

/// info | কোডটি সহজ ভাষায়

* লাইন ৯–১২: `Subscription` মডেল, অর্থাৎ webhook-এ আপনার অ্যাপ কোন ডেটা পাঠাবে (ইউজারনেম, মাসিক ফি, শুরুর তারিখ)।
* লাইন ১৫: `@app.webhooks.post("new-subscription")` একটি webhook ঘোষণা করে, যার নাম `new-subscription`।
* লাইন ১৬–২০: ফাংশনের প্যারামিটার `body: Subscription` বলে দেয় বডি কেমন হবে। docstring ডকুমেন্টেশনে বর্ণনা হিসেবে দেখাবে। ফাংশনে কোনো আসল কোড নেই, কারণ এটি শুধু ডকুমেন্টেশনের জন্য।
* লাইন ২৩–২৫: একটি সাধারণ পাথ অপারেশন, তুলনার জন্য।

///

আপনার সংজ্ঞায়িত webhook-গুলো **OpenAPI** স্কিমা আর স্বয়ংক্রিয় **ডকস UI**-তে দেখা যাবে।

/// note | নোট

`app.webhooks` অবজেক্টটি আসলে শুধু একটি `APIRouter`, ঠিক যে টাইপটি আপনি একাধিক ফাইলে অ্যাপ সাজানোর সময় ব্যবহার করেন।

///

লক্ষ্য করুন, webhook-এ আপনি আসলে কোনো *পাথ* (যেমন `/items/`) ঘোষণা করছেন না। সেখানে যে টেক্সট দেন তা শুধু webhook-এর একটি **পরিচয়চিহ্ন** (ইভেন্টের নাম)। যেমন `@app.webhooks.post("new-subscription")`-এ webhook-এর নাম `new-subscription`।

কারণ ধরে নেওয়া হয় যে **আপনার ব্যবহারকারীরা** অন্য কোনোভাবে (যেমন একটি ওয়েব ড্যাশবোর্ডে) আসল **URL পাথ** নির্ধারণ করবেন, যেখানে তারা webhook রিকোয়েস্ট পেতে চান।

/// tip | উদাহরণ দিয়ে বুঝি

[OpenAPI কলব্যাক](openapi-callbacks.md)-এর সাথে পার্থক্য কী? কলব্যাকে URL আসে একটি নির্দিষ্ট রিকোয়েস্টের সাথে (যেমন `callback_url` কোয়েরি প্যারামিটার), আর উত্তর সেই রিকোয়েস্টেরই ফলাফল। Webhook-এ URL ব্যবহারকারী আগে থেকেই একবার নিবন্ধন করে রাখেন, আর যখনই ঘটনা ঘটে (নতুন সাবস্ক্রিপশন), তখনই আপনার অ্যাপ সেখানে পাঠায়।

///
