# ওভাররাইড দিয়ে ডিপেন্ডেন্সি টেস্ট করা { #testing-dependencies-with-overrides }

/// note | এই পেজে যা শিখবেন

* টেস্টের সময় একটি আসল ডিপেন্ডেন্সির বদলে নকল (mock) ডিপেন্ডেন্সি বসানো।
* `app.dependency_overrides` ডিকশনারি কীভাবে কাজ করে।
* টেস্ট শেষে ওভাররাইড সরিয়ে ফেলা।

///

## টেস্টের সময় ডিপেন্ডেন্সি ওভাররাইড করা { #overriding-dependencies-during-testing }

কিছু পরিস্থিতিতে আপনি টেস্টের সময় একটি ডিপেন্ডেন্সি ওভাররাইড করতে (অর্থাৎ অন্য কিছু দিয়ে বদলে দিতে) চাইতে পারেন।

আপনি চান না আসল ডিপেন্ডেন্সিটি চলুক (বা এর কোনো সাব-ডিপেন্ডেন্সিও)।

বরং আপনি একটি ভিন্ন ডিপেন্ডেন্সি দিতে চান, যা শুধু টেস্টের সময় (হয়তো শুধু নির্দিষ্ট কিছু টেস্টে) ব্যবহার হবে, আর এমন একটি মান দেবে যা আসল ডিপেন্ডেন্সির মানের জায়গায় ব্যবহার করা যায়।

### ব্যবহারের ক্ষেত্র: বাইরের সার্ভিস { #use-cases-external-service }

একটি উদাহরণ হতে পারে: আপনার একটি বাইরের অথেনটিকেশন প্রোভাইডার আছে যাকে কল করতে হয়।

আপনি এটিকে একটি টোকেন পাঠান আর এটি একজন অথেনটিকেটেড ইউজার ফেরত দেয়।

এই প্রোভাইডার হয়তো প্রতি রিকোয়েস্টে টাকা নেয়, আর একে কল করতে টেস্টের জন্য একটি নির্দিষ্ট নকল ইউজার রাখার চেয়ে বেশি সময় লাগে।

আপনি সম্ভবত বাইরের প্রোভাইডারটি একবার টেস্ট করতে চান, কিন্তু প্রতিটি টেস্টে এটিকে কল করা জরুরি নয়।

এই ক্ষেত্রে, আপনি যে ডিপেন্ডেন্সি ওই প্রোভাইডারকে কল করে সেটি ওভাররাইড করতে পারেন, আর শুধু টেস্টের জন্য একটি কাস্টম ডিপেন্ডেন্সি ব্যবহার করতে পারেন যা একজন নকল ইউজার ফেরত দেয়।

/// tip | উদাহরণ দিয়ে বুঝি

সিনেমার শুটিংয়ে বিপজ্জনক দৃশ্যে আসল নায়কের বদলে স্টান্টম্যান নামানো হয়। দর্শকের কাছে দৃশ্য একই থাকে, কিন্তু আসল নায়কের ঝুঁকি বা খরচ লাগে না। ডিপেন্ডেন্সি ওভাররাইড হলো সেই স্টান্টম্যান: আপনার পাথ অপারেশন জানেই না যে আসল ডিপেন্ডেন্সির বদলে নকলটি এসেছে।

### `app.dependency_overrides` অ্যাট্রিবিউট ব্যবহার করুন { #use-the-app-dependency-overrides-attribute }

এসব ক্ষেত্রে আপনার **FastAPI** অ্যাপ্লিকেশনের একটি অ্যাট্রিবিউট আছে `app.dependency_overrides`, এটি একটি সাধারণ `dict`।

টেস্টের জন্য একটি ডিপেন্ডেন্সি ওভাররাইড করতে, key হিসেবে আসল ডিপেন্ডেন্সি (একটি ফাংশন) দিন, আর value হিসেবে আপনার ওভাররাইড ডিপেন্ডেন্সি (আরেকটি ফাংশন)।

তারপর **FastAPI** আসল ডিপেন্ডেন্সির বদলে ওই ওভাররাইডটি কল করবে।

{* ../../docs_src/dependency_testing/tutorial001_an_py310.py hl[26:27,30] *}

/// info | কোডটি সহজ ভাষায়

* লাইন ৯–১০: আসল ডিপেন্ডেন্সি `common_parameters`, যা `q`, `skip`, `limit` কোয়েরি প্যারামিটার নেয়।
* লাইন ১৩–২০: দুটি পাথ অপারেশন (`/items/` আর `/users/`) এই ডিপেন্ডেন্সি ব্যবহার করে।
* লাইন ২৬–২৭: নকল ডিপেন্ডেন্সি `override_dependency`। এটি সবসময় `skip` = 5 আর `limit` = 10 ফেরত দেয়।
* লাইন ৩০: `app.dependency_overrides[common_parameters] = override_dependency` লিখে FastAPI-কে বলা হলো: "যেখানেই `common_parameters` দরকার, সেখানে `override_dependency` চালাও।"
* লাইন ৫১–৫৭: রিকোয়েস্টে `skip=100&limit=200` পাঠালেও উত্তরে আসে `skip` 5 আর `limit` 10, কারণ আসল ডিপেন্ডেন্সি আর চলছে না।

///

/// tip | পরামর্শ

আপনার **FastAPI** অ্যাপ্লিকেশনের যেকোনো জায়গায় ব্যবহৃত ডিপেন্ডেন্সির জন্য আপনি ওভাররাইড সেট করতে পারেন।

আসল ডিপেন্ডেন্সিটি ব্যবহার হতে পারে একটি *পাথ অপারেশন ফাংশনে*, একটি *পাথ অপারেশন ডেকোরেটরে* (যখন রিটার্ন মান ব্যবহার করেন না), একটি `.include_router()` কলে, ইত্যাদি।

FastAPI তবুও এটিকে ওভাররাইড করতে পারবে।

///

তারপর `app.dependency_overrides`-কে একটি খালি `dict` সেট করে আপনার ওভাররাইডগুলো রিসেট করতে (সরিয়ে ফেলতে) পারেন:

```Python
app.dependency_overrides = {}
```

/// tip | পরামর্শ

যদি শুধু কিছু টেস্টের সময় একটি ডিপেন্ডেন্সি ওভাররাইড করতে চান, তাহলে টেস্টের শুরুতে (টেস্ট ফাংশনের ভেতরে) ওভাররাইড সেট করুন আর শেষে (টেস্ট ফাংশনের শেষে) রিসেট করুন।

///

/// warning | সাধারণ ভুল

* key হিসেবে ফাংশনটি নিজেই দিন (`common_parameters`), এটিকে কল করে নয় (`common_parameters()` নয়)।
* ওভাররাইড রিসেট করতে ভুলে গেলে পরের টেস্টগুলোতেও নকল ডিপেন্ডেন্সি চলতে থাকবে, ফলে বিভ্রান্তিকর ফলাফল আসতে পারে।

///

/// check | সংক্ষেপে মনে রাখুন

* `app.dependency_overrides[আসল_ফাংশন] = নকল_ফাংশন` দিয়ে ডিপেন্ডেন্সি বদলান।
* ধীর, খরচসাপেক্ষ বা বাইরের সার্ভিসনির্ভর ডিপেন্ডেন্সি টেস্টে এভাবে বদলে নেওয়া হয়।
* কাজ শেষে `app.dependency_overrides = {}` দিয়ে সব আগের অবস্থায় ফেরান।
