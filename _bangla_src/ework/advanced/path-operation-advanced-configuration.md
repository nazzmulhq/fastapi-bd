# পাথ অপারেশনের উন্নত কনফিগারেশন { #path-operation-advanced-configuration }

/// note | এই পেজে যা শিখবেন

* OpenAPI-তে প্রতিটি পাথ অপারেশনের অনন্য নাম (`operationId`) ঠিক করা।
* একটি পাথ অপারেশন ডকুমেন্টেশন থেকে লুকানো।
* docstring-এর কতটুকু ডকুমেন্টেশনে যাবে তা সীমিত করা (`\f`)।
* `openapi_extra` দিয়ে OpenAPI স্কিমায় নিজের তথ্য যোগ করা, যেমন YAML বডির বিবরণ।

///

## OpenAPI operationId { #openapi-operationid }

/// warning | সতর্কতা

আপনি যদি OpenAPI-তে "বিশেষজ্ঞ" না হন, তাহলে সম্ভবত এটি আপনার দরকার নেই।

///

`operation_id` প্যারামিটার দিয়ে আপনার *পাথ অপারেশনে* ব্যবহারের জন্য OpenAPI `operationId` সেট করতে পারেন।

আপনাকে নিশ্চিত করতে হবে যে এটি প্রতিটি অপারেশনের জন্য অনন্য।

{* ../../docs_src/path_operation_advanced_configuration/tutorial001_py310.py hl[6] *}

`operationId` হলো প্রতিটি পাথ অপারেশনের একটি অনন্য নাম। স্বয়ংক্রিয়ভাবে ক্লায়েন্ট কোড তৈরির টুলগুলো এই নাম দিয়েই ফাংশনের নাম বানায়, যেমন `some_specific_id_you_define()`।

### পাথ অপারেশন ফাংশনের নামকে operationId হিসেবে ব্যবহার { #using-the-path-operation-function-name-as-the-operationid }

আপনি যদি আপনার API-এর ফাংশনের নামগুলোকে `operationId` হিসেবে ব্যবহার করতে চান, তাহলে `FastAPI`-তে একটি কাস্টম `generate_unique_id_function` দিতে পারেন।

ফাংশনটি প্রতিটি `APIRoute` পায়, আর ওই পাথ অপারেশনের জন্য ব্যবহারের `operationId` ফেরত দেয়।

{* ../../docs_src/path_operation_advanced_configuration/tutorial002_py310.py hl[2,5:6,9] *}

/// warning | সতর্কতা

এটি করলে আপনাকে নিশ্চিত করতে হবে যে আপনার প্রতিটি *পাথ অপারেশন ফাংশনের* নাম অনন্য।

এমনকি সেগুলো ভিন্ন ভিন্ন মডিউলে (Python ফাইলে) থাকলেও।

## OpenAPI থেকে বাদ দিন { #exclude-from-openapi }

তৈরি হওয়া OpenAPI স্কিমা থেকে (আর তাই স্বয়ংক্রিয় ডকুমেন্টেশন সিস্টেম থেকে) একটি *পাথ অপারেশন* বাদ দিতে `include_in_schema` প্যারামিটার ব্যবহার করে `False` সেট করুন:

{* ../../docs_src/path_operation_advanced_configuration/tutorial003_py310.py hl[6] *}

পাথটি তখনও কাজ করবে, শুধু `/docs`-এ দেখা যাবে না। যেমন অভ্যন্তরীণ ব্যবহারের বা পরীক্ষামূলক কোনো পাথের জন্য।

## docstring থেকে উন্নত বিবরণ { #advanced-description-from-docstring }

একটি *পাথ অপারেশন ফাংশনের* docstring-এর কোন লাইনগুলো OpenAPI-তে ব্যবহার হবে তা সীমিত করতে পারেন।

একটি `\f` ("form feed" অক্ষরের এস্কেপ করা রূপ) যোগ করলে **FastAPI** OpenAPI-এর জন্য ব্যবহৃত আউটপুট এই জায়গায় কেটে দেয়।

এটি ডকুমেন্টেশনে দেখাবে না, কিন্তু অন্য টুলগুলো (যেমন Sphinx) বাকি অংশ ব্যবহার করতে পারবে।

{* ../../docs_src/path_operation_advanced_configuration/tutorial004_py310.py hl[17:27] *}

এখানে `\f`-এর আগের তালিকাটি `/docs`-এ দেখাবে, আর পরের `:param item: User input.` শুধু কোডের ভেতরের ডকুমেন্টেশন টুলের জন্য থাকবে।

## বাড়তি রেসপন্স { #additional-responses }

একটি *পাথ অপারেশনের* জন্য `response_model` আর `status_code` কীভাবে ঘোষণা করতে হয় তা সম্ভবত দেখেছেন।

এটি একটি *পাথ অপারেশনের* মূল রেসপন্সের মেটাডেটা সংজ্ঞায়িত করে।

তাদের মডেল, স্ট্যাটাস কোড ইত্যাদিসহ বাড়তি রেসপন্সও ঘোষণা করতে পারেন।

ডকুমেন্টেশনে এ নিয়ে একটি পুরো অধ্যায় আছে, এটি পড়তে পারেন [OpenAPI-তে বাড়তি রেসপন্স](additional-responses.md)-এ।

## OpenAPI Extra { #openapi-extra }

আপনার অ্যাপ্লিকেশনে একটি *পাথ অপারেশন* ঘোষণা করলে **FastAPI** স্বয়ংক্রিয়ভাবে ওই *পাথ অপারেশন* সম্পর্কে প্রাসঙ্গিক মেটাডেটা তৈরি করে OpenAPI স্কিমাতে অন্তর্ভুক্ত করে।

/// note | কারিগরি বিবরণ

OpenAPI স্পেসিফিকেশনে এটিকে বলা হয় [Operation Object](https://github.com/OAI/OpenAPI-Specification/blob/main/versions/3.0.3.md#operation-object)।

///

এতে *পাথ অপারেশন* সম্পর্কে সব তথ্য থাকে, আর এটি স্বয়ংক্রিয় ডকুমেন্টেশন তৈরিতে ব্যবহার হয়।

এতে থাকে `tags`, `parameters`, `requestBody`, `responses` ইত্যাদি।

*পাথ অপারেশন*-নির্দিষ্ট এই OpenAPI স্কিমা সাধারণত **FastAPI** স্বয়ংক্রিয়ভাবে তৈরি করে, তবে আপনি এটি বাড়াতেও পারেন।

/// tip | পরামর্শ

এটি একটি নিম্ন-স্তরের সম্প্রসারণের জায়গা।

আপনার যদি শুধু বাড়তি রেসপন্স ঘোষণা করতে হয়, তাহলে আরও সুবিধাজনক উপায় হলো [OpenAPI-তে বাড়তি রেসপন্স](additional-responses.md)।

///

`openapi_extra` প্যারামিটার ব্যবহার করে একটি *পাথ অপারেশনের* OpenAPI স্কিমা বাড়াতে পারেন।

### কাস্টম OpenAPI *পাথ অপারেশন* স্কিমা { #custom-openapi-path-operation-schema }

`openapi_extra`-এর ডিকশনারিটি *পাথ অপারেশনের* স্বয়ংক্রিয়ভাবে তৈরি OpenAPI স্কিমার সাথে গভীরভাবে মিশিয়ে (deep merge) দেওয়া হবে।

তাই স্বয়ংক্রিয়ভাবে তৈরি স্কিমাতে বাড়তি ডেটা যোগ করতে পারেন।

যেমন, আপনি হয়তো ঠিক করলেন Pydantic-সহ FastAPI-এর স্বয়ংক্রিয় ফিচারগুলো ব্যবহার না করে নিজের কোড দিয়ে রিকোয়েস্ট পড়বেন আর যাচাই করবেন, কিন্তু তবুও OpenAPI স্কিমাতে রিকোয়েস্টটি সংজ্ঞায়িত করতে চান।

এটি `openapi_extra` দিয়ে করতে পারেন:

{* ../../docs_src/path_operation_advanced_configuration/tutorial006_py310.py hl[19:36, 39:40] *}

এই উদাহরণে আমরা কোনো Pydantic মডেল ঘোষণা করিনি। আসলে রিকোয়েস্ট বডি JSON হিসেবে <dfn title="বাইটের মতো কোনো সাধারণ ফরম্যাট থেকে Python অবজেক্টে রূপান্তর করা">পার্স</dfn>-ও করা হয় না, এটি সরাসরি `bytes` হিসেবে পড়া হয়, আর `magic_data_reader()` ফাংশনটি কোনোভাবে এটি পার্স করার দায়িত্বে থাকবে।

তবুও আমরা রিকোয়েস্ট বডির প্রত্যাশিত স্কিমা ঘোষণা করতে পারি।

/// info | কোডটি সহজ ভাষায়

* লাইন ১৯-৩৬: হাতে লেখা OpenAPI বিবরণ: বডি একটি JSON অবজেক্ট, যাতে `name` আর `price` আবশ্যক।
* লাইন ৩৮-৪১: ফাংশন `request: Request` নেয়, আর `await request.body()` দিয়ে কাঁচা বাইট পড়ে। FastAPI নিজে কোনো যাচাই করে না।

ফলে `/docs`-এ বডির বিবরণ সুন্দরভাবে দেখায়, কিন্তু পড়া আর যাচাইয়ের পুরো নিয়ন্ত্রণ আপনার হাতে।

### কাস্টম OpenAPI কনটেন্ট টাইপ { #custom-openapi-content-type }

এই একই কৌশল ব্যবহার করে, একটি Pydantic মডেল দিয়ে JSON Schema সংজ্ঞায়িত করতে পারেন, যা তারপর *পাথ অপারেশনের* কাস্টম OpenAPI স্কিমা অংশে অন্তর্ভুক্ত হয়।

আর রিকোয়েস্টের ডেটা টাইপ JSON না হলেও এটি করতে পারেন।

যেমন, এই অ্যাপ্লিকেশনে আমরা Pydantic মডেল থেকে JSON Schema বের করার FastAPI-এর একীভূত সুবিধা বা JSON-এর স্বয়ংক্রিয় যাচাই ব্যবহার করছি না। আসলে আমরা রিকোয়েস্টের কনটেন্ট টাইপ ঘোষণা করছি YAML হিসেবে, JSON নয়:

{* ../../docs_src/path_operation_advanced_configuration/tutorial007_py310.py hl[15:20, 22] *}

তবুও, যদিও আমরা ডিফল্ট একীভূত সুবিধা ব্যবহার করছি না, তবুও যে ডেটা YAML-এ গ্রহণ করতে চাই তার JSON Schema হাতে তৈরি করতে একটি Pydantic মডেল ব্যবহার করছি।

তারপর আমরা সরাসরি রিকোয়েস্ট ব্যবহার করি, আর বডিটি `bytes` হিসেবে বের করি। এর মানে FastAPI রিকোয়েস্টের পেলোড JSON হিসেবে পার্স করার চেষ্টাও করবে না।

তারপর আমাদের কোডে ওই YAML বিষয়বস্তু সরাসরি পার্স করি, আর আবার সেই একই Pydantic মডেল দিয়ে YAML বিষয়বস্তু যাচাই করি:

* লাইন ১৭: `Item.model_json_schema()` Pydantic মডেল থেকে JSON Schema বানিয়ে `application/x-yaml` কনটেন্ট টাইপের নিচে রাখে।
* লাইন ২৩: কাঁচা বডি বাইট হিসেবে পড়া।

/// check | সংক্ষেপে মনে রাখুন

* `operation_id="..."` বা `generate_unique_id_function` দিয়ে OpenAPI-তে অপারেশনের নাম ঠিক করুন, নামগুলো অনন্য রাখুন।
* `include_in_schema=False` দিয়ে ডকুমেন্টেশন থেকে লুকান।

* `openapi_extra={...}` দিয়ে স্বয়ংক্রিয় স্কিমায় নিজের তথ্য মেশান, যেমন JSON নয় এমন বডির বিবরণ।
