# উন্নত ডিপেন্ডেন্সি { #advanced-dependencies }

/// note | এই পেজে যা শিখবেন

* প্যারামিটার দিয়ে সাজানো যায় এমন ডিপেন্ডেন্সি (একই ডিপেন্ডেন্সি, ভিন্ন সেটিংস)।
* `__call__` দিয়ে একটি অবজেক্টকে "ডাকা যায়" এমন বানানো।
* `yield`-সহ ডিপেন্ডেন্সির আচরণ বিভিন্ন সংস্করণে কীভাবে বদলেছে (কারিগরি ইতিহাস)।

## প্যারামিটারযুক্ত ডিপেন্ডেন্সি { #parameterized-dependencies }

এ পর্যন্ত আমরা যত ডিপেন্ডেন্সি দেখেছি সবগুলোই একটি নির্দিষ্ট ফাংশন বা ক্লাস।

কিন্তু এমন ক্ষেত্র থাকতে পারে যেখানে আপনি অনেকগুলো আলাদা ফাংশন বা ক্লাস ঘোষণা না করেই ডিপেন্ডেন্সিতে প্যারামিটার সেট করতে চাইবেন।

ধরা যাক আমরা এমন একটি ডিপেন্ডেন্সি চাই, যা যাচাই করে কুয়েরি প্যারামিটার `q`-তে কিছু নির্দিষ্ট বিষয়বস্তু আছে কিনা।

কিন্তু আমরা চাই সেই নির্দিষ্ট বিষয়বস্তুটি প্যারামিটার দিয়ে বদলানো যাক।

/// tip | উদাহরণ দিয়ে বুঝি

একটি "অনুমতি যাচাইকারী" ভাবুন। এক জায়গায় দেখতে হবে ইউজার "admin" কিনা, আরেক জায়গায় "editor" কিনা। প্রতিটির জন্য আলাদা ফাংশন না লিখে একটি ছাঁচ বানিয়ে `RoleChecker("admin")`, `RoleChecker("editor")` এভাবে ব্যবহার করা যায়।

## একটি "callable" ইনস্ট্যান্স { #a-callable-instance }

Python-এ একটি ক্লাসের ইনস্ট্যান্সকে "callable" (ডাকা যায় এমন) বানানোর একটি উপায় আছে।

ক্লাসটি নিজে নয় (যা আগে থেকেই একটি callable), বরং ওই ক্লাসের একটি ইনস্ট্যান্স।

এটি করতে আমরা একটি `__call__` মেথড ঘোষণা করি:

{* ../../docs_src/dependencies/tutorial011_an_py310.py hl[12] *}

এই ক্ষেত্রে, বাড়তি প্যারামিটার আর সাব-ডিপেন্ডেন্সি যাচাই করতে **FastAPI** এই `__call__`-ই ব্যবহার করবে, আর পরে আপনার *পাথ অপারেশন ফাংশনের* প্যারামিটারে একটি মান দিতে এটিকেই ডাকা হবে।

## ইনস্ট্যান্সটি ডিপেন্ডেন্সি হিসেবে ব্যবহার করুন { #use-the-instance-as-a-dependency }

তারপর `Depends(FixedContentQueryChecker)`-এর বদলে একটি `Depends(checker)`-এ এই `checker` ব্যবহার করতে পারি, কারণ ডিপেন্ডেন্সিটি হলো ইনস্ট্যান্স `checker`, ক্লাসটি নিজে নয়।

আর ডিপেন্ডেন্সি সমাধানের সময় **FastAPI** এই `checker`-কে এভাবে ডাকবে:

```Python
checker(q="somequery")
```

{* ../../docs_src/dependencies/tutorial011_an_py310.py hl[22] *}

/// info | পুরো কোডটি সহজ ভাষায়

* লাইন ৯-১০: `__init__` তৈরির সময় একবার চলে, খোঁজার শব্দটি (`fixed_content`) মনে রাখে।
* লাইন ১২-১৫: `__call__` প্রতিটি রিকোয়েস্টে চলে, `q`-তে ওই শব্দ আছে কিনা দেখে `True`/`False` দেয়।
* লাইন ১৮: `checker = FixedContentQueryChecker("bar")` মানে "bar" খোঁজার একটি যাচাইকারী।
* লাইন ২২: `Depends(checker)`।

তাই `/query-checker/?q=foobar` → `true`, `/query-checker/?q=hello` → `false`।

আপনি যদি এসব বুঝে থাকেন, তাহলে ওই সিকিউরিটি টুলগুলো ভেতরে কীভাবে কাজ করে তা ইতিমধ্যে জানেন।

## `yield`, `HTTPException`, `except` আর ব্যাকগ্রাউন্ড টাস্কসহ ডিপেন্ডেন্সি { #dependencies-with-yield-httpexception-except-and-background-tasks }

/// warning | সতর্কতা

খুব সম্ভবত এই কারিগরি বিবরণ আপনার দরকার নেই।

এই বিবরণগুলো মূলত কাজে লাগবে যদি আপনার 0.121.0-এর চেয়ে পুরোনো একটি FastAPI অ্যাপ্লিকেশন থাকে আর `yield`-সহ ডিপেন্ডেন্সি নিয়ে সমস্যায় পড়েন।

///

বিভিন্ন ব্যবহারের ক্ষেত্র বিবেচনা আর কিছু সমস্যা ঠিক করতে `yield`-সহ ডিপেন্ডেন্সি সময়ের সাথে বিকশিত হয়েছে, এখানে কী কী বদলেছে তার একটি সারাংশ দেওয়া হলো।

### `yield` আর `scope`-সহ ডিপেন্ডেন্সি { #dependencies-with-yield-and-scope }

সংস্করণ 0.121.0-এ FastAPI `yield`-সহ ডিপেন্ডেন্সির জন্য `Depends(scope="function")`-এর সাপোর্ট যোগ করেছে।

`Depends(scope="function")` ব্যবহার করলে `yield`-এর পরের বের হওয়ার কোড *পাথ অপারেশন ফাংশন* শেষ হওয়ার সাথে সাথে, ক্লায়েন্টকে রেসপন্স ফেরত পাঠানোর আগে চলে।

আর `Depends(scope="request")` (ডিফল্ট) ব্যবহার করলে `yield`-এর পরের বের হওয়ার কোড রেসপন্স পাঠানোর পরে চলে।

এ নিয়ে আরও পড়তে পারেন [`yield`-সহ ডিপেন্ডেন্সি - আগে বের হওয়া আর `scope`](../tutorial/dependencies/dependencies-with-yield.md#early-exit-and-scope)-এর ডকুমেন্টেশনে।

### `yield` আর `StreamingResponse`-সহ ডিপেন্ডেন্সি, কারিগরি বিবরণ { #dependencies-with-yield-and-streamingresponse-technical-details }

FastAPI 0.118.0-এর আগে, `yield`-সহ একটি ডিপেন্ডেন্সি ব্যবহার করলে, *পাথ অপারেশন ফাংশন* ফেরার পরে কিন্তু রেসপন্স পাঠানোর ঠিক আগে বের হওয়ার কোড চলত।

উদ্দেশ্য ছিল নেটওয়ার্কে রেসপন্স যাওয়া পর্যন্ত অপেক্ষা করে প্রয়োজনের চেয়ে বেশি সময় রিসোর্স ধরে না রাখা।

এই পরিবর্তনের আরও মানে ছিল, আপনি একটি `StreamingResponse` ফেরত দিলে `yield`-সহ ডিপেন্ডেন্সির বের হওয়ার কোড আগেই চলে যেত।

যেমন, `yield`-সহ একটি ডিপেন্ডেন্সিতে আপনার একটি ডেটাবেস সেশন থাকলে, ডেটা স্ট্রিম করার সময় `StreamingResponse` ওই সেশন ব্যবহার করতে পারত না, কারণ `yield`-এর পরের বের হওয়ার কোডে সেশনটি আগেই বন্ধ হয়ে যেত।

0.118.0-এ এই আচরণ ফিরিয়ে নেওয়া হয়েছে, যাতে `yield`-এর পরের বের হওয়ার কোড রেসপন্স পাঠানোর পরে চলে।

/// note | নোট

নিচে যেমন দেখবেন, এটি সংস্করণ 0.106.0-এর আগের আচরণের খুবই কাছাকাছি, তবে কোণের ক্ষেত্রগুলোর জন্য বেশ কিছু উন্নতি আর বাগ সংশোধনসহ।

///

#### আগেভাগে বের হওয়ার কোডের ব্যবহারের ক্ষেত্র { #use-cases-with-early-exit-code }

নির্দিষ্ট শর্তসহ কিছু ব্যবহারের ক্ষেত্র আছে, যেগুলো রেসপন্স পাঠানোর আগে `yield`-সহ ডিপেন্ডেন্সির বের হওয়ার কোড চালানোর পুরোনো আচরণ থেকে উপকৃত হতে পারে।

যেমন, কল্পনা করুন আপনার এমন কোড আছে যা `yield`-সহ একটি ডিপেন্ডেন্সিতে শুধু একজন ইউজার যাচাই করতে একটি ডেটাবেস সেশন ব্যবহার করে, কিন্তু *পাথ অপারেশন ফাংশনে* ডেটাবেস সেশনটি আর কখনো ব্যবহার হয় না, শুধু ডিপেন্ডেন্সিতে হয়, **আর** রেসপন্স পাঠাতে অনেক সময় লাগে, যেমন একটি `StreamingResponse` যা ধীরে ধীরে ডেটা পাঠায়, কিন্তু কোনো কারণে ডেটাবেস ব্যবহার করে না।

এই ক্ষেত্রে রেসপন্স পাঠানো শেষ না হওয়া পর্যন্ত ডেটাবেস সেশনটি ধরে রাখা হবে, কিন্তু আপনি যদি এটি ব্যবহার না করেন, তাহলে ধরে রাখার দরকার নেই।

এভাবে সেশনটি ডেটাবেস সংযোগ ছেড়ে দেবে, যাতে অন্য রিকোয়েস্টগুলো সেটি ব্যবহার করতে পারে। (ডেটাবেসে একসাথে সীমিত সংখ্যক সংযোগ থাকে, তাই অপ্রয়োজনে ধরে রাখলে অন্য রিকোয়েস্টকে অপেক্ষা করতে হয়।)

`yield`-সহ একটি ডিপেন্ডেন্সি থেকে আগেভাগে বের হওয়ার দরকার এমন ভিন্ন কোনো ব্যবহারের ক্ষেত্র থাকলে, অনুগ্রহ করে আপনার নির্দিষ্ট ক্ষেত্রটি আর `yield`-সহ ডিপেন্ডেন্সি আগেভাগে বন্ধ হলে কেন আপনার সুবিধা হবে তা নিয়ে একটি [GitHub Discussion Question](https://github.com/fastapi/fastapi/discussions/new?category=questions) তৈরি করুন।

`yield`-সহ ডিপেন্ডেন্সিতে আগেভাগে বন্ধ করার জোরালো ব্যবহারের ক্ষেত্র থাকলে, আমি আগেভাগে বন্ধ করা বেছে নেওয়ার একটি নতুন উপায় যোগ করার কথা ভাবব।

### `yield` আর `except`-সহ ডিপেন্ডেন্সি, কারিগরি বিবরণ { #dependencies-with-yield-and-except-technical-details }

FastAPI 0.110.0-এর আগে, `yield`-সহ একটি ডিপেন্ডেন্সি ব্যবহার করে ওই ডিপেন্ডেন্সিতে `except` দিয়ে একটি এক্সেপশন ধরে আবার রেইজ না করলে, এক্সেপশনটি স্বয়ংক্রিয়ভাবে যেকোনো এক্সেপশন হ্যান্ডলার বা অভ্যন্তরীণ সার্ভার এরর হ্যান্ডলারে রেইজ/পাঠানো হতো।

হ্যান্ডলার ছাড়া পাঠানো এক্সেপশন (অভ্যন্তরীণ সার্ভার এরর) থেকে অসামলানো মেমরি খরচ ঠিক করতে, আর সাধারণ Python কোডের আচরণের সাথে সামঞ্জস্যপূর্ণ করতে সংস্করণ 0.110.0-এ এটি বদলানো হয়েছে।

### ব্যাকগ্রাউন্ড টাস্ক আর `yield`-সহ ডিপেন্ডেন্সি, কারিগরি বিবরণ { #background-tasks-and-dependencies-with-yield-technical-details }

FastAPI 0.106.0-এর আগে, `yield`-এর পরে এক্সেপশন রেইজ করা সম্ভব ছিল না, `yield`-সহ ডিপেন্ডেন্সির বের হওয়ার কোড রেসপন্স পাঠানোর *পরে* চলত, তাই [এক্সেপশন হ্যান্ডলারগুলো](../tutorial/handling-errors.md#install-custom-exception-handlers) আগেই চলে যেত।

এটি মূলত এভাবে ডিজাইন করা হয়েছিল, যাতে ব্যাকগ্রাউন্ড টাস্কের ভেতরে ডিপেন্ডেন্সিগুলোর "yield করা" একই অবজেক্ট ব্যবহার করা যায়, কারণ বের হওয়ার কোড ব্যাকগ্রাউন্ড টাস্ক শেষ হওয়ার পরে চলত।

নেটওয়ার্কে রেসপন্স যাওয়ার অপেক্ষায় রিসোর্স ধরে না রাখার উদ্দেশ্যে FastAPI 0.106.0-এ এটি বদলানো হয়েছে।

/// tip | পরামর্শ

এছাড়া একটি ব্যাকগ্রাউন্ড টাস্ক সাধারণত একটি স্বাধীন লজিক, যা আলাদাভাবে, নিজস্ব রিসোর্স (যেমন নিজস্ব ডেটাবেস সংযোগ) দিয়ে সামলানো উচিত।

তাই এভাবে আপনার কোড সম্ভবত আরও পরিচ্ছন্ন হবে।

///

আপনি যদি আগে এই আচরণের ওপর নির্ভর করতেন, তাহলে এখন ব্যাকগ্রাউন্ড টাস্কের রিসোর্সগুলো ব্যাকগ্রাউন্ড টাস্কের ভেতরেই তৈরি করা উচিত, আর ভেতরে শুধু এমন ডেটা ব্যবহার করা উচিত যা `yield`-সহ ডিপেন্ডেন্সির রিসোর্সের ওপর নির্ভর করে না।

যেমন, একই ডেটাবেস সেশন ব্যবহার না করে, আপনি ব্যাকগ্রাউন্ড টাস্কের ভেতরে একটি নতুন ডেটাবেস সেশন তৈরি করবেন, আর এই নতুন সেশন দিয়ে ডেটাবেস থেকে অবজেক্টগুলো আনবেন। আর তারপর ডেটাবেসের অবজেক্টটি ব্যাকগ্রাউন্ড টাস্ক ফাংশনে প্যারামিটার হিসেবে না দিয়ে, ওই অবজেক্টের ID দেবেন, আর তারপর ব্যাকগ্রাউন্ড টাস্ক ফাংশনের ভেতরে আবার অবজেক্টটি আনবেন।

/// check | সংক্ষেপে মনে রাখুন

* প্যারামিটারযুক্ত ডিপেন্ডেন্সি: একটি ক্লাসে `__init__` (সেটিংস) আর `__call__` (প্রতিটি রিকোয়েস্টের কাজ), তারপর `Depends(MyChecker("value"))`।
* `yield`-সহ ডিপেন্ডেন্সির বের হওয়ার কোড ডিফল্টভাবে রেসপন্স পাঠানোর পরে চলে, আগে চাইলে `scope="function"`।
* ব্যাকগ্রাউন্ড টাস্কে ডিপেন্ডেন্সির সেশন না পাঠিয়ে ID পাঠান, আর ভেতরে নতুন সেশন খুলুন।
