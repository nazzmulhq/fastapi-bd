# OpenAPI কলব্যাক { #openapi-callbacks }

/// note | এই পেজে যা শিখবেন

* "কলব্যাক" কী: আপনার API যখন উল্টো দিকে অন্যের API-তে রিকোয়েস্ট পাঠায়।
* কীভাবে ডকুমেন্টেশনে দেখাবেন যে ওই বাইরের API দেখতে কেমন হওয়া উচিত।
* `APIRouter` দিয়ে কলব্যাক পাথ অপারেশন লেখা আর `callbacks=` দিয়ে যুক্ত করা।

///

আপনি এমন একটি API তৈরি করতে পারেন যার একটি *পাথ অপারেশন* অন্য কারো তৈরি একটি *বাইরের API*-তে (সম্ভবত সেই ডেভেলপারেরই, যিনি আপনার API *ব্যবহার* করবেন) একটি রিকোয়েস্ট পাঠাতে পারে।

আপনার API অ্যাপ যখন *বাইরের API*-কে কল করে, সেই প্রক্রিয়াকে বলে "কলব্যাক" (callback)। কারণ বাইরের ডেভেলপারের লেখা সফটওয়্যার আপনার API-তে একটি রিকোয়েস্ট পাঠায়, তারপর আপনার API *ফিরতি কল করে* (*calls back*), একটি *বাইরের API*-তে (সম্ভবত একই ডেভেলপারের তৈরি) রিকোয়েস্ট পাঠিয়ে।

এই ক্ষেত্রে, আপনি হয়তো ডকুমেন্ট করতে চাইবেন যে ওই বাইরের API দেখতে কেমন *হওয়া উচিত*। এর কোন *পাথ অপারেশন* থাকা উচিত, কোন বডি আশা করা উচিত, কোন রেসপন্স ফেরত দেওয়া উচিত, ইত্যাদি।

/// tip | উদাহরণ দিয়ে বুঝি

আপনি দর্জির দোকানে জামা বানাতে দিলেন আর বললেন, "তৈরি হলে এই নম্বরে ফোন দেবেন।" এখানে দর্জি (আপনার API) কাজ শেষে আপনাকে (বাইরের API) ফোন দেবে, এটাই কলব্যাক। দর্জির রসিদে যদি লেখা থাকে "আমরা ফোন করে অর্ডার নম্বর বলব, আপনি শুধু 'ঠিক আছে' বলবেন", সেটা হলো কলব্যাকের ডকুমেন্টেশন। এই পেজ সেই রসিদ লেখা শেখায়।

///

## কলব্যাকসহ একটি অ্যাপ { #an-app-with-callbacks }

চলুন একটি উদাহরণ দিয়ে এগুলো দেখি।

ধরুন আপনি একটি অ্যাপ বানাচ্ছেন যা দিয়ে ইনভয়েস (বিল) তৈরি করা যায়।

এই ইনভয়েসগুলোর থাকবে একটি `id`, `title` (ঐচ্ছিক), `customer` আর `total`।

আপনার API-র ব্যবহারকারী (একজন বাইরের ডেভেলপার) একটি POST রিকোয়েস্ট দিয়ে আপনার API-তে একটি ইনভয়েস তৈরি করবেন।

তারপর আপনার API (ধরে নিই):

* বাইরের ডেভেলপারের কোনো গ্রাহকের কাছে ইনভয়েসটি পাঠাবে।
* টাকা সংগ্রহ করবে।
* API ব্যবহারকারীকে (বাইরের ডেভেলপার) একটি নোটিফিকেশন ফেরত পাঠাবে।
    * এটি করা হবে ওই বাইরের ডেভেলপারের দেওয়া কোনো *বাইরের API*-তে (*আপনার API* থেকে) একটি POST রিকোয়েস্ট পাঠিয়ে (এটাই "কলব্যাক")।

## কলব্যাক ডকুমেন্ট করা { #documenting-the-callback }

আসল কলব্যাক কোড অনেকটাই আপনার নিজের API অ্যাপের ওপর নির্ভর করবে।

আর এটি সম্ভবত এক অ্যাপ থেকে আরেক অ্যাপে অনেক আলাদা হবে।

এটি হতে পারে মাত্র এক বা দুই লাইনের কোড, যেমন:

```Python
callback_url = "https://example.com/api/v1/invoices/events/"
httpx.post(callback_url, json={"description": "Invoice paid", "paid": True})
```

কিন্তু সম্ভবত কলব্যাকের সবচেয়ে গুরুত্বপূর্ণ অংশ হলো নিশ্চিত করা যে আপনার API ব্যবহারকারী (বাইরের ডেভেলপার) *বাইরের API*-টি সঠিকভাবে তৈরি করেছেন, *আপনার API* কলব্যাকের রিকোয়েস্ট বডিতে যে ডেটা পাঠাবে সেই অনুযায়ী, ইত্যাদি।

তাই এরপর আমরা কোড যোগ করব যা ডকুমেন্ট করবে, *আপনার API* থেকে কলব্যাক গ্রহণ করতে ওই *বাইরের API* দেখতে কেমন হওয়া উচিত।

সেই ডকুমেন্টেশন আপনার API-র `/docs`-এ Swagger UI-তে দেখাবে, আর বাইরের ডেভেলপাররা জানতে পারবেন কীভাবে *বাইরের API* তৈরি করতে হবে।

এই উদাহরণে কলব্যাক নিজে বাস্তবায়ন করা হয়নি (সেটি হয়তো মাত্র এক লাইনের কোড), শুধু ডকুমেন্টেশনের অংশটি।

/// tip | পরামর্শ

আসল কলব্যাক শুধুই একটি HTTP রিকোয়েস্ট।

নিজে কলব্যাক বাস্তবায়ন করার সময় [HTTPX](https://www.python-httpx.org) বা [Requests](https://requests.readthedocs.io/)-এর মতো কিছু ব্যবহার করতে পারেন।

///

## কলব্যাক ডকুমেন্টেশনের কোড লিখুন { #write-the-callback-documentation-code }

এই কোড আপনার অ্যাপে চালানো হবে না, ওই *বাইরের API* দেখতে কেমন হওয়া উচিত তা শুধু *ডকুমেন্ট* করতে আমাদের এটি দরকার।

কিন্তু আপনি তো ইতিমধ্যে জানেন **FastAPI** দিয়ে কীভাবে সহজে একটি API-র স্বয়ংক্রিয় ডকুমেন্টেশন তৈরি করতে হয়।

তাই *বাইরের API* দেখতে কেমন হওয়া উচিত তা ডকুমেন্ট করতে আমরা সেই একই জ্ঞান ব্যবহার করব... বাইরের API-র যে *পাথ অপারেশন(গুলো)* বাস্তবায়ন করা উচিত (যেগুলো আপনার API কল করবে), সেগুলো তৈরি করে।

/// tip | পরামর্শ

কলব্যাক ডকুমেন্ট করার কোড লেখার সময় কল্পনা করা কাজে লাগতে পারে যে আপনিই সেই *বাইরের ডেভেলপার*। আর আপনি এখন *আপনার API* নয়, *বাইরের API* বাস্তবায়ন করছেন।

সাময়িকভাবে এই দৃষ্টিভঙ্গি (*বাইরের ডেভেলপারের*) গ্রহণ করলে আরও স্পষ্ট মনে হতে পারে যে ওই *বাইরের API*-র জন্য প্যারামিটার, বডির Pydantic মডেল, রেসপন্সের মডেল ইত্যাদি কোথায় বসাতে হবে।

### কলব্যাক *পাথ অপারেশন* তৈরি করুন { #create-the-callback-path-operation }

কলব্যাক *পাথ অপারেশন* তৈরি করতে ওপরে তৈরি করা একই `APIRouter` ব্যবহার করুন।

এটি দেখতে হুবহু একটি সাধারণ FastAPI *পাথ অপারেশনের* মতো হবে:

* এটি সম্ভবত যে বডি গ্রহণ করা উচিত তার একটি ঘোষণা রাখবে, যেমন `body: InvoiceEvent`।
* আর যে রেসপন্স ফেরত দেওয়া উচিত তার ঘোষণাও রাখতে পারে, যেমন `response_model=InvoiceEventReceived`।

///

সাধারণ একটি *পাথ অপারেশন* থেকে এর ২টি মূল পার্থক্য আছে:

* এতে কোনো আসল কোড থাকার দরকার নেই, কারণ আপনার অ্যাপ কখনো এই কোড কল করবে না। এটি শুধু *বাইরের API* ডকুমেন্ট করতে ব্যবহার হয়। তাই ফাংশনে শুধু `pass` থাকতে পারে।
* *পাথে* একটি [OpenAPI 3 এক্সপ্রেশন](https://github.com/OAI/OpenAPI-Specification/blob/main/versions/3.1.0.md#key-expression) থাকতে পারে (নিচে আরও দেখুন), যেখানে *আপনার API*-তে পাঠানো মূল রিকোয়েস্টের প্যারামিটার আর অংশগুলো ভেরিয়েবল হিসেবে ব্যবহার করা যায়।

### কলব্যাক পাথ এক্সপ্রেশন { #the-callback-path-expression }

কলব্যাক *পাথে* একটি [OpenAPI 3 এক্সপ্রেশন](https://github.com/OAI/OpenAPI-Specification/blob/main/versions/3.1.0.md#key-expression) থাকতে পারে, যাতে *আপনার API*-তে পাঠানো মূল রিকোয়েস্টের অংশ থাকতে পারে।

এই ক্ষেত্রে, এটি এই `str`:

```Python
"{$callback_url}/invoices/{$request.body.id}"
```


### কলব্যাক রাউটার যোগ করুন { #add-the-callback-router }

এই পর্যায়ে ওপরে তৈরি করা কলব্যাক রাউটারে আপনার দরকারি *কলব্যাক পাথ অপারেশন(গুলো)* আছে (যেগুলো *বাইরের ডেভেলপারের* *বাইরের API*-তে বাস্তবায়ন করা উচিত)।

এখন *আপনার API-র পাথ অপারেশন ডেকোরেটরে* `callbacks` প্যারামিটার ব্যবহার করে ওই কলব্যাক রাউটারের `.routes` অ্যাট্রিবিউটটি দিন:

{* ../../docs_src/openapi_callbacks/tutorial001_py310.py hl[33] *}

/// tip | পরামর্শ

লক্ষ্য করুন, আপনি `callbacks=`-এ রাউটারটি নিজে (`invoices_callback_router`) দিচ্ছেন না, দিচ্ছেন এর `.routes`, যেমন `invoices_callback_router.routes`। FastAPI ওই রাউটগুলো ব্যবহার করে কলব্যাকের OpenAPI ডকুমেন্টেশন তৈরি করবে।

### ডকস দেখুন { #check-the-docs }

এখন অ্যাপ চালু করে [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)-এ যান।

আপনার ডকসে আপনার *পাথ অপারেশনের* জন্য একটি "Callbacks" অংশ দেখবেন, যা দেখায় *বাইরের API* দেখতে কেমন হওয়া উচিত:

<img src="/img/tutorial/openapi-callbacks/image01.png">

/// check | সংক্ষেপে মনে রাখুন

* কলব্যাক = আপনার API যখন কাজ শেষে ক্লায়েন্টের দেওয়া URL-এ রিকোয়েস্ট পাঠায়।
* একটি আলাদা `APIRouter`-এ "বাইরের API দেখতে কেমন হবে" তা পাথ অপারেশন হিসেবে লিখুন (বডিতে শুধু `pass`)।
* পাথে `{$callback_url}`, `{$request.body.id}` এর মতো এক্সপ্রেশন দিয়ে মূল রিকোয়েস্টের মান ব্যবহার করা যায়।
* `callbacks=router.routes` দিয়ে যুক্ত করলে `/docs`-এ "Callbacks" অংশ দেখা যায়।
