# ইতিহাস, ডিজাইন এবং ভবিষ্যৎ { #history-design-and-future }

/// note | এই পেজে যা জানবেন

FastAPI-এর জন্মকথা: নির্মাতা কেন নতুন একটি ফ্রেমওয়ার্ক বানালেন, তৈরির আগে কী কী গবেষণা করলেন, কোন সিদ্ধান্ত কেন নিলেন, আর সামনে কী আসছে। নির্মাতা নিজেই প্রথম পুরুষে ("আমি") লিখেছেন।

///

কিছুদিন আগে, [একজন **FastAPI** ব্যবহারকারী জিজ্ঞেস করেছিলেন](https://github.com/fastapi/fastapi/issues/3#issuecomment-454956920):

> এই প্রজেক্টের ইতিহাস কী? মনে হচ্ছে কয়েক সপ্তাহের মধ্যে কোথাও থেকে না এসে এটি দারুণ কিছু হয়ে গেছে [...]

এখানে সেই ইতিহাসের সামান্য কিছু বলা হলো।

## বিকল্পগুলো { #alternatives }

আমি কয়েক বছর ধরে জটিল প্রয়োজনসহ API তৈরি করে আসছি (মেশিন লার্নিং, বিতরণকৃত সিস্টেম, অ্যাসিঙ্ক্রোনাস কাজ, NoSQL ডেটাবেস ইত্যাদি), ডেভেলপারদের কয়েকটি দলকে নেতৃত্ব দিয়ে।

এর অংশ হিসেবে, আমাকে অনেক বিকল্প খুঁজে দেখতে, পরীক্ষা করতে আর ব্যবহার করতে হয়েছে।

**FastAPI**-এর ইতিহাস অনেকাংশেই এর পূর্বসূরিদের ইতিহাস।

[বিকল্প](alternatives.md) অংশে যেমন বলা হয়েছে:

<blockquote markdown="1">

অন্যদের আগের কাজ না থাকলে **FastAPI**-এর অস্তিত্বই থাকত না।

আগে অনেক টুল তৈরি হয়েছে, যা এটি তৈরিতে অনুপ্রেরণা দিয়েছে।

আমি কয়েক বছর ধরে একটি নতুন ফ্রেমওয়ার্ক তৈরি এড়িয়ে চলছিলাম। প্রথমে আমি **FastAPI**-এর সব ফিচার অনেকগুলো ভিন্ন ফ্রেমওয়ার্ক, প্লাগ-ইন আর টুল দিয়ে সমাধান করার চেষ্টা করেছিলাম।

কিন্তু এক পর্যায়ে, আগের টুলগুলোর সেরা ধারণাগুলো নিয়ে, আগে উপলব্ধই ছিল না এমন ভাষার ফিচার (Python 3.6+ টাইপ হিন্ট) ব্যবহার করে, সেগুলো সম্ভাব্য সেরা উপায়ে মিলিয়ে, এই সব ফিচার দেয় এমন কিছু তৈরি করা ছাড়া আর কোনো উপায় ছিল না।

</blockquote>

## অনুসন্ধান { #investigation }

আগের সব বিকল্প ব্যবহার করে আমি সবগুলো থেকে শেখার, ধারণা নেওয়ার, আর আমার নিজের ও যেসব ডেভেলপার দলের সাথে কাজ করেছি তাদের জন্য আমার খুঁজে পাওয়া সেরা উপায়ে সেগুলো মেলানোর সুযোগ পেয়েছি।

যেমন, এটা স্পষ্ট ছিল যে আদর্শভাবে এটি স্ট্যান্ডার্ড Python টাইপ হিন্টের ওপর ভিত্তি করে হওয়া উচিত।

এ ছাড়া, সবচেয়ে ভালো পদ্ধতি ছিল ইতিমধ্যে বিদ্যমান স্ট্যান্ডার্ডগুলো ব্যবহার করা।

তাই **FastAPI**-এর কোড লেখা শুরুর আগেই, আমি কয়েক মাস ধরে OpenAPI, JSON Schema, OAuth2 ইত্যাদির স্পেসিফিকেশন পড়েছি। এদের সম্পর্ক, মিল আর পার্থক্য বুঝেছি।

/// tip | এ থেকে কী শেখার আছে

ভালো সফটওয়্যার শুধু কোড লিখে হয় না। FastAPI-এর নির্মাতা কোড লেখার আগে মাসের পর মাস অন্যদের টুল ব্যবহার করেছেন, স্ট্যান্ডার্ড পড়েছেন, এডিটরে পরীক্ষা করেছেন। নিজের প্রজেক্টেও আগে সমস্যা আর বিদ্যমান সমাধানগুলো ভালো করে বুঝে নেওয়া বড় সুফল দেয়।

///

## ডিজাইন { #design }

তারপর আমি কিছু সময় ব্যয় করেছি একজন ব্যবহারকারী হিসেবে (FastAPI ব্যবহারকারী একজন ডেভেলপার হিসেবে) যে ডেভেলপার "API" আমি চাইতাম তা ডিজাইন করতে।

আমি সবচেয়ে জনপ্রিয় Python এডিটরগুলোতে কয়েকটি ধারণা পরীক্ষা করেছি: PyCharm, VS Code, Jedi-ভিত্তিক এডিটর।

সর্বশেষ [Python Developer Survey](https://www.jetbrains.com/research/python-developers-survey-2018/#development-tools) অনুযায়ী, এগুলো প্রায় ৮০% ব্যবহারকারীকে কভার করে।

এর মানে **FastAPI** বিশেষভাবে সেই এডিটরগুলোতে পরীক্ষা করা হয়েছে যা ৮০% Python ডেভেলপার ব্যবহার করেন। আর যেহেতু অন্যান্য বেশিরভাগ এডিটরও একইভাবে কাজ করার প্রবণতা রাখে, তাই এর সব সুবিধা কার্যত সব এডিটরেই কাজ করা উচিত।

এভাবে আমি কোডের পুনরাবৃত্তি যতটা সম্ভব কমানোর, সব জায়গায় completion পাওয়ার, টাইপ আর এরর যাচাই ইত্যাদির সেরা উপায় খুঁজে পেয়েছি।

সবই এমনভাবে যাতে সব ডেভেলপারের জন্য সেরা ডেভেলপমেন্ট অভিজ্ঞতা পাওয়া যায়।

## প্রয়োজনীয়তা { #requirements }

কয়েকটি বিকল্প পরীক্ষা করার পরে, আমি এর সুবিধাগুলোর জন্য [**Pydantic**](https://pydantic.dev/docs/) ব্যবহারের সিদ্ধান্ত নিই।

তারপর আমি এতে অবদান রেখেছি, যাতে এটি JSON Schema-র সাথে সম্পূর্ণ সামঞ্জস্যপূর্ণ হয়, শর্ত ঘোষণার বিভিন্ন উপায় সাপোর্ট করে, আর কয়েকটি এডিটরে পরীক্ষার ভিত্তিতে এডিটর সাপোর্ট (টাইপ যাচাই, autocompletion) উন্নত হয়।

ডেভেলপমেন্টের সময়, আমি আরেকটি মূল প্রয়োজনীয় অংশ [**Starlette**](https://starlette.dev/)-এও অবদান রেখেছি।

## ডেভেলপমেন্ট { #development }

যখন আমি **FastAPI** নিজেই তৈরি শুরু করি, ততদিনে বেশিরভাগ অংশ জায়গামতো ছিল, ডিজাইন নির্ধারিত ছিল, প্রয়োজনীয়তা আর টুল প্রস্তুত ছিল, আর স্ট্যান্ডার্ড ও স্পেসিফিকেশন সম্পর্কে জ্ঞান ছিল স্পষ্ট আর তাজা।

## ভবিষ্যৎ { #future }

এই পর্যায়ে এসে, এটা ইতিমধ্যে স্পষ্ট যে **FastAPI** তার ধারণাগুলো নিয়ে অনেক মানুষের কাজে লাগছে।

অনেক ক্ষেত্রে আরও ভালোভাবে মানানসই হওয়ায় আগের বিকল্পগুলোর বদলে এটিকে বেছে নেওয়া হচ্ছে।

অনেক ডেভেলপার আর দল ইতিমধ্যে তাদের প্রজেক্টের জন্য **FastAPI**-এর ওপর নির্ভর করছে (আমি আর আমার দলসহ)।

তবুও, আরও অনেক উন্নতি আর ফিচার আসছে।

**FastAPI**-এর সামনে এক দারুণ ভবিষ্যৎ।

আর [আপনার সাহায্য](help-fastapi.md) খুবই প্রশংসিত।
