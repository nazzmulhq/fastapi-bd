# Pydantic AI-এর এন্টারপ্রাইজ সাপোর্ট { #enterprise-support-for-pydantic-ai }

/// note | এই পেজে যা শিখবেন

Pydantic AI-এর জন্য বাণিজ্যিক (পেইড) সাপোর্ট কী দেয়, কীভাবে কাজ করে, আর open source অংশ কেন সবার জন্য খোলা থাকে।

///

Pydantic AI MIT লাইসেন্সে open source। এটি যখন একটি গুরুত্বপূর্ণ এজেন্ট সিস্টেমের অংশ হয়ে যায়, তখন কোনো দুর্ঘটনা (incident), প্রোভাইডার বদল বা বড় রোলআউটের সময় একটি প্রকাশ্য issue tracker সেই পথ নয়, যেখানে আপনি জরুরি সমস্যা নিয়ে যেতে চাইবেন।

বাণিজ্যিক সাপোর্ট আপনার দলকে প্রোডাকশনের দুর্ঘটনা, কাঠামো, প্রোভাইডার বদল আর আপগ্রেডের জন্য সরাসরি Pydantic AI ইঞ্জিনিয়ারদের কাছে পৌঁছানোর সুযোগ দেয়। এন্টারপ্রাইজ প্ল্যানে আছে ২৪/৭ অগ্রাধিকারভিত্তিক সাপোর্ট, সেটআপে সহায়তা, আর আপনার কাজের ধরনের সাথে মেলানো একটি SLA। কোনো দুর্বলতা (vulnerability) চুক্তিভুক্ত রিলিজ লাইনে প্রভাব ফেললে আমরা কীভাবে সমন্বয় করব, তাও আপনার চুক্তিতে ঠিক করা যায়।

[Pydantic AI সাপোর্ট নিয়ে আলোচনা করুন](https://pydantic.dev/contact){ .md-button .md-button--primary }


## Pydantic AI ইঞ্জিনিয়াররা কোথায় সাহায্য করতে পারেন { #where-pydantic-ai-engineers-can-help }

সাধারণ প্রশ্নের জন্য প্রকাশ্য ডকুমেন্টেশন, issue tracker আর কমিউনিটি চ্যানেল ব্যবহার করুন। এন্টারপ্রাইজ সাপোর্টে আছে প্রোডাকশনের দুর্ঘটনা, এজেন্টের কাঠামো পর্যালোচনা, framework বা প্রোভাইডার রোলআউট, আর সমন্বিত দুর্বলতা-প্রতিক্রিয়া।


## সাপোর্ট কীভাবে কাজ করে { #how-support-works }


1. **সাপোর্টের সীমা ঠিক করা**

   আপনার চুক্তিতে কোন framework আর প্রোভাইডার integration, রিলিজ লাইন, পরিবেশ, পরিচালনা আর নিরাপত্তার যোগাযোগকারী, আর প্রাথমিক সাড়া দেওয়ার লক্ষ্য থাকবে, তা সংজ্ঞায়িত করুন।

2. **দরকারি প্রেক্ষাপট প্রস্তুত রাখা**

   গুরুত্বপূর্ণ এজেন্ট পথগুলো চিহ্নিত করুন, আর ঠিক করুন কীভাবে আবার ঘটানো যায় এমন উদাহরণ, মডেলের ইনপুট-আউটপুট, trace, কনফিগারেশন আর সাম্প্রতিক পরিবর্তন সংগ্রহ করবেন।

3. **সরাসরি জানানো**

   প্রোডাকশনে প্রভাব ফেলা সমস্যা বা সন্দেহজনক দুর্বলতা চুক্তিতে ঠিক করা ব্যক্তিগত চ্যানেলে Pydantic AI ইঞ্জিনিয়ারদের কাছে আনুন। ব্যর্থ অংশটি আলাদা করতে আর পরের করণীয় ঠিক করতে আমরা আপনার দলের সাথে কাজ করি।


## open source-ই ভিত্তি { #open-source-remains-the-foundation }

Pydantic AI-এর লাইসেন্স, ডকুমেন্টেশন, রিলিজ, issue tracker আর কমিউনিটি সাপোর্ট সবার জন্য খোলা থাকে। এন্টারপ্রাইজ সাপোর্ট শুধু সেই দলগুলোর জন্য একটি সরাসরি পথ আর চুক্তিভিত্তিক প্রতিশ্রুতি যোগ করে, যারা প্রোডাকশনে framework-টির ওপর নির্ভর করে।

## দলগুলো যা জিজ্ঞাসা করে { #questions-teams-ask }

/// details | Logfire কি বাধ্যতামূলক?
    type: note

না। বাণিজ্যিক সাপোর্ট open-source Pydantic AI framework-এর জন্যই পাওয়া যায়। Logfire trace তদন্ত দ্রুত করতে পারে, কিন্তু Logfire বাধ্যতামূলক নয়।

///

/// details | Pydantic AI ইঞ্জিনিয়াররা কী কী তদন্তে সাহায্য করতে পারেন?
    type: note

সমস্যাটি আবার ঘটাতে, Pydantic AI-এর আচরণ আলাদা করতে, সংশ্লিষ্ট বাস্তবায়নের খুঁটিনাটি ব্যাখ্যা করতে আর পরের করণীয় ঠিক করতে আমরা আপনার ইঞ্জিনিয়ারদের সাথে কাজ করি। আশেপাশের অ্যাপ্লিকেশন আর মডেল সেবার মালিকানা আপনার দল আর প্রোভাইডারেরই থাকে।

///

/// details | নির্দিষ্ট সংস্করণ আর প্রাথমিক সাড়ার লক্ষ্য কি ঠিক করা যায়?
    type: note

হ্যাঁ। সমর্থিত সংস্করণ, গুরুত্বের স্তর, প্রাথমিক সাড়ার লক্ষ্য আর অন্য প্রতিশ্রুতি আপনার বাণিজ্যিক চুক্তিতে সংজ্ঞায়িত হয়। আপনার প্রয়োজন নিয়ে আলোচনা করতে [যোগাযোগ করুন](https://pydantic.dev/contact)।

///

/// details | নিরাপত্তা দুর্বলতা কীভাবে সামলানো হয়?
    type: note

যে কেউ Pydantic AI-এর [নিরাপত্তা জানানোর প্রক্রিয়া](https://github.com/pydantic/pydantic-ai/security/policy) দিয়ে গোপনে একটি সন্দেহজনক দুর্বলতা জানাতে পারেন। চুক্তিভুক্ত রিলিজ লাইনে প্রভাব ফেলা নিশ্চিত সমস্যার ক্ষেত্রে, এন্টারপ্রাইজ সাপোর্ট নির্দিষ্ট নিরাপত্তা যোগাযোগকারী আর প্রভাব মূল্যায়ন, প্রতিকার, সংশোধিত রিলিজ ও প্রকাশে সমন্বিত কাজ যোগ করে। উপযুক্ত ক্ষেত্রে advisory আর CVE প্রকাশ করা হয়; জানানো আর সাড়ার প্রতিশ্রুতি আপনার চুক্তিতে সংজ্ঞায়িত।
