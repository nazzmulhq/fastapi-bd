ডিপেন্ডেন্সি¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা শিখবেন

  • "ডিপেন্ডেন্সি ইনজেকশন" আসলে কী, সহজ ভাষায় আর উদাহরণ দিয়ে।
  • একটি ডিপেন্ডেন্সি ফাংশন বানিয়ে Depends দিয়ে কীভাবে ব্যবহার করবেন।
  • Annotated দিয়ে একই ডিপেন্ডেন্সি বারবার ছোট করে লেখা।
  • কেন এই ব্যবস্থা এত শক্তিশালী: কোড পুনঃব্যবহার, সিকিউরিটি, ডেটাবেস সংযোগ।

FastAPI-তে একটি খুবই শক্তিশালী কিন্তু সহজবোধ্য ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা আছে।

এটি এমনভাবে ডিজাইন করা যাতে ব্যবহার করা খুব সহজ হয়, আর যেকোনো ডেভেলপার খুব সহজে অন্য অংশগুলো FastAPI-এর সাথে যুক্ত করতে পারেন।

"ডিপেন্ডেন্সি ইনজেকশন" কী¶

প্রোগ্রামিংয়ে "ডিপেন্ডেন্সি ইনজেকশন" মানে হলো, আপনার কোডের (এই ক্ষেত্রে আপনার পাথ অপারেশন ফাংশনের) এমন একটি উপায় আছে, যা দিয়ে সে ঘোষণা করতে পারে কাজ করতে আর ব্যবহার করতে তার কী কী লাগবে: "ডিপেন্ডেন্সি" (নির্ভরতা)।

তারপর সেই ব্যবস্থাটি (এই ক্ষেত্রে FastAPI) আপনার কোডকে সেই প্রয়োজনীয় ডিপেন্ডেন্সিগুলো দেওয়ার জন্য যা দরকার তা করার দায়িত্ব নেবে (ডিপেন্ডেন্সিগুলো "ইনজেক্ট" করবে, মানে ঢুকিয়ে দেবে)।

উদাহরণ দিয়ে বুঝি

একজন রাঁধুনির কথা ভাবুন। রান্না শুরুর আগে তিনি একটি তালিকা দেন: "আমার লাগবে কাটা পেঁয়াজ, গরম তেল, ধোয়া চাল"। একজন সহকারী সেগুলো প্রস্তুত করে রাঁধুনির হাতে দিয়ে যায়। রাঁধুনিকে নিজে পেঁয়াজ কাটতে হয় না, তিনি শুধু বলেন কী লাগবে।

  • রাঁধুনি = আপনার পাথ অপারেশন ফাংশন।
  • "কী লাগবে" তালিকা = Depends(...)।
  • সহকারী = FastAPI, যে ডিপেন্ডেন্সি ফাংশন চালিয়ে ফলাফল হাতে তুলে দেয়।

আর একই সহকারী (ডিপেন্ডেন্সি) দশজন রাঁধুনির জন্য একই কাজ করতে পারে। একবার লিখলেই সবখানে ব্যবহার।

এটি খুবই কাজের যখন আপনার দরকার:

  • একই লজিক ভাগাভাগি করা (একই কোড লজিক বারবার)।
  • ডেটাবেস সংযোগ ভাগাভাগি করা।
  • সিকিউরিটি, অথেনটিকেশন (লগইন যাচাই), রোলের শর্ত (যেমন শুধু অ্যাডমিন) ইত্যাদি প্রয়োগ করা।
  • এবং আরও অনেক কিছু...

এসবই, কোডের পুনরাবৃত্তি যতটা সম্ভব কমিয়ে।

প্রথম ধাপ¶

খুব সহজ একটি উদাহরণ দেখা যাক। এটি এতটাই সহজ যে আপাতত খুব একটা কাজের নয়।

তবে এভাবে আমরা ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা কীভাবে কাজ করে তাতে মনোযোগ দিতে পারব।

একটি ডিপেন্ডেন্সি, বা "dependable" তৈরি করুন¶

প্রথমে ডিপেন্ডেন্সিটিতে মনোযোগ দেওয়া যাক।

এটি শুধু একটি ফাংশন, যা একটি পাথ অপারেশন ফাংশন যে সব প্যারামিটার নিতে পারে, ঠিক সেগুলোই নিতে পারে:

from typing import Annotated

from fastapi import Depends, FastAPI

app = FastAPI()


async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}


@app.get("/items/")
async def read_items(commons: Annotated[dict, Depends(common_parameters)]):
    return commons


@app.get("/users/")
async def read_users(commons: Annotated[dict, Depends(common_parameters)]):
    return commons

ব্যাস।

২ লাইন।

আর এর আকার ও গঠন আপনার সব পাথ অপারেশন ফাংশনের মতোই।

এটিকে "ডেকোরেটর" ছাড়া (@app.get("/some-path") ছাড়া) একটি পাথ অপারেশন ফাংশন হিসেবে ভাবতে পারেন।

আর এটি যা খুশি রিটার্ন করতে পারে।

এই ক্ষেত্রে, এই ডিপেন্ডেন্সিটি আশা করে:

  • একটি ঐচ্ছিক কুয়েরি প্যারামিটার q, যা একটি str।
  • একটি ঐচ্ছিক কুয়েরি প্যারামিটার skip, যা একটি int, আর ডিফল্টভাবে 0।
  • একটি ঐচ্ছিক কুয়েরি প্যারামিটার limit, যা একটি int, আর ডিফল্টভাবে 100।

তারপর এটি শুধু ওই মানগুলোসহ একটি dict রিটার্ন করে।

"dependant"-এ ডিপেন্ডেন্সিটি ঘোষণা করুন¶

আপনার পাথ অপারেশন ফাংশনের প্যারামিটারে যেভাবে Body, Query ইত্যাদি ব্যবহার করেন, সেভাবেই একটি নতুন প্যারামিটারে Depends ব্যবহার করুন:

from typing import Annotated

from fastapi import Depends, FastAPI

app = FastAPI()


async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}


@app.get("/items/")
async def read_items(commons: Annotated[dict, Depends(common_parameters)]):
    return commons


@app.get("/users/")
async def read_users(commons: Annotated[dict, Depends(common_parameters)]):
    return commons

from fastapi import Depends, FastAPI

app = FastAPI()


async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}


@app.get("/items/")

    return commons


@app.get("/users/")
async def read_users(commons: dict = Depends(common_parameters)):
    return commons

পুরো কোডটি সহজ ভাষায়

  • লাইন ৮-৯: common_parameters ফাংশন তিনটি কুয়েরি প্যারামিটার নেয় আর একটি ডিকশনারিতে ভরে ফেরত দেয়।
  • লাইন ১৩: commons: Annotated[dict, Depends(common_parameters)] মানে: "read_items চালানোর আগে common_parameters চালাও, আর এর ফলাফল commons-এ দাও"।
  • লাইন ১৪: commons ফেরত দেওয়া হলো।
  • লাইন ১৮: read_users-ও একই ডিপেন্ডেন্সি ব্যবহার করছে।

তাই /items/?q=book&limit=5 খুললে পাবেন {"q": "book", "skip": 0, "limit": 5}। q, skip, limit তিনটি প্যারামিটার একবার লিখে দুটি পাথ অপারেশনে ব্যবহার হলো।

যদিও আপনার ফাংশনের প্যারামিটারে Depends ঠিক Body, Query ইত্যাদির মতো করেই ব্যবহার করেন, তবুও Depends একটু আলাদাভাবে কাজ করে।

Depends-কে শুধু একটিমাত্র প্যারামিটার দেন।

এই প্যারামিটারটি অবশ্যই একটি ফাংশনের মতো কিছু হতে হবে।

এটি আপনি সরাসরি ডাকবেন না (শেষে বন্ধনী () দেবেন না), শুধু Depends()-এর একটি প্যারামিটার হিসেবে দেবেন।

সাধারণ ভুল

Depends(common_parameters()) লিখবেন না, লিখুন Depends(common_parameters)। বন্ধনী দিলে ফাংশনটি তখনই একবার চলে যায়, আর FastAPI প্রতিটি রিকোয়েস্টে এটিকে চালাতে পারে না।

আর ওই ফাংশন পাথ অপারেশন ফাংশনের মতো একইভাবে প্যারামিটার নেয়।

পরামর্শ

ফাংশন ছাড়া আর কোন কোন "জিনিস" ডিপেন্ডেন্সি হিসেবে ব্যবহার করা যায় তা পরের অধ্যায়ে দেখবেন।

যখনই একটি নতুন রিকোয়েস্ট আসে, FastAPI এই কাজগুলোর দায়িত্ব নেয়:

  • সঠিক প্যারামিটার দিয়ে আপনার ডিপেন্ডেন্সি ("dependable") ফাংশনটি ডাকা।
  • আপনার ফাংশন থেকে ফলাফল নেওয়া।
  • সেই ফলাফল আপনার পাথ অপারেশন ফাংশনের প্যারামিটারে বসিয়ে দেওয়া।
graph TB

common_parameters(["common_parameters"])
read_items["/items/"]
read_users["/users/"]

common_parameters --> read_items
common_parameters --> read_users

এভাবে ভাগাভাগি করা কোড আপনি একবার লেখেন, আর FastAPI আপনার পাথ অপারেশনগুলোর জন্য সেটি ডাকার দায়িত্ব নেয়।

পরামর্শ

খেয়াল করুন, একটি বিশেষ ক্লাস তৈরি করে কোথাও FastAPI-কে দিয়ে সেটি "রেজিস্টার" করা বা এরকম কিছু করার দরকার নেই।

আপনি শুধু এটি Depends-কে দেন, আর FastAPI জানে বাকিটা কীভাবে করতে হয়।

Annotated ডিপেন্ডেন্সি ভাগাভাগি করুন¶

ওপরের উদাহরণগুলোতে দেখছেন যে একটু কোডের পুনরাবৃত্তি আছে।

common_parameters() ডিপেন্ডেন্সি ব্যবহার করতে হলে টাইপ অ্যানোটেশন আর Depends()-সহ পুরো প্যারামিটারটি লিখতে হয়:

commons: Annotated[dict, Depends(common_parameters)]

কিন্তু যেহেতু আমরা Annotated ব্যবহার করছি, তাই ওই Annotated মানটি একটি ভেরিয়েবলে রেখে একাধিক জায়গায় ব্যবহার করতে পারি:

from typing import Annotated

from fastapi import Depends, FastAPI

app = FastAPI()


async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}


CommonsDep = Annotated[dict, Depends(common_parameters)]


@app.get("/items/")
async def read_items(commons: CommonsDep):
    return commons


@app.get("/users/")
async def read_users(commons: CommonsDep):
    return commons

এখানে লাইন ১২-এ CommonsDep নামে একটি "শর্টকাট" বানানো হলো, তারপর লাইন ১৬ আর ২১-এ শুধু commons: CommonsDep লিখলেই হচ্ছে।

পরামর্শ

এটি শুধু স্ট্যান্ডার্ড Python, একে বলে "type alias" (টাইপের বিকল্প নাম), আসলে এটি FastAPI-এর নিজস্ব কিছু নয়।

কিন্তু যেহেতু FastAPI Python-এর স্ট্যান্ডার্ডের ওপর তৈরি, Annotated-সহ, তাই আপনার কোডে এই কৌশল ব্যবহার করতে পারেন। 😎

ডিপেন্ডেন্সিগুলো প্রত্যাশামতোই কাজ করতে থাকবে, আর সবচেয়ে ভালো ব্যাপার হলো টাইপের তথ্য সংরক্ষিত থাকবে, মানে আপনার এডিটর আপনাকে অটোকমপ্লিশন, লেখার সময়েই এরর দেখানো ইত্যাদি দিতে থাকবে। mypy-এর মতো অন্য টুলের ক্ষেত্রেও একই কথা।

এটি বিশেষভাবে কাজে লাগবে যখন একটি বড় কোডবেসে অনেক পাথ অপারেশনে একই ডিপেন্ডেন্সি বারবার ব্যবহার করবেন।

async হবে নাকি হবে না¶

যেহেতু ডিপেন্ডেন্সিগুলোও FastAPI ডাকে (আপনার পাথ অপারেশন ফাংশনের মতোই), তাই ফাংশন সংজ্ঞায়িত করার সময় একই নিয়ম প্রযোজ্য।

async def বা সাধারণ def ব্যবহার করতে পারেন।

আর সাধারণ def পাথ অপারেশন ফাংশনের ভেতরে async def ডিপেন্ডেন্সি, বা async def পাথ অপারেশন ফাংশনের ভেতরে def ডিপেন্ডেন্সি ইত্যাদি ঘোষণা করতে পারেন।

কোনো সমস্যা নেই। FastAPI জানবে কী করতে হবে।

নোট

পার্থক্যটা না জানলে ডকুমেন্টেশনের async আর await নিয়ে Async: "তাড়া আছে?" অংশটি দেখুন।

OpenAPI-এর সাথে একীভূত¶

আপনার ডিপেন্ডেন্সিগুলোর (আর সাব-ডিপেন্ডেন্সিগুলোর) সব রিকোয়েস্ট ঘোষণা, যাচাই আর শর্ত একই OpenAPI স্কিমাতে একীভূত হবে।

তাই ইন্টারঅ্যাকটিভ ডকুমেন্টেশনেও এই ডিপেন্ডেন্সিগুলোর সব তথ্য থাকবে:

সহজ ব্যবহার¶

খেয়াল করলে দেখবেন, পাথ অপারেশন ফাংশনগুলো এমনভাবে ঘোষণা করা হয় যাতে যখনই একটি পাথ আর অপারেশন মিলে যায় তখন সেগুলো ব্যবহার হয়, আর তারপর FastAPI রিকোয়েস্ট থেকে ডেটা বের করে সঠিক প্যারামিটার দিয়ে ফাংশনটি ডাকার দায়িত্ব নেয়।

আসলে সব (বা বেশিরভাগ) ওয়েব ফ্রেমওয়ার্কই এভাবেই কাজ করে।

ওই ফাংশনগুলো আপনি কখনো সরাসরি ডাকেন না। সেগুলো ডাকে আপনার ফ্রেমওয়ার্ক (এই ক্ষেত্রে FastAPI)।

ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা দিয়ে আপনি FastAPI-কে এটাও বলে দিতে পারেন যে আপনার পাথ অপারেশন ফাংশন আরও কিছুর ওপর "নির্ভর" করে, যা আপনার পাথ অপারেশন ফাংশনের আগে চালাতে হবে। আর FastAPI সেটি চালানো আর ফলাফল "ইনজেক্ট" করার দায়িত্ব নেবে।

"ডিপেন্ডেন্সি ইনজেকশন"-এর এই একই ধারণার জন্য অন্যান্য প্রচলিত শব্দ হলো:

  • রিসোর্স (resources)
  • প্রোভাইডার (providers)
  • সার্ভিস (services)
  • ইনজেক্টেবল (injectables)
  • কম্পোনেন্ট (components)

FastAPI প্লাগ-ইন¶

ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা ব্যবহার করে ইন্টিগ্রেশন আর "প্লাগ-ইন" বানানো যায়। কিন্তু আসলে "প্লাগ-ইন" বানানোর কোনো দরকারই নেই, কারণ ডিপেন্ডেন্সি ব্যবহার করে অসীম সংখ্যক ইন্টিগ্রেশন আর মিথস্ক্রিয়া ঘোষণা করা যায়, যা আপনার পাথ অপারেশন ফাংশনগুলোর জন্য উপলব্ধ হয়ে যায়।

আর ডিপেন্ডেন্সি খুব সহজ ও সহজবোধ্য উপায়ে তৈরি করা যায়, যাতে আপনি শুধু দরকারি Python প্যাকেজগুলো ইমপোর্ট করে আক্ষরিক অর্থেই কয়েক লাইনের কোডে সেগুলো আপনার API ফাংশনের সাথে যুক্ত করতে পারেন।

পরের অধ্যায়গুলোতে রিলেশনাল ও NoSQL ডেটাবেস, সিকিউরিটি ইত্যাদি নিয়ে এর উদাহরণ দেখবেন।

FastAPI সামঞ্জস্য¶

ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থার সরলতা FastAPI-কে সামঞ্জস্যপূর্ণ করে:

  • সব রিলেশনাল ডেটাবেসের সাথে
  • NoSQL ডেটাবেসের সাথে
  • বাইরের প্যাকেজের সাথে
  • বাইরের API-এর সাথে
  • অথেনটিকেশন ও অথরাইজেশন সিস্টেমের সাথে
  • API ব্যবহার পর্যবেক্ষণ সিস্টেমের সাথে
  • রেসপন্স ডেটা ইনজেকশন সিস্টেমের সাথে
  • ইত্যাদি।

সহজ এবং শক্তিশালী¶

স্তরভিত্তিক ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থাটি সংজ্ঞায়িত ও ব্যবহার করা খুব সহজ হলেও এটি খুবই শক্তিশালী।

এমন ডিপেন্ডেন্সি সংজ্ঞায়িত করতে পারেন, যারা নিজেরাও আবার ডিপেন্ডেন্সি সংজ্ঞায়িত করতে পারে।

শেষে ডিপেন্ডেন্সির একটি স্তরভিত্তিক গাছ (tree) তৈরি হয়, আর ডিপেন্ডেন্সি ইনজেকশন ব্যবস্থা আপনার হয়ে এই সব ডিপেন্ডেন্সি (আর তাদের সাব-ডিপেন্ডেন্সি) সমাধান করে প্রতিটি ধাপে ফলাফল দেওয়ার (ইনজেক্ট করার) দায়িত্ব নেয়।

যেমন, ধরা যাক আপনার ৪টি API এন্ডপয়েন্ট (পাথ অপারেশন) আছে:

  • /items/public/
  • /items/private/
  • /users/{user_id}/activate
  • /items/pro/

তাহলে শুধু ডিপেন্ডেন্সি আর সাব-ডিপেন্ডেন্সি দিয়েই এদের প্রতিটির জন্য আলাদা আলাদা অনুমতির শর্ত যোগ করতে পারেন:

চিত্রটি সহজ ভাষায়

  • current_user (বর্তমান লগইন করা ইউজার খুঁজে বের করা) একটি মূল ডিপেন্ডেন্সি।
  • active_user নির্ভর করে current_user-এর ওপর, আর দেখে ইউজার সক্রিয় কিনা।
  • admin_user আর paying_user নির্ভর করে active_user-এর ওপর।
  • /items/public/ কোনো ডিপেন্ডেন্সি ছাড়াই সবার জন্য খোলা।
  • /items/private/ শুধু সক্রিয় ইউজারদের জন্য, /users/{user_id}/activate শুধু অ্যাডমিনের জন্য, /items/pro/ শুধু টাকা দেওয়া ইউজারদের জন্য।

প্রতিটি পাথ অপারেশনে শুধু বলে দেন কোন ডিপেন্ডেন্সি লাগবে, বাকি পুরো শিকল FastAPI নিজেই চালায়।

OpenAPI-এর সাথে একীভূত¶

এই সব ডিপেন্ডেন্সি তাদের শর্ত ঘোষণা করার সাথে সাথে আপনার পাথ অপারেশনগুলোতে প্যারামিটার, যাচাই ইত্যাদিও যোগ করে।

FastAPI এসব OpenAPI স্কিমাতে যোগ করার দায়িত্ব নেবে, যাতে ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমে সেগুলো দেখা যায়।

সংক্ষেপে মনে রাখুন

  • ডিপেন্ডেন্সি হলো একটি সাধারণ ফাংশন, যা পাথ অপারেশনের মতোই প্যারামিটার নেয়।
  • ব্যবহার: commons: Annotated[dict, Depends(common_parameters)], ফাংশনের নাম দিন, ডাকবেন না।
  • FastAPI প্রতিটি রিকোয়েস্টে ডিপেন্ডেন্সি চালিয়ে ফলাফল আপনার প্যারামিটারে দেয়।
  • বারবার লেখা এড়াতে CommonsDep = Annotated[...] এর মতো type alias বানান।
