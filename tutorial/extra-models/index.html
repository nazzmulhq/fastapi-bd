অতিরিক্ত মডেল¶

🌐 AI এবং মানুষের যৌথ অনুবাদ

এই অনুবাদটি মানুষের নির্দেশনায় AI দিয়ে করা হয়েছে। 🤝

এতে মূল অর্থ ভুল বোঝা বা অস্বাভাবিক শোনানোর মতো ভুল থাকতে পারে। 🤖

ইংরেজি সংস্করণ

আগের উদাহরণ থেকে চালিয়ে গেলে, একাধিক সম্পর্কিত মডেল থাকা খুবই সাধারণ ব্যাপার।

ইউজার মডেলের ক্ষেত্রে এটি বিশেষভাবে সত্য, কারণ:

  • ইনপুট মডেলে একটি পাসওয়ার্ড রাখার সুযোগ থাকতে হবে।
  • আউটপুট মডেলে কোনো পাসওয়ার্ড থাকা উচিত নয়।
  • ডেটাবেস মডেলে সম্ভবত একটি হ্যাশ করা পাসওয়ার্ড থাকতে হবে।

বিপদ

কখনো ইউজারদের প্লেইনটেক্সট পাসওয়ার্ড সংরক্ষণ করবেন না। সবসময় একটি "নিরাপদ হ্যাশ" সংরক্ষণ করুন যা পরে আপনি যাচাই করতে পারবেন।

আপনি যদি না জানেন, তাহলে সিকিউরিটি অধ্যায়গুলোতে শিখবেন "পাসওয়ার্ড হ্যাশ" কী।

একাধিক মডেল¶

পাসওয়ার্ড ফিল্ডসহ মডেলগুলো দেখতে কেমন হতে পারে এবং সেগুলো কোথায় ব্যবহৃত হয়, তার একটি সাধারণ ধারণা এখানে দেওয়া হলো:

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserInDB(BaseModel):
    username: str
    hashed_password: str
    email: EmailStr
    full_name: str | None = None


def fake_password_hasher(raw_password: str):
    return "supersecret" + raw_password


def fake_save_user(user_in: UserIn):
    hashed_password = fake_password_hasher(user_in.password)
    user_in_db = UserInDB(**user_in.model_dump(), hashed_password=hashed_password)
    print("User saved! ..not really")
    return user_in_db


@app.post("/user/", response_model=UserOut)
async def create_user(user_in: UserIn):
    user_saved = fake_save_user(user_in)
    return user_saved

**user_in.model_dump() সম্পর্কে¶

Pydantic-এর .model_dump()¶

user_in হলো UserIn ক্লাসের একটি Pydantic মডেল।

Pydantic মডেলের একটি .model_dump() মেথড আছে, যা মডেলের ডেটাসহ একটি dict রিটার্ন করে।

তাই, আমরা যদি এভাবে একটি Pydantic অবজেক্ট user_in তৈরি করি:

user_in = UserIn(username="john", password="secret", email="john.doe@example.com")

আর তারপর কল করি:

user_dict = user_in.model_dump()

তাহলে এখন user_dict ভেরিয়েবলে ডেটাসহ একটি dict আছে (এটি একটি Pydantic মডেল অবজেক্টের বদলে একটি dict)।

আর আমরা যদি কল করি:

print(user_dict)

তাহলে আমরা এরকম একটি Python dict পাব:

{
    'username': 'john',
    'password': 'secret',
    'email': 'john.doe@example.com',
    'full_name': None,
}

একটি dict আনপ্যাক করা¶

আমরা যদি user_dict-এর মতো একটি dict নিয়ে **user_dict দিয়ে একটি ফাংশনে (বা ক্লাসে) পাঠাই, তাহলে Python এটিকে "আনপ্যাক" করবে। এটি user_dict-এর কী ও ভ্যালুগুলো সরাসরি কী-ভ্যালু আর্গুমেন্ট হিসেবে পাঠাবে।

তাই ওপরের user_dict নিয়ে চালিয়ে গেলে, লেখা:

UserInDB(**user_dict)

এর সমতুল্য কিছু তৈরি করবে:

UserInDB(
    username="john",
    password="secret",
    email="john.doe@example.com",
    full_name=None,
)

অথবা আরও নির্ভুলভাবে, ভবিষ্যতে এতে যে বিষয়বস্তুই থাকুক, সরাসরি user_dict ব্যবহার করে:

UserInDB(
    username = user_dict["username"],
    password = user_dict["password"],
    email = user_dict["email"],
    full_name = user_dict["full_name"],
)

আরেকটির বিষয়বস্তু থেকে একটি Pydantic মডেল¶

যেহেতু ওপরের উদাহরণে আমরা user_in.model_dump() থেকে user_dict পেয়েছি, তাই এই কোড:

user_dict = user_in.model_dump()
UserInDB(**user_dict)

এর সমতুল্য হবে:

UserInDB(**user_in.model_dump())

...কারণ user_in.model_dump() একটি dict, আর তারপর আমরা এটিকে ** উপসর্গসহ UserInDB-তে পাঠিয়ে Python-কে "আনপ্যাক" করাই।

তাই আমরা আরেকটি Pydantic মডেলের ডেটা থেকে একটি Pydantic মডেল পাই।

একটি dict আনপ্যাক করা ও অতিরিক্ত কিওয়ার্ড¶

আর তারপর অতিরিক্ত কিওয়ার্ড আর্গুমেন্ট hashed_password=hashed_password যোগ করলে, যেমন:

UserInDB(**user_in.model_dump(), hashed_password=hashed_password)

...শেষ পর্যন্ত এটি হয় এরকম:

UserInDB(
    username = user_dict["username"],
    password = user_dict["password"],
    email = user_dict["email"],
    full_name = user_dict["full_name"],
    hashed_password = hashed_password,
)

সতর্কতা

সহায়ক অতিরিক্ত ফাংশন fake_password_hasher ও fake_save_user শুধু ডেটার একটি সম্ভাব্য প্রবাহ দেখানোর জন্য, অবশ্যই এগুলো কোনো আসল নিরাপত্তা দিচ্ছে না।

পুনরাবৃত্তি কমান¶

কোডের পুনরাবৃত্তি কমানো FastAPI-এর মূল ধারণাগুলোর একটি।

কারণ কোডের পুনরাবৃত্তি বাগ, সিকিউরিটি সমস্যা, কোড অসংগতির সমস্যা (যখন আপনি এক জায়গায় আপডেট করেন কিন্তু অন্যগুলোতে করেন না) ইত্যাদির সম্ভাবনা বাড়ায়।

আর এই মডেলগুলো সবাই অনেক ডেটা ভাগাভাগি করছে এবং অ্যাট্রিবিউটের নাম ও টাইপের পুনরাবৃত্তি করছে।

আমরা আরও ভালো করতে পারি।

আমরা একটি UserBase মডেল ঘোষণা করতে পারি যা আমাদের অন্য মডেলগুলোর ভিত্তি হিসেবে কাজ করবে। তারপর আমরা ওই মডেলের সাবক্লাস তৈরি করতে পারি যেগুলো এর অ্যাট্রিবিউট (টাইপ ঘোষণা, ভ্যালিডেশন ইত্যাদি) ইনহেরিট করবে।

সব ডেটা রূপান্তর, ভ্যালিডেশন, ডকুমেন্টেশন ইত্যাদি স্বাভাবিকভাবেই কাজ করবে।

এভাবে আমরা কেবল মডেলগুলোর মধ্যকার পার্থক্যগুলো ঘোষণা করতে পারি (প্লেইনটেক্সট password-সহ, hashed_password-সহ এবং পাসওয়ার্ড ছাড়া):

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserBase(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserIn(UserBase):
    password: str


class UserOut(UserBase):
    pass


class UserInDB(UserBase):
    hashed_password: str


def fake_password_hasher(raw_password: str):
    return "supersecret" + raw_password


def fake_save_user(user_in: UserIn):
    hashed_password = fake_password_hasher(user_in.password)
    user_in_db = UserInDB(**user_in.model_dump(), hashed_password=hashed_password)
    print("User saved! ..not really")
    return user_in_db


@app.post("/user/", response_model=UserOut)
async def create_user(user_in: UserIn):
    user_saved = fake_save_user(user_in)
    return user_saved

Union বা anyOf¶

আপনি একটি রেসপন্সকে দুই বা ততোধিক টাইপের Union হিসেবে ঘোষণা করতে পারেন, অর্থাৎ রেসপন্সটি সেগুলোর যেকোনোটি হতে পারে।

OpenAPI-তে এটি anyOf দিয়ে সংজ্ঞায়িত হবে।

এটি করতে স্ট্যান্ডার্ড Python টাইপ হিন্ট typing.Union ব্যবহার করুন:

নোট

একটি Union সংজ্ঞায়িত করার সময় সবচেয়ে নির্দিষ্ট টাইপটি আগে রাখুন, তারপর কম নির্দিষ্ট টাইপটি। নিচের উদাহরণে Union[PlaneItem, CarItem]-এ বেশি নির্দিষ্ট PlaneItem আছে CarItem-এর আগে।

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class BaseItem(BaseModel):
    description: str
    type: str


class CarItem(BaseItem):
    type: str = "car"


class PlaneItem(BaseItem):
    type: str = "plane"
    size: int


items = {
    "item1": {"description": "All my friends drive a low rider", "type": "car"},
    "item2": {
        "description": "Music is my aeroplane, it's my aeroplane",
        "type": "plane",
        "size": 5,
    },
}


@app.get("/items/{item_id}", response_model=PlaneItem | CarItem)
async def read_item(item_id: str):
    return items[item_id]

Python 3.10-এ Union¶

এই উদাহরণে আমরা response_model আর্গুমেন্টের ভ্যালু হিসেবে Union[PlaneItem, CarItem] দিচ্ছি।

যেহেতু আমরা এটিকে একটি টাইপ অ্যানোটেশনে না রেখে একটি আর্গুমেন্টের ভ্যালু হিসেবে দিচ্ছি, তাই Python 3.10-এও আমাদের Union ব্যবহার করতে হবে।

এটি যদি একটি টাইপ অ্যানোটেশনে থাকত, তাহলে আমরা খাড়া দাগ ব্যবহার করতে পারতাম, এভাবে:

some_variable: PlaneItem | CarItem

কিন্তু আমরা যদি সেটি response_model=PlaneItem | CarItem অ্যাসাইনমেন্টে রাখি, তাহলে একটি এরর পাব, কারণ Python এটিকে টাইপ অ্যানোটেশন হিসেবে না ধরে PlaneItem ও CarItem-এর মধ্যে একটি অবৈধ অপারেশন করার চেষ্টা করবে।

মডেলের লিস্ট¶

একইভাবে আপনি অবজেক্টের লিস্টের রেসপন্স ঘোষণা করতে পারেন।

এর জন্য স্ট্যান্ডার্ড Python list ব্যবহার করুন:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str


items = [
    {"name": "Foo", "description": "There comes my hero"},
    {"name": "Red", "description": "It's my aeroplane"},
]


@app.get("/items/", response_model=list[Item])
async def read_items():
    return items

যেকোনো dict-সহ রেসপন্স¶

Pydantic মডেল ব্যবহার না করে, শুধু কী ও ভ্যালুর টাইপ ঘোষণা করে একটি সাধারণ যেকোনো dict দিয়েও আপনি একটি রেসপন্স ঘোষণা করতে পারেন।

আপনি যদি বৈধ ফিল্ড/অ্যাট্রিবিউটের নামগুলো (যা একটি Pydantic মডেলের জন্য দরকার হতো) আগে থেকে না জানেন, তাহলে এটি কাজে আসে।

এক্ষেত্রে আপনি dict ব্যবহার করতে পারেন:

from fastapi import FastAPI

app = FastAPI()


@app.get("/keyword-weights/", response_model=dict[str, float])
async def read_keyword_weights():
    return {"foo": 2.3, "bar": 3.4}

সংক্ষেপে¶

একাধিক Pydantic মডেল ব্যবহার করুন এবং প্রতিটি ক্ষেত্রের জন্য ইচ্ছেমতো ইনহেরিট করুন।

কোনো এনটিটির যদি বিভিন্ন "অবস্থা" থাকতে হয়, তাহলে প্রতি এনটিটির জন্য একটিমাত্র ডেটা মডেল রাখার দরকার নেই। ইউজার "এনটিটি" এর একটি উদাহরণ, যার অবস্থাগুলোর মধ্যে আছে password, password_hash, বা পাসওয়ার্ড ছাড়া।
