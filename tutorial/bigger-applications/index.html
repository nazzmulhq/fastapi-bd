বড় অ্যাপ্লিকেশন - একাধিক ফাইল¶

🌐 AI এবং মানুষের যৌথ অনুবাদ

এই অনুবাদটি মানুষের নির্দেশনায় AI দিয়ে করা হয়েছে। 🤝

এতে মূল অর্থ ভুল বোঝা বা অস্বাভাবিক শোনানোর মতো ভুল থাকতে পারে। 🤖

ইংরেজি সংস্করণ

আপনি যদি একটি অ্যাপ্লিকেশন বা ওয়েব API তৈরি করেন, তাহলে সবকিছু একটিমাত্র ফাইলে রাখতে পারার ঘটনা খুব কমই ঘটে।

পূর্ণ নমনীয়তা বজায় রেখেই আপনার অ্যাপ্লিকেশন সাজানোর জন্য FastAPI একটি সুবিধাজনক টুল দেয়।

নোট

আপনি যদি Flask থেকে আসেন, তাহলে এটি Flask-এর Blueprints-এর সমতুল্য।

একটি উদাহরণ ফাইল কাঠামো¶

ধরা যাক আপনার এরকম একটি ফাইল কাঠামো আছে:

.
├── app
│   ├── __init__.py
│   ├── main.py
│   ├── dependencies.py
│   └── routers
│   │   ├── __init__.py
│   │   ├── items.py
│   │   └── users.py
│   └── internal
│       ├── __init__.py
│       └── admin.py

পরামর্শ

বেশ কয়েকটি __init__.py ফাইল আছে: প্রতিটি ডিরেক্টরি বা সাবডিরেক্টরিতে একটি করে।

এটিই এক ফাইল থেকে আরেক ফাইলে কোড ইম্পোর্ট করতে দেয়।

যেমন, app/main.py-তে আপনার এরকম একটি লাইন থাকতে পারে:

from app.routers import items
  • app ডিরেক্টরিতে সবকিছু আছে। আর এতে একটি খালি ফাইল app/__init__.py আছে, তাই এটি একটি "Python প্যাকেজ" ("Python মডিউলের" একটি সংগ্রহ): app।
  • এতে একটি app/main.py ফাইল আছে। যেহেতু এটি একটি Python প্যাকেজের (__init__.py ফাইলসহ একটি ডিরেক্টরি) ভেতরে আছে, তাই এটি ওই প্যাকেজের একটি "মডিউল": app.main।
  • একটি app/dependencies.py ফাইলও আছে, app/main.py-এর মতোই এটিও একটি "মডিউল": app.dependencies।
  • আরেকটি __init__.py ফাইলসহ একটি সাবডিরেক্টরি app/routers/ আছে, তাই এটি একটি "Python সাবপ্যাকেজ": app.routers।
  • app/routers/items.py ফাইলটি একটি প্যাকেজ app/routers/-এর ভেতরে আছে, তাই এটি একটি সাবমডিউল: app.routers.items।
  • app/routers/users.py-এর ক্ষেত্রেও তাই, এটি আরেকটি সাবমডিউল: app.routers.users।
  • আরেকটি __init__.py ফাইলসহ একটি সাবডিরেক্টরি app/internal/-ও আছে, তাই এটি আরেকটি "Python সাবপ্যাকেজ": app.internal।
  • আর app/internal/admin.py ফাইলটি আরেকটি সাবমডিউল: app.internal.admin।

মন্তব্যসহ একই ফাইল কাঠামো:

.

│   ├── main.py          # "main" মডিউল, যেমন import app.main
│   ├── dependencies.py  # "dependencies" মডিউল, যেমন import app.dependencies
│   └── routers          # "routers" একটি "Python সাবপ্যাকেজ"
│   │   ├── __init__.py  # "routers"-কে একটি "Python সাবপ্যাকেজ" বানায়
│   │   ├── items.py     # "items" সাবমডিউল, যেমন import app.routers.items
│   │   └── users.py     # "users" সাবমডিউল, যেমন import app.routers.users

APIRouter¶

ধরা যাক শুধু ইউজার সামলানোর জন্য নির্দিষ্ট ফাইলটি হলো /app/routers/users.py-এর সাবমডিউলটি।

আপনি চান আপনার ইউজার সম্পর্কিত পাথ অপারেশনগুলো বাকি কোড থেকে আলাদা থাকুক, যাতে সবকিছু গোছানো থাকে।

কিন্তু এটি এখনো একই FastAPI অ্যাপ্লিকেশন/ওয়েব API-এর অংশ (এটি একই "Python প্যাকেজের" অংশ)।

APIRouter ব্যবহার করে আপনি ওই মডিউলের জন্য পাথ অপারেশন তৈরি করতে পারেন।

APIRouter ইম্পোর্ট করুন¶

FastAPI ক্লাসের মতোই আপনি এটি ইম্পোর্ট করে একটি "ইনস্ট্যান্স" তৈরি করেন:

app/routers/users.py
from fastapi import APIRouter

router = APIRouter()


@router.get("/users/", tags=["users"])
async def read_users():
    return [{"username": "Rick"}, {"username": "Morty"}]


@router.get("/users/me", tags=["users"])
async def read_user_me():
    return {"username": "fakecurrentuser"}


@router.get("/users/{username}", tags=["users"])
async def read_user(username: str):
    return {"username": username}

APIRouter-সহ পাথ অপারেশন¶

তারপর আপনার পাথ অপারেশনগুলো ঘোষণা করতে এটি ব্যবহার করেন।

FastAPI ক্লাস যেভাবে ব্যবহার করতেন, সেভাবেই এটি ব্যবহার করুন:

app/routers/users.py
from fastapi import APIRouter

router = APIRouter()


@router.get("/users/", tags=["users"])
async def read_users():
    return [{"username": "Rick"}, {"username": "Morty"}]


@router.get("/users/me", tags=["users"])
async def read_user_me():
    return {"username": "fakecurrentuser"}


@router.get("/users/{username}", tags=["users"])
async def read_user(username: str):
    return {"username": username}

আপনি APIRouter-কে একটি "মিনি FastAPI" ক্লাস হিসেবে ভাবতে পারেন।

একই সব অপশন সাপোর্টেড।

একই সব parameters, responses, dependencies, tags ইত্যাদি।

পরামর্শ

এই উদাহরণে ভেরিয়েবলটির নাম router, তবে আপনি এটির যেকোনো নাম দিতে পারেন।

আমরা এই APIRouter-কে মূল FastAPI অ্যাপে অন্তর্ভুক্ত করব, তবে প্রথমে ডিপেন্ডেন্সি ও আরেকটি APIRouter দেখে নেওয়া যাক।

ডিপেন্ডেন্সি¶

আমরা দেখছি যে অ্যাপ্লিকেশনের কয়েকটি জায়গায় ব্যবহৃত কিছু ডিপেন্ডেন্সি আমাদের দরকার হবে।

তাই আমরা সেগুলো তাদের নিজস্ব dependencies মডিউলে (app/dependencies.py) রাখি।

এখন আমরা একটি কাস্টম X-Token হেডার পড়তে একটি সহজ ডিপেন্ডেন্সি ব্যবহার করব:

app/dependencies.py
from typing import Annotated

from fastapi import Header, HTTPException


async def get_token_header(x_token: Annotated[str, Header()]):
    if x_token != "fake-super-secret-token":
        raise HTTPException(status_code=400, detail="X-Token header invalid")


async def get_query_token(token: str):
    if token != "jessica":
        raise HTTPException(status_code=400, detail="No Jessica token provided")

পরামর্শ

এই উদাহরণটি সহজ করতে আমরা একটি বানানো হেডার ব্যবহার করছি।

তবে বাস্তব ক্ষেত্রে অন্তর্ভুক্ত সিকিউরিটি ইউটিলিটি ব্যবহার করে আপনি আরও ভালো ফল পাবেন।

APIRouter-সহ আরেকটি মডিউল¶

ধরা যাক আপনার অ্যাপ্লিকেশনের "items" সামলানোর জন্য নির্দিষ্ট এন্ডপয়েন্টগুলোও আছে app/routers/items.py মডিউলে।

আপনার পাথ অপারেশন আছে এগুলোর জন্য:

  • /items/
  • /items/{item_id}

এর পুরো গঠন app/routers/users.py-এর মতোই।

তবে আমরা আরেকটু বুদ্ধিমান হয়ে কোড কিছুটা সহজ করতে চাই।

আমরা জানি এই মডিউলের সব পাথ অপারেশনে একই জিনিস আছে:

  • পাথ prefix: /items।
  • tags: (শুধু একটি ট্যাগ: items)।
  • অতিরিক্ত responses।
  • dependencies: এগুলো সবারই আমাদের তৈরি করা সেই X-Token ডিপেন্ডেন্সি দরকার।

তাই এর সবকিছু প্রতিটি পাথ অপারেশনে যোগ করার বদলে আমরা এটি APIRouter-এ যোগ করতে পারি।

app/routers/items.py
from fastapi import APIRouter, Depends, HTTPException

from ..dependencies import get_token_header

router = APIRouter(
    prefix="/items",
    tags=["items"],
    dependencies=[Depends(get_token_header)],
    responses={404: {"description": "Not found"}},
)


fake_items_db = {"plumbus": {"name": "Plumbus"}, "gun": {"name": "Portal Gun"}}


@router.get("/")
async def read_items():
    return fake_items_db


@router.get("/{item_id}")
async def read_item(item_id: str):
    if item_id not in fake_items_db:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"name": fake_items_db[item_id]["name"], "item_id": item_id}


@router.put(
    "/{item_id}",
    tags=["custom"],
    responses={403: {"description": "Operation forbidden"}},
)
async def update_item(item_id: str):
    if item_id != "plumbus":
        raise HTTPException(
            status_code=403, detail="You can only update the item: plumbus"
        )
    return {"item_id": item_id, "name": "The great Plumbus"}

যেহেতু প্রতিটি পাথ অপারেশনের পাথ অবশ্যই / দিয়ে শুরু হতে হবে, যেমন:

@router.get("/{item_id}")
async def read_item(item_id: str):
    ...

...তাই prefix-এর শেষে / থাকা যাবে না।

তাই এক্ষেত্রে prefix হলো /items।

আমরা tags-এর একটি লিস্ট এবং অতিরিক্ত responses-ও যোগ করতে পারি, যা এই রাউটারে অন্তর্ভুক্ত সব পাথ অপারেশনে প্রয়োগ হবে।

আর আমরা dependencies-এর একটি লিস্ট যোগ করতে পারি, যা রাউটারের সব পাথ অপারেশনে যোগ হবে এবং সেগুলোতে করা প্রতিটি রিকোয়েস্টের জন্য এক্সিকিউট/সমাধান হবে।

পরামর্শ

লক্ষ করুন, পাথ অপারেশন ডেকোরেটরে ডিপেন্ডেন্সির মতোই, আপনার পাথ অপারেশন ফাংশনে কোনো ভ্যালু পাঠানো হবে না।

শেষ ফলাফল হলো item-এর পাথগুলো এখন:

  • /items/
  • /items/{item_id}

...ঠিক যেমনটা আমরা চেয়েছিলাম।

  • এগুলো একটিমাত্র স্ট্রিং "items" ধারণকারী ট্যাগের একটি লিস্ট দিয়ে চিহ্নিত হবে।
    • এই "ট্যাগগুলো" স্বয়ংক্রিয় ইন্টারঅ্যাকটিভ ডকুমেন্টেশন সিস্টেমের (OpenAPI ব্যবহার করে) জন্য বিশেষভাবে কাজের।
  • এগুলোর সবগুলোতে পূর্বনির্ধারিত responses অন্তর্ভুক্ত থাকবে।
  • এই সব পাথ অপারেশনের আগে dependencies-এর লিস্টটি মূল্যায়ন/এক্সিকিউট হবে।
    • আপনি যদি কোনো নির্দিষ্ট পাথ অপারেশনেও ডিপেন্ডেন্সি ঘোষণা করেন, সেগুলোও এক্সিকিউট হবে।
    • রাউটারের ডিপেন্ডেন্সিগুলো প্রথমে এক্সিকিউট হয়, তারপর ডেকোরেটরের dependencies, এবং তারপর সাধারণ প্যারামিটার ডিপেন্ডেন্সিগুলো।
    • আপনি scopes-সহ Security ডিপেন্ডেন্সিও যোগ করতে পারেন।

পরামর্শ

APIRouter-এ dependencies থাকলে তা, যেমন, পুরো একদল পাথ অপারেশনের জন্য অথেনটিকেশন আবশ্যক করতে ব্যবহার করা যায়। এমনকি যদি ডিপেন্ডেন্সিগুলো প্রতিটিতে আলাদাভাবে যোগ করা না হয়।

পরামর্শ

prefix, tags, responses ও dependencies প্যারামিটারগুলো (আরও অনেক ক্ষেত্রের মতোই) শুধু FastAPI-এর একটি ফিচার, যা আপনাকে কোডের পুনরাবৃত্তি এড়াতে সাহায্য করে।

ডিপেন্ডেন্সিগুলো ইম্পোর্ট করুন¶

এই কোডটি থাকে app.routers.items মডিউলে, অর্থাৎ app/routers/items.py ফাইলে।

আর আমাদের ডিপেন্ডেন্সি ফাংশনটি পেতে হবে app.dependencies মডিউল, অর্থাৎ app/dependencies.py ফাইল থেকে।

আপেক্ষিক ইম্পোর্ট কীভাবে কাজ করে¶

পরামর্শ

ইম্পোর্ট কীভাবে কাজ করে তা যদি আপনি ভালোভাবে জানেন, তাহলে নিচের পরের অংশে চলে যান।

একটিমাত্র ডট ., যেমন:

from .dependencies import get_token_header

এর মানে হবে:

  • এই মডিউলটি (app/routers/items.py ফাইল) যে প্যাকেজে আছে (app/routers/ ডিরেক্টরি), সেখান থেকে শুরু করে...
  • dependencies মডিউলটি খুঁজে বের করো (app/routers/dependencies.py-এ একটি কাল্পনিক ফাইল)...
  • আর সেটি থেকে get_token_header ফাংশনটি ইম্পোর্ট করো।

কিন্তু ওই ফাইলটি নেই, আমাদের ডিপেন্ডেন্সিগুলো আছে app/dependencies.py ফাইলে।

মনে করে দেখুন আমাদের অ্যাপ/ফাইল কাঠামো দেখতে কেমন:

দুটি ডট .., যেমন:

from ..dependencies import get_token_header

এর মানে:

  • এই মডিউলটি (app/routers/items.py ফাইল) যে প্যাকেজে আছে (app/routers/ ডিরেক্টরি), সেখান থেকে শুরু করে...
  • প্যারেন্ট প্যাকেজে যাও (app/ ডিরেক্টরি)...
  • আর সেখানে dependencies মডিউলটি খুঁজে বের করো (app/dependencies.py-এর ফাইল)...
  • আর সেটি থেকে get_token_header ফাংশনটি ইম্পোর্ট করো।

এটি সঠিকভাবে কাজ করে! 🎉

একইভাবে, আমরা যদি তিনটি ডট ... ব্যবহার করতাম, যেমন:

from ...dependencies import get_token_header

তার মানে হতো:

  • এই মডিউলটি (app/routers/items.py ফাইল) যে প্যাকেজে আছে (app/routers/ ডিরেক্টরি), সেখান থেকে শুরু করে...
  • প্যারেন্ট প্যাকেজে যাও (app/ ডিরেক্টরি)...
  • তারপর ওই প্যাকেজের প্যারেন্টে যাও (কোনো প্যারেন্ট প্যাকেজ নেই, app হলো সর্বোচ্চ স্তর 😱)...
  • আর সেখানে dependencies মডিউলটি খুঁজে বের করো (app/dependencies.py-এর ফাইল)...
  • আর সেটি থেকে get_token_header ফাংশনটি ইম্পোর্ট করো।

এটি app/-এর ওপরের কোনো প্যাকেজকে বোঝাত, যার নিজস্ব __init__.py ফাইল ইত্যাদি আছে। কিন্তু আমাদের তা নেই। তাই আমাদের উদাহরণে এটি একটি এরর দিত। 🚨

তবে এখন আপনি জানেন এটি কীভাবে কাজ করে, তাই আপনার নিজের অ্যাপ যত জটিলই হোক, সেগুলোতে আপেক্ষিক ইম্পোর্ট ব্যবহার করতে পারবেন। 🤓

কিছু কাস্টম tags, responses ও dependencies যোগ করুন¶

আমরা প্রতিটি পাথ অপারেশনে prefix /items বা tags=["items"] যোগ করছি না, কারণ এগুলো আমরা APIRouter-এ যোগ করেছি।

তবে আমরা তবুও আরও tags যোগ করতে পারি যা একটি নির্দিষ্ট পাথ অপারেশনে প্রয়োগ হবে, এবং ওই পাথ অপারেশনের জন্য নির্দিষ্ট কিছু অতিরিক্ত responses-ও যোগ করতে পারি:

app/routers/items.py
from fastapi import APIRouter, Depends, HTTPException

from ..dependencies import get_token_header

router = APIRouter(
    prefix="/items",
    tags=["items"],
    dependencies=[Depends(get_token_header)],
    responses={404: {"description": "Not found"}},
)


fake_items_db = {"plumbus": {"name": "Plumbus"}, "gun": {"name": "Portal Gun"}}


@router.get("/")
async def read_items():
    return fake_items_db


@router.get("/{item_id}")
async def read_item(item_id: str):
    if item_id not in fake_items_db:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"name": fake_items_db[item_id]["name"], "item_id": item_id}


@router.put(
    "/{item_id}",
    tags=["custom"],
    responses={403: {"description": "Operation forbidden"}},
)
async def update_item(item_id: str):
    if item_id != "plumbus":
        raise HTTPException(
            status_code=403, detail="You can only update the item: plumbus"
        )
    return {"item_id": item_id, "name": "The great Plumbus"}

পরামর্শ

এই শেষ পাথ অপারেশনটিতে ট্যাগের সমন্বয় থাকবে: ["items", "custom"]।

আর ডকুমেন্টেশনে এতে দুটি রেসপন্সই থাকবে, একটি 404-এর জন্য এবং একটি 403-এর জন্য।

মূল FastAPI¶

এবার app/main.py-এর মডিউলটি দেখা যাক।

এখানেই আপনি FastAPI ক্লাস ইম্পোর্ট করে ব্যবহার করেন।

এটিই হবে আপনার অ্যাপ্লিকেশনের মূল ফাইল যা সবকিছুকে একসাথে বেঁধে রাখে।

আর যেহেতু আপনার বেশিরভাগ লজিক এখন তার নিজস্ব নির্দিষ্ট মডিউলে থাকবে, তাই মূল ফাইলটি বেশ সহজ হবে।

FastAPI ইম্পোর্ট করুন¶

আপনি স্বাভাবিকভাবেই একটি FastAPI ক্লাস ইম্পোর্ট করে তৈরি করেন।

আর আমরা এমনকি গ্লোবাল ডিপেন্ডেন্সিও ঘোষণা করতে পারি, যা প্রতিটি APIRouter-এর ডিপেন্ডেন্সির সাথে মিলিত হবে:

app/main.py
from fastapi import Depends, FastAPI

from .dependencies import get_query_token, get_token_header
from .internal import admin
from .routers import items, users

app = FastAPI(dependencies=[Depends(get_query_token)])


app.include_router(users.router)
app.include_router(items.router)
app.include_router(
    admin.router,
    prefix="/admin",
    tags=["admin"],
    dependencies=[Depends(get_token_header)],
    responses={418: {"description": "I'm a teapot"}},
)


@app.get("/")
async def root():
    return {"message": "Hello Bigger Applications!"}

এবার আমরা APIRouter থাকা অন্য সাবমডিউলগুলো ইম্পোর্ট করি:

app/main.py
from fastapi import Depends, FastAPI

from .internal import admin

যেহেতু app/routers/users.py ও app/routers/items.py ফাইলগুলো একই Python প্যাকেজ app-এর অংশ এমন সাবমডিউল, তাই "আপেক্ষিক ইম্পোর্ট" ব্যবহার করে এগুলো ইম্পোর্ট করতে আমরা একটিমাত্র ডট . ব্যবহার করতে পারি।

ইম্পোর্ট কীভাবে কাজ করে¶

এই অংশটি:

from .routers import items, users

এর মানে:

  • এই মডিউলটি (app/main.py ফাইল) যে প্যাকেজে আছে (app/ ডিরেক্টরি), সেখান থেকে শুরু করে...
  • সাবপ্যাকেজ routers খোঁজো (app/routers/-এর ডিরেক্টরি)...
  • আর সেটি থেকে সাবমডিউল items (app/routers/items.py-এর ফাইল) ও users (app/routers/users.py-এর ফাইল) ইম্পোর্ট করো...

items মডিউলে একটি ভেরিয়েবল router (items.router) থাকবে। এটি সেই একই যা আমরা app/routers/items.py ফাইলে তৈরি করেছিলাম, এটি একটি APIRouter অবজেক্ট।

তারপর আমরা users মডিউলের জন্যও একই কাজ করি।

আমরা এগুলো এভাবেও ইম্পোর্ট করতে পারতাম:

from app.routers import items, users

নোট

প্রথম ভার্সনটি একটি "আপেক্ষিক ইম্পোর্ট":

from .routers import items, users

দ্বিতীয় ভার্সনটি একটি "পরম ইম্পোর্ট":

from app.routers import items, users

Python প্যাকেজ ও মডিউল সম্পর্কে আরও জানতে মডিউল নিয়ে অফিসিয়াল Python ডকুমেন্টেশন পড়ুন।

নামের সংঘর্ষ এড়ান¶

আমরা সাবমডিউল items থেকে শুধু এর router ভেরিয়েবল ইম্পোর্ট না করে সরাসরি সাবমডিউলটি ইম্পোর্ট করছি।

কারণ সাবমডিউল users-এও router নামে আরেকটি ভেরিয়েবল আছে।

আমরা যদি একটির পর আরেকটি ইম্পোর্ট করতাম, যেমন:

from .routers.items import router
from .routers.users import router

তাহলে users-এর router items-এর router-কে ওভাররাইট করত এবং আমরা একই সময়ে দুটি ব্যবহার করতে পারতাম না।

তাই একই ফাইলে দুটোই ব্যবহার করতে পারার জন্য আমরা সরাসরি সাবমডিউলগুলো ইম্পোর্ট করি:

app/main.py

নোট

আর items.router-এ app/routers/items.py ফাইলের ভেতরের APIRouter আছে।

app.include_router() দিয়ে আমরা প্রতিটি APIRouter-কে মূল FastAPI অ্যাপ্লিকেশনে যোগ করতে পারি।

এটি ওই রাউটারের সব রাউটকে এর অংশ হিসেবে অন্তর্ভুক্ত করবে।

কারিগরি বিবরণ

রাউটারটি মূল অ্যাপ্লিকেশনে অন্তর্ভুক্ত হলেও FastAPI মূল APIRouter ও এর APIRoute-গুলোকে সক্রিয় রাখে।

এর মানে রাউটার অন্তর্ভুক্ত হওয়ার পরেও কাস্টম APIRouter ও APIRoute সাবক্লাসগুলো ভূমিকা রাখতে পারে।

পরামর্শ

রাউটার অন্তর্ভুক্ত করার সময় আপনাকে পারফরম্যান্স নিয়ে চিন্তা করতে হবে না।

এটি হালকা হওয়ার জন্য এবং প্রতিটি রিকোয়েস্টে বাড়তি খরচ যোগ না করার জন্য ডিজাইন করা।

তাই এটি পারফরম্যান্সে প্রভাব ফেলবে না। ⚡

কাস্টম prefix, tags, responses ও dependencies-সহ একটি APIRouter অন্তর্ভুক্ত করুন¶

এবার কল্পনা করুন আপনার প্রতিষ্ঠান আপনাকে app/internal/admin.py ফাইলটি দিয়েছে।

এতে কিছু অ্যাডমিন পাথ অপারেশনসহ একটি APIRouter আছে, যা আপনার প্রতিষ্ঠান কয়েকটি প্রজেক্টের মধ্যে শেয়ার করে।

এই উদাহরণে এটি খুবই সহজ হবে। তবে ধরা যাক যেহেতু এটি প্রতিষ্ঠানের অন্য প্রজেক্টগুলোর সাথে শেয়ার করা, তাই আমরা এটি পরিবর্তন করে সরাসরি APIRouter-এ একটি prefix, dependencies, tags ইত্যাদি যোগ করতে পারি না:

app/internal/admin.py
from fastapi import APIRouter

router = APIRouter()


@router.post("/")
async def update_admin():
    return {"message": "Admin getting schwifty"}

তবুও আমরা চাই APIRouter অন্তর্ভুক্ত করার সময় একটি কাস্টম prefix সেট করতে, যাতে এর সব পাথ অপারেশন /admin দিয়ে শুরু হয়, এই প্রজেক্টের জন্য আমাদের আগে থেকে থাকা dependencies দিয়ে এটি সুরক্ষিত করতে, এবং tags ও responses অন্তর্ভুক্ত করতে।

app.include_router()-এ ওই প্যারামিটারগুলো দিয়ে, মূল APIRouter পরিবর্তন না করেই আমরা এর সবকিছু ঘোষণা করতে পারি:

এভাবে মূল APIRouter অপরিবর্তিত থাকবে, তাই আমরা তখনও সেই একই app/internal/admin.py ফাইল প্রতিষ্ঠানের অন্য প্রজেক্টগুলোর সাথে শেয়ার করতে পারব।

ফলাফল হলো, আমাদের অ্যাপে admin মডিউলের প্রতিটি পাথ অপারেশনে থাকবে:

  • prefix /admin।
  • ট্যাগ admin।
  • ডিপেন্ডেন্সি get_token_header।
  • রেসপন্স 418। 🍵

তবে এটি কেবল আমাদের অ্যাপের ওই APIRouter-কে প্রভাবিত করবে, এটি ব্যবহার করে এমন অন্য কোনো কোডকে নয়।

তাই, যেমন, অন্য প্রজেক্টগুলো ভিন্ন অথেনটিকেশন পদ্ধতিসহ একই APIRouter ব্যবহার করতে পারবে।

খুবই কারিগরি বিবরণ

নোট: এটি একটি খুবই কারিগরি বিবরণ, যা আপনি সম্ভবত এড়িয়ে যেতে পারেন।

APIRouter-গুলো "মাউন্ট" করা হয় না, এগুলো অ্যাপ্লিকেশনের বাকি অংশ থেকে বিচ্ছিন্ন নয়।

FastAPI মূল রাউটার ও পাথ অপারেশনগুলোকে সক্রিয় রাখে, এবং রিকোয়েস্ট সামলানো ও OpenAPI তৈরির সময় রাউটারের prefix, ডিপেন্ডেন্সি, ট্যাগ, রেসপন্স ও অন্যান্য মেটাডেটা একত্রিত করে।

pyproject.toml-এ entrypoint কনফিগার করুন¶

যেহেতু আপনার FastAPI app অবজেক্ট app/main.py-এ আছে, তাই আপনি আপনার pyproject.toml ফাইলে entrypoint এভাবে কনফিগার করতে পারেন:

[tool.fastapi]
entrypoint = "app.main:app"

যা এভাবে ইম্পোর্ট করার সমতুল্য:

from app.main import app

এভাবে fastapi কমান্ড জানবে আপনার অ্যাপ কোথায় খুঁজতে হবে।

নোট

আপনি কমান্ডে পাথও দিতে পারতেন, যেমন:

$ uv run fastapi dev app/main.py

তবে প্রতিবার fastapi কমান্ড চালানোর সময় সঠিক পাথ দেওয়ার কথা আপনাকে মনে রাখতে হবে।

এছাড়া অন্যান্য টুল হয়তো এটি খুঁজে পাবে না, যেমন VS Code এক্সটেনশন বা FastAPI Cloud, তাই pyproject.toml-এ entrypoint ব্যবহার করার পরামর্শ দেওয়া হয়।

স্বয়ংক্রিয় API ডকুমেন্টেশন দেখুন¶

এবার আপনার অ্যাপ চালান:

$ uv run fastapi dev

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

আর http://127.0.0.1:8000/docs-এ ডকুমেন্টেশন খুলুন।

আপনি স্বয়ংক্রিয় API ডকুমেন্টেশন দেখবেন, যাতে সব সাবমডিউলের পাথ সঠিক পাথ (ও prefix) এবং সঠিক ট্যাগসহ অন্তর্ভুক্ত আছে:

একই রাউটার ভিন্ন prefix দিয়ে একাধিকবার অন্তর্ভুক্ত করুন¶

ভিন্ন ভিন্ন prefix দিয়ে একই রাউটারের সাথে আপনি একাধিকবার .include_router() ব্যবহার করতে পারেন।

এটি কাজে আসতে পারে, যেমন, একই API ভিন্ন ভিন্ন prefix-এর অধীনে প্রকাশ করতে, যেমন /api/v1 ও /api/latest।

এটি একটি অ্যাডভান্সড ব্যবহার যা হয়তো আপনার আসলে দরকার হবে না, তবে দরকার হলে এটি আছে।

একটি APIRouter-কে আরেকটিতে অন্তর্ভুক্ত করুন¶

যেভাবে আপনি একটি FastAPI অ্যাপ্লিকেশনে একটি APIRouter অন্তর্ভুক্ত করতে পারেন, সেভাবেই একটি APIRouter-কে আরেকটি APIRouter-এ অন্তর্ভুক্ত করতে পারেন, এভাবে:

router.include_router(other_router)

FastAPI অ্যাপে router অন্তর্ভুক্ত করার আগে বা পরে আপনি এটি করতে পারেন। FastAPI তবুও রাউটিং ও OpenAPI-তে other_router-এর পাথ অপারেশনগুলো অন্তর্ভুক্ত করবে।

রাউটারগুলোতে পরে যোগ করা পাথ অপারেশনের ক্ষেত্রেও একই কথা প্রযোজ্য। আগের অন্তর্ভুক্তির মাধ্যমেও সেগুলো দেখা যাবে।

কারিগরি বিবরণ

একটি রাউটার অন্তর্ভুক্ত করার পরে সরাসরি router.routes পরিবর্তন করা এড়িয়ে চলুন। FastAPI রাউটার অন্তর্ভুক্তিকে সক্রিয় (live) হিসেবে গণ্য করে, তাই মূল রাউটার ও এর রাউটগুলো রাউটিং ও OpenAPI তৈরির অংশ থেকে যায়।

রাউট ও রাউটার যোগ করতে পাথ অপারেশন ডেকোরেটর ও .include_router()-এর মতো ডকুমেন্টেড API ব্যবহার করুন।

router.routes-কে একটি নিম্ন-স্তরের রাউট ট্রি হিসেবে গণ্য করুন যাতে রাউট সংজ্ঞা ও অন্তর্ভুক্ত রাউটার থাকতে পারে, এবং চূড়ান্ত পাথ অপারেশনগুলোর একটি সমতল লিস্ট হিসেবে এর ওপর নির্ভর করা এড়িয়ে চলুন।
