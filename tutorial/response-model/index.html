রেসপন্স মডেল - রিটার্ন টাইপ¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা শিখবেন

  • ফাংশনের রিটার্ন টাইপ দিয়ে রেসপন্সের আকার ঠিক করা।
  • response_model প্যারামিটার কখন আর কেন লাগে।
  • রেসপন্স থেকে পাসওয়ার্ডের মতো গোপন তথ্য কীভাবে স্বয়ংক্রিয়ভাবে বাদ দেবেন (সবচেয়ে জরুরি অংশ)।
  • ইনহেরিট্যান্স দিয়ে এডিটরের সাহায্য আর ডেটা ফিল্টারিং দুটোই পাওয়া।
  • ডিফল্ট মানগুলো রেসপন্স থেকে বাদ দেওয়া, কিছু ফিল্ড অন্তর্ভুক্ত বা বাদ দেওয়া।

পাথ অপারেশন ফাংশনের রিটার্ন টাইপ অ্যানোটেট করে রেসপন্সের জন্য ব্যবহৃত টাইপ ঘোষণা করতে পারেন।

ফাংশনের প্যারামিটারে ইনপুট ডেটার জন্য যেভাবে টাইপ অ্যানোটেশন ব্যবহার করেন, সেভাবেই এখানেও করতে পারেন। Pydantic মডেল, লিস্ট, ডিকশনারি, পূর্ণসংখ্যা, বুলিয়ান এর মতো একক মান ইত্যাদি ব্যবহার করতে পারেন।

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []


@app.post("/items/")
async def create_item(item: Item) -> Item:
    return item


@app.get("/items/")
async def read_items() -> list[Item]:
    return [
        Item(name="Portal Gun", price=42.0),
        Item(name="Plumbus", price=32.0),
    ]

কোডটি সহজ ভাষায়

  • লাইন ১৬: -> Item হলো রিটার্ন টাইপ। এটি বলছে "এই ফাংশন একটি Item ফেরত দেবে"। -> চিহ্নটি Python-এ ফাংশনের রিটার্ন টাইপ লেখার নিয়ম।
  • লাইন ২১: -> list[Item] মানে "এই ফাংশন Item-এর একটি তালিকা ফেরত দেবে"।

FastAPI এই রিটার্ন টাইপ ব্যবহার করে:

  • ফেরত দেওয়া ডেটা যাচাই করে।
    • ডেটা অবৈধ হলে (যেমন কোনো ফিল্ড নেই), তার মানে আপনার অ্যাপের কোডে গোলমাল আছে, যা ফেরত দেওয়ার কথা তা দিচ্ছে না। তখন ভুল ডেটা ফেরত না দিয়ে এটি একটি সার্ভার এরর ফেরত দেবে। এভাবে আপনি আর আপনার ক্লায়েন্টরা নিশ্চিত থাকতে পারেন যে তারা প্রত্যাশিত ডেটা আর ডেটার আকার পাবে।
  • OpenAPI পাথ অপারেশনে রেসপন্সের জন্য একটি JSON Schema যোগ করে।
    • এটি স্বয়ংক্রিয় ডকুমেন্টেশন ব্যবহার করবে।
    • স্বয়ংক্রিয় ক্লায়েন্ট কোড তৈরির টুলগুলোও এটি ব্যবহার করবে।
  • Pydantic ব্যবহার করে ফেরত দেওয়া ডেটা JSON-এ সিরিয়ালাইজ করে। Pydantic-এর ভেতরের অংশ Rust ভাষায় লেখা, তাই এটি অনেক দ্রুত হবে।

কিন্তু সবচেয়ে জরুরি হলো:

  • এটি আউটপুট ডেটাকে রিটার্ন টাইপে যা সংজ্ঞায়িত আছে তার মধ্যেই সীমিত ও ছেঁকে রাখবে।
    • নিরাপত্তার জন্য এটি বিশেষভাবে জরুরি, নিচে আরও দেখব।

উদাহরণ দিয়ে বুঝি

রেসপন্স মডেল হলো একটি ছাঁকনির মতো। আপনার ফাংশন হয়তো একটি বড় ডিকশনারি ফেরত দিচ্ছে, যাতে পাসওয়ার্ড, অভ্যন্তরীণ নোট সবকিছু আছে। রেসপন্স মডেল শুধু সেই ফিল্ডগুলোই বাইরে যেতে দেয় যেগুলো মডেলে লেখা আছে, বাকিটা আটকে যায়।

response_model প্যারামিটার¶

কিছু ক্ষেত্রে আপনাকে এমন ডেটা ফেরত দিতে হয় বা দিতে চান, যা টাইপে ঘোষণা করা জিনিসটির হুবহু মতো নয়।

যেমন, আপনি হয়তো একটি ডিকশনারি বা একটি ডেটাবেস অবজেক্ট ফেরত দিতে চান, কিন্তু ঘোষণা করতে চান একটি Pydantic মডেল হিসেবে। এভাবে আপনার ফেরত দেওয়া অবজেক্টের (যেমন ডিকশনারি বা ডেটাবেস অবজেক্ট) ডকুমেন্টেশন, যাচাই ইত্যাদি সব কাজ Pydantic মডেলটি করবে।

রিটার্ন টাইপ অ্যানোটেশন যোগ করলে টুল আর এডিটরগুলো একটি (সঠিক) এরর দেখিয়ে আপত্তি করবে যে আপনার ফাংশন যে টাইপ (যেমন একটি dict) ফেরত দিচ্ছে তা আপনার ঘোষিত টাইপ (যেমন একটি Pydantic মডেল) থেকে আলাদা।

সেসব ক্ষেত্রে রিটার্ন টাইপের বদলে পাথ অপারেশন ডেকোরেটরের response_model প্যারামিটার ব্যবহার করতে পারেন।

যেকোনো পাথ অপারেশনে response_model প্যারামিটার ব্যবহার করতে পারেন:

  • @app.get()
  • @app.post()
  • @app.put()
  • @app.delete()
  • ইত্যাদি।
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []


@app.post("/items/", response_model=Item)
async def create_item(item: Item) -> Any:
    return item


@app.get("/items/", response_model=list[Item])
async def read_items() -> Any:
    return [
        {"name": "Portal Gun", "price": 42.0},
        {"name": "Plumbus", "price": 32.0},
    ]

কোডটি সহজ ভাষায়

  • লাইন ১৭: response_model=Item ডেকোরেটরের ভেতরে, ফাংশনে নয়।
  • লাইন ১৮: -> Any মানে "যেকোনো কিছু ফেরত দিতে পারে", তাই এডিটর আপত্তি করবে না।
  • লাইন ২২: response_model=list[Item]।
  • লাইন ২৪-২৭: ফাংশন ফেরত দিচ্ছে সাধারণ ডিকশনারির তালিকা, Pydantic অবজেক্ট নয়। FastAPI response_model অনুযায়ী এগুলো যাচাই করে Item আকারে রূপান্তর করবে, যেমন description, tax, tags-এর ডিফল্ট মানগুলো যোগ করে দেবে।

নোট

খেয়াল করুন, response_model হলো "ডেকোরেটর" মেথডের (get, post ইত্যাদি) একটি প্যারামিটার। আপনার পাথ অপারেশন ফাংশনের নয়, যেমনটা সব প্যারামিটার আর বডির ক্ষেত্রে হয়।

response_model সেই একই টাইপ গ্রহণ করে যা আপনি একটি Pydantic মডেলের ফিল্ডে ঘোষণা করতেন। তাই এটি একটি Pydantic মডেল হতে পারে, আবার যেমন Pydantic মডেলের একটি list-ও হতে পারে, যেমন List[Item]।

FastAPI এই response_model ব্যবহার করে ডেটার সব ডকুমেন্টেশন, যাচাই ইত্যাদি করবে, এবং আউটপুট ডেটাকে তার টাইপ ঘোষণা অনুযায়ী রূপান্তর ও ফিল্টারও করবে।

পরামর্শ

আপনার এডিটর, mypy ইত্যাদিতে কঠোর টাইপ যাচাই চালু থাকলে ফাংশনের রিটার্ন টাইপ Any হিসেবে ঘোষণা করতে পারেন।

এতে এডিটরকে বলে দেন যে আপনি ইচ্ছা করেই যেকোনো কিছু ফেরত দিচ্ছেন। তবুও FastAPI response_model দিয়ে ডেটার ডকুমেন্টেশন, যাচাই, ফিল্টারিং ইত্যাদি করবে।

response_model-এর অগ্রাধিকার¶

রিটার্ন টাইপ আর response_model দুটোই ঘোষণা করলে response_model অগ্রাধিকার পাবে, আর FastAPI সেটিই ব্যবহার করবে।

এভাবে রেসপন্স মডেল থেকে আলাদা টাইপ ফেরত দিলেও আপনার ফাংশনে সঠিক টাইপ অ্যানোটেশন যোগ করতে পারেন, যা এডিটর আর mypy-এর মতো টুল ব্যবহার করবে। আর তবুও response_model ব্যবহার করে FastAPI ডেটা যাচাই, ডকুমেন্টেশন ইত্যাদি করবে।

ওই পাথ অপারেশনের জন্য রেসপন্স মডেল তৈরি বন্ধ করতে response_model=None-ও ব্যবহার করতে পারেন। এমন জিনিসের জন্য টাইপ অ্যানোটেশন দিলে, যেগুলো বৈধ Pydantic ফিল্ড নয়, আপনার এটি করতে হতে পারে। নিচের একটি অংশে এর উদাহরণ দেখবেন।

একই ইনপুট ডেটা ফেরত দেওয়া¶

এখানে আমরা একটি UserIn মডেল ঘোষণা করছি, যাতে সাধারণ টেক্সট আকারে একটি পাসওয়ার্ড থাকবে:

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


# Don't do this in production!
@app.post("/user/")
async def create_user(user: UserIn) -> UserIn:
    return user

নোট

EmailStr ব্যবহার করতে প্রথমে email-validator ইনস্টল করুন। EmailStr যাচাই করে যে মানটি একটি সঠিক ইমেইল ঠিকানা।

আপনার প্রজেক্টে এটি যোগ করুন:

$ uv add email-validator

অথবা এভাবে:

$ uv add "pydantic[email]"

আর এই মডেল দিয়েই ইনপুট আর আউটপুট দুটোই ঘোষণা করছি:

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


# Don't do this in production!
@app.post("/user/")
async def create_user(user: UserIn) -> UserIn:
    return user

এখন, যখনই একটি ব্রাউজার পাসওয়ার্ডসহ একজন ইউজার তৈরি করবে, API রেসপন্সে সেই একই পাসওয়ার্ড ফেরত দেবে।

এই ক্ষেত্রে হয়তো সমস্যা না-ও হতে পারে, কারণ একই ইউজার পাসওয়ার্ডটি পাঠাচ্ছে।

কিন্তু একই মডেল যদি আরেকটি পাথ অপারেশনে ব্যবহার করি, তাহলে হয়তো আমাদের ইউজারদের পাসওয়ার্ড প্রত্যেক ক্লায়েন্টকে পাঠিয়ে দেব।

বিপদ

সব ঝুঁকি না জেনে আর নিজে কী করছেন তা ঠিকঠাক না বুঝে কখনো একজন ইউজারের সাধারণ (প্লেইন) পাসওয়ার্ড সংরক্ষণ করবেন না বা এভাবে রেসপন্সে পাঠাবেন না।

একটি আউটপুট মডেল যোগ করুন¶

এর বদলে আমরা সাধারণ পাসওয়ার্ডসহ একটি ইনপুট মডেল আর পাসওয়ার্ড ছাড়া একটি আউটপুট মডেল তৈরি করতে পারি:

from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

এখানে, যদিও আমাদের পাথ অপারেশন ফাংশন পাসওয়ার্ডসহ একই ইনপুট ইউজার ফেরত দিচ্ছে:

from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

...আমরা response_model হিসেবে ঘোষণা করেছি আমাদের মডেল UserOut, যাতে পাসওয়ার্ড নেই:

from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

তাই FastAPI আউটপুট মডেলে ঘোষণা করা হয়নি এমন সব ডেটা ছেঁকে বাদ দেওয়ার দায়িত্ব নেবে (Pydantic ব্যবহার করে)।

কী ঘটছে, ধাপে ধাপে

  1. ক্লায়েন্ট পাঠাল: username, password, email, full_name।
  2. FastAPI এটিকে UserIn হিসেবে যাচাই করে user প্যারামিটারে দিল।
  3. ফাংশন পুরো user (পাসওয়ার্ডসহ) ফেরত দিল।
  4. response_model=UserOut থাকায় FastAPI শুধু username, email, full_name রাখল, password বাদ দিল।
  5. ক্লায়েন্ট পাসওয়ার্ড ছাড়া রেসপন্স পেল।

ভুলবশত পাসওয়ার্ড ফাঁস হওয়া এভাবে কাঠামোগতভাবেই আটকে যায়।

response_model নাকি রিটার্ন টাইপ¶

এই ক্ষেত্রে, যেহেতু দুটি মডেল আলাদা, তাই ফাংশনের রিটার্ন টাইপ UserOut অ্যানোটেট করলে এডিটর আর টুলগুলো আপত্তি করবে যে আমরা একটি অবৈধ টাইপ ফেরত দিচ্ছি, কারণ এরা আলাদা ক্লাস।

এ কারণেই এই উদাহরণে আমাদের এটি response_model প্যারামিটারে ঘোষণা করতে হয়েছে।

...তবে এর সমাধান দেখতে নিচে পড়তে থাকুন।

রিটার্ন টাইপ ও ডেটা ফিল্টারিং¶

আগের উদাহরণ থেকে চলুন। আমরা চেয়েছিলাম ফাংশনটি একটি টাইপ দিয়ে অ্যানোটেট করতে, কিন্তু ফাংশন থেকে এমন কিছু ফেরত দিতে চেয়েছিলাম যাতে আসলে আরও বেশি ডেটা আছে।

আমরা চাই FastAPI রেসপন্স মডেল দিয়ে ডেটা ফিল্টার করতে থাকুক। যাতে ফাংশন বেশি ডেটা ফেরত দিলেও রেসপন্সে কেবল রেসপন্স মডেলে ঘোষিত ফিল্ডগুলোই থাকে।

আগের উদাহরণে, ক্লাসগুলো আলাদা হওয়ায় আমাদের response_model প্যারামিটার ব্যবহার করতে হয়েছিল। কিন্তু তার মানে ফাংশনের রিটার্ন টাইপ যাচাই করা এডিটর আর টুলের সাহায্য আমরা পাই না।

তবে বেশিরভাগ ক্ষেত্রে, যেখানে এমন কিছু করা দরকার, আমরা চাই মডেলটি শুধু এই উদাহরণের মতো কিছু ডেটা ফিল্টার/বাদ দিক।

আর সেসব ক্ষেত্রে আমরা ক্লাস আর ইনহেরিট্যান্স ব্যবহার করে ফাংশনের টাইপ অ্যানোটেশনের সুবিধা নিতে পারি, এডিটর আর টুলে ভালো সাহায্য পেতে পারি, আর তবুও FastAPI-এর ডেটা ফিল্টারিং পেতে পারি।

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class BaseUser(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserIn(BaseUser):
    password: str


@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user

এতে আমরা টুলের সাহায্য পাই, এডিটর আর mypy থেকে, কারণ টাইপের দিক থেকে এই কোড সঠিক। আবার FastAPI থেকে ডেটা ফিল্টারিংও পাই।

এটা কীভাবে কাজ করে? দেখা যাক। 🤓

টাইপ অ্যানোটেশন ও টুল¶

প্রথমে দেখা যাক এডিটর, mypy আর অন্য টুলগুলো এটি কীভাবে দেখবে।

BaseUser-এ আছে মূল ফিল্ডগুলো। তারপর UserIn, BaseUser থেকে ইনহেরিট করে password ফিল্ড যোগ করে, তাই এতে দুটি মডেলেরই সব ফিল্ড থাকবে।

আমরা ফাংশনের রিটার্ন টাইপ অ্যানোটেট করি BaseUser হিসেবে, কিন্তু আসলে ফেরত দিচ্ছি একটি UserIn ইনস্ট্যান্স।

এডিটর, mypy আর অন্য টুলগুলো এ নিয়ে আপত্তি করবে না, কারণ টাইপের দৃষ্টিতে UserIn হলো BaseUser-এর একটি সাব-ক্লাস। অর্থাৎ যেখানে BaseUser জাতীয় কিছু প্রত্যাশিত, সেখানে এটি একটি বৈধ টাইপ।

উদাহরণ দিয়ে বুঝি

ধরুন বলা হলো "একটি যানবাহন নিয়ে আসুন", আর আপনি একটি বাস নিয়ে এলেন। বাস তো যানবাহনই, তাই কেউ আপত্তি করবে না। এখানে BaseUser হলো "যানবাহন", UserIn হলো "বাস" (যানবাহনের সব বৈশিষ্ট্য, সাথে বাড়তি password)।

FastAPI-এর ডেটা ফিল্টারিং¶

এবার FastAPI-এর দিক থেকে, এটি রিটার্ন টাইপ দেখবে এবং নিশ্চিত করবে যে আপনি যা ফেরত দিচ্ছেন তাতে শুধু টাইপে ঘোষিত ফিল্ডগুলোই আছে।

FastAPI ভেতরে Pydantic দিয়ে কয়েকটি কাজ করে, যাতে ফেরত দেওয়া ডেটা ফিল্টারিংয়ে ক্লাস ইনহেরিট্যান্সের সেই একই নিয়মগুলো ব্যবহার না হয়। নইলে আপনি প্রত্যাশার চেয়ে অনেক বেশি ডেটা ফেরত দিয়ে ফেলতে পারতেন।

এভাবে দুই দিকের সেরাটাই পান: টুলের সাহায্যসহ টাইপ অ্যানোটেশন আর ডেটা ফিল্টারিং।

স্বয়ংক্রিয় ডকুমেন্টেশন দেখলে দেখবেন ইনপুট মডেল আর আউটপুট মডেল দুটোরই নিজস্ব JSON Schema থাকবে:

আর ইন্টারঅ্যাকটিভ API ডকুমেন্টেশনে দুটি মডেলই ব্যবহার হবে:

অন্যান্য রিটার্ন টাইপ অ্যানোটেশন¶

এমন ক্ষেত্র থাকতে পারে যেখানে আপনি এমন কিছু ফেরত দেন যা একটি বৈধ Pydantic ফিল্ড নয়, আর ফাংশনে সেভাবেই অ্যানোটেট করেন, শুধু টুলের (এডিটর, mypy ইত্যাদি) সাহায্য পেতে।

সরাসরি একটি Response ফেরত দেওয়া¶

সবচেয়ে প্রচলিত ক্ষেত্র হবে সরাসরি একটি Response ফেরত দেওয়া, যা পরে অ্যাডভান্সড ডকুমেন্টেশনে বোঝানো হয়েছে।

from fastapi import FastAPI, Response
from fastapi.responses import JSONResponse, RedirectResponse

app = FastAPI()


@app.get("/portal")
async def get_portal(teleport: bool = False) -> Response:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return JSONResponse(content={"message": "Here's your interdimensional portal."})

FastAPI এই সহজ ক্ষেত্রটি স্বয়ংক্রিয়ভাবে সামলায়, কারণ রিটার্ন টাইপ অ্যানোটেশনটি হলো Response ক্লাস (বা এর সাব-ক্লাস)।

আর টুলগুলোও খুশি থাকবে, কারণ RedirectResponse আর JSONResponse দুটোই Response-এর সাব-ক্লাস, তাই টাইপ অ্যানোটেশন সঠিক।

এখানে teleport=true দিলে ক্লায়েন্টকে অন্য একটি URL-এ পাঠিয়ে (রিডাইরেক্ট করে) দেওয়া হয়, নইলে একটি JSON বার্তা দেওয়া হয়।

একটি Response সাব-ক্লাস অ্যানোটেট করা¶

টাইপ অ্যানোটেশনে Response-এর একটি সাব-ক্লাসও ব্যবহার করতে পারেন:

from fastapi import FastAPI
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/teleport")
async def get_teleport() -> RedirectResponse:
    return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")

এটিও কাজ করবে, কারণ RedirectResponse হলো Response-এর একটি সাব-ক্লাস, আর FastAPI এই সহজ ক্ষেত্রটি স্বয়ংক্রিয়ভাবে সামলাবে।

অবৈধ রিটার্ন টাইপ অ্যানোটেশন¶

কিন্তু আপনি যখন অন্য কোনো যেমন-তেমন অবজেক্ট ফেরত দেন যা একটি বৈধ Pydantic টাইপ নয় (যেমন একটি ডেটাবেস অবজেক্ট) আর ফাংশনে সেভাবেই অ্যানোটেট করেন, তখন FastAPI সেই টাইপ অ্যানোটেশন থেকে একটি Pydantic রেসপন্স মডেল তৈরির চেষ্টা করবে, এবং ব্যর্থ হবে।

একই ঘটবে যদি আপনার কাছে বিভিন্ন টাইপের একটি ইউনিয়ন থাকে, যার এক বা একাধিক বৈধ Pydantic টাইপ নয়। যেমন এটি ব্যর্থ হবে 💥:

from fastapi import FastAPI, Response
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/portal")
async def get_portal(teleport: bool = False) -> Response | dict:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return {"message": "Here's your interdimensional portal."}

...এটি ব্যর্থ হয় কারণ টাইপ অ্যানোটেশনটি একটি Pydantic টাইপ নয় এবং কেবল একটিমাত্র Response ক্লাস বা সাব-ক্লাসও নয়, এটি একটি Response আর একটি dict-এর ইউনিয়ন (দুটির যেকোনোটি)।

রেসপন্স মডেল বন্ধ করুন¶

ওপরের উদাহরণ থেকে চলুন, হয়তো আপনি FastAPI-এর ডিফল্ট ডেটা যাচাই, ডকুমেন্টেশন, ফিল্টারিং ইত্যাদি চান না।

কিন্তু তবুও এডিটর আর টাইপ যাচাইকারীর (যেমন mypy) মতো টুলের সাহায্য পেতে ফাংশনে রিটার্ন টাইপ অ্যানোটেশন রাখতে চান।

এই ক্ষেত্রে response_model=None সেট করে রেসপন্স মডেল তৈরি বন্ধ করতে পারেন:

from fastapi import FastAPI, Response
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/portal", response_model=None)
async def get_portal(teleport: bool = False) -> Response | dict:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return {"message": "Here's your interdimensional portal."}

এতে FastAPI রেসপন্স মডেল তৈরি এড়িয়ে যাবে, আর এভাবে আপনার FastAPI অ্যাপ্লিকেশনকে প্রভাবিত না করেই প্রয়োজনীয় যেকোনো রিটার্ন টাইপ অ্যানোটেশন রাখতে পারবেন। 🤓

রেসপন্স মডেলের এনকোডিং প্যারামিটার¶

আপনার রেসপন্স মডেলে ডিফল্ট মান থাকতে পারে, যেমন:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5
    tags: list[str] = []


items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The bartenders", "price": 62, "tax": 20.2},
    "baz": {"name": "Baz", "description": None, "price": 50.2, "tax": 10.5, "tags": []},
}


@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
async def read_item(item_id: str):
    return items[item_id]
  • description: Union[str, None] = None (বা Python 3.10-এ str | None = None)-এর ডিফল্ট হলো None।
  • tax: float = 10.5-এর ডিফল্ট হলো 10.5।
  • tags: List[str] = []-এর ডিফল্ট হলো একটি খালি লিস্ট: []।

কিন্তু সেগুলো যদি আসলে সংরক্ষিত না থাকে, তাহলে হয়তো ফলাফল থেকে সেগুলো বাদ দিতে চাইবেন।

যেমন, NoSQL ডেটাবেসে অনেক ঐচ্ছিক অ্যাট্রিবিউটসহ মডেল থাকলে, আপনি হয়তো ডিফল্ট মানে ভরা খুব লম্বা JSON রেসপন্স পাঠাতে চাইবেন না।

response_model_exclude_unset প্যারামিটার ব্যবহার করুন¶

পাথ অপারেশন ডেকোরেটরের প্যারামিটার response_model_exclude_unset=True সেট করতে পারেন:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5
    tags: list[str] = []


items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The bartenders", "price": 62, "tax": 20.2},
    "baz": {"name": "Baz", "description": None, "price": 50.2, "tax": 10.5, "tags": []},
}


@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
async def read_item(item_id: str):
    return items[item_id]

তাহলে ওই ডিফল্ট মানগুলো রেসপন্সে অন্তর্ভুক্ত হবে না, শুধু আসলে সেট করা মানগুলো থাকবে।

তাই ID foo-ওয়ালা আইটেমের জন্য ওই পাথ অপারেশনে রিকোয়েস্ট পাঠালে রেসপন্স (ডিফল্ট মান ছাড়া) হবে:

{
    "name": "Foo",
    "price": 50.2
}

নোট

এগুলোও ব্যবহার করতে পারেন:

  • response_model_exclude_defaults=True: ডিফল্টের সমান মানগুলো বাদ দেয়।
  • response_model_exclude_none=True: None মানগুলো বাদ দেয়।

যেমন exclude_defaults আর exclude_none-এর জন্য Pydantic ডকুমেন্টেশনে বর্ণিত আছে।

ডিফল্টওয়ালা ফিল্ডে মানসহ ডেটা¶

কিন্তু আপনার ডেটায় যদি মডেলের ডিফল্টওয়ালা ফিল্ডগুলোর জন্য মান থাকে, যেমন ID bar-ওয়ালা আইটেম:

{
    "name": "Bar",
    "description": "The bartenders",
    "price": 62,
    "tax": 20.2
}

তাহলে সেগুলো রেসপন্সে অন্তর্ভুক্ত হবে।

ডিফল্টের সমান মানসহ ডেটা¶

ডেটায় যদি ডিফল্টের সমান মান থাকে, যেমন ID baz-ওয়ালা আইটেম:

{
    "name": "Baz",
    "description": None,
    "price": 50.2,
    "tax": 10.5,
    "tags": []
}

FastAPI যথেষ্ট বুদ্ধিমান (আসলে, Pydantic যথেষ্ট বুদ্ধিমান) বুঝতে যে, description, tax আর tags-এর মান ডিফল্টের সমান হলেও, সেগুলো স্পষ্টভাবে সেট করা হয়েছে (ডিফল্ট থেকে নেওয়া হয়নি)।

তাই সেগুলো JSON রেসপন্সে অন্তর্ভুক্ত হবে।

পরামর্শ

খেয়াল করুন, ডিফল্ট মান যেকোনো কিছু হতে পারে, শুধু None নয়।

এগুলো একটি লিস্ট ([]), 10.5-এর মতো একটি float ইত্যাদি হতে পারে।

response_model_include আর response_model_exclude¶

পাথ অপারেশন ডেকোরেটরের প্যারামিটার response_model_include আর response_model_exclude-ও ব্যবহার করতে পারেন।

এগুলো অ্যাট্রিবিউটের নামের একটি str-এর set নেয়, যেগুলো অন্তর্ভুক্ত করতে হবে (বাকিগুলো বাদ দিয়ে) বা বাদ দিতে হবে (বাকিগুলো রেখে)।

আপনার যদি কেবল একটি Pydantic মডেল থাকে আর আউটপুট থেকে কিছু ডেটা সরাতে চান, তাহলে এটি একটি দ্রুত শর্টকাট হিসেবে ব্যবহার করা যায়।

পরামর্শ

তবে এই প্যারামিটারগুলোর বদলে এখনো ওপরের ধারণাগুলো, মানে একাধিক ক্লাস ব্যবহার করারই সুপারিশ করা হয়।

কারণ response_model_include বা response_model_exclude ব্যবহার করে কিছু অ্যাট্রিবিউট বাদ দিলেও, আপনার অ্যাপের OpenAPI (আর ডকুমেন্টেশন)-এ তৈরি হওয়া JSON Schema তখনও পুরো মডেলেরটাই থাকবে।

একইভাবে কাজ করা response_model_by_alias-এর ক্ষেত্রেও এটি প্রযোজ্য।

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5


items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The Bar fighters", "price": 62, "tax": 20.2},
    "baz": {
        "name": "Baz",
        "description": "There goes my baz",
        "price": 50.2,
        "tax": 10.5,
    },
}


@app.get(
    "/items/{item_id}/name",
    response_model=Item,
    response_model_include={"name", "description"},
)
async def read_item_name(item_id: str):
    return items[item_id]


@app.get("/items/{item_id}/public", response_model=Item, response_model_exclude={"tax"})
async def read_item_public_data(item_id: str):
    return items[item_id]

এখানে /items/foo/name শুধু name আর description ফেরত দেবে, আর /items/foo/public tax ছাড়া বাকি সব ফেরত দেবে।

পরামর্শ

{"name", "description"} সিনট্যাক্স ওই দুটি মান দিয়ে একটি set তৈরি করে।

এটি set(["name", "description"])-এর সমতুল্য।

set-এর বদলে list ব্যবহার¶

set ব্যবহার করতে ভুলে গিয়ে যদি list বা tuple ব্যবহার করেন, FastAPI তবুও এটিকে একটি set-এ রূপান্তর করবে আর সঠিকভাবে কাজ করবে:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5


items = {

    "bar": {"name": "Bar", "description": "The Bar fighters", "price": 62, "tax": 20.2},

        "description": "There goes my baz",

    },
}


@app.get(

সংক্ষেপে¶

রেসপন্স মডেল সংজ্ঞায়িত করতে, আর বিশেষ করে গোপন ডেটা যে ছেঁকে বাদ পড়ছে তা নিশ্চিত করতে, পাথ অপারেশন ডেকোরেটরের response_model প্যারামিটার ব্যবহার করুন।

শুধু স্পষ্টভাবে সেট করা মানগুলো ফেরত দিতে response_model_exclude_unset ব্যবহার করুন।

সংক্ষেপে মনে রাখুন

  • রিটার্ন টাইপ (-> Item) বা response_model=Item দিয়ে রেসপন্সের আকার ঠিক করুন, দুটো থাকলে response_model জিতবে।
  • রেসপন্স মডেল একটি ছাঁকনি: মডেলে নেই এমন ফিল্ড (যেমন পাসওয়ার্ড) বাইরে যায় না।
  • ইনপুট (UserIn) আর আউটপুট (UserOut) মডেল আলাদা রাখুন, অথবা ইনহেরিট্যান্স (UserIn(BaseUser)) ব্যবহার করে রিটার্ন টাইপ BaseUser দিন।
  • ডিফল্ট মান বাদ দিতে response_model_exclude_unset=True।
  • Response ফেরত দিলে বা অদ্ভুত টাইপ থাকলে দরকার হলে response_model=None।
