রেসপন্স মডেল - রিটার্ন টাইপ¶

🌐 AI এবং মানুষের যৌথ অনুবাদ

এই অনুবাদটি মানুষের নির্দেশনায় AI দিয়ে করা হয়েছে। 🤝

এতে মূল অর্থ ভুল বোঝা বা অস্বাভাবিক শোনানোর মতো ভুল থাকতে পারে। 🤖

ইংরেজি সংস্করণ

পাথ অপারেশন ফাংশনের রিটার্ন টাইপ অ্যানোটেট করে আপনি রেসপন্সের জন্য ব্যবহৃত টাইপ ঘোষণা করতে পারেন।

ফাংশনের প্যারামিটারে ইনপুট ডেটার জন্য যেভাবে টাইপ অ্যানোটেশন ব্যবহার করেন, এখানেও সেভাবেই ব্যবহার করতে পারেন: Pydantic মডেল, লিস্ট, ডিকশনারি, পূর্ণসংখ্যা ও বুলিয়ানের মতো স্কেলার ভ্যালু ইত্যাদি।

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []


@app.post("/items/")
async def create_item(item: Item) -> Item:
    return item


@app.get("/items/")
async def read_items() -> list[Item]:
    return [
        Item(name="Portal Gun", price=42.0),
        Item(name="Plumbus", price=32.0),
    ]

FastAPI এই রিটার্ন টাইপ ব্যবহার করবে:

  • রিটার্ন করা ডেটা ভ্যালিডেট করতে।
    • ডেটা অবৈধ হলে (যেমন কোনো ফিল্ড অনুপস্থিত), এর মানে আপনার অ্যাপের কোডে সমস্যা আছে, যা রিটার্ন করার কথা তা রিটার্ন করছে না, আর তখন এটি ভুল ডেটা রিটার্ন না করে একটি সার্ভার এরর রিটার্ন করবে। এভাবে আপনি ও আপনার ক্লায়েন্টরা নিশ্চিত থাকতে পারেন যে তারা প্রত্যাশিত ডেটা ও ডেটার আকৃতি পাবে।
  • OpenAPI পাথ অপারেশনে রেসপন্সের জন্য একটি JSON Schema যোগ করতে।
    • এটি স্বয়ংক্রিয় ডকুমেন্টেশন ব্যবহার করবে।
    • স্বয়ংক্রিয় ক্লায়েন্ট কোড জেনারেশন টুলগুলোও এটি ব্যবহার করবে।
  • Pydantic ব্যবহার করে রিটার্ন করা ডেটা JSON-এ সিরিয়ালাইজ করতে, যা Rust-এ লেখা, তাই এটি অনেক বেশি দ্রুত হবে।

তবে সবচেয়ে গুরুত্বপূর্ণ:

  • এটি আউটপুট ডেটাকে রিটার্ন টাইপে যা সংজ্ঞায়িত করা আছে তাতে সীমিত ও ফিল্টার করবে।
    • এটি সিকিউরিটির জন্য বিশেষভাবে গুরুত্বপূর্ণ, নিচে এ সম্পর্কে আরও দেখব।

response_model প্যারামিটার¶

কিছু ক্ষেত্রে আপনাকে এমন ডেটা রিটার্ন করতে হয় বা করতে চান যা টাইপে যা ঘোষণা করা আছে হুবহু তা নয়।

যেমন, আপনি হয়তো একটি ডিকশনারি বা একটি ডেটাবেস অবজেক্ট রিটার্ন করতে চান, কিন্তু এটিকে একটি Pydantic মডেল হিসেবে ঘোষণা করতে চান। এভাবে আপনার রিটার্ন করা অবজেক্টের (যেমন একটি ডিকশনারি বা ডেটাবেস অবজেক্ট) জন্য সব ডেটা ডকুমেন্টেশন, ভ্যালিডেশন ইত্যাদি Pydantic মডেলটি করবে।

আপনি রিটার্ন টাইপ অ্যানোটেশন যোগ করলে টুল ও এডিটরগুলো একটি (সঠিক) এরর দিয়ে আপত্তি জানাবে যে আপনার ফাংশন এমন একটি টাইপ (যেমন একটি dict) রিটার্ন করছে যা আপনার ঘোষিত টাইপ (যেমন একটি Pydantic মডেল) থেকে আলাদা।

সেসব ক্ষেত্রে রিটার্ন টাইপের বদলে আপনি পাথ অপারেশন ডেকোরেটরের প্যারামিটার response_model ব্যবহার করতে পারেন।

যেকোনো পাথ অপারেশনে আপনি response_model প্যারামিটার ব্যবহার করতে পারেন:

  • @app.get()
  • @app.post()
  • @app.put()
  • @app.delete()
  • ইত্যাদি।
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
    tags: list[str] = []


@app.post("/items/", response_model=Item)
async def create_item(item: Item) -> Any:
    return item


@app.get("/items/", response_model=list[Item])
async def read_items() -> Any:
    return [
        {"name": "Portal Gun", "price": 42.0},
        {"name": "Plumbus", "price": 32.0},
    ]

নোট

লক্ষ করুন, response_model হলো "ডেকোরেটর" মেথডের (get, post ইত্যাদি) একটি প্যারামিটার। সব প্যারামিটার ও বডির মতো আপনার পাথ অপারেশন ফাংশনের নয়।

একটি Pydantic মডেল ফিল্ডের জন্য আপনি যে টাইপ ঘোষণা করতেন, response_model সেই একই টাইপ গ্রহণ করে, তাই এটি একটি Pydantic মডেল হতে পারে, আবার, যেমন, Pydantic মডেলের একটি list-ও হতে পারে, যেমন List[Item]।

FastAPI এই response_model ব্যবহার করে সব ডেটা ডকুমেন্টেশন, ভ্যালিডেশন ইত্যাদি করবে, এবং আউটপুট ডেটাকে এর টাইপ ঘোষণা অনুযায়ী রূপান্তর ও ফিল্টারও করবে।

পরামর্শ

আপনার এডিটর, mypy ইত্যাদিতে যদি কঠোর টাইপ চেক থাকে, তাহলে আপনি ফাংশনের রিটার্ন টাইপ Any হিসেবে ঘোষণা করতে পারেন।

এভাবে আপনি এডিটরকে জানান যে আপনি ইচ্ছাকৃতভাবে যেকোনো কিছু রিটার্ন করছেন। তবে FastAPI তবুও response_model দিয়ে ডেটা ডকুমেন্টেশন, ভ্যালিডেশন, ফিল্টারিং ইত্যাদি করবে।

response_model-এর অগ্রাধিকার¶

আপনি যদি একটি রিটার্ন টাইপ এবং একটি response_model দুটোই ঘোষণা করেন, তাহলে response_model অগ্রাধিকার পাবে এবং FastAPI সেটিই ব্যবহার করবে।

এভাবে রেসপন্স মডেল থেকে আলাদা কোনো টাইপ রিটার্ন করলেও আপনি এডিটর ও mypy-এর মতো টুলের জন্য আপনার ফাংশনে সঠিক টাইপ অ্যানোটেশন যোগ করতে পারেন। আর তবুও response_model ব্যবহার করে FastAPI দিয়ে ডেটা ভ্যালিডেশন, ডকুমেন্টেশন ইত্যাদি করাতে পারেন।

ওই পাথ অপারেশনের জন্য রেসপন্স মডেল তৈরি বন্ধ করতে আপনি response_model=None-ও ব্যবহার করতে পারেন। আপনি যদি এমন কিছুর জন্য টাইপ অ্যানোটেশন যোগ করেন যা বৈধ Pydantic ফিল্ড নয়, তাহলে এটি করতে হতে পারে। নিচের একটি অংশে আপনি এর একটি উদাহরণ দেখবেন।

একই ইনপুট ডেটা রিটার্ন করুন¶

এখানে আমরা একটি UserIn মডেল ঘোষণা করছি, এতে একটি প্লেইনটেক্সট পাসওয়ার্ড থাকবে:

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


# Don't do this in production!
@app.post("/user/")
async def create_user(user: UserIn) -> UserIn:
    return user

নোট

EmailStr ব্যবহার করতে প্রথমে email-validator ইনস্টল করুন।

এটি আপনার প্রজেক্টে যোগ করুন:

$ uv add email-validator

অথবা এভাবে:

$ uv add "pydantic[email]"

আর আমরা এই মডেলটি দিয়ে আমাদের ইনপুট ঘোষণা করছি এবং একই মডেল দিয়ে আমাদের আউটপুট ঘোষণা করছি:

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


# Don't do this in production!
@app.post("/user/")
async def create_user(user: UserIn) -> UserIn:
    return user

এখন যখনই কোনো ব্রাউজার পাসওয়ার্ডসহ একজন ইউজার তৈরি করবে, API রেসপন্সে একই পাসওয়ার্ড রিটার্ন করবে।

এক্ষেত্রে হয়তো সমস্যা নেই, কারণ পাসওয়ার্ডটি একই ইউজার পাঠাচ্ছেন।

কিন্তু আমরা যদি অন্য কোনো পাথ অপারেশনের জন্য একই মডেল ব্যবহার করি, তাহলে আমরা আমাদের ইউজারদের পাসওয়ার্ড প্রত্যেক ক্লায়েন্টকে পাঠিয়ে ফেলতে পারি।

বিপদ

সব ঝুঁকি জেনে এবং আপনি কী করছেন তা না বুঝে কখনো কোনো ইউজারের প্লেইন পাসওয়ার্ড সংরক্ষণ করবেন না বা এভাবে রেসপন্সে পাঠাবেন না।

একটি আউটপুট মডেল যোগ করুন¶

এর বদলে আমরা প্লেইনটেক্সট পাসওয়ার্ডসহ একটি ইনপুট মডেল এবং পাসওয়ার্ড ছাড়া একটি আউটপুট মডেল তৈরি করতে পারি:

from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

এখানে, যদিও আমাদের পাথ অপারেশন ফাংশন পাসওয়ার্ডসহ সেই একই ইনপুট ইউজার রিটার্ন করছে:

from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

...আমরা response_model হিসেবে আমাদের UserOut মডেলটি ঘোষণা করেছি, যাতে পাসওয়ার্ড নেই:

from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user

তাই আউটপুট মডেলে ঘোষণা করা নেই এমন সব ডেটা ফিল্টার করে বাদ দেওয়ার দায়িত্ব FastAPI নেবে (Pydantic ব্যবহার করে)।

response_model নাকি রিটার্ন টাইপ¶

এক্ষেত্রে, যেহেতু দুটি মডেল আলাদা, তাই আমরা যদি ফাংশনের রিটার্ন টাইপ UserOut হিসেবে অ্যানোটেট করতাম, তাহলে এডিটর ও টুলগুলো আপত্তি জানাত যে আমরা একটি অবৈধ টাইপ রিটার্ন করছি, কারণ সেগুলো ভিন্ন ক্লাস।

এ কারণেই এই উদাহরণে আমাদের এটি response_model প্যারামিটারে ঘোষণা করতে হয়েছে।

...তবে কীভাবে এটি কাটিয়ে ওঠা যায় তা দেখতে নিচে পড়া চালিয়ে যান।

রিটার্ন টাইপ ও ডেটা ফিল্টারিং¶

আগের উদাহরণ থেকে চালিয়ে যাওয়া যাক। আমরা ফাংশনটিকে একটি টাইপ দিয়ে অ্যানোটেট করতে চেয়েছিলাম, কিন্তু ফাংশন থেকে এমন কিছু রিটার্ন করতে চেয়েছিলাম যাতে আসলে আরও বেশি ডেটা থাকে।

আমরা চাই FastAPI রেসপন্স মডেল ব্যবহার করে ডেটা ফিল্টার করা চালিয়ে যাক। যাতে ফাংশন বেশি ডেটা রিটার্ন করলেও রেসপন্সে কেবল রেসপন্স মডেলে ঘোষিত ফিল্ডগুলোই থাকে।

আগের উদাহরণে ক্লাসগুলো আলাদা হওয়ায় আমাদের response_model প্যারামিটার ব্যবহার করতে হয়েছিল। কিন্তু এর মানে এটাও যে ফাংশনের রিটার্ন টাইপ যাচাই করা এডিটর ও টুলগুলো থেকে আমরা সাপোর্ট পাই না।

তবে বেশিরভাগ ক্ষেত্রে যখন আমাদের এরকম কিছু করতে হয়, তখন আমরা চাই মডেলটি এই উদাহরণের মতো শুধু কিছু ডেটা ফিল্টার/বাদ দিক।

আর সেসব ক্ষেত্রে আমরা ক্লাস ও ইনহেরিটেন্স ব্যবহার করে ফাংশনের টাইপ অ্যানোটেশনের সুবিধা নিয়ে এডিটর ও টুলে আরও ভালো সাপোর্ট পেতে পারি, আর তবুও FastAPI-এর ডেটা ফিল্টারিং পেতে পারি।

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class BaseUser(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserIn(BaseUser):
    password: str


@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user

এর মাধ্যমে আমরা এডিটর ও mypy থেকে টুলিং সাপোর্ট পাই, কারণ টাইপের দিক থেকে এই কোডটি সঠিক, আবার FastAPI থেকে ডেটা ফিল্টারিংও পাই।

এটি কীভাবে কাজ করে? চলুন দেখে নিই। 🤓

টাইপ অ্যানোটেশন ও টুলিং¶

প্রথমে দেখা যাক এডিটর, mypy ও অন্যান্য টুল এটিকে কীভাবে দেখবে।

BaseUser-এ মূল ফিল্ডগুলো আছে। তারপর UserIn BaseUser থেকে ইনহেরিট করে এবং password ফিল্ড যোগ করে, তাই এতে দুটি মডেলের সব ফিল্ড থাকবে।

আমরা ফাংশনের রিটার্ন টাইপ BaseUser হিসেবে অ্যানোটেট করি, কিন্তু আসলে একটি UserIn ইনস্ট্যান্স রিটার্ন করি।

এডিটর, mypy ও অন্যান্য টুল এ নিয়ে আপত্তি জানাবে না, কারণ টাইপিংয়ের ভাষায় UserIn হলো BaseUser-এর একটি সাবক্লাস, অর্থাৎ যেখানে BaseUser হলেই চলে সেখানে এটি একটি বৈধ টাইপ।

FastAPI ডেটা ফিল্টারিং¶

এবার FastAPI-এর ক্ষেত্রে, এটি রিটার্ন টাইপ দেখবে এবং নিশ্চিত করবে যে আপনি যা রিটার্ন করছেন তাতে কেবল টাইপে ঘোষিত ফিল্ডগুলোই আছে।

FastAPI ভেতরে ভেতরে Pydantic দিয়ে বেশ কিছু কাজ করে যাতে রিটার্ন করা ডেটা ফিল্টারিংয়ে ক্লাস ইনহেরিটেন্সের ওই একই নিয়ম ব্যবহার না হয়, নইলে আপনি প্রত্যাশার চেয়ে অনেক বেশি ডেটা রিটার্ন করে ফেলতে পারতেন।

এভাবে আপনি দুই দিকেরই সেরাটা পান: টুলিং সাপোর্টসহ টাইপ অ্যানোটেশন এবং ডেটা ফিল্টারিং।

ডকুমেন্টেশনে দেখুন¶

স্বয়ংক্রিয় ডকুমেন্টেশন দেখলে আপনি যাচাই করতে পারবেন যে ইনপুট মডেল ও আউটপুট মডেল দুটোরই নিজস্ব JSON Schema আছে:

আর দুটি মডেলই ইন্টারঅ্যাকটিভ API ডকুমেন্টেশনে ব্যবহার হবে:

অন্যান্য রিটার্ন টাইপ অ্যানোটেশন¶

এমন ক্ষেত্র থাকতে পারে যেখানে আপনি এমন কিছু রিটার্ন করেন যা বৈধ Pydantic ফিল্ড নয়, এবং শুধু টুলিংয়ের (এডিটর, mypy ইত্যাদি) সাপোর্ট পাওয়ার জন্য ফাংশনে সেটি অ্যানোটেট করেন।

সরাসরি একটি Response রিটার্ন করুন¶

সবচেয়ে প্রচলিত ক্ষেত্র হবে সরাসরি একটি Response রিটার্ন করা, যা পরে অ্যাডভান্সড ডকুমেন্টেশনে ব্যাখ্যা করা হয়েছে।

from fastapi import FastAPI, Response
from fastapi.responses import JSONResponse, RedirectResponse

app = FastAPI()


@app.get("/portal")
async def get_portal(teleport: bool = False) -> Response:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return JSONResponse(content={"message": "Here's your interdimensional portal."})

এই সহজ ক্ষেত্রটি FastAPI স্বয়ংক্রিয়ভাবে সামলায়, কারণ রিটার্ন টাইপ অ্যানোটেশনটি Response ক্লাস (বা এর একটি সাবক্লাস)।

আর টুলগুলোও খুশি থাকবে, কারণ RedirectResponse ও JSONResponse দুটোই Response-এর সাবক্লাস, তাই টাইপ অ্যানোটেশনটি সঠিক।

একটি Response সাবক্লাস অ্যানোটেট করুন¶

টাইপ অ্যানোটেশনে আপনি Response-এর একটি সাবক্লাসও ব্যবহার করতে পারেন:

from fastapi import FastAPI
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/teleport")
async def get_teleport() -> RedirectResponse:
    return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")

এটিও কাজ করবে কারণ RedirectResponse হলো Response-এর একটি সাবক্লাস, আর FastAPI এই সহজ ক্ষেত্রটি স্বয়ংক্রিয়ভাবে সামলাবে।

অবৈধ রিটার্ন টাইপ অ্যানোটেশন¶

কিন্তু আপনি যখন এমন অন্য কোনো যেকোনো অবজেক্ট রিটার্ন করেন যা বৈধ Pydantic টাইপ নয় (যেমন একটি ডেটাবেস অবজেক্ট) এবং ফাংশনে সেভাবেই অ্যানোটেট করেন, তখন FastAPI ওই টাইপ অ্যানোটেশন থেকে একটি Pydantic রেসপন্স মডেল তৈরির চেষ্টা করবে, এবং ব্যর্থ হবে।

একই ঘটনা ঘটত যদি আপনার কাছে বিভিন্ন টাইপের মধ্যে একটি ইউনিয়ন-এর মতো কিছু থাকত যেখানে এক বা একাধিক টাইপ বৈধ Pydantic টাইপ নয়, যেমন এটি ব্যর্থ হবে 💥:

from fastapi import FastAPI, Response
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/portal")
async def get_portal(teleport: bool = False) -> Response | dict:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return {"message": "Here's your interdimensional portal."}

...এটি ব্যর্থ হয় কারণ টাইপ অ্যানোটেশনটি কোনো Pydantic টাইপ নয় এবং কেবল একটিমাত্র Response ক্লাস বা সাবক্লাসও নয়, এটি একটি Response ও একটি dict-এর মধ্যে ইউনিয়ন (দুটির যেকোনোটি)।

রেসপন্স মডেল বন্ধ করুন¶

ওপরের উদাহরণ থেকে চালিয়ে গেলে, আপনি হয়তো FastAPI যে ডিফল্ট ডেটা ভ্যালিডেশন, ডকুমেন্টেশন, ফিল্টারিং ইত্যাদি করে তা চান না।

কিন্তু এডিটর ও টাইপ চেকারের (যেমন mypy) মতো টুল থেকে সাপোর্ট পেতে আপনি হয়তো তবুও ফাংশনে রিটার্ন টাইপ অ্যানোটেশনটি রাখতে চান।

এক্ষেত্রে response_model=None সেট করে আপনি রেসপন্স মডেল তৈরি বন্ধ করতে পারেন:

from fastapi import FastAPI, Response
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/portal", response_model=None)
async def get_portal(teleport: bool = False) -> Response | dict:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return {"message": "Here's your interdimensional portal."}

এতে FastAPI রেসপন্স মডেল তৈরি এড়িয়ে যাবে, আর এভাবে আপনার FastAPI অ্যাপ্লিকেশনে কোনো প্রভাব না ফেলেই আপনি যেকোনো প্রয়োজনীয় রিটার্ন টাইপ অ্যানোটেশন রাখতে পারবেন। 🤓

রেসপন্স মডেলের এনকোডিং প্যারামিটার¶

আপনার রেসপন্স মডেলে ডিফল্ট ভ্যালু থাকতে পারে, যেমন:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5
    tags: list[str] = []


items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The bartenders", "price": 62, "tax": 20.2},
    "baz": {"name": "Baz", "description": None, "price": 50.2, "tax": 10.5, "tags": []},
}


@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
async def read_item(item_id: str):
    return items[item_id]
  • description: Union[str, None] = None (বা Python 3.10-এ str | None = None)-এর ডিফল্ট হলো None।
  • tax: float = 10.5-এর ডিফল্ট হলো 10.5।
  • tags: List[str] = []-এর ডিফল্ট হলো একটি খালি লিস্ট: []।

কিন্তু সেগুলো যদি আসলে সংরক্ষিত না হয়ে থাকে, তাহলে আপনি হয়তো ফলাফল থেকে সেগুলো বাদ দিতে চাইবেন।

যেমন, একটি NoSQL ডেটাবেসে যদি আপনার অনেক ঐচ্ছিক অ্যাট্রিবিউটসহ মডেল থাকে, কিন্তু আপনি ডিফল্ট ভ্যালুতে ভরা খুব লম্বা JSON রেসপন্স পাঠাতে চান না।

response_model_exclude_unset প্যারামিটার ব্যবহার করুন¶

আপনি পাথ অপারেশন ডেকোরেটরের প্যারামিটার response_model_exclude_unset=True সেট করতে পারেন:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5
    tags: list[str] = []


items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The bartenders", "price": 62, "tax": 20.2},
    "baz": {"name": "Baz", "description": None, "price": 50.2, "tax": 10.5, "tags": []},
}


@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
async def read_item(item_id: str):
    return items[item_id]

আর ওই ডিফল্ট ভ্যালুগুলো রেসপন্সে অন্তর্ভুক্ত হবে না, কেবল আসলে সেট করা ভ্যালুগুলোই থাকবে।

তাই আপনি যদি foo ID-সহ আইটেমের জন্য ওই পাথ অপারেশনে একটি রিকোয়েস্ট পাঠান, তাহলে রেসপন্স (ডিফল্ট ভ্যালু বাদে) হবে:

{
    "name": "Foo",
    "price": 50.2
}

নোট

আপনি এগুলোও ব্যবহার করতে পারেন:

  • response_model_exclude_defaults=True
  • response_model_exclude_none=True

যেমনটা exclude_defaults ও exclude_none-এর জন্য Pydantic ডকুমেন্টেশনে বর্ণনা করা হয়েছে।

ডিফল্টসহ ফিল্ডের জন্য ভ্যালুসহ ডেটা¶

কিন্তু আপনার ডেটায় যদি ডিফল্ট ভ্যালুসহ মডেলের ফিল্ডগুলোর জন্য ভ্যালু থাকে, যেমন bar ID-সহ আইটেমটি:

{
    "name": "Bar",
    "description": "The bartenders",
    "price": 62,
    "tax": 20.2
}

তাহলে সেগুলো রেসপন্সে অন্তর্ভুক্ত হবে।

ডিফল্টের মতো একই ভ্যালুসহ ডেটা¶

ডেটায় যদি ডিফল্টগুলোর মতো একই ভ্যালু থাকে, যেমন baz ID-সহ আইটেমটি:

{
    "name": "Baz",
    "description": None,
    "price": 50.2,
    "tax": 10.5,
    "tags": []
}

FastAPI যথেষ্ট বুদ্ধিমান (আসলে, Pydantic যথেষ্ট বুদ্ধিমান) বুঝতে যে, যদিও description, tax ও tags-এর ভ্যালু ডিফল্টের মতোই, সেগুলো স্পষ্টভাবে সেট করা হয়েছে (ডিফল্ট থেকে নেওয়া হয়নি)।

তাই সেগুলো JSON রেসপন্সে অন্তর্ভুক্ত হবে।

পরামর্শ

লক্ষ করুন, ডিফল্ট ভ্যালু যেকোনো কিছু হতে পারে, শুধু None নয়।

এগুলো একটি লিস্ট ([]), 10.5-এর একটি float ইত্যাদি হতে পারে।

response_model_include ও response_model_exclude¶

আপনি পাথ অপারেশন ডেকোরেটরের প্যারামিটার response_model_include ও response_model_exclude-ও ব্যবহার করতে পারেন।

এগুলো অ্যাট্রিবিউটের নামসহ str-এর একটি set নেয়, যেগুলো অন্তর্ভুক্ত করতে হবে (বাকিগুলো বাদ দিয়ে) বা বাদ দিতে হবে (বাকিগুলো অন্তর্ভুক্ত রেখে)।

আপনার যদি কেবল একটি Pydantic মডেল থাকে এবং আউটপুট থেকে কিছু ডেটা সরাতে চান, তাহলে এটি একটি দ্রুত শর্টকাট হিসেবে ব্যবহার করা যায়।

পরামর্শ

তবে এই প্যারামিটারগুলোর বদলে ওপরের ধারণাগুলো, অর্থাৎ একাধিক ক্লাস ব্যবহার করার পরামর্শই দেওয়া হয়।

কারণ আপনি কিছু অ্যাট্রিবিউট বাদ দিতে response_model_include বা response_model_exclude ব্যবহার করলেও আপনার অ্যাপের OpenAPI-তে (এবং ডকুমেন্টেশনে) তৈরি হওয়া JSON Schema তখনও সম্পূর্ণ মডেলেরটাই থাকবে।

একইভাবে কাজ করা response_model_by_alias-এর ক্ষেত্রেও এটি প্রযোজ্য।

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5


items = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": "The Bar fighters", "price": 62, "tax": 20.2},
    "baz": {
        "name": "Baz",
        "description": "There goes my baz",
        "price": 50.2,
        "tax": 10.5,
    },
}


@app.get(
    "/items/{item_id}/name",
    response_model=Item,
    response_model_include={"name", "description"},
)
async def read_item_name(item_id: str):
    return items[item_id]


@app.get("/items/{item_id}/public", response_model=Item, response_model_exclude={"tax"})
async def read_item_public_data(item_id: str):
    return items[item_id]

পরামর্শ

{"name", "description"} সিনট্যাক্সটি ওই দুটি ভ্যালু দিয়ে একটি set তৈরি করে।

এটি set(["name", "description"])-এর সমতুল্য।

set-এর বদলে list ব্যবহার¶

আপনি যদি set ব্যবহার করতে ভুলে গিয়ে এর বদলে একটি list বা tuple ব্যবহার করেন, তাহলেও FastAPI এটিকে একটি set-এ রূপান্তর করবে এবং এটি সঠিকভাবে কাজ করবে:

রেসপন্স মডেল সংজ্ঞায়িত করতে এবং বিশেষ করে ব্যক্তিগত ডেটা যাতে ফিল্টার হয়ে বাদ পড়ে তা নিশ্চিত করতে পাথ অপারেশন ডেকোরেটরের প্যারামিটার response_model ব্যবহার করুন।

কেবল স্পষ্টভাবে সেট করা ভ্যালুগুলো রিটার্ন করতে response_model_exclude_unset ব্যবহার করুন।
