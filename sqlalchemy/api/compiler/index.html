কম্পাইলার API: Compiled, SQLCompiler, DDLCompiler, IdentifierPreparer …¶

এই পেজে যা আছে

SQLAlchemy যেভাবে Python এক্সপ্রেশন থেকে SQL স্ট্রিং বানায় তার ভেতরের ক্লাসগুলো:

  • Compiled আর তার মূল বাস্তবায়ন SQLCompiler (আর StrSQLCompiler), DDL-এর জন্য DDLCompiler।
  • টাইপের নাম বানানোর TypeCompiler, GenericTypeCompiler, StrSQLTypeCompiler।
  • নাম quote করার IdentifierPreparer।
  • সহায়ক: ExpandedState, ResultColumnsEntry, CacheKey, Linting, FromLinter, CompilerState, InsertmanyvaluesSentinelOpts, AggregateOrderByStyle, aggregate_orderby_inline, ilike_case_insensitive, prefix_anon_map।

stmt.compile() বা str(stmt) দিলে যে অবজেক্ট পান সেটি এই Compiled। কম্পাইলার এক্সপ্রেশন-গাছ ঘুরে প্রতিটি অংশের জন্য একটি visit_<নাম>() মেথড ডাকে (Select → visit_select, BinaryExpression → visit_binary)। প্রতিটি ডায়ালেক্ট এগুলোর কয়েকটি বদলে নিজের SQL লেখে। সাধারণ অ্যাপে এদের দরকার হয় SQL দেখে ডিবাগ করতে (compiled.string, compiled.params), আর নিজের SQL কনস্ট্রাক্ট বানাতে (@compiles)। শত শত visit_* মেথড প্রতিটি ক্লাসে নাম ধরে একটি ভাঁজ করা বক্সে তালিকা করা।

উদাহরণগুলোর জন্য ধরে নেওয়া সেটআপ

m = MetaData()
users = Table("users", m, Column("id", Integer, primary_key=True), Column("name", String(50)))
pg = postgresql.dialect()
c = select(users).where(users.c.id == bindparam("uid")).compile(dialect=pg)   # একটি SQLCompiler

ডেটাবেস লাগে না; সব উদাহরণ শুধু কম্পাইল করে দেখায়।

Compiled ও SQLCompiler¶

Compiled¶

from sqlalchemy.sql.compiler import Compiled

একটি কম্পাইল করা SQL বা DDL স্টেটমেন্ট: SQL স্ট্রিং (string), প্যারামিটারের নাম ও মান (params), আর কোন ডায়ালেক্টের জন্য। stmt.compile(dialect=...) এটি দেয়; str(stmt) আসলে str(stmt.compile())। SQL স্টেটমেন্টের জন্য আসল ক্লাস SQLCompiler, DDL-এর জন্য DDLCompiler।

ডিবাগ টিপ: প্যারামিটারের মান বসিয়ে দেখতে stmt.compile(dialect=..., compile_kwargs={"literal_binds": True})। (শুধু দেখার জন্য; চালানোর জন্য নয়, কারণ SQL injection-এর ঝুঁকি।)

উদাহরণ:

print(type(c).__name__, isinstance(c, Compiled))   # PGCompiler_psycopg True
print(c.string)
# SELECT users.id, users.name
# FROM users
# WHERE users.id = %(uid)s::INTEGER
print(select(users.c.name).where(users.c.id == 5).compile(dialect=pg, compile_kwargs={"literal_binds": True}))
# SELECT users.name
# FROM users
# WHERE users.id = 5

সব মেথড ও অ্যাট্রিবিউট এক নজরে¶

সদস্য ধরন কাজ
cache_key অ্যাট্রিবিউট (internal) যে CacheKey দিয়ে এই কম্পাইল-ফল ক্যাশে রাখা হয়েছে; সরাসরি compile() করলে None।
can_execute অ্যাট্রিবিউট এটি চালানো যায় এমন স্টেটমেন্ট কি না (SELECT/INSERT/DDL হলে True; একটি কলাম-এক্সপ্রেশন কম্পাইল করলে False)।
compile_state অ্যাট্রিবিউট (internal) কম্পাইলের সময় তৈরি স্টেটমেন্ট-বিশেষ অবস্থা (FROM-এর তালিকা ইত্যাদি)।
construct_params() মেথড প্যারামিটারের নাম → মান dict বানায়; চাইলে নতুন মান দিয়ে (construct_params({"uid": 7}))।
dialect অ্যাট্রিবিউট যে ডায়ালেক্টের জন্য কম্পাইল হয়েছে।
dml_compile_state অ্যাট্রিবিউট (internal) INSERT/UPDATE/DELETE-এর বাইরের স্টেটমেন্টের compile state (নইলে None)।
execution_options অ্যাট্রিবিউট স্টেটমেন্টের execution options (কম্পাইলের সময় যা ছিল)।
is_ddl অ্যাট্রিবিউট DDL (CREATE/DROP …) কম্পাইল কি না।
is_sql অ্যাট্রিবিউট সাধারণ SQL স্টেটমেন্ট কম্পাইল কি না।
params প্রপার্টি প্যারামিটারের নাম → মান dict (স্টেটমেন্টে দেওয়া মান; না দেওয়া থাকলে None)।
process() মেথড এই কম্পাইলার দিয়ে একটি এক্সপ্রেশনের SQL অংশ বানায় (ভেতরে সংশ্লিষ্ট visit_* ডাকে)।
schema_translate_map অ্যাট্রিবিউট execution_options(schema_translate_map={...}) থাকলে স্কিমার নাম বদলের ম্যাপ, নইলে None।
sql_compiler প্রপার্টি SQL এক্সপ্রেশন কম্পাইল করতে পারে এমন কম্পাইলার: SQLCompiler-এ নিজেই, DDLCompiler-এ ভেতরের একটি SQLCompiler (DDL-এর ভেতরের CHECK শর্ত ইত্যাদির জন্য)।
state অ্যাট্রিবিউট (internal) কম্পাইলারের অবস্থা (CompilerState): কাজ শেষে STRING_APPLIED।
statement অ্যাট্রিবিউট যে মূল স্টেটমেন্ট (এক্সপ্রেশন অবজেক্ট) কম্পাইল করা হয়েছে।
string অ্যাট্রিবিউট তৈরি SQL স্ট্রিং (str(compiled)-এর মতো)।
visit_unsupported_compilation() মেথড (internal) কোনো কনস্ট্রাক্টের জন্য visit_* না পেলে এটি ডাকা হয় আর UnsupportedCompilationError দেয়।

SQLCompiler¶

from sqlalchemy.sql.compiler import SQLCompiler

SELECT/INSERT/UPDATE/DELETE কম্পাইলের ডিফল্ট বাস্তবায়ন। প্রতিটি ডায়ালেক্টের নিজের subclass আছে (PGCompiler, SQLiteCompiler, MySQLCompiler …), যা কিছু visit_* আর *_clause মেথড বদলায়: যেমন MySQL-এ LIMIT লেখার ধরন, PostgreSQL-এ ::INTEGER cast।

বেশিরভাগ সদস্য ডায়ালেক্ট লেখকদের জন্য hook (limit_clause(), for_update_clause() …)। ব্যবহারকারীর কাজের অংশ: string, params, positiontup, binds, effective_returning, আর @compiles-এর ভেতরে process()।

উদাহরণ:

print(select(users.c.id).limit(5).compile(dialect=mysql.dialect()).string.splitlines()[-1].strip())   # LIMIT %s
print(select(users.c.id).limit(5).compile(dialect=pg).string.splitlines()[-1].strip())   # LIMIT %(param_1)s::INTEGER

visit_* মেথড: প্রতিটি SQL কনস্ট্রাক্টের জন্য একটি (৯৭টি, দেখতে ক্লিক করুন)

প্রতিটি এক্সপ্রেশন-ক্লাসের একটি __visit_name__ আছে (Select → "select", BinaryExpression → "binary", Label → "label" …)। কম্পাইলার সেই নাম ধরে visit_<নাম>(element, **kw) ডাকে, আর মেথডটি ঐ অংশের SQL স্ট্রিং ফেরত দেয়। ডায়ালেক্ট এগুলো override করে নিজের SQL লেখে। নিজের কোডে এগুলো সরাসরি ডাকবেন না; compiler.process(element) ডাকুন, সেটাই ঠিক visit_* বেছে নেয়। নিজের কনস্ট্রাক্টের জন্য নতুন visit লিখতে @compiles ব্যবহার করুন।

visit_<অপারেটর>_binary (যেমন visit_like_op_binary) আর visit_<অপারেটর>_unary_operator ধরনের মেথডগুলো নির্দিষ্ট অপারেটরের জন্য: like(), ilike(), regexp_match(), is_distinct_from() ইত্যাদি।

aggregate_orderby_inline¶

from sqlalchemy.sql.compiler import aggregate_orderby_inline

(অভ্যন্তরীণ, ২.১) INLINE ধরনের ডেটাবেসে aggregate_order_by() লেখার জন্য কম্পাইলার যে মোড়ক-এক্সপ্রেশন বানায়: ফাংশনের আর্গুমেন্টের ভেতরে ORDER BY বসায়।

উদাহরণ:

print(select(func.string_agg(users.c.name, ",").aggregate_order_by(users.c.id)).compile(dialect=pg).string.splitlines()[0])
# SELECT string_agg(users.name, %(string_agg_2)s::VARCHAR ORDER BY users.id) AS string_agg_1
