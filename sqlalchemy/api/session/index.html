Session API: সম্পূর্ণ রেফারেন্স¶

এই পেজে যা আছে

  • Session-এর প্রতিটি মেথড, প্রপার্টি ও কনস্ট্রাক্টর প্যারামিটার, সহজ বাংলায় আর উদাহরণসহ।
  • sessionmaker, SessionTransaction, scoped_session আর সেশন-সম্পর্কিত ফাংশনগুলো।
  • তালিকাটি সরাসরি SQLAlchemy 2.1-এর সোর্স থেকে তৈরি, তাই কোনো সদস্য বাদ পড়েনি।

Session হলো ORM-এর কেন্দ্র। অবজেক্ট যোগ, খোঁজা, বদলানো, মোছা আর ট্রানজ্যাকশন, সব এর মাধ্যমেই। ধারণাগুলো সহজ ভাষায় বুঝতে আগে Transaction ও Session-এর ভেতরের কাজ অধ্যায়টি পড়ে নিতে পারেন। এই পেজটি হলো "অভিধান": কোন মেথড ঠিক কী করে, তা খুঁজে দেখার জায়গা।

উদাহরণগুলোর জন্য ধরে নেওয়া সেটআপ

এই পেজের সব উদাহরণ নিচের মডেল আর ডেটা ধরে লেখা, আর আমরা PostgreSQL 16-এ প্রতিটি উদাহরণ আলাদা করে চালিয়ে দেখেছি। ডেটাবেসে আগে থেকে তিনজন ইউজার আছেন: id ১ "রহিম" (একটি ঠিকানাসহ), id ২ "করিম", id ৩ "সুমি"।

from sqlalchemy import ForeignKey, String, create_engine, func, insert, select
from sqlalchemy.orm import (DeclarativeBase, Mapped, Session, mapped_column,
                            relationship, selectinload, sessionmaker)

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(50))
    addresses: Mapped[list["Address"]] = relationship(back_populates="user", cascade="all, delete-orphan")

class Address(Base):
    __tablename__ = "addresses"
    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str]
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
    user: Mapped["User"] = relationship(back_populates="addresses")

engine = create_engine("postgresql+psycopg2://user:pass@localhost/shop")
session = Session(engine)

এখানে sync Session দেখানো হয়েছে। async কোডে প্রায় সব মেথড একই, শুধু সামনে await বসে। বিস্তারিত দেখুন Async API পেজে।

Session¶

from sqlalchemy.orm import Session

ORM-এর মাধ্যমে ডেটাবেসে সব কাজ (persistence) পরিচালনা করে। একটি Session একটি "কাজের খাতা" (unit of work): আপনি কোন অবজেক্ট যোগ করলেন, কোনটা বদলালেন, কোনটা মুছলেন, সব মনে রাখে, আর flush() বা commit()-এর সময় সঠিক ক্রমে SQL পাঠায়। ভেতরে একটি identity map রাখে, যাতে একই রো-র জন্য মেমরিতে একটাই অবজেক্ট থাকে।

সাধারণ নিয়ম: একটি কাজ (যেমন একটি HTTP রিকোয়েস্ট) = একটি সেশন। কাজ শেষে বন্ধ করুন। with Session(engine) as session: লিখলে ব্লক শেষে নিজেই বন্ধ হয়।

উদাহরণ:

with Session(engine) as session:
    session.add(User(name="নতুন ইউজার"))
    session.commit()
    users = session.scalars(select(User).order_by(User.id)).all()
    print([u.name for u in users])

কনস্ট্রাক্টরের প্যারামিটার¶

Session(bind=None, *, autoflush=True, future=True, expire_on_commit=True, autobegin=True, twophase=False, binds=None, enable_baked_queries=True, info=None, query_cls=None, autocommit=False, join_transaction_mode='conditional_savepoint', close_resets_only=_NoArg.NO_ARG, execution_options={})
প্যারামিটার কাজ
bind যে Engine বা Connection-এর মাধ্যমে সেশন ডেটাবেসে যাবে। সাধারণত Session(engine)।
autoflush True (ডিফল্ট) হলে প্রতিটি কুয়েরির আগে সেশন নিজে থেকেই জমা পরিবর্তন flush() করে, যাতে কুয়েরি সেগুলো দেখতে পায়।
future 2.0 থেকে অর্থহীন, শুধু পুরোনো কোডের সাথে মিল রাখার জন্য আছে। সবসময় True।
expire_on_commit True (ডিফল্ট) হলে commit()-এর পর সব অবজেক্টের মান মুছে যায় (expire), পরে পড়লে আবার ডেটাবেস থেকে আসে। async-এ সাধারণত False দিন।
autobegin True (ডিফল্ট) হলে প্রথম কাজের সময় ট্রানজ্যাকশন নিজে শুরু হয়। False দিলে আগে session.begin() না ডাকলে এরর।
twophase True দিলে commit দুই ধাপে হয় (two-phase commit), একাধিক ডেটাবেসে একসাথে নিশ্চিতভাবে commit করার জন্য।
binds মডেল বা টেবিল অনুযায়ী আলাদা Engine-এর একটি dict, যেমন {User: engine1, Order: engine2}।
enable_baked_queries পুরোনো "baked query" ক্যাশ চালু রাখবে কি না (legacy, শুধু session.query()-এ প্রভাব ফেলে)।
info নিজের যেকোনো তথ্য রাখার জন্য একটি dict, পরে session.info দিয়ে পাওয়া যায়।
query_cls legacy session.query() কোন Query ক্লাস ব্যবহার করবে।
autocommit 1.x-এর পুরোনো autocommit মোড। 2.0-তে সরানো হয়েছে; শুধু False গ্রহণযোগ্য।
join_transaction_mode বাইরে থেকে দেওয়া Connection-এ আগেই ট্রানজ্যাকশন চললে সেশন কীভাবে যোগ দেবে: "conservative_savepoint" (ডিফল্ট), "create_savepoint" (টেস্টে কাজের), "rollback_only", "control_fully"।
close_resets_only True (ডিফল্ট) হলে close()-এর পরও সেশনটি আবার ব্যবহার করা যায়। False দিলে close() মানে চিরতরে বন্ধ।
execution_options (২.১-এ নতুন) এই সেশনের প্রতিটি execute()-এ প্রযোজ্য ডিফল্ট execution option-এর dict, যেমন {"populate_existing": True}।

সদস্য ধরন কাজ
add() মেথড একটি অবজেক্টকে সেশনে যোগ করে।
add_all() মেথড অনেকগুলো অবজেক্ট একসাথে সেশনে যোগ করে, প্রতিটির জন্য add() ডাকার সমান।
begin() মেথড স্পষ্টভাবে একটি ট্রানজ্যাকশন শুরু করে আর একটি SessionTransaction দেয়।
begin_nested() মেথড চলমান ট্রানজ্যাকশনের ভেতরে একটি "নেস্টেড" ট্রানজ্যাকশন, মানে ডেটাবেসে SAVEPOINT, শুরু করে।
bind_mapper() মেথড একটি নির্দিষ্ট মডেলের সব কাজ কোন Engine-এ যাবে তা ঠিক করে দেয়।
bind_table() মেথড bind_mapper()-এর মতো, তবে মডেলের বদলে একটি Table-এর জন্য Engine ঠিক করে।
bulk_insert_mappings() মেথড (legacy) dict-এর তালিকা দিয়ে অনেক রো দ্রুত INSERT করে, ORM অবজেক্ট না বানিয়ে।
bulk_save_objects() মেথড (legacy) অনেক অবজেক্ট একসাথে INSERT/UPDATE করে, unit of work-এর অনেক হিসাব (event, relationship cascade) বাদ দিয়ে।
bulk_update_mappings() মেথড (legacy) primary key-সহ dict-এর তালিকা দিয়ে অনেক রো আপডেট করে।
close() মেথড সেশনের ট্রানজ্যাকশন শেষ (rollback) করে, কানেকশন পুলে ফেরত দেয়, আর সব অবজেক্টকে সেশন থেকে বিচ্ছিন্ন (detached) করে।
commit() মেথড জমা থাকা সব পরিবর্তন flush() করে, তারপর ডেটাবেসে COMMIT পাঠায়।
connection() মেথড সেশনের চলমান ট্রানজ্যাকশনের সাথে যুক্ত Core Connection দেয়।
connection_callable অ্যাট্রিবিউট (internal) ভেতরের একটি হুক, যা সাধারণত None থাকে।
delete() মেথড একটি অবজেক্টকে মোছার জন্য চিহ্নিত করে।
delete_all() মেথড (২.১-এ নতুন) অনেকগুলো অবজেক্ট একসাথে মোছার জন্য চিহ্নিত করে, প্রতিটিতে delete() ডাকার সমান।
deleted প্রপার্টি যে অবজেক্টগুলো delete() দিয়ে মোছার জন্য চিহ্নিত কিন্তু এখনো flush হয়নি, সেগুলোর সেট (set-এর মতো একটি কালেকশন)।
dirty প্রপার্টি যে persistent অবজেক্টগুলোর কোনো অ্যাট্রিবিউট বদলানো হয়েছে, সেগুলোর সেট।
enable_relationship_loading() মেথড একটি অবজেক্টকে সেশনে যোগ না করেই তার relationship লোড করার সুবিধা দেয়, ফরেন কি-র বর্তমান মান দিয়ে।
execute() মেথড যেকোনো স্টেটমেন্ট (select, insert, update, delete, text) চালায় আর একটি Result দেয়।
execution_options অ্যাট্রিবিউট (২.১-এ নতুন) কনস্ট্রাক্টরে দেওয়া ডিফল্ট execution option-গুলো, যা এই সেশনের প্রতিটি execute()-এ প্রয়োগ হয়।
expire() মেথড একটি অবজেক্টের সব (বা নির্দিষ্ট) অ্যাট্রিবিউটের মেমরিতে থাকা মান মুছে দেয়।
expire_all() মেথড সেশনের সব persistent অবজেক্টকে expire করে।
expunge() মেথড একটি অবজেক্টকে সেশন থেকে সরিয়ে দেয় (detached করে)।
expunge_all() মেথড সেশনের সব অবজেক্ট সরিয়ে identity map খালি করে।
flush() মেথড জমা থাকা সব পরিবর্তনের SQL (INSERT/UPDATE/DELETE) এখনই ডেটাবেসে পাঠায়, কিন্তু commit করে না।
get() মেথড primary key দিয়ে একটি অবজেক্ট দেয়, না থাকলে None।
get_bind() মেথড একটি কুয়েরি বা মডেলের জন্য সেশন কোন Engine/Connection ব্যবহার করবে তা বের করে দেয়।
get_nested_transaction() মেথড এখন কোনো নেস্টেড (SAVEPOINT) ট্রানজ্যাকশন চললে সেটার SessionTransaction দেয়, নইলে None।
get_one() মেথড get()-এর মতোই, কিন্তু রো না পেলে None না দিয়ে NoResultFound এরর দেয়।
get_transaction() মেথড এখন যে মূল (root) ট্রানজ্যাকশন চলছে সেটার SessionTransaction দেয়, না থাকলে None।
identity_key() ক্লাস মেথড একটি অবজেক্টের identity map-এর key, মানে (ক্লাস, primary key-র tuple, identity_token) বানিয়ে দেয়।
in_nested_transaction() মেথড এখন কোনো SAVEPOINT চললে True।
in_transaction() মেথড এখন কোনো ট্রানজ্যাকশন চললে True।
info প্রপার্টি নিজের তথ্য রাখার একটি dict, যেমন রিকোয়েস্ট id বা বর্তমান ইউজার।
invalidate() মেথড সেশন বন্ধ করে, আর ব্যবহৃত DBAPI কানেকশনগুলো "অকেজো" ঘোষণা করে পুলে ফেরত না দিয়ে ফেলে দেয়।
is_active প্রপার্টি সেশন "আংশিক rollback" অবস্থায় না থাকলে True।
is_modified() মেথড অবজেক্টের কোনো অ্যাট্রিবিউটের মান আসলেই বদলেছে কি না দেখে True/False দেয়।
merge() মেথড বাইরের একটি অবজেক্টের অবস্থা সেশনের ভেতরের সংশ্লিষ্ট অবজেক্টে কপি করে, আর সেই ভেতরের অবজেক্টটি ফেরত দেয়।
merge_all() মেথড (২.১-এ নতুন) অনেক অবজেক্টে একসাথে merge() চালায় আর merge করা অবজেক্টগুলোর তালিকা দেয়।
new প্রপার্টি যে নতুন অবজেক্টগুলো add() করা হয়েছে কিন্তু এখনো flush হয়নি (pending), সেগুলোর সেট।
no_autoflush প্রপার্টি একটি context manager, যার ভেতরে সাময়িকভাবে autoflush বন্ধ থাকে।
object_session() ক্লাস মেথড একটি অবজেক্ট কোন সেশনের সাথে যুক্ত তা দেয়, না থাকলে None।
prepare() মেথড two-phase commit-এর প্রথম ধাপ: চলমান ট্রানজ্যাকশন "প্রস্তুত" করে।
query() মেথড (legacy) 1.x যুগের Query অবজেক্ট দেয়।
refresh() মেথড অবজেক্টের মানগুলো এখনই ডেটাবেস থেকে আবার পড়ে আনে (একটি SELECT)।
reset() মেথড সেশনকে একদম শুরুর অবস্থায় ফিরিয়ে নেয়: ট্রানজ্যাকশন বাতিল, সব অবজেক্ট বিচ্ছিন্ন, কানেকশন ফেরত।
rollback() মেথড চলমান ট্রানজ্যাকশন বাতিল করে।
scalar() মেথড একটি স্টেটমেন্ট চালিয়ে প্রথম রো-র প্রথম কলামের মানটি দেয় (না থাকলে None)।
scalars() মেথড একটি স্টেটমেন্ট চালিয়ে প্রতিটি রো-র প্রথম কলাম দিয়ে একটি ScalarResult দেয়।

Session.begin_nested()¶

Session.begin_nested()

ধরন: মেথড

চলমান ট্রানজ্যাকশনের ভেতরে একটি "নেস্টেড" ট্রানজ্যাকশন, মানে ডেটাবেসে SAVEPOINT, শুরু করে। ভেতরের অংশ ব্যর্থ হলে শুধু সেটুকু বাতিল হয়, বাইরের কাজ থেকে যায়।

    session.add(User(name="টিকে থাকবে"))

            session.add(User(name="বাতিল হবে"))
            raise ValueError("সমস্যা")
    except ValueError:
        pass
print(session.scalars(select(User.name).where(User.id > 3)).all())   # ['টিকে থাকবে']

autoflush প্রপার্টি বর্তমান সেশনের autoflush সেটিং পড়া বা বদলানোর proxy।
begin() মেথড স্পষ্টভাবে একটি ট্রানজ্যাকশন শুরু করে আর একটি SessionTransaction দেয়।
begin_nested() মেথড চলমান ট্রানজ্যাকশনের ভেতরে একটি "নেস্টেড" ট্রানজ্যাকশন, মানে ডেটাবেসে SAVEPOINT, শুরু করে।
bind প্রপার্টি বর্তমান সেশন কোন Engine-এ যুক্ত তা দেয় (proxy)।
binds প্রপার্টি বর্তমান সেশনের মডেল/টেবিল-ভিত্তিক bind-এর dict (proxy)।
bulk_insert_mappings() মেথড dict-এর তালিকা দিয়ে অনেক রো দ্রুত INSERT করে, ORM অবজেক্ট না বানিয়ে।
bulk_save_objects() মেথড অনেক অবজেক্ট একসাথে INSERT/UPDATE করে, unit of work-এর অনেক হিসাব (event, relationship cascade) বাদ দিয়ে।
bulk_update_mappings() মেথড primary key-সহ dict-এর তালিকা দিয়ে অনেক রো আপডেট করে।
close() মেথড সেশনের ট্রানজ্যাকশন শেষ (rollback) করে, কানেকশন পুলে ফেরত দেয়, আর সব অবজেক্টকে সেশন থেকে বিচ্ছিন্ন (detached) করে।
commit() মেথড জমা থাকা সব পরিবর্তন flush() করে, তারপর ডেটাবেসে COMMIT পাঠায়।
configure() মেথড ভেতরের sessionmaker-এর সেটিং বদলায়।
connection() মেথড সেশনের চলমান ট্রানজ্যাকশনের সাথে যুক্ত Core Connection দেয়।
delete() মেথড একটি অবজেক্টকে মোছার জন্য চিহ্নিত করে।
delete_all() মেথড (২.১-এ নতুন) অনেকগুলো অবজেক্ট একসাথে মোছার জন্য চিহ্নিত করে, প্রতিটিতে delete() ডাকার সমান।
deleted প্রপার্টি যে অবজেক্টগুলো delete() দিয়ে মোছার জন্য চিহ্নিত কিন্তু এখনো flush হয়নি, সেগুলোর সেট (set-এর মতো একটি কালেকশন)।
dirty প্রপার্টি যে persistent অবজেক্টগুলোর কোনো অ্যাট্রিবিউট বদলানো হয়েছে, সেগুলোর সেট।
execute() মেথড যেকোনো স্টেটমেন্ট (select, insert, update, delete, text) চালায় আর একটি Result দেয়।
execution_options প্রপার্টি (২.১-এ নতুন) কনস্ট্রাক্টরে দেওয়া ডিফল্ট execution option-গুলো, যা এই সেশনের প্রতিটি execute()-এ প্রয়োগ হয়।
expire() মেথড একটি অবজেক্টের সব (বা নির্দিষ্ট) অ্যাট্রিবিউটের মেমরিতে থাকা মান মুছে দেয়।
expire_all() মেথড সেশনের সব persistent অবজেক্টকে expire করে।
expunge() মেথড একটি অবজেক্টকে সেশন থেকে সরিয়ে দেয় (detached করে)।
expunge_all() মেথড সেশনের সব অবজেক্ট সরিয়ে identity map খালি করে।
flush() মেথড জমা থাকা সব পরিবর্তনের SQL (INSERT/UPDATE/DELETE) এখনই ডেটাবেসে পাঠায়, কিন্তু commit করে না।
get() মেথড primary key দিয়ে একটি অবজেক্ট দেয়, না থাকলে None।
get_bind() মেথড একটি কুয়েরি বা মডেলের জন্য সেশন কোন Engine/Connection ব্যবহার করবে তা বের করে দেয়।
get_one() মেথড get()-এর মতোই, কিন্তু রো না পেলে None না দিয়ে NoResultFound এরর দেয়।
identity_key() ক্লাস মেথড একটি অবজেক্টের identity map-এর key, মানে (ক্লাস, primary key-র tuple, identity_token) বানিয়ে দেয়।

info প্রপার্টি নিজের তথ্য রাখার একটি dict, যেমন রিকোয়েস্ট id বা বর্তমান ইউজার।
is_active প্রপার্টি সেশন "আংশিক rollback" অবস্থায় না থাকলে True।
is_modified() মেথড অবজেক্টের কোনো অ্যাট্রিবিউটের মান আসলেই বদলেছে কি না দেখে True/False দেয়।
merge() মেথড বাইরের একটি অবজেক্টের অবস্থা সেশনের ভেতরের সংশ্লিষ্ট অবজেক্টে কপি করে, আর সেই ভেতরের অবজেক্টটি ফেরত দেয়।
merge_all() মেথড (২.১-এ নতুন) অনেক অবজেক্টে একসাথে merge() চালায় আর merge করা অবজেক্টগুলোর তালিকা দেয়।
new প্রপার্টি যে নতুন অবজেক্টগুলো add() করা হয়েছে কিন্তু এখনো flush হয়নি (pending), সেগুলোর সেট।
no_autoflush প্রপার্টি একটি context manager, যার ভেতরে সাময়িকভাবে autoflush বন্ধ থাকে।
object_session() ক্লাস মেথড একটি অবজেক্ট কোন সেশনের সাথে যুক্ত তা দেয়, না থাকলে None।
query() মেথড 1.x যুগের Query অবজেক্ট দেয়।
query_property() মেথড (legacy) মডেল ক্লাসে একটি query প্রপার্টি বানায়, যাতে User.query.filter(...) লেখা যায় (Flask-SQLAlchemy ধাঁচ)।
refresh() মেথড অবজেক্টের মানগুলো এখনই ডেটাবেস থেকে আবার পড়ে আনে (একটি SELECT)।
remove() মেথড বর্তমান scope-এর সেশন বন্ধ করে রেজিস্ট্রি থেকে সরায়।
reset() মেথড সেশনকে একদম শুরুর অবস্থায় ফিরিয়ে নেয়: ট্রানজ্যাকশন বাতিল, সব অবজেক্ট বিচ্ছিন্ন, কানেকশন ফেরত।
rollback() মেথড চলমান ট্রানজ্যাকশন বাতিল করে।
scalar() মেথড একটি স্টেটমেন্ট চালিয়ে প্রথম রো-র প্রথম কলামের মানটি দেয় (না থাকলে None)।
scalars() মেথড একটি স্টেটমেন্ট চালিয়ে প্রতিটি রো-র প্রথম কলাম দিয়ে একটি ScalarResult দেয়।

from sqlalchemy.orm import make_transient

make_transient(instance)

ধরন: ফাংশন

একটি অবজেক্টকে আবার "transient" (একদম নতুন, কোনো সেশনের অজানা) অবস্থায় নিয়ে যায়। primary key মান থেকে যায়। অবজেক্ট কপি করে নতুন রো বানাতে কাজে লাগে (id None করে আবার add)।

উদাহরণ:

user = session.get(User, 1)
make_transient(user)
user.id = None
session.add(user)
session.commit()
print(user.id)   # 4 — একই নামে নতুন রো

make_transient_to_detached()¶

make_transient_to_detached(instance)

ধরন: ফাংশন

একটি transient অবজেক্টকে "detached" বানায়, যেন এটি আগে কোনো সেশনে লোড হয়েছিল। ক্যাশ থেকে বানানো অবজেক্টকে add() দিয়ে INSERT ছাড়াই সেশনে ফেরাতে কাজে লাগে। primary key সেট থাকতে হবে।

উদাহরণ:

cached = User(id=2, name="করিম")
make_transient_to_detached(cached)
session.add(cached)          # INSERT নয়, persistent হিসেবে যুক্ত
cached.name = "করিম (ক্যাশ থেকে)"
session.commit()             # UPDATE হয়

was_deleted()¶

from sqlalchemy.orm import was_deleted

was_deleted(object_)

ধরন: ফাংশন

অবজেক্টটি কোনো flush-এ ডেটাবেস থেকে মুছে গেছে কি না জানায়।

উদাহরণ:

user = session.get(User, 3)
session.delete(user)
session.flush()
print(was_deleted(user))   # True

সংক্ষেপে মনে রাখুন

  • লেখা: add() / add_all() → flush() (ঐচ্ছিক) → commit()। মোছা: delete() / delete_all()।
  • পড়া: primary key-তে get() / get_one(), বাকি সব scalars() / execute() / scalar()।
  • ট্রানজ্যাকশন: with session.begin():, ভেতরে আংশিক বাতিলের জন্য begin_nested()।
  • মেমরির অবস্থা: new, dirty, deleted, is_modified(); নতুন করে পড়া refresh() / expire()।
  • পুরোনো API (query(), bulk_*) চলে, কিন্তু নতুন কোডে select() আর insert()/update() স্টেটমেন্ট।
