ORM স্টেট ও ইনস্পেকশন: InstanceState, AttributeState, ORMExecuteState …¶

এই পেজে যা আছে

ORM ভেতরে ভেতরে প্রতিটি অবজেক্ট আর ক্লাসের হিসাব রাখে। এই পেজ সেই হিসাবের অবজেক্টগুলো:

  • অবজেক্টের অবস্থা: inspect(user) যা দেয় সেই InstanceState (transient / pending / persistent / detached / deleted, কী বদলেছে, কী লোড হয়নি), প্রতিটি অ্যাট্রিবিউটের AttributeState, সেশনের IdentityMap।
  • ক্লাসের দিক: ClassManager, InstrumentedAttribute (User.name আসলে যা)।
  • ইভেন্ট হুকে যা আসে: ORMExecuteState (do_orm_execute), UserDefinedOption, AttributeEventToken, QueryContext, UOWTransaction।
  • ধ্রুবক: PassiveFlag, LoaderCallableStatus, SessionTransactionOrigin, আর with_loader_criteria()-এর LoaderCriteriaOption।

সাধারণ অ্যাপে এদের বেশিরভাগ সরাসরি লাগে না। কাজে লাগে ডিবাগ করতে ("এই অবজেক্টটি কি সেশনে আছে? কোন ফিল্ড বদলেছে?"), অডিট লগ বানাতে (কে কোন ফিল্ড কী থেকে কী করল), আর ইভেন্ট হুক লিখতে। সাধারণ ব্যবহারকারী-মুখী অংশগুলো (InstanceState, AttributeState, ORMExecuteState) আগে, একেবারে ভেতরের (internal) অংশ পরে।

উদাহরণগুলোর জন্য ধরে নেওয়া সেটআপ

Session API পেজের মতো User (id, name, addresses) আর Address (id, email, user_id, user), ডেটা: রহিম (দুটি ঠিকানা), করিম। insp = inspect(obj) দিয়ে InstanceState পাওয়া যায়। PostgreSQL 16-এ চালিয়ে দেখা।

অবজেক্টের অবস্থা¶

InstanceState¶

from sqlalchemy.orm import InstanceState

প্রতিটি ORM অবজেক্টের সাথে লুকিয়ে থাকা "হিসাবের খাতা"। পেতে: inspect(user)। এতে আছে অবজেক্টটি কোন অবস্থায় (নিচের পাঁচটির একটি), কোন সেশনে, primary key কী, কোন অ্যাট্রিবিউট বদলেছে, কোনটি এখনো লোড হয়নি।

অবস্থা মানে
transient নতুন বানানো, সেশনে নেই, ডেটাবেসেও নেই
pending session.add() হয়েছে, কিন্তু এখনো flush হয়নি
persistent সেশনে আছে আর ডেটাবেসে একটি রো-র সাথে যুক্ত
deleted session.delete() হয়ে flush হয়েছে, commit বাকি
detached ডেটাবেসে আছে, কিন্তু কোনো সেশনে নেই (সেশন বন্ধ হয়েছে)

উদাহরণ:

u = User(name="নতুন")
insp = inspect(u)
print(type(insp).__name__, insp.transient)   # InstanceState True
session.add(u); print(insp.pending)   # True
session.flush(); print(insp.persistent, insp.identity)   # True (3,)
session.close(); print(insp.detached)   # True

callables অ্যাট্রিবিউট (internal) অ্যাট্রিবিউট-প্রতি "পরে লোড করো" ফাংশনগুলো (deferred/expired কলামের জন্য)।
class_ অ্যাট্রিবিউট অবজেক্টের ক্লাস।
committed_state অ্যাট্রিবিউট (internal) বদলানো অ্যাট্রিবিউটগুলোর আগের (ডেটাবেসে থাকা) মান, flush না হওয়া পর্যন্ত।
deleted প্রপার্টি অবজেক্টটি "deleted" অবস্থায় কি না: session.delete() হয়ে flush হয়েছে, কিন্তু commit বাকি।
detached প্রপার্টি অবজেক্টটি detached কি না: ডেটাবেসে আছে কিন্তু কোনো সেশনে নেই।
dict প্রপার্টি অবজেক্টের __dict__ (যেখানে লোড হওয়া মানগুলো থাকে)।

expired_attributes অ্যাট্রিবিউট যে অ্যাট্রিবিউটগুলো expire হয়ে আছে (নাম-এর set)।
get_history() মেথড (internal) একটি অ্যাট্রিবিউটের History (added, unchanged, deleted), PassiveFlag অনুযায়ী লোড করে বা না করে।
get_impl() মেথড (internal) একটি অ্যাট্রিবিউটের ভেতরের implementation অবজেক্ট।
has_identity প্রপার্টি primary key-এর পরিচয় (identity key) আছে কি না: persistent, detached বা deleted হলে True।
identity প্রপার্টি primary key-এর মান tuple হিসেবে ((1,)), না থাকলে None।
identity_key প্রপার্টি identity map-এ ব্যবহৃত পূর্ণ key: (ক্লাস, primary key tuple, identity_token)।
identity_token অ্যাট্রিবিউট sharding ইত্যাদিতে একই primary key কয়েক জায়গায় থাকলে আলাদা করার টোকেন; সাধারণত None।
insert_order অ্যাট্রিবিউট (internal) pending অবজেক্টগুলো কোন ক্রমে add() হয়েছিল (flush-এ INSERT-এর ক্রম ঠিক রাখতে)।
key অ্যাট্রিবিউট identity_key-এর মতো (persistent অবজেক্টের), নতুন অবজেক্টে None।
load_options অ্যাট্রিবিউট (internal) অবজেক্টটি লোড হওয়ার সময় যে লোডার অপশন ছিল (lazy load-এ আবার প্রয়োগের জন্য)।
load_path অ্যাট্রিবিউট (internal) কোন লোড-পথে অবজেক্টটি এসেছে (যেমন User → addresses)।
manager অ্যাট্রিবিউট (internal) ক্লাসের ClassManager।
mapper প্রপার্টি অবজেক্টের ক্লাসের Mapper।
modified অ্যাট্রিবিউট কোনো অ্যাট্রিবিউট বদলানো হয়েছে কি না (flush বাকি)।
obj অ্যাট্রিবিউট (internal) অবজেক্টের weak reference; ডাকলে (insp.obj()) অবজেক্টটি (garbage collect হলে None)।
object প্রপার্টি মূল অবজেক্টটি (obj()-এর সহজ রূপ)।
parents প্রপার্টি (internal) কোন অবজেক্ট(গুলো)র collection-এ এটি আছে, তার ভেতরের হিসাব (backref/orphan পরীক্ষার জন্য)।
pending প্রপার্টি session.add() হয়েছে কিন্তু এখনো flush হয়নি কি না।
persistent প্রপার্টি সেশনে আছে আর ডেটাবেসের একটি রো-র সাথে যুক্ত কি না।
runid অ্যাট্রিবিউট (internal) কোন লোড অপারেশনে অবজেক্টটি শেষবার ভরা হয়েছে তার নম্বর (একই লোডে দুবার ভরা এড়াতে)।
session প্রপার্টি অবজেক্টটি যে Session-এ আছে, নইলে None।
session_id অ্যাট্রিবিউট (internal) সেশনের ভেতরের নম্বর (Session.hash_key), নেই হলে None।
transient প্রপার্টি একেবারে নতুন, সেশন আর ডেটাবেস দুটোর বাইরে কি না।
unloaded প্রপার্টি যে অ্যাট্রিবিউটগুলো এখনো লোড হয়নি (lazy relationship, deferred বা expired কলাম)।
unloaded_expirable প্রপার্টি unloaded-এর আরেক নাম।
unmodified প্রপার্টি যে অ্যাট্রিবিউটগুলোতে কোনো অসংরক্ষিত বদল নেই।

was_deleted প্রপার্টি অবজেক্টটি কখনো deleted অবস্থায় ছিল (আর রোলব্যাক হয়ে ফেরেনি) কি না।

সেশনের "কে কে আছে" তালিকা: identity key ((ক্লাস, primary key, token)) → অবজেক্ট। এর জন্যই একই সেশনে session.get(User, 1) দুবার ডাকলে একই অবজেক্ট আসে, আর দ্বিতীয়বার SQL চলে না। অবজেক্টগুলো দুর্বলভাবে (weak reference) রাখা হয়: আপনার কোডে কোনো রেফারেন্স না থাকলে আর অসংরক্ষিত বদল না থাকলে অবজেক্টটি সাথে সাথে map থেকে চলে যায় (নিচে keys()-এর উদাহরণ)। তাই inspect(session.get(User, 1)).persistent লিখলে False আসতে পারে: অবজেক্টটি ধরে রাখার কেউ নেই। আগে u = session.get(User, 1), তারপর inspect(u)।

উদাহরণ:

u1 = session.get(User, 1)
u2 = session.scalars(select(User).where(User.name == "রহিম")).one()
print(u1 is u2, len(session.identity_map))   # True 1

check_modified() মেথড কোনো অবজেক্টে অসংরক্ষিত বদল আছে কি না।
contains_state() মেথড নির্দিষ্ট InstanceState-টি এখানে আছে কি না।
fast_get_state() মেথড (internal) key দিয়ে InstanceState (অবজেক্ট নয়), দ্রুত পথে; না থাকলে None।
get() মেথড identity key দিয়ে অবজেক্ট; না থাকলে default।
has_key() মেথড key-টি আছে কি না (key in session.identity_map-এর মতো)।

ক্লাসের দিক¶

InstrumentedAttribute¶

from sqlalchemy.orm import InstrumentedAttribute

User.name (ক্লাস-লেভেলে) আসলে এই অবজেক্ট: একটি Python descriptor। ক্লাস থেকে পড়লে SQL এক্সপ্রেশন (User.name == "x"), অবজেক্ট থেকে পড়লে মান (user.name), আর লিখলে বদলের হিসাব রাখে। কুয়েরিতে ব্যবহারের সব অপারেটর তার মূল ক্লাস QueryableAttribute-এর।

উদাহরণ:

print(type(User.name).__name__, isinstance(User.addresses, InstrumentedAttribute))   # InstrumentedAttribute True
print(User.name == "রহিম")   # users.name = :name_1

সদস্য: নিজস্ব নতুন কোনো সদস্য নেই; সব মেথড ও অ্যাট্রিবিউট QueryableAttribute-এর মতো।

ClassManager¶

from sqlalchemy.orm import ClassManager

(প্রধানত অভ্যন্তরীণ) ক্লাস-লেভেলের হিসাব: কোন অ্যাট্রিবিউট instrumented, নতুন অবজেক্টের InstanceState কীভাবে বসবে, collection কীভাবে বানাবে। এটি একটি dict: অ্যাট্রিবিউটের নাম → InstrumentedAttribute।

উদাহরণ:

m = inspect(User).class_manager
print(type(m).__name__, sorted(m.keys()))   # ClassManager ['addresses', 'id', 'name']

Python dict-এর সব মেথড (clear(), copy(), fromkeys(), get(), items(), keys(), pop(), popitem(), setdefault(), update(), values()) সাধারণ dict-এর মতোই কাজ করে; নিচে শুধু নিজস্ব সদস্য।

SessionEvents.do_orm_execute ইভেন্টের আর্গুমেন্ট: session.execute() (বা lazy load ইত্যাদি) যে স্টেটমেন্ট চালাতে যাচ্ছে তার সব তথ্য। হুকে এটি দেখে আপনি স্টেটমেন্ট বদলাতে পারেন (যেমন সব কুয়েরিতে "soft delete" শর্ত যোগ), আবার চালাতে পারেন (invoke_statement(), যেমন ক্যাশিং), বা শুধু লগ করতে পারেন। হুক থেকে Result ফেরত দিলে সেটাই চূড়ান্ত ফল হয়।

log = []

def watch(state):
    log.append((state.is_select, state.is_relationship_load, state.bind_mapper.class_.__name__))
u = session.get(User, 1)
u.addresses                                    # lazy load
print(log)   # [(True, False, 'User'), (True, True, 'Address')]

সদস্য ধরন কাজ
all_mappers প্রপার্টি স্টেটমেন্টের শীর্ষ স্তরে যত mapper জড়িত (যেমন select(User, Address)-এ দুটো)।
bind_arguments অ্যাট্রিবিউট কোন ডেটাবেসে চলবে তা ঠিক করার আর্গুমেন্ট (mapper, clause …) dict।
bind_mapper প্রপার্টি মূল ("bind") mapper: সাধারণত স্টেটমেন্টের প্রথম entity।
execution_options অ্যাট্রিবিউট মোট execution options (স্টেটমেন্টের + execute()-এ দেওয়া), একসাথে।
identity_token অ্যাট্রিবিউট (internal) sharding-এর জন্য রাখা একটি slot।
invoke_statement() মেথড স্টেটমেন্টটি (বা বদলানো রূপ) এখনই চালিয়ে Result দেয়, আর বাকি do_orm_execute হুকগুলোও আবার চলে না।
is_column_load প্রপার্টি True হলে এটা একটি বিদ্যমান অবজেক্টের কলাম আবার লোড করা (expired অ্যাট্রিবিউট, refresh(), deferred কলাম)।
is_delete প্রপার্টি স্টেটমেন্টটি DELETE কি না (ORM-enabled delete())।
is_executemany প্রপার্টি প্যারামিটার একাধিক dict-এর তালিকা কি না (বাল্ক INSERT/UPDATE)।
is_from_statement প্রপার্টি select(...).from_statement(text(...)) ধরনের কি না।
is_insert প্রপার্টি INSERT কি না।
is_orm_statement প্রপার্টি ORM স্টেটমেন্ট কি না (মডেল/ORM অ্যাট্রিবিউট আছে)।
is_relationship_load প্রপার্টি relationship লোড করার জন্য (lazy load, selectinload ইত্যাদি) কি না।
is_select প্রপার্টি SELECT কি না।
is_update প্রপার্টি UPDATE কি না।
lazy_loaded_from প্রপার্টি lazy load হলে কোন অবজেক্টের (InstanceState) জন্য, নইলে None।
load_options প্রপার্টি (internal) এই execution-এর ORM লোড-অপশন অবজেক্ট (populate_existing, autoflush ইত্যাদি)।
loader_strategy_path প্রপার্টি (internal) relationship লোডের বর্তমান পথ (PathRegistry), নইলে None।
local_execution_options অ্যাট্রিবিউট শুধু execute(..., execution_options={...})-এ দেওয়া অপশন (স্টেটমেন্টেরগুলো বাদে)।
parameters অ্যাট্রিবিউট execute()-এ দেওয়া প্যারামিটার (dict বা তালিকা)।
session অ্যাট্রিবিউট যে Session-এ চলছে।

QueryContext¶

from sqlalchemy.orm.context import QueryContext

(অভ্যন্তরীণ) একটি ORM কুয়েরির ফল থেকে অবজেক্ট বানানোর সময়ের অবস্থা। InstanceEvents.load(target, context) আর refresh(target, context, attrs) ইভেন্টে context হিসেবে আসে; সেখান থেকে সেশন, execution options ইত্যাদি পড়া যায়।

উদাহরণ:

seen = []
@event.listens_for(User, "load")
def on_load(target, context):
    seen.append((type(context).__name__, context.session is session, target.name))
session.get(User, 1)
print(seen)   # [('QueryContext', True, 'রহিম')]

load_options অ্যাট্রিবিউট (internal) লোড-অপশন অবজেক্ট।
loaders_require_buffering অ্যাট্রিবিউট (internal) লোডারদের সব রো আগে বাফার করা দরকার কি না।

params অ্যাট্রিবিউট (internal) কুয়েরির প্যারামিটার।

populate_existing অ্যাট্রিবিউট সেশনে থাকা অবজেক্টও নতুন মানে ভরবে কি না।
post_load_paths অ্যাট্রিবিউট (internal) লোড শেষে চলার কাজ (যেমন selectin লোড)।
propagated_loader_options অ্যাট্রিবিউট (internal) lazy load-এ পৌঁছে দেওয়ার লোডার অপশন।
query অ্যাট্রিবিউট (internal) যে স্টেটমেন্ট চলছে।
refresh_state অ্যাট্রিবিউট (internal) refresh() বা expired লোড হলে কোন অবজেক্টের InstanceState, নইলে None।

runid অ্যাট্রিবিউট (internal) এই লোড অপারেশনের নম্বর।
session অ্যাট্রিবিউট যে সেশনে লোড হচ্ছে।
top_level_context অ্যাট্রিবিউট (internal) nested লোডে সবচেয়ে বাইরের QueryContext (না থাকলে None)।
user_passed_query অ্যাট্রিবিউট (internal) ব্যবহারকারী যে স্টেটমেন্ট দিয়েছিল (ORM বদলানোর আগে)।

CALLABLES_OK অ্যাট্রিবিউট (১) মান না থাকলে লোডার ফাংশন চালানো যাবে।
DEFERRED_HISTORY_LOAD অ্যাট্রিবিউট (২৫৬) অ্যাট্রিবিউটের আগের মানের বিশেষ লোড (active_history-এর জন্য)।
INCLUDE_PENDING_MUTATIONS অ্যাট্রিবিউট (৫১২) এখনো প্রয়োগ না হওয়া collection বদলও হিসাবে ধরবে।
INIT_OK অ্যাট্রিবিউট (৮) অন্য কিছু না পেলে খালি মান (None বা খালি collection) বসানো যাবে।
LOAD_AGAINST_COMMITTED অ্যাট্রিবিউট (৩২) লোডের সময় primary/foreign key-এর commit-হওয়া (আগের) মান ব্যবহার করবে।
NON_PERSISTENT_OK অ্যাট্রিবিউট (১৬) অভিভাবক persistent না হলেও লোডার চালানো যাবে।
NO_AUTOFLUSH অ্যাট্রিবিউট (৬৪) লোডের সময় autoflush বন্ধ।
NO_CHANGE অ্যাট্রিবিউট (০) কিছুই চালাবে না, কিছুই বদলাবে না।
NO_RAISE অ্যাট্রিবিউট (১২৮) লোডার কোনো assertion এরর তুলবে না (merge()-এ)।
PASSIVE_MERGE অ্যাট্রিবিউট PASSIVE_OFF | NO_RAISE: session.merge()-এর জন্য।
PASSIVE_NO_FETCH অ্যাট্রিবিউট PASSIVE_OFF থেকে SQL_OK বাদ: সব চলবে, শুধু SQL নয়।

PASSIVE_NO_INITIALIZE অ্যাট্রিবিউট লোড বা খালি-মান কিছুই নয়: যা আছে শুধু তাই (না থাকলে NO_VALUE)।
PASSIVE_OFF অ্যাট্রিবিউট সব অনুমতি: দরকার হলে SQL চালিয়ে লোড করবে (সাধারণ অ্যাট্রিবিউট পড়ার আচরণ)।
PASSIVE_ONLY_PERSISTENT অ্যাট্রিবিউট PASSIVE_OFF থেকে NON_PERSISTENT_OK বাদ: শুধু persistent অভিভাবকের জন্য লোড।
