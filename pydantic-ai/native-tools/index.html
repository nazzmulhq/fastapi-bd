নেটিভ টুল¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা শিখবেন

  • নেটিভ টুল কী: যে টুল LLM provider নিজেই দেয় আর তাদের সার্ভারে চালায় (web search, code execution, ছবি তৈরি...)।
  • NativeTool দিয়ে এজেন্টে যোগ করা, আর রানের প্রসঙ্গ অনুযায়ী গতিশীল কনফিগারেশন।
  • প্রতিটি টুল — Web Search, X Search, Code Execution, Image Generation, Web Fetch, Memory, Advisor, MCP Server, File Search — আর কোন provider কী সমর্থন করে।

নেটিভ টুল LLM provider দেয় আর চালায়, অথচ common tools হলো Pydantic AI-এর চালানো নিজের বাস্তবায়ন।

উদাহরণ দিয়ে বুঝি

সাধারণ টুল হলো আপনার নিজের রান্নাঘরে রান্না করা খাবার — আপনি রাঁধেন (Python ফাংশন চলে আপনার সার্ভারে)। নেটিভ টুল হলো রেস্তোরাঁর নিজস্ব রান্নাঘরে তৈরি পদ — আপনি শুধু অর্ডার দেন ("web search চালাও"), provider-এর সার্ভারেই সব হয়। সুবিধা: কোনো কোড লিখতে হয় না, দ্রুত। অসুবিধা: শুধু যে provider সেই "পদ" রাখে সেখানেই পাওয়া যায়।

এক নজরে¶

Pydantic AI নিচের নেটিভ টুলগুলো সমর্থন করে:

  • WebSearchTool: এজেন্টকে ওয়েবে সার্চ করতে দেয়
  • XSearchTool: এজেন্টকে X/Twitter সার্চ করতে দেয় (শুধু xAI)
  • CodeExecutionTool: এজেন্টকে একটি নিরাপদ পরিবেশে কোড চালাতে দেয়
  • ImageGenerationTool: এজেন্টকে ছবি তৈরি করতে দেয়
  • WebFetchTool: এজেন্টকে ওয়েব পেজ আনতে দেয়
  • MemoryTool: এজেন্টকে memory ব্যবহার করতে দেয়
  • MCPServerTool: এজেন্টকে দূরের MCP সার্ভার ব্যবহার করতে দেয়, যোগাযোগ মডেল provider সামলায়
  • FileSearchTool: এজেন্টকে vector search দিয়ে আপলোড করা ফাইলে সার্চ করতে দেয় (RAG)
  • AdvisorTool: একটি দ্রুত executor মডেলকে তৈরির মাঝে একটি শক্তিশালী advisor মডেলের পরামর্শ নিতে দেয় (Anthropic, OpenRouter)

এই টুলগুলো এজেন্টের capabilities তালিকায় দেওয়া হয়, NativeTool-এ মোড়া, আর মডেল provider-এর অবকাঠামোয় চলে।

কল আর ফল মডেলের উত্তরে দেখা দেয় NativeToolCallPart আর NativeToolReturnPart হিসেবে। একটি নেটিভ টুল কলের আগে মডেল যে লেখা লেখে তা আউটপুট নয়, ভূমিকা হিসেবে ধরা হয়, যদি না শেষ নেটিভ টুল কলের পরে কোনো লেখা না থাকে: কিছু provider, যেমন Gemini 2.5-সহ Google, একটি উত্তরকে ভিত্তি দেওয়া সার্চগুলো এর লেখার পরে জানায়।

Provider সমর্থন

সব মডেল provider নেটিভ টুল সমর্থন করে না। একটি অসমর্থিত provider-এর সাথে একটি নেটিভ টুল ব্যবহার করলে, এজেন্ট চালানোর চেষ্টার সময় Pydantic AI একটি UserError তুলবে।

একটি provider এমন একটি নেটিভ টুল সমর্থন করলে যা বর্তমানে Pydantic AI সমর্থন করে না, অনুগ্রহ করে একটি issue জমা দিন।

Provider-অনুযায়ী মানিয়ে নেওয়া capability

একটি উচ্চ-স্তরের, মডেল-নিরপেক্ষ পদ্ধতির জন্য, provider-adaptive tool capabilities বিবেচনা করুন: WebSearch, WebFetch, ImageGeneration আর MCP। এগুলো সমর্থিত হলে নিজে থেকে মডেলের নেটিভ টুল ব্যবহার করে আর আপনি local= দিয়ে চালু করা একটি লোকাল বাস্তবায়নে ফিরে যায়, তাই আপনার এজেন্ট কোড না বদলেই provider-জুড়ে কাজ করে। দুটি ভিন্নভাবে কাজ করে: ImageGeneration fallback_image_model= বা fallback_subagent_model= দিয়ে built-in বিকল্পও চালু করে, আর MCP ডিফল্টভাবে লোকালে চলে আর native=True দিয়ে নেটিভ MCP বেছে নেয়।

Google-এ টুলের মিশ্রণ¶

Gemini 3 মডেল নেটিভ টুলকে ফাংশন টুলের সাথে মেলানো সমর্থন করে, আউটপুট টুল আর NativeOutput-সহ। আগের Gemini মডেল এই মিশ্রণ ব্যবহার করতে পারে না; নেটিভ টুলের পাশাপাশি গোছানো আউটপুটের জন্য PromptedOutput ব্যবহার করুন।

গতিশীল কনফিগারেশন¶

কখনো কখনো run context-এর ভিত্তিতে (যেমন ব্যবহারকারীর dependencies) একটি নেটিভ টুল গতিশীলভাবে কনফিগার করতে হয়, বা শর্তসাপেক্ষে বাদ দিতে হয়। capabilities-এ NativeTool দিয়ে একটি ফাংশন মুড়ে এটি করতে পারেন। ফাংশনটি RunContext আর্গুমেন্ট নেয় আর একটি AbstractNativeTool বা None ফেরত দেয়।

এটি বিশেষভাবে কাজে লাগে WebSearchTool-এর মতো টুলে, যেখানে আপনি বর্তমান রিকোয়েস্টের ভিত্তিতে ব্যবহারকারীর অবস্থান সেট করতে চাইতে পারেন, বা ব্যবহারকারী কোনো অবস্থান না দিলে টুলটি বন্ধ করতে চাইতে পারেন।

dynamic_native_tool.py
from pydantic_ai import Agent, RunContext, WebSearchTool
from pydantic_ai.capabilities import NativeTool


async def prepared_web_search(ctx: RunContext[dict]) -> WebSearchTool | None:
    if not ctx.deps.get('location'):
        return None

    return WebSearchTool(
        user_location={'city': ctx.deps['location']},
    )

agent = Agent(
    'openai-responses:gpt-6.1-sol',
    capabilities=[NativeTool(prepared_web_search)],
    deps_type=dict,
)

# Run with location
result = agent.run_sync(
    'What is the weather like?',
    deps={'location': 'London'},
)
print(result.output)
#> It's currently raining in London.

# Run without location (tool will be omitted)
result = agent.run_sync(
    'What is the capital of France?',
    deps={'location': None},
)
print(result.output)
#> The capital of France is Paris.

একটি fallback_subagent_model-এর অধীনে None ফেরত দেওয়া

যেখানেই নেটিভ টুল একমাত্র পথ, সেখানে None মানে বাদ দেওয়া। XSearch আর ImageGeneration ব্যতিক্রম: একবার fallback_subagent_model সেট হলে, factory None ফেরত দিলেই তাদের subagent টুল মডেলকে দেওয়া হয়, আর এটি ডাকলে ডিফল্ট সেটিং দিয়ে চলার বদলে UserError ওঠে। দেখুন X Search আর Image Generation।

Anthropic Web Search টুলের সংস্করণ

Pydantic AI কোনো dynamic_filtering অপশন দেয় না। Anthropic-এর জন্য, Pydantic AI model profile আর Anthropic client থেকে web search টুলের সংস্করণ বাছে: Anthropic-এর dynamic-filtering web টুল সমর্থন করা মডেল আর প্ল্যাটফর্মের জন্য web_search_20260209, আর অন্যথায় web_search_20250305। পুরনো Amazon Bedrock client Anthropic web search সমর্থন করে না, তাই AsyncAnthropicBedrock-এর সাথে WebSearchTool ব্যবহার করলে Pydantic AI একটি UserError তোলে। Vertex AI-তে, WebSearchTool সবসময় web_search_20250305 ব্যবহার করে, কারণ Anthropic সেখানে dynamic-filtering সংস্করণ দেয় না, তাই অন্যথায় সমর্থিত মডেলেও dynamic filtering অনুপলব্ধ। বর্তমান মডেল সমর্থন আর প্ল্যাটফর্মের প্রাপ্যতার জন্য দেখুন Anthropic web search ডক আর tool reference।

সংক্ষেপে মনে রাখুন

  • নেটিভ টুল provider-এর সার্ভারে চলে; যোগ করুন capabilities=[NativeTool(WebSearchTool())] দিয়ে।
  • সব provider সব টুল সমর্থন করে না — অসমর্থিত হলে UserError; provider-জুড়ে কাজ করতে WebSearch/WebFetch/ImageGeneration/MCP capability (লোকাল বিকল্পসহ)।
  • OpenAI-এ বেশিরভাগ নেটিভ টুলের জন্য Responses API লাগে।
  • সীমিত-করা প্যারামিটার (allowed_domains, max_uses...) প্রয়োগ না হলে টুলটি চলে না — নিঃশব্দে উপেক্ষিত হয় না।
  • প্রসঙ্গ অনুযায়ী বদলাতে NativeTool(lambda ctx: ...); None ফেরত দিলে টুল বাদ।
