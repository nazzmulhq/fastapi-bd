Toolset¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা শিখবেন

  • Toolset কী: একসাথে নথিভুক্ত করা যায় এমন টুলের একটি সংগ্রহ, আর এজেন্টকে এটি দেওয়ার চার উপায়।
  • FunctionToolset, toolset-এর নিজস্ব নির্দেশনা, আর toolset জোড়া লাগানো: মেলানো, ছাঁকা, উপসর্গ, নাম বদল, অনুমোদন, deferred loading।
  • বাইরের (frontend) টুলের জন্য ExternalToolset, গতিশীলভাবে toolset তৈরি, আর নিজের toolset লেখা।
  • MCP, LangChain আর অন্য third-party toolset।

একটি toolset হলো টুলের একটি সংগ্রহ যা একবারে একটি এজেন্টে নথিভুক্ত করা যায়। এগুলো বিভিন্ন এজেন্ট আবার ব্যবহার করতে পারে, চলার সময় বা টেস্টের সময় বদলানো যায়, আর জোড়া লাগিয়ে গতিশীলভাবে কোন টুল উপলব্ধ তা ছাঁকা, টুলের সংজ্ঞা বদলানো বা টুল চালানোর আচরণ বদলানো যায়। একটি toolset-এ লোকালে সংজ্ঞায়িত ফাংশন থাকতে পারে, সেগুলো দিতে একটি বাইরের সার্ভিসের ওপর নির্ভর করতে পারে, বা উপলব্ধ টুলের তালিকা আর সেগুলো ডাকা সামলাতে নিজের লজিক বাস্তবায়ন করতে পারে। Toolset capabilities দিয়েও দেওয়া যায়, যা hook, নির্দেশনা আর মডেল সেটিংসহ টুল বান্ডেল করে।

উদাহরণ দিয়ে বুঝি

টুল যদি একটি স্ক্রুড্রাইভার হয়, toolset হলো পুরো টুলবক্স। একটি "আবহাওয়া টুলবক্স", একটি "ডেটাবেস টুলবক্স" — যেকোনো এজেন্টকে একবারে পুরো বাক্সটি দিন। আর বাক্সগুলো মোড়ানো যায়: "এই বাক্সের শুধু পড়ার টুলগুলো দাও" (ছাঁকা), "সবগুলোর নামের আগে weather_ লাগাও" (উপসর্গ), "এগুলো চালানোর আগে অনুমোদন নাও" (approval)।

Toolset ব্যবহার হয় (আরও অনেক কিছুর মধ্যে) একটি এজেন্টের কাছে উপলব্ধ MCP সার্ভার সংজ্ঞায়িত করতে। Pydantic AI-তে অনেক ধরনের toolset আছে যা নিচে বর্ণিত, আর আপনি AbstractToolset ক্লাস থেকে উত্তরাধিকার নিয়ে একটি নিজের toolset সংজ্ঞায়িত করতে পারেন।

একটি এজেন্ট রানের সময় যে toolset উপলব্ধ থাকবে তা চারটি ভিন্ন উপায়ে নির্দিষ্ট করা যায়:

  • এজেন্ট তৈরির সময়, Agent-এর [toolsets][pydantic_ai.agent.Agent.__init__] keyword আর্গুমেন্ট দিয়ে, যা toolset instance আর এজেন্টের run context-এর ভিত্তিতে গতিশীলভাবে toolset তৈরি করা ফাংশন দুটোই নেয়
  • এজেন্ট চলার সময়, agent.run(), agent.run_sync(), agent.run_stream() বা agent.iter()-এর toolsets keyword আর্গুমেন্ট দিয়ে। এই toolset-গুলো Agent-এ নথিভুক্তগুলোর বাড়তি হবে
  • গতিশীলভাবে, @agent.toolset decorator দিয়ে, যা আপনাকে এজেন্টের run context-এর ভিত্তিতে একটি toolset তৈরি করতে দেয়
  • একটি প্রাসঙ্গিক override হিসেবে, agent.override() context manager-এর toolsets keyword আর্গুমেন্ট দিয়ে। এই toolset-গুলো context manager-এর আয়ুষ্কালে এজেন্ট তৈরি বা চলার সময় দেওয়াগুলোর জায়গা নেবে
toolsets.py
from pydantic_ai import Agent, FunctionToolset
from pydantic_ai.models.test import TestModel


def agent_tool():
    return "I'm registered directly on the agent"


def extra_tool():
    return "I'm passed as an extra tool for a specific run"


def override_tool():
    return 'I override all other tools'


agent_toolset = FunctionToolset(tools=[agent_tool]) # (1)!
extra_toolset = FunctionToolset(tools=[extra_tool])
override_toolset = FunctionToolset(tools=[override_tool])

test_model = TestModel() # (2)!
agent = Agent(test_model, toolsets=[agent_toolset])

result = agent.run_sync('What tools are available?')
assert test_model.last_model_request_parameters is not None
print([t.name for t in test_model.last_model_request_parameters.function_tools])
#> ['agent_tool']

result = agent.run_sync('What tools are available?', toolsets=[extra_toolset])
print([t.name for t in test_model.last_model_request_parameters.function_tools])
#> ['agent_tool', 'extra_tool']

with agent.override(toolsets=[override_toolset]):
    result = agent.run_sync('What tools are available?', toolsets=[extra_toolset]) # (3)!
    print([t.name for t in test_model.last_model_request_parameters.function_tools])
    #> ['override_tool']
  1. FunctionToolset পরের অংশে বিস্তারিত ব্যাখ্যা করা হবে।
  2. আমরা এখানে TestModel ব্যবহার করছি কারণ এতে প্রতিটি রানে কোন টুল উপলব্ধ ছিল তা দেখা সহজ।
  3. এই extra_toolset উপেক্ষিত হবে কারণ আমরা একটি override context-এর ভেতরে।

Function toolset¶

নাম থেকেই বোঝা যায়, একটি FunctionToolset লোকালে সংজ্ঞায়িত ফাংশনকে টুল হিসেবে উপলব্ধ করে।

ফাংশন চারটি ভিন্ন উপায়ে টুল হিসেবে যোগ করা যায়:

  • @toolset.tool decorator দিয়ে — যে টুলের এজেন্টের context-এ প্রবেশ লাগে তার জন্য
  • @toolset.tool_plain decorator দিয়ে — যে টুলের এজেন্টের context-এ প্রবেশ লাগে না তার জন্য
  • constructor-এর [tools][pydantic_ai.toolsets.FunctionToolset.__init__] keyword আর্গুমেন্ট দিয়ে, যা সাধারণ ফাংশন বা Tool-এর instance নিতে পারে
  • toolset.add_function() আর toolset.add_tool() মেথড দিয়ে, যা যথাক্রমে একটি সাধারণ ফাংশন বা Tool-এর একটি instance নিতে পারে

add_function() আর add_tool() মেথড একটি টুল ফাংশন থেকেও ব্যবহার করা যায়, একটি রানের সময় গতিশীলভাবে নতুন টুল নথিভুক্ত করতে যা পরের রান ধাপে উপলব্ধ হবে।

function_toolset.py
from datetime import datetime

from pydantic_ai import Agent, FunctionToolset, RunContext
from pydantic_ai.models.test import TestModel


def temperature_celsius(city: str) -> float:
    return 21.0


def temperature_fahrenheit(city: str) -> float:
    return 69.8


weather_toolset = FunctionToolset(tools=[temperature_celsius, temperature_fahrenheit])


@weather_toolset.tool
def conditions(ctx: RunContext, city: str) -> str:
    if ctx.run_step % 2 == 0:
        return "It's sunny"
    else:
        return "It's raining"


datetime_toolset = FunctionToolset()
datetime_toolset.add_function(lambda: datetime.now(), name='now')

test_model = TestModel()  # (1)!
agent = Agent(test_model)

result = agent.run_sync('What tools are available?', toolsets=[weather_toolset])
assert test_model.last_model_request_parameters is not None
print([t.name for t in test_model.last_model_request_parameters.function_tools])
#> ['temperature_celsius', 'temperature_fahrenheit', 'conditions']

result = agent.run_sync('What tools are available?', toolsets=[datetime_toolset])
print([t.name for t in test_model.last_model_request_parameters.function_tools])
#> ['now']
  1. আমরা এখানে TestModel ব্যবহার করছি কারণ এতে প্রতিটি রানে কোন টুল উপলব্ধ ছিল তা দেখা সহজ।

(এই উদাহরণ সম্পূর্ণ, "যেমন আছে তেমন" চালানো যায়)

প্রথম মডেল রিকোয়েস্টের পরে রানে যোগ দেওয়া একটি টুল, যেভাবেই সেখানে পৌঁছাক, বার্তার ইতিহাসে একটি ToolAvailabilityDeltaPart হিসেবে রেকর্ড হয়, যদি না আগের কোনো সরাসরি দৃশ্যমান টুল স্থির রাখার জন্য তখনো উপস্থিত না থাকে। defer_loading=True-সহ একটি নতুন টুল বদলে tool search corpus-এ যোগ দেয়। প্রতিটি provider এটি কীভাবে পৌঁছে দেয় তা দেখুন Tools that appear mid-run-এ।

Toolset-এর নির্দেশনা¶

একটি FunctionToolset এমন নির্দেশনা দিতে পারে যা নিজে থেকে মডেল রিকোয়েস্টে যোগ হয়। এতে প্রতিটি toolset তার টুলের পাশাপাশি নিজের ব্যবহারের নির্দেশনা বহন করে, তাই toolset ব্যবহার করা প্রতিটি এজেন্টে নির্দেশনা পুনরাবৃত্তি করতে হয় না।

নির্দেশনা দেওয়া যায় স্ট্রিং, ফাংশন (sync বা async, RunContext-সহ বা ছাড়া), বা দুটোর মিশ্রণ হিসেবে:

toolset_instructions.py
from pydantic_ai import Agent, FunctionToolset, ModelRequest
from pydantic_ai.models.test import TestModel

search_toolset = FunctionToolset(
    instructions='Always use the search tool before answering factual questions.',
)


@search_toolset.tool_plain
def search(query: str) -> str:
    """Search for information."""

বদলায় এমন toolset নির্দেশনা¶

নির্দেশনা ফাংশন প্রতিটি মডেল রিকোয়েস্টের আগে চলে, তাই তাদের লেখা একটি রানের সময় বদলাতে পারে, যেমন একটি টুল কিছু অবস্থা হালনাগাদ করার পরে। ডিফল্টভাবে প্রতিটি পরিবর্তন নির্দেশনার prefix নতুন করে লেখে, যা provider-কে এর পেছনের cache করা কথোপকথন আবার ব্যবহার করা থেকে থামায়। কথোপকথনের মাঝে বদলানো নির্দেশনার জন্য, আমরা পরিবর্তনগুলো বদলে ইতিহাসে জোড়ার পরামর্শ দিই: prefix cache-এ থাকে, প্রতিটি পরিবর্তনে ব্লকের সম্পূর্ণ নতুন লেখা ইতিহাসে যোগ হওয়ার বিনিময়ে। এগুলো শুধু আপনার নিয়ন্ত্রিত অবস্থা থেকে তৈরি করুন: অবিশ্বস্ত লেখা নির্দেশনার বাইরে রাখুন।

যোগ দিতে, toolset-কে একটি id দিন আর ফাংশনটি @toolset.instructions(name=..., on_change='append') দিয়ে নথিভুক্ত করুন। একটি নিজের toolset বদলে get_instructions() থেকে on_change='append'-সহ একটি InstructionPart ফেরত দিতে পারে:

from pydantic_ai.models.test import TestModel

    items: list[str] = field(default_factory=list[str])

@cart_toolset.tool

    """Add an item to the cart."""
    ctx.deps.items.append(item)
    return 'Added.'

        part.content

গতিশীল টুল সংজ্ঞা¶

PreparedToolset এজেন্ট রানের প্রতিটি ধাপের আগে উপলব্ধ টুলের পুরো তালিকা বদলাতে দেয়, একটি ব্যবহারকারী-সংজ্ঞায়িত ফাংশন দিয়ে যা এজেন্টের run context আর ToolDefinition-এর একটি তালিকা নেয় আর সেই ধাপে দেখানোর টুল সংজ্ঞা ফেরত দেয়।

এটি prepare_tools capability hook-এর toolset-নির্দিষ্ট সমতুল্য, যা toolset-জুড়ে একটি এজেন্টে নথিভুক্ত সব টুল সংজ্ঞা প্রস্তুত করে।

মনে রাখবেন PreparedToolset দিয়ে টুল যোগ বা নাম বদল সম্ভব নয়। বদলে, FunctionToolset.add_function() বা RenamedToolset ব্যবহার করতে পারেন।

ApprovalRequiredToolset একটি toolset মুড়ে রাখে আর একটি নির্দিষ্ট টুল কলের জন্য গতিশীলভাবে অনুমোদন বাধ্যতামূলক করতে দেয়, একটি ব্যবহারকারী-সংজ্ঞায়িত ফাংশনের ভিত্তিতে যা এজেন্টের run context, টুলের ToolDefinition আর যাচাই করা টুল কলের আর্গুমেন্ট পায়। কোনো ফাংশন দেওয়া না হলে, সব টুল কলে অনুমোদন লাগবে।

Deferred loading¶

DeferredLoadingToolset একটি toolset মুড়ে রাখে আর এর টুলগুলো deferred loading-এর জন্য চিহ্নিত করে, tool search দিয়ে আবিষ্কার না হওয়া পর্যন্ত মডেলের কাছ থেকে লুকিয়ে। বড় toolset-এর জন্য (যেমন অনেক endpoint-সহ MCP সার্ভার) এটি কাজে লাগে, যেখানে সব টুল সংজ্ঞা মডেলের প্রসঙ্গে লোড করা অপচয় হতো।

FunctionToolset তার constructor-এ সব টুল deferred loading-এর জন্য চিহ্নিত করতে defer_loading=True-ও নেয়। অন্য toolset-এর জন্য, .defer_loading() ডাকুন — শুধু নির্দিষ্ট টুল লুকাতে টুলের নামের একটি তালিকা দিন, বা সব লুকাতে None (ডিফল্ট)।

from pydantic_ai.mcp import MCPToolset

agent = Agent('openai:gpt-6.1-sol', toolsets=[mcp.defer_loading()])

ফেরত schema রাখা¶

IncludeReturnSchemasToolset একটি toolset মুড়ে রাখে আর এর সব টুলে include_return_schema=True সেট করে, যাতে মডেল ফেরত টাইপের তথ্য পায়। নিজস্বভাবে ফেরত schema সমর্থন করা মডেলে (যেমন Google Gemini), schema একটি গোছানো API ফিল্ড হিসেবে পাঠানো হয়। অন্য মডেলে, এটি JSON লেখা হিসেবে টুলের বর্ণনায় ঢোকানো হয়।

টুল চালানো বদলানো¶

WrapperToolset আরেকটি toolset মুড়ে রাখে আর সব দায়িত্ব তাকে দেয়।

এটি ডিফল্টভাবে কিছুই করে না, তবে call_tool() মেথড override করে মোড়ানো toolset-এর টুল চালানোর আচরণ বদলাতে WrapperToolset-এর subclass করতে পারেন।

logging_toolset.py
import asyncio
from typing import Any

from pydantic_ai import Agent, RunContext, ToolsetTool, WrapperToolset
from pydantic_ai.models.test import TestModel

from prepared_toolset import prepared_toolset

LOG = []

class LoggingToolset(WrapperToolset):
    async def call_tool(self, name: str, tool_args: dict[str, Any], ctx: RunContext, tool: ToolsetTool) -> Any:
        LOG.append(f'Calling tool {name!r} with args: {tool_args!r}')
        try:
            await asyncio.sleep(0.1 * len(LOG)) # (1)!

            result = await super().call_tool(name, tool_args, ctx, tool)
            LOG.append(f'Finished calling tool {name!r} with result: {result!r}')
        except Exception as e:
            LOG.append(f'Error calling tool {name!r}: {e}')
            raise e
        else:
            return result


logging_toolset = LoggingToolset(prepared_toolset)

agent = Agent(TestModel(), toolsets=[logging_toolset]) # (2)!
result = agent.run_sync('Call all the tools')
print(LOG)

External toolset¶

আপনার এজেন্টের যদি এমন বাইরের টুল ডাকতে পারা দরকার যা একটি upstream সার্ভিস বা frontend দেয় আর চালায়, তাহলে টুলের নাম, আর্গুমেন্টের JSON schema আর বর্ণনাসহ ToolDefinition-এর একটি তালিকা থেকে একটি ExternalToolset তৈরি করতে পারেন।

মডেল একটি বাইরের টুল ডাকলে, কলটি "deferred" ধরা হয়, আর এজেন্ট রান একটি DeferredToolRequests আউটপুট অবজেক্ট দিয়ে শেষ হবে, যার একটি calls তালিকায় থাকে টুলের নাম, যাচাই করা আর্গুমেন্ট আর একটি অনন্য টুল কল ID-সহ ToolCallPart, যা ফল তৈরি করবে এমন upstream সার্ভিস বা frontend-এ পাঠানো হবে বলে আশা করা হয়।

upstream সার্ভিস বা frontend থেকে টুল কলের ফল পেলে, একটি calls dictionary-সহ একটি DeferredToolResults অবজেক্ট তৈরি করতে পারেন, যা প্রতিটি টুল কল ID-কে ম্যাপ করে মডেলে ফেরত দেওয়ার একটি যেকোনো মানে, একটি ToolReturn অবজেক্টে, বা টুল কল ব্যর্থ হলে একটি exception-এ: মডেলের আবার চেষ্টা করা উচিত হলে একটি ModelRetry, বা ব্যর্থতা মডেলকে একটি ব্যর্থ ফল হিসেবে জানানো উচিত হলে (টুলের retry বাজেট খরচ না করে) একটি ToolFailed, যাতে এটি কীভাবে এগোবে তা ঠিক করতে পারে। এই DeferredToolResults অবজেক্ট তারপর মূল রানের বার্তার ইতিহাসের পাশাপাশি deferred_tool_results হিসেবে এজেন্ট রান মেথডগুলোর একটিতে দেওয়া যায়।

মনে রাখবেন Agent-এর বা agent.run()-এর output_type-এ DeferredToolRequests যোগ করতে হবে, যাতে এজেন্ট রানের আউটপুটের সম্ভাব্য টাইপ সঠিকভাবে অনুমিত হয়। আরও তথ্যের জন্য দেখুন Deferred Tools ডকুমেন্টেশন।

উদাহরণ দিয়ে বুঝি

ধরুন একটি টুল ব্রাউজারের ভাষা জানতে চায় (navigator.language) — এটি সার্ভারে চালানো সম্ভব নয়, শুধু ব্যবহারকারীর ব্রাউজারে। তাই এজেন্ট বলে "এই টুলটি চালাতে হবে" আর থেমে যায় (DeferredToolRequests)। frontend টুলটি চালিয়ে ফল (DeferredToolResults) পাঠায়, আর এজেন্ট সেখান থেকে চালিয়ে যায়।

দেখাতে, চলুন প্রথমে deferred টুল ছাড়া একটি সহজ এজেন্ট সংজ্ঞায়িত করি:

deferred_toolset_agent.py
from pydantic import BaseModel

from pydantic_ai import Agent, FunctionToolset

toolset = FunctionToolset()


@toolset.tool_plain
def get_default_language():
    return 'en-US'


@toolset.tool_plain

    return 'David'


class PersonalizedGreeting(BaseModel):

    language_code: str


agent = Agent('openai:gpt-6.1-sol', toolsets=[toolset], output_type=PersonalizedGreeting)

result = agent.run_sync('Greet the user in a personalized way')
print(repr(result.output))
#> PersonalizedGreeting(greeting='Hello, David!', language_code='en-US')

এরপর, চলুন একটি ফাংশন সংজ্ঞায়িত করি যা একটি কাল্পনিক "run agent" API endpoint-এর প্রতিনিধিত্ব করে, যা frontend ডাকতে পারে আর মডেলে পাঠানোর বার্তার একটি তালিকা, frontend টুল সংজ্ঞার একটি তালিকা, আর ঐচ্ছিক deferred টুল ফল নেয়। এখানেই ExternalToolset, DeferredToolRequests আর DeferredToolResults আসে:

deferred_toolset_api.py
from pydantic_ai import (
    DeferredToolRequests,
    DeferredToolResults,
    ExternalToolset,
    ModelMessage,
    ToolDefinition,
)

from deferred_toolset_agent import PersonalizedGreeting, agent


def run_agent(
    messages: list[ModelMessage] = [],
    frontend_tools: list[ToolDefinition] = [],
    deferred_tool_results: DeferredToolResults | None = None,
) -> tuple[PersonalizedGreeting | DeferredToolRequests, list[ModelMessage]]:
    deferred_toolset = ExternalToolset(frontend_tools)
    result = agent.run_sync(
        toolsets=[deferred_toolset], # (1)!
        output_type=[agent.output_type, DeferredToolRequests], # (2)!
        message_history=messages, # (3)!
        deferred_tool_results=deferred_tool_results,
    )
    return result.output, result.new_messages()
  1. Deferred Tools ডকুমেন্টেশনে যেমন বলা হয়েছে, এই toolsets Agent constructor-এ দেওয়াগুলোর বাড়তি
  2. Deferred Tools ডকুমেন্টেশনে যেমন বলা হয়েছে, এই output_type Agent constructor-এ দেওয়াটি override করে, তাই আমাদের নিশ্চিত করতে হবে যেন এটি না হারাই
  3. আমরা কোনো user_prompt keyword আর্গুমেন্ট রাখি না কারণ আমরা আশা করি frontend এটি messages দিয়ে দেবে

এখন, কল্পনা করুন নিচের কোডটি frontend-এ বাস্তবায়িত, আর run_agent এজেন্ট চালানো backend-এর একটি API কলের প্রতিনিধি। এখানেই আমরা আসলে deferred টুল কল চালাই আর নতুন ফলসহ একটি নতুন রান শুরু করি:

গতিশীলভাবে একটি toolset তৈরি¶

প্রতিটি এজেন্ট রান বা রান ধাপের আগে এমন একটি ফাংশন দিয়ে toolset গতিশীলভাবে তৈরি করা যায় যা এজেন্টের run context নিয়ে একটি toolset বা None ফেরত দেয়। এটি কাজে লাগে যখন একটি toolset (যেমন একটি MCP সার্ভার) একটি এজেন্ট রানের নির্দিষ্ট তথ্যের ওপর নির্ভর করে, যেমন এর dependencies — যেমন প্রতি-ব্যবহারকারী credential দিয়ে একটি MCP সার্ভারে সংযোগ করতে।

একটি গতিশীল toolset নথিভুক্ত করতে, Agent constructor-এর toolsets আর্গুমেন্টে RunContext নেয় এমন একটি ফাংশন দিতে পারেন, বা একটি মানানসই ফাংশন @agent.toolset decorator-এ মুড়তে পারেন।

ডিফল্টভাবে, ফাংশনটি প্রতিটি এজেন্ট রান ধাপের আগে আবার ডাকা হবে। decorator ব্যবহার করলে, toolset পুরো রানের জন্য শুধু একবার তৈরি করতে হবে বোঝাতে ঐচ্ছিকভাবে একটি per_run_step=False আর্গুমেন্ট দিতে পারেন।

ফাংশনটি যে toolset ফেরত দেয় তার নির্দেশনা গতিশীল toolset-এর নামে ধরা হয়, তাই সেগুলো on_change='append' ব্যবহার করতে, decorator-কে একটি id দিন: @agent.toolset(id='orders')।

from dataclasses import dataclass
from typing import Literal

from pydantic_ai import Agent, RunContext
from pydantic_ai.models.test import TestModel

from function_toolset import datetime_toolset, weather_toolset


@dataclass
class ToggleableDeps:
    active: Literal['weather', 'datetime']

    def toggle(self):
        if self.active == 'weather':
            self.active = 'datetime'
        else:
            self.active = 'weather'

test_model = TestModel()  # (1)!
agent = Agent(
    test_model,
    deps_type=ToggleableDeps  # (2)!
)

@agent.toolset
def toggleable_toolset(ctx: RunContext[ToggleableDeps]):
    if ctx.deps.active == 'weather':
        return weather_toolset
    else:
        return datetime_toolset

@agent.tool
def toggle(ctx: RunContext[ToggleableDeps]):
    ctx.deps.toggle()

deps = ToggleableDeps('weather')

result = agent.run_sync('Toggle the toolset', deps=deps)
assert test_model.last_model_request_parameters is not None
print([t.name for t in test_model.last_model_request_parameters.function_tools])  # (3)!
#> ['toggle', 'now']

একটি নিজের toolset তৈরি¶

উপলব্ধ টুলের তালিকা আর সেগুলো ডাকা সামলানোর নিজস্ব লজিকসহ একটি পুরোপুরি নিজের toolset সংজ্ঞায়িত করতে, AbstractToolset-এর subclass করে get_tools() আর call_tool() মেথড বাস্তবায়ন করতে পারেন।

toolset-এর টুল কীভাবে ব্যবহার করতে হবে তার একটি বর্ণনা দিতে get_instructions() মেথডও override করতে পারেন। এটি এজেন্টের নির্দেশনায় ঢোকানো হবে আর মডেলকে আপনার toolset-এর টুল কার্যকরভাবে কীভাবে ব্যবহার করবে তা বুঝতে সাহায্যে কাজে লাগে।

toolset-এর একটি id থাকলে আর এটি নির্দেশনা দিলে, সেই id একটি এজেন্টে নথিভুক্ত toolset-এর মধ্যে অনন্য হতে হবে, একটি capability-র দেওয়াগুলো গুনে। এর নির্দেশনা মডেলে পৌঁছায় 'toolset:<toolset id>' দিয়ে চিহ্নিত instruction parts হিসেবে, তাই একটি অ্যাপ্লিকেশন তাদের শব্দের চেয়ে দীর্ঘজীবী একটি key দিয়ে সেগুলোতে পৌঁছাতে পারে। toolset যে প্রতিটি অংশ ফেরত দেয় তা সেই একটি key বহন করে; একটি অংশকে আলাদাভাবে পৌঁছানোযোগ্য চাইলে, আপনার toolset-এর সাপেক্ষে একটি name-সহ ('limits') একটি InstructionPart ফেরত দিন, যা framework 'toolset:weather:limits'-এ যোগ্য করে। নিজের id লিখে দেবেন না — framework আগেই যা জানে তা পুনরাবৃত্তি করতেন, আর আপনার নিজের একটি নাম একটি শীর্ষ-স্তরের key-এর সাথে গুলিয়ে যেতে পারে না।

একটি id-সহ একটি wrapper toolset যা get_instructions() override করে, super().get_instructions(ctx) তাকে যে অংশ-অবজেক্ট দিয়েছে হুবহু সেগুলো অপরিবর্তিত ফেরত দিয়ে যা মোড়ায় তা এগিয়ে দিতে পারে: সেগুলো যে toolset লিখেছে তাদের id রাখে, বা তাদের toolset-এর id না থাকলে কোনো id নয়। বাকি প্রতিটি অংশ wrapper-এর নিজের id দিয়ে key করা: যেগুলো এটি যোগ করে, যেগুলো জায়গায় বদলায়, আর কপিগুলো, এমনকি replace(part)-এর মতো একটি অপরিবর্তিত কপি যা তখনো যে অংশ থেকে এসেছে তার id বহন করে। একটি গতিশীল toolset যে toolset তৈরি করে তা এভাবে মোড়ানো হয় না, তাই এটি যা বলে তার সবকিছু গতিশীল toolset-এর id দিয়ে key করা।

get_instructions() প্রতিটি মডেল রিকোয়েস্টের আগে ডাকা হয়। এটি যা ফেরত দেয় তা একটি কথোপকথনের সময় বদলাতে পারলে, InstructionPart-এ on_change='append' সেট করুন যাতে পরিবর্তনগুলো cache করা prefix নতুন করে না লিখে ইতিহাসে জোড়া হয়; দেখুন Toolset instructions that change।

পরামর্শ

আপনার toolset-এর মডেল সেটিং বা hook-ও দেওয়া দরকার হলে, বদলে একটি নিজের capability তৈরির কথা ভাবুন।

toolset-এর জীবনচক্র বিভিন্ন পরিসরে অবস্থা সামলানোর hook দেয়:

  • for_run(): প্রতিটি এজেন্ট রানের আগে একবার ডাকা হয়। প্রতি-রান অবস্থা বিচ্ছিন্ন করতে একটি নতুন instance ফেরত দিন (যেমন গণক রিসেট, একটি নতুন session তৈরি)। framework ফেরত দেওয়া instance-এ ঢোকে আর বেরোয়।
  • for_run_step(): প্রতিটি রান ধাপের শুরুতে ডাকা হয়। প্রতি-ধাপের অবস্থা-পরিবর্তনের জন্য একটি বদলানো instance ফেরত দিন। ভেতরের toolset-এর পরিবর্তন সামলালে (যেমন একটি toolset আরেকটি দিয়ে বদলানো), ভেতরের জীবনচক্রের দায়িত্ব আপনার (পুরনোটি থেকে বেরোনো, নতুনটিতে ঢোকা)।
  • [__aenter__()][pydantic_ai.toolsets.AbstractToolset.__aenter__] আর [__aexit__()][pydantic_ai.toolsets.AbstractToolset.__aexit__]: এজেন্ট রানের সময়কাল পর্যন্ত টিকে থাকা উচিত এমন রিসোর্স (যেমন নেটওয়ার্ক সংযোগ) সেট আপ আর বন্ধ করা।

প্রতি-রান আর প্রতি-ধাপের জীবনচক্র¶

Toolset প্রতি-রান বিচ্ছিন্নতা আর প্রতি-ধাপের অবস্থা ব্যবস্থাপনার জন্য জীবনচক্র hook সমর্থন করে:

  • for_run(ctx) -- প্রতিটি এজেন্ট রানে একবার ডাকা হয়, __aenter__-এর আগে। রানগুলোর মধ্যে অবস্থা বিচ্ছিন্ন করতে একটি নতুন instance ফেরত দিন। ডিফল্ট: self ফেরত দেয়।
  • for_run_step(ctx) -- প্রতিটি রান ধাপের শুরুতে ডাকা হয়। ভেতরের পরিবর্তন (যেমন টুলের উপলব্ধতা হালনাগাদ) জায়গায় সামলান। ডিফল্ট: self ফেরত দেয়।

pydantic-ai-ejentum¶
