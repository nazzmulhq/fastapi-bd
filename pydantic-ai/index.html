Pydantic AI¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

How Python does AI

Agents, realtime voice, image generation, embeddings. Every model, every interface, typed end to end.

এই পেজে যা শিখবেন

  • Pydantic AI কী, আর এটি দিয়ে কী কী বানানো যায় (কোডিং এজেন্ট, ডেটা বের করা, টেকসই ওয়ার্কফ্লো, ভয়েস, ছবি তৈরি)।
  • কেন Pydantic AI: যেকোনো মডেল, শুরু থেকে শেষ পর্যন্ত টাইপ, পরিমাপ, ক্যাপাবিলিটি, সব ইন্টারফেস।
  • একটি পূর্ণ উদাহরণ: ব্যাংকের গ্রাহকসেবা এজেন্ট, প্রতিটি লাইনের ব্যাখ্যাসহ।
  • Logfire দিয়ে এজেন্ট কী করছে তা দেখা, আর এরপর কোথায় যাবেন।

উদাহরণ দিয়ে বুঝি

LLM (যেমন ChatGPT বা Claude) হলো একজন খুব জ্ঞানী কিন্তু হাত-পা বাঁধা পরামর্শদাতা: কথা বলতে পারে, কিন্তু নিজে ডেটাবেস দেখতে বা ইমেইল পাঠাতে পারে না। এজেন্ট হলো সেই পরামর্শদাতাকে কিছু যন্ত্রপাতি (টুল) দেওয়া আর একটি নিয়ম বেঁধে দেওয়া: "উত্তর এই ছকেই দেবে"। Pydantic AI সেই এজেন্ট বানানোর Python লাইব্রেরি, আর FastAPI যেমন Pydantic দিয়ে ইনপুট যাচাই করে, Pydantic AI-ও তেমনি LLM-এর উত্তর Pydantic দিয়ে যাচাই করে।

Pydantic AI হলো Python-এর AI SDK: একটি টাইপসহ, বাড়ানো যায় এমন এজেন্ট লুপ, যেখানে যেকোনো মডেল শুধু একটি স্ট্রিং বদলালেই বদলে যায়। একই এজেন্ট যেখানে দরকার সেখানেই চলে: একটি ওয়েব ফ্রন্টএন্ডের পেছনে, টার্মিনালে, ভয়েস কলে, একটি টেকসই ব্যাকগ্রাউন্ড কিউতে, GitHub Actions-এ, অথবা একটি সাধারণ অবজেক্ট হিসেবে, যার ওপর আপনি run() ডাকেন। ছবি তৈরি আর embedding-ও একই বাক্সে আসে।

Pydantic AI Harness-এ আছে জটিল, দীর্ঘ কাজের জন্য একটি এজেন্টের যা যা দরকার, ক্যাপাবিলিটি হিসেবে লাগিয়ে নেওয়া যায়: স্মৃতি, গার্ডরেইল আর সাব-এজেন্ট থেকে শুরু করে পরিকল্পনা, কনটেক্সট ব্যবস্থাপনা আর সংরক্ষণ (persistence), এমনকি একটি সম্পূর্ণ কোডিং এজেন্ট পর্যন্ত।

Pydantic Evals একটি এজেন্টের চূড়ান্ত আউটপুট আর টুল-কলের ধারাবাহিকতা (trajectory) মূল্যায়ন করে, ডেটাসেটের ওপর বা প্রোডাকশনের আসল ট্রাফিকে; আর একটি এজেন্ট লুপ যথেষ্ট না হলে Pydantic Graph দেয় টাইপসহ নিয়ন্ত্রণ-প্রবাহ। দুটোই আলাদা open-source প্যাকেজ, তেমনি genai-prices, যা মডেলের দাম হালনাগাদ রাখে, আর Monty, মডেলের লেখা কোড চালানোর নিরাপদ (sandboxed) Python interpreter।

Pydantic Logfire হলো AI ইঞ্জিনিয়ারিং প্ল্যাটফর্ম, যা শুধু LLM কল নয়, আপনার পুরো অ্যাপ দেখে; আর Pydantic AI Gateway হলো সব মডেলের জন্য একটি চাবি (key), সাথে তাৎক্ষণিক খরচ পর্যবেক্ষণ আর বাজেট নিয়ন্ত্রণ। আমাদের instrumentation সাধারণ OpenTelemetry, তাই আপনার আগে থেকে চালানো যেকোনো backend কাজ করে।

আপনি কী বানাচ্ছেন?¶

সাধারণ টাইপসহ ডেটা বের করা থেকে শুরু করে জটিল, দীর্ঘ সময় ধরে চলা বহু-এজেন্টের সহযোগিতা পর্যন্ত, Pydantic AI আর Pydantic AI Harness সব সামলায়।

আপনার টার্মিনালে একটি সম্পূর্ণ কোডিং এজেন্ট: workspace-এর ভেতরে সীমিত ফাইল অ্যাক্সেস, অনুমোদিত কমান্ডের shell, রিপোর ধারণা (repo orientation), পরিকল্পনা, আর দীর্ঘ সেশনেও টিকে থাকা কনটেক্সট ব্যবস্থাপনা। এখানে সাথে লাগানো হয়েছে ওয়েব সার্চ আর দ্বিতীয় মতামত দেওয়া একজন উপদেষ্টা (advisor):

pip install pydantic-ai pydantic-ai-harness

uv add pydantic-ai pydantic-ai-harness

from pydantic_ai import Agent
from pydantic_ai.capabilities import WebSearch
from pydantic_ai_harness import Advisor, Coder

agent = Agent(
    'anthropic:claude-fable-5-1',

agent.to_cli_sync()

]

review_sentiment.py
from typing import Literal

from pydantic import BaseModel, Field

from pydantic_ai import Agent, RunContext


class Sentiment(BaseModel):
    label: Literal['positive', 'negative', 'neutral']
    score: float = Field(ge=-1, le=1)


agent = Agent('openai:gpt-6.1-sol', output_type=Sentiment)


@agent.tool
def recent_reviews(ctx: RunContext, product: str) -> list[str]:
    """Fetch recent review snippets for a product."""
    return ['The new release fixed everything I complained about!']


result = agent.run_sync('How are people feeling about the Extract app?')
print(result.output)
#> label='positive' score=0.9

@agent.tool ফাংশনটি একটি RunContext পায়, যা আপনার dependencies বহন করে আনে; এর বাকি signature আর docstring হয়ে যায় টুলের schema, আপনার কোড চলার আগেই আর্গুমেন্টগুলো যাচাই হয়, আর রানটি নিশ্চিতভাবে একটি Sentiment ফেরত দেয়, ফলে আপনার IDE, type checker আর LLM সবাই ফেরত টাইপ নিয়ে একমত।

from temporalio import workflow

from pydantic_ai import Agent
from pydantic_ai.capabilities import WebFetch, WebSearch
from pydantic_ai.durable_exec.temporal import PydanticAIWorkflow, TemporalDurability

agent = Agent(
    'openai:gpt-6.1-sol',
    instructions='Research the topic and write a structured brief.',
    name='researcher',
    capabilities=[WebSearch(), WebFetch(), TemporalDurability()],
)


@workflow.defn
class ResearchWorkflow(PydanticAIWorkflow):
    __pydantic_ai_agents__ = [agent]

    @workflow.run
    async def run(self, topic: str) -> str:
        result = await agent.run(f'Write a brief on: {topic}')
        return result.output

কেন Pydantic AI¶

  • যেকোনো মডেল, একটিই Python API। প্রায় সব মডেল আর প্রোভাইডার (OpenAI, Anthropic, Google, Bedrock, Azure AI Foundry, Groq, Mistral, xAI, Ollama আর আরও কয়েক ডজন), একটি স্ট্রিং দিয়ে বদলানো যায়, অথবা Pydantic AI Gateway দিয়ে: সবগুলোর জন্য একটি চাবি, বিকল্পে চলে যাওয়া (failover) আর খরচ পর্যবেক্ষণসহ। কোনো প্রধান সুবিধা একটি কোম্পানিতে আটকে নেই।

  • শুরু থেকে শেষ পর্যন্ত টাইপসহ। গোছানো আউটপুট, টাইপসহ dependency injection, টাইপসহ টুল: আপনার IDE, type checker আর কোডিং এজেন্ট সবাই জানে আপনার এজেন্ট কী ফেরত দেয়, ফলে অনেক ধরনের এরর চলার সময় থেকে সরে লেখার সময়েই ধরা পড়ে। সাধারণ নিয়ন্ত্রণ-প্রবাহ যথেষ্ট না হলে, Pydantic Graph গ্রাফ-ভিত্তিক ওয়ার্কফ্লোতে একই টাইপের সুবিধা আনে।

  • আন্দাজে নয়, মেপে। OpenTelemetry-নির্ভর instrumentation যেকোনো OTel backend-এর সাথে কাজ করে; একটি লাইনেই Pydantic Logfire চালু হয়, তাৎক্ষণিক ডিবাগিং, ট্রেসিং আর genai-prices-ভিত্তিক খরচ হিসাবের জন্য। Pydantic Evals চূড়ান্ত আউটপুট আর টুল-কলের ধারাবাহিকতা মূল্যায়ন করে, কোডে রাখা ডেটাসেটের ওপর, অথবা অনলাইন মূল্যায়ন দিয়ে প্রোডাকশনের আসল ট্রাফিকের একটি নমুনার ওপর।

  • সব সরঞ্জাম, জোড়া লাগানোর মতো করে। একটিই মৌলিক উপাদান, ক্যাপাবিলিটি, টুল, নির্দেশনা (instructions), hook আর মডেল সেটিংস-কে বারবার ব্যবহারযোগ্য একক হিসেবে বাঁধে। মূল প্যাকেজে আছে MCP আর ওয়েব সার্চের মতো মৌলিক জিনিস, Harness-এ আছে বাকি সব, আর Coder ও Researcher-এর মতো সম্পূর্ণ এজেন্টও শুধু ক্যাপাবিলিটি জোড়া লাগিয়ে তৈরি: যেভাবে জোড়া হয়েছে, সেভাবেই খোলা যায়। অথবা কোড ছাড়াই YAML/JSON agent spec দিয়ে লিখুন।

  • সব ইন্টারফেস। একটি এজেন্টের সংজ্ঞা চলে CLI, একটি built-in ওয়েব চ্যাট, বা রিয়েলটাইম কথোপকথন হিসেবে; UI ইভেন্ট স্ট্রিম (AG-UI, Vercel AI) একে আপনার নিজের ফ্রন্টএন্ড বা অন্য যেকোনো কিছুর সাথে যুক্ত করে; ACP একে editor এজেন্ট হিসেবে চালায়; আর GitHub Agentic Workflows একে issue, pull request বা সময়সূচিতে স্ক্রিন ছাড়া (headless) চালায়।

  • টেকসই এক্সিকিউশন। আটটি ইঞ্জিনে টেকসই এক্সিকিউশন: Temporal, DBOS, Prefect, Restate, AWS Lambda, Airflow, Absurd আর pgtask, এর প্রথম পাঁচটি সংশ্লিষ্ট কোম্পানির দলের সাথে যৌথভাবে রক্ষণাবেক্ষণ করা। এজেন্ট রিস্টার্টের পরেও টিকে থাকে আর আপনার ইতিমধ্যে চালানো ইঞ্জিনে দিনের পর দিন চলতে পারে, সাথে আছে মানুষের অনুমোদন (human-in-the-loop)।

  • অন্য framework থেকে আসছেন? তুলনাগুলো দেখায় LangChain, Google ADK, Claude Agent SDK আর আরও সাতটির থেকে Pydantic AI কোথায় আলাদা, আর migration skill দিয়ে আপনার কোডিং এজেন্ট একটি বিদ্যমান অ্যাপ্লিকেশন নিয়ে আসতে পারে।

Pydantic দলের তৈরি: Pydantic Validation হলো OpenAI SDK, Anthropic SDK, Google ADK, LangChain আর AI জগতের বেশিরভাগের যাচাই-স্তর (আর FastAPI যার ওপর তৈরি তার ভিত্তি)। Pydantic AI এজেন্টের জগতে সেই একই অনুভূতি নিয়ে আসে।

সব একসাথে: একটি ব্যাংকের গ্রাহকসেবা এজেন্ট¶

এখানে একটি ব্যাংকের গ্রাহকসেবা এজেন্ট, যা কয়েকটি সুবিধা একসাথে কাজ করতে দেখায়: dependency injection নির্দেশনা আর টুলে ডেটাবেস সংযোগ বহন করে, ফাংশন টুল যা মডেল ডাকে, প্রতিটি রানে যাচাই হওয়া গোছানো আউটপুট, গ্রাহকের প্রেক্ষাপট বাঁধা একটি বারবার ব্যবহারযোগ্য ক্যাপাবিলিটি, আর একটি চাহিদামতো ক্যাপাবিলিটি, যা মডেল শুধু কথোপকথনে দরকার হলে লোড করে:

bank_support.py
from dataclasses import dataclass

from pydantic import BaseModel, Field
from pydantic_ai import Agent, Capability, RunContext

from bank_database import DatabaseConn


@dataclass
class SupportDependencies:  # (1)!
    customer_id: int
    db: DatabaseConn  # (2)!


class SupportOutput(BaseModel):  # (3)!
    support_advice: str = Field(description='Advice returned to the customer')
    block_card: bool = Field(description="Whether to block the customer's card")
    risk: int = Field(description='Risk level of query', ge=0, le=10)


customer_context = Capability[SupportDependencies](  # (4)!
    id='customer-context',
    description="Who the customer is and what's on their account.",
)


@customer_context.instructions  # (5)!
async def add_customer_name(ctx: RunContext[SupportDependencies]) -> str:
    customer_name = await ctx.deps.db.customer_name(id=ctx.deps.customer_id)
    return f"The customer's name is {customer_name!r}"


@customer_context.tool  # (6)!
async def customer_balance(
    ctx: RunContext[SupportDependencies], include_pending: bool
) -> float:
    """Returns the customer's current account balance."""  # (7)!
    return await ctx.deps.db.customer_balance(
        id=ctx.deps.customer_id,
        include_pending=include_pending,
    )


refunds = Capability[SupportDependencies](  # (8)!
    id='refunds',
    description='Refund eligibility and refund status.',
    defer_loading=True,
)


@refunds.tool
async def refund_status(ctx: RunContext[SupportDependencies]) -> str:
    """Look up the refund status for the customer's most recent charge."""
    return await ctx.deps.db.refund_status(id=ctx.deps.customer_id)


support_agent = Agent(  # (9)!
    'openai:gpt-6.1-sol',  # (10)!
    deps_type=SupportDependencies,
    output_type=SupportOutput,  # (11)!
    instructions=(
        'You are a support agent in our bank, give the '
        'customer support and judge the risk level of their query.'
    ),
    capabilities=[customer_context, refunds],  # (12)!
)

  1. SupportDependencies dataclass দিয়ে সেই ডেটা, সংযোগ আর যুক্তি মডেলে পাঠানো হয়, যা নির্দেশনা আর টুল ফাংশন চালানোর সময় লাগবে। Pydantic AI-এর dependency injection ব্যবস্থা আপনার এজেন্টের আচরণ নিজের মতো করার একটি টাইপ-নিরাপদ উপায় দেয়, আর unit test ও eval চালানোর সময় বিশেষভাবে কাজে লাগে।
  2. উদাহরণটি ছোট আর পাঠযোগ্য রাখতে এটি একটি ডেটাবেস সংযোগের সরল খসড়া। বাস্তবে, গ্রাহকের তথ্য পেতে আপনি একটি বাইরের ডেটাবেসে (যেমন PostgreSQL) সংযোগ করবেন।
  3. এজেন্টের ফেরত দেওয়া গোছানো ডেটা সীমিত রাখতে এই Pydantic মডেল ব্যবহার হয়। এই সহজ সংজ্ঞা থেকেই Pydantic JSON Schema বানায়, যা LLM-কে বলে কীভাবে ডেটা ফেরত দিতে হবে, আর রানের শেষে ডেটা সঠিক কিনা তা নিশ্চিত করতে যাচাই করে।
  4. একটি Capability সম্পর্কিত নির্দেশনা আর টুলকে একটি বারবার ব্যবহারযোগ্য এককে বাঁধে: ওয়েব সার্চের মতো built-in ক্যাপাবিলিটি আর Harness-এর সবকিছুর পেছনে এই একই মৌলিক উপাদান। এটি গ্রাহকের প্রেক্ষাপট বহন করে; যেমন আছে তেমনই অন্য যেকোনো এজেন্টের capabilities তালিকায় বসিয়ে দিতে পারেন।
  5. গতিশীল নির্দেশনা dependency injection ব্যবহার করতে পারে। dependency আসে RunContext আর্গুমেন্টের মাধ্যমে, যা ওপরের deps_type দিয়ে প্যারামিটারযুক্ত। এখানের টাইপ annotation ভুল হলে static type checker তা ধরবে।
  6. tool decorator এমন একটি ফাংশন নথিভুক্ত করে, যার signature হয়ে যায় একটি টুল, যা উত্তর দেওয়ার সময় LLM ডাকতে পারে। আবারও, dependency আসে RunContext দিয়ে; বাকি যেকোনো আর্গুমেন্ট হয়ে যায় LLM-এ পাঠানো টুলের schema। এই আর্গুমেন্টগুলো যাচাইয়ে Pydantic ব্যবহার হয়, আর এরর LLM-এর কাছে ফেরত যায় যাতে সে আবার চেষ্টা করতে পারে।
  7. একটি টুলের docstring-ও টুলের বর্ণনা হিসেবে LLM-এ যায়। প্যারামিটারের বর্ণনা docstring থেকে বের করে LLM-এ পাঠানো প্যারামিটারের schema-য় যোগ করা হয়।
  8. defer_loading=True একে একটি চাহিদামতো ক্যাপাবিলিটি বানায়, একটি Agent Skill-এর মতো। prompt-এ এটি এক লাইনের একটি তালিকা-এন্ট্রিতে গুটিয়ে থাকে, আর এর টুলগুলো লুকানো থাকে যতক্ষণ না মডেল একে প্রাসঙ্গিক মনে করে framework-এর দেওয়া load_capability টুল দিয়ে লোড করে।
  9. এই এজেন্টটি একটি ব্যাংকে প্রথম স্তরের গ্রাহকসেবা দেবে। এজেন্ট কোন ধরনের dependency নেবে আর কোন ধরনের আউটপুট ফেরত দেবে, তাতে এটি generic। এক্ষেত্রে গ্রাহকসেবা এজেন্টের টাইপ Agent[SupportDependencies, SupportOutput]।
  10. এখানে আমরা এজেন্টটিকে একটি OpenAI মডেল ব্যবহার করতে কনফিগার করছি; এজেন্ট চালানোর সময়েও মডেল ঠিক করা যায়।
  11. এজেন্টের উত্তর নিশ্চিতভাবে একটি SupportOutput হবে। এজেন্টটি generic বলে, static type checking-এর সুবিধার জন্য এর টাইপও SupportOutput থাকবে। যাচাই ব্যর্থ হলে, এজেন্টকে আবার চেষ্টা করতে বলা হয়।
  12. এজেন্টে ক্যাপাবিলিটিগুলো লাগান। আরও ক্যাপাবিলিটি, যেমন ওয়েব সার্চ বা Harness-এর যেকোনো কিছু, একই তালিকায় পাশাপাশি বসে যায়।
  13. বাস্তব ব্যবহারে, এজেন্টের প্রেক্ষাপট আর সেবা বাড়াতে আপনি আরও টুল আর বড় নির্দেশনা যোগ করবেন।
  14. চূড়ান্ত উত্তরে না পৌঁছানো পর্যন্ত LLM-এর সাথে কথোপকথন চালিয়ে, এজেন্টটি asynchronous ভাবে চালান। এই মোটামুটি সহজ ক্ষেত্রেও, আউটপুট পেতে টুল ডাকার সাথে সাথে এজেন্ট LLM-এর সাথে কয়েকটি বার্তা আদান-প্রদান করবে।
  15. এই পালাটি চাহিদামতো ক্যাপাবিলিটি পরখ করে: মডেল refunds তালিকা-এন্ট্রি দেখে, id='refunds' দিয়ে load_capability ডাকে, আর তার পরেই উত্তর দেওয়ার জন্য refund_status টুলটি পায়: চাহিদামতো লোডিং কাজে।

কোডটি সহজ ভাষায়

ভাবুন ব্যাংকের একজন নতুন কর্মী। SupportDependencies হলো তাকে দেওয়া চাবির গোছা (কোন গ্রাহক, ডেটাবেসের সংযোগ)। টুলগুলো (customer_balance ইত্যাদি) হলো সে যে খাতাগুলো খুলে দেখতে পারে। SupportOutput হলো ব্যাংকের নির্দিষ্ট ফর্ম, যা দিয়েই তাকে উত্তর দিতে হবে। আর refunds ক্যাপাবিলিটি হলো একটি আলমারি, যা শুধু ফেরতের প্রশ্ন এলে খোলা হয়, যাতে সাধারণ কাজের সময় টেবিলে ভিড় না থাকে।

dependencies dataclass পূর্ণ টাইপ-নিরাপত্তাসহ ডেটাবেস সংযোগকে নির্দেশনা আর টুলে বহন করে: একটি পরীক্ষার নকল (test double) বসিয়ে দিলে একই এজেন্ট unit test আর eval-এ চলে। আর গ্রাহকের প্রেক্ষাপট যেহেতু একটি ক্যাপাবিলিটি, এটি জোড়া লাগানো যায়: একই একক কোনো পরিবর্তন ছাড়াই একটি ভয়েস এজেন্ট বা ওয়েব অ্যাপে বসে যায়।

সংক্ষেপের জন্য এখানের কোডটি অসম্পূর্ণ (DatabaseConn-এর সংজ্ঞা নেই); সম্পূর্ণ bank_support.py উদাহরণটি পাবেন এখানে।

Pydantic Logfire দিয়ে instrumentation¶

Pydantic AI OpenTelemetry-নির্ভর: Instrumentation ক্যাপাবিলিটি প্রতিটি মডেল কল আর টুল কলের জন্য মানক OTel span তৈরি করে, আর যেকোনো OTLP backend কাজ করে। সবচেয়ে সহজ সেটআপ হলো logfire SDK, যা সাধারণ OpenTelemetry বোঝে আর Pydantic Logfire বা অন্য যেকোনো backend-এ পাঠাতে পারে।

মাত্র কয়েকটি টুলওয়ালা একটি সহজ এজেন্টেও LLM-এর সাথে অনেক আদান-প্রদান হতে পারে, ফলে শুধু কোড পড়ে কী ঘটছে তা নিশ্চিত হওয়া প্রায় অসম্ভব। ওপরের রানগুলো চলতে দেখতে, Logfire সেটআপ করুন আর কোডে নিচেরটি যোগ করুন:

bank_support_with_logfire.py
...
from pydantic_ai import Agent, RunContext

from bank_database import DatabaseConn

import logfire

logfire.configure()  # (1)!
logfire.instrument_pydantic_ai()  # (2)!
logfire.instrument_sqlite3()  # (3)!

...

support_agent = Agent(
    'openai:gpt-6.1-sol',
    deps_type=SupportDependencies,
    output_type=SupportOutput,
    instructions=(
        'You are a support agent in our bank, give the '
        'customer support and judge the risk level of their query.'
    ),
    capabilities=[customer_context],
)
  1. Logfire SDK কনফিগার করুন; project সেটআপ না থাকলে এটি ব্যর্থ হবে।
  2. এটি এখন থেকে ব্যবহৃত সব Pydantic AI এজেন্টকে instrument করবে। শুধু একটি নির্দিষ্ট এজেন্ট instrument করতে, এজেন্টের capabilities=[...]-এ একটি Instrumentation এন্ট্রি যোগ করুন।
  3. আমাদের ডেমোতে, DatabaseConn একটি PostgreSQL ডেটাবেসে সংযোগ করতে sqlite3 ব্যবহার করে, তাই ডেটাবেসের query লগ করতে logfire.instrument_sqlite3() ব্যবহার হয়েছে।

এতেই আপনার এজেন্টকে কাজ করতে দেখার নিচের দৃশ্যটি পাওয়া যায়:

llms.txt¶

Pydantic AI ডকুমেন্টেশন llms.txt ফরম্যাটে পাওয়া যায়। এই ফরম্যাট Markdown-এ সংজ্ঞায়িত আর LLM, AI কোডিং সহকারী ও এজেন্টের জন্য উপযোগী।

দুটি ফরম্যাট পাওয়া যায়:

  • llms.txt: প্রজেক্টের একটি সংক্ষিপ্ত বর্ণনা আর ডকুমেন্টেশনের বিভিন্ন অংশের লিংকসহ একটি ফাইল। এই ফাইলের গঠন এখানে বিস্তারিত বর্ণিত।
  • llms-full.txt: llms.txt ফাইলের মতোই, তবে প্রতিটি লিংকের বিষয়বস্তু ভেতরে দেওয়া। মনে রাখুন, কিছু LLM-এর জন্য এই ফাইলটি খুব বড় হতে পারে।

আজ পর্যন্ত, IDE বা কোডিং এজেন্ট এই ফাইলগুলো নিজে থেকে কাজে লাগায় না, তবে আপনি লিংক বা পুরো লেখাটি দিলে সেগুলো ব্যবহার করবে।

পরের ধাপ¶

এখনই কিছু চালান। একটি কমান্ডেই আপনার টার্মিনালে একটি সম্পূর্ণ কোডিং এজেন্ট চলে আসে:

uvx --with pydantic-ai-harness clai -a pydantic_ai_harness.coder:coder_agent -m anthropic:claude-fable-5-1

অথবা Pydantic AI ইনস্টল করুন, একটি মডেল বেছে নিন (Pydantic AI Gateway হলো সবগুলোর জন্য একটি চাবি), আর আপনার নিজের কোডিং এজেন্টকে কাজে লাগান: হালনাগাদ framework জ্ঞান দিতে Pydantic AI skill ইনস্টল করুন, তাকে উদাহরণগুলো আর Harness সূচি দেখিয়ে দিন, তারপর বলুন আপনি কী বানাতে চান।

আপনার এজেন্ট কী করল দেখুন। একে instrument করুন: এক লাইনের সেটআপ, আর প্রতিটি মডেল কল ও টুল কল দেখা যায়। এটি মানক OpenTelemetry: Pydantic Logfire, যার একটি ফ্রি স্তর আছে (ক্রেডিট কার্ড লাগে না; শুধু একটি GitHub অ্যাকাউন্ট দিয়েই সাইন আপ), দেখার সবচেয়ে সহজ উপায়; তবে যেকোনো OTLP backend কাজ করে।

চালু করুন। প্রোডাকশনে যাওয়া সেই প্রশ্নগুলোর উত্তর দেয় যা দল একটি এজেন্ট চালুর আগে জিজ্ঞাসা করে: ক্র্যাশ থেকে উদ্ধার আর মানুষের অনুমোদন থেকে শুরু করে খরচের সীমা, ট্রেসিং আর deploy পর্যন্ত।

একটি রিপোজিটরিতে কাজে লাগান। সেই একই এজেন্ট, বা আপনার নিজের লেখা একটি, GitHub Agentic Workflow হিসেবে issue, pull request বা সময়সূচিতে চলে: স্ক্রিন ছাড়া, একটি sandbox-এ, নিরাপদ আউটপুটের মাধ্যমে লিখে।

আরও গভীরে যান। Agents গাইড হলো মূল পথনির্দেশ; API রেফারেন্স পুরো ইন্টারফেস বর্ণনা করে; Harness-এ আছে সব সরঞ্জাম।

সাহায্য নিন। Slack-এ যোগ দিন বা GitHub-এ একটি issue খুলুন।

Pydantic Stack-এর অংশ¶

প্রোডাকশন-মানের AI এজেন্ট চালু করতে আপনার যা যা দরকার:

  • Pydantic Validation: সবকিছুর নিচের যাচাই-স্তর
  • Pydantic AI Harness: অফিসিয়াল ক্যাপাবিলিটি লাইব্রেরি আর harness, একক ক্যাপাবিলিটি থেকে সম্পূর্ণ এজেন্ট পর্যন্ত
  • Pydantic Logfire: AI-কেন্দ্রিক, পুরো অ্যাপের পর্যবেক্ষণ
  • Pydantic AI Gateway: সব মডেলের জন্য একটি চাবি, খরচ পর্যবেক্ষণ আর খরচের সীমাসহ
  • Pydantic Evals: এজেন্টসহ যেকোনো Python ফাংশন মূল্যায়ন, চূড়ান্ত আউটপুট থেকে টুল-কলের ধারাবাহিকতা পর্যন্ত, ডেটাসেটে বা লাইভ ট্রাফিকে (Logfire-এ প্রোডাকশন eval সহ)
  • Pydantic Graph: টাইপসহ গ্রাফ নিয়ন্ত্রণ-প্রবাহ
  • genai-prices: মডেলের দামের তথ্য, হালনাগাদ রাখা
  • Monty: মডেলের লেখা কোডের জন্য একটি sandboxed Python interpreter

সংক্ষেপে মনে রাখুন

  • Pydantic AI = টাইপসহ এজেন্ট: Agent(model, output_type=..., deps_type=..., capabilities=[...]) আর @agent.tool।
  • মডেল বদলাতে শুধু স্ট্রিং বদলান; API key ছাড়া পরীক্ষায় Agent('test')।
  • টুলের আর্গুমেন্ট আর চূড়ান্ত আউটপুট দুটোই Pydantic দিয়ে যাচাই হয়; ভুল হলে মডেল আবার চেষ্টা করে।
  • কী ঘটছে দেখতে Logfire (বা যেকোনো OpenTelemetry backend)।
