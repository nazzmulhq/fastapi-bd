এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

Modal Sandbox¶

এই পেজে যা শিখবেন

  • আপনার মেশিনের বদলে একটি বিচ্ছিন্ন Modal cloud sandbox-এ এজেন্টের কমান্ড আর ফাইল সম্পাদনা চালানো।
  • একই sandbox-এ চালিয়ে যাওয়া, পরে আবার যুক্ত হওয়া, রানের আগে প্রস্তুত করা আর পরিষ্কার করা (sandbox নিজে থেকে বন্ধ হয় না!)।
  • কনফিগারেশন, durable execution, telemetry আর আগের version থেকে migrate।

আপনার মেশিনের বদলে একটি বিচ্ছিন্ন Modal cloud sandbox-এ আপনার এজেন্টের কমান্ড আর ফাইল সম্পাদনা চালান।

Source

Pydantic AI Harness 0.x release-এ থাকা অবস্থায়, minor release-এর মধ্যে API বদলাতে পারে; বদলালে, deprecation warning আর release-note-এর migration নির্দেশনা আপনাকে (বা আপনার এজেন্টকে) ঠিক কীভাবে আপগ্রেড করতে হবে তা বলে দেয়। দেখুন version policy।

ইনস্টল¶

pip install "pydantic-ai-harness[modal,anthropic]"

uv add "pydantic-ai-harness[modal,anthropic]"

modal token new

uv run modal token new

এটি আপনার Modal credential সংরক্ষণ করে; CI-তে, এর বদলে MODAL_TOKEN_ID আর MODAL_TOKEN_SECRET সেট করুন। anthropic extra আছে কারণ উদাহরণগুলো একটি Anthropic মডেল ব্যবহার করে; এটি আপনার মডেল provider-এর extra দিয়ে বদলান, আর উদাহরণের জন্য ANTHROPIC_API_KEY সেট করুন।

দ্রুত শুরু¶

from pydantic_ai import Agent
from pydantic_ai_harness.coder import Coder
from pydantic_ai_harness.modal_sandbox import ModalSandbox

agent = Agent('anthropic:claude-opus-5-5', capabilities=[ModalSandbox(), Coder()])
result = agent.run_sync('Clone https://github.com/pydantic/pydantic-ai and summarize how capabilities work.')

Coder-এর shell আর ফাইল টুল এখন আপনার মেশিনে নয়, sandbox-এ চলে। Coder-এর RepoContext রান শুরু হলে sandbox তৈরি করে; এর বদলে প্রথম টুল কলে তৈরি করতে Coder(repo_context=False) দিন। রান শেষ হওয়ার পরও sandbox চলতে থাকে, আর bill হতে থাকে; দেখুন Clean up।

একটি নতুন sandbox সর্বোচ্চ 24 ঘণ্টা বাঁচে, Modal-এর সর্বোচ্চ; এটি আগে শেষ করতে ModalSandbox(sandbox_timeout=3600) দিন। Modal একটি image তৈরি বা আনার সময় প্রথম ব্যবহারে কয়েক মিনিট লাগতে পারে। Modal sandbox চালু করতে না পারলে, যেমন image না থাকায়, প্রথম ব্যবহার কারণ বলা একটি error তোলে।

ডিফল্ট image root হিসেবে /root-এ চলে, home ডিরেক্টরি, Python 3.12, git আর rg-সহ, কিন্তু আপনার project-এর কোনো dependency নেই, এমনকি pytest-ও নয়। এগুলো একটি নিজস্ব image-এ ইনস্টল করুন, বা রানের আগে await workspace.run(['pip', 'install', ...]) দিয়ে, যেমন Prepare a sandbox before the run-এ। project home ডিরেক্টরির বাইরে রাখতে ModalSandbox(working_dir='/root/project') দিন; একটি নতুন sandbox এটি তৈরি করে। একটি নিজস্ব image এর নিজের working directory-তে কমান্ড শুরু করে।

সতর্কতা: খরচ

রান শেষ হলেও sandbox বন্ধ হয় না আর Modal bill করতে থাকে — ডিফল্টভাবে 24 ঘণ্টা পর্যন্ত! কাজ শেষে await ModalSandbox().destroy(result.workspace.ref) দিয়ে বন্ধ করুন, বা idle_timeout= দিন যাতে অব্যবহৃত sandbox আগে বন্ধ হয়। দেখুন Clean up।

একই sandbox-এ চালিয়ে যাওয়া¶

from pydantic_ai import Agent
from pydantic_ai_harness.coder import Coder
from pydantic_ai_harness.modal_sandbox import ModalSandbox

agent = Agent('anthropic:claude-opus-5-5', capabilities=[ModalSandbox(), Coder()])
result = agent.run_sync('Clone https://github.com/pydantic/pydantic-ai and summarize how capabilities work.')

followup = agent.run_sync(
    'Which capability would you add next, and where would it live?',
    message_history=result.all_messages(),
)

পরের রান message history-তে sandbox খুঁজে পায় আর এতে কাজ করে, তাই clone তখনও সেখানে থাকে। history ছাড়া, একটি রান একটি নতুন sandbox শুরু করে। sandbox বন্ধ বা মেয়াদোত্তীর্ণ হয়ে গেলে, রান একটি খালি sandbox-এ নতুন করে শুরু না করে WorkspaceUnavailableError তোলে।

টুল বাছাই¶

একটি সরু এজেন্টের জন্য, Coder-এর বদলে Shell আর FileSystem ব্যবহার করুন, বা sandbox-এ চলা নিজের টুল লিখুন:

from pydantic_ai import Agent, RunContext
from pydantic_ai_harness.filesystem import FileSystem
from pydantic_ai_harness.modal_sandbox import ModalSandbox
from pydantic_ai_harness.shell import Shell

agent = Agent('anthropic:claude-opus-5-5', capabilities=[ModalSandbox(), Shell(), FileSystem()])


@agent.tool
async def run_python(ctx: RunContext, code: str) -> str:
    """Run a Python snippet in the sandbox."""
    result = await ctx.workspace.run(['python', '-c', code], timeout=10)
    return result.stdout + result.stderr

আরও জানতে দেখুন Workspaces।

বাতিল আর কমান্ডের সময়সীমা sandbox শেষ না করে foreground কমান্ড থামানোর চেষ্টা করে; সর্বোত্তম-চেষ্টার সতর্কতার জন্য দেখুন What a timeout stops। Shell একটি 30-সেকেন্ডের timeout সেট করে; আপনার নিজের টুলে, ওপরের মতো একটি timeout দিন।

শুধু আপনার নিজের টুল sandbox ব্যবহার করলে, অনুপস্থিত-টুলের সতর্কবার্তা চুপ করাতে ModalSandbox(warn_if_no_tools=False) দিন, বা এর শ্রেণি ModalSandboxNoToolsWarning ছাঁকুন।

ফাইল পড়া FIFO, device আর নিয়মিত ফাইল নয় এমন যেকোনো কিছুর জন্য OSError তোলে, লোকাল backend যেমন করে।

একটি timeout কী থামায়¶

run(timeout=...) sandbox অর্জনের পরে এর ঘড়ি শুরু করে আর কমান্ড শুরু, চালানো আর আউটপুট সংগ্রহ অন্তর্ভুক্ত করে। এর সময়সীমায় বা বাতিলে, backend কমান্ডের foreground process group থামানোর চেষ্টা করে, ভাগ করা sandbox বা বিচ্ছিন্ন background job নয়। আংশিক stdout আর stderr WorkspaceTimeoutError-এ পাওয়া যায়; stop RPC ব্যর্থ হলে, কমান্ড হয়তো তবুও চলে, তাই স্পষ্ট পরিষ্কার-কাজের জন্য sandbox ref রাখুন। timeout=None-এর কোনো কমান্ড সময়সীমা নেই; sandbox-এর নিজস্ব আয়ু আর idle সেটিং তবুও প্রযোজ্য। util-linux-এর setsid ছাড়া একটি নিজস্ব বা যুক্ত image-এ, একটি সময়সীমা বা বাতিল শুধু wrapper process থামায়, কমান্ডের সন্তানদের নয়; সেগুলোও থামাতে image-এ util-linux ইনস্টল করুন।

পরে আবার যুক্ত হওয়া¶

message history ছাড়া sandbox-এ ফিরে আসতে, এর ref রেখে workspace= হিসেবে ফেরত দিন:

from pydantic_ai import Agent
from pydantic_ai_harness.coder import Coder
from pydantic_ai_harness.modal_sandbox import ModalSandbox

agent = Agent('anthropic:claude-opus-5-5', capabilities=[ModalSandbox(), Coder()])

result = agent.run_sync('Clone https://github.com/pydantic/pydantic-ai and summarize how capabilities work.')
ref = result.workspace.ref  # store this, e.g. in your database

later = agent.run_sync('Which capability would you add next, and where would it live?', workspace=ref)

ref কোনো credential রাখে না, তাই আবার যুক্ত হওয়া process-এরও আপনার Modal credential লাগে। message history একটির নাম দিলেও একটি নতুন sandbox শুরু করতে workspace='new' দিন।

image, app_name, create_app_if_missing, sandbox_timeout আর idle_timeout শুধু একটি নতুন sandbox গড়ে; working_dir আর env প্রতিটি কমান্ডে প্রযোজ্য, আবার যুক্ত হওয়ার পরেও।

আগে থেকেই একটি modal.Sandbox আছে? একটি রানে workspace=ModalSandboxBackend(sandbox=sandbox) দিন, pydantic_ai_harness.modal_sandbox থেকে ModalSandboxBackend-সহ। ModalSandbox-এর সেটিং এতে প্রযোজ্য নয়; backend-এ working_dir= আর env= দিন। workspace API কভার করে না এমন Modal সুবিধার জন্য একটি backend-এর get_sandbox() এর modal.Sandbox ফেরত দেয়; এখনও sandbox নেই এমন একটি backend-এ এটি একটি তৈরি করে, প্রথম কাজের মতো। এটি বদলায় না কে sandbox বন্ধ করে: যার হাতে ref, সে।

রানের আগে একটি sandbox প্রস্তুত করা¶

এজেন্ট শুরুর আগে ফাইল বসাতে বা প্যাকেজ ইনস্টল করতে, নিজে backend তৈরি করুন, Workspace দিয়ে এতে কাজ করুন, আর রানে দিন:

import asyncio

from pydantic_ai import Agent
from pydantic_ai.workspaces import Workspace
from pydantic_ai_harness.coder import Coder
from pydantic_ai_harness.modal_sandbox import ModalSandbox, ModalSandboxBackend

agent = Agent('anthropic:claude-opus-5-5', capabilities=[ModalSandbox(), Coder()])


async def main() -> None:
    backend = ModalSandboxBackend(working_dir='/root/project')
    try:
        workspace = Workspace(backend)
        await workspace.write_text('calc.py', 'def add(a, b):\n    return a - b\n')
        installed = await workspace.run(['pip', 'install', 'pytest'], timeout=300)
        if installed.exit_code != 0:
            raise RuntimeError(f'pip install failed: {installed.stderr}')
        result = await agent.run('Fix the bug in calc.py.', workspace=backend)
        print(result.output)
    finally:
        ref = backend.ref  # set once the sandbox exists
        if ref is not None:
            await ModalSandbox().destroy(ref)


if __name__ == '__main__':
    asyncio.run(main())

setup বা রান ব্যর্থ হলেও finally sandbox বন্ধ করে। Modal sandbox তৈরি করার সময় task বাতিল হলে, সেখানে backend.ref তখনও None, আর Modal যে sandbox তৈরি করতে থাকে তা চলতে থাকে; এর ID WARNING-এ log হয় (দেখুন Telemetry), তাই ModalSandbox().destroy(WorkspaceRef(provider='modal', id=...)) দিয়ে এটি বন্ধ করুন। এর বদলে এটি রাখতে, backend.ref রেখে পরে আবার যুক্ত হতে workspace= হিসেবে দিন।

পরিষ্কার¶

রান শেষ হওয়ার পরও sandbox চলতে থাকে, আর bill হতে থাকে। Pydantic AI কখনো এটি বন্ধ করে না। আপনার রাখা ref দিয়ে এটি বন্ধ করুন:

from pydantic_ai.workspaces import WorkspaceRef
from pydantic_ai_harness.modal_sandbox import ModalSandbox


async def terminate_sandbox(ref: WorkspaceRef) -> None:
    await ModalSandbox().destroy(ref)

ModalSandbox().backend(ref) I/O ছাড়াই একটি বিদ্যমান ref-এর জন্য একটি backend তৈরি করে। destroy(ref) sandbox ID সরাসরি ব্যবহার করে; এটি একটি মেয়াদোত্তীর্ণ sandbox আবার চালু করে না বা এর টুল চালায় না, আর আর নেই এমন একটি sandbox চুপচাপ ফেরত আসে। যে sandbox-এর image কমান্ড Modal-এর stop signal উপেক্ষা করে (যেমন একটি খালি python image), সেটি destroy ফেরত আসার পর প্রায় 30 সেকেন্ড চলতে পারে। শুধু আপনার মালিকানাধীন sandbox মুছুন।

যে sandbox আপনি বন্ধ করেন না তা শেষ হয় এর sandbox_timeout ফুরোলে, বা আপনি একটি সেট করলে idle_timeout সেকেন্ড কার্যকলাপ ছাড়া কাটার পর। দেখুন Modal's timeouts।

একটি ব্যর্থ রান কোনো ফল ফেরত দেয় না, তাই রাখার মতো কোনো ref নেই, আর after_run চলে না। Modal sandbox তৈরি করার সময় বাতিল হওয়া একটি রান কোনো hook-এর জন্য কোনো ref রেখে যায় না; দেখুন Telemetry। একটি ব্যর্থ রানের sandbox বন্ধ করতে, একটি on_run_error hook-এ পরিষ্কার করুন:

from typing import Any

from pydantic_ai import Agent, RunContext
from pydantic_ai.capabilities import Hooks
from pydantic_ai.run import AgentRunResult
from pydantic_ai_harness.coder import Coder
from pydantic_ai_harness.modal_sandbox import ModalSandbox

hooks = Hooks()


@hooks.on.run_error
async def terminate_failed_run(ctx: RunContext[None], *, error: BaseException) -> AgentRunResult[Any]:
    if ctx.workspace.ref is not None:
        await ModalSandbox().destroy(ctx.workspace.ref)
    raise error


agent = Agent('anthropic:claude-opus-5-5', capabilities=[ModalSandbox(), Coder(), hooks])

কনফিগারেশন¶

অপশন যা করে
image একটি নতুন sandbox-এর image: একটি registry tag বা একটি modal.Image। ডিফল্ট: Python 3.12, git আর ripgrep-সহ Debian slim।
app_name একটি নতুন sandbox যে Modal app-এর। ডিফল্ট: 'pydantic-ai-harness'।
create_app_if_missing সেই app না থাকলে তৈরি করা। ডিফল্ট: True।
sandbox_timeout Modal থামানোর আগে একটি নতুন sandbox কত সেকেন্ড বাঁচে (10-86,400)। ডিফল্ট: 86_400 (24 ঘণ্টা, Modal-এর সর্বোচ্চ)।
idle_timeout Modal একটি নতুন sandbox থামানোর আগে কার্যকলাপ ছাড়া কত সেকেন্ড। ডিফল্ট: None, কোনো idle সীমা নেই।
working_dir কমান্ড যে absolute ডিরেক্টরিতে শুরু হয় আর আপেক্ষিক path যার বিপরীতে মীমাংসা হয়। ডিফল্ট: ডিফল্ট image-এ /root, অন্যথায় image-এর নিজস্ব working directory। একটি নতুন sandbox-এ তৈরি হয়; একটি যুক্ত বা caller-দেওয়া sandbox-এ এটি আগে থেকেই থাকতে হবে।
env প্রতিটি কমান্ড যে environment variable পায়। ডিফল্ট: None। আপনার মেশিনের environment-এর কিছুই sandbox-এ পৌঁছায় না।
warn_if_no_tools এজেন্টের কোনো Shell বা FileSystem টুল না থাকলে সতর্ক করা। ডিফল্ট: True।

Modal শুধু asyncio event loop-এ চলে: এর SDK asyncio task ব্যবহার করে, তাই Trio-র অধীনে backend UserError তোলে।

sandbox আপনার মেশিন থেকে বিচ্ছিন্ন, নেটওয়ার্ক থেকে নয়: এতে বাইরের দিকে ইন্টারনেট প্রবেশ আছে, আর প্রতিটি env মান মডেল আর এটি যা চালায় তার সবকিছু পড়তে পারে, এটি clone করা একটি repository-র কোডসহ। secret env-এ রাখুন শুধু তখনই যখন এজেন্টের সেগুলো পাওয়া উচিত। Modal-এর block_network-এর মতো নেটওয়ার্ক বাধার জন্য, নিজে modal.Sandbox তৈরি করে workspace= হিসেবে ModalSandboxBackend(sandbox=...) দিন।

Durable execution¶

temporal extra-ও ইনস্টল করুন:

pip install "pydantic-ai-harness[modal,anthropic,temporal]"

uv add "pydantic-ai-harness[modal,anthropic,temporal]"

প্রথমে localhost:7233-এ একটি Temporal dev server চালান। activity নিবন্ধনের জন্য এজেন্ট আর workflow module স্তরে সংজ্ঞায়িত হতে হবে।

import asyncio
import uuid

from pydantic_ai import Agent
from pydantic_ai.durable_exec.temporal import PydanticAIPlugin, PydanticAIWorkflow, TemporalDurability
from pydantic_ai_harness.coder import Coder
from pydantic_ai_harness.modal_sandbox import ModalSandbox
from temporalio import workflow
from temporalio.client import Client
from temporalio.worker import Worker

agent = Agent(
    'anthropic:claude-opus-5-5',
    name='modal_coder',
    capabilities=[ModalSandbox(), Coder(), TemporalDurability()],
)


@workflow.defn
class SandboxWorkflow(PydanticAIWorkflow):
    __pydantic_ai_agents__ = [agent]

    @workflow.run
    async def run(self, prompt: str) -> str:
        return (await agent.run(prompt)).output


async def main() -> None:
    client = await Client.connect('localhost:7233', plugins=[PydanticAIPlugin()])
    async with Worker(client, task_queue='sandbox', workflows=[SandboxWorkflow]):
        print(
            await client.execute_workflow(
                SandboxWorkflow.run, 'Use the shell tool to run pwd.',
                id=f'sandbox-{uuid.uuid4()}', task_queue='sandbox',
            )
        )


if __name__ == '__main__':
    asyncio.run(main())

এই উদাহরণের বাইরে অলসভাবে তৈরি sandbox-এর জন্য, Coder(repo_context=False) ব্যবহার করুন; ডিফল্টভাবে Coder রান শুরুর সময় repository instructions পড়ে।

এটি ব্যবহার করা workflow চলমান থাকা অবস্থায় একটি capability সরালে তাদের replay history বদলে যায়। পরিবর্তন deploy করার আগে ওই workflow drain করুন বা Temporal worker versioning ব্যবহার করুন।

Telemetry¶

ModalSandbox নিজের কোনো span তৈরি করে না। Core-এর instrumentation এজেন্ট run span-এ sandbox লেখে pydantic_ai.workspace.provider আর pydantic_ai.workspace.id হিসেবে, আর একটি টুলের করা প্রতিটি কমান্ড বা ফাইল কাজ সেই tool call-এর span-এর ভেতরে চলে; রান শুরুর কাজ, যেমন RepoContext-এর repo instructions লোড, এজেন্ট run span-এ চলে। একটি sandbox তৈরি করলে pydantic_ai_harness.modal_sandbox._backend logger-এ INFO-তে এর ID log হয় (Created Modal sandbox <id>)। একটি নতুন sandbox-এর অপেক্ষায় থাকা প্রতিটি caller Modal এটি তৈরি শেষ করার আগে বাতিল হলে, কোনো পরিষ্কার-কাজ এর ref দেখে না, আর একই logger WARNING-এও এর ID log করে।

আগের ModalSandbox থেকে আপগ্রেড¶

আগের ModalSandbox নিজের run_command, read_file, write_file আর list_directory টুল নিবন্ধন করত আর রান শেষ হলে এর sandbox বন্ধ করত। এখন এটি শুধু sandbox দেয়, তাই ওপরে দেখানো মতো Coder(), বা Shell() আর FileSystem() যোগ করুন। পুরনো আর্গুমেন্ট এখনও তৈরি হয়, প্রতিস্থাপনের নাম দেওয়া একটি deprecation warning-সহ, আর উপেক্ষিত হয় (sandbox_id এখনও যুক্ত করে)। সরানো import প্রতিস্থাপনের নাম দেওয়া একটি error দিয়ে ব্যর্থ হয়। warning-গুলো pydantic_ai_harness থেকে HarnessDeprecationWarning ব্যবহার করে।

Lifecycle-এ কী বদলেছে¶

  • একটি রান আর sandbox বন্ধ করে না। আপনি বন্ধ না করা পর্যন্ত বা এর sandbox_timeout শেষ না করা পর্যন্ত এটি চলে (দেখুন Clean up)। Modal-কে একটি অব্যবহৃত sandbox আগে থামাতে idle_timeout= সেট করুন, বা কাজ শেষে await ModalSandbox().destroy(result.workspace.ref) ডাকুন।
  • sandbox_timeout-এর ডিফল্ট এখন 5 মিনিটের বদলে 24 ঘণ্টা, যাতে পরের একটি রান একই sandbox-এ চালিয়ে যেতে পারে।
  • একটি message_history চালিয়ে যাওয়া একটি রান আগের রানের sandbox-এ আবার যুক্ত হয়। একটি নতুনের জন্য workspace='new' দিন।
  • একটি মেয়াদোত্তীর্ণ বা বন্ধ sandbox-এ আবার যুক্ত হলে WorkspaceUnavailableError ওঠে। কোনো খালি প্রতিস্থাপন তৈরি হয় না। কমান্ডের মাঝে sandbox বন্ধ হওয়ায় একটি কমান্ড 137 দিয়ে বেরোলে, এটি একই error তোলে; একটি চলমান sandbox-এ একটি SIGKILL করা কমান্ড exit 137 ফেরত দেয়।

Migration টেবিল¶

আগের API এখন
রান শেষ হলে sandbox বন্ধ আর নয়: এর sandbox_timeout (ডিফল্ট 24 ঘণ্টা) এটি শেষ না করা পর্যন্ত চলে আর bill হয়। idle_timeout= সেট করুন, বা await ModalSandbox().destroy(result.workspace.ref) ডাকুন।
image, app_name, create_app_if_missing, env অপরিবর্তিত। image একটি modal.Image-ও নেয়, আর এর ডিফল্টে এখন git আর ripgrep আছে।
sandbox_timeout নাম অপরিবর্তিত। ডিফল্ট এখন 300-এর বদলে 86_400 (24 ঘণ্টা)।
workdir নাম বদলে working_dir। workdir= এখনও কাজ করে, একটি deprecation warning-সহ।
ডিফল্ট working directory ডিফল্ট image-এ /root, যেখানে পুরনো ডিফল্ট image (python:3.12-slim) /-এ কমান্ড শুরু করত। একটি নিজস্ব image এর নিজস্ব WORKDIR রাখে।
sandbox_id অবচিত; রানের নিজের কোনো ref না থাকলে এখনও সেই sandbox-এ যুক্ত করে, workspace='new'-সহও। agent.run(..., workspace=WorkspaceRef(provider='modal', id=sandbox_id)) ব্যবহার করুন।
session, ModalSandboxSession session অবচিত আর উপেক্ষিত; ModalSandboxSession সরানো। agent.run(..., workspace=ModalSandboxBackend(sandbox=<modal.Sandbox>)) ব্যবহার করুন।
default_command_timeout অবচিত আর উপেক্ষিত। Shell(default_timeout=...) ব্যবহার করুন।
max_command_timeout অবচিত আর উপেক্ষিত, কোনো সরাসরি সমতুল্য ছাড়া: মডেলের চাওয়া একটি timeout কিছুই সীমিত করে না। Shell(default_timeout=...) একটি না দেওয়া কমান্ডের timeout সেট করে; sandbox_timeout একটি নতুন sandbox-এর আয়ু সীমিত করে আর যুক্ত sandbox-এ প্রযোজ্য নয়।
max_output_bytes, max_output_lines অবচিত আর উপেক্ষিত। Shell(max_output_chars=...) বা ToolOutputLimits ব্যবহার করুন। যে কমান্ডের মিলিত stdout আর stderr 10 MiB পেরোয় তা থামানো হয় আর WorkspaceOutputLimitError তোলে।
max_read_bytes অবচিত আর উপেক্ষিত। FileSystem(max_read_lines=..., max_read_chars=...) ব্যবহার করুন।
instructions অবচিত আর উপেক্ষিত। এজেন্টের instructions ব্যবহার করুন।
run_command টুল সরানো। Shell() ব্যবহার করুন।
read_file, write_file, list_directory টুল সরানো। FileSystem() ব্যবহার করুন। এটি শুধু working directory আর এর নিচে পৌঁছায়; FileSystem(root_dir='/') পুরো sandbox-এ পৌঁছায়, পুরনো টুলগুলোর মতো। read_file-এর offset এখন শূন্য-ভিত্তিক: পুরনো টুল 1 থেকে লাইন গুনত।
Shell() বা FileSystem()-এর পাশে PrefixTools(ModalSandbox(...), prefix='modal') modal_* টুল চলে গেছে, আর prefix-ছাড়া Shell আর FileSystem টুল, যা আগে আপনার মেশিনে কাজ করত, এখন sandbox-এ চলে। PrefixTools বাদ দিন।
ModalSandboxExecResult সরানো। pydantic_ai.workspaces.CommandResult ব্যবহার করুন।
ModalSandboxError সরানো। pydantic_ai.workspaces.WorkspaceError ধরুন। এটি কভার করে না 10 মিনিটের মধ্যে শেষ না হওয়া sandbox তৈরি (TimeoutError), বা সংযোগ ব্যর্থতার মতো সাময়িক Modal error, যা অপরিবর্তিত প্রচারিত হয় যাতে একটি durable engine এগুলো retry করতে পারে। modal প্যাকেজ ছাড়া, pydantic_ai_harness.modal_sandbox import করলে ImportError ওঠে।
ModalSandboxTerminalError, ModalSandboxUnavailableError, ModalSandboxAuthError সরানো। pydantic_ai.workspaces.WorkspaceUnavailableError ধরুন।

Access to an isolated cloud sandbox powered by Modal.

Gives the agent tools to run commands and manage files inside a Modal sandbox, a place to execute untrusted or model-generated code without touching the host. By default each run gets a fresh sandbox created from image. When the run ends, the capability requests termination and waits for a bounded period; sandbox_timeout is the server-side cleanup backstop. To keep one sandbox across runs, either set sandbox_id to attach to a sandbox you manage elsewhere, or pass a session you own (an open ModalSandboxSession) so you control its lifetime and can read its sandbox_id. The capability never opens or terminates a session you pass.

Requires the modal extra (uv add "pydantic-ai-harness[modal]") and Modal credentials, configured as for the Modal CLI: run modal token new once, or set MODAL_TOKEN_ID / MODAL_TOKEN_SECRET in the environment.

from pydantic_ai import Agent
from pydantic_ai_harness.modal_sandbox import ModalSandbox

agent = Agent('anthropic:claude-sonnet-4-6', capabilities=[ModalSandbox()])
result = agent.run_sync('Write a Python script that prints the first 10 primes and run it.')
print(result.output)

default_command_timeout = 60.0

Default timeout in seconds for one run_command, used when the model omits one.

This bounds a single command; sandbox_timeout bounds the whole sandbox's lifetime. Modal enforces whole-second deadlines, so fractional values are rounded up (0.5 behaves as 1).

max_command_timeout class-attribute instance-attribute ¶

max_command_timeout = None

Hard ceiling in seconds for any single run_command, including a model-supplied timeout_seconds. None falls back to sandbox_timeout.

Modal has no per-command kill, so a cancelled command keeps running until its deadline; this caps how long that worst case can be. An owned command cannot outlive sandbox_timeout anyway, so the default ceiling is exact for owned sandboxes.

For an attached or injected sandbox the fallback is still sandbox_timeout, which is pinned to its default (300s) in those modes because the capability does not know the real lifetime of a sandbox it did not create. So every command there is capped at 300s unless you set max_command_timeout to the value the sandbox actually allows.

max_output_bytes class-attribute instance-attribute ¶

max_output_bytes = DEFAULT_MAX_BYTES

Maximum payload retained per command stream or file read, measured in UTF-8 bytes.

For commands the cap applies to stdout and stderr separately, both client-side (each stream retains at most this many bytes after Modal delivers each transport chunk) and in the tool output, so a large stderr cannot crowd out stdout. Labels, truncation notes, continuation offsets, timeouts, and exit codes add a small amount beyond this payload limit. Whichever of max_output_bytes and max_output_lines is reached first wins.

max_output_lines class-attribute instance-attribute ¶

max_output_lines = DEFAULT_MAX_LINES

Maximum payload lines retained per command stream or file read, alongside max_output_bytes.

A second cap so many short lines cannot pile up under the byte budget. Whichever cap is reached first wins. Labels and truncation or status notes can add lines beyond this payload limit. Both caps proxy a context budget; a future token-based cap would be additive.

max_read_bytes class-attribute instance-attribute ¶

max_read_bytes = _DEFAULT_MAX_READ_BYTES

Largest file read_file will read whole; larger files are refused with a hint to use shell tools.

Modal has no bounded file-read API. The tool checks metadata before reading and checks the returned byte count again, but a file that grows between those operations can briefly exceed this value in client memory before it is rejected.

def get_instructions(self) -> str | None:
    """Explain the sandbox to the model, unless overridden or disabled via `instructions`."""
    if self.instructions is not None:
        return self.instructions or None
    # A reused sandbox (attach or injected session) can carry files from earlier runs;
    # only a per-run owned sandbox starts clean each time.
    reused = self.sandbox_id is not None or self.session is not None
    template = _ATTACHED_INSTRUCTIONS if reused else _OWNED_INSTRUCTIONS
    # Report the deadline the toolset will actually apply (quantized and clamped, see
    # `ModalSandboxToolset._command_timeout`), so the numbers cannot contradict behavior.
    ceiling = self.max_command_timeout if self.max_command_timeout is not None else self.sandbox_timeout
    default_timeout = min(max(1, math.ceil(self.default_command_timeout)), ceiling)
    return template.format(default_timeout=default_timeout, max_timeout=ceiling)
