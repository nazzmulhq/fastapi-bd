OpenTelemetry¶

🌐 AI এবং মানুষের যৌথ অনুবাদ

এই অনুবাদটি মানুষের নির্দেশনায় AI দিয়ে করা হয়েছে। 🤝

এতে মূল অর্থ ভুল বোঝা বা অস্বাভাবিক শোনানোর মতো ভুল থাকতে পারে। 🤖

ইংরেজি সংস্করণ

আপনার API চলার সময় আপনি হয়তো জানতে চাইবেন এটি কতটা ট্রাফিক পাচ্ছে, কোন রিকোয়েস্টগুলো ধীর, এবং কখন এরর ঘটছে।

টেলিমেট্রি হলো আপনার অ্যাপ্লিকেশনের আচরণ সম্পর্কিত ডেটা যা আপনাকে এই প্রশ্নগুলোর উত্তর দিতে সাহায্য করে। প্রচলিত ধরনগুলো হলো:

  • মেট্রিক্স: এমন পরিমাপ যা সময়ের সাথে সারসংক্ষেপ করা যায়, যেমন রেসপন্স টাইম এবং সামলানো রিকোয়েস্টের সংখ্যা।
  • ট্রেস: প্রতিটি রিকোয়েস্ট এবং সেগুলো সামলাতে করা অপারেশনগুলোর রেকর্ড। প্রতিটি সময়-পরিমাপকৃত অপারেশনকে বলা হয় একটি span।
  • লগ: ইভেন্টের টাইমস্ট্যাম্পসহ রেকর্ড, যেমন একটি অ্যাপ্লিকেশন চালু হওয়া বা একটি অপারেশন ব্যর্থ হওয়া।

OpenTelemetry হলো টেলিমেট্রি সংগ্রহ করে একটি মনিটরিং সার্ভিসে পাঠানোর স্ট্যান্ডার্ড ও টুলের একটি সেট, যেখানে আপনি ড্যাশবোর্ডে সেগুলো ঘেঁটে দেখতে পারেন।

FastAPI ডিফল্টভাবে HTTP রিকোয়েস্টের ট্রেস, মেট্রিক্স ও লগের জন্য OpenTelemetry সাপোর্ট দেয়। WebSocket কানেকশনও ট্রেস ও লগ দেয়। সেই ডেটা দেখতে এটি গ্রহণ করার জন্য একটি মনিটরিং সার্ভিস কনফিগার করুন।

FastAPI ইনস্টল করুন¶

standard এক্সট্রাসহ FastAPI ইনস্টল করুন, যাতে টেলিমেট্রি পাঠানোর প্যাকেজগুলো আছে:

$ uv add "fastapi[standard]"
---> 100%

অ্যাপ তৈরি করুন¶

main.py নামে একটি ফাইল তৈরি করুন:

from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}

টেলিমেট্রি সংগ্রহ করতে আপনাকে কোনো কাস্টম কোড লিখতে হবে না।

FastAPI Cloud¶

আপনি যখন fastapi[standard]-সহ FastAPI Cloud-এ ডিপ্লয় করেন, তখন মেট্রিক্স স্বয়ংক্রিয়ভাবে কাজ করে। আপনাকে আর কিছু কনফিগার করতে হবে না।

Pro প্ল্যানে আপনি মেট্রিক্স ড্যাশবোর্ডে রিকোয়েস্টের সংখ্যা, এররের হার ও রেসপন্স টাইম দেখতে পারেন।

অন্যান্য মনিটরিং সার্ভিস¶

অন্য কোনো মনিটরিং সার্ভিসে টেলিমেট্রি পাঠাতে এমন একটি এন্ডপয়েন্ট কনফিগার করুন যা OTLP গ্রহণ করে, অর্থাৎ টেলিমেট্রি পাঠানোর জন্য OpenTelemetry প্রোটোকল। সার্ভিসটির HTTP/protobuf বেস এন্ডপয়েন্ট ব্যবহার করুন।

উদাহরণের URL-এর বদলে আপনার এন্ডপয়েন্ট দিয়ে এই এনভায়রনমেন্ট ভেরিয়েবলগুলো সেট করুন:

export FASTAPI_OTEL_AUTO_CONFIGURE=true
export OTEL_SERVICE_NAME=my-api
export OTEL_EXPORTER_OTLP_ENDPOINT=https://collector.example.com

FASTAPI_OTEL_AUTO_CONFIGURE=true FastAPI-এর স্বয়ংক্রিয় এক্সপোর্টার সেটআপ চালু করে। OTEL_SERVICE_NAME মনিটরিং সার্ভিসে আপনার অ্যাপ শনাক্ত করে। এন্ডপয়েন্টটি হলো ডেটা গ্রহণের বেস URL। ওই URL-এর অধীনে ট্রেস পাঠানো হয় /v1/traces-এ, মেট্রিক্স /v1/metrics-এ, এবং লগ /v1/logs-এ।

আপনার সার্ভিসে যদি অথেনটিকেশন লাগে, তাহলে এটি যে হেডারগুলো নির্দিষ্ট করে সেগুলো দিয়ে OTEL_EXPORTER_OTLP_HEADERS সেট করুন, যেমন api-key=YOUR_API_KEY।

অ্যাপ চালান¶

একই টার্মিনালে অ্যাপটি চালু করুন:

$ uv run fastapi run

আরেকটি টার্মিনালে একটি রিকোয়েস্ট পাঠান:

$ curl http://127.0.0.1:8000/items/1
{"item_id":1}

আপনার মনিটরিং সার্ভিস খুলে my-api খুঁজুন। পরবর্তী এক্সপোর্টের পরে আপনি একটি GET /items/{item_id} span-সহ একটি ট্রেস দেখতে পাবেন, সাথে রিকোয়েস্টের সংখ্যা, রেসপন্সের সময়কাল ও সক্রিয় রিকোয়েস্টের মেট্রিক্স।

টেলিমেট্রি কাস্টমাইজ করুন¶

প্রোভাইডার ও এক্সপোর্টার কনফিগার করুন¶

একটি প্রোভাইডার ট্রেস, মেট্রিক্স বা লগ রেকর্ড করার অবজেক্টগুলো সরবরাহ করে। এর কনফিগারেশন নিয়ন্ত্রণ করে সেই ডেটা কীভাবে প্রসেস ও এক্সপোর্ট হবে।

টেলিমেট্রি লাইব্রেরিগুলো OpenTelemetry-এর গ্লোবাল প্রোভাইডার কনফিগার করতে পারে। অ্যাপ চালু হওয়ার আগে লাইব্রেরিটি কনফিগার করুন, আর FastAPI স্বয়ংক্রিয়ভাবে ওই প্রোভাইডারগুলো ব্যবহার করবে।

ডিফল্টভাবে FastAPI কোনো এক্সপোর্টার যোগ না করেই কনফিগার করা প্রোভাইডারগুলো ব্যবহার করে। যখন স্বয়ংক্রিয় সেটআপ চালু থাকে এবং এনভায়রনমেন্টে একটি OTLP এন্ডপয়েন্ট সেট করা থাকে, তখন FastAPI প্রতিটি চালু প্রোভাইডারে ওই গন্তব্যের জন্য একটি এক্সপোর্টার যোগ করে। বিদ্যমান এক্সপোর্টারগুলো তাদের গন্তব্যে ডেটা পাঠাতে থাকে।

অন্য কোনো লাইব্রেরি যদি ইতিমধ্যে একই গন্তব্যে এক্সপোর্ট কনফিগার করে থাকে, তাহলে ডুপ্লিকেট টেলিমেট্রি এড়াতে FASTAPI_OTEL_AUTO_CONFIGURE সেট না করে রাখুন বা false সেট করুন।

আপনি telemetry ডিকশনারিতে সরাসরি একটি প্রোভাইডারও দিতে পারেন। যেমন, এই প্রোভাইডারটি আপনার টার্মিনালে রিকোয়েস্টের span প্রিন্ট করতে OpenTelemetry-এর কনসোল এক্সপোর্টার ব্যবহার করে:

from fastapi import FastAPI
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor, ConsoleSpanExporter

tracer_provider = TracerProvider()
tracer_provider.add_span_processor(BatchSpanProcessor(ConsoleSpanExporter()))

app = FastAPI(telemetry={"tracer_provider": tracer_provider})


@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}

এক্সপোর্টার span-গুলো তাদের গন্তব্যে পাঠায়। BatchSpanProcessor span-গুলো দলবদ্ধ করে ব্যাকগ্রাউন্ডে পাঠায়। আপনার মনিটরিং লাইব্রেরির গন্তব্য ব্যবহার করতে কনসোল এক্সপোর্টারটিকে সেটির সরবরাহ করা একটি এক্সপোর্টার দিয়ে বদলে দিন। আরও কনফিগারেশন অপশনের জন্য OpenTelemetry-এর Python ইনস্ট্রুমেন্টেশন গাইড দেখুন।

একটি মেট্রিক্স বা লগ প্রোভাইডার সরবরাহ করতে একই ডিকশনারিতে meter_provider বা logger_provider ব্যবহার করুন। যে অ্যাপ্লিকেশন বা লাইব্রেরি একটি প্রোভাইডার তৈরি করে, সেটিই তার বন্ধ হওয়া পরিচালনা করে। FastAPI তার যোগ করা এক্সপোর্ট কম্পোনেন্টগুলো পরিচালনা করে।

সতর্কতা

OpenTelemetry ডিফল্টভাবে গ্লোবাল প্রোভাইডার ব্যবহার করে। মাউন্ট করা সাব-অ্যাপ্লিকেশনের জন্য স্বাধীন টেলিমেট্রি কনফিগারেশন নিশ্চিত নয়।

রিকোয়েস্টের অপারেশন ট্রেস করুন¶

ডিফল্টভাবে রিকোয়েস্টের ট্রেসে ডিপেন্ডেন্সি সমাধান, আপনার পাথ অপারেশন ফাংশন চালানো, রেসপন্স সিরিয়ালাইজ করা, এবং FastAPI-এর BackgroundTasks-এর প্রতিটি টাস্ক চালানোর জন্য span থাকে। এই span-গুলো একই প্রোভাইডার ও এক্সপোর্টার ব্যবহার করে।

ব্যাকগ্রাউন্ড টাস্কের span-গুলো রিকোয়েস্টের ট্রেসেরই অংশ থাকে। এগুলো HTTP রেসপন্স span শেষ হওয়ার পরে চলে, তাই পরিমাপকৃত রেসপন্স টাইম বাড়ায় না।

কেবল HTTP রিকোয়েস্ট span রেকর্ড করতে operation_spans-কে False সেট করুন:

from fastapi import FastAPI

app = FastAPI(telemetry={"operation_spans": False})


@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}

WebSocket কানেকশন ট্রেস করুন¶

প্রতিটি WebSocket কানেকশনের একটি span থাকে, যেমন WS /ws/{room}, যা হ্যান্ডলার ও ডিপেন্ডেন্সি পরিষ্কার করা কাভার করে। এটি একই প্রোভাইডার ও সেটিংস ব্যবহার করে, ডিপেন্ডেন্সি সমাধান ও এন্ডপয়েন্ট এক্সিকিউশনের জন্য operation_spans-সহ।

HTTP রিকোয়েস্ট মেট্রিক্স কেবল HTTP রিকোয়েস্ট কাভার করে। 1000 বা 1001 কোডসহ স্বাভাবিক WebSocket বিচ্ছিন্নতা এরর লগ তৈরি করে না।

এরর পরীক্ষা করুন¶

FastAPI অসামলানো এক্সেপশনগুলোকে OpenTelemetry লগ হিসেবে রেকর্ড করে, রিকোয়েস্ট বা কানেকশনের ট্রেসের সাথে যুক্ত করে। ট্রেসটি স্যাম্পল না হলেও এরর লগ রেকর্ড হয়।

এক্সেপশন লগে এক্সেপশনের টাইপ, মেসেজ ও স্ট্যাক ট্রেস থাকে। মেসেজ ও স্ট্যাক ট্রেসে সংবেদনশীল তথ্য থাকতে পারে। সেগুলো ফিল্টার বা মুছে ফেলতে আপনার প্রোভাইডারের লগ প্রসেসর ব্যবহার করুন, অথবা এই লগগুলো বন্ধ করতে logs-কে False সেট করুন।

FastAPI রিকোয়েস্ট ভ্যালিডেশনের ব্যর্থতাগুলোও রাউট ও এররের সংখ্যাসহ সতর্কতা লগ হিসেবে রেকর্ড করে। এই লগগুলোতে অবৈধ ইনপুট থাকে না।

কী রেকর্ড করবেন তা বেছে নিন¶

telemetry ডিকশনারি এই সেটিংসগুলোও গ্রহণ করে:

সেটিং উদ্দেশ্য ডিফল্ট
tracing HTTP রিকোয়েস্ট ও WebSocket কানেকশনের span রেকর্ড করে True
metrics HTTP রিকোয়েস্ট মেট্রিক্স রেকর্ড করে True
logs ভ্যালিডেশন ব্যর্থতা ও অসামলানো এক্সেপশন রেকর্ড করে True
operation_spans রিকোয়েস্টের অপারেশনগুলোর জন্য span যোগ করে True
exclude ASGI scope পাওয়া একটি ফাংশন True রিটার্ন করলে রিকোয়েস্ট এড়িয়ে যায় None
auto_configure এনভায়রনমেন্ট ভেরিয়েবলে সেট করা এন্ডপয়েন্টের জন্য এক্সপোর্টার যোগ করে FASTAPI_OTEL_AUTO_CONFIGURE=true হলে True, অন্যথায় False

যেমন, হেলথ চেক বাদ দিয়ে মেট্রিক্স সংগ্রহ করতে:

from fastapi import FastAPI

app = FastAPI(
    telemetry={
        "tracing": False,
        "exclude": lambda scope: scope["path"] == "/health",
    }
)

telemetry ডিকশনারিতে একটি স্পষ্ট auto_configure ভ্যালু FASTAPI_OTEL_AUTO_CONFIGURE-কে ওভাররাইড করে। কোডে স্বয়ংক্রিয় সেটআপ চালু করতে telemetry={"auto_configure": True} ব্যবহার করুন, অথবা এনভায়রনমেন্ট ভেরিয়েবল চালু করে দিলেও একটি অ্যাপের জন্য এটি বন্ধ করতে telemetry={"auto_configure": False} ব্যবহার করুন।
