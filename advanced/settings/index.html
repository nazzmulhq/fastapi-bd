সেটিংস এবং এনভায়রনমেন্ট ভেরিয়েবল¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা শিখবেন

  • কেন গোপন কী, ডেটাবেস পাসওয়ার্ড ইত্যাদি কোডে না লিখে বাইরে রাখা হয়।
  • Pydantic BaseSettings দিয়ে এনভায়রনমেন্ট ভেরিয়েবল পড়া ও যাচাই করা।
  • ডিপেন্ডেন্সি হিসেবে সেটিংস দেওয়া, যাতে টেস্টে সহজে বদলানো যায়।
  • .env ফাইল থেকে সেটিংস পড়া আর @lru_cache দিয়ে একবারই পড়া।

অনেক ক্ষেত্রে আপনার অ্যাপ্লিকেশনের কিছু বাইরের সেটিংস বা কনফিগারেশন দরকার হতে পারে, যেমন গোপন কী (secret key), ডেটাবেসের লগইন তথ্য, ইমেইল সার্ভিসের লগইন তথ্য ইত্যাদি।

এই সেটিংসগুলোর বেশিরভাগই পরিবর্তনশীল (বদলাতে পারে), যেমন ডেটাবেসের URL। আর অনেকগুলো সংবেদনশীল হতে পারে, যেমন গোপন তথ্য।

এই কারণে এগুলো সাধারণত এনভায়রনমেন্ট ভেরিয়েবলে দেওয়া হয়, যা অ্যাপ্লিকেশন পড়ে নেয়।

একটি এনভায়রনমেন্ট ভেরিয়েবল (সংক্ষেপে env var) হলো এমন একটি মান যা Python কোডের বাইরে, অপারেটিং সিস্টেমে থাকে, আর আপনার অ্যাপ্লিকেশন ও অন্যান্য প্রোগ্রাম তা পড়তে পারে।

কোনো কমান্ড চালানোর সময় সেই কমান্ডের জন্য একটি এনভায়রনমেন্ট ভেরিয়েবল তৈরি করতে পারেন। প্ল্যাটফর্ম অনুযায়ী কমান্ডগুলো নিচে দেখবেন।

উদাহরণ দিয়ে বুঝি

একটি রেস্টুরেন্টের রেসিপি বই (আপনার কোড) সবাই দেখতে পারে, কিন্তু আলমারির চাবি (পাসওয়ার্ড) রেসিপি বইয়ে লিখে রাখা হয় না, ম্যানেজারের কাছে আলাদা থাকে। এনভায়রনমেন্ট ভেরিয়েবল হলো সেই আলাদা জায়গা: কোড GitHub-এ গেলেও গোপন তথ্য ফাঁস হয় না, আর একই কোড ভিন্ন সার্ভারে ভিন্ন সেটিংস নিয়ে চলতে পারে।

পরামর্শ

এনভায়রনমেন্ট ভেরিয়েবল কীভাবে কাজ করে তার বিস্তারিত ব্যাখ্যার জন্য এনভায়রনমেন্ট ভেরিয়েবল গাইড পড়ুন।

টাইপ এবং যাচাই¶

এই এনভায়রনমেন্ট ভেরিয়েবলগুলো শুধু টেক্সট স্ট্রিং রাখতে পারে, কারণ এগুলো Python-এর বাইরের জিনিস আর অন্যান্য প্রোগ্রাম ও পুরো সিস্টেমের সাথে (এমনকি Linux, Windows, macOS-এর মতো ভিন্ন অপারেটিং সিস্টেমের সাথেও) মানানসই হতে হয়।

এর মানে Python-এ এনভায়রনমেন্ট ভেরিয়েবল থেকে পড়া যেকোনো মান হবে একটি str, আর অন্য টাইপে রূপান্তর বা যেকোনো যাচাই কোডেই করতে হবে।

(যেমন ITEMS_PER_USER=50 পড়লে পাবেন "50" টেক্সট, সংখ্যা 50 নয়।)

Pydantic Settings¶

সৌভাগ্যক্রমে, এনভায়রনমেন্ট ভেরিয়েবল থেকে আসা এই সেটিংসগুলো সামলাতে Pydantic একটি দারুণ টুল দেয়: Pydantic: Settings management।

pydantic-settings ইনস্টল করুন¶

আপনার প্রজেক্টে pydantic-settings প্যাকেজ যোগ করুন:

$ uv add pydantic-settings
---> 100%

all extras ইনস্টল করলেও এটি সাথে চলে আসে:

$ uv add "fastapi[all]"
---> 100%

Settings অবজেক্ট তৈরি করুন¶

Pydantic থেকে BaseSettings ইমপোর্ট করে একটি সাব-ক্লাস তৈরি করুন, অনেকটা Pydantic মডেলের মতোই।

Pydantic মডেলের মতোই, আপনি টাইপ অ্যানোটেশনসহ ক্লাস অ্যাট্রিবিউট ঘোষণা করেন, চাইলে ডিফল্ট মানসহ।

Pydantic মডেলে যে যাচাইয়ের সুবিধা আর টুল ব্যবহার করেন, সবই এখানে ব্যবহার করতে পারেন, যেমন ভিন্ন ডেটা টাইপ আর Field() দিয়ে অতিরিক্ত যাচাই।

from fastapi import FastAPI
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    app_name: str = "Awesome API"
    admin_email: str
    items_per_user: int = 50


settings = Settings()
app = FastAPI()


@app.get("/info")
async def info():
    return {
        "app_name": settings.app_name,
        "admin_email": settings.admin_email,
        "items_per_user": settings.items_per_user,
    }

কোডটি সহজ ভাষায়

  • লাইন ২: pydantic_settings থেকে BaseSettings ইমপোর্ট।
  • লাইন ৫–৮: Settings ক্লাস। app_name-এর ডিফল্ট আছে, admin_email-এর ডিফল্ট নেই (তাই এটি বাধ্যতামূলক), items_per_user একটি int যার ডিফল্ট 50।
  • লাইন ১১: Settings() তৈরি করার মুহূর্তেই Pydantic এনভায়রনমেন্ট ভেরিয়েবল পড়ে, টাইপ রূপান্তর করে আর যাচাই করে। ADMIN_EMAIL সেট না থাকলে এখানেই এরর হবে।

পরামর্শ

দ্রুত কপি-পেস্ট করার মতো কিছু চাইলে এই উদাহরণটি ব্যবহার করবেন না, নিচের সর্বশেষটি ব্যবহার করুন।

তারপর যখন ওই Settings ক্লাসের একটি ইনস্ট্যান্স তৈরি করবেন (এখানে settings অবজেক্টে), Pydantic এনভায়রনমেন্ট ভেরিয়েবলগুলো বড়-ছোট হাতের অক্ষরের পার্থক্য না করে পড়বে। তাই বড় হাতের ভেরিয়েবল APP_NAME-ও app_name অ্যাট্রিবিউটের জন্য পড়া হবে।

এরপর এটি ডেটা রূপান্তর আর যাচাই করবে। তাই যখন ওই settings অবজেক্ট ব্যবহার করবেন, তখন আপনার ঘোষণা করা টাইপের ডেটা পাবেন (যেমন items_per_user হবে একটি int)।

settings ব্যবহার করুন¶

তারপর নতুন settings অবজেক্টটি আপনার অ্যাপ্লিকেশনে ব্যবহার করতে পারেন:

from pydantic_settings import BaseSettings

    admin_email: str
    items_per_user: int = 50

    }

সার্ভার চালান¶

এরপর কনফিগারেশনগুলো এনভায়রনমেন্ট ভেরিয়েবল হিসেবে দিয়ে সার্ভার চালাবেন, যেমন একটি ADMIN_EMAIL আর APP_NAME এভাবে সেট করতে পারেন:

Bash-এ একটি কমান্ডের জন্য একাধিক env var সেট করতে, সেগুলোকে স্পেস দিয়ে আলাদা করে সবগুলো কমান্ডের আগে বসান।

আর তখন admin_email সেটিং হবে "deadpool@example.com"।

app_name হবে "ChimichangApp"।

আর items_per_user তার ডিফল্ট মান 50-ই রাখবে।

অন্য মডিউলে সেটিংস¶

বড় অ্যাপ্লিকেশন - একাধিক ফাইল-এ যেমন দেখেছেন, এই সেটিংসগুলো অন্য একটি মডিউল ফাইলে রাখতে পারেন।

যেমন, আপনার একটি config.py ফাইল থাকতে পারে:

    admin_email: str
    items_per_user: int = 50

আর তারপর এটি main.py ফাইলে ব্যবহার করুন:

ডিপেন্ডেন্সিতে সেটিংস¶

কিছু ক্ষেত্রে সব জায়গায় ব্যবহৃত একটি গ্লোবাল settings অবজেক্ট রাখার বদলে একটি ডিপেন্ডেন্সি থেকে সেটিংস দেওয়া কাজে লাগতে পারে।

এটি বিশেষ করে টেস্টের সময় উপকারী, কারণ নিজের কাস্টম সেটিংস দিয়ে একটি ডিপেন্ডেন্সি ওভাররাইড করা খুবই সহজ।

মূল অ্যাপ ফাইল¶

এখন আমরা একটি ডিপেন্ডেন্সি তৈরি করি যা একটি নতুন config.Settings() ফেরত দেয়।

from functools import lru_cache
from typing import Annotated

from fastapi import Depends, FastAPI

from .config import Settings

app = FastAPI()


@lru_cache
def get_settings():
    return Settings()


@app.get("/info")
async def info(settings: Annotated[Settings, Depends(get_settings)]):
    return {
        "app_name": settings.app_name,
        "admin_email": settings.admin_email,
        "items_per_user": settings.items_per_user,
    }

সেটিংস এবং টেস্টিং¶

তারপর get_settings-এর জন্য একটি ডিপেন্ডেন্সি ওভাররাইড তৈরি করে টেস্টের সময় একটি ভিন্ন সেটিংস অবজেক্ট দেওয়া খুবই সহজ হবে:

from fastapi.testclient import TestClient

from .config import Settings
from .main import app, get_settings

client = TestClient(app)


def get_settings_override():
    return Settings(admin_email="testing_admin@example.com")


app.dependency_overrides[get_settings] = get_settings_override


def test_app():
    response = client.get("/info")
    data = response.json()
    assert data == {
        "app_name": "Awesome API",
        "admin_email": "testing_admin@example.com",
        "items_per_user": 50,
    }
🤓 অন্যান্য সংস্করণ ও ধরন

.env ফাইল পড়া¶

যদি আপনার অনেক সেটিংস থাকে যা হয়তো প্রায়ই বদলায়, হয়তো ভিন্ন ভিন্ন পরিবেশে (যেমন নিজের কম্পিউটার, টেস্ট সার্ভার, আসল সার্ভার), তাহলে এগুলো একটি ফাইলে রেখে সেখান থেকে এনভায়রনমেন্ট ভেরিয়েবলের মতো পড়া কাজে লাগতে পারে।

এই অভ্যাসটি এতটাই প্রচলিত যে এর একটি নাম আছে: এই এনভায়রনমেন্ট ভেরিয়েবলগুলো সাধারণত .env নামের একটি ফাইলে রাখা হয়, আর ফাইলটিকে বলা হয় "dotenv"।

পরামর্শ

ডট (.) দিয়ে শুরু হওয়া ফাইল Linux আর macOS-এর মতো Unix-ধাঁচের সিস্টেমে লুকানো ফাইল হয়।

তবে একটি dotenv ফাইলের নাম হুবহু এটাই হতে হবে এমন নয়।

একটি বাইরের লাইব্রেরি ব্যবহার করে Pydantic এই ধরনের ফাইল পড়া সাপোর্ট করে। আরও পড়ুন Pydantic Settings: Dotenv (.env) support-এ।

পরামর্শ

এটি কাজ করাতে uv add python-dotenv দিয়ে আপনার প্রজেক্টে python-dotenv যোগ করুন।

সাধারণ ভুল

.env ফাইলে সাধারণত পাসওয়ার্ড আর গোপন কী থাকে। তাই এটিকে .gitignore-এ যোগ করুন, যাতে ভুল করে GitHub-এ চলে না যায়।

আপনার একটি .env ফাইল থাকতে পারে এমন:

ADMIN_EMAIL="deadpool@example.com"
APP_NAME="ChimichangApp"

.env থেকে সেটিংস পড়া¶

আর তারপর আপনার config.py এভাবে আপডেট করুন:

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    app_name: str = "Awesome API"
    admin_email: str
    items_per_user: int = 50

    model_config = SettingsConfigDict(env_file=".env")
🤓 অন্যান্য সংস্করণ ও ধরন

পরামর্শ

সম্ভব হলে Annotated সংস্করণটি ব্যবহার করুন।

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    app_name: str = "Awesome API"
    admin_email: str
    items_per_user: int = 50

    model_config = SettingsConfigDict(env_file=".env")

পরামর্শ

model_config অ্যাট্রিবিউটটি শুধু Pydantic কনফিগারেশনের জন্য ব্যবহার হয়। আরও পড়ুন Pydantic: Concepts: Configuration-এ।

এখানে আমরা আপনার Pydantic Settings ক্লাসের ভেতরে env_file কনফিগ সংজ্ঞায়িত করি, আর এর মান হিসেবে যে dotenv ফাইল ব্যবহার করতে চাই তার নাম দিই।

lru_cache দিয়ে Settings শুধু একবার তৈরি করা¶

ডিস্ক থেকে ফাইল পড়া সাধারণত একটি খরচসাপেক্ষ (ধীর) কাজ, তাই আপনি সম্ভবত এটি শুধু একবার করে একই সেটিংস অবজেক্ট বারবার ব্যবহার করতে চাইবেন, প্রতিটি রিকোয়েস্টে পড়ার বদলে।

কিন্তু যতবারই আমরা লিখি:

Settings()

একটি নতুন Settings অবজেক্ট তৈরি হবে, আর তৈরির সময় এটি আবার .env ফাইল পড়বে।

যদি ডিপেন্ডেন্সি ফাংশনটি শুধু এমন হতো:

def get_settings():
    return Settings()

তাহলে আমরা প্রতিটি রিকোয়েস্টে ওই অবজেক্ট তৈরি করতাম, আর প্রতিটি রিকোয়েস্টে .env ফাইল পড়তাম। ⚠️

কিন্তু যেহেতু আমরা ওপরে @lru_cache ডেকোরেটর ব্যবহার করছি, তাই Settings অবজেক্ট শুধু একবারই তৈরি হবে, প্রথমবার কল করার সময়। ✔️

from functools import lru_cache
from typing import Annotated

from fastapi import Depends, FastAPI

from . import config

app = FastAPI()


@lru_cache
def get_settings():
    return config.Settings()


@app.get("/info")
async def info(settings: Annotated[config.Settings, Depends(get_settings)]):
    return {
        "app_name": settings.app_name,
        "admin_email": settings.admin_email,
        "items_per_user": settings.items_per_user,
    }
🤓 অন্যান্য সংস্করণ ও ধরন

পরামর্শ

সম্ভব হলে Annotated সংস্করণটি ব্যবহার করুন।

from functools import lru_cache

from fastapi import Depends, FastAPI

from . import config

app = FastAPI()


@lru_cache
def get_settings():
    return config.Settings()


@app.get("/info")
async def info(settings: config.Settings = Depends(get_settings)):
    return {
        "app_name": settings.app_name,
        "admin_email": settings.admin_email,
        "items_per_user": settings.items_per_user,
    }

তারপর পরের রিকোয়েস্টগুলোর ডিপেন্ডেন্সিতে get_settings()-এর যেকোনো পরবর্তী কলে, get_settings()-এর ভেতরের কোড চালিয়ে নতুন Settings অবজেক্ট তৈরির বদলে, এটি প্রথম কলে ফেরত দেওয়া একই অবজেক্ট বারবার ফেরত দেবে।

উদাহরণ দিয়ে বুঝি

ধরুন প্রতিদিন সকালে কেউ আপনাকে বাসার Wi-Fi পাসওয়ার্ড জিজ্ঞেস করে। প্রতিবার রাউটারের নিচে উঁকি দিয়ে পড়ার বদলে আপনি প্রথমবার পড়ে মনে রেখে দিলেন, তারপর থেকে মুখস্থ বলে দেন। @lru_cache ঠিক এই "মনে রাখা"র কাজটি করে।

lru_cache কারিগরি বিবরণ¶

@lru_cache যে ফাংশনকে ডেকোরেট করে সেটিকে এমনভাবে বদলে দেয় যাতে প্রতিবার ফাংশনের কোড চালিয়ে আবার হিসাব না করে, প্রথমবার ফেরত দেওয়া একই মান ফেরত দেয়।

তাই নিচের ফাংশনটি আর্গুমেন্টের প্রতিটি সমন্বয়ের জন্য একবার করে চলবে। তারপর আর্গুমেন্টের প্রতিটি সমন্বয়ের জন্য ফেরত দেওয়া মানগুলো বারবার ব্যবহার হবে, যখনই ফাংশনটি হুবহু একই আর্গুমেন্ট সমন্বয় দিয়ে কল হবে।

যেমন, যদি আপনার একটি ফাংশন থাকে:

@lru_cache
def say_hi(name: str, salutation: str = "Ms."):
    return f"Hello {salutation} {name}"

আমাদের ডিপেন্ডেন্সি get_settings()-এর ক্ষেত্রে, ফাংশনটি কোনো আর্গুমেন্টই নেয় না, তাই এটি সবসময় একই মান ফেরত দেয়।

এভাবে, এটি প্রায় একটি গ্লোবাল ভেরিয়েবলের মতোই আচরণ করে। কিন্তু যেহেতু এটি একটি ডিপেন্ডেন্সি ফাংশন ব্যবহার করে, তাই টেস্টের জন্য আমরা সহজেই এটি ওভাররাইড করতে পারি।

@lru_cache হলো functools-এর অংশ, যা Python-এর স্ট্যান্ডার্ড লাইব্রেরির অংশ। আরও পড়ুন @lru_cache-এর জন্য Python ডকুমেন্টেশনে।

সংক্ষেপে¶

Pydantic Settings ব্যবহার করে আপনার অ্যাপ্লিকেশনের সেটিংস বা কনফিগারেশন সামলাতে পারেন, Pydantic মডেলের পুরো ক্ষমতাসহ।

  • একটি ডিপেন্ডেন্সি ব্যবহার করে টেস্টিং সহজ করতে পারেন।
  • এর সাথে .env ফাইল ব্যবহার করতে পারেন।
  • @lru_cache ব্যবহার করলে প্রতিটি রিকোয়েস্টে বারবার dotenv ফাইল পড়া এড়ানো যায়, আবার টেস্টের সময় ওভাররাইড করার সুযোগও থাকে।

সংক্ষেপে মনে রাখুন

  • গোপন ও পরিবর্তনশীল তথ্য কোডে নয়, এনভায়রনমেন্ট ভেরিয়েবল বা .env ফাইলে রাখুন (আর .env গিটে দেবেন না)।
  • class Settings(BaseSettings) লিখে টাইপসহ সেটিংস ঘোষণা করুন, Pydantic নিজেই পড়বে ও যাচাই করবে।
  • @lru_cache + get_settings() ডিপেন্ডেন্সি = একবার পড়া, বারবার ব্যবহার, আর টেস্টে সহজে বদলানো।
