প্রক্সির পেছনে¶

🌐 সহজ বাংলায় ব্যাখ্যাসহ সংস্করণ

এটি শুধু অনুবাদ নয়: প্রতিটি পেজে সহজ ভাষায় ব্যাখ্যা, বাস্তব জীবনের উদাহরণ, কোডের লাইন-ধরে-ধরে ব্যাখ্যা, সাধারণ ভুল আর শেষে সারসংক্ষেপ যোগ করা হয়েছে। 🤝

কোড, প্যারামিটারের নাম আর কমান্ড ইংরেজিতেই রাখা হয়েছে, কারণ এগুলো ঠিক এভাবেই লিখতে হয়। অচেনা শব্দের মানে জানতে মেনুর "শিখুন" অংশে "সহজ শব্দকোষ" পেজটি দেখুন।

এটি মানুষের নির্দেশনায় AI দিয়ে তৈরি, তাই কোথাও ভুল থাকতে পারে। সন্দেহ হলে মূল ইংরেজি সংস্করণ মিলিয়ে নিন। 🤖

ইংরেজি সংস্করণ

এই পেজে যা শিখবেন

  • প্রক্সি (Nginx, Traefik) কী, আর এর পেছনে FastAPI চালালে কী কী সমস্যা হতে পারে।
  • X-Forwarded-* হেডার আর --forwarded-allow-ips দিয়ে সঠিক HTTPS ঠিকানায় রিডাইরেক্ট।
  • প্রক্সি যখন পাথের শুরুতে /api/v1 এর মতো prefix যোগ করে, তখন root_path দিয়ে ডকুমেন্টেশন ঠিক রাখা।
  • Traefik দিয়ে নিজের কম্পিউটারে পুরো ব্যাপারটি পরীক্ষা করা।

অনেক পরিস্থিতিতে আপনি আপনার FastAPI অ্যাপের সামনে Traefik বা Nginx-এর মতো একটি প্রক্সি ব্যবহার করবেন।

এই প্রক্সিগুলো HTTPS সার্টিফিকেট আর অন্যান্য কাজ সামলাতে পারে।

প্রক্সি সহজ ভাষায়

প্রক্সি হলো অফিসের অভ্যর্থনা ডেস্কের মতো। বাইরের সবাই (ব্রাউজার) প্রথমে অভ্যর্থনায় আসে, তারা পরিচয় যাচাই করে (HTTPS), তারপর ভেতরের সঠিক বিভাগে (আপনার FastAPI অ্যাপ) পাঠিয়ে দেয়। সমস্যা হলো, ভেতরের বিভাগ সরাসরি অতিথিকে দেখে না, শুধু অভ্যর্থনা ডেস্ককে দেখে। তাই অতিথি কোন দরজা দিয়ে এসেছিল (HTTPS নাকি HTTP, কোন ঠিকানা), সেটি অভ্যর্থনাকে আলাদা করে জানিয়ে দিতে হয়।

প্রক্সি ফরোয়ার্ডেড হেডার¶

আপনার অ্যাপ্লিকেশনের সামনের একটি প্রক্সি সাধারণত আপনার সার্ভারে রিকোয়েস্ট পাঠানোর আগে তাৎক্ষণিকভাবে কিছু হেডার সেট করে, যাতে সার্ভার জানে যে রিকোয়েস্টটি প্রক্সি ফরোয়ার্ড করেছে, আর জানতে পারে মূল (পাবলিক) URL, ডোমেইনসহ, যে এটি HTTPS ব্যবহার করছে, ইত্যাদি।

সার্ভার প্রোগ্রাম (যেমন FastAPI CLI-এর মাধ্যমে Uvicorn) এই হেডারগুলো বুঝতে আর তারপর সেই তথ্য আপনার অ্যাপ্লিকেশনে পাঠাতে সক্ষম।

কিন্তু নিরাপত্তার জন্য, যেহেতু সার্ভার জানে না যে এটি একটি বিশ্বস্ত প্রক্সির পেছনে আছে, তাই এটি ওই হেডারগুলো বুঝবে না। (নইলে যে কেউ নকল হেডার পাঠিয়ে নিজের IP লুকাতে পারত।)

কারিগরি বিবরণ

প্রক্সি হেডারগুলো হলো:

  • X-Forwarded-For
  • X-Forwarded-Proto
  • X-Forwarded-Host

প্রক্সি ফরোয়ার্ডেড হেডার চালু করুন¶

CLI অপশন --forwarded-allow-ips দিয়ে FastAPI CLI চালু করতে পারেন, আর যে IP ঠিকানাগুলোকে ওই ফরোয়ার্ডেড হেডার পড়ার জন্য বিশ্বাস করা উচিত সেগুলো দিতে পারেন।

এটি --forwarded-allow-ips="*" সেট করলে এটি সব আসা IP-কে বিশ্বাস করবে।

আপনার সার্ভার যদি একটি বিশ্বস্ত প্রক্সির পেছনে থাকে আর শুধু প্রক্সিই এর সাথে কথা বলে, তাহলে এতে ওই প্রক্সির IP যাই হোক, এটি তা গ্রহণ করবে।

$ uv run fastapi run --forwarded-allow-ips="*"

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

HTTPS-সহ রিডাইরেক্ট¶

যেমন, ধরা যাক আপনি একটি পাথ অপারেশন /items/ সংজ্ঞায়িত করলেন:

from fastapi import FastAPI

app = FastAPI()


@app.get("/items/")
def read_items():
    return ["plumbus", "portal gun"]

ক্লায়েন্ট যদি /items-এ (শেষে স্ল্যাশ ছাড়া) যাওয়ার চেষ্টা করে, তাহলে ডিফল্টভাবে তাকে /items/-এ রিডাইরেক্ট করা হবে।

কিন্তু CLI অপশন --forwarded-allow-ips সেট করার আগে এটি হয়তো http://localhost:8000/items/-এ রিডাইরেক্ট করত।

কিন্তু হয়তো আপনার অ্যাপ্লিকেশন হোস্ট করা আছে https://mysuperapp.com-এ, আর রিডাইরেকশন হওয়া উচিত https://mysuperapp.com/items/-এ।

--proxy-headers সেট করায় এখন FastAPI সঠিক জায়গায় রিডাইরেক্ট করতে পারবে। 😎

https://mysuperapp.com/items/

পরামর্শ

HTTPS সম্পর্কে আরও জানতে চাইলে HTTPS সম্পর্কে গাইডটি দেখুন।

প্রক্সি ফরোয়ার্ডেড হেডার কীভাবে কাজ করে¶

ক্লায়েন্ট আর অ্যাপ্লিকেশন সার্ভারের মাঝখানে প্রক্সি কীভাবে ফরোয়ার্ডেড হেডার যোগ করে, তার একটি চিত্র:

sequenceDiagram
    participant Client
    participant Proxy as Proxy/Load Balancer
    participant Server as FastAPI Server

    Client->>Proxy: HTTPS Request<br/>Host: mysuperapp.com<br/>Path: /items

    Note over Proxy: Proxy adds forwarded headers

    Proxy->>Server: HTTP Request<br/>X-Forwarded-For: [client IP]<br/>X-Forwarded-Proto: https<br/>X-Forwarded-Host: mysuperapp.com<br/>Path: /items

    Note over Server: Server interprets headers<br/>(if --forwarded-allow-ips is set)

    Server->>Proxy: HTTP Response<br/>with correct HTTPS URLs

    Proxy->>Client: HTTPS Response

প্রক্সি মূল ক্লায়েন্ট রিকোয়েস্টটি মাঝপথে ধরে, আর অ্যাপ্লিকেশন সার্ভারে রিকোয়েস্ট পাঠানোর আগে বিশেষ ফরোয়ার্ডেড হেডারগুলো (X-Forwarded-*) যোগ করে।

এই হেডারগুলো মূল রিকোয়েস্টের এমন তথ্য সংরক্ষণ করে, যা নইলে হারিয়ে যেত:

  • X-Forwarded-For: মূল ক্লায়েন্টের IP ঠিকানা
  • X-Forwarded-Proto: মূল প্রোটোকল (https)
  • X-Forwarded-Host: মূল হোস্ট (mysuperapp.com)

FastAPI CLI --forwarded-allow-ips দিয়ে কনফিগার করা থাকলে এটি এই হেডারগুলো বিশ্বাস করে আর ব্যবহার করে, যেমন রিডাইরেক্টে সঠিক URL তৈরি করতে।

পাথ prefix কেটে ফেলা প্রক্সি¶

আপনার এমন একটি প্রক্সি থাকতে পারে, যা আপনার অ্যাপ্লিকেশনে একটি পাথ prefix যোগ করে।

এসব ক্ষেত্রে আপনার অ্যাপ্লিকেশন কনফিগার করতে root_path ব্যবহার করতে পারেন।

root_path হলো ASGI স্পেসিফিকেশনের দেওয়া একটি ব্যবস্থা (যার ওপর FastAPI তৈরি, Starlette-এর মাধ্যমে)।

root_path এই নির্দিষ্ট ক্ষেত্রগুলো সামলাতে ব্যবহার হয়।

আর সাব-অ্যাপ্লিকেশন mount করার সময় এটি ভেতরেও ব্যবহার হয়।

এই ক্ষেত্রে পাথ prefix কেটে ফেলা প্রক্সি থাকার মানে, আপনি কোডে /app-এ একটি পাথ ঘোষণা করতে পারেন, কিন্তু তারপর ওপরে একটি স্তর (প্রক্সি) যোগ করেন, যা আপনার FastAPI অ্যাপ্লিকেশনকে /api/v1-এর মতো একটি পাথের অধীনে রাখে।

এই ক্ষেত্রে মূল পাথ /app আসলে সার্ভ হবে /api/v1/app-এ।

যদিও আপনার সব কোড এমনভাবে লেখা যেন শুধু /app আছে।

from fastapi import FastAPI, Request

app = FastAPI()


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

আর প্রক্সি অ্যাপ সার্ভারে (সম্ভবত FastAPI CLI-এর মাধ্যমে Uvicorn) রিকোয়েস্ট পাঠানোর আগে তাৎক্ষণিকভাবে পাথ prefix-টি "কেটে ফেলবে", আপনার অ্যাপ্লিকেশনকে এই বিশ্বাসে রেখে যে এটি /app-এ সার্ভ হচ্ছে, যাতে আপনার সব কোডে /api/v1 prefix যোগ করতে না হয়।

এ পর্যন্ত সবকিছু স্বাভাবিকভাবে কাজ করবে।

কিন্তু তারপর, আপনি যখন একীভূত ডকুমেন্টেশন UI (ফ্রন্টএন্ড) খুলবেন, এটি /api/v1/openapi.json-এর বদলে /openapi.json-এ OpenAPI স্কিমা পাওয়ার আশা করবে।

তাই ফ্রন্টএন্ড (যা ব্রাউজারে চলে) /openapi.json-এ পৌঁছানোর চেষ্টা করবে আর OpenAPI স্কিমা পাবে না।

যেহেতু আমাদের অ্যাপের জন্য /api/v1 পাথ prefix-সহ একটি প্রক্সি আছে, তাই ফ্রন্টএন্ডকে OpenAPI স্কিমা আনতে হবে /api/v1/openapi.json থেকে।

পরামর্শ

IP 0.0.0.0 সাধারণত বোঝাতে ব্যবহার হয় যে প্রোগ্রামটি ওই মেশিন/সার্ভারে উপলব্ধ সব IP-তে শুনছে।

ডকুমেন্টেশন UI-এরও দরকার হবে OpenAPI স্কিমা ঘোষণা করুক যে এই API server-টি /api/v1-এ আছে (প্রক্সির পেছনে)। যেমন:

{
    "openapi": "3.1.0",
    // More stuff here
    "servers": [
        {
            "url": "/api/v1"
        }
    ],
    "paths": {
            // More stuff here
    }
}

এই উদাহরণে "প্রক্সি" হতে পারে Traefik-এর মতো কিছু। আর সার্ভার হতে পারে Uvicorn-সহ FastAPI CLI-এর মতো কিছু, যা আপনার FastAPI অ্যাপ্লিকেশন চালাচ্ছে।

root_path দেওয়া¶

এটি অর্জন করতে কমান্ড লাইন অপশন --root-path ব্যবহার করতে পারেন, এভাবে:

$ uv run fastapi run main.py --forwarded-allow-ips="*" --root-path /api/v1

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

আপনি যদি Hypercorn ব্যবহার করেন, তাতেও --root-path অপশন আছে।

কারিগরি বিবরণ

ASGI স্পেসিফিকেশন এই ব্যবহারের ক্ষেত্রের জন্য একটি root_path সংজ্ঞায়িত করে।

আর --root-path কমান্ড লাইন অপশনটি সেই root_path দেয়।

বর্তমান root_path দেখা¶

প্রতিটি রিকোয়েস্টে আপনার অ্যাপ্লিকেশনের ব্যবহৃত বর্তমান root_path পেতে পারেন, এটি scope ডিকশনারির অংশ (যা ASGI স্পেসিফিকেশনের অংশ)।

এখানে শুধু দেখানোর উদ্দেশ্যে আমরা এটি বার্তায় অন্তর্ভুক্ত করছি।

from fastapi import FastAPI, Request

app = FastAPI()


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

তারপর, যদি Uvicorn এভাবে চালু করেন:

$ uv run fastapi run main.py --forwarded-allow-ips="*" --root-path /api/v1

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

রেসপন্স হবে এরকম কিছু:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

FastAPI অ্যাপে root_path সেট করা¶

বিকল্পভাবে, --root-path বা সমতুল্য কোনো কমান্ড লাইন অপশন দেওয়ার উপায় না থাকলে, আপনার FastAPI অ্যাপ তৈরির সময় root_path প্যারামিটার সেট করতে পারেন:

from fastapi import FastAPI, Request

app = FastAPI(root_path="/api/v1")


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

FastAPI-তে root_path দেওয়া আর Uvicorn বা Hypercorn-এ --root-path কমান্ড লাইন অপশন দেওয়া সমতুল্য।

root_path সম্পর্কে¶

মনে রাখবেন, সার্ভার (Uvicorn) ওই root_path অ্যাপে পাঠানো ছাড়া আর কিছুর জন্য ব্যবহার করবে না।

কিন্তু ব্রাউজার দিয়ে http://127.0.0.1:8000/app-এ গেলে আপনি স্বাভাবিক রেসপন্স দেখবেন:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

তাই এটি আশা করবে না যে একে http://127.0.0.1:8000/api/v1/app-এ অ্যাক্সেস করা হবে।

Uvicorn আশা করবে প্রক্সি Uvicorn-কে অ্যাক্সেস করবে http://127.0.0.1:8000/app-এ, আর তারপর ওপরে বাড়তি /api/v1 prefix যোগ করার দায়িত্ব প্রক্সির।

পাথ prefix কেটে ফেলা প্রক্সি সম্পর্কে¶

মনে রাখবেন, পাথ prefix কেটে ফেলা প্রক্সি এটি কনফিগার করার উপায়গুলোর কেবল একটি।

সম্ভবত অনেক ক্ষেত্রে ডিফল্ট হবে যে প্রক্সি পাথ prefix কাটে না।

এমন ক্ষেত্রে (পাথ prefix না কেটে), প্রক্সি শুনবে https://myawesomeapp.com-এর মতো কিছুতে, আর তারপর ব্রাউজার যদি https://myawesomeapp.com/api/v1/app-এ যায় আর আপনার সার্ভার (যেমন Uvicorn) http://127.0.0.1:8000-এ শোনে, তাহলে প্রক্সি (পাথ prefix না কেটে) Uvicorn-কে একই পাথে অ্যাক্সেস করবে: http://127.0.0.1:8000/api/v1/app।

Traefik দিয়ে নিজের কম্পিউটারে পরীক্ষা¶

Traefik ব্যবহার করে পাথ prefix কেটে ফেলার পরীক্ষাটি সহজেই নিজের কম্পিউটারে চালাতে পারেন।

Traefik ডাউনলোড করুন, এটি একটিমাত্র প্রোগ্রাম ফাইল, সংকুচিত ফাইলটি খুলে সরাসরি টার্মিনাল থেকে চালাতে পারেন।

তারপর traefik.toml নামে একটি ফাইল তৈরি করুন, এতে লিখুন:

[entryPoints]
  [entryPoints.http]
    address = ":9999"

[providers]
  [providers.file]
    filename = "routes.toml"

এটি Traefik-কে বলে ৯৯৯৯ পোর্টে শুনতে আর আরেকটি ফাইল routes.toml ব্যবহার করতে।

পরামর্শ

আমরা স্ট্যান্ডার্ড HTTP পোর্ট ৮০-এর বদলে ৯৯৯৯ পোর্ট ব্যবহার করছি, যাতে অ্যাডমিন (sudo) অধিকার নিয়ে এটি চালাতে না হয়।

এবার সেই আরেকটি ফাইল routes.toml তৈরি করুন:

[http]
  [http.middlewares]

    [http.middlewares.api-stripprefix.stripPrefix]
      prefixes = ["/api/v1"]

  [http.routers]

    [http.routers.app-http]
      entryPoints = ["http"]
      service = "app"
      rule = "PathPrefix(`/api/v1`)"
      middlewares = ["api-stripprefix"]

  [http.services]

    [http.services.app]
      [http.services.app.loadBalancer]
        [[http.services.app.loadBalancer.servers]]
          url = "http://127.0.0.1:8000"

এই ফাইলটি Traefik-কে /api/v1 পাথ prefix ব্যবহার করতে কনফিগার করে।

আর তারপর Traefik তার রিকোয়েস্টগুলো http://127.0.0.1:8000-এ চলা আপনার Uvicorn-এ পাঠাবে।

এবার Traefik চালু করুন:

$ ./traefik --configFile=traefik.toml

INFO[0000] Configuration loaded from file: /home/user/awesomeapi/traefik.toml

আর এবার --root-path অপশন ব্যবহার করে আপনার অ্যাপ চালু করুন:

$ uv run fastapi run main.py --forwarded-allow-ips="*" --root-path /api/v1

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

রেসপন্সগুলো দেখুন¶

এবার Uvicorn-এর পোর্টসহ URL-এ গেলে: http://127.0.0.1:8000/app, আপনি স্বাভাবিক রেসপন্স দেখবেন:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

পরামর্শ

খেয়াল করুন, আপনি http://127.0.0.1:8000/app-এ অ্যাক্সেস করলেও এটি --root-path অপশন থেকে নেওয়া /api/v1-এর root_path দেখায়।

আর এবার পাথ prefix-সহ Traefik-এর পোর্টের URL খুলুন: http://127.0.0.1:9999/api/v1/app।

আমরা একই রেসপন্স পাই:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

কিন্তু এবার প্রক্সির দেওয়া prefix পাথ /api/v1-সহ URL-এ।

অবশ্যই, এখানে ধারণা হলো সবাই প্রক্সির মাধ্যমে অ্যাপে অ্যাক্সেস করবে, তাই পাথ prefix /api/v1-সহ সংস্করণটিই "সঠিক"।

আর Uvicorn সরাসরি যে prefix ছাড়া সংস্করণ (http://127.0.0.1:8000/app) দেয়, সেটি শুধু প্রক্সির (Traefik) অ্যাক্সেসের জন্য।

এটি দেখায় কীভাবে প্রক্সি (Traefik) পাথ prefix ব্যবহার করে, আর কীভাবে সার্ভার (Uvicorn) --root-path অপশন থেকে root_path ব্যবহার করে।

ডকুমেন্টেশন UI দেখুন¶

কিন্তু এবার মজার অংশ। ✨

অ্যাপে অ্যাক্সেসের "অফিসিয়াল" উপায় হবে আমাদের সংজ্ঞায়িত পাথ prefix-সহ প্রক্সির মাধ্যমে। তাই, যেমনটা আশা করা যায়, URL-এ পাথ prefix ছাড়া সরাসরি Uvicorn-এর দেওয়া ডকুমেন্টেশন UI চেষ্টা করলে এটি কাজ করবে না, কারণ এটি প্রক্সির মাধ্যমে অ্যাক্সেস হওয়ার আশা করে।

এটি দেখতে পারেন http://127.0.0.1:8000/docs-এ:

কিন্তু ৯৯৯৯ পোর্টের প্রক্সি ব্যবহার করে "অফিসিয়াল" URL-এ, /api/v1/docs-এ ডকুমেন্টেশন UI অ্যাক্সেস করলে এটি সঠিকভাবে কাজ করে! 🎉

এটি দেখতে পারেন http://127.0.0.1:9999/api/v1/docs-এ:

ঠিক যেমনটা আমরা চেয়েছিলাম। ✔️

এর কারণ, FastAPI এই root_path ব্যবহার করে root_path-এর দেওয়া URL দিয়ে OpenAPI-তে ডিফল্ট server তৈরি করে।

বাড়তি সার্ভার¶

সতর্কতা

এটি আরও উন্নত একটি ব্যবহারের ক্ষেত্র। নির্দ্বিধায় বাদ দিতে পারেন।

ডিফল্টভাবে FastAPI root_path-এর URL দিয়ে OpenAPI স্কিমাতে একটি server তৈরি করবে।

তবে আপনি অন্য বিকল্প servers-ও দিতে পারেন, যেমন আপনি যদি চান একই ডকুমেন্টেশন UI একটি staging (পরীক্ষামূলক) আর একটি production (আসল) এনভায়রনমেন্ট দুটোর সাথেই কাজ করুক।

আপনি যদি servers-এর একটি কাস্টম তালিকা দেন আর একটি root_path থাকে (কারণ আপনার API একটি প্রক্সির পেছনে আছে), তাহলে FastAPI তালিকার শুরুতে এই root_path-সহ একটি "server" বসিয়ে দেবে।

যেমন:

from fastapi import FastAPI, Request

app = FastAPI(
    servers=[
        {"url": "https://stag.example.com", "description": "Staging environment"},
        {"url": "https://prod.example.com", "description": "Production environment"},
    ],
    root_path="/api/v1",
)


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

এমন একটি OpenAPI স্কিমা তৈরি করবে:

{
    "openapi": "3.1.0",
    // More stuff here
    "servers": [
        {
            "url": "/api/v1"
        },
        {
            "url": "https://stag.example.com",
            "description": "Staging environment"
        },
        {
            "url": "https://prod.example.com",
            "description": "Production environment"
        }
    ],
    "paths": {
            // More stuff here
    }
}

পরামর্শ

root_path থেকে নেওয়া /api/v1 url মানসহ স্বয়ংক্রিয়ভাবে তৈরি server-টি খেয়াল করুন।

http://127.0.0.1:9999/api/v1/docs-এর ডকুমেন্টেশন UI-তে এটি দেখতে এমন হবে:

পরামর্শ

আপনি যে server বেছে নেবেন, ডকুমেন্টেশন UI সেটির সাথেই কাজ করবে।

কারিগরি বিবরণ

OpenAPI স্পেসিফিকেশনে servers প্রপার্টি ঐচ্ছিক।

আপনি servers প্যারামিটার নির্দিষ্ট না করলে আর root_path /-এর সমান হলে, তৈরি হওয়া OpenAPI স্কিমাতে servers প্রপার্টি ডিফল্টভাবে পুরোপুরি বাদ যাবে, যা / url মানসহ একটিমাত্র server-এর সমতুল্য।

root_path থেকে স্বয়ংক্রিয় server বন্ধ করুন¶

আপনি যদি না চান FastAPI root_path ব্যবহার করে একটি স্বয়ংক্রিয় server অন্তর্ভুক্ত করুক, তাহলে root_path_in_servers=False প্যারামিটার ব্যবহার করতে পারেন:

from fastapi import FastAPI, Request

app = FastAPI(
    servers=[
        {"url": "https://stag.example.com", "description": "Staging environment"},
        {"url": "https://prod.example.com", "description": "Production environment"},
    ],
    root_path="/api/v1",
    root_path_in_servers=False,
)


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

তাহলে এটি OpenAPI স্কিমাতে সেটি অন্তর্ভুক্ত করবে না।

একটি সাব-অ্যাপ্লিকেশন mount করা¶

root_path-সহ একটি প্রক্সি ব্যবহারের পাশাপাশি যদি একটি সাব-অ্যাপ্লিকেশনও mount করতে হয় (সাব-অ্যাপ্লিকেশন - Mount-এ বর্ণিত উপায়ে), তাহলে যেমনটা আশা করবেন, স্বাভাবিকভাবেই করতে পারেন।

FastAPI ভেতরে বুদ্ধিমত্তার সাথে root_path ব্যবহার করবে, তাই এটি এমনিতেই কাজ করবে। ✨

সংক্ষেপে মনে রাখুন

  • প্রক্সির পেছনে চালালে fastapi run --forwarded-allow-ips="*" (শুধু যদি প্রক্সিই সার্ভারের সাথে কথা বলে), যাতে HTTPS আর আসল IP সঠিকভাবে বোঝা যায়।
  • প্রক্সি যদি /api/v1 এর মতো prefix কেটে ফেলে, তাহলে --root-path /api/v1 বা FastAPI(root_path="/api/v1") দিন, যাতে /docs ঠিকমতো কাজ করে।
  • servers=[...] দিয়ে ডকুমেন্টেশনে একাধিক সার্ভার (staging/production) দেখানো যায়।
