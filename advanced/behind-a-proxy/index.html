প্রক্সির পেছনে¶

🌐 AI এবং মানুষের যৌথ অনুবাদ

এই অনুবাদটি মানুষের নির্দেশনায় AI দিয়ে করা হয়েছে। 🤝

এতে মূল অর্থ ভুল বোঝা বা অস্বাভাবিক শোনানোর মতো ভুল থাকতে পারে। 🤖

ইংরেজি সংস্করণ

অনেক পরিস্থিতিতে আপনি আপনার FastAPI অ্যাপের সামনে Traefik বা Nginx-এর মতো একটি প্রক্সি ব্যবহার করবেন।

এই প্রক্সিগুলো HTTPS সার্টিফিকেট ও অন্যান্য বিষয় সামলাতে পারে।

প্রক্সি Forwarded হেডার¶

আপনার অ্যাপ্লিকেশনের সামনের একটি প্রক্সি সাধারণত আপনার সার্ভারে রিকোয়েস্ট পাঠানোর আগে তাৎক্ষণিকভাবে কিছু হেডার সেট করে, যাতে সার্ভার জানতে পারে যে রিকোয়েস্টটি প্রক্সি ফরোয়ার্ড করেছে, এবং মূল (পাবলিক) URL, ডোমেইনসহ, এটি HTTPS ব্যবহার করছে কিনা ইত্যাদি জানতে পারে।

সার্ভার প্রোগ্রাম (যেমন FastAPI CLI-এর মাধ্যমে Uvicorn) এই হেডারগুলো বুঝতে পারে, এবং তারপর সেই তথ্য আপনার অ্যাপ্লিকেশনে পাঠায়।

কিন্তু সিকিউরিটির জন্য, যেহেতু সার্ভার জানে না যে এটি একটি বিশ্বস্ত প্রক্সির পেছনে আছে, তাই এটি ওই হেডারগুলো বিবেচনায় নেবে না।

কারিগরি বিবরণ

প্রক্সি হেডারগুলো হলো:

  • X-Forwarded-For
  • X-Forwarded-Proto
  • X-Forwarded-Host

প্রক্সি Forwarded হেডার চালু করুন¶

আপনি CLI অপশন --forwarded-allow-ips দিয়ে FastAPI CLI চালু করতে পারেন এবং ওই forwarded হেডারগুলো পড়ার জন্য বিশ্বস্ত IP ঠিকানাগুলো দিতে পারেন।

আপনি যদি এটি --forwarded-allow-ips="*" সেট করেন, তাহলে এটি সব আগত IP-কে বিশ্বাস করবে।

আপনার সার্ভার যদি একটি বিশ্বস্ত প্রক্সির পেছনে থাকে এবং কেবল প্রক্সিই এর সাথে কথা বলে, তাহলে এতে ওই প্রক্সির IP যাই হোক তা গ্রহণ করবে।

$ uv run fastapi run --forwarded-allow-ips="*"

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

HTTPS-সহ রিডাইরেক্ট¶

যেমন, ধরা যাক আপনি একটি পাথ অপারেশন /items/ সংজ্ঞায়িত করেছেন:

from fastapi import FastAPI

app = FastAPI()


@app.get("/items/")
def read_items():
    return ["plumbus", "portal gun"]

ক্লায়েন্ট যদি /items-এ যাওয়ার চেষ্টা করে, তাহলে ডিফল্টভাবে এটি /items/-এ রিডাইরেক্ট হবে।

কিন্তু CLI অপশন --forwarded-allow-ips সেট করার আগে এটি http://localhost:8000/items/-এ রিডাইরেক্ট করতে পারত।

কিন্তু হয়তো আপনার অ্যাপ্লিকেশন https://mysuperapp.com-এ হোস্ট করা, এবং রিডাইরেকশন হওয়া উচিত https://mysuperapp.com/items/-এ।

--proxy-headers সেট করলে এখন FastAPI সঠিক জায়গায় রিডাইরেক্ট করতে পারবে। 😎

https://mysuperapp.com/items/

পরামর্শ

আপনি যদি HTTPS সম্পর্কে আরও জানতে চান, তাহলে HTTPS প্রসঙ্গে গাইডটি দেখুন।

প্রক্সি Forwarded হেডার কীভাবে কাজ করে¶

ক্লায়েন্ট ও অ্যাপ্লিকেশন সার্ভারের মাঝে প্রক্সি কীভাবে forwarded হেডার যোগ করে তার একটি দৃশ্যমান উপস্থাপনা এখানে দেওয়া হলো:

sequenceDiagram
    participant Client
    participant Proxy as Proxy/Load Balancer
    participant Server as FastAPI Server

    Client->>Proxy: HTTPS Request<br/>Host: mysuperapp.com<br/>Path: /items

    Note over Proxy: Proxy adds forwarded headers

    Proxy->>Server: HTTP Request<br/>X-Forwarded-For: [client IP]<br/>X-Forwarded-Proto: https<br/>X-Forwarded-Host: mysuperapp.com<br/>Path: /items

    Note over Server: Server interprets headers<br/>(if --forwarded-allow-ips is set)

    Server->>Proxy: HTTP Response<br/>with correct HTTPS URLs

    Proxy->>Client: HTTPS Response

প্রক্সি মূল ক্লায়েন্ট রিকোয়েস্টটি আটকায় এবং অ্যাপ্লিকেশন সার্ভারে রিকোয়েস্ট পাঠানোর আগে বিশেষ forwarded হেডারগুলো (X-Forwarded-*) যোগ করে।

এই হেডারগুলো মূল রিকোয়েস্ট সম্পর্কে এমন তথ্য সংরক্ষণ করে যা নইলে হারিয়ে যেত:

  • X-Forwarded-For: মূল ক্লায়েন্টের IP ঠিকানা
  • X-Forwarded-Proto: মূল প্রোটোকল (https)
  • X-Forwarded-Host: মূল হোস্ট (mysuperapp.com)

যখন FastAPI CLI --forwarded-allow-ips দিয়ে কনফিগার করা থাকে, তখন এটি এই হেডারগুলো বিশ্বাস করে এবং ব্যবহার করে, যেমন রিডাইরেক্টে সঠিক URL তৈরি করতে।

বাদ দেওয়া পাথ prefix-সহ প্রক্সি¶

আপনার এমন একটি প্রক্সি থাকতে পারে যা আপনার অ্যাপ্লিকেশনে একটি পাথ prefix যোগ করে।

এসব ক্ষেত্রে আপনার অ্যাপ্লিকেশন কনফিগার করতে আপনি root_path ব্যবহার করতে পারেন।

root_path হলো ASGI স্পেসিফিকেশনের দেওয়া একটি ব্যবস্থা (যার ওপর, Starlette-এর মাধ্যমে, FastAPI তৈরি)।

এই নির্দিষ্ট ক্ষেত্রগুলো সামলাতে root_path ব্যবহার হয়।

আর সাব-অ্যাপ্লিকেশন মাউন্ট করার সময়ও এটি ভেতরে ভেতরে ব্যবহার হয়।

বাদ দেওয়া পাথ prefix-সহ একটি প্রক্সি থাকার মানে, এক্ষেত্রে, আপনি আপনার কোডে /app-এ একটি পাথ ঘোষণা করতে পারেন, কিন্তু তারপর ওপরে একটি স্তর (প্রক্সি) যোগ করেন যা আপনার FastAPI অ্যাপ্লিকেশনকে /api/v1-এর মতো একটি পাথের অধীনে রাখবে।

এক্ষেত্রে মূল পাথ /app আসলে /api/v1/app-এ সার্ভ হবে।

যদিও আপনার সব কোড এই ধরে নিয়ে লেখা যে শুধু /app আছে।

from fastapi import FastAPI, Request

app = FastAPI()


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

আর অ্যাপ সার্ভারে (সম্ভবত FastAPI CLI-এর মাধ্যমে Uvicorn) রিকোয়েস্ট পাঠানোর আগে প্রক্সি তাৎক্ষণিকভাবে পাথ prefix "বাদ দেবে", আপনার অ্যাপ্লিকেশনকে এই বিশ্বাসে রেখে যে এটি /app-এ সার্ভ হচ্ছে, যাতে prefix /api/v1 অন্তর্ভুক্ত করতে আপনাকে আপনার সব কোড আপডেট করতে না হয়।

এ পর্যন্ত সবকিছু স্বাভাবিকভাবে কাজ করবে।

কিন্তু তারপর আপনি যখন অন্তর্ভুক্ত ডকুমেন্টেশন UI (ফ্রন্টএন্ড) খুলবেন, তখন এটি /api/v1/openapi.json-এর বদলে /openapi.json-এ OpenAPI স্কিমা পাওয়ার আশা করবে।

তাই ফ্রন্টএন্ড (যা ব্রাউজারে চলে) /openapi.json-এ পৌঁছানোর চেষ্টা করবে এবং OpenAPI স্কিমা পেতে পারবে না।

যেহেতু আমাদের অ্যাপের জন্য /api/v1 পাথ prefix-সহ একটি প্রক্সি আছে, তাই ফ্রন্টএন্ডকে /api/v1/openapi.json-এ OpenAPI স্কিমা আনতে হবে।

graph LR

browser("Browser")
proxy["Proxy on http://0.0.0.0:9999/api/v1/app"]
server["Server on http://127.0.0.1:8000/app"]

browser --> proxy
proxy --> server

পরামর্শ

IP 0.0.0.0 সাধারণত বোঝাতে ব্যবহার হয় যে প্রোগ্রামটি ওই মেশিন/সার্ভারে উপলব্ধ সব IP-তে শুনছে।

ডকুমেন্টেশন UI-এর OpenAPI স্কিমারও দরকার হবে এটি ঘোষণা করা যে এই API server আছে /api/v1-এ (প্রক্সির পেছনে)। যেমন:

{
    "openapi": "3.1.0",
    // More stuff here
    "servers": [
        {
            "url": "/api/v1"
        }
    ],
    "paths": {
            // More stuff here
    }
}

এই উদাহরণে "Proxy" হতে পারে Traefik-এর মতো কিছু। আর সার্ভার হতে পারে Uvicorn-সহ FastAPI CLI-এর মতো কিছু, যা আপনার FastAPI অ্যাপ্লিকেশন চালাচ্ছে।

root_path দেওয়া¶

এটি অর্জন করতে আপনি কমান্ড লাইন অপশন --root-path এভাবে ব্যবহার করতে পারেন:

$ uv run fastapi run main.py --forwarded-allow-ips="*" --root-path /api/v1

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

আপনি যদি Hypercorn ব্যবহার করেন, তাতেও --root-path অপশন আছে।

কারিগরি বিবরণ

ASGI স্পেসিফিকেশন এই ব্যবহারের ক্ষেত্রের জন্য একটি root_path সংজ্ঞায়িত করে।

আর --root-path কমান্ড লাইন অপশন সেই root_path দেয়।

বর্তমান root_path যাচাই¶

প্রতিটি রিকোয়েস্টের জন্য আপনার অ্যাপ্লিকেশনে ব্যবহৃত বর্তমান root_path আপনি পেতে পারেন, এটি scope ডিকশনারির অংশ (যা ASGI স্পেকের অংশ)।

এখানে আমরা শুধু দেখানোর উদ্দেশ্যে এটি মেসেজে অন্তর্ভুক্ত করছি।

from fastapi import FastAPI, Request

app = FastAPI()


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

তারপর আপনি যদি Uvicorn এভাবে চালু করেন:

$ uv run fastapi run main.py --forwarded-allow-ips="*" --root-path /api/v1

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

রেসপন্সটি হবে এরকম কিছু:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

FastAPI অ্যাপে root_path সেট করা¶

বিকল্পভাবে, আপনার যদি --root-path বা সমতুল্য কোনো কমান্ড লাইন অপশন দেওয়ার উপায় না থাকে, তাহলে আপনার FastAPI অ্যাপ তৈরির সময় root_path প্যারামিটার সেট করতে পারেন:

from fastapi import FastAPI, Request

app = FastAPI(root_path="/api/v1")


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

FastAPI-তে root_path দেওয়া Uvicorn বা Hypercorn-এ --root-path কমান্ড লাইন অপশন দেওয়ার সমতুল্য।

root_path সম্পর্কে¶

মনে রাখবেন, সার্ভার (Uvicorn) সেই root_path অ্যাপে পাঠানো ছাড়া অন্য কিছুতে ব্যবহার করবে না।

কিন্তু আপনি যদি আপনার ব্রাউজারে http://127.0.0.1:8000/app-এ যান, তাহলে স্বাভাবিক রেসপন্স দেখবেন:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

তাই এটি http://127.0.0.1:8000/api/v1/app-এ অ্যাক্সেস হওয়ার আশা করবে না।

Uvicorn আশা করবে যে প্রক্সি http://127.0.0.1:8000/app-এ Uvicorn অ্যাক্সেস করবে, আর তারপর ওপরে অতিরিক্ত /api/v1 prefix যোগ করার দায়িত্ব হবে প্রক্সির।

বাদ দেওয়া পাথ prefix-সহ প্রক্সি সম্পর্কে¶

মনে রাখবেন, বাদ দেওয়া পাথ prefix-সহ একটি প্রক্সি এটি কনফিগার করার উপায়গুলোর কেবল একটি।

সম্ভবত অনেক ক্ষেত্রে ডিফল্ট হবে যে প্রক্সির কোনো বাদ দেওয়া পাথ prefix নেই।

এরকম ক্ষেত্রে (বাদ দেওয়া পাথ prefix ছাড়া), প্রক্সি https://myawesomeapp.com-এর মতো কিছুতে শুনবে, আর তারপর ব্রাউজার যদি https://myawesomeapp.com/api/v1/app-এ যায় এবং আপনার সার্ভার (যেমন Uvicorn) http://127.0.0.1:8000-এ শোনে, তাহলে প্রক্সি (বাদ দেওয়া পাথ prefix ছাড়া) একই পাথে Uvicorn অ্যাক্সেস করবে: http://127.0.0.1:8000/api/v1/app।

Traefik দিয়ে লোকালি টেস্টিং¶

Traefik ব্যবহার করে আপনি সহজেই লোকালি বাদ দেওয়া পাথ prefix-সহ পরীক্ষাটি চালাতে পারেন।

Traefik ডাউনলোড করুন, এটি একটিমাত্র বাইনারি, আপনি কম্প্রেস করা ফাইলটি এক্সট্র্যাক্ট করে সরাসরি টার্মিনাল থেকে চালাতে পারেন।

তারপর traefik.toml নামে একটি ফাইল তৈরি করুন, এতে লিখুন:

[entryPoints]
  [entryPoints.http]
    address = ":9999"

[providers]
  [providers.file]
    filename = "routes.toml"

এটি Traefik-কে পোর্ট 9999-এ শুনতে এবং আরেকটি ফাইল routes.toml ব্যবহার করতে বলে।

পরামর্শ

আমরা স্ট্যান্ডার্ড HTTP পোর্ট 80-এর বদলে পোর্ট 9999 ব্যবহার করছি, যাতে আপনাকে অ্যাডমিন (sudo) অনুমতি দিয়ে এটি চালাতে না হয়।

এবার সেই অন্য ফাইল routes.toml তৈরি করুন:

[http]
  [http.middlewares]

    [http.middlewares.api-stripprefix.stripPrefix]
      prefixes = ["/api/v1"]

  [http.routers]

    [http.routers.app-http]
      entryPoints = ["http"]
      service = "app"
      rule = "PathPrefix(`/api/v1`)"
      middlewares = ["api-stripprefix"]

  [http.services]

    [http.services.app]
      [http.services.app.loadBalancer]
        [[http.services.app.loadBalancer.servers]]
          url = "http://127.0.0.1:8000"

এই ফাইলটি Traefik-কে পাথ prefix /api/v1 ব্যবহার করার জন্য কনফিগার করে।

আর তারপর Traefik তার রিকোয়েস্টগুলো http://127.0.0.1:8000-এ চলমান আপনার Uvicorn-এ রিডাইরেক্ট করবে।

এবার Traefik চালু করুন:

$ ./traefik --configFile=traefik.toml

INFO[0000] Configuration loaded from file: /home/user/awesomeapi/traefik.toml

আর এবার --root-path অপশন ব্যবহার করে আপনার অ্যাপ চালু করুন:

$ uv run fastapi run main.py --forwarded-allow-ips="*" --root-path /api/v1

<span style="color: green;">INFO</span>:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

রেসপন্সগুলো যাচাই করুন¶

এখন আপনি যদি Uvicorn-এর পোর্টসহ URL-এ যান: http://127.0.0.1:8000/app, তাহলে স্বাভাবিক রেসপন্স দেখবেন:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

পরামর্শ

লক্ষ করুন, আপনি http://127.0.0.1:8000/app-এ অ্যাক্সেস করলেও এটি --root-path অপশন থেকে নেওয়া /api/v1-এর root_path দেখায়।

আর এবার পাথ prefix-সহ Traefik-এর পোর্টসহ URL খুলুন: http://127.0.0.1:9999/api/v1/app।

আমরা একই রেসপন্স পাই:

{
    "message": "Hello World",
    "root_path": "/api/v1"
}

তবে এবার প্রক্সির দেওয়া prefix পাথ /api/v1-সহ URL-এ।

অবশ্যই, এখানে ধারণাটি হলো সবাই প্রক্সির মাধ্যমে অ্যাপ অ্যাক্সেস করবে, তাই পাথ prefix /api/v1-সহ ভার্সনটিই "সঠিক"।

আর সরাসরি Uvicorn-এর দেওয়া পাথ prefix ছাড়া ভার্সনটি (http://127.0.0.1:8000/app) কেবল প্রক্সির (Traefik) অ্যাক্সেসের জন্য।

এটি দেখায় যে প্রক্সি (Traefik) কীভাবে পাথ prefix ব্যবহার করে এবং সার্ভার (Uvicorn) কীভাবে --root-path অপশন থেকে root_path ব্যবহার করে।

ডকুমেন্টেশন UI যাচাই করুন¶

তবে এখানেই মজার অংশ। ✨

অ্যাপ অ্যাক্সেস করার "অফিসিয়াল" উপায় হবে আমাদের সংজ্ঞায়িত পাথ prefix-সহ প্রক্সির মাধ্যমে। তাই প্রত্যাশামতোই, আপনি যদি URL-এ পাথ prefix ছাড়া সরাসরি Uvicorn-এর সার্ভ করা ডকুমেন্টেশন UI চেষ্টা করেন, তাহলে এটি কাজ করবে না, কারণ এটি প্রক্সির মাধ্যমে অ্যাক্সেস হওয়ার আশা করে।

আপনি এটি যাচাই করতে পারেন http://127.0.0.1:8000/docs-এ:

কিন্তু আমরা যদি পোর্ট 9999-সহ প্রক্সি ব্যবহার করে "অফিসিয়াল" URL-এ, /api/v1/docs-এ ডকুমেন্টেশন UI অ্যাক্সেস করি, তাহলে এটি সঠিকভাবে কাজ করে! 🎉

আপনি এটি যাচাই করতে পারেন http://127.0.0.1:9999/api/v1/docs-এ:

ঠিক যেমনটা আমরা চেয়েছিলাম। ✔️

কারণ FastAPI এই root_path ব্যবহার করে root_path-এর দেওয়া URL দিয়ে OpenAPI-তে ডিফল্ট server তৈরি করে।

অতিরিক্ত সার্ভার¶

সতর্কতা

এটি আরও অ্যাডভান্সড একটি ব্যবহারের ক্ষেত্র। নির্দ্বিধায় এড়িয়ে যান।

ডিফল্টভাবে FastAPI OpenAPI স্কিমায় root_path-এর URL দিয়ে একটি server তৈরি করবে।

তবে আপনি অন্যান্য বিকল্প servers-ও দিতে পারেন, যেমন আপনি যদি চান একই ডকুমেন্টেশন UI একটি স্টেজিং ও একটি প্রোডাকশন এনভায়রনমেন্ট দুটোর সাথেই কাজ করুক।

আপনি যদি servers-এর একটি কাস্টম লিস্ট দেন এবং একটি root_path থাকে (কারণ আপনার API একটি প্রক্সির পেছনে থাকে), তাহলে FastAPI লিস্টের শুরুতে এই root_path-সহ একটি "server" যোগ করবে।

যেমন:

from fastapi import FastAPI, Request

app = FastAPI(
    servers=[
        {"url": "https://stag.example.com", "description": "Staging environment"},
        {"url": "https://prod.example.com", "description": "Production environment"},
    ],
    root_path="/api/v1",
)


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

এরকম একটি OpenAPI স্কিমা তৈরি করবে:

{
    "openapi": "3.1.0",
    // More stuff here
    "servers": [
        {
            "url": "/api/v1"
        },
        {
            "url": "https://stag.example.com",
            "description": "Staging environment"
        },
        {
            "url": "https://prod.example.com",
            "description": "Production environment"
        }
    ],
    "paths": {
            // More stuff here
    }
}

পরামর্শ

লক্ষ করুন, root_path থেকে নেওয়া /api/v1 url ভ্যালুসহ স্বয়ংক্রিয়ভাবে তৈরি হওয়া সার্ভারটি।

http://127.0.0.1:9999/api/v1/docs-এর ডকুমেন্টেশন UI-তে এটি দেখতে এরকম হবে:

পরামর্শ

ডকুমেন্টেশন UI আপনার বেছে নেওয়া সার্ভারের সাথে কাজ করবে।

কারিগরি বিবরণ

OpenAPI স্পেসিফিকেশনে servers প্রপার্টিটি ঐচ্ছিক।

আপনি যদি servers প্যারামিটার উল্লেখ না করেন এবং root_path /-এর সমান হয়, তাহলে তৈরি হওয়া OpenAPI স্কিমা থেকে ডিফল্টভাবে servers প্রপার্টিটি পুরোপুরি বাদ যাবে, যা / url ভ্যালুসহ একটিমাত্র সার্ভারের সমতুল্য।

root_path থেকে স্বয়ংক্রিয় সার্ভার বন্ধ করুন¶

আপনি যদি না চান যে FastAPI root_path ব্যবহার করে একটি স্বয়ংক্রিয় সার্ভার অন্তর্ভুক্ত করুক, তাহলে root_path_in_servers=False প্যারামিটার ব্যবহার করতে পারেন:

from fastapi import FastAPI, Request

app = FastAPI(
    servers=[
        {"url": "https://stag.example.com", "description": "Staging environment"},
        {"url": "https://prod.example.com", "description": "Production environment"},
    ],
    root_path="/api/v1",
    root_path_in_servers=False,
)


@app.get("/app")
def read_main(request: Request):
    return {"message": "Hello World", "root_path": request.scope.get("root_path")}

আর তাহলে এটি OpenAPI স্কিমায় সেটি অন্তর্ভুক্ত করবে না।

একটি সাব-অ্যাপ্লিকেশন মাউন্ট করা¶

root_path-সহ একটি প্রক্সি ব্যবহারের পাশাপাশি যদি আপনাকে একটি সাব-অ্যাপ্লিকেশন মাউন্ট করতে হয় (সাব-অ্যাপ্লিকেশন - মাউন্ট-এ যেমন বর্ণনা করা হয়েছে), তাহলে আপনি প্রত্যাশামতোই স্বাভাবিকভাবে এটি করতে পারেন।

FastAPI ভেতরে ভেতরে বুদ্ধিমত্তার সাথে root_path ব্যবহার করবে, তাই এটি এমনিতেই কাজ করবে। ✨
